# AGENTS.md — AI 协作规范

本文档为 AI 编码助手（如 Claude、Copilot 等）提供项目上下文和开发约定。

## 项目概述

`topo-metrics` 是一个 Python 库，提供遥感图像和医学影像领域的**拓扑结构评估指标**。核心目标是让研究者和工程师能方便地计算预测结果与真实标注之间的拓扑一致性。

当前支持：APLS（Average Path Length Similarity）、TopoF1（Topological F1 Score）。

## 技术栈

- **语言**: Python 3.12+
- **包管理**: uv
- **构建系统**: pyproject.toml（PEP 621）
- **测试**: pytest
- **代码风格**: ruff（lint + format）

## 依赖策略

- **最小化外部依赖**。优先使用 numpy/scipy 等科学计算基础库。
- 图操作如需复杂算法（如 networkx），作为可选依赖引入。
- 新增依赖需说明理由。

## 测试要求

- 每个指标至少覆盖：
  1. **完全一致**：prediction == ground_truth → score 应为最优值
  2. **完全不同**：空白预测 vs 有标注 → score 应为最差值
  3. **典型场景**：部分匹配的中间值
- 测试中使用小型合成数据，不要依赖外部文件。
- 运行方式：`uv run pytest`

## 关键约束

1. **输入类型分层**：指标的输入类型分为三层，实现时必须按类型分层设计：
   - **像素级**：直接对 numpy ndarray（二值图）进行像素级计算，不涉及图结构转换。
   - **像素→图**：接受 numpy ndarray 输入，内部将其转换为图结构后进行拓扑计算。
   - **图级**：只接受图结构（如 networkx Graph）作为输入。
2. **返回值**：每个指标函数返回单一标量 float。
3. **性能**：对于大图（如 1024×1024），应考虑内存效率，避免不必要的全图复制。
4. **数值稳定性**：注意除零保护，使用 `np.finfo` 或小常数 eps。

## Deep Research 工作流

当需要进行广泛的技术调研时，采用多模型深度调研 + 综合评价的工作流。

### 调研组织结构

```
docs/deepresearch_result/
└── <调研主题>/
    ├── 问题.md                    # 调研问题的完整描述
    ├── <模型1>.md                 # 各模型的调研结果（如 ChatGPT.md, gemini.md）
    ├── <模型2>.md
    ├── ...
    └── 综合评价与总结.md           # 由 AI 生成的横向比较与综合评价
```

- 模型提供商数量不固定，每次调研可能使用 2-5 个不同模型。
- 所有调研结果和综合评价存放在同一目录下。

### 综合评价与总结的固定格式

每次广泛调研完成后，**必须**按以下结构生成 `综合评价与总结.md`：

```markdown
# 综合评价与总结

本文件对 N 份大模型深度调研结果（模型A、模型B、...）进行横向比较与综合评价。

## 一、总体评价
- 各模型的多维度评分表（覆盖面、结构化信息、引用质量、分类体系、优先级建议、工具库设计、综合评分）
- 按综合质量排序

## 二、各模型详细评价
对每个模型，包含以下 8 个子章节：
### 2.N 模型名 — 一句话定性
1. **覆盖范围**：列举所有提到的指标/损失名称，是否覆盖所有要求的领域和类别
2. **结构化信息质量**：是否按要求的字段提供完整信息，最完整和最不完整的指标
3. **论文引用与代码链接**：引用格式、可追溯性、GitHub 链接覆盖情况
4. **分类体系（Taxonomy）**：是否提供分类，分类方式和质量
5. **优先级建议与实现难度评估**：是否有版本划分、难度评估是否合理
6. **工具库设计建议**：package/API/graph schema 等建议的质量
7. **独特贡献**：其他模型可能没有的独到见解
8. **不足之处**：信息缺失、不准确、泛泛而谈的地方

## 三、交叉对比：关键指标信息完备性
- 核心指标的横向覆盖对比表（每列一个模型，行是指标，标注覆盖深度）

## 四、交叉对比：分类体系
- 各模型分类体系的横向对比表，标注一致性

## 五、交叉对比：优先级建议
- 各模型 v0.1/v0.2/v1.0 划分的横向对比表
- 标注关键分歧并给出建议

## 六、对项目设计的关键启示
- 所有模型一致认同的设计原则
- 各模型的独到建议
- 预警和注意事项

## 七、各模型在关键事实上的准确性
- 如果存在事实性错误（如论文归属错误），在此汇总纠正

## 八、结论与建议
- 推荐阅读优先级排序
- 下一步行动建议
```

### 执行规则

1. **并行总结**：使用多个子代理并行读取各模型调研结果，按上述 8 个维度分别总结。
2. **综合撰写**：收集所有子代理的总结后，按固定格式撰写综合评价。
3. **文档索引更新**：完成后同步更新 `docs/README.md` 中的文档索引。
