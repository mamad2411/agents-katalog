# Agent Handoff Protocol

このルールは、Cloud AgentとLocal Agent間の引き継ぎを標準化し、効率的なタスク移譲を実現します。

## 適用範囲

- Cloud Agent ⇄ Local Agent間のタスク引き継ぎ
- 引き継ぎドキュメントの作成・読み込み・管理

## トリガーワード

### 送信側（引き継ぎドキュメント作成）

ユーザーが以下の言葉を使ったら、引き継ぎドキュメントを作成する：

- **「引き継ぎドキュメント作成」**
- **「次のエージェントに引き継ぐ」**
- **「ローカルエージェントに引き継ぐ」**
- **「クラウドエージェントに引き継ぐ」**

### 受信側（引き継ぎドキュメント読み込み）

ユーザーが以下の言葉を使ったら、引き継ぎドキュメントを読み込んで作業を開始する：

- **「引き継ぎドキュメント読み込み」**
- **「前のエージェントから引き継ぐ」**
- **「引き継ぎコンテキスト読み込んで」**
- **「続きから開始」**

## 引き継ぎドキュメントの構成

### 必須セクション

1. **メタ情報** - 送信元、送信先、優先度、期限
2. **前提知識・参照ドキュメント** - ADR、ガイド、コードへのリンク
3. **現在の状況サマリー** - 達成済み、未着手、ブロッカー
4. **技術スタック** - 言語、ライブラリ、インフラ
5. **実装要件** - 必須、推奨、オプション
6. **環境情報** - 実行環境、認証情報、ツール
7. **依存関係** - 事前タスク、並行可能タスク、後続タスク
8. **詳細タスクリスト** - 具体的なタスクと成功基準
9. **成功基準** - 最低限の成功、完全な成功、確認方法
10. **テスト・検証手順** - 単体、統合、本番想定
11. **トラブルシューティング** - よくあるエラーと解決方法
12. **ロールバック手順** - 緊急停止、データ復旧
13. **制約事項・トレードオフ** - 技術、コスト、時間
14. **セキュリティ・機密情報の扱い** - 認証情報の管理
15. **完了報告フォーマット** - 報告すべき内容
16. **次のアクション** - 報告先、次の引き継ぎ先

詳細は `docs/handoffs/templates/handoff-template.md` を参照。

## ファイル配置・命名規則

### ディレクトリ構造

```
docs/handoffs/
├── INDEX.md              # 全引き継ぎの一覧・ステータス管理
├── templates/            # テンプレート
├── active/               # 🟢 進行中の引き継ぎ
├── completed/            # ✅ 完了した引き継ぎ（直近3ヶ月）
│   └── YYYY-MM/
└── archive/              # 📦 アーカイブ（3ヶ月以上前）
    └── YYYY-MM/
```

### 命名規則

```
{送信元}-to-{送信先}-{タスク概要}-{YYYYMMDD}.md

例:
- cloud-to-local-tapo-poller-20260803.md
- local-to-cloud-esp32-integration-20260804.md
```

### ライフサイクル

1. **作成時** → `active/` に配置
2. **タスク完了後** → `completed/YYYY-MM/` に移動
3. **3ヶ月経過後** → `archive/YYYY-MM/` に移動（または削除）

## 送信側エージェントの責任

### 引き継ぎドキュメント作成時

1. **テンプレートを使用**:
   ```
   docs/handoffs/templates/handoff-template.md
   ```

2. **必須セクションを全て記入**:
   - 曖昧な表現を避け、具体的に記述
   - コマンド例、パス、URLを正確に記載
   - 成功基準を明確に定義

3. **ファイル配置**:
   - `docs/handoffs/active/{命名規則}.md` に保存

4. **INDEX.md更新**:
   - `docs/handoffs/INDEX.md` の「Active Handoffs」セクションに追加

5. **コミット＆プッシュ**:
   ```bash
   git add docs/handoffs/
   git commit -m "Add agent handoff: {タスク概要}"
   git push
   ```

6. **ユーザーに報告**:
   - 引き継ぎドキュメントのパスを伝える
   - 次のエージェントで行うべきアクションを簡潔に説明

### 注意事項

- **コンテキストの完全性**: 受信側エージェントが初見でも理解できる情報を提供
- **依存関係の明示**: 事前に完了すべきタスクを漏れなく記載
- **環境差分の考慮**: Cloud AgentとLocal Agentの実行環境の違いを意識

## 受信側エージェントの責任

### 引き継ぎドキュメント読み込み時

1. **INDEX.md確認**:
   ```
   docs/handoffs/INDEX.md
   ```
   - 「Active Handoffs」から該当ドキュメントを特定

2. **ドキュメント読み込み**:
   - 全セクションを順番に読む
   - 不明点があればユーザーに確認（推測しない）

3. **前提知識の習得**:
   - セクション2の参照ドキュメントを先に読む
   - ADR、ガイド、既存コードを理解

4. **環境準備**:
   - セクション6の環境情報に従って設定
   - 必要なツール、認証情報を用意

5. **タスク実行**:
   - セクション8のタスクリストに従って実装
   - 各タスクの成功基準を満たすことを確認

6. **テスト・検証**:
   - セクション10の手順に従ってテスト
   - 問題があればセクション11でトラブルシューティング

7. **完了報告**:
   - セクション15のフォーマットに従って報告
   - 未解決の問題、次の課題を明記

8. **ファイル移動**:
   - `docs/handoffs/active/{ファイル名}.md` →
   - `docs/handoffs/completed/YYYY-MM/{ファイル名}.md`

9. **INDEX.md更新**:
   - 「Active Handoffs」から削除
   - 「Recently Completed」に追加（成功/失敗、学びを記載）

10. **コミット＆プッシュ**:
    ```bash
    git add docs/handoffs/
    git commit -m "Complete agent handoff: {タスク概要}"
    git push
    ```

### 注意事項

- **推測しない**: 不明な点はユーザーに確認
- **成功基準の厳守**: セクション9の基準を満たすまで完了としない
- **学びの記録**: 遭遇した問題と解決方法をINDEX.mdに記載

## 保持ポリシー

| ディレクトリ | 保持期間 | 管理者 |
|-------------|---------|-------|
| `active/` | タスク完了まで | Agent |
| `completed/` | 3ヶ月 | Agent + User |
| `archive/` | 任意（削除可） | User |

- **ユーザーの責任**: 定期的に `completed/` をレビューし、3ヶ月経過したものを `archive/` に移動
- **削除判断**: 学びが少ない、または類似タスクが多い場合は削除可

## 引き継ぎの品質基準

良い引き継ぎドキュメントの特徴：

- ✅ **具体性**: コマンド、パス、URLが正確
- ✅ **完全性**: 受信側が追加調査不要
- ✅ **検証可能性**: 成功基準が明確
- ✅ **安全性**: ロールバック手順が記載
- ✅ **学習可能性**: トラブルシューティングが充実

悪い引き継ぎドキュメントの特徴：

- ❌ **曖昧性**: 「適切に設定」「よしなに対応」などの表現
- ❌ **不完全性**: 認証情報の取得方法が不明
- ❌ **非現実的**: 受信側の環境で実行不可能
- ❌ **未検証**: 送信側が実際に試していない手順

## エスカレーション

以下の場合はユーザーにエスカレーション：

- 引き継ぎドキュメントに重大な欠落がある
- 環境的に実行不可能なタスクが含まれている
- ブロッカーが解決できない
- 期限に間に合わない可能性がある

このプロトコルは進化します：

- 引き継ぎの成功/失敗から学び、テンプレートを改善

- 不要なセクションは削除

改善提案はユーザーに報告してください。
