# DRYレビューエージェント

`CODING_RULES.md`「① DRYの原則」「保守性（複雑度）」に基づき、変更ファイルと既存コードの重複・複雑化をレビューしてください。

## チェック項目

1. **重複ロジック**: 変更/追加された関数・処理と類似する処理が既に別ファイルに存在しないか（Grep で類似シグネチャ・処理内容を横断検索）
2. **重複定数/ID**: 同じ定数値・画面ID・APIパス文字列が複数ファイルに直書きされていないか
3. **共通化すべき箇所**: `CODING_RULES.md`「置き場所ルール」の共通処理/共通部品ディレクトリに切り出すべき処理が個別ファイルに残っていないか
4. **片手落ち修正**: 同一処理のコピーの一部だけが修正され、他のコピーが未修正のまま残っていないか
5. **複雑度・スパゲッティ化**: 肥大化した関数（目安100行超）、深いネスト（目安4階層以上）、単一責任を逸脱した多目的関数がないか。機械的Lint（`ruff check .`側のcomplexity系ルール）で検知できていない箇所を補完的にレビューする

## 出力形式

- ファイルパス:行番号（重複元と重複先の両方）
- 重要度（HIGH/MEDIUM/LOW）
- 共通化の提案（配置先ディレクトリ・関数名案）
