# AGENTS.md

A study of agent instruction files: a frozen corpus of 1,666 markdown files
scraped from 289 GitHub repos, scripts that measure them, and documents that
quote the resulting numbers in prose. No application code, no build, no test
suite. Bash and Python 3.13 with `gh`, `jq` and `curl`.

This file is written to the rules in `BEST_PRACTICES.md`. `CLAUDE.md` is a symlink
to it, which is the exception the rules allow: one developer, one OS, and no
Claude-specific content to add. Elsewhere prefer a `CLAUDE.md` containing
`@AGENTS.md`.

## The one rule that matters

**The corpus is frozen evidence and the prose quotes numbers computed from it.**
Re-running the pipeline against today's GitHub will change star counts, repo
membership and therefore most percentages in `README.md`, `ANALYSIS.md`,
`ANALYSIS_FULL.md`, `BEST_PRACTICES.md`, `RELATED_WORK.md` and `REPOS.md`.

So: do not re-run steps 1, 2, 5 or 9 to "refresh" things. If you do re-run them,
you MUST re-derive every affected figure and update all six documents in the same
change, or the repo starts lying. Steps 3, 4, 7 and 8 are pure functions of the
committed corpus and are safe to re-run any time.

## Commands

```bash
# offline, safe, reproduces the committed outputs exactly
python3 scripts/03_analyze.py                 # per-file metrics + aggregates
python3 scripts/04_practices.py               # 27 practice frequencies
python3 scripts/07_compare.py                 # four runs side by side
python3 scripts/08_gradient.py                # correlations
python3 scripts/08_gradient.py --counts data/practices_primary_all_by_repo.tsv \
    --out data/gradient_primary.json          # confound-controlled version

# the full pool and the strata (still offline, reads corpus_full/)
python3 scripts/03_analyze.py --corpus corpus_full --out data/analysis_full.json \
    --csv data/file_metrics_full.csv
python3 scripts/04_practices.py --corpus corpus_full --out-prefix data/practices_full
python3 scripts/03_analyze.py --corpus corpus_full --only data/repos_tail.txt \
    --out data/analysis_tail.json --csv data/file_metrics_tail.csv

# network steps: slow, mutate the sample, read the rule above first
./scripts/01_select_repos.sh                  # ~10 min, 560 repos, needs gh auth
./scripts/01c_refilter.sh                     # offline reclassify from cached trees
./scripts/01b_rank.sh                         # rank, write REPOS.md
./scripts/02_download_md.sh                   # ~5 min
SEL=data/selected_all.jsonl OUTDIR=corpus_full ./scripts/02_download_md.sh
./scripts/09_file_history.sh                  # ~2 min, commit history per file
```

Run the network steps with `run_in_background`; step 1 exceeds a 600s foreground
timeout. Scripts `cd` to the repo root themselves, so they work from any
directory.

## Verifying a change to the analysis scripts

Steps 3 and 4 must stay byte-identical on their defaults. After editing either:

```bash
python3 scripts/03_analyze.py && python3 scripts/04_practices.py
git diff --stat data/analysis.json data/file_metrics.csv data/practices.tsv
```

Empty diff means the refactor was safe. A non-empty diff means either a real
change to the measurement, in which case every affected number in the documents
needs updating, or a bug.

## Conventions

- Percentages in prose are **shares of repositories, not of files**. Say which
  run a figure comes from when it is not the 50-repo sample.
- **Verify every number before writing it in prose.** Compute it with a script or
  a one-off `python3 -` block against the CSVs. Several figures in early drafts
  were wrong because they came from a search summary or a mis-scoped regex.
- Prose in this repo uses **no em dashes**. Use commas, semicolons or parentheses.
- When a regex-based metric looks surprisingly high, spot-check the matches before
  publishing it. Three patterns in `scripts/04_practices.py` were over-broad on
  the first pass and are documented as tightened in `METHODOLOGY.md`.
- New pipeline stages get a numbered script with a header comment stating its
  inputs and outputs, and a row in the table in `METHODOLOGY.md`.
- Keep the strata comparable: changing the classifier means re-running `01c`,
  `01b`, `02`, then everything downstream.

## Do not touch

- **`corpus/` and `corpus_full/`**: downloaded evidence. Never hand-edit a file
  there. Files are skipped if they already exist, so to force a re-fetch delete
  the specific file first.
- **`REPOS.md`**: generated by `scripts/01b_rank.sh`.
- **Every generated table and aggregate under `data/`** (json, tsv and csv alike):
  edit the script that emits it, never the output.
- `data/exclusions.txt` and `data/curated_candidates.txt` are the two
  hand-maintained inputs. Every exclusion needs a reason in the second column.

## Gotchas

<!-- Append one line. Never restructure. Never delete without a reason.
     - TAG `trigger` -> action. why
     TAG in: SLOW REBUILD FLAKY ENV FROZEN FORBIDDEN
     Format spec: skills/init-agents-md/references/GOTCHAS.md
     Validate: skills/init-agents-md/lint-gotchas.sh AGENTS.md -->

- SLOW `./scripts/01_select_repos.sh` -> run with `run_in_background`, ~10 min. It
  exceeds a 600s foreground timeout and dies mid-pool.
- ENV `gh auth status` -> must be authenticated for any network step. Unauthenticated
  runs hit the 60 requests/hour cap and fail quietly as "MISS" lines on stderr.
- FLAKY `data/repo_meta.jsonl` -> one row is a GitHub 404 body, not a repo; ignore it.
  It has no instruction files so it reaches no sample; step 1 rejects such rows and
  step 8 skips them.
- REBUILD `data/trees/` -> present means step 1 skips tree fetches but still requeries
  metadata for all 560 candidates. Delete a tree to force one refetch.
- REBUILD `corpus_full/` -> seed with `cp -R corpus/. corpus_full/` before downloading.
  Skipping that costs 511 extra requests for the same result.
- FROZEN `corpus/`, `corpus_full/` -> never hand-edit, re-fetch with
  `./scripts/02_download_md.sh`. Files already on disk are skipped, so delete the one
  file first.
- ENV `curl` -> step 2 percent-encodes paths containing spaces. Two repos need this;
  without it `curl` returns 404 and the file is silently skipped.
- ENV `MAX_FILES_PER_REPO=80` -> two repos exceed it, `code-yeongyu/oh-my-openagent`
  (113, in the 50-repo sample) and `agent0ai/agent-zero` (153, full pool only). Every
  manifest such as `corpus/openai__codex/manifest.json` lists what was skipped, so a
  manifest count can exceed what is on disk.

## Before you finish

1. `python3 scripts/03_analyze.py && python3 scripts/04_practices.py`
2. `git diff --stat data/analysis.json data/practices.tsv` is empty, or every
   changed figure is reflected in the documents.
3. No em dashes anywhere. Check without typing one:
   `python3 -c "import glob;print([f for f in glob.glob('*.md')+glob.glob('templates/*.md') if chr(8212) in open(f).read()])"`
   must print `[]`.
4. Any new number in prose traces to a command someone else could re-run.
5. Commit with a message that says what changed and why, including corrections to
   earlier figures. Do not push unless asked.

here that would have saved the first attempt.
