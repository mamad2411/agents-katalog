# Documentation Instructions

- Write for a reader who has not seen this repository. State prerequisites before steps.
- Lead with the outcome, then the procedure. No filler introductions or conclusions.
- Every command block is copy-runnable and states the shell it targets.
- Use relative links to files in this repository so they survive a fork or clone.
- Do not document intended behavior as if it exists. Mark planned work explicitly.
- Keep one H1 per document. Use sentence case for headings.
- Update the document in the same change that alters the behavior it describes.
- Do not paste secrets, tenant identifiers, subscription identifiers, or customer data into documentation.
