# Project Claude instrumentation

This folder owns project-root session instrumentation used by `routes/projectClaude.ts`.

- `reconcile.ts` handles project settings side effects: hook install/removal, Claude memory opt-out, project-root MCP reconciliation, repo-local `.git/info/exclude` updates (never the tracked `.gitignore`), and the Pi subagents shim.
- `managedCwd.ts` filters Lattice-owned scratch/worktree cwd values: these sessions already have their own instrumentation and must not be double-counted as generic project sessions.
- `lifecycle.ts` is the source of truth for project session presence, which follows the agent's **turns**: `UserPromptSubmit` / tool use / subagent events create the node (or bring back one the idle TTL or a restart dropped), `Stop` removes it after the 15-second `TURN_END_GRACE_MS` unless activity within that window cancels removal (Claude fires early Stops around subagents), `SessionStart` alone draws nothing, and `SessionEnd` — or the tab's terminal exiting (`routes/projectClaude.ts` subscribes to the terminal registry's `ended` event, which carries the tab's pinned `agentSessionId`) — removes it immediately via `endProjectSession`. Sessions carry `harness` (from the token label) so the graph colors terminal Codex white and Pi blue.
- `activity.ts` fans live project-session hook events into graph activity/focus beams after lifecycle admits the event.
- The route is harness-neutral: `../projectCodexHooks.ts` attaches project activity hooks to eligible user/startup Codex launches (instrumentation enabled, cwd inside the project, outside managed scratch/worktrees) via per-invocation `-c hooks.*` overrides plus `--dangerously-bypass-hook-trust` (token label `codex`). Hook trust bypass is distinct from `--yolo`'s approval/sandbox bypass. Injection writes neither the repo's `.codex/hooks.json` nor the user's `~/.codex` configuration; each event override replaces that event's user-config hooks for this launch, while repo `hooks.json` is a separate source and still loads. A project-root `pi` posts via the project-mode activity extension `reconcile.ts` writes (`../piActivity.ts`, token label `pi`).
- `../codexStopHook.ts` owns compatible command syntax: observed Codex 0.144.1 used whitespace-split direct argv; 0.157 used Windows PowerShell 5.1. Forward stdin activity JSON with `-d@-` (Windows: `cmd /c curl … -d@- <url>`); bare `@-` fails PowerShell parsing, and bare `curl` resolves to `Invoke-WebRequest` there.

Invariant: after `SessionEnd` (or `endProjectSession`), the session id is held in a short recently-ended guard. Any late or reordered hook for that id is dropped so a ghost node cannot reappear. A post-`Stop` removal is NOT remembered as ended — the session's next turn must bring its node back.

Invariant: `../projectClaudeHooks.ts` read-modify-writes the user's own `<project>/.claude/settings.local.json` from three writers (hook install, hook removal, auto-memory reconcile). They are serialized per file — an overlapping reconcile (second project open / settings save) used to interleave them and drop one writer's change. A file that doesn't parse, or whose `hooks` (or an event Lattice adds to) isn't the documented object/array shape, is left byte-for-byte alone. Only `ENOENT` means "no file yet": any other read failure (`EBUSY`/`EPERM`/`EACCES` — an editor or AV scanner holding it on Windows) aborts the write, since treating it as absent once replaced the user's whole file with just Lattice's hook entries (`../__tests__/projectClaudeHooksMalformed.test.ts`).

Command reference (from `backend/`): `npm run build`, `npm test`, `npx tsc --noEmit`.
