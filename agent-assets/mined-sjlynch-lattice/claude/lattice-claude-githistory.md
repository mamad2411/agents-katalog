# backend/src/gitHistory

Backs the frontend timeline scrubber (`GET /api/git-history`, served by `routes/health/gitInfo.ts`). **One** `git log --name-status -M` round-trip per request returns every commit *and* its changed-file list, so the scrubber can derive each drag-range's change map purely client-side without re-hitting the backend. `../gitHistory.ts` is the public shim (`getGitHistory` + the types).

## Contract

- `index.ts` — git execution. `getGitHistory` checks `--is-inside-work-tree`, then runs `git log -<N> --no-merges --name-status -M --format=…`, `git status --porcelain=v1 -z`, `git ls-files -z` (the tracked set behind `deletedPaths`), and `computeStatusSignature` in parallel. `clampLogLimit` bounds N to **1–50**. A non-zero exit (no commits yet, shallow repo, …) yields an empty result rather than an error.
- `deletedPaths.ts` — `computeDeletedPaths(commits, uncommitted, tracked)`: which of the paths mentioned in the history no longer exist. This is the timeline's **ghost-node set**, and it is computed here because the frontend provably cannot derive it. Two tempting client-side shortcuts are both wrong: (a) *"a history path missing from the scan was deleted"* — the scan only collects `SOURCE_EXTS` files while `git log --name-status` is unfiltered, so every tracked image/font/`.ico`/extension-less name (`.gitignore`) looked deleted and got drawn as a grey disc + red ring on the commit that ADDED it; (b) *"the path's newest status in log order is `D`"* — `git log` sorts by commit date and `--no-merges` drops the merges, so a sibling branch's `M` can sort after the branch that actually deleted the file. **That second one is not exotic for Lattice — running every task on its own branch is the product**, and it hid a real deletion in Lattice's own history (two children of one parent, 36 minutes apart). `git ls-files` answers it directly and order-free (it reads the index, so staged adds/deletes are already accounted for); the one thing it can't see — a tracked file deleted in the working tree but not staged — is subtracted from the porcelain status. A `null` tracked set means the probe failed and yields `[]`: losing the ghosts for one request beats declaring every history path deleted.
- `signature.ts` — `computeStatusSignature(repoRoot)`: a compact fingerprint of the exact state the scrubber renders — `git status --porcelain=v2 --branch -z` (the `# branch.oid` header carries HEAD; entries carry every dirty path) hashed to a short sha1. Returned as `GitHistoryResult.signature` **and** used by the `../gitStatus.ts` watcher to decide whether a filesystem change actually moved the repo state; both run the identical command so their values always agree. Never rejects (returns `''` on a missing repo / vanished cwd) so a watcher recompute can't unhandled-reject.
- `parseLog.ts` — splits the log on a custom `␃COMMIT␃` header sentinel (metadata fields joined by an exotic `␟` separator so ordinary commit subjects don't collide; the last field is the multi-line body `%b`, closed by a `␃ENDMSG␃` marker, so the name-status block starts after that marker — not after the first newline), then parses each name-status block. A rename/copy (`R…`/`C…`, surfaced because of `-M`) is **decomposed into a delete of the old path + an add of the new** (carrying `oldPath`) so the graph can ghost the old node and green-ring the new one. git emits newest-first; we reverse to oldest→newest to match the scrubber's left-to-right ticks.
- `parseStatus.ts` — parses the NUL-separated `git status` porcelain into dirty-path changes (a rename target consumes the following NUL token as its old path). Index + worktree codes collapse to a single status per path by priority **D > A/R > M**. Unmerged (conflict) records are read by what is on disk: only `DD` is a deletion; `DU`/`UD` keep the surviving side, so they are `M` (as `D` they ghosted a present file via `deletedPaths`).
- `parserShared.ts` — the sentinels, `normalizeGitPath` (backslash→slash), `unquoteGitPath` (git still C-quotes a log path holding a quote/backslash/control char even under `core.quotePath=false`; POSIX-only names), `parseNameStatusToken` (`T` type changes read as `M`), and the status-priority merge shared by both parsers.
- `types.ts` — `GitCommit` / `GitCommitChange` / `GitFileStatus` / `GitUncommitted` / `GitHistoryResult` (which carries `deletedPaths`).

Split: **parsing + derivation** (`parseLog.ts` / `parseStatus.ts` / `parserShared.ts` / `deletedPaths.ts` — pure, unit-tested in `__tests__/gitHistoryParsers.test.ts` and `__tests__/gitDeletedPaths.test.ts`) vs **git execution** (`index.ts`).
