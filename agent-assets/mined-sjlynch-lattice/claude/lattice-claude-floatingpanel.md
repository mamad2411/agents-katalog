# frontend/src/components/floatingPanel

- `geometry.ts` owns viewport padding, position clamping, initial placement, and the persisted `{ pos, size }` localStorage shape.
- `FloatingPanel` / `useFloatingPanelState` accept optional `defaultPosition` for first-open placement (Security uses the right edge). Saved geometry takes precedence, and placement is still clamped to the viewport.
- `hooks.ts` is a re-export barrel only (`useFloatingPanelState`, `panelForEscape`, `useFloatingPanelEscape`, `usePanelDrag`, `usePanelResize`); `../FloatingPanel.tsx` and tests import from it, so new hooks go in the concern modules below and are re-exported here. `../FloatingPanel.tsx` should stay focused on portal markup and wiring.
- `usePanelGeometry.ts` — `useFloatingPanelState`: `pos`/`size` state seeded from storage, the open-clamp, the `maximized`/`toggleMaximize` toggle, and persistence. Writes are **coalesced** through `createGeometryWriteQueue`: drag/resize change geometry on every mousemove, so each key's latest `{ pos, size }` is written at most once per animation frame, and flushed synchronously on unmount, on `pagehide`, and before a mounting panel reads its key — the stored value always ends where a write per change would have left it. Pinned by `__tests__/floatingPanelGeometryWrites.test.ts`.
- `panelEscapeStack.ts` — the module-level open-panel stack, `panelForEscape`, and `useFloatingPanelEscape` (see Escape below). The stack must stay a single module instance.
- `useDocumentDragGesture.ts` — the document `mousemove`/`mouseup` listener lifecycle for one pointer gesture (start/stop, detached on mouseup and unmount).
- `usePanelDragResize.ts` — `usePanelDrag` (titlebar, honours `.fp-no-drag`, clamped to the viewport) and `usePanelResize` (bottom-right grip, bounded by `minSize` and the viewport), both on `useDocumentDragGesture`.
- Maximize/restore (OS-window style): double-clicking the titlebar (or the top-right maximize icon next to Close) fills the window; toggling back restores the exact prior `pos`/`size` (left untouched while maximized). Drag/resize are disabled while maximized. Titlebar controls carry `.fp-no-drag` so a double-click on the search box / buttons never maximizes.
- Escape: several panels can be open at once (no backdrop), so `useFloatingPanelEscape` keeps an open-order stack and only ONE panel handles a given Escape — the panel the key was pressed in, or the most recently opened one when nothing is focused (target = body). Focus in a control outside every panel closes none. Inner layers (`Modal`, task overlays via `shared/useEscapeToClose`, `SettingsInfo`) stop propagation in the capture phase first.
- Non-modal: the panel is `role="dialog"` WITHOUT `aria-modal`, and uses `useFocusTrap(open, { trapTab: false })` — focus moves in on open (unless a child already has it) and returns to the opener on close, but Tab is never wrapped and the panel never joins the modal trap stack. Panels have no backdrop and sit side by side, so the old trap pulled Tab from older panels (and from the page) into the newest one. Real modals (`Modal`, confirms, folder picker) keep their trap. Pinned by `__tests__/focusTrapNonModal.test.ts`.
