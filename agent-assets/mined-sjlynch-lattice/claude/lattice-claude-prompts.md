# frontend/src/components/workflows/prompts

Raw markdown bodies for built-in workflow quick-add prompts, plus the rules for
the TS modules (one level up) that surface and tailor them.

## Map

- `*.md` — prompt bodies, imported `?raw` by `../defaultPrompts.ts`.
- `../defaultPrompts.ts` — `DEFAULT_PROMPTS` chip metadata (id / title / label /
  icon / body / optional `tools`). Bodies must stay self-sufficient: a chip may
  be the only step a user runs.
- `../promptTemplates.ts` — `PROJECT_AWARE_PROMPTS` (which ids get a stack
  variant) and `promptWithProjectVariant` / `promptsWithProjectVariants`.
- `../projectStackDetection.ts` — `PROJECT_STACKS`, framework signals,
  `detectProjectPromptProfile` (which stacks a scan matches + their guidance).
- `../projectPromptVariants.ts` — facade re-exporting the two above; import from
  it. Only the refactor / bug-catcher prompts are project-aware.

## Invariants

- **Every prompt here must be planner-only.** A workflow step runs under
  `WORKFLOW_STEP.md`, which forbids editing project files or committing — the
  step's only output is Lattice task-board entries. A prompt that says "do the
  work" or "commit your work" hands the agent contradictory instructions, and
  one resolved that by committing straight to the repo. Phrase every prompt as
  *file tasks for* the work.
- **These bytes must equal the backend's copy.** A quick-add that was ever
  reworded has an entry in `backend/src/workflows/defaultPromptMigrations.ts`
  (add one the first time you reword a prompt) whose `current` must match
  the `.md` byte for byte (CRLF-normalized, trailing whitespace trimmed);
  `backend/src/__tests__/defaultPromptMigrations.test.ts` fails on drift. So
  rewording a prompt is a two-file change: also append the old body to that
  entry's `legacy` (saved workflows hold a copy and are migrated on load) and
  update `current`. Otherwise keep bytes stable when refactoring components.
- A chip may carry `tools` (`opengrep.md` → `tools: ['opengrep']`): the seeded
  step runs that pre-run tool before its harness spawns, and the body is
  written against the report it leaves beside the brief
  (`OPENGREP_FINDINGS.md`). The "Security review (Opengrep)" template in
  `src/workflowTemplates.ts` imports the same body — one copy to keep
  planner-only.
- Don't duplicate stack detection in the markdown; project variants are
  generated by `../promptTemplates.ts` + `../projectStackDetection.ts`.
- `{{user_instructions}}` is appended by `withUserInstructions`
  (`../promptVariables.ts`), not written here, unless a template needs a
  different placement.
