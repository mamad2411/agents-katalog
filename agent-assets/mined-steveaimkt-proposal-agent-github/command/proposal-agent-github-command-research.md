`output/$ARGUMENTS/rfp_analysis.md` 기반으로 웹 리서치를 수행합니다. `research` 스킬을 사용하세요.

## 1. 전제 확인

`output/$ARGUMENTS/rfp_analysis.md` 또는 `mkt_analysis.md` 를 읽습니다.
없으면 중단: "먼저 `/analyze $ARGUMENTS` 를 실행해주세요."

프로젝트명, 유형, 과업 범위, Pain Point 3개를 확인하고 리서치 키워드를 도출합니다.

## 2. 4개 병렬 리서치

네 리서처를 **동시에** 실행합니다.

| 리서처 | 영역 | 필수 산출 |
|--------|------|----------|
| **시장환경** | 시장 규모·성장률·트렌드·정책 | 데이터 포인트 2개+ |
| **경쟁벤치마킹** | 유사 사업 3~5건, 전략·성과 비교 | 사례 3건+ |
| **타겟인사이트** | 인구통계·행동패턴·소비 트렌드 | 데이터 포인트 2개+ |
| **BP·KPI** | 국내외 성공사례 + 산업 평균 KPI | 사례 3건+, KPI 수치 |

각 영역당 WebSearch 2~3회, 유용한 결과는 WebFetch로 원문 확인.

## 3. research_brief.md 작성

`output/$ARGUMENTS/research_brief.md` 로 저장.

**모든 데이터에 출처(기관명 / URL / 발행연도) 필수** — 체크리스트 2-2 MUST.
출처를 못 찾은 데이터는 **버립니다.** 추정치로 채우지 마세요.

포함 항목:
- 영역별 발견 + 출처
- Planner 활용 가이드 (Win Theme 참고, KPI 산출근거, 핵심 Evidence Top 10)
- 데이터 신뢰성 표기 (최근 2년 이내 여부)

## 4. 보고

영역별 핵심 발견 1줄씩 요약하고, 체크리스트 2-1~2-5 판정 후 컨펌 요청.
출처 없어 버린 데이터가 있으면 **명시적으로 보고**하세요.
