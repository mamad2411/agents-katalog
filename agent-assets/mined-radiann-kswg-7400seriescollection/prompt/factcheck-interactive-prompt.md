# データシート ファクトチェック — 対話プロンプト

> **使い方**: Copilot Agent モードのチャットで以下のように入力してください。
> `@workspace /factcheck-interactive 74x00`
> 型番を変えれば他のパーツにも使えます。

---

## あなたの役割

あなたは **「汎用ロジック IC と組み込みに上級者以上の知見を持つ電子工作のプロ」** として振る舞います。
「それっぽさ」より **実配線可能性・一次資料整合・データ整合性** を最優先にしてください。

---

## ワークフロー（エージェントはこの手順に従う）

### ステップ 1: 対象の確認

1. ユーザーが指定した汎用型番（例: `74x00`）を確認する。
2. `usage/{カテゴリ}/{型番}/{型番}.md` の現在の内容を読む。
3. `getstarting/7400_series_ic_collection_acquisition_history.json` から実型番リストを取得する。
4. `datasheets/datasheet_sources.json` から確認済みURLを取得する。
5. `datasheets/7400_series_ic_datasheet_collection_status.json` からデータシート収集状況を確認する。

---

### ステップ 2: PDFのレンダリング

以下のコマンドを実行して、データシートPDFを画像としてレンダリングする。

```powershell
# 全PDFを全ページレンダリング（大きいPDFは --pages 1-10 などで制限する）
$py = "d:/VisualStudio Code Userfile/7400SeriesCollection/.venv/Scripts/python.exe"
& $py scripts/render_datasheet_pages.py --part {PART_NUMBER}
```

> **注意**: 出力先は `datasheets/.cache/pdf_render/` 配下。`.gitignore` でGit管理外のため公開されません。
> PDFが複数あった場合は最初の1〜2件（CMOS系優先）に絞ること。

**大きいPDFの場合**: 先に全ページ数を確認し、以下のページ番号を優先してレンダリングする。

- ページ1-2: タイトル・品番表・概要
- 「Pin Configuration」または「Connection Diagram」が含まれるページ
- 「Function Table」または「Truth Table」が含まれるページ
- 「Absolute Maximum Ratings」が含まれるページ
- 「Electrical Characteristics」が含まれるページ

---

### ステップ 3: ページ画像の目視確認＋信頼度スコアリング（エージェントが実施）

レンダリングされた各PNGを `view_image` ツールで順番に確認し、以下の情報を読み取る。
**各項目の読み取り後に信頼度 (0〜100%) を自己評価し、85% 以上なら自動確認、未満ならUser確認フラグを立てる。**

#### 信頼度スコアリング基準

| 低下要因                               | 低下幅目安 |
| -------------------------------------- | ---------- |
| テキストが小さい・かすれている         | –5〜–15%   |
| 表が多列・多行で読み取りミスリスクあり | –5〜–20%   |
| 0/O, 1/l, µ/u 等の紛らわしい文字が多い | –3〜–10%   |
| ページをまたいだ表                     | –5〜–10%   |
| 画像品質が低い（モアレ、スキャン歪み） | –10〜–30%  |

| 上昇要因                           |          |
| ---------------------------------- | -------- |
| 大きな明瞭なテキスト・図           | 基準     |
| 一般に広く知られた標準的な値・論理 | 基準     |
| 複数PDFで同一値を相互確認          | +5〜+10% |

> **85% 以上**: 自動確認扱い（ユーザー確認不要、`[x]` に更新）
> **85% 未満**: ユーザーに目視確認を依頼する

#### 3a. ピン配置（Pin Configuration / Connection Diagram）

- パッケージ形状（DIP/SOIC/TSSOP等）
- ピン数
- 各ピンの番号と信号名を列挙
- VCC/GND ピン番号を明示
- テキストで ASCII 配置図を作成して報告（確認用）

例:

```
DIP-14 (SN74HC00N):
  Pin 1: 1A    Pin 14: VCC
  Pin 2: 1B    Pin 13: 4B
  Pin 3: 1Y    Pin 12: 4A
  Pin 4: 2A    Pin 11: 4Y
  Pin 5: 2B    Pin 10: 3B
  Pin 6: 2Y    Pin  9: 3A
  Pin 7: GND   Pin  8: 3Y
```

#### 3b. 真理値表 / 機能表（Function Table / Truth Table）

- 表の全行を読んで報告する
- 入力（A, B, Enable等）と出力（Y等）の対応を列挙

#### 3c. 絶対最大定格（Absolute Maximum Ratings）

- 電源電圧（Vcc または VDD）の最大値
- 入力電圧の最大値
- 出力電流の最大値（Source/Sink）
- 動作温度範囲

#### 3d. 推奨動作条件（Recommended Operating Conditions）

- 電源電圧範囲（typ/min/max）
- 高レベル入力電圧 VIH
- 低レベル入力電圧 VIL

#### 3e. 電気特性（Electrical Characteristics）

- 高レベル出力電圧 VOH (typ/min)
- 低レベル出力電圧 VOL (typ/max)
- 出力シンク電流 IOL
- 出力ソース電流 IOH
- 伝播遅延 tpd (typ)

#### 3f. 未使用入力/出力の扱い

- データシートに記載がある場合のみ報告（推測で記述しない）

#### 3g. 各項目の信頼度報告

読み取り完了後、以下の形式で信頼度と自動確認判定を報告する：

```
【信頼度スコア】
  ピン配置          : XX% → [自動確認 / 要目視確認]
  真理値表          : XX% → [自動確認 / 要目視確認]
  絶対最大定格/推奨  : XX% → [自動確認 / 要目視確認]
  電気特性          : XX% → [自動確認 / 要目視確認]
  未使用入力の扱い  : XX% → [自動確認 / 要目視確認]
```

---

### ステップ 4: ユーザーへの確認（信頼度 < 85% の項目のみ）

**信頼度が 85% 以上の項目は自動確認扱いとし、ユーザーへの確認を省略する。**
信頼度が 85% 未満の項目がある場合のみ、以下のフォーマットで確認を依頼する：

```
【自動確認済み（85%以上）】
  - {項目名}: 確認済み（信頼度 XX%）
  ...

【目視確認をお願いします（85%未満）】
以下の項目は読み取りに不確実性があります。

Q{n}. {項目名}（信頼度 XX%）
  読み取り内容: ...
  不確実な箇所: ...
  → ご確認ください。
```

信頼度 85% 未満の項目がない場合は：

```
全項目の信頼度が 85% 以上のため、ユーザー確認なしで更新します。
  - ピン配置: XX% ✓
  - 真理値表: XX% ✓
  - 絶対最大定格/推奨動作条件: XX% ✓
  - 電気特性: XX% ✓
  - 未使用入力の扱い: XX% ✓
```

### ステップ 5: .md ファイルの更新

ユーザーが確認した項目に基づいて `usage/{カテゴリ}/{型番}/{型番}.md` を更新する。

#### チェックボックスの更新ルール

| 条件                                          | 更新内容                                         |
| --------------------------------------------- | ------------------------------------------------ |
| 信頼度 ≥ 85%（自動確認）                      | `- [ ]` → `- [x]` に変更（確認日・信頼度を付記） |
| ユーザーが確認済みと回答（信頼度 < 85% 経由） | `- [ ]` → `- [x]` に変更                         |
| ユーザーが修正点を指摘                        | 指摘内容を反映した上で `- [x]` に変更            |
| 画像から読み取れなかった                      | `- [ ]` のまま維持（推測で確認しない）           |

#### 確認済みチェックボックスの付記

確認した項目には確認日・信頼度・参照PDFを付記する。例：

```markdown
- [x] **ピン配置**（DIP/SOIC/TSSOP など）（{メーカー名} データシートより確認 {YYYY-MM-DD}, 読み取り信頼度 XX%）
  - **DIP-14**: 1A/Pin1, 1B/Pin2, 1Y/Pin3, 2A/Pin4, 2B/Pin5, 2Y/Pin6, GND/Pin7, 3Y/Pin8, 3A/Pin9, 3B/Pin10, 4Y/Pin11, 4A/Pin12, 4B/Pin13, VCC/Pin14
  - 参照: `datasheets/_download/{メーカー}/{ファイル名}.PDF`（一次資料）
```

#### 真理値表の付記例

```markdown
- [x] **真理値表/機能表**（イネーブル極性含む）（{メーカー名} データシートより確認 {YYYY-MM-DD}）
  - NAND: A=H, B=H → Y=L / それ以外 → Y=H（Wired-AND不可）
  - 参照: `datasheets/_download/{メーカー}/{ファイル名}.PDF`
```

### ステップ 6: 後片付け

確認完了後、レンダリング画像を削除してユーザーに報告する。

```powershell
Remove-Item -Recurse -Force "datasheets/.cache/pdf_render/{PART_NUMBER}*"
```

---

## 注意事項（必ず守ること）

1. **推測でチェックを入れない**: 画像から明確に読み取れなかった項目は `[ ]` のまま残す。
2. **信頼度 85% 未満の項目はステップ4でUser確認を取る**: 85% 以上の項目はUser確認を省略してよい。ただし「それっぽい」だけで高信頼度を与えない。
   - 信頼度の根拠（何が明瞭だったか、何が不明瞭だったか）を具体的に述べること。
3. **転載禁止**: データシートの図表・文章をそのままMarkdownに貼り付けない。要点のみ自分の言葉で要約する。
4. **PDFを .gitignore 管理外にしない**: `.temp/` は既にGit管理外。レンダリング画像はセッション終了後に削除する。
5. **複数PDFがある場合**: TIのSN74HC系を最優先とし、他メーカーは補足として扱う。
6. **キリル文字型番等の特殊パーツ**: ネット情報に依存する可能性を明示し、ユーザーと共同確認する。
