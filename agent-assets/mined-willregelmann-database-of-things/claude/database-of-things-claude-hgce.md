# HGCE (High Grade Cosmic Era) — curation hints

The newer High Grade prefix for the Cosmic Era/Gundam SEED timeline —
distinct from [`../hggs/CLAUDE.md`](../hggs/CLAUDE.md), the original
2002-2010s SEED HG line (see [`../CLAUDE.md`](../CLAUDE.md) for why these
stay separate). Flat — one directory, one file per kit, no further
nesting, no `variants` sub-entities, same reasoning as
[`../../rg/CLAUDE.md`](../../rg/CLAUDE.md).

## Naming files: no number prefix

**Files are `<slugified-name>.yaml`** — only 24 of 55 kits (44%) have a
documented lineup number, the lowest coverage of any HG sub-line so far
(many are sports-team tie-ins, event exclusives, and other unnumbered
promotional releases) — same MG/RG/EG/PG/SD/HGUC/HGGS flat-naming
exception.

## Sourcing

Same `allpages&apprefix=HGCE ` + `redirects=1` method as
[`../hguc/CLAUDE.md`](../hguc/CLAUDE.md) — 101 raw pages resolved to 56
real targets, no `/Variants` navigational subpages.

**New unreleased-kit marker found: `{{PollsDoesNotGuarantee}}`.** One
resolved page, `HGCE ZGMF-X56S/θ Destiny Impulse Gundam`, carries this
template — it documents a 2016 fan census poll result (which mobile suit
should get the next HGCE Impulse variant) that was never actually
produced as HGCE (a Real Grade version was released years later instead).
Doesn't match any of the previously-documented unreleased-kit keyword
patterns (`{{Canceled}}`, "Under Consideration", etc. — see
[`../../rg/CLAUDE.md`](../../rg/CLAUDE.md) and
[`../../pg/CLAUDE.md`](../../pg/CLAUDE.md)) and has no proper infobox at
all, which is what excluded it here — but don't rely on "no infobox" as
the only signal on a future sub-line; a poll/rumor page could in
principle still carry a stub infobox. Grep for this template too.

**Images**: 54 of 55 kits had a usable infobox `image`; one
(`ZGMF-MM07 Z'Gok (Clear Color Ver.)`, a Gundam Base exclusive) has
completely empty Packaging and Stock Photos galleries on its own wiki
page — genuinely no image available, stays imageless. Same kit also has
no `Release Date` at all (not even a "See below" deferral) — a real,
sparse-documentation gap, not a parsing bug.
