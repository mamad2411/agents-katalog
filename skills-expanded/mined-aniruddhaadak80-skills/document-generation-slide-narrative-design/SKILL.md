# Design slide decks as narratives, not bullet dumps

> Assertion-per-slide structure, visual-first layouts, and appendix discipline for deck generation.

**Track:** ✍️ Technical Writing · **Domain:** Document Generation · **Level:** intermediate · **~35 min**

**Who this is for:** Technical Writers, Developer Advocates, Engineers Who Document, Content Leads

## When to Use This Skill

Assertion-per-slide structure, visual-first layouts, and appendix discipline for deck generation.
Use it whenever a matching task appears in conversation — the agent loads these instructions on demand.

## Steps

1. Write the slide TITLES first as a story outline; if titles alone don't persuade, fix the narrative
2. One assertion per slide; the title IS the assertion, body is evidence
3. Prefer a single strong visual over six bullets wherever truth allows
4. Standardize layout masters: title, content, split, quote — nothing bespoke
5. Push all depth to appendix slides referenced by name
6. Export-check readability at projector distance and phone size

## Common Pitfalls

- 40-slide decks where every slide is a document page
- Animation substituting for argument
