# Stock Work Project

这是一个持续使用的 A 股辅助研究项目。

每次开始任务时：

1. 先把本 `AGENTS.md` 所在目录识别为实际项目根目录；不得假定项目一定安装在 `D:\stock-work`。
2. 如果 `.agent/STATE.md` 缺失、首次全项目扫描不是 `DONE`、生命周期为 `UNINITIALIZED/INITIALIZING`，或项目位置/环境明显变化，必须在初始化判断前执行只读的全项目扫描：盘点本地文件名、目录结构、项目配置、Python 环境、已安装 Skills/工具、Git 仓库与 commit、依赖清单、代码、测试、数据资产和报告目录。
3. 扫描环境时只检查项目内及相关环境变量、常见安装位置，不默认扫描整个硬盘；不得跟随指向项目外的链接。大型数据、缓存、`.git` 对象、虚拟环境内部包和密钥只检查存在性与必要元数据，不读取或输出敏感内容。
4. 扫描结果必须分为“已存在、可复用、缺失、冲突”，并指出实际路径和与模板不同之处。扫描阶段不得安装、克隆、覆盖、移动、删除或重建任何内容。
5. 完成扫描后，必须使用读取工具加载 `.agent/AGENT.md` 和 `.agent/STATE.md`；以扫描事实校准生命周期和实际环境，再决定继续使用、修补或初始化。已处于 `READY` 且没有环境变化时，只做根目录、核心文档、解释器和关键仓库的轻量漂移检查；发现变化再重新全扫。
6. 再按 `.agent/AGENT.md` 的要求读取与本次任务有关的其它文档。
7. 不要仅根据历史会话记忆、模板路径或文件存在性推断当前规则、数据或部署状态。
8. `.agent` 中的当前文档是本项目规范的事实来源；实际文件、环境和仓库状态是部署事实来源，两者冲突时先记录并处理冲突，不得静默覆盖。
