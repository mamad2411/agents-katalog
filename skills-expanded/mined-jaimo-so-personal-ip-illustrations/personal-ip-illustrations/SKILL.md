# 个人 IP 正文配图

## 核心定位

将中文内容中的一个关键判断、流程、状态、结构或隐喻，转成一张 16:9 横版正文配图。默认主角是固定的个人 IP：棕色蓬松短发、黑色圆框眼镜、棕色大眼、浅蓝灰衬衫的少年。

采用全手绘视觉语言：参考图只用于锁定角色身份；IP 主角、物件、连线、箭头与短批注都以白底细线手绘呈现。角色保留高辨识度，但不保留 3D 材质、体积光或玩偶渲染。目标不是商业海报、PPT 信息图或儿童表情包，而是让读者先看见一个有记忆点的动作，再迅速理解内容。

## 先读这些参考

按任务需要读取，不要一次加载全部：

- `references/ip-character.md`：固定角色的外观、身份锚点、可变项和禁忌。生成或编辑图片前必读。
- `references/style-dna.md`：全手绘角色与结构的风格 DNA、颜色与留白规则。
- `references/composition-patterns.md`：适合正文的结构类型、原创隐喻方法和构图禁忌。
- `references/prompt-template.md`：单张生图与局部编辑的提示词模板。
- `references/qa-checklist.md`：角色一致性和成图质量检查。
- `assets/ip-reference.jpg`：唯一的默认角色参考图。仅用于锁定角色身份；不要复刻其中的室内背景、自拍角度或姿势。

## 工作流

### 1. 消化内容并找认知锚点

读取用户给出的文章、主题、链接、Markdown、Notion 内容或截图。找出最值得视觉化的一个动作、变化或结构，例如：卡住、分流、承接、过滤、积累、对比、回路、取舍、搭桥。

不要平均配图。短内容建议 1–3 张，普通文章默认 4–8 张；每张只讲一个锚点。

### 2. 先输出策略（仅在用户要规划时）

输出 shot list。每张写明：

- 放在什么段落后；
- 主题与核心意思；
- 结构类型；
- IP 主角在做的关键动作；
- 主物件与信息流；
- 2–5 个建议中文标注词。

优先选择主角能亲自完成的动作。若移除主角后隐喻仍完整成立，重构画面，让他成为推动、搬运、判断、修补或连接的一部分。

### 3. 单张生成

当用户要求“生成、做图、输出图片”时，逐张调用图像生成工具，不要把多张图拼成一张。每次生成前：

1. 读取 `references/ip-character.md`、`references/style-dna.md`、`references/prompt-template.md` 和 `references/qa-checklist.md`。
2. 用图像查看工具检查 `assets/ip-reference.jpg`；调用图像生成工具时，把该文件作为唯一角色参考图传入 `referenced_image_paths`。不要同时传 `num_last_images_to_include`。
3. 依据当前内容发明新的低科技物理隐喻；不要复用旧项目或上一张图的主物件、动作和构图。
4. 在提示词中明确角色身份锚点、画面动作、手绘结构、白底留白、中文标注和禁忌。

默认使用“全手绘角色模式”：角色和所有结构均以细黑手绘线稿呈现，使用极少量平涂或淡色点缀保留棕发、眼镜、肤色和蓝灰衬衫。只有用户明确要求“保留 3D 角色”时，才恢复 3D 主角与手绘结构的混合模式。

### 4. 检查与迭代

按 `references/qa-checklist.md` 检查。优先重生成或编辑以下问题：角色像了参考图却只在角落卖萌、发型或眼镜丢失、长成不同人物、画面变成海报/PPT、标注太多或错字、主角与背景比例失衡、白底不干净。

编辑已有图片时，保留角色身份、画幅、已正确的物件与构图；只改用户指明的区域。去除错误文字时，用干净白底补齐，不添加新标题。

### 5. 保存交付

在当前 workspace 中保存到：

```text
assets/<article-slug>-personal-ip-illustrations/
```

按顺序命名：

```text
01-topic-name.png
02-topic-name.png
```

不要覆盖已有图片，除非用户明确要求。交付时说明图片数量、每张用途、保存路径，以及哪些是可选图。

## 输出边界

- 默认输出 16:9 PNG 正文配图和简洁 shot list。
- 不把文章全文塞进图里，不制作复杂架构图、课程页、真实 UI 截图、商业 KV 或可编辑 SVG。
- 不擅自改变 IP 的性别、年龄感、发色、眼镜或核心面部气质。
- 如果用户提供新的正式角色设定或要求替换 IP，先确认要替换 `assets/ip-reference.jpg`，再将其作为新的唯一参考。
