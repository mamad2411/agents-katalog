# MVP Research

Create `docs/EvidencePack-[AppName].md`.

## Inputs

Read `docs/IdeaBrief-*.md` when available. Ask for missing competitors, examples, or links.

Use current web search when market, competitor, pricing, model, or tool information could be stale. Cite source URLs with access dates for major claims.

## Output

Include:

- Go / Narrow / Pause verdict
- User and problem evidence table
- Competitor/workaround table
- Feature pattern and gaps
- MVP feature recommendation
- Monetization clues
- Technical feasibility
- Source notes and uncertainties

## Rules

- Prefer evidence tables over long essays.
- Separate facts, assumptions, and uncertain claims.
- If evidence is weak, recommend a narrower MVP rather than forcing a positive conclusion.
