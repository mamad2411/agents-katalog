---
name: digest
description: 总结一段时间内当前项目 git 提交完成的内容与类型百分比，默认近一周，可指定日期范围或相对范围。触发场景：工作总结、周报、阶段汇报、统计提交分布、digest
---

统计当前项目指定时间范围内的 git 提交，按固定格式输出内容总结与类型占比。数据以 git log 为准，不凭记忆推断。

## 流程

1. **解析时间范围**（一律 UTC+8，与 AGENTS.md 时间规范一致）：
   - 无参数：默认近一周（今天往前 7 天，含今天）。
   - 日期范围：`/digest 2026-09-01 2026-09-15`（两参数，闭区间；缺结束日期则以今天为结束）。
   - 相对范围：`/digest 近3天`、`/digest 近一个月`、`/digest 本月`（本月为当月 1 日至今）。
   - 参数无法解析时，先说明默认按近一周执行，不中断。
2. **一次调用获取提交数据**，不要分多次执行：
   ```bash
   git log --since="<起始> 00:00:00" --until="<结束> 23:59:59" --date=format:'%Y-%m-%d %H:%M:%S' --pretty=format:'%h|%ad|%s' --shortstat
   ```
   提交量大时（>200 条）不追加读取更多明细，以 subject 汇总为主。
3. **解析类型**：提交信息按项目规范 `YYYYMMdd：类型：描述` 解析，类型取 `功能 | 修复 | 优化 | 重构 | 文档 | 样式 | 测试`；不符合规范的提交归入「其他」并在明细中原样保留描述。
4. **统计占比**：每类提交数 ÷ 提交总数，百分比保留一位小数（如 `37.5%`）；按占比降序排列。类型映射冲突时（如同一条含多个类型词）以第一个类型词为准。
5. **按固定格式输出**（见下），逐字遵守结构，不增删章节。

## 输出格式（固定）

```markdown
# 工作总结：{起始日期} ~ {结束日期}

**提交总数**：{N} 条

## 类型占比

| 类型 | 提交数 | 占比 | 分布 |
|------|--------|--------|------|
| {类型} | {n} | {p}% | {█×k}{·×(20-k)} {p}% |

（条形图共 20 格，k = round(占比/5)；行按占比降序）

## 完成内容

### {类型}（{n} 条，{p}%）
- `{hash}` {描述}

（每类一节，节内按时间正序；占比为 0 的类型不输出该节）

## 概要

- {按类型占比与主要变更归纳 2~4 条，每条一句话，说明本阶段完成的主要内容与重心}
```

## 约束

- 时间范围内无提交时，直接说明「时间范围内无提交」并给出时间范围，不输出空表。
- 只统计当前分支可见的提交；merge commit 不参与类型统计，单独计入提交总数并在概要中说明。
- 描述一律取提交信息原文，不改写、不翻译；归纳只出现在「概要」节。
- 输出中所有日期使用 `YYYY-MM-dd`，时间为 `YYYY-MM-dd HH:mm:ss`。
