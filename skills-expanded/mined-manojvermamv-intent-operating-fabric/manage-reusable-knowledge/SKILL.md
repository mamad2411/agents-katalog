# Manage Reusable Knowledge

## Procedure

1. Accept only an explicitly distilled candidate, never raw experience.
2. Reject secrets, private paths, personal data, guessed universals, or authority changes.
3. Check applicability, versions, evidence summary, verification recipe, failures, and counterexamples.
4. Store as `candidate`.
5. Offer it to a suitable target machine as prior knowledge.
6. Require that target to execute the verification recipe locally and return an independent record.
7. Promote only under owner policy; otherwise keep, reject, or supersede explicitly.

## Boundary

Promotion distributes knowledge, not authority. Every new machine must still verify locally.
