# SeaLeap 家居品类多站点联投

先确定要速度、规模质量还是利润，再逐站确认家居商品是否具备测试条件。组合只是候选路线，最终按当前证据选择。

## 输入

美国站 ASIN 与实际销售/利润、目标国家、各站商品匹配及可售状态、尺寸/重量/危险品等限制、FBA/远程配送或其他履约成本、合规准备、本地关键词与素材、逐国预算和总上限。

## 工作流

1. 固定业务目标和源站基线，确认美国热销证据、库存与贡献利润足以支持测试。
2. 分别比较北美扩展、欧洲扩展、澳洲/中东扩展；每个国家独立核对需求、竞争、履约成本、费用、语言、规格、认证和售后。
3. 验证源站成功经验中可复用的产品事实与消费者任务，重新校准本地词、价格、币种和场景。美国表现不直接充当目标国预期。
4. 审查一键推广当前功能、目标商品及 AI 建议，逐国确认预算和竞价，并计算汇率统一后的总暴露。
5. 在最有证据的组合中选择受控试验，固定时间窗口与成功/停止条件；启动后核对每个国家是否真正 Delivering。
6. 以逐国利润、CPC、订单 CVR、ACoS、库存和归因成熟度决定保留、扩大、调整或退出。

## 交付

三条路线比较、逐国资格和成本缺口、ASIN/本地化矩阵、预算草案、验证计划、拒绝或暂缓站点的理由。

## 证据与执行范围

- 材料中的案例、比例和时间表标为 `COURSE_BASELINE` 或 `TRAINING_CASE`；来源与口径已核验的店铺数据标为 `ACCOUNT_FACT`，用户转交但未核验的数据标为 `USER_PROVIDED`，合成练习标为 `SIMULATED`。推断标为 `HYPOTHESIS`，缺失项写 `UNKNOWN`，不补成 0。
- 先固定店铺、广告 profile、站点、ASIN、币种、数据窗口与归因口径。课程介绍的资格、界面、报告字段和功能覆盖在实际使用时核验。
- 默认交付诊断与草案。真实写入只在当前会话已授权的对象、动作和预算内执行，并保存旧值与回读结果；新增范围先取得授权。
