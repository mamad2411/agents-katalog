# Resolve Pull Request

> **Writing style:** Follow [WRITING_STYLE](../../references/WRITING_STYLE.md) for all text you write — chat messages, questions, plans, reports, and generated docs.

Turns a PR's **reviewer comments** into code fixes. It fetches the inline review comments with **MCP**. If there is no MCP, it uses the platform **CLI** (`gh`, `glab`, or a Bitbucket CLI). It sorts the comments into tasks, then hands the fixes to the **party-mode** workflow (Root Agent → developer/tester sub-agents → review → report). When the changes are accepted, it replies to and resolves each fixed comment thread.

## How to Use This Skill

1. Find the access method (MCP or CLI), then the target PR.
2. Fetch every reviewer comment with its file, line, body, author, and thread/resolved state.
3. Sort and group the comments into tasks (skip comments with no clear request and ones already resolved).
4. Hand the grouped tasks to **party-mode** — the Root Agent brainstorms, plans, gets approval, delegates to developer/tester sub-agents, and reviews.
5. After the fixes are accepted, push the branch, then reply to and resolve each fixed comment thread.
6. Report what was fixed, what was skipped (with reasons), and what is left.

## Notes

- This skill **changes code** — but never directly. All coding goes to party-mode's developer/tester sub-agents. The Root Agent never edits files itself.
- The party-mode **approval gate is required**: no fix is made until the user approves the plan.
- Only act on comments that point to a real file + line and ask for a clear change. Skip resolved threads, outdated comments, praise, and unclear notes — and report why you skipped each one.
- Never show secrets or credentials found in a comment thread. Replace them with `[REDACTED]`.
- Never add AI/agent attribution to thread replies (no "Generated by", "Resolved by Claude", "Co-Authored-By: Claude", or similar). Each reply says only what changed.
