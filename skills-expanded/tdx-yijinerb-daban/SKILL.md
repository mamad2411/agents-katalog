# 一进二量化打板（盘后建池 + 次日竞价定夺 · 本地通道）

## 为什么聚焦一进二（设计前提）

- **采样池小**：只取上一交易日**首板涨停**的股票（通常几十只），数据分析快，且可以**逐只做深度多维分析**（封板质量、板块梯队、身位），不像全市场打板那样只能粗筛。
- **更贴合实战**：一进二是有明确母体（昨日首板）的接力博弈，逻辑链清晰、可验证。

## ⏰ 两种运行时段（先判断现在是哪种）

- **模式A —— 盘后（收盘时段，约 15:00 后）**：取**当日**封住首板的涨停股（=次日一进二候选母体），逐只深度分析，**产出"次日竞价重点监测股"清单**。
- **模式B —— 次日 9:25-9:29 竞价窗口**：对监测池逐只取**实时竞价快照**，套阈值+排雷+评分+可成交性，定出当日最终一进二可打标的。

时段判断：盘后/收盘/"选监测股"→模式A；竞价/早盘/"今天打哪只"→模式B（无现成监测池则先跑模式A 再进竞价）。

- 数据全部来自**本地通达信终端**（tqcenter 直连，Python 脚本，无需 token/云端服务）。前提：终端已启动。
- **涨停池**：内置条件选股公式 `B007 沪深京涨跌停选股` 跑全A → 逐只用日K验证"确为首板（非二板及以上）"。
- **封板明细**（首封时间/开板次数/最大封单）：`get_zdt_data` 涨跌停接口；封单为量（手）×涨停价换算金额。
- **题材/涨停原因**：云端"涨停原因"接口本地无等价物 → 用 `get_relation` **概念板块近似**，输出标注 `themeSource=concept-approx`，**不臆造**。
- **量比(LB)**：本地快照无量比字段 → 竞价评分量比项自动跳过（竞价满分 70），池内统一缺失不影响排序。
- **委比(Wtb)/涨停价/流通市值**：由五档、昨收×1.1、流通股本自算。
- 事实、推断、交易动作分开写；缺失字段标注"近似/证据不足"。

## 配套运行器脚本（本地直跑，评分逻辑与 v3.2.4/442 样本校准版逐位一致）

- `scripts/run_modeA.py`（盘后建池）：B007 取当日涨停 → 日K验证首板 → 封板质量评分（封流比为主指标 + 封成比 + 开板次数 + 首封时间 + 板型）→ 输出 `modeA-result.md`（人读）、`modeA-pool.json`（**全量字段**，供模式B 读取）与 `modeA-features.csv`（**扁平特征表**，按日归档 `history/`）。
  ```
  py -3.13 scripts/run_modeA.py --top=20
  ```
- `scripts/run_modeB.py`（次日 9:25-9:29 竞价定夺）：读 `modeA-pool.json` → 逐只取实时竞价快照 → 竞价评分（高开+委比）+ 可成交性（`Now>=ZTPrice` 判顶一字买不进）+ 板块梯队身位（概念聚类排龙头/卡位/跟风）→ 综合分选最终标的 → `modeB-result.md` + `modeB-features.csv`。市场闸门触发自动停做（盘后跌停≥8 或 池均高开≤1.3%）。
  ```
  py -3.13 scripts/run_modeB.py --top=10
  ```
- `scripts/backtest.py`（攒够 ≥5 交易日跑）：读 `history/*/modeA-pool.json` + 日K回补 T+1/T+2/T+3 → `backtest-samples.csv`（分析主表）+ `backtest-report.md`。
  ```
  py -3.13 scripts/backtest.py
  ```
- 回归测试（离线，不联网不连终端）：`py -3.13 scripts/test_scoring.py` → 应 **60/60 全过**。

> 阈值已按 442 只首板真实分布校准（v3.2.4）：封流比 ≥1.5%极硬/0.8-1.5%硬/0.4-0.8%中/<0.4%近淘汰；卡位身位 -10 强降权（0/25 连板）。**v3.3.2（219 样本回测）**：封成比改四档 ≥32 +10 / 16-32 +6 / 8-16 +2 / <8 0；开板 1-2 次不扣分、≥3 次固定 −4。

## 评分体系

五大维度 0-100：① 封板质量 25 · ② 竞价表现 25 · ③ 板块梯队与身位 25（一进二命门）· ④ 资金与筹码 15 · ⑤ 位置/空间/风控 10。深度细则见 [references/scoring-rules.md](references/scoring-rules.md)。

## Workflow — 模式A（盘后：跑脚本 + 解读监测池）

1. 跑 `py -3.13 scripts/run_modeA.py`（约 1-2 分钟，几十只首板）。
2. 脚本自动完成：B007 全A选股 → 剔非主板/ST → 日K验证首板 → ZDT 明细（首封时间/开板次数/封单）→ 快照（封流比/委比/市值）→ 概念板块题材近似 → 打分排序 → 落盘三件套。
3. 解读 `modeA-result.md` 并按 Output Rules 向用户汇报：验证通过清单、监测股清单（每只标注：代码|名称|封板质量|题材与身位|监测理由|**次日竞价要盯什么**）、排雷剔除说明、一句话准备结论 + 风险提示。
4. 若脚本输出"未取得涨停清单/无首板"：先确认终端在跑、当日是否交易日，盘后数据未更新时可稍后重跑。

## Workflow — 模式B（次日 9:25-9:29 竞价：定夺）

1. 载入模式A 监测池（`--pool=` 指定，默认 `modeA-pool.json`）。非 9:25-9:29 窗口运行要提示数据非竞价口径。
2. 跑 `py -3.13 scripts/run_modeB.py`。脚本自动完成：市场闸门（v3.3.3：模式A 盘后跌停家数 ≥8 **或** 监测池竞价平均高开 ≤1.3% → **直接停做**；涨停家数仅展示，原「<40 停做」回测无效已删）→ 逐只竞价快照（高开 4.5-7% 黄金区、竞价量、五档委比）→ 可成交性（顶一字买不进标注"仅监测"）→ 概念聚类身位（龙头+15/卡位-10/跟风+2）→ 单日仅取 1 只最高分可成交标的。
3. 按七段 Output Rules 汇报（见下）。

## Output Rules

**模式A**（5 段）：1) 明日市场环境预判；2) 当日首板池（验证通过清单：代码|名称|涨幅|首封时间|封单|题材；注明剔除的非首板）；3) **次日竞价重点监测股清单**（含每只监测要点与盯盘点）；4) 排雷剔除说明；5) 一句话准备结论 + 风险提示。

**模式B**（7 段）：1) 市场环境（明确"今日是否做一进二"）；2) 监测池竞价快照；3) 候选打分表（代码|名称|高开%|封板质量|板块身位|评分|评级|可成交性，降序）；4) 首选标的详解（最高分1-2只，五维逐条给证据）；5) 排雷与"买不进"剔除；6) 操作与风控（**T+1 合规**：单票12%、单日1只、扫板入场；**当日只否决不止损**——竞价走弱/炸板则弃打或撤单，一旦成交强制持有过夜；止损/止盈在**次日 T+2** 竞价或开盘执行；弱势停做）；7) 一句话交易结论。

竞价数字标注来源（竞价窗口实时/近似）；题材标注"概念近似"。

## Hard Rules

- "首板"必须经日K验证（当日 ≥9.8% 且前两日均 <9.8%），不得混入二板及以上。
- 市场闸门触发（盘后跌停≥8 或 竞价池均高开≤1.3%）**必须停做一进二**并写明原因。闸门依据见 references/scoring-rules.md 第四节。
- 连板容错极低：宁可不做，不做孤票、不做烂板进二、不做高位透支、不做买不进的一字。
- 模式B 必须在 9:25-9:29 窗口运行；非窗口要提示数据非竞价口径。
- 字段取不到标注"近似/证据不足"，不臆造。
- 始终带风险提示：一进二失败易出大面（次日低开大跌），仅适合主线强势行情，量力而行。**注意 A股 T+1：打板当日买入无法当日止损，止损只能次日执行，须承受隔夜跳空风险。**

## 与云端原版的差异（v3.3 本地通道）

| 项 | 云端版 | 本地版 |
