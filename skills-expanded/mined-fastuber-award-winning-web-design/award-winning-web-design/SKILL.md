# Award-Winning Web Design

A studio swipe file for building distinctive, award-caliber web work instead of templated AI defaults. The knowledge lives in `references/` — a verified gallery of real sites plus signal-dense, copy-pasteable technique recipes.

## How to use it

Load files **on demand (progressive disclosure)** — the brief tells you which one or two to open. Don't dump the whole library into context.

1. **Mine signature moves, don't clone.** Each entry names a *signature move* (what makes a site memorable) and a *steal* (the concrete mechanism — a shader pattern, a GSAP recipe, a grid rule). Reproduce the mechanism; never lift a literal layout, copy, or color story.
2. **Commit to ONE aesthetic direction per brief.** Don't blend three looks into mush. Pick a direction from `aesthetic-directions.md`, then make typography, motion, color, and interaction all serve that single idea. Spend your boldness in one signature element; keep everything around it quiet.
3. **Clear the craft/performance floor.** Award sites win on *coordination* — one memorable idea, immaculate easing, choreographed load, an honest reduced-motion path, Core Web Vitals in budget — not on effect count. The failure mode of imitators is "effect soup." Run the `craft-and-performance.md` checklist before calling a build done.
4. **Escape the three AI-default looks.** Don't spend a free aesthetic axis on: (1) cream `#F4F1EA` + high-contrast serif + terracotta; (2) near-black + a single acid-green/vermilion accent; (3) broadsheet hairline rules + zero border-radius. If the brief explicitly asks for one of these, follow it — otherwise reach for a distinctive direction from the catalog.
5. **Reach for native CSS first.** View Transitions, scroll-driven animations, and `scroll-state()` before JS; GSAP/Lenis/Three.js only where the effect genuinely needs them.

## Operations

Every request is one of four operations — identify it first; full procedures + file maps live in `references/operations.md`:

- **Build** — the default: a fresh page/site from a brief, following the flow above. If the brief requires owner self-editing, add the client-editable layer (`references/client-editable-sites.md`) — annotate while building, not after.
- **Audit** — grade an existing page: diagnose the tells via `references/anti-slop.md`, score it against `references/validation-gates.md`, deliver a report (not edits).
- **Redesign** — preserve the content and IA, re-skin under ONE new direction from `aesthetic-directions.md`; ends with the validation-gates pass.
- **Study** — extract a site's design DNA into a direction brief (usually chains into Build).

## Reference files

**`references/README.md` is the full index + when-to-open map — skim it first.** The 20 reference files, grouped:

*Galleries & case studies*
- **`references/award-winning-gallery.md`** — real award sites grouped by vibe; each with its signature move and a concrete steal.
- **`references/gallery-by-vertical.md`** — the same pool re-cut by **industry** (e-commerce/DTC, editorial, SaaS, portfolios, 3D configurators, WebGPU, motion-brand). Start here when the brief names an industry.
- **`references/case-studies.md`** — 6 deep end-to-end teardowns (Igloo Inc, Lusion, Active Theory, Obys, Immersive Garden, Basement): stack + signature technique step-by-step + why it won + reproduce-vs-studio.

*Design systems*
- **`references/aesthetic-directions.md`** — *start here to choose the look.* 24 buildable directions (Cosmic Aurora, Liquid Glass, Neo-Brutalist Pop, Kinetic Type Lab, Spatial WebGL World…), each with palette, type, layout, signature, motion, reduced-motion fallback, and "when to use."
- **`references/color-systems.md`** — modern CSS color: OKLCH perceptual palettes + band-free `in oklch` gradients, `color-mix()`/relative color, `display-p3`, `light-dark()`, `contrast-color()`, animatable `@property` color.
- **`references/color-texture-atmosphere.md`** — 9 visual directions → hex palettes + CSS/SVG/canvas/shader recipes (aurora mesh, grain, glass 2.0, neo-brutalism, maximalism, duotone, organic, Y2K, dark/light).
- **`references/svg-plates.md`** — the **procedural inline-SVG "plate"** that stands in for photography across `templates/` (external images are banned): the four families in real use, deriving the drawing's `viewBox` from the grid slot, recolouring one plate through custom properties, hover mechanics, `role="img"`-vs-`aria-hidden` labelling, and node/weight budgets. *Open when the brief needs imagery and you have no photography.*
- **`references/typography-and-layout.md`** — typeface pairings + foundries, fluid `clamp()` scales, variable/kinetic type, award grids (breakout, bento, asymmetric, subgrid, container queries, scrollytelling).
- **`references/component-patterns.md`** — award-level UI chrome: sticky/shrinking headers, overlay/mega menus, footers, hero archetypes, tabs, accordion, `<dialog>`/drawer, toast, tasteful consent — each with a11y + reduced-motion.

*Motion & technique*
- **`references/motion-and-scroll.md`** — Lenis + GSAP (ScrollTrigger/SplitText/Flip/Observer), pinning, horizontal scroll, marquee, parallax/velocity-skew, native scroll-driven + View Transitions, preloaders, route transitions.
- **`references/motion-easing-and-timing.md`** — the easing/timing/choreography bible (cubic-bezier tables, duration ladder, stagger, spring/damp, one-easing-family discipline, CSS `linear()` springs).
- **`references/interaction-and-microcopy.md`** — custom/blend-mode/contextual cursors, magnetic buttons, hover reveals & image trails, drag-inertia, scroll progress (frame-rate-independent lerp), tactile forms, plus award-level microcopy.
- **`references/webgl-3d-shaders.md`** — stack selection (Three.js / R3F / drei, OGL, WebGPU + TSL), GLSL/TSL patterns (displacement, RGB-shift hover, flowmap, curl-noise GPGPU, metaballs, dithering), Gaussian Splatting, perf budgets + low-power tiers.
- **`references/responsive-mobile-craft.md`** — mobile quality floor: `svh/lvh/dvh` + safe-area `env()`, pointer/hover gating, 44–48px targets, Lenis `syncTouch`, `matchMedia` mobile fallbacks, DPR clamp.
- **`references/craft-and-performance.md`** — *the quality floor every deliverable must clear:* choreographed preloader/asset strategy, `prefers-reduced-motion`, focus/keyboard a11y, Core Web Vitals (LCP/INP/CLS), on-demand WebGL, font/lazy-media loading, pre-ship checklist.

*Process & quality gates*
- **`references/anti-slop.md`** — the consolidated AI-default tells + fixes (layout, color, type, motion, copy), ending in a pre-flight. *Open BEFORE designing;* also the diagnostic half of any audit.
- **`references/validation-gates.md`** — the numbered pass/fail ship/no-ship gates (hard gates, verdict rules, ledger). *Run AFTER the build renders, before calling it done.*
- **`references/operations.md`** — the four verbs (BUILD / AUDIT / REDESIGN / STUDY): per-operation procedure + which files to open in what order. *Open when the ask is not a fresh build.*
- **`references/build-pipeline.md`** — the machine BUILD runs on: the ordered chain of committed artifacts (design-brief contract → optional reference boards → gate sweep → identity ledger). Holds the persisted design-brief template and the cross-build anti-convergence ledger. *Open at the start of any fresh build, even a simple one.*

*Client-editable layer (v3)*

## Templates

`references/templates/` holds COMPLETE, self-contained, clone-and-adapt page templates — each folder is a working `index.html` plus a `TEMPLATE.md` marking the swap points. When a brief matches an existing vertical + direction, cloning a template is a faster, higher-floor starting point than building from scratch. **`references/templates/README.md` is the index + the "how to save a new template" convention — skim it first.** Discipline: copy a template as scaffolding, then ADAPT it to the brief (brand, copy, palette, sections) — never ship the demo brand, and re-run the `craft-and-performance.md` checklist after your edits. When you build something distinctive and reusable, SAVE it back as a new template per that README so the library compounds over time.
