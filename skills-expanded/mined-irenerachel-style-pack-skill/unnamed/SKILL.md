# 风格包

把一组图像或一个已有风格包变成可复用的视觉生产流程。两种任务模式：

- **提取模式**：从电影剧照、截图、图集或本地文件夹提取风格包 → 必须读完 `references/提取风格包.md` 和 `references/色卡规范.md` 后执行。
- **使用模式**：读取已有风格包，把剧本或创意需求拆成文生图 + 视频提示词表格，再按需生成图片或视频 → 读 `references/使用风格包.md` 后执行。

任何模式下，先读完对应的 reference 文档再动手，不要凭本文件的概述直接开工。

**图片反推原则**：凡是基于图片反推提示词，反推对象都是图片所在子文件夹的整体风格，不是单张图的内容。色调、画面和风格细节必须反推得非常精细（色温、滤镜感、饱和度、高光/阴影偏色、颗粒、锐度、光比、景深、构图骨架），使其能像同一套滤镜、构图和画面处理一样，用于优化提示词的风格输出。图片收集、数量、拼图和目录等设置保持不变。

**分组提示词 Scale 输出标准**：`分析/分组提示词/` 不是简单 prompt 汇总，而是每个视觉分组的一份独立提示词 Skill。每份分组提示词必须达到“可复现、可替换、可排错”的标准：先锁定这个分组解决的画面类型，再用一句强视觉锁固定色彩、光源、构图、主体比例和情绪；然后给出可替换变量、完整文生图提示词、视频提示词、适用镜头、跑偏风险和自检清单。禁止只写氛围词、关键词堆叠或几句泛泛描述。

**色卡是提取模式的强制交付，不是可选美化项**：每个正式视觉分组必须基于同一套 10 色同时生成两张 `1920×1080` RGB PNG：①标注色卡，严格使用 `10 色 = 3 主色 + 5 辅助色 + 2 点缀色`，每个色块标明角色编号、中文色名和大写 HEX；②完全无标题、无文字、无留白、无间距、无边框、无圆角的纯色色卡，固定为满版 `5×2` 色块。还必须生成 `分析/色卡数据.json`、`参考图/分组色卡总览.jpg` 与 `参考图/纯色色卡总览.jpg`。优先直接运行 `scripts/generate_palette_cards.py`，然后运行 `scripts/validate_palette_cards.py`。只生成其中一种色卡、只写色值、只写颜色分析、只生成一张全局色卡、只在聊天里展示颜色、或漏掉任一分组色卡，都视为未完成；缺少依赖或执行失败时必须明确报告阻塞，禁止声称风格包完成。详细规范见 `references/色卡规范.md`。

## 最高优先级红线

这三条红线存在的原因：风格迁移的价值在于"同一套视觉语言下的新作品"，一旦复用原片元素，产出就变成了侵权风险高、无法商用的换皮镜头。

### 红线 1：只借视觉语法，不借原片内容

可以参考：光影方式、色彩体系、构图习惯、镜头距离、空间压迫感、画面节奏、材质颗粒、景深和焦点策略、导演或摄影师作为风格锚点。

绝对不要复用：原片具体场景、地点、道具、服装和角色造型、人物关系、经典构图的元素组合、标志性动作或桥段，以及参考图里可被一眼识别的主体、姿态、装置、文字、品牌或符号。

判断标准：新画面和参考风格并排看，应该像同一套视觉语言下的新作品；但不能像换了主体的原片镜头。

### 红线 2：原创元素必须来自用户的新剧本或新需求

生成提示词时，先把用户给的新剧本拆成：新主体、新地点、新时代或世界观、新道具、新人物关系、新事件、新情绪目标。这些内容进入 `原创元素` 一栏。参考风格只能进入 `风格借用点` 一栏。

### 红线 3：不要把规避句写成负面提示词

不要在最终文生图提示词里堆"不要出现某电影元素"。正确做法是正向写清楚新的主体、场景和道具，让画面自然离开参考片。规避检查写在表格和自检里，不塞进最终 prompt 主体。

## 输出路径与命名

风格包名称默认使用简洁中文；用户指定了名称、语言或命名方式时，以用户要求为准。输出位置按以下优先级解析，禁止写死用户名、主目录或某台设备的绝对路径：

1. **用户指定完整输出路径**：直接使用该路径。
2. **用户指定父目录**：在该目录下创建 `[名称]-风格包/`。
3. **用户未指定路径，但当前任务有明确项目工作区**：输出到当前工作区下的 `[名称]-风格包/`。如果当前工作区本身是 Skill 目录、临时目录或只读目录，不使用该位置。
4. **以上条件都不满足**：回退到当前用户的下载目录 `~/Downloads/[名称]-风格包/`。

路径示例：`<用户指定目录>/花样年华-风格包/`、`<当前工作区>/雨夜霓虹-风格包/`、`~/Downloads/花样年华-风格包/`。

执行时还要遵守：

- 用户给出的目录可以是中文或英文，不要擅自改到别处。
- 写入前先把 `~`、相对路径或父目录解析成明确的实际目标，并确认目标位于允许写入的范围。
- 除非用户明确要求，不要输出到临时目录或 Skill 自身目录。
- 目标已存在时，如果用户明确要求更新该风格包，可以在现有目录内增量更新；否则不要静默覆盖，改用带版本号的目录，或在会改变用户选择时先询问。
- 用户要求打包、另存或压缩时，直接以用户指定位置为准，不需要先复制到固定下载目录。
- 交付时说明最终解析后的实际保存路径。

## 风格包目录结构

```text
[名称]-风格包/
├── 00-说明.md
├── design.md
├── 参考图/
│   ├── 原图/
│   ├── manifest.json          # 每张图的来源记录
│   ├── 分组/                   # 按视觉模块分组的图片与本组色卡（只放图片，不放文档）
│   │   └── 01-[分组名]/
│   │       ├── [参考图].jpg
│   │       ├── 00-[分组名]-色卡.png      # 1920×1080，带角色/色名/HEX
│   │       └── 00-[分组名]-纯色色卡.png  # 1920×1080，只有 10 个满版色块
│   ├── 分组总览/               # 每组一张拼图 [分组名].jpg
│   ├── 分组色卡总览.jpg         # 所有标注色卡的 2 列总览
│   ├── 纯色色卡总览.jpg         # 所有无文字纯色色卡的 2 列总览
│   └── 总览-contact-sheet.jpg
└── 分析/
    ├── 单图标签-第一版.json     # 逐图打标签的原始结果
    ├── 色卡数据.json            # 3 主色 + 5 辅助色 + 2 点缀色的结构化色值
    ├── 风格规则-第一版.md       # 从标签归纳出的规则草稿
    ├── 分组总结.md
    ├── 分组提示词/
    │   ├── 01-[分组名].md      # 统一带两位序号前缀
    │   └── ...
    ├── 提示词模板.md
    └── 提示词表格模板.md
```

三条硬性约定：

- 图片素材是风格包的必要部分。提取时不能只输出文档，必须有参考图、总览拼图和分组拼图。
- 色卡是风格包的必要部分。每个含真实参考图的分组都必须同时有 `00-[分组名]-色卡.png` 和 `00-[分组名]-纯色色卡.png`，并生成 `分析/色卡数据.json`、`参考图/分组色卡总览.jpg` 和 `参考图/纯色色卡总览.jpg`；任何一项缺失都不能交付。
- 分组提示词只保留 `分析/分组提示词/` 一份，`参考图/分组/` 里只放图片，不再复制文档副本——两份副本改一处漏一处，反而降低可靠性。

## 输出格式偏好

默认输出中文。提取模式必须把参考图、拼图和标准色卡保存到风格包目录；色卡不受“用户是否额外要求生成图片”影响，必须自动生成。使用模式默认交付一个本地 Markdown 表格文档 + 简短说明文件保存位置，用户要求生成内容图时再保存到单独文件夹。不要只在聊天里散写几条 prompt——这个 Skill 的核心是可复用本地资产与表格文档。

## 输出前自检（两种模式通用）

1. 已读取对应模式的 reference 文档，并按其流程执行。
2. `原创元素` 全部来自用户新内容，`风格借用点` 只写可迁移视觉语法。
3. 提示词里没有出现参考片的具体场景、地点、服装、道具、人物造型或经典桥段。
4. 分组提示词达到 Scale 输出标准：有强视觉锁、可替换变量、摄影参数、光线色调、材质细节、画面限制、视频运动方案、跑偏点和自检清单。
5. 提取模式已为每个正式分组生成符合 `references/色卡规范.md` 的标注色卡和无文字纯色色卡，两套总览均已生成，`scripts/validate_palette_cards.py` 验收通过；没有用文字色值、全局单卡或其中一种色卡替代双卡交付。
6. 文生图提示词为中文、完整、可直接生成；视频提示词包含主体动作、镜头运动、焦点变化和时长。
7. 输出路径已按“用户指定路径 → 明确项目工作区 → 当前用户下载目录”的优先级解析，没有写死用户名，并在交付时说明了实际保存路径。

各模式专属的完成清单见对应 reference 文档末尾。
