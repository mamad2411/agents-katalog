# 分析报告

问题：{分析问题}　读者：{读者}

## 步骤
1. 把问题改写成可以用数据回答的形式，并写清指标口径。
2. 写下分析方法：用了哪些数据、时间范围、筛选条件、怎么算的。
3. 只写真正算过的数字；没算的标「待计算」。
4. 每个结论配一个证据（数字、表或图）和把握程度。
5. 读者不懂技术时，把方法放到附录，正文只讲结论和含义。

## 模板

```
# <标题：直接写结论>

## 一句话结论

## 关键发现
1. <发现> —— 证据：… —— 把握：高 / 中 / 低
2. …

## 建议
| 建议 | 依据 | 预期效果 | 优先级 |

## 数据与方法
- 数据来源与时间范围：…
- 指标口径：…
- 筛选与清洗：…
- 方法：…
- 复现：脚本 / 查询所在位置与运行方式

## 局限与风险
- 样本、数据质量、相关不等于因果……

## 下一步可以验证的问题
```

## 财务与行业数据（用到财报、研报或行业统计时加用）
- 财务数据统一报告期（年报 / 季报 / 滚动十二个月）、币种和单位，注明是否经审计、是否重述。
- 从研报或行业报告取数时，每个数字记下机构、报告日期和页码；同一指标多家给值时并列，除非用户要一致预期，否则不取平均。
- 预测值和实际值分列，预测列标「E」（如 2026E）；增长率、利润率等派生指标写明计算公式。
- 行业数据注明统计口径和覆盖范围，口径不同的数字不放在同一列比较。

## 使用边界

优先使用已有信息；用户的数量、格式和任务范围优先于本文默认模板。工具权限、主目录/附加只读、Plan 模式与预算以当次实际能力为准；不换工具规避拒绝。这里只给工作方法，不授权写入、命令、付费、发送、提交或发布；未执行/验证的步骤如实标明。

## 程序交付合同
按合同写入产物目录的 `报告.md`；来源节使用编号，正文每节附本次实际读取的文件或抓取 URL。表格列名和图表要求以合同为准；分析报告须有实际本地图片引用。

## 图表与 Word 交付
用 run_command 依据实际数据生成本地 PNG 图表并交接文件引用：有可用的 Python 解释器和绘图库（如 matplotlib）时直接画图；没有时如实报告图表缺失并说明阻塞，不伪造数据或图。本方法不调用付费图片生成。用 office_create 同时交付合同的 `报告.docx`，使用真正标题和段落。图片段落格式为 `{type:"paragraph",text:"图 1：标题；来源与口径",image:{path:"实际图表.png",width:640,height:360}}`；路径须为本次可读文件，不是网页链接。仅写图片路径或 Markdown 图片文本不能通过 DOCX hasChart。含图片的文档当前只能新建，改稿另存新文档。
