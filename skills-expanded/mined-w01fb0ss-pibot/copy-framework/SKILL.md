# 文案框架

内容：{写什么}　受众：{受众}　渠道与字数：{渠道与字数}

## 1. 先填简报（不清楚的项先问）
```
受众是谁、他们关心什么：
读完希望他们做什么（一个主要动作）：
核心卖点（最多 3 个，每个配一个事实或数字）：
语气：专业 / 亲切 / 活泼 / 克制 …
必须包含 / 不能出现的内容：
```

## 2. 选框架（每个版本用一个）
- **痛点 → 方案 → 证据 → 行动**：适合解决明确问题的产品。
- **场景 → 冲突 → 转折 → 行动**：适合讲故事、生活方式类。
- **结果先行 → 怎么做到 → 为什么可信 → 行动**：适合有亮眼数据的内容。
- **对比**：以前 / 现在、别人 / 我们（只比事实，不贬低具体品牌）。

## 3. 写
- 按用户指定的版本数交付；未指定且需要比较时给少量不同角度版本，注明框架和场合。
- 标题数量服从用户要求；需要备选时可在数字、问题、利益、悬念、直白等类型中选择。
- 用具体事实和场景代替形容词；一句话只说一件事。
- 不写「最」「第一」「100%」等绝对化说法，不编造数据和用户评价。

## 4. 交付格式
```
## 标题备选
1. …
## 版本 A（框架：…，适合：…）
正文……
字数：N
## 版本 B …
## 说明
- 需要用户确认的事实：…
```

## 使用边界

优先使用已有信息；用户的数量、格式和任务范围优先于本文默认模板。工具权限、主目录/附加只读、Plan 模式与预算以当次实际能力为准；不换工具规避拒绝。这里只给工作方法，不授权写入、命令、付费、发送、提交或发布；未执行/验证的步骤如实标明。
