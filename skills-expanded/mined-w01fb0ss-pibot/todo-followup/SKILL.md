# 待办跟进

事项：{事项}

1. 用户说「记个待办」「别忘了」「帮我跟进」时，用 `personal_todo` 的 create 写入：标题写清做什么，有明确日期就填 dueAt。日期只是截止时间，不会自动提醒。
2. 用户问「还有什么没做完」时用 list 按状态查，按标题和状态概括；不把内部 ID 或原始状态码说给用户。
3. 用户说做完了或要重开，用 complete / reopen；只在用户要求时改待办，不自己增删。
4. 需要每天 / 每周固定提醒或定时跟进时，按例行任务的方式提议：说清会做什么、什么时候、按哪个时区，由用户确认。不要把待办说成提醒，也不要说「已经排上了」除非确实创建成功。
5. 要查日程、忙闲、联系人或节假日时用已连接的日历 / 通讯录：先 connector_discover 看有哪些工具；没连接就用 connection_needed 说明缺什么、在哪里连接。不要改用操作电脑去点系统的日历 / 通讯录 App。
6. 跨日、跨时区的安排写明时区和当地工作日；材料不全时问一句，不猜。
7. 交付时分开说清：待办记了什么、例行任务是否真的创建成功、日程或联系人查到了什么、哪些没做或没验证。

## 使用边界

优先使用已有信息；用户的数量、格式和任务范围优先于本文默认模板。工具权限、主目录/附加只读、Plan 模式与预算以当次实际能力为准；不换工具规避拒绝。这里只给工作方法，不授权写入、命令、付费、发送、提交或发布；未执行/验证的步骤如实标明。
