# fn-scaffold：结构与骨架（fn-ladder 第③阶段）

照责任文档生成工程结构与全部函数骨架。**本阶段产出物是代码**（目录结构 + 签名 + 桩），不写任何文档。

## 进入检查

`responsibility.md` 存在且经用户确认。中途接手：grep 桩标记判断骨架是否已生成，已生成则直接指路 fn-implement。**功能演进模式**：只为新函数加桩，已 wired 的存量代码一律不动（比"存量只增不删"更严：演进周期里旧桩位早已是真实现）。

## 动作

1. **定文件结构**（固定规则）：一切置于 `fn_work/` 下——`src/` 中每个顶层函数一个文件夹，文件夹内顶层函数必须单独一个文件，其子函数尽量实现在该文件夹内的文件中，多个顶层函数共用的子函数放 `shared/`（与顶层函数文件夹同级）；`tests/` 镜像 `src/` 结构、测试文件与被测函数同名，与 `src/` 同级；环境与依赖文件（venv、node_modules、requirements.txt 等）也放 `fn_work/`。存量项目不走本规则——先经 fn-refactor 重构进入本结构。呈现结构树：

   ```
   fn_work/
   ├── src/
   │   ├── <顶层函数A>/        # 顶层函数 A 及其子树
   │   │   ├── <顶层函数A>.py  # 顶层函数必须单独一个文件
   │   │   └── <子函数>.py     # 子函数尽量在本文件夹
   │   ├── <顶层函数B>/
   │   │   └── ...
   │   └── shared/             # 共享子函数，与顶层函数文件夹同级
   └── tests/                  # 镜像 src/，与被测函数同名
   ```
2. **一次性写全部新函数签名 + 桩**，统一标记格式 `unimplemented:fn:<函数名>`（可 grep、不误伤）：

   | 语言 | 桩 |
   |---|---|
   | Python | `raise NotImplementedError("unimplemented:fn:<名>")` |
   | TS/JS | `throw new Error("unimplemented:fn:<名>")` |
   | Rust | `todo!("unimplemented:fn:<名>")` |
   | Go | `panic("unimplemented:fn:<名>")` |

3. **编译/类型检查必须通过**——桩阶段就让整棵调用链可编译，此后"还剩什么没做"由代码自己报告。
4. **存量代码只增不删**：改造现有函数的任务在本阶段不动现有函数体，只新增桩；函数级的改动留给 fn-implement。

## 铁律

- **不写任何实现逻辑**，哪怕"顺手"。桩的本分是占位与暴露剩余工作。
- 编译/类型检查不过 = 本阶段未完成，不许出门。
- 呈现结构树 + 签名清单 + 编译验证输出后**停在门口**——这是签名审查点，改方向最便宜的时刻。等用户显式同意才进 fn-implement。

## 红旗（出现即停）

| 念头 | 现实 |
|---|---|
| "这个函数太简单，直接写完吧" | 骨架期写实现 = 越阶段，签名审查被架空 |
| "编译等实现时再一起过" | 桩链不可编译，剩余工作就对代码不可见 |
| "标记格式换一个也行" | 统一标记是全局核验的 grep 锚点，不许变体 |

## 出口

结构树 + 签名清单 + 编译验证输出呈现后**停**，显式提示两项：**下一步命令 `/fn-implement`**，或**修订本步骤**；用户未显式选择前不推进。
