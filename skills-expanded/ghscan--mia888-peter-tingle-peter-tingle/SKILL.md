# peter_tingle

## 两大用法（核心）

本 Skill 做两件事，通常**先 1 后 2**：

| | **1. 总结文风** | **2. 模仿写作** |
|--|----------------|----------------|
| **做什么** | 从范文/论文/素材里**提炼写作规则** | 按已定规则**写稿、改稿、续写** |
| **主要文件** | `写作约束.md` →「我的写作约束」 | `中文草稿.md`、`英文草稿.md` |
| **素材从哪来** | `文献合集/`（须先上传） | 同上 + 已写好的约束 |
| **你怎么说** | 「**把上传资料的文风总结成约束**」；或自写 / 套用示例 | 「按约束写引言」「模仿这个文风扩写」「译成英文」等 |
| **Agent 产出** | 结构、句式、思维、符号、引用习惯与引用风格等**可执行约束** | 符合约束的正文；并依流程问中英衔接、逐章或成篇 |

启用 skill 后，在开场白中**必须简要介绍这两大用法**，并问：

> 你现在想 **总结文风**（上传素材→归纳约束），还是 **模仿写作**（按约束写稿）？  
> 若还没有约束、但想先模仿写作，我会**自动调取范本**到「写作约束」，请你查看并按需修改。

**总结文风** ≠ 写正文。**模仿写作** 须以「我的写作约束（当前生效）」为准；若尚未填写，见下节 **「尚无约束却选模仿写作」**（自动调取范本）。

## 尚无约束却选模仿写作（Agent 必做）

**触发**：用户明确选择 **模仿写作**（或说「按约束写」「开始写稿」），且「我的写作约束（当前生效）」仍为空白、`（待填写）` 或未实质填写。

**不要**只让用户回去总结文风。须**立即**：

1. 将 `写作约束.md` 中 **「示例约束（作者预设）」** 全文复制到 **「我的写作约束（当前生效）」**（与「套用示例约束」相同操作）  
2. **提醒用户**（必须包含以下要点，中文）：  
   - 已为你**调取作者范本约束**作为起点  
   - 请打开 `用户请点这里/写作约束.md` **查看**「我的写作约束」  
   - 范本偏**学术论文**；备考雅思/托福或另有要求时，请**按你的需求修改**（或说「在约束基础上改成……」）  
   - 确认无误后再开始写稿；也可先说「约束已改好」  
3. **保存文风询问**：完成步骤 1–2 后，**同样执行「保存文风询问」**（与「套用示例约束」相同；见下节）  
4. **暂停长文生成**：在用户表示已查看/已修改，或明确说「先用范本写」之前，**不要**大段写入 `中文草稿` / `英文草稿`（短示例句除外）  

若用户随后上传了文献并说「用素材约束而不是范本」，再执行「从素材归纳文风」覆盖「我的写作约束」。

## 适用场景（同一套写作文档，不同写法）

本 Skill **不限于学位论文**。同一工作流可用于：

| 场景 | 文献合集放什么 | 写作约束写什么 | 中文 / 外文草稿 |
|------|----------------|----------------|-----------------|
| **学术论文** | 期刊、专著、法规、自己的旧稿 | 引用体例、章节、字数、语气 | 论文章节；英文可平行中文 |
| **雅思写作** | 真题、范文、评分标准 Band 描述、Simon/官方指南 | Task 1/2、目标分数、字数、结构模板、禁用表达 | 提纲/中文思路 → **英文成稿**（主战场在英文草稿） |
| **托福写作** | TPO/真题、范文、Rubric、综合/独立题说明 | 题型、字数、计时习惯、论证结构 | 笔记/中文大纲 → **英文成稿** |
| **其他外文写作** | 目标语范文、教材、老师批改样例 | 语种、体裁、格式、谁的目标读者 | 中文构思稿 + **目标语草稿**（英文草稿可改为其他语种内容） |

启用 skill 后，若用户未说明场景，**主动问一句**：「你是写论文、备考雅思/托福，还是练其他外文写作？」并据此调整对「文献合集」「约束」的举例说明。

**示例约束**（`写作约束.md` 内）默认为**学术论文**预设；备考雅思/托福时请**自写约束**或说「在示例约束基础上改成雅思 Task 2、目标 7 分」等，**不要**在未改约束时把 AGLC 论文规则硬套到雅思作文。

### ① 文献合集（`用户请点这里/文献合集/`）

- **作用**：Agent 读取论据、范文、评分标准、术语与引用来源（论文 **或** 雅思/托福资料 **或** 目标语范文）  
- **上传什么**（按场景）：  
  - 论文：参考文献、方法说明、开题或旧稿  
  - 雅思/托福：真题、范文、Band/Rubric 说明、课堂讲义  
  - 其他外文：目标语范文、教材、批改样例  
- **怎么传**：  
  - **方式 A**：PDF / Word / txt / md **拖入** `用户请点这里/文献合集/`  
  - **方式 B（推荐）**：在 Agent 对话框 **上传文件**，说「帮我把这些文献整理进文献合集」— Agent 自动命名并放入该文件夹  
  - 详见 `用户请点这里/文献合集/使用说明.md`  
- **完成**：至少 3 篇相关文献 → 用户说「文献ok」  

### ② 写作约束（`用户请点这里/写作约束.md`）— **用法 1：总结文风** 的主战场

- **作用**：存放归纳出的文风规则；**模仿写作**时 Agent 只认「我的写作约束（当前生效）」  
- **总结文风怎么做**：文献入库 → 说 **「把上传资料的文风总结成约束」**（或自写 / 在示例上改 / 套用示例）  
- **尚无约束却选模仿写作**：自动将「示例约束」填入「我的写作约束」，并提醒用户打开本文件查看、按需求修改  
- **完成**：约束定稿 → 用户说「约束已写好」→ 进入 **用法 2：模仿写作**；若从素材归纳，Agent 会先问是否**保存**至 `保存的文风/`

### ③ 中文草稿（`用户请点这里/中文草稿.md`）— **用法 2：模仿写作**（**可选**）

- **作用**：在约束下写中文或列提纲；Agent 扩写、润色、改结构时**严格遵循约束**  
- **学术论文**：约束定稿后，用户可**自行选择**——先写中文稿，或**跳过中文、直接写外文**（见下节「约束定稿后：中文可选」）  
- **文风定稿后（必问，见下节「中文→英文衔接」）**：问是否做英文、英文按约束还是按中文稿  
- **完成**：当前章节/全文中文经用户确认（若选择写中文）

### ④ 英文草稿（`用户请点这里/英文草稿.md`）— **用法 2：模仿写作**

- **作用**：在约束下写外文成稿（论文英文、雅思/托福作文等）  
- **怎么用**：依约束（及可选中文稿）生成；按约束检查文体与引用  
- **英文文风定稿后（必问，见下节「英文续写策略」）**：问逐章确认还是一次成篇  
- **完成**：用户满意后可整理导出

## 文献入库：用户通过对话框发文件时（Agent 必做）

当用户在 Agent 对话中 **上传、粘贴或拖拽** 文献，并说「整理进文献合集」「存入文献合集」或类似意思时：

1. **接收**对话中的附件或用户指向的工作区外文件  
2. **保存到** `用户请点这里/文献合集/`（仅此目录，勿放根目录或其他文件夹）  
3. **重命名**为可读文件名，建议格式：`作者或来源-年份-短标题.ext`（例：`张三2023-数字化转型.pdf`）；保留原扩展名  
4. **分类**：一次 ≥5 篇或用户注明主题时，可建子文件夹（如 `文献合集/方法/`、`文献合集/案例/`）  
5. **去重**：若同名文件已存在，询问是否覆盖或加后缀 `-2`  
6. **回复清单**：列出入库文件名与路径；提示可说「文献ok」，或「**把上传资料的文风总结成约束**」从素材归纳规则  

若用户只发文件未说明意图，主动问：「要帮你整理进 `文献合集/` 吗？整理后也可说『把上传资料的文风总结成约束』。」

## 从素材归纳文风 → 写作约束（Agent 必做）

**触发语**（同义即可）：「把上传资料的文风总结成约束」「从文献合集归纳文风」「分析范文风格写入约束」「总结这些材料的写作习惯」。

**前置**：`用户请点这里/文献合集/` 中已有可读素材（范文、论文、雅思/托福高分作文、用户旧稿等）。若为空，先引导上传或从对话框入库。

**步骤**：

1. **读取**文献合集中用户指定文件；未指定则读**全部**（或最近上传的；文件过多时先问用户范围）  
2. **按下列维度归纳**（每项须写清观察到的**具体习惯**；素材中无体现则写「未见明显规律」）：

| 维度 | 归纳内容 |
|------|----------|
| **文章结构与逻辑** | 整体布局、段落功能、论证顺序、过渡方式 |
| **句式表达习惯** | 句长、主被动、连接词、语气、中英/外文特有句式 |
| **文章思维习惯** | 如何提出观点、举例、对比、让步、总结 |
| **符号运用** | 标点、括号、引号、列表、强调、数字与单位写法 |
| **引用习惯** | 引用密度、转述 vs 直引、脚注/尾注位置、是否与论述交织 |
| **引用风格** | 识别 APA / MLA / AGLC / Chicago / GB/T 7714 等；书目与文内格式要点 |

3. **写入** `用户请点这里/写作约束.md` 的 **「我的写作约束（当前生效）」**，结构建议：

```markdown
# 我的写作约束（当前生效）

> 归纳自文献合集：（列出文件名与日期）
> 用户可在此基础上增删改。

## 1. 文章结构与逻辑
…

## 2. 句式表达习惯
…

## 3. 文章思维习惯
…

## 4. 符号运用
…

## 5. 引用习惯
…

## 6. 引用风格
…

## 7. 其他（字数、体裁、禁用项等，若素材或用户另有要求）
…
```

4. **回复用户**：摘要 3–5 条最关键发现；**然后必须执行「保存文风询问」**（见下节）。  
5. **勿**在归纳时大段照抄原文；写的是**可执行的写作规则**，不是文献摘要。

用户确认后，可说「约束已写好」进入中文/外文草稿。

## 保存总结的文风（Agent 必做）

**触发**（须主动询问，不可跳过）：

- 刚完成 **从素材归纳文风** 并写入「我的写作约束（当前生效）」  
- 刚完成 **套用示例约束** / **用作者的约束**（含 **尚无约束却选模仿写作** 时的自动调取范本）  
- 刚完成 **在示例约束基础上修改** 并写入「我的写作约束（当前生效）」  
- 用户说 **「保存文风」** / **「把当前约束存起来」** / **「存档这套文风」**（此时「当前生效」须有实质内容）

**步骤 1 — 是否保存**（上述操作完成后**立即**问；在用户回复前勿默认已保存）：

> 文风已写入「我的写作约束（当前生效）」。  
> 要不要**保存**到 `保存的文风/` 文件夹，方便以后复用？  
> 回复 **保存** / **不保存**（也可稍后再说「保存文风」）

| 用户回复 | Agent 动作 |
|----------|------------|
| **不保存** | 确认「好的，当前约束仍在写作约束里，可说『约束已写好』开始写稿」 |
| **保存** | 进入步骤 2 |

**步骤 2 — 询问命名**（仅当用户选保存）：

> 请给这套文风**起个名字**（例：「硕士论文引言」「雅思 Task2-7分」「民法案例分析」）。

| 用户回复 | Agent 动作 |
|----------|------------|
| 给出名称 | 执行步骤 3 |
| 未给名称 | **继续追问**，不得擅自用「未命名」等默认名（除非用户明确说「就叫未命名」） |

**步骤 3 — 写入存档**：

1. 确保存在目录 `用户请点这里/保存的文风/`（不存在则创建）  
2. 将「我的写作约束（当前生效）」**全文**写入 `用户请点这里/保存的文风/{命名}.md`  
3. **文件名**：取用户命名，去掉 `/ \ : * ? " < > |` 等非法字符；空格可保留或改为 `-`；过长时截断至合理长度  
4. **若 `{命名}.md` 已存在**：问用户 **覆盖** 还是 **另存为 `{命名}-2.md`**  
5. 文件头部须含元信息，格式示例：

```markdown
# 文风存档：{用户命名}

> 保存日期：YYYY-MM-DD  
> 归纳来源：（文献合集中的文件名；若为套用/改示例则写「作者示例约束」或「示例约束改写」）

---

（此处为「我的写作约束（当前生效）」正文，不含示例约束节）
```

6. **回复用户**：给出保存路径，并提示可说「加载保存的文风：{命名}」或「约束已写好」进入写稿。

**加载已保存文风**（触发：「加载保存的文风：xxx」「用存档的 xxx 文风」「列出保存的文风」）：

| 用户说法 | Agent 动作 |
|----------|------------|
| 列出保存的文风 | 列出 `保存的文风/` 下所有 `.md` 文件名（不含 `使用说明.md`） |
| 加载 xxx | 读 `保存的文风/xxx.md`（模糊匹配时列出候选让用户选）→ 正文写入「我的写作约束（当前生效）」→ 确认已加载 |

**删除存档**：用户明确要求时，删除对应文件并确认（勿擅自删）。

## 写作约束：套用与修改（Agent 必做）

文件 `用户请点这里/写作约束.md` 含两节：**我的写作约束（当前生效）**、**示例约束（作者预设）**。

| 用户说法 | Agent 动作 |
|----------|------------|
| **套用示例约束** / **用作者的约束** / **不想写约束了** | 将「示例约束」全文复制到「我的写作约束（当前生效）」→ **问是否保存文风** → 确认「已套用，可说约束已写好」 |
| **把上传资料的文风总结成约束** / **从文献合集归纳文风** | 执行上文「从素材归纳文风」全流程 |
| **在示例约束基础上……**（如改引用格式、改字数） | 读示例 → 按用户要求修改 → 写入「我的写作约束」→ **问是否保存文风** |
| **我自己写约束** | 引导填写「我的写作约束」各条，或用户口述由 Agent 写入 |
| 改稿 / 写引言 | **必须先读「我的写作约束（当前生效）」**；若为空且用户选模仿写作 → **自动调取范本**并提醒查看修改 |

启用 skill 介绍第 ② 步时，**必须说明**上述用法（含 **从上传素材归纳文风**）。

## 约束定稿后：是否写中文稿（Agent 必问，学术论文）

**触发**：用户说 **「约束已写好」**，且场景为 **学术论文 / 学位论文 / 课程论文**（非纯雅思/托福备考作文）。

**必须确认**（在开始写正文前）：

> 约束已定。接下来怎么写？  
> - **A. 先写中文稿** — 在 `中文草稿.md` 写/改，定稿后再做外文  
> - **B. 跳过中文，直接写外文** — 确认第 ② 步约束已含外文翻译细则后，在 `英文草稿.md` **按约束**写（不必先有中文版）

| 用户选择 | Agent 动作 |
|----------|------------|
| **先写中文** / A | 引导写 `中文草稿.md`；中文定稿后走「中文→英文衔接」 |
| **跳过中文** / **直接写外文** / B | 输出 **问题 1b**（确认约束已含外文翻译细则 + 练习声明）→ 在 `英文草稿.md` **按约束**写；**不要**要求先有中文稿 |
| 未说明 | **必须追问**，不得默认 |

**雅思/托福**：可跳过本问，默认可直接写 `英文草稿.md`（中文仅提纲或跳过）。

## 中文→英文衔接（Agent 必问，不可跳过）

**触发**：用户说「中文文风改好了」「中文章节定稿」「中文可以了」，或 Agent 判断用户刚完成中文润色/改文风。

**必须依次确认**（用中文、选项清晰；在用户回复前**不要**开始写英文）：

**问题 1 — 是否做英文？**

> 中文当前章节/文风已改好。要不要现在开始 **英文草稿**？  
> 回复 **做英文** / **先不做**（稍后说「开始英文」即可）

**问题 1b — 外文学术论文：确认约束已含外文翻译细则（不可跳过）**

**触发**：用户选 **做英文**，且场景为 **学术论文 / 学位论文 / 课程论文**（含用户明说「写英文论文」「译成学术论文英文」；**不含**纯雅思/托福备考作文）。

在用户回复 **做英文** 后、进入问题 2 **之前**，**必须**输出以下提示（要点不可省略），然后**直接进入问题 2**（无需等待用户确认已阅读）：

> **进入第 ④ 步「修改外文草稿」前，请确认第 ② 步约束已含外文翻译细则：**  
> 阅读并将要点合并进 `写作约束.md` 的「我的写作约束（当前生效）」——细则见 `用户请点这里/外文翻译约束范本.md`（完整条文亦见「示例约束」中「英文稿（与中文平行）」等条目）。  
> **这不是单独流程步骤**，而是确定约束时针对学术论文外文的补充规则（平行译法、简单句转述文献等），有助于形成个人表述习惯、降低与通用 AI 直译的相似度。  
>  
> **请务必知悉：** 本 Skill **仅用于个人写作练习**。正式**提交**课程作业、学位论文或投稿时，请**自行独立写作**，**不要**将本工具生成内容直接作为提交稿。  
>  
> 确认约束无误后，我们继续选择英文生成方式。

**雅思/托福** 等考试作文场景：可跳过上述提示，直接进入问题 2（考试约束以「我的写作约束」为准）。

**问题 2 — 仅当用户选「做英文」时**

> 英文希望怎么生成？  
> - **A. 按约束生成** — 以「我的写作约束」+ 文献为主，英文独立组织（不必与中文逐句对应）  
> - **B. 按中文稿生成** — 严格对照 `用户请点这里/中文草稿.md` 对应章节平行撰写/翻译（结构、论点与中文版一致）

| 用户选择 | Agent 动作 |
|----------|------------|
| 先不做 | 停止；提醒可说「开始英文」时再问问题 1b（若适用）与问题 2 |
| 做英文 + **按约束** | 读「我的写作约束」+ `外文翻译约束范本.md`（学术论文）+ 文献；写入 `英文草稿.md`；**不强制**镜像中文段落顺序 |
| 做英文 + **按中文稿** | 读 `中文草稿.md` + 约束与范本中的平行译法规则；平行写入 `英文草稿.md` |

若用户未说明 A/B，**必须追问**，不得默认。

**直接请求英文学术产出**（未走中文定稿流程）：若用户说「写英文论文引言」「把第二节译成学术英文」等，仍须先输出 **问题 1b** 提示（学术论文场景），再写稿。

## 文档导出 Word / PDF（Agent 必做）

**触发语**：「导出 Word」「导出 PDF」「导出成 docx」「整理导出」「列出导出格式」「导出稿件」等。

**脚本位置**（安装后亦在 skill 目录内）：`agent/scripts/export_document.py`

### 首次导出前

若不存在 `.venv-export/`，在终端执行：

```bash
bash agent/scripts/setup-export.sh
```

### 步骤 1 — 询问导出格式（不可跳过，除非用户已明确指定）

列出**内置 + 用户**格式（运行 `list-formats`），用表格呈现，并**必须**提供选项：

> 要用哪种格式导出？  
> - **A. aglc4-en** — AGLC 4th 英文学术（内置脚注体例）  
> - **B. gbt7714-zh** — 中文学术  
> - **C. apa-7-en** — APA 7th 英文学术（内置脚注体例）  
> - **D. mla-9-en** — MLA 9th 英文学术（内置脚注体例）  
> - **E. multilingual** — 英/中/日/韩/西等多语言字体自动匹配  
> - **F. ielts-en** — 雅思/托福作文  
> - **G. plain** — 无特殊版式  
> - **H. 用户自定义** — `导出格式/` 下某文件夹（若存在则列出）  
> - **I. 不要求格式** — 等同 `plain`  
> - **J. 上传新格式** — 引导用户将 PDF/说明放入 `用户请点这里/导出格式/新格式名/`，并协助编写 `format.json`

用户已说「用 AGLC 导出」等则不必再问，直接采用对应 id。

### 步骤 2 — 确认源文件

默认导出 `英文草稿.md`；若用户指定中文或某章节，读取对应 `用户请点这里/*.md`。  
提醒：脚注在 Markdown 中写 `[^1]`，定义写 `[^1]: 脚注正文`（导出为 **Word 原生脚注**）。  
导出前建议执行 **「整理被引用文献」**（见下节），确保 `_registry.json` 与 `索引.md` 最新。

### 步骤 3 — 执行导出

```bash
.venv-export/bin/python agent/scripts/export_document.py list-formats

.venv-export/bin/python agent/scripts/export_document.py export \
  -i "用户请点这里/英文草稿.md" \
  -f aglc4-en \
  -o "用户请点这里/导出/文件名.docx" \
  --pdf
```

- `-f`：格式 id（`aglc4-en` / `multilingual` / `plain` / 用户文件夹名）  
- `--pdf`：在 docx 成功后尝试 PDF（需本机 LibreOffice 或 pandoc+xelatex；失败时告知用户用 Word 另存为 PDF）  
- 若用户格式目录含 `reference.docx` 且已装 pandoc，优先用 pandoc + 参考模板

### 步骤 4 — 回复用户

- 给出 `docx` / `pdf` 完整路径  
- 若选用 `aglc4-en` / `apa-7-en` / `mla-9-en`，提示对应内置脚注指南（`aglc4-footnote-guide.md` 等）已作为体例参考  
- 若 `pdf` 为 null，转述 `pdf_note`，**不要**谎称 PDF 已生成  
- 提醒：正式提交前须自行核对脚注、字体与课程格式

### 用户上传 PDF 版式时

1. 保存到 `用户请点这里/导出格式/{命名}/reference.pdf`（可同时放 `说明.md`）  
2. Agent 阅读 PDF/说明，协助生成或补全同目录 `format.json`  
3. 可选：用户提供 Word 模板 → 存为 `reference.docx` 供 pandoc 套用  
4. 导出时 `-f` 使用 `{命名}` 或 `format.json` 中的 `id`

### 导出相关禁止

- **禁止**用 Agent 凭空编造二进制 docx 内容而不调用本脚本  
- **禁止**跳过格式询问（用户已指定除外）  
- **禁止**声称已导出 PDF 而脚本未返回 `pdf` 路径

## 被引用文献登记与归集（Agent 必做）

**与 `文献合集/` 的区别**：文献合集 = 全部参考资料；**`被引用文献/`** = 稿内**实际引用**的原文摘录 + 位置，**按作者归集**供读者查阅。

**目录**：`用户请点这里/被引用文献/`  
**登记簿**：`_registry.json`（Agent 维护）  
**生成物**：`索引.md`、`按作者/{作者}.md`（脚本生成）  
**脚本**：`agent/scripts/build_citation_index.py`

### 何时必须登记

在第 ③④ 步写稿/改稿时，凡从 `文献合集/` **转述、短引、照搬法规条文**并写入脚注 `[^id]`，**必须**同步向 `_registry.json` 的 `citations` 数组**追加或更新**一条，包含：

- `id`（与 `[^id]` 一致）、`authors`、`author_key`（第一作者姓氏，用于归集）
- `source_file`（`文献合集/` 相对路径）、`location`（页/章/条号等）
- `original_text`（**被引用处的原文摘录**，转述也须摘录依据句段）
- `draft_file`、`draft_section`、`footnote_id`、`usage_type`（`paraphrase` / `direct_quote` / `statute`）
- `draft_excerpt`（可选，稿内表述）

**同一作者**的多条引用由脚本自动归入 `按作者/{author_key}.md`。

### 触发语

「整理被引用文献」「更新引用索引」「检查引用是否都已登记」「列出被引用作者」

### Agent 必做步骤

1. 读/写 `用户请点这里/被引用文献/_registry.json`  
2. 从 `文献合集/` 提取原文时，**标注精确位置**（页码、章节、段落）  
3. 执行：

```bash
.venv-export/bin/python agent/scripts/build_citation_index.py build
```

4. 可选校验：

```bash
.venv-export/bin/python agent/scripts/build_citation_index.py validate
```

5. 回复：条目数、作者数、`索引.md` 路径；提示用户打开 `按作者/` 查阅同一作者全部引用

### 登记示例（`_registry.json` 单条）

```json
{
  "id": "smith2023",
  "authors": ["Smith"],
  "author_key": "Smith",
  "source_file": "文献合集/Smith2023-AI-Liability.pdf",
  "location": "p. 45, ch. 2",
  "original_text": "The liability structure should retain fault presumptions in low-autonomy settings.",
  "draft_file": "用户请点这里/英文草稿.md",
  "draft_section": "Introduction",
  "footnote_id": "smith2023",
  "usage_type": "paraphrase",
  "draft_excerpt": "In settings of low autonomy, fault presumptions should remain."
}
```

### 禁止

- **禁止**只在脚注写出处而不登记 `original_text` 与 `location`  
- **禁止**把未在正文引用的文献放入 `被引用文献/`（那些留在 `文献合集/`）  
- **禁止**声称已「按作者归集」而未运行 `build` 脚本
