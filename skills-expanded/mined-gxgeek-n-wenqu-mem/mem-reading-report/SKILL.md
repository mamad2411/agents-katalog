# ZJU MEM 读书报告与中期衔接

## 1. 使用边界

本 skill 的主任务是写**读书报告**，并把第 4 篇读书报告自然接入 ZJU MEM 中期考核。中期相关文本必须围绕“课程学习、实践实训、读书报告完成情况”“已完成论文工作及阶段成果”“与开题报告不符情况说明”“下一步工作安排”“已写章节与三级目录”五段结构服务，不能把读书报告写成孤立的读后感。

按用户目标选择模式：

- **读书报告模式**：生成 3000-8000 字读书报告，默认 5000 字，重点是文献综合、研究空白、对本人论文的启示。
- **中期衔接模式**：用于第 4 篇读书报告或中期材料，强化文献阅读统计、核心文献矩阵、综述如何支撑论文问题/方法/创新点。
- **中期报告框架模式**：仅在用户明确要求“完整中期报告”且提供真实进展材料时使用；按 MEM 五段结构生成草稿或检查清单，不凭空编造已完成成果。
- **审查/修订模式**：对既有读书报告或中期材料按盲审专家和学院教务管理员双重视角做风险审查、评分和修改建议。

中期相关任务必须先阅读 `references/midterm_requirements.md`，并检查文件头 `last_verified`；若距当前日期超过 90 天，提醒用户 MEM 政策可能已更新，建议确认最新要求。反幻觉、文献追溯、自动评分、报告互补、文献可核验和盲审风险分别见本文件第 4、7、8、13、14、15 节。

## 2. 一次性输入收集

一次性收集缺失信息，避免反复打断。用户已经在自然语言或文件名中明确给出的字段视为已确认；非关键字段可以先用 `[待补充]` 占位，但正式 DOCX 前必须回填。

### 2.1 任务参数

| 输入 | 必填 | 处理规则 |
| ---- | ---- | -------- |
| 文献路径 | 是 | 3-8 篇文献或一个目录，支持 `.pdf`、`.md`、`.txt`、`.docx`；少于 3 篇按第 6 节降级 |
| 报告标题 | 是 | 可按论文主线微调，不机械照搬文件名 |
| 字数要求 | 否 | 默认 5000 字；低于 3000 或超过 8000 时先确认用途 |
| 输出路径 | 否 | 默认当前目录 `读书报告_<标题首词>_<YYYYMMDD>.docx` |
| 是否用于 MEM 中期 | 否 | 若是第 4 篇读书报告，必须按中期衔接模式写 |

### 2.2 封面与学术身份

每次都要核对，不从记忆或旧任务中套用：

| 字段 | 要求 |
| ---- | ---- |
| 学校、学院、专业、姓名、学号、导师 | 用于封面；学号与工号不能混淆 |
| 研究方向 | 必填；决定“对自身研究的启示”质量 |
| 学位论文题目 | 可选；已有题目时必须写进启示与中期衔接逻辑 |

### 2.3 中期衔接材料

若用户要写中期报告片段或完整中期报告，还需提供：

- 开题报告中的研究目标、主要内容、技术路线或方法。
- 已完成论文工作：文献综述、调研、问卷、访谈、数据、模型、实验、章节初稿等。
- 阶段成果证据：表格、图、截图、模型、样本量、指标、初步结果。
- 与开题不符之处及原因；如果没有，也要写“经核对暂无实质偏离”并说明核对依据。
- 下一步安排：按月份或节点列任务、产出物、验收标准和缓冲期。
- 已写论文章节与三级目录。

## 3. 简洁调用流程

默认采用”少交互、强自检、对抗循环”的 7 步流程：

1. **确认范围**：识别模式、文献数量、封面字段、研究方向和输出路径。只问一次关键缺口；不影响写作的字段先标 `[待补充]`。
2. **解析与建账**：逐篇提取元数据、页码/章节、核心观点、方法、结论和局限，建立”文献来源台账”。
3. **跨文献综合**：先形成共识、分歧、研究空白、方法启示，再写正文；禁止逐篇摘要串联。
4. **成稿与追溯**：每个实质观点都要能追到文献、页码/章节或用户提供的进展材料。
5. **自动评分**：运行 `scripts/audit_report.py` 生成 MEM 100 分制评分和检查清单；正式 DOCX 默认不附入评分附录，评分结果只用于修订和最终说明。
6. **对抗审查循环**：以盲审专家+教务管理员双重视角执行对抗审查（详见 §15）。自动检查 → 发现问题 → 自动/手动修复 → 重新检查，最多迭代 3 轮。迭代满 3 轮仍有致命问题则降级交付并明确告知剩余风险。
7. **交付复核**：检查 DOCX 可打开、封面字段完整、引用编号一致、模板占位消失。输出最终对抗审查通过报告，说明迭代轮数、修复项和剩余风险。

长任务中应给用户进度反馈：`已解析 X/Y 篇文献`、`已完成证据台账`、`自动评分为 X/100，正在补强低分项`、`DOCX 已生成并通过基础检查`。失败时说清“哪个文件、失败原因、可选处理”，不要只抛异常。

## 4. 反幻觉硬约束

这些规则优先级高于字数、流畅度和“写得像论文”：

1. **不编造文献**：参考文献表只能包含用户提供、用户明确授权补充，或工具真实检索到并记录来源的文献。不能根据题目猜作者、年份、期刊、卷期、页码。
2. **不编造数据**：样本量、指标值、实验结果、政策日期、企业案例、模型参数必须来自文献、用户材料或真实输出。拿不准写 `[待核对]` 或“文献未给出具体数值”。
3. **不编造成果**：中期报告不得虚构问卷、访谈、模型、章节字数、系统截图、导师意见或实践实训。
4. **不把示例当事实**：`references/writing_examples.md` 中的快递、关键链、EPC、金融工程等内容只是写法示范，不能迁移为用户报告中的事实。
5. **直接引用要保守**：没有原文页码或准确位置时，不写引号式直接引用；改为概述并标注 `[待核对页码]`。
6. **来源不足不硬凑**：文献质量弱或数量少时按第 6 节降级，不用空泛套话填满字数。

### 4.1 文献来源台账

写作前必须建立内部台账；正式报告中至少保留“核心文献矩阵”，必要时附“来源追溯表”。推荐字段：

| 文献编号 | 文件名/来源 | 页码或章节 | 可用观点/数据 | 用于报告位置 | 可靠性 |
| -------- | ----------- | ---------- | ------------- | ------------ | ------ |
| [1] | `xxx.pdf` | p.12 / 第 3 节 | 方法 A 的适用条件 | 三、方法综述 | 已核对 |

可靠性分三档：

- **已核对**：文件中明确出现，含页码/章节或可定位段落。
- **弱核对**：只从摘要、结论或 OCR 粗文本获得，需在正文谨慎表达。
- **待核对**：元数据不全、页码不清、PDF 解析异常；只能作为待补充信息，不能写成确定结论。

## 5. 文献解析与综合标准

逐篇提取：

- 作者、年份、出处与文献类型。
- 核心研究问题、理论基础、方法或模型。
- 关键结论、数据、图表或可引用证据。
- 局限性和作者未解决的问题。
- 与用户研究方向或论文题目的关系。

写作前必须完成三项综合判断：

1. **共识与分歧**：哪些结论一致，哪些结论互补或冲突。
2. **研究空白**：哪些问题尚未被充分回答，为什么与用户论文相关。
3. **方法启示**：哪些方法可直接借鉴，哪些需要调整，调整依据是什么。

第 3 节必须按主题、方法、场景或问题链组织。若正文连续出现“张三认为、李四认为、王五认为”式段落，要重写为主题综合。

## 6. 弱文献与边界条件降级

### 6.1 文献数量不足

| 情况 | 处理 |
| ---- | ---- |
| 0 篇 | 不能生成正式读书报告；只能给提纲、选题拆解和文献补充清单 |
| 1-2 篇 | 生成“文献阅读札记/小综述草稿”，明确标注“材料不足，不建议作为正式 MEM 读书报告提交” |
| 3-4 篇且质量参差 | 进入弱文献模式：区分核心/辅助/背景文献，降低结论强度，减少研究空白外推，附补充文献建议 |
| 5-8 篇 | 正常生成；若外文、核心期刊或方法文献明显不足，也要提示结构性缺口 |
| 超过 8 篇 | 先筛核心文献，剩余转为背景或参考文献，不强行全篇精读 |

### 6.2 弱文献模式写法

- 报告标题和引言避免写成“系统综述”“全面研究”，改为“基于若干文献的初步综述”或“阶段性读书报告”。
- 第 2 节必须说明文献选择局限：数量、类型、年份、研究方向覆盖不足。
- 第 3 节按“已能确认的结论”和“尚需补充验证的判断”分开写。
- 第 4 节的研究空白只写“在现有材料范围内未充分覆盖”，不能写“国内外研究空白”“首次”。
- 第 5 节只给“初步启示”和“后续需核对文献”，不把弱证据写成论文创新点。

### 6.3 PDF、DOCX 和模板异常

- **PDF 解析失败**：报告具体文件名和失败原因；尝试从文件名、摘要页或用户粘贴文本恢复。不能跳过失败文献后当作已阅读。
- **扫描版 PDF**：先用 `pdftotext` 提取文字；若结果为空或只有空白，判定为扫描版 PDF。可运行 `scripts/md_to_docx.py --extract-pdf-text "<文献.pdf>" "<输出.txt>"`，环境已有 `pytesseract` 和 `pdf2image` 时会尝试 OCR，OCR 文本用 `[OCR]` 标注；缺少可选依赖时只提示，不强制安装。
- **OCR 文本质量差**：把该文献标为“弱核对”，只使用可确认字段；公式、页码和数据全部标 `[待核对]`。
- **DOCX 解析失败**：请用户导出为 PDF/TXT，或只处理可读取部分并列明缺失。
- **模板文件损坏**：先交付 Markdown 草稿、自动评分和检查清单；同时提示 `assets/template.docx` 需要替换。不得用错误模板生成看似正式但格式不可靠的 DOCX。
- **用户中途改需求**：保留已解析台账，只重做受影响部分；若研究方向、论文题目或用途改变，必须重写“研究空白”和“对自身研究启示”。

## 7. 读书报告章节模板与质量标准

默认结构如下，标题可按主题微调，但不要删除“研究空白”和“对自身研究方向的启示”。

| 章节 | 建议字数 | 必须回答的问题 | 质量标准 |
| ---- | -------- | -------------- | -------- |
| 封面 | - | 谁提交、什么题目、什么专业方向 | 姓名、学号、导师、学院、专业、日期真实完整；无旧模板残留 |
| 一、引言 | 约 500 字 | 为什么读这些文献，和本人研究有什么关系 | 有具体场景/问题，不用万能背景；说明文献选择依据 |
| 二、文献基本情况概述 | 约 600 字 | 文献类型、方法、结论和关联是什么 | 至少一张文献矩阵；每篇文献都有“与本研究关联” |
| 三、文献核心内容综述 | 约 2000 字 | 多篇文献合起来说明了什么 | 按主题/方法/问题链组织；每个主题至少综合 2 篇文献或说明单篇限制 |
| 四、研究空白与争议焦点 | 约 800 字 | 已有研究没解决什么，分歧在哪 | 空白要由文献证据推出；避免“无人研究”“填补空白”等绝对化 |
| 五、对自身研究方向的启示 | 约 800 字 | 对论文问题、方法、数据、章节有什么作用 | 至少对应到研究问题、方法选择、指标/模型或论文章节中的 2 项 |
| 六、总结 | 约 300 字 | 本次阅读形成了哪些具体判断 | 总结可执行收获；下一步阅读或研究动作有对象和目的 |
| 参考文献 | - | 正文引用是否可追溯 | 按 GB/T 7714-2015 顺序编码制；正文编号与列表一一对应 |
| 提交前自检 | - | 是否达到 MEM 提交质量 | 由 `scripts/audit_report.py` 生成，默认不写入正式 DOCX |

小节级质量标准：

- **1.1 选题背景与研究方向**：写清具体工程管理场景、研究对象和痛点；不能只写宏观趋势。
- **1.2 文献选择依据**：说明为什么选这些文献，覆盖了哪些主题/方法/场景；弱文献模式要说明覆盖不足。
- **2.1 文献统计**：写总量、精读数量、类型分布、年份范围；中期前第 4 篇必须能移入中期报告。
- **2.2 核心文献矩阵**：每篇文献有方法、核心观点、局限、与本人论文的具体关系。
- **3.1-3.n 主题综述**：每个主题至少包含“已有结论 + 支撑文献 + 适用条件/局限 + 对本文的含义”。
- **4.1 研究空白**：空白必须来自文献对照，不写“无人研究”“填补空白”等绝对化表述。
- **4.2 争议焦点**：说明分歧来自研究对象、样本、方法、指标或场景差异，而不是简单说“观点不同”。
- **5.1 方法启示**：写明拟借鉴的方法、需要调整的参数/变量/流程和调整依据。
- **5.2 论文落点**：对应到研究问题、章节、指标体系、模型、数据来源或实践方案。
- **6.1 阅读收获**：总结 2-3 个具体判断，不写泛泛感想。
- **6.2 下一步动作**：写明继续补哪类文献、用于解决哪个论文问题、预计交付什么。

若这是 MEM 中期前第 4 篇读书报告，第 2 节和第 5 节额外满足：

- 给出文献阅读统计：总量、核心文献数、中文核心/学位论文/外文文献等分类。
- 给出 5-10 篇核心文献矩阵：核心观点、方法、与本人论文关联。
- 明确“文献综述如何引出研究问题、方法选择或创新点”。

## 8. 自动评分与交付质量门

生成 DOCX 前必须运行自动审查脚本：

```bash
python3 scripts/audit_report.py \
  "<草稿.md>"
```

该脚本按 MEM 100 分制输出启发式评分：

| 项目 | 分值 | 低分原因 |
| ---- | ---- | -------- |
| 完成度 | 30 | 字数不足、缺核心章节、缺中期材料、缺核心文献矩阵 |
| 规范性 | 20 | 封面缺项、引用编号不一致、参考文献格式粗糙、图表无编号 |
| 逻辑性 | 20 | 文献串联、缺共识分歧、研究空白与论文题目脱节 |
| 可行性 | 20 | 下一步计划无时间/交付物/验收标准，成果无证据 |
| 创新性 | 10 | 只罗列文献，缺场景、数据、方法或实践对象上的具体增量 |

质量门：

- **低于 70 分**：不能作为正式版交付；必须补齐低分项，或明确告知用户只是草稿。
- **70-79 分**：可作为基础版，但要在最终说明中列出风险和建议补强项。
- **80 分及以上**：可作为正式初稿；仍需人工核对文献元数据和导师偏好。

自动评分不能替代人工判断。若脚本分数高但文献证据薄弱、成果不可追溯、研究方向错配，应以人工审查为准并降级。只有用户明确要求保留评分附录时，才可使用 `audit_report.py --append-checklist` 和 `md_to_docx.py --audit-appendix`。

## 9. 生成 DOCX

使用本 skill 的模板转换脚本。脚本以 `assets/template.docx` 为基底，保留模板样式、页眉页脚、页面设置和封面结构，只重写正文内容。

```bash
python3 scripts/md_to_docx.py \
  --no-audit-appendix --clean-generate "<草稿.md>" "<输出.docx>"
```

草稿必须包含封面字段：

```markdown
# 报告题目

姓名：XXX
学号：XXXXXXXX
导师：XXX
学校：XXX大学
学院：XXX学院
专业：XXX
研究方向：XXX
提交日期：YYYY 年 M 月 D 日
```

## 10. 中期报告五段结构

用户要求完整 MEM 中期报告时，按以下结构生成或审查：

1. **课程学习、实践实训、读书报告完成情况**：课程只列与论文直接相关者；文献阅读要量化并列核心文献矩阵。
2. **已完成论文工作及阶段成果**：每项成果用 What → How → Result 写闭环，并配证据。
3. **与开题报告不符情况说明**：按“原计划 → 实际情况 → 原因与调整方案”写；没有偏离也要说明核对依据。
4. **下一步论文工作安排**：按月份或节点写任务、交付物、验收标准、风险缓冲，避免“继续看文献”。
5. **已写章节内容与三级目录**：列已完成章节、字数或页数、主要内容节选，并给出完整三级目录。

完整细则、评审表硬约束和现场追问见 `references/midterm_requirements.md`。

## 11. 写作风格要求

- 学术化但不堆术语；第一次出现专业概念时给出简短解释。
- 每段要服务于论文主线，体现作者判断，不做中立旁观摘要。
- 段落 150-300 字为宜；句子以 25-50 字为主。
- 不写万能句：“具有重要理论意义和实践价值”“随着……不断发展”“继续深入研究”等。
- 正文引用使用顺序编码制，如 `[1]`、`[2-4]`、`[5, 7]`。
- 不编造数据、页码、作者观点；拿不准的字段标 `[待核对]`。
- 示例只学结构和写法，不迁移示例中的行业、数据、作者或结论。

详细去 AI 化规则见 `references/anti_ai_checklist.md`，跨方向示例见 `references/writing_examples.md`。

## 12. 配套资料一键生成

每篇读书报告生成 Word 后，**必须同步生成以下配套资料**，打包在同一目录下。这是 MEM 读书报告会的硬需求——系统填报需要摘要、口头汇报需要 PPT 大纲。

### 12.1 必生成资料清单

| 序号 | 资料 | 用途 | 格式 |
|------|------|------|------|
| 1 | 读书报告摘要 | MEM 系统"读书报告摘要"字段填报 | 300-500 字纯文本 |
| 2 | PPT 大纲 | 口头汇报准备（15-20 分钟） | 8-10 页结构大纲 |
| 3 | 全套资料汇总 | 所有报告的统一索引导航 | Markdown 表格 |

### 12.2 读书报告摘要规范

- **硬约束：摘要少于 300 字禁止输出**；必须退回补写到 300-500 字后再交付
- 300-500 字，无图表，无公式，无参考文献引用
- 结构：背景（1句）→ 覆盖文献（列出作者+主题）→ 组织逻辑 → 核心发现（2-3句）→ 对学位论文的支撑
- 示例结构：
  > 本报告围绕[研究方向]，选取[文献A]、[文献B]等X篇文献，按[组织维度]组织综述。分析了[核心发现]，讨论了[研究空白]，为学位论文的[具体环节]提供了[支撑类型]。

### 12.3 PPT 大纲规范

- 8-10 页结构，标注每页核心内容和时间分配
- 结构：选题背景 → 文献选择 → 核心发现（2-3页，按主题）→ 研究空白 → 对论文启示 → 总结
- 不要写"谢谢聆听""Q&A"等水页
- 每页要点用条目式，不超过 5 条

### 12.4 生成时机

- **单篇模式**：每篇报告转 Word 后立即生成配套资料
- **批量模式**（>=2 篇）：所有报告 Word 生成完毕后，统一生成含全部配套资料的汇总文档
- 配套资料与报告放在同一目录，命名规则：`读书报告X_配套资料.md` 或 `读书报告_全套资料汇总.md`

### 12.5 与中期报告的衔接

生成配套资料时，自动检查是否需要同时输出中期报告相关字段：
- 如果用户处于中期报告阶段（5-6 月），额外生成"中期报告会系统填报指引"
- 如果已有多篇报告，汇总表中包含各篇的评分、字数、主题、填报摘要

完整细则见 `references/midterm_requirements.md` 的"读书报告衔接规则"。

## 13. 报告间互补检查

当同一用户已经有多篇读书报告，尤其是第 2-4 篇或中期前集中生成时，必须检查报告之间是否互补，不能只是换标题重复同一套话。

硬规则：

- **主题互补**：每篇报告至少有一个清晰差异点，如理论基础、研究方法、数据来源、应用场景、管理问题或论文支撑章节。
- **文献互补**：核心文献重复率原则上不超过 40%；必须重复引用的基础文献，要说明其在本篇中的新用途。
- **论文章节互补**：每篇报告都要对应到学位论文的不同落点，避免全部写成“支撑文献综述”。
- **研究空白互补**：不得四篇都写同一个空白；若空白一致，要分别说明理论空白、方法空白、数据空白或场景空白。
- **中期统计一致**：第 4 篇读书报告、全套资料汇总和中期报告中的阅读数量、核心文献数、文献类型分布必须一致。

交付前输出一行互补结论：`本篇相对前序报告的新增贡献是：……；与前序报告可能重叠的部分是：……；已处理方式：……`。

## 14. 文献可核验规则

正式报告中的每一条文献、数据和实质观点都必须可核验。可核验不是“看起来像引用”，而是能回到具体文件、页码、章节、DOI、URL 或用户材料。

硬规则：

- **参考文献来源**：参考文献表只保留已提供文件、已真实检索并记录链接、或用户明确确认的文献；不得根据题名猜作者、期刊、年份、卷期和页码。
- **正文观点定位**：每个关键判断至少能对应到文献编号 + 页码/章节/表图号；PDF 解析失败、OCR 质量差或只读摘要的内容只能标为弱核对。
- **外部文献核验**：用户要求补充新文献时，必须记录检索来源、访问日期、DOI/URL 或数据库信息；无法核验的文献不得进入正式参考文献表。
- **数据与案例核验**：业务量、样本量、指标值、政策日期、企业案例和模型结果必须附来源；只来自示例或模型推断的内容必须删除。
- **引用格式核验**：正文顺序编码与参考文献一一对应；参考文献格式缺字段时标 `[待核对]`，正式交付前不得残留未说明的 `[待核对]`。
- **摘要可核验**：摘要中出现的核心发现、文献数量、方法和论文支撑关系必须与正文一致，不得在摘要中新增正文没有证据的结论。

交付前至少抽查 3 条最重要结论，写入内部核验记录：`结论 → 文献/材料 → 定位 → 是否可用于正式稿`。

## 15. 对抗审查循环

生成 DOCX 后、交付前，必须执行对抗审查循环。这不是一次性检查，而是”审查→修复→再审查”的迭代过程，最多 3 轮。

### 15.1 循环机制

```
生成 DOCX → 自动评分(§8) → 对抗审查(§15) → 发现问题?
                                          ├─ 致命问题 → 自动修复或标记 → 重新审查(下一轮)
                                          ├─ 重要问题 → 自动修复或标记 → 继续同轮
                                          └─ 无致命/重要 → 输出审查通过报告 → 交付
```

- **最多 3 轮**。第 1 轮全量审查，第 2 轮只复查上一轮标记的问题，第 3 轮确认修复。
- 迭代满 3 轮仍有致命问题：降级交付（标注为”草稿”），输出未修复问题清单和人工处理建议。
- 每轮结束时输出：`对抗审查第 X 轮：致命 Y 条 / 重要 Z 条 / 已修复 W 条 / 需人工 N 条`

### 15.2 自动审查清单（第 1 轮必检）

逐项执行，结果分为 PASS / WARN / FAIL：

| # | 检查项 | 判定 | 自动修复 |
|---|--------|------|---------|
| 1 | 生成痕迹 | 正文含 “Codex””自动评分””MEM_READING””AI 生成””启发式自检” → FAIL | 自动删除含这些词的段落 |
| 2 | 摘要字数 | 系统填报摘要中文字符 < 300 → FAIL | 无法自动修复，标记需人工扩写 |
| 3 | 文献年份一致性 | 同一文献在不同报告中年份不一致 → FAIL | 自动统一为 BibTeX 正式出版年 |
| 4 | 参考文献完整性 | 正文引用无对应参考文献条目 → FAIL | 无法自动，标记需人工补或删 |
| 5 | 样本量可核验 | 正文出现 n=XXX 但无来源标注 → WARN | 自动追加”[数据来源待核验]” |
| 6 | DOI 缺失 | 期刊/会议论文缺少 DOI → WARN | 自动从 BibTeX/Crossref 补入 |
| 7 | 报告间重叠 | 多篇报告核心文献重叠 > 40% → WARN | 无法自动，输出重叠报告和文献列表 |
| 8 | 章节编号连续 | 章节跳号或缺章 → FAIL | 无法自动，标记需人工修正 |
| 9 | 万能句式 | 含”具有重要理论意义””填补国内外空白””随着…不断发展” → WARN | 自动替换为”[具体说明]”占位 |
| 10 | 中期规范时效 | midterm_requirements.md last_verified > 90 天 → WARN | 无法自动，提醒用户确认最新政策 |
| 11 | 封面字段完整 | 姓名/学号/导师/学院/专业/日期任一项缺或为占位符 → FAIL | 无法自动，必须人工回填 |
| 12 | GB/T 7714 格式 | 参考文献格式不统一（大小写混用、缺DOI、期刊名不完整） → WARN | 尝试自动统一，不确定处标[格式待核] |
| 13 | 实证数字来源 | 正文出现 KMO/R²/p值等统计结果但无”数据来源见…” → WARN | 自动追加”数据来源见学位论文第X章”占位 |
| 14 | 报告间内容互补 | 多篇报告”启示”部分指向相同论文章节或雷同表述 → WARN | 输出重叠段落，标记需差异化 |
| 15 | 占位符残留 | 含”TODO””待补充””[待核验]”超过 3 处 → WARN | 超过则输出清单，要求减少后交付 |

### 15.3 双重角色审查

自动审查后，以两个角色做人工视角的文本审查：

- **ZJU MEM 盲审专家**：看研究问题是否真实、文献是否能支撑论文、方法是否匹配、成果是否可验证、创新是否克制。重点追问：”这个结论哪篇文献支撑？””这个数据从哪里来？””这个方法为什么选它？”
- **学院教务管理员**：看封面和身份字段、时间节点、读书报告篇数、中期登记材料、导师签字、三级目录、格式和系统填报是否缺项。

出现以下情况要主动打回修改：

- “看起来很完整”，但文献矩阵中的观点无页码/来源，正文引用不可追溯。
- “中期进展写得漂亮”，但没有样本量、图表、模型、章节字数等证据。
- “自动评分较高”，但研究方向与用户论文题目不一致，启示部分可套用于任何题目。
- “格式像模板”，但封面字段沿用旧姓名/学号/导师，或参考文献并非 GB/T 7714-2015。
- “摘要已达标”，但摘要中出现的核心结论在正文中找不到对应证据。

### 15.4 迭代与退出

| 轮次 | 动作 | 退出条件 |
|------|------|---------|
| 第 1 轮 | 执行 15 项自动审查 + 双重角色文本审查，记录所有 FAIL/WARN | - |
| 第 2 轮 | 只复查第 1 轮 FAIL/WARN 项；FAIL 项必须有修复动作 | 无 FAIL 项 |
| 第 3 轮 | 确认修复后无新问题产生 | 无 FAIL 项，WARN ≤ 3 条 |
| 3 轮后 | 仍有 FAIL 则降级为草稿交付，附未解决问题清单 | 强制退出 |

### 15.5 通过标准

- **正式稿**：0 条 FAIL，WARN ≤ 3 条，所有实证数字可追溯，文献年份统一，无生成痕迹。
- **有条件通过**：0 条 FAIL，WARN 3-5 条。交付时列出每条 WARN 和人工处理建议。
- **草稿**：仍有 FAIL 或 WARN > 5 条。明确标注”不建议直接提交”，附完整问题清单。

详细对抗清单见 `references/adversarial_review.md`（含本次审查发现的 4 致命+9 重要典型案例）。

## 17. 失败模式

- 文献综述写成逐篇摘要，缺少跨文献综合。
- 读书报告没有落到本人论文问题、方法或章节安排。
- 文献数量或质量不足，却写成“系统综述”或“全面研究”。
- 正文出现无法追溯的数据、页码、作者观点或参考文献。
- MEM 中期文本只写“计划做”，缺少已完成证据。
- 缺少课程学习/实践实训/读书报告部分。
- 进度不足 50% 或工作量偏少却没有解释与补救计划。
- 图表无编号、公式无出处、参考文献混乱。
- 研究方法与问题不匹配，或成果展示与开题目标脱节。
- 下一步计划只有“继续看文献、完善论文”等空话。
- 回避真实难点，写“暂无问题”但没有核对依据。
