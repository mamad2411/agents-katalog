# lgui-ux：原型图 → UX 设计稿

**什么时候用：** 用户给了一张原型图要照着做界面；或者界面需求要先和用户对一遍再动手。设计稿定了以后，拼界面用 `lgui-ui`，写功能用 `lgui-code`，截图验收用 `lgui-verify`。

**先读：** [做法](references/method.md)（固定步骤，每次照做）和 [design.json 的字段](references/design-json.md)。

**命令行在哪：** 本技能所在目录往上两级是插件目录，命令行是 `node <插件目录>/tools/lgui.mjs`（下面写作 `lgui`）。

**输入：** 原型图；工程（有就读 `.lgui/project.json` 的方向、设计尺寸、语言，没有就问）。**开始前问用户这几件事，不要自己定：** 原型图是不是自己的作品；只出设计稿，还是连开发交接一起（全套）；只出网页还是也导出 Unity；只有触屏还是也有键盘鼠标；图里没有的画面（弹窗等）要不要一起设计；美术谁出。

**命令：**

| 要做的事 | 命令 |
|---|---|
| 量位置、尺寸、颜色：把原型图的一块放大，叠上坐标网格，列出主色 | `lgui ux crop <原型图> --rect x,y,宽,高 --scale <设计单位换算>`（网格标的数就是要写进设计稿的数；先整图分区看，再每个部件放大 3 倍以上量） |
| 看工程里有哪些现成的可以用 | `lgui ui list --shared`（框架自带和项目通用的组件、图片、字体） |
| 校验设计稿，生成原型页和线框图 | `lgui ux page <design.json 所在的文件夹>`（有错什么都不写；警告逐条处理或和用户确认） |

**要点：**

- 设计稿只有一个源文件 `design/<名字>/design.json`，原型页、线框图、开发交接都由它生成，不手改。
- **元素只列一遍，叠三层：** 方向只管位置（两个方向的控件名和类型必须一样），语言只管文字，平台只管能不能做。工程是横竖都支持的，全屏画面两个方向都要出；没有原型图的那个方向自己设计，并标成「自己设计」。
- **每个数标来源：** 在图上量的、估的、自己设计的，分开写，不把估的当成量的。
- **每个元素标复用来源：** 框架自带、框架自带换样子、排布模式、工程已有、新建。先查再标，不凭记忆；设计稿只写要什么，不写框架怎么实现。
- **原型图不是自己的作品时，** 只用来对位置、尺寸、质感和颜色；角色、名字、图案都换成原创的，替换的文字和原文差不多宽。
- **做不做是用户定的：** 每个元素是完整实现、占位、还是只显示，拆完元素后给用户看原型页确认；没把握的判断列进未定事项，写上没人答时怎么办。
- 图里的文字照原样量，但超出框架上限的（描边太粗、字太小）不照抄，给出选择让用户定。

**产出：** `design/<名字>/` 里的 `design.json`、原型图、`prototype.html`（给用户看）、`wireframe/`；全套模式多一份 `handoff.md`。交回时写：几个画面几个元素、要新做哪些、还有哪些未定事项、还剩哪些警告。错误码见 [error-codes.md](../../references/error-codes.md)。
