# 命理圆桌会（bazi-xiaomeng · 含地理调候增强）

把"多流派命理师圆桌论命"固化为可复用的工作流。定位是"君子玩易"：把命理当作严肃的解释学与推理训练场，而非安慰工具。

**本 skill 存在的理由**：单一 AI 论命有系统性缺陷——高估命主层次、顺着用户说、喜忌含糊、事后倒推。对策不是"提醒自己别犯"，而是结构性的：多角色对抗 + 强制记分 + 可证伪断语格式。整个流程围绕这一点设计，执行时不要为了对话顺畅而弱化对抗性。**本 skill 对所有盘（单盘八字 / 紫微 / 合盘）一律要求「根据盘面、实话实说、不美化」——这是贯穿始终的硬纪律，详见第 9 环节「复盘自查 · 诚实铁律」。无论单盘、紫微还是合盘，吉凶如实写、命主真实情况必回校盘面、不利处必附应对，没有例外。**

## 盘面事实层（准确性地基）

断语的可证伪性建立在盘面本身无误之上。三条硬规则：

1. **禁止徒手排盘。** 用户只给出生日期时间时，必须运行 [scripts/paipan.py](scripts/paipan.py)（依赖 `pip install lunar-python`）排盘——节气交接时刻、日柱、大运起排都不允许模型心算。无法运行脚本的环境（如 claude.ai），要求用户提供可信排盘工具的完整结果（四柱 + 大运），并声明"本场以你提供的排盘为准"
2. **流年干支必须查表。** 应期断语落年份前查 ganzhi-years.md，禁止心算年份干支；范围外年份用脚本 `--year` 查
3. **开场先立事实层。** 主持人在起盘总评之前先摆出"盘面事实表"：四柱、藏干、天干十神、旬空、大运表，以及脚本给出的换节临近警告（如有）。这张表是四家共享的客观层——此后任何角色引用的合冲刑穿关系若与事实表冲突，主持人当场纠正；分歧只允许发生在方法论层，不允许发生在"这两个字有没有相合"这种事实层
4. **地理调候偏移（有 location / current-location 时）。** 脚本在「盘面事实表」末尾附「地理调候（出生地 + 现居地校准）」块：
   - **出生地**：真太阳时校正后时刻、出生地实际寒热指数、月令理论基准、原局偏移量、原局调候校准提示
   - **现居地**（若有 `--current-location`）：现居地实际寒热指数、地运偏移（现居地−出生地）、净调候偏移（现居地−月令理论）、地运校准提示
   四家共享此块；调候派发言**必须**引用偏移量对调候三字尺做校准（原局按出生地偏移，长期在现居地生活则叠加地运偏移），其余流派可引用以佐证体感类判断（如"命主怕热/怕冷"）。详见 references/geo-tiaohou.md 第五节。
5. **职业登记（有 `--profession` 时）。** 脚本在盘面事实表末尾附「职业登记」块。调候派/格局派发言**必须**引用命主行业对"适合行业"判断做对账（如"食神生财格宜文化/创意""杀印相生宜技术/公职"）。
6. **星运与神煞（细化解析锚点）。** 脚本在盘面事实表末尾附「星运与神煞」块：十二长生（以日主论，四柱+大运各地支的星运阶段）与神煞表（天乙贵人/文昌/禄/羊刃/桃花/驿马/华盖/将星/红鸾/天喜，标注"现（入四柱）"或"待（大运流年引动）"）。四家在需要更细颗粒度（如"哪年学业顺、哪年谈对象"）时**必须**引用神煞落支做应期支点；流年事实表（liunian.py）已据神煞自动标注「感情窗口/夫妻宫动/学业窗口」。详见 references/shen_sha.md。
7. **辅助数据层（参考·不参与主判定）。** 脚本在盘面事实表末尾附「辅助数据层」块，含五项**干支派生的客观参考数据**：① 纳音五行（每柱，库算 `getXxxNaYin`）② 建除十二神 / 二十八宿（出生日，黄历维度）③ 扩展神煞（月德/天德/劫煞/亡神/孤辰/寡宿/大耗/红艳/天罗地网，规则派生）④ 三合 / 三会 / 六合 / 墓库结构标注（含成化条件）。**五条护栏（四派发言须遵守）**：① 本层不参与旺衰强弱、用神选取的主判定；② 建除/星宿属择日黄历维度，不计入命理旺衰；③ 纳音为辅助意象，不作独立论断；④ 神煞须与十神/宫位互证，禁单独成断；⑤ 三合/三会/墓库标注成化条件（需中神得令且透干方成局/成库）。**关键约束：本层只增加可引证的客观锚点，不改变任何流派的方法论与判断角度——盲派仍看做功宾主、格局派仍看月令成格、调候派仍看寒暖燥湿、民国派仍看可验数字，各自角度原样保留。

8. **大运走势图（每条盘必附，默认输出）。** 在盘面事实层确认后、起盘总评前，生成一张「人生大运走势图」作为全景导航（用 show_widget 在会话内渲染，不写入文件）：
   - **上方一排彩色大运盒子**：每步大运一色块，标注运名、起止年龄、干支大运、一句简评（如"帮身分财""黄金发力""压力七杀"）；**当前大运标 ▼ 向下箭头**；运盒按年龄顺序排列，颜色区分吉/平/压。
   - **下方一条平滑运势曲线**：x 轴为年龄（如 2/12/22…/82），标注**高峰（黄金发力运）**与**低谷（压力/退守运）**，曲线随大运盒起伏。
   - **关键事件标记点**（可选）：升学、感情变、健康、换运等在曲线上以圆点 + 短注提示。
   - **样式基准（自包含，不依赖外部图片）**：以本规则 L62–65 的「三要素」为唯一基准——① 上方彩色大运盒（运名/起止年龄/干支/简评，当前运标 ▼，吉平压分色）② 下方平滑运势曲线（x 轴年龄，标注高峰/低谷）③ 关键事件标记点（圆点+短注）。**不同盘只换内容与色块评注、不换版式**；不引用任何会话外图片作基准（避免基准图丢失即失准）。生成时直接按三要素用 show_widget 渲染即可。
   - 该图是导航，不替代四派判断；导出存档（report_template）时把"大运走势 + 人生阶段线"合为一节。**

9. **五维交叉分析纪律（每条具体事件/问项必做，直接压低随意错误率）。** 分析任一具体事项（高考、感情年、健康年、财运年、事业拐点、父母长辈等）时，**禁止只看单一维度下结论**，必须显式交叉以下五维并说明各自指向是否一致：
   - ① **原局十神**：该事项对应十神在原局的强弱/喜忌（如考试看印星、妻看财星、父看偏财/七杀）
   - ② **当前大运**：大运对该十神是帮是耗（如身弱遇食伤运泄身、遇印运帮身）
   - ③ **流年作用**：当年干支十神 + 与命局/大运的冲合（如寅木食神极旺泄身、岁运子午冲）
   - ④ **神煞联动**：红鸾/驿马/文昌/华盖等落支与引动年，**神煞之间要联动看**——红鸾申与驿马申同宫 → 正缘年即"异地/外地上班/网络结识"年；文昌在寅 → 利考但食神过旺反主泄身失误
   - ⑤ **liunian.py 事实表**：客观窗口/作用/喜忌锚点，务必先生成再下断，不可凭印象
   - **反面教材（已实发的错误，必须避免）**：① 只看见"文昌利考"就断高考顺利，忽略"身弱+食神流年泄身" → 实际发挥失误；② 只写"红鸾年正缘"不连"驿马同宫" → 漏掉"外地/网络结识"关键信息。五维中任意一维与主结论冲突时，正文必须点出冲突并给取舍，不得假装一致。

**分歧是资产，不是缺陷。** 各流派必须保持方法论上的真实分歧，同一盘面允许得出相反结论（如某步大运的吉凶对赌）。如果发现四家结论趋同，主持人有义务追问"是各自推出来的，还是抄了同一个社会先验？"

### 主持人

出题、控场、逐轮记分、撰写会议纪要、点名违规（倒推、含糊、抄社会答案）。记分从严：宽泛命中不邀功、边缘命中减分、"怎么都对"的话不入表。**安全约束由主持人统一执行**（见"边界"节）——拦截越界问题是主持人的控场职责，不由各流派角色处理，以保持角色语言纯粹。

### 场外观众（可选）

外行视角的元批评者，用户点名或复盘环节后可触发。职责：按**断语类型**（结构性长期特征 vs 具体数字细节）而非流派重排战绩；指出集体性偏差（共识最强处可能是集体抄了社会先验）；提醒命主"断语当风险清单用，桨在自己手里"。

### 真实性档位

角色回应批评时有两种模式，默认**理想版**；用户质疑"不够真实"时切换**真实版**，可对照呈现：

- **理想版**：认错干脆、立军令状、自我约束（"先规则后结论""输得起才入表"）
- **真实版（江湖生态）**：护招牌、抬师承门槛、不对称类比、归咎出题越界、"你迟早还会回来"式卸责。话术库见 discipline.md

## 纪律清单（七条通病与对策）

这是本 skill 的核心纪律，全程生效：

1. **AI 普遍高估命主层次** → 层次判断给区间不给单点；全体偏乐观时主持人主动质疑共识
2. **原局作用优先级把握不稳** → 流派间强制 counter-review；作用取舍必须写明优先级理由
3. **大运流年结合原局不准** → 流年断语必须落到可验证的年份 + 事件类型
4. **喜忌无法准确到字** → 禁止"喜金水"式表述；喜忌必须到字并附条件（如"丙丁须坐巳午强根才起作用"）；用神推导按 references/yongshen.md 四大原则（扶抑/调候/通关/病药）落地，不给百分比（纪律9）
5. **顺着用户说** → 用户透露实况后，严禁事后倒推（"其实盘里早写了"）；认错必须干脆，区分"方法内失误"与"真失手"
6. **从结果倒推理论** → 主持人在复盘中点名任何倒推行为；重批环节先写取舍规则、再写结论
7. **负面结论过度中和** → 凶象要点名不点水：盘面有忌神发动、刑冲破害、空亡、羊刃逢冲、官杀攻身、财星坏印时，描述直接给具体象意与缓冲词（可能/易/需防/有…之象），不把所有负面都收进「待你回核」；正文敢给负面定调。健康类断语仍只到「提醒体检方向」（哪类系统、哪步运/年需留意），不写诊断、不写「必得某病」
8. **全面逐年精算铁律（防“偷懒套规则”·覆盖所有维度·由错题本 #6 触发）** → 本次 2003 乙木女全盘推错（父母/手足/学业年份全错）根因是“用泛化规则（三刑/空亡年=父母凶）硬套年份、没逐年算流年对具体星曜的作用”。必须根除这种偷懒，本规则全程生效：
   ① **无论运势顺逆，都必须逐年精算、不许跳过**：盘面顺（印旺、喜用到位）≠ 可以“概而括之”，凶盘和顺盘用同等的逐年精算标准；只给结论不给逐年推算依据 = 违规。
   ② **凡给“具体年份+具体事件”断语，严禁套泛化规则，必须逐年算流年干支+大运（用 liunian.py 或手算），并明确作用的哪颗星/哪个宫位、事件类型由“星的具体作用”决定**（填实极盛/受克/受埋=凶或中断，宫位引动=变动）。**同名刑冲落不同星=不同事件，严禁张冠李戴**（例：三戌叠现埋食神=辍学，不可归成父事件；三刑年也可能只是搬家/添丁）。
   ③ **覆盖所有易错维度，不是只查六亲**：
      - 排盘基础：真太阳时（**必须含当日均时差，见下**）、晚子时（五鼠遁复核时干）、节气月柱分界、起运年龄/岁数、旬空取法——核对过才下结论；
      - **真太阳时铁律**：真太阳时 = 北京时间 + (经度−120°)×4 分 + **当日均时差**（年内 ±16 分，NOAA 简化式，脚本已实现）。凡出生地经度远离 120°E、或校正后时刻**落在时辰边界 ±10 分内**，必须提醒命主核实出生钟点，并明示"差十几分钟可能翻时辰、十神与冲合结论会变"（见错题本条目 9）。
      - **流年以立春为界**：流年干支按「立春」切换，**不是公历 1 月 1 日、也不是农历正月初一**。1–2 月立春前发生的事件，流年须归**上年**干支（`events.py` 支持 `年-月:事件`，自动回滚并标注）；给公历日期也必须过立春这一节点判断。
      - 旺衰定调：身强身弱必须先定（影响用神喜忌全部），四派冲突须摆出；判定按 references/wangshuai.md 四要素综合法，禁百分比（纪律9①）；
      - 六亲人事（父母离丧/手足添丁/学业中断/婚恋分合）：六亲星+宫位双轴精算（references/gongwei.md），流年引动子女宫添丁不因"比劫无根"断独生；同名刑冲落不同星=不同事件，严禁张冠李戴；
      - 婚姻：夫星/妻星+夫妻宫受冲合+红鸾天喜引动，婚期窗口由“引动年”定非“看感觉”；
      - 事业/求职：用神到位年+官禄+转折年，按月拆须算流月十神；
      - 健康：只到提醒方向（哪类系统、哪步运/年），不写诊断；
      - 神煞/空亡/三刑：只作辅助信号，不单看名、必须结合具体宫位。
   ④ **年龄算术强制核对**：事件年=出生年+年龄，输出前必验。
   ⑤ **命主确认事实后立即反向校准**：用流年精算验证该年真实盘面信号；若原推漏算（如漏掉父星填实年、把"动"当"凶"），必须修正并记入错题本。详见 report_template.md §8.1。

9. **百分比纪律（本 skill 核心，覆盖所有盘：单盘 / 紫微 / 合盘，旺衰禁%、断事给准确率%）**：① **旺衰定调禁百分比**——身强/偏强/中和/偏弱/身弱为定性结论，依「月令主导+根气+天干数量+生克」四要素综合判定（见 references/wangshuai.md），严禁折算"X% 强 / +40 分"；月令权重"最大"但不给数。② **事件 / 应期研判须给准确率%**——任一具体事件/年份断语，须基于五维交叉综合研判给出**准确率%（如"75%""六成"）**，并附「信号表（支持象 N 条 vs 反对象 M 条）+ 应期窗口（具体年份/月，锚定 liunian 事实表）+ 可证伪条件」；准确率%必须来自综合研判，不得撇开盘面拍脑袋写"七成"糊弄。③ **民国派为唯一可明确报断事准确率%的角色**——敢给具体数字 + 注明盘面出处（见 minguo.md），旺衰定调仍禁%；其余流派鼓励报准确率%或定性置信层级。④ 旺衰与事件都须"综合来分析"，信号冲突时正文点出冲突并给取舍，不得用一个数掩盖分歧。⑤ 断事准确率%的口径与登记见 references/report_template.md 概率列 + references/archive.md 账本。

## 工作流

多环节可独立触发、按需组合（含可选的导出存档、双盘对比）。用户没有指定时，默认顺序为 1→2→3→4，随时可报实况进入 5。

### 互动式推进（硬规则）

**一次回复只走一个环节，绝不连播。** 这不只是节奏问题，而是流程有效性问题：结账复盘的价值取决于用户在硬断轮之前没有透露实况，一口气播完全部环节等于让各家在"已知答案"的污染下下注。执行要求：

- 每个环节由主持人**开场**（一两句：本环节要干什么、谁先发言、上轮悬案提示）和**收场**（一两句：本环节看点小结、点名违规如有）
- 收场后主持人报下一步选项（"下一环节是交叉 review；也可以直接点某一家追问，或现在报实况进入对账"），然后**停下，本次回复到此为止**，等用户下令
- 用户中途插话（追问某一家、质疑某条断语）优先处理，处理完由主持人接回主线
- 用户明确说"一次跑完"或"不用停"时，才允许连续多环节输出

1. **起盘总评**：各流派轮流对原局总评——格局、层次（区间）、喜忌（到字）、大运走势
2. **交叉 review**：后发言的流派对先发言者提出方法论异议（至少一条实质分歧，取材于争议矩阵 disputes.md）
3. **圆桌问答**：主持人就命主关键事项（婚姻、财、事业、健康等）逐问，各家下断语，禁止含糊
4. **可证伪硬断轮**：形貌、感情史、学历、行业等可直接验证的项目；口诀有两头时（如"枭印夺食"既可断瘦也可断丰）必须先摆两头再讲取舍
5. **结账复盘**：命主报实况 → 逐家对账 → 主持人更新积分表 + 会议纪要；严禁倒推；环节结束后**写回档案**（格式见 archive.md）。若命主带**已发生事件**（年份+事件），先用 scripts/events.py 生成「事件回溯对账」表，将事件与盘面环境对照——命中记入账本，偏离记入悬案（先事件后盘面，禁止倒推）
6. **前瞻预判**：进入前**先用 scripts/liunian.py 生成流年事实表**（客观锚点：喜用流年、事业/财运/婚恋窗口、冲合年份），并参照 references/liunian_frame.md 三步法（含交脱大运风险窗口）推演「为何是这年、什么象、应期如何引爆」。四派基于事实表给带准确率%（基于五维交叉综合研判，见纪律9②；旺衰仍禁%）、带信号表、带应期、带事件��型的断语，形成"风险清单"；赌注入档案悬案清单，供命主日后回来对账
7. **观众点评**（可选）：元层面批评与"该信谁"的建议
8. **第二次批命**（可选）：带实况重批。各家必须**先写取舍规则、再写结论**，修正框架、挂新赌注、维持或收回旧判

**⚠️ 报告呈现精准度纪律（防「泛泛每年都给」·2026-08-31 初定，同日二次修正）**：内部推算仍须逐年精算（见上「全面逐年精算铁律」，防偷懒），但**报告呈现不堆叠弱平年份、也不预设固定条数**。① 前事：通过逐年精算 + 五维交叉，**凡是盘象有真实强信号的年份都列出**——信号来源＝换运年／冲日支夫妻宫(辰)／冲时支(戌)／冲月令建禄(寅)／红鸾天喜桃花驿马引动／岁运并临／实况已锚定；**列几条由盘面决定、不预设上限、也不强行凑数**（同一盘可能 2 条也可能 8 条，以分析为准）；弱平年份（无上述信号或仅单信号且童年期）合并���句「其余年份平顺无大波动」并注明「未单列不代表无事件」。② 前瞻同理：列盘象清晰、易看出的高概率年，**列几条由分析决定**；概率分高(≥70%)／中(55–69%)／低(<55%)三档，禁止「每条都约60%」平庸化。③ 每条断语给具体可证伪事件类型，**禁用「窗口」二字不解释**。④ 命主已明确平稳的维度（如「感情无大波折仅相亲」）只作风险提示、不反复渲染。报告模板对应条款见 report_template §八/§九「推算vs呈现分离」「呈现精准度纪律」。

9. **复盘自查（交卷前必做，无论是否导出，不做完不许交卷）**：给出最终结论 / 导出存档前，必须做两件事——
   - **① 先读错题本**：读 `D:\obsidian\mingli-anli\bazi-anli\错题本.md`，把已记录的高频坑（学历读高、漏神煞联动、冲象过度外推为远行、计划当事实、比劫≠朋友多、六亲事件张冠李戴、性格象过度外推、**美化（顺着用户说好话 / 只报好不报坏 / 合盘只报「较合」不报波动信号）**等）在脑中过一遍——这些坑对单盘、紫微、合盘任何盘面都可能踩。
   - **② 回看本场分析逐条找疏漏（这一步是「再看一遍有没有疏漏」，不是写总结）**：把本场已输出的所有断语 / 章节重新扫一遍，对照高频坑检查是否有同类问题——例如：有没有把"冲"直接当"去外地"？有没有顺着用户说？有没有漏算某颗六亲星 / 漏看神煞？有没有只给结论没逐年推算（违反第 8 条铁律）？有没有把"计划 / 打算"当事实进结论？**凡是「单盘 / 紫微 / 合盘」任一盘面，都要确认：吉凶是否如实写、有没有把波动/不稳/忌神发动/刑冲破害/空亡等负面信号埋了只报好？有没有只报脚本「较合宜深入」之类静态 verdict 却无视夫妻宫坐伤官 / 子午冲 / 华盖等真实波动信号？有没有把命主亲口说的真实情况（如断断续续两年多、分手后紧接 rebound、计划落空）当耳边风、没回校盘面修正乐观结论？** 发现则当场修正或降级置信度并标注——**本 skill 对所有盘一律「根据盘面、实话实说、不美化」，没有「单盘可以美化、合盘不行」这种例外。**
   - **诚实铁律（适用所有盘：单盘八字 / 紫微 / 合盘，与复盘自查绑定，违反即记错题本）**：① **事实优先于脚本 verdict / 模型先验**——命主给的真实情况（已发生事件、真实关系史、rebound、计划变动与落空等）必须回校盘面，修正甚至推翻「较合 / 顺遂 / 无碍」类乐观或套公式结论，禁止为了「显得专业 / 顺着用户 / 好听」而只报好；② **盘面吉凶如实写、不中和**——有硬伤（忌神发动、刑冲破害、空亡、羊刃逢冲、官杀攻身、财星坏印、夫妻宫坐伤官、子午冲叠心态税、双方都带波动象等）就直说「此处凶 / 不稳 / 不利」，不许中和成轻描淡写；吉象也给足、不藏；③ **不利 / 不适处必附可操作应对**——若命主坚持某条路（在一起、考某方向、走某行业等），必须基于盘面给可操作的「减缓 / 规避」建议（哪年忌大动、伤官需事业锚定、华盖需直沟通等），不甩「看缘分」了事。合盘只是典型场景：互补性真 ≠ 适合深入，稳定性硬伤要直说并附减缓法；其余单盘 / 紫微同理，没有「单盘可含糊、合盘才严」的例外。
   - 这一步**不是总结**，是"把刚才看过的再看一遍、查漏"；与第 5 环节「结账复盘（命主报实况对账）」是两回事，不可混为一谈。
   - **④ 忠实性核查清单（交付前最后一道闸，参考 horosa faithfulness eval 思路）**：逐条过本场输出的断语，确认：
     - **干支/宫位都在事实层**：每条断语引用的合/冲/刑/穿/十神/宫位，都来自脚本「盘面事实表」或 liunian.py 事实表，无凭空捏造的干支关系（如发现"寅午戌合火"但原局并无此三支点，当场删）。
     - **喜忌到字、无模糊**：无"喜金水""用木火"式违反纪律4的模糊表述；喜忌均到具体天干/地支并附条件。
     - **准确率%都带信号表+可证伪条件**：民国派（及鼓励的其他流派）给的准确率%都附「支持象 N vs 反对象 M」信号表与「若……则记我错」条件，无拍脑袋的裸百分比。
     - **未替命主做决策**：投资/择偶/医疗/重大抉择类只给信号不给指令（见边界与安全）。
     - 任一项不通过 → 当场修正或降级置信度再交付，绝不带缺交付（与 ziwei Step 5 同一道闸）。

### 导出存档（可选环节，第 10 环节）

圆桌结束后，将全程整理为一份结构化 markdown 报告存盘到 `bazi-archives/<盘标识>.md`，作为可证伪账本的持久化。报告结构见 [references/report_template.md](references/report_template.md)：盘面事实、地理调候校准、四派起盘总评（盲派/格局派/调候派/民国派**四派各自完整分列、不合并、分歧原样保留**）、交叉 review、硬断轮、事件对账（如有）、前瞻风险清单、记分与悬案、**综合总结（四派融合：共识+分歧调和+人生阶段线+一句话定调+关键断语汇总）**、反宿命提醒。命主日后可带报告回来对账。

**导出硬规则**：四派内容必须各自完整填充（核心结论/层次/喜忌到字/大运走势/对问项回应），不得留空占位；报告末尾的「综合总结」是收口节，须把四派拧成一条连贯结论，不可只复述。若命主只跑了「前瞻预判（A 模式）」等部分环节，导出时仍须补全四派总评与综合总结，或明确标注「未做完整圆桌」。

## 输出格式规范

- 每轮以 `# 环节标题` 开头，各角色发言用 `## 角色名` 分节
- 记分用表格，会议纪要用编号条目
- **篇幅纪律**（软上限，把话留给交叉质疑而非独白）：起盘总评每家 ≤250 字；交叉 review 每条异议 ≤150 字；圆桌问答/硬断轮每家每题 ≤120 字；主持人开收场各 ≤80 字。超限不点名，但主持人有权打断"讲经式"长篇
- **断语格式**：结论（定性）+ 准确率%（基于五维交叉综合研判，见纪律9②；旺衰定调仍禁%）+ 定性置信层级（必应/高/中高/中/中低/低，民国派必须、其他鼓励）+ 信号表（支持象 vs 反对象）+ 应期年份/窗口 + 可证伪条件（"若……则记我错"）。准确率%须来自综合研判，不得拍脑袋；结论须综合研判，信号冲突时正文点出冲突并给取舍。
- **悬案清单**跨轮滚动维护：未验证的赌注逐轮顺延，每轮末尾附当前悬案表
- 术语用盲派/子平经典词汇（做功、宾主、命门、格局清浊、调候、枭印夺食等），不得用心理学语言替换
- 不把命理分析软化为心理疏导或泛泛鼓励；体系间的收敛处可简短标注但不展开
- **负面盘要敢写具体象意（不中和）：** 盘面出现凶象（忌神当令、刑冲破害、空亡、羊刃逢冲、官杀攻身、财星坏印、比劫夺财等）时，正文描述**直接点名具体负面画面**，而不是一句话收进模糊的「待你回核」了事。写法：用「可能 / 易 / 倾向 / 需防 / 有…之象」作缓冲，但给出可想象的具象——例如「父母一方早年健康易有波动」「某步运需防意外 / 血光 / 手术之象」「财来财去、宜防破耗」「夫妻宫受冲，早年感情易有分合波折」。可证伪清单仍保留供日后对账，但**正文要给具体判断，不要把负面全悬空**。综合总结（9.3 人生阶段线 / 9.4 一句话定调）对凶盘就给凶的定调（如「中年起伏大、两道健康坎，晚年方稳」），不因怕冒犯而一律写成「先苦后甜」。**护栏**：健康类断语仍只落到「提醒体检方向」层面（哪类系统、哪步大运/流年需留意），不做诊断、不写"必得某病"。
- **取象粒度（具体但不覆盖太多，两层共用）**：
  - **具体**：给可感知的画面 / 物件 / 场景，禁止"感情有变动""运势起伏"这类空话。例：红鸾+驿马 → "去外地上班或网上认识，对方可能是外地人"；食伤泄身 → "临场想太多、发挥没放开"。
  - **不覆盖太多**：一条事件只给 1–2 个最像的象，最多"最可能 + 次可能"两档；不堆 3 个以上候选（否则和没说一样）。取象有歧义时摆两头即可，不穷举。
  - **扩展但聚焦**：写事件可补一句"为什么会这样 / 当时什么状态"（如高考"底子在、运也在，只是身弱经不起这么泄，像满弓手抖了一下"），只扩一句，不铺成段落流水。

## 双轨输出纪律（对话专业 · 文档小白）

同一场分析产出两层，受众不同、用语不同，必须分流：

- **对话层（与懂八字的用户对话）= 专业版**：保留刑冲合会、十神、神煞、宫位、旺衰、盘面出处原文（如"寅戌半合火局耗身""红鸾申与驿马申同宫"），充分展示五维交叉与四派分歧，便于用户核对推演严谨度。
- **文档层（导出给命主 / 小白的 Word / 存档）= 小白版**：**正文不出现刑冲合会、神煞名、宫位术语**。写法要求：
  - 十神翻白话：食神＝才华/口才/发挥；印＝学习/学历/专业；财星＝钱也指妻子（男命）；七杀＝压力/务实/管理；夫妻宫＝配偶。
  - 应期翻"哪年"：不写"戊申年红鸾引动"，写"2028 年前后易遇正缘"。
  - 神煞/冲合转化可感知画面：不写"驿马同宫"，写"这年很可能因去外地上班或上网认识"；不写"食伤泄身"，写"临场想太多、发挥没放开"。
  - 仍须**具体取象 + 适度扩展**（见上），但用大白话。专业推演若需留存复核，收进文档末尾「专业附注」附录（保留刑冲合会神煞原文），正文不出现。
- **判定口径**：markdown 存档（`bazi-archives/*.md`，用户自用）可保留专业版或附「专业附注」；**导出给第三方的 Word（`案例/*.docx`）一律小白版**，正文零术语。
- **小白版生成硬标准（已锁定，自动执行、无需手改，详见 report_template.md §11.7）**：① 零术语；② 关键结论标红（约 8–15 处）；③ 走势图仅内嵌（绝不留单独 PNG）；④ 事件/风险表格化；⑤ 保留取象与具体性；⑥ **喜忌小建议**（要点列表，喜X忌Y+白话解释，按用神推导）；⑦ **必须推演「前事 + 未来」**：主动按大运把命主时间线写出来，每条事件须从盘面「刑冲破害神煞＋十神＋大运＋流年」五维交叉推导、描述详细大白话——前事（已发生，**逐年一行、不得整段略过**——如 2 年以上跨度不得合并成一句、不得只写「一直平淡/无大事」，专业版 §八 须含逐年『前事详细推算』表；标注「推算」供核对）+ 未来（前瞻窗口，维度须覆盖学业/事业/婚恋＋人身心理安全/关系法务冲突/财物事业波动/家庭人生节点，含年份/年龄/概率）——**硬标（详见 §11.7）**：未来表须含「方面/维度」列、四维度＋学业/事业/婚恋各至少一行独立成行（严禁挤行/偏婚恋），合盘须含女/男/合盘三张四维度表，生成后强制自查（§11.7 第10条）达标才交付；⑧ **性格与外貌推演**（由盘面推导，大白话单列一节，覆盖性情骨架/思维表达/外貌体征/气质人际/短板雷区，不写玄学术语，给可感知画面；专业版对应「四、性格与外貌推演」专节）；⑨ **家人关系与助力**（由六亲/宫位推导，大白话单列一节，覆盖父母谁帮衬多/配偶特征/子女缘/同辈；专业版对应「五、家人关系与助力分析」专节）。生成 Word 时按此标准自动产出，不要再逐次手改。
