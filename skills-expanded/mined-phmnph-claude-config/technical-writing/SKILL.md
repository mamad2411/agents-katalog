# Write a usable technical document

Establish the audience and the action or understanding the document should enable.
Use the repository's existing format. For a short PR description or small doc
edit, write directly; no full style-guide pass is needed.

Lead with the concrete behavior or problem. Use real commands, paths and symbols;
verify those that readers will rely on. Preserve qualifications and distinguish
observed results from plans. Keep a procedure actionable, a reference factual,
and an explanation focused on the reason a decision matters.

Match detail to the reader and task. Explain an unfamiliar engineering choice
through its effect and a concrete example, rather than demanding vocabulary the
reader does not have. Remove repetition without removing necessary context.

For a substantial document or structural writing review, consult the relevant
sections of [writing-guide.md](references/writing-guide.md). Apply $unslop to
every user-facing chat response. For document artifacts, use a separate style
edit when the wording needs it.

Finish when the requested document is accurate, navigable, and sufficient for
its intended use. Do not expand a short request into a reference manual or
change code to make the documentation easier to write.
