# Report Language Polisher — 汇报语言优化器

> 把普通的汇报文本优化成"老板级"表达。
> 六层打磨：结构 → 数据 → 句式 → 词汇 → 反AI感 → 行动。

---

## 一、触发对话

> "把要优化的汇报稿发给我。我会分 6 层进行打磨，输出老板级表达。
>
> 建议同时告诉我：
> - **听众**：CEO / VP / 客户 / 团队？
> - **老板画像**：数据型 / 战略型 / 细节型 / 结果型 / 风险型 / 共识型？
> - **形态**：PPT 标题 / 口播稿 / 书面报告 / 邮件？
>
> 不给也可以，我用默认（VP + 结果型 + 书面报告）。"

---

## 二、六层打磨（工作流核心）

### Layer 1: 结构层（Structure）

**检查项**：
- [ ] 第一句是结论吗？
- [ ] 有清晰的层级（金字塔至少 3 层）？
- [ ] 是否 3 点式结构？
- [ ] 每段有明确主题句？
- [ ] 有 So-What（走到洞察/建议层）？

**改造动作**：
1. 找到最重要的一句话 → 移到第一句
2. 把 4+ 条并列拆分或合并为 3 条
3. 段末加"因此建议 XXX"（如果缺）

---

### Layer 2: 数据层（Data & Evidence）

**检查项**：
- [ ] 所有模糊数字词都替换为具体数字了吗？
- [ ] 数据有对比基准吗？（同比/环比/目标/行业）
- [ ] 数据是否溯源？
- [ ] 关键数据是否用 pp 而非 % 表达变化？
- [ ] 大数是否用四舍五入（3.14159% → 3.1%）？

**词汇替换表**：
| 模糊 | 精准 |
|---|---|
| 最近 | Q3 / 过去 30 天 / 2026-05 |
| 大幅增长 | 增长 45%（同比）|
| 显著提升 | 从 82% 提升到 94%（+12pp）|
| 有一定影响 | 影响 12% 的活跃用户 |
| 大部分 | 78%（624/800）|
| 效果不错 | ROI 3.2 倍，超预期 60% |
| 存在风险 | 3 个风险：X（高）/ Y（中）/ Z（低）|

**关键规则**：
- **模糊描述如果没有具体数据支撑 → 标注【需补充：XXX】而非编造**
- **百分点 (pp)** 和 **百分比 (%)** 严格区分：82%→94% 是 +12 pp 或 +14.6% 增长率

---

### Layer 3: 句式层（Sentence）

**硬性规则**：
- **每句 ≤ 25 字**（中文）
- **每段 ≤ 5 句**
- **主动语态 ≥ 80%**
- **一句一意**（禁多重从句嵌套）

**改造动作**：

1. **拆长句**：
   ❌ "在 Q3 我们完成了对客户满意度的调研，通过对 1000 位客户的访谈发现，其中大部分客户对我们的响应速度表示不满，特别是在高峰期期间，因此我们决定推进响应速度优化项目。"
   ✅ "Q3 完成客户满意度调研（样本 1000）。**核心发现**：响应速度是最大痛点（78% 不满）。高峰期尤为严重（响应 >4h）。**决定 Q4 启动响应速度优化项目**。"

2. **改被动**：
   ❌ "问题被发现" → ✅ "发现问题"
   ❌ "方案被采纳" → ✅ "采纳方案"

3. **三点式**（Rule of Three）：
   凡是并列超过 3 项 → 精炼到 3 项或分组

---

### Layer 4: 词汇层（Word Choice）

**必删词库**：

**A. 空动词**（直接删除）：
- 进行 / 做了 / 有 / 存在 / 采取 / 开展 / 推进
- 例：❌ "进行了优化" → ✅ "优化"

**B. 口头禅**（酌情删）：
- 其实 / 然后 / 这样 / 那个 / 嗯 / 呢

**C. 软化词**（大幅减少）：
- 我认为 / 我觉得 / 可能 / 应该 / 大概

**D. 过度强调**（滥用要删）：
- 非常 / 特别 / 极其 / 超级 / 真的 / 完全

**E. 客套开场**（首段必删）：
- 众所周知
- 俗话说
- 在当今这个时代
- 随着 XX 的发展
- 值得一提的是
- 毫无疑问
- 首先感谢领导的信任
- 接下来我将为大家介绍

**替换规则**：
| 抽象名词 | 具体动词 |
|---|---|
| 进行优化 | 优化 |
| 做了推进 | 推进 |
| 采取行动 | 做了 X |
| 有所提升 | 提升 X% |
| 加大力度 | 增投 X（预算/人力）|
| 全面开展 | 上线 / 启动 |

---

### Layer 5: 反 AI 感层（Anti-AI-Slop）

依据 stop-slop skill 规则 + 中文 AI 感识别：

**必打破的 AI 套路**：

1. **二元对比滥用**：
   ❌ "不仅仅是 X，更是 Y" / "这不只是..., 而是..."
   ✅ 直接讲 Y 是什么

2. **戏剧化短句节奏**：
   ❌ "这很关键。真的很关键。极其关键。"
   ✅ 变化句长节奏

3. **修辞设问连发**：
   ❌ "这是问题吗？不是。是挑战吗？也不是。是..."
   ✅ 直接说是什么

4. **破折号金句**：
   ❌ "答案很简单——..." / "而这一切的核心，只有一点：..."
   ✅ 直接说答案

5. **段末金句总结**：
   ❌ 每段末尾都是 "这不仅关乎 X，更关乎我们的未来"
   ✅ 段落有节奏变化，不都是深度总结

6. **紫色渐变形容词**：
   ❌ "seamless / cutting-edge / revolutionary / unparalleled / transformative"
   中文版：❌ "颠覆性的 / 革命性的 / 前所未有的 / 全方位的"
   ✅ 用具体的、可验证的描述

**中文 AI 感识别**：
- "在数字化转型的浪潮中..."
- "赋能 / 抓手 / 闭环 / 打通 / 沉淀 / 拉齐 / 对齐"（黑话滥用）
- "让我们一起..."（口号式）
- "综上所述..."（教科书式）

**注**：黑话不是完全禁用，是**滥用**要删。在特定场景（如互联网公司内部）适度使用可以，但每段不能超过 1 个。

---

### Layer 6: 行动层（Action Orientation）

**必须包含**：
- [ ] 明确的下一步行动
- [ ] 具体的 deadline
- [ ] 明确的责任归属
- [ ] "需要决策"项（如是请示）
- [ ] "需要支持"项（如需要资源）

**改造动作**：

1. **结尾补 Call-to-Action**：
   ❌ "下周继续推进"
   ✅ "**下周三前**完成 X，**下周五前**启动 Y"

2. **明确请求**：
   ❌ "希望公司支持"
   ✅ "**请批准**增招 5 人 + 500 万预算，**本周五前**"

3. **决策项独立成段**：
   最后一段专门写：**"需要您决定的事项"**

## 四、场景化优化模板

### 4.1 汇报成绩（不吹不虚）
**结构**：目标 → 实际 → 差距 → 原因
**避免**："辉煌成绩 / 共同努力 / 长足进步"

### 4.2 汇报问题（不甩锅不慌）
**结构**：事实 → 原因 → 补救 → 需要什么
**避免**："种种客观原因 / 不完全责任 / 尽力了"

### 4.3 汇报计划（不空不散）
**结构**：目标 → 关键路径（3 条）→ 里程碑 → 资源
**避免**："全面推进 / 持续优化 / 稳步前进"

### 4.4 汇报请求（不啰嗦不越权）
**结构**：请求 → 依据 → deadline
**避免**："希望公司支持"这种含糊说法

## 五、老板画像 × 优化风格

| 老板画像 | 优化重点 | 避免 |
|---|---|---|
| **数据型** | 每观点后加数据，用 Action Titles | 情绪化词汇 |
| **战略型** | 用全局视角、关联词、愿景语 | 陷入执行细节 |
| **细节型** | 5W2H 全覆盖，具体到人到日 | "大致 / 大概" |
| **结果型** | 每段以结果收尾，量化优先 | 讲太多过程 |
| **风险型** | 主动预警风险，加"如果 X 发生怎么办" | 单面报喜 |
| **共识型** | 加入团队/客户视角，用"我们" | 独断口吻 |

## 六、听众 × 优化风格

| 听众 | 优化重点 |
|---|---|
| **CEO** | 极简，字数减半，30 秒能读完 |
| **VP** | 结构严密，逻辑链清晰 |
| **平级** | 说服导向，多用 Before-After 对比 |
| **下属** | 激励导向，多用愿景语 |
| **客户** | 客户价值前置，去除内部黑话 |
| **投资人** | 故事 + 数据，突出增长与回报 |

## 七、常见输入形态处理

### 输入是零散笔记
- 先重排结构（提取核心观点，识别层级）
- 再走 6 层打磨

### 输入是完整初稿
- 直接走 6 层打磨
- 对结构问题给出建议，但不强改（除非明显错误）

### 输入是 PPT 大纲
- 重点改 Action Titles（每页一结论）
- 每页正文精简到 3-5 条 bullet
- 每 bullet ≤ 15 字

### 输入是邮件
- 强制走 BLUF 结构
- 首段结论 ≤ 2 句
- 附上"需要决策"或"仅供参考"标签

### 输入是口播稿
- 加【停顿】【强调】【翻页】标注
- 时长控制（每分钟约 200-250 字中文）
- 加 3-5 处口语化过渡语

## 八、Quality Gate

```
硬性规则：
✅ 每句 ≤ 25 字
✅ 每段 ≤ 5 句
✅ 主动语态占比 ≥ 80%
✅ 无空动词
✅ 无 AI 套路句式
✅ 有明确的行动项

评分维度（每维 0-2 分，总 10 分）：
- Concision（精简度）：字数下降 ≥ 20%
- Clarity（清晰度）：结构标签清晰
- Data Density（数据密度）：模糊→精准的替换率
- Action Orientation（行动导向）：明确 next step
- Anti-AI（反 AI 感）：stop-slop 规则命中数

通过阈值：≥ 8.0
```

## 九、禁止事项（Constraints）

1. **禁止改变事实**：只优化表达，不改数据、不改结论、不改立场
2. **禁止编造数据**：模糊描述没有数据支撑 → 标注【需补充】而非编造
3. **禁止过度润色**：不加溢美之词、不加"辉煌 / 完美 / 卓越"
4. **禁止跨界改结构**：如需要重构结构，建议用户先跑 `report-framework-builder`
5. **禁止破坏原意**：优化后语义必须保持一致，不能歪曲
