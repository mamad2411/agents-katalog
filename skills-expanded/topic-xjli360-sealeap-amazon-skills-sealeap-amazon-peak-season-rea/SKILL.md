# SeaLeap 亚马逊旺季广告备战

把活动日期、备货、广告结构和页面准备对齐，形成能按周推进、在高峰及时检查、在节后退出的行动计划。

## 输入

目标站点、当地节日与活动官方日期、ASIN、促销资格和价格、可售/在途库存、补货时效、利润底线、广告历史及每日预算上限。先确认当前是在活动前、活动中还是活动后；已结束活动进入复盘。

## 工作流

1. 从当地官方活动信息建立倒排日历，以活动开始日 T 为锚点；素材里的月份只作为历史示意。
2. T-4 周研究品类、去年同活动表现和当前意图，核对库存及页面，选择长尾探索与品牌防御的重点。
3. T-3 周启动并验证关键词、商品定向或品牌创意；将已验证搜索词作为手动投放候选，设置总体损失上限。
4. T-2 周依据报告优化结构与创意，留出审核时间。只有足够分时证据时才设计分时竞价。
5. 高峰按库存、费用和归因成熟度监控。促销品将售罄时，评估把预算移向有货且利润健康的正价商品，并记录旧/新分配。
6. 活动后审查花费、搜索词、素材、退货与利润，再衔接圣诞、新年、情人节或本地节日；不要把高峰预算惯性延续。

## 交付

- 按当地时区的倒排日历与责任人。
- ASIN 可售、促销、页面和库存缺口表。
- 各阶段预算草案、总上限、调整触发器及回退值。
- 高峰监控频率、告警指标、节后复盘及下一波计划。

## 证据与执行范围

- 材料中的案例、比例和时间表标为 `COURSE_BASELINE` 或 `TRAINING_CASE`；来源与口径已核验的店铺数据标为 `ACCOUNT_FACT`，用户转交但未核验的数据标为 `USER_PROVIDED`，合成练习标为 `SIMULATED`。推断标为 `HYPOTHESIS`，缺失项写 `UNKNOWN`，不补成 0。
- 先固定店铺、广告 profile、站点、ASIN、币种、数据窗口与归因口径。课程介绍的资格、界面、报告字段和功能覆盖在实际使用时核验。
- 默认交付诊断与草案。真实写入只在当前会话已授权的对象、动作和预算内执行，并保存旧值与回读结果；新增范围先取得授权。
