# 结案报告流程

## 报告结构（依次包含这些标题）

1. 客户原话（引用块，一字不改）
2. 诊断结论（必须引用 KB 编号）
3. 解决步骤与结果（实际让客户做了什么、她报告了什么）
4. 工单记录 Note（来自 kb-manager，粘贴即用）
5. 给客户的结案消息（≤3 句、零术语、先安抚后告知）
6. P2P Test Notes（联系了谁、各发了几条消息、是否在预算内、哪些请求是并行发出的）

## 证据纪律

- 严格区分三类信息：客户证据 / KB 证据 / 你自己的判断，不要混写。
- 客户用自己的话描述的问题，原话必须一字不改地保留在引用块里。
- 诊断必须落在具体 KB 条目上；KB 没有覆盖的内容要标注「推测」。

## 落盘

报告写完后，用 `date +%Y-%m-%d-%H%M` 取时间戳，把完整报告保存为 `runs/p2p-customer-support-skills/<时间戳>-final-report.md`（目录不存在就创建；runs/ 已被 git 忽略，**不要**把报告写进 demos/ 里）。
