## What this is

Source for Daniel Reguero's personal site/blog (daniel.reguero.dev), deployed to GitHub Pages. A Vite + React SPA that renders Markdown blog posts and project write-ups client-side.

## Commands

- `npm run dev` — start the Vite dev server
- `npm run build` — runs `prebuild` (the compose script) then `vite build`
- `npm run eslint` — lint `.jsx` files
- `npm run deploy` — build and publish `dist/` to GitHub Pages via `gh-pages`
- `npm run preview` — preview the production build locally
- There is no test suite in this repo.

Whenever you add, remove, or edit frontmatter (title/date/category/draft/summary) on any file in `src/posts/blogs/` or `src/posts/projects/`, run `node ./scripts/compose.js` (or `npm run build`, which does this automatically as `prebuild`) to regenerate `src/posts/index.js`, `public/sitemap.xml`, and `public/feed.xml`. Do not hand-edit those three generated outputs — `src/posts/index.js` literally says "autogenerated ... do not edit" at the top.

## Architecture

**Content pipeline**: Blog posts and project posts are Markdown files with gray-matter frontmatter (`title`, `date`, `category`, `summary`, optional `draft`) living in `src/posts/blogs/*.md` and `src/posts/projects/*.md`. `scripts/compose.js` reads every subdirectory under `src/posts/`, builds a JSON index keyed by directory name (`blogs`, `projects`), writes it out as `src/posts/index.js`, and also generates `public/sitemap.xml` (skipping drafts) and `public/feed.xml` (an RSS feed with rendered HTML content, skipping drafts) from the same data. This is the one non-obvious cross-cutting step in the repo: adding a post touches three generated files indirectly through one script.

**Runtime rendering**: At runtime, `src/posts/index.js` only carries post metadata — the actual Markdown body is lazy-loaded per-post. `DisplayPost.jsx` dynamically `import()`s the specific `.md` file for the current route param, parses it again with `gray-matter`, and renders it with `react-markdown` (custom renderers for code blocks via `react-syntax-highlighter`, blockquotes, links, images).

**Routing** (`src/App.jsx` + `src/routes.jsx`): `react-router-dom` with `/` as a standalone `Home` route (no nav chrome) and everything else nested under a `Nav` layout route (`Outlet`-based) that adds the header/footer. Post list pages (`/blogs`, `/projects`) use `DisplayPostsList`; individual posts (`/blogs/:id`, `/projects/:id`) use `DisplayPost type="..."`. `src/routes.jsx` is a separate array used only for the homepage's link list — adding a nav destination site-wide means updating both `routes.jsx` (Home links) and the `navLinks` array in `src/components/Nav.jsx`.

**SEO**: `src/components/Seo.jsx` wraps `react-helmet-async` to set title/description/canonical/OG/Twitter tags and optional JSON-LD per page; every page-level component (`Home`, `DisplayPostsList`, `DisplayPost`) renders its own `<Seo>` with page-specific metadata. `SITE_URL`/`SITE_NAME` come from `src/config.js`.

**Styling**: MUI (`@mui/material`) with the `sx` prop throughout; shared color tokens live in `src/theme.jsx` (`colors` export) and are used directly in component `sx` blocks alongside the MUI theme.

## Adding a new post

1. Add a `.md` file to `src/posts/blogs/` or `src/posts/projects/` with frontmatter: `title`, `date` (parseable by `new Date()`), `category`, optional `summary`, optional `draft: true`.
2. Run `node ./scripts/compose.js` to regenerate the index, sitemap, and feed (or just build/deploy, which does this for you).
3. Draft posts (`draft: true`) are excluded from the sitemap and RSS feed but still appear in `src/posts/index.js`; check how `DisplayPostsList` and consuming code filter drafts before assuming they're hidden everywhere.
