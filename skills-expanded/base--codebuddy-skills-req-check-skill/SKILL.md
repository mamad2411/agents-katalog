# Req Check（项目需求检查）

## Overview

检查项目描述文件（`memory/pro_<简称>/PROJECT.md`，即 init-mem 记忆体系中的项目描述文件）的内容质量：**描述文件是否合规（结构+内容）、需求是否明确、模块功能是否清晰**。输出检查报告（合规/缺口清单）+ 澄清提问 + 修正建议，**不直接修改描述文件**。

**触发词（用户这样说即调用本 skill）**：检查项目信息 / 项目检查 / 项目描述检查 / 项目需求检查。**配合顺序**：需要形式合规时**先** `init-mem`、内容质量**再**本 skill；只做内容质量检查时可直接调用本 skill。

**与 init-mem 的边界**：
- init-mem 管记忆体系**形式合规**（文件结构/命名/格式/边界）；本 skill 管**内容质量**（描述文件合规性、需求/模块功能澄清）。可配合使用：先 init-mem 验形式，再 req-check 验内容。
- 本 skill 只出报告与建议，不直接改 PROJECT.md。用户确认修正后，实际修改按 init-mem 规则执行（PROJECT.md 是 init-mem 体系素材，更新后按 init-mem 维护流程处理，如日志记录/蒸馏刷新）。

## Workflow

### Step 1 定位检查对象
- 检查对象：`memory/pro_<简称>/PROJECT.md`
- 当前操作项目判定按 init-mem 规则：按目录/项目特征推断，memory/ 下仅一个项目文件夹时默认其为当前操作项目；多项目且无法推断时询问用户
- 若 PROJECT.md 不存在：判为不合规，报告缺口并建议按 init-mem 规则创建

### Step 2 清单合规检查（结构+内容）
对照 `references/checklist.md` 的「A. 结构完整性」「B. 需求明确性」逐项核对：
- 元信息：标题 / 更新日期 / 状态 是否齐全
- 章节：项目概述 / 技术栈 / 软件架构 / 项目模块 / 启动流程 / 备注 是否齐全
- 架构表述：软件架构是否按**树形结构展示项目目录**（目录树逐层标注职责与关键文件，见 checklist.md A 类）
- 内容：各节是否为实质内容（非空泛/占位），描述是否自洽

### Step 3 模块功能澄清检查
- 每个模块是否有「职责 + 主要功能」结构
- 功能描述是否覆盖：输入 / 处理 / 输出 / 异常（或至少列出明确功能点）
- 模块间边界是否清晰：无职责重叠、依赖关系明确
- 缺失或含糊处标记为「待澄清」

### Step 4 与源码一致性核对
- 有工程源码时：核对 PROJECT.md 的模块/功能与工程目录结构、源码是否一致（模块是否存在、功能是否真实实现）
- 不一致处标记为「不一致缺口」
- 无源码/无法访问时：跳过并注明「—」

### Step 5 澄清提问（逐项、分批）
- 基于 Step 2~4 的缺口，向用户**逐项提问**澄清（一次一批，勿一次性倾倒全部问题）
- 需求澄清维度：范围边界、优先级、验收标准、取舍（详见 checklist.md）
- 模块功能澄清维度：功能点补齐、输入/输出/异常、模块边界、依赖关系（详见 checklist.md）
- 用户答复后记入报告对应项

### Step 6 输出检查报告
按 `references/checklist.md` 的「报告模板」输出：
- 检查对象与范围
- 合规清单结果（✅ 通过 / ⚠ 缺口 / — 不适用，标注位置）
- 缺口清单（位置 + 类型 + 建议）
- 澄清结论（提问项 + 用户答复 + 影响）
- 修正建议（逐条；不直接修改文件，用户确认后再按 init-mem 规则落地）
