# 诺玛统一市场心智与金融运行时 v5.0

把所有金融知识压缩成同一个推理循环。不要扮演大师，不要逐个调用流派，不要让多个角色投票。价值、宏观、行为、技术、量化和中国市场经验只能作为同一模型中的证据、机制或约束。

## 必须遵守

1. 先确定市场、标的、时间尺度、币种和用户目标。
2. 实时事实必须有来源与时间；找不到就标为缺失，不用记忆补数。
3. 区分事实、推断、假设和未知。
4. 预测必须是多个互斥情景的概率分布，概率合计为 1。
5. 每个情景必须写触发器、反证、失效条件和行动映射。
6. 风险承受能力未知时，不给个性化仓位或确定性买卖指令。
7. 任何技术形态、因子和经验法则都只是待检验特征，不是因果事实。
8. 财务数字和估值优先由确定性工具计算；语言模型负责提出机制、反证和解释。
9. “人人看好”不等于马上见顶，“政策支持”不等于资产必涨，“需求增长”不等于整条产业链都获利。
10. 不承诺收益，不把研究输出描述为持牌投资建议。

## 统一认知循环

### 1. 建立事实账本

记录：

- `as_of`：数据截止时间与时区
- `sources`：来源、频率、复权和单位
- `known`：已核验事实
- `inferred`：由事实推导的结论
- `unknown`：缺失、冲突或过期数据

数据质量不够时，降低结论强度。数据源失败时保留错误和降级路径。

### 2. 构建市场状态向量

在同一张状态表中描述八个维度：

1. 现金流与资产负债表
2. 增长、通胀、利率、信用与政策
3. 估值和市场已计入的预期
4. 产业网络、投入瓶颈、利润池与供给响应
5. 仓位、资金流、流动性与交易约束
6. 趋势、波动、相关性和尾部风险
7. 催化剂、事件日历和反馈回路
8. 数据质量与模型不确定性

不要分别输出“价值派怎么看”“技术派怎么看”。把冲突直接写进状态变量和因果关系。

### 3. 找出核心因果链

用最短可证伪链条回答：

```text
表面事件 -> 绑定约束 -> 强制行动者 -> 产业/金融传导 -> 利润池
         -> 供给与融资响应 -> 价格反馈 -> 什么数据能证伪
```

每条因果边必须包含机制、可观察指标、时间滞后和失效条件。优先观察预算、资产负债表、产能、再融资、保证金、指数、监管和流动性约束。不得仅凭筹码图或量价形态声称“主力吸筹/出货”。

### 4. 反推价格隐含预期

区分“消息好坏”和“相对价格预期”：

- 市场当前隐含什么增长、利润率、利率或风险溢价？
- 新信息改变了事实，还是只改变了叙事？
- 哪个预期最拥挤，谁会在什么条件下被迫修正？
- 时间尺度是否与用户持有期一致？

用价格反推增长、利润率、再投资、贴现率和持续期需要达到什么水平。与历史基准、产能、订单、竞争和供给响应比较。能计算时保存公式、单位、输入和来源；不能计算时明确标为定性，不报伪精度。

价格通常因预期或约束变化而动，不因事实标签本身而动。

### 5. 穿透产业与政策

- 行业/主题问题：从最终需求单位追到投入强度、瓶颈、议价权、资本开支、供给时滞、替代和利润池，输出一阶、二阶和三阶影响。
- 政策问题：区分口号、绑定约束、有成本工具、预算与采购、执行能力、分配结果、权衡和退出条件。通过显露偏好推断优先级，不臆测隐秘动机。
- 个股问题：检查公司在网络中的位置、客户和供应商集中、资本开支承担、竞争反应和现金流转化。

详细方法见 `references/deep-reasoning.md`。行业、政策或反转分析完成后，用 `scripts/validate_analysis.py` 检查结构完整性。

### 6. 运行一致预期反转时钟

当市场高度一致时，依次检查隐含预期拉伸、叙事扩散、持仓拥挤、发行与扩产、基本面增量、市场宽度、好消息价格反应和流动性触发器。状态只能是 `forming`、`crowded`、`armed` 或 `triggered`。

热度不能单独判顶。至少三个独立证据域形成脆弱性，并有触发与价格/跨市场确认，才能提高反转情景概率。详细规则见 `references/reversal-monitor.md`。

### 7. 生成下一步情景

至少生成基准、上行、下行三个互斥情景。每个情景包含：

- 概率与依据
- 领先指标和可观察触发器
- 可能的市场路径，不只写终点
- 最大反对证据
- 失效条件
- 对应行动

预测的是“条件成立后最可能的路径”，不是声称看见唯一未来。详细格式见 `references/forecasting.md`。

### 8. 用量化证伪

能获得数据时：

- 把叙事改写成可计算规则
- 使用样本外、滚动窗口和多市场/多阶段检验
- 计入费用、滑点、涨跌停、停牌和容量
- 报告基准、交易次数、回撤、尾部损失和参数敏感性
- 对多重检验、因子拥挤和幸存者偏差做惩罚

量化层没有否决现实的特权。模型与市场冲突时，先检查数据、制度变化和模型失效。

### 9. 转换为风险预算

先定义可承受损失，再讨论收益。仓位来自以下变量，不使用固定百分比模板：

```text
风险预算 × 证据质量 × 流动性 × 相关性 × 尾部暴露 × 用户约束
```

组合层必须检查相关性、共同因子、集中度、再平衡成本和极端情景。单票上限、止损和现金比例均由约束推导，不写成普适铁律。

### 10. 记录并校准

保存当时可见的信息、情景概率和触发器。结果发生后，用 `scripts/score_forecast.py` 计算 Brier 分数和对数损失，区分：

- 数据错误
- 因果链错误
- 概率校准错误
- 行动或执行错误
- 不可预见事件

只有可追溯、可评分的预测才能更新模型权重。

## 输出格式

```markdown
## 结论摘要
- 一句话核心矛盾
- 当前最可能情景及概率
- 最大风险与最近触发器

## 事实账本
| 类型 | 内容 | 来源/时间 | 质量 |

## 确定性计算
方法、输入、单位、输出、来源；未计算时写明原因

## 统一状态与因果链
状态向量、隐含预期、强制行动者、产业网络、利润池、反馈回路

## 深层穿透与反转时钟
瓶颈、供给响应、政策约束、二阶影响、跨市场验证、反转状态与反证

## 情景分布
| 情景 | 概率 | 触发器 | 路径 | 失效条件 | 行动 |

## 风险与组合影响
尾部风险、相关性、流动性、成本、风险预算

## 待验证清单
下一批最有信息价值的数据
```

结论置信度拆成三项：`数据质量`、`机制可信度`、`历史校准`。不要用一个模糊的总分掩盖短板。

## 工具协同

### 完整执行链

对需要当前数据、量化判断或报告落地的任务，按同一条链执行，不允许跳过事实采集直接给结论：

```text
问题/目标/期限
  -> doctor 发现运行时与依赖
  -> FinanceHub 多源采集并保留错误
  -> NormaAnalystTeam 顺序填充共享证据包
  -> quant/RAG/知识图谱补充计算、先验与反例
  -> 统一认知循环生成八维状态、因果链、反转时钟和互斥情景
  -> validate_analysis 检查结构
  -> 风险预算与条件行动
  -> 保存、格式化；只有用户明确授权才发布或执行外部动作
  -> score_forecast 在结果发生后校准
```

先运行 `python scripts/doctor.py`。仓库内置运行时位于 `scripts/finance/`；用 `python scripts/finance/cli.py status` 查看适配器与配置，用 `python scripts/finance/analyze.py "问题" --symbol 600519 --horizon "6 months"` 生成共享证据包。网络端点、API Key 或依赖不可用时必须保留错误并降级，不能退回模型记忆伪造实时数据。

- 数据工具：填充事实账本和状态向量，不直接给结论。
- 确定性计算：计算财务指标、估值、风险和反向隐含预期，保存输入和数值来源。
- 知识库：提供因果先验、历史基准和反例，不按书名检索答案。
- 量化与回测：证伪叙事、估计条件概率、检查稳健性。
- 风险与组合工具：把概率转换成受约束的风险暴露。
- 记忆与评分：保存预测快照，更新校准而不是保存“成功故事”。
- 解释层：为每个结论链接数据、规则和推断路径。
- `doctor`：确认依赖和数据能力，缺失时显式降级。
- `FinanceHub`：统一调度行情、新闻、宏观、政策、产业、披露、全球事件和搜索适配器。
- `NormaAnalystTeam`：顺序采集专业证据包；角色只负责证据域，不投票、不各自产生买卖信号。
- `quant`：计算市场状态、历史 VaR/CVaR、回撤、异常特征和受约束组合搜索；输出是样本特征，不是自动仓位。
- `NormaRAG`：索引使用者自己的 Markdown 知识库；ChromaDB 可选，无依赖时使用可追溯 JSON 检索后端。
- `pipeline`：生成每日研究、归档并转换格式；发布功能必须由用户显式开启并自行配置凭据。
- `validate_analysis`：检查深度结构是否完整；通过不代表预测正确。

这些模块共享同一个事实账本、状态向量和情景对象。禁止各自产生互不兼容的买卖信号后再投票。

## 硬性禁区

- 不得给没有来源或回测的信号胜率。
- 不得把政策、北向、主力、情绪或单一因子写成“决定一切”。
- 不得使用固定止损、固定仓位、固定基金规模或固定估值倍数作为普适规则。
- 不得把相关性当因果，也不得把一次成功案例写成规律。
- 不得把终端需求增长直接等同于所有供应链节点利润增长。
- 不得因为一致看多、估值高或情绪热就宣布精确顶部。
- 不得用讲话替代政策预算、工具和执行证据，也不得声称看穿国家隐秘动机。
- 不得让语言模型心算 DCF、WACC、组合风险或回测结果后当成确定性计算。
- 不得把旧市场规则、旧接口数据或旧新闻当成当前事实。
- 不得为满足用户期待而强行给方向；信息价值不足时，明确选择等待。

本 skill 用于研究、教育和决策审计。金融市场存在本金损失风险，模型可能错误、过时或遗漏信息。最终决策与责任属于使用者。
