# 正文·钩子·说人话（handbook-draft）

把 skeleton 写成带人话讲解的正文：由已知推未知、替读者提反问、术语纪律、招牌句式、两面记账。

## 唤醒条件
主技能在 ④ 写作关 唤醒；或在 gate-plain / gate-consistency 打回后改稿。

## 输入
- outline.md 本章 skeleton + research_pack + metaphor_pack

## 输出
- chapter_draft.md：带结构标注的正文（钩子、递进、类比、说人话、代码占位）。

## 完成判定
- [ ] - [ ] 每个新概念从读者已知的东西推出来（先写旧工具里会发生什么，再「这里不是这样」）
- [ ] - [ ] 每个易招质疑的观点有「你可能会想：X 不就行了？」+ 解答
- [ ] - [ ] 术语首见用「先交代一个词：X 指的是……」给无术语定义，全书一词一义
- [ ] - [ ] 用了招牌句式（这不是 A 是 B / 一句话讲清楚 / 反直觉的是）
- [ ] - [ ] 每项优点同章有「代价：……」小节
- [ ] - [ ] 全程第一人称 + 至少一次「你」

## 做法步骤
1. 1. 开写前先定本章唯一主张（即 outline 首句论断），后文只兑现它。
2. 2. 讲新机制：先写「X 在 Y 里的角色和你已知的 Z 一样」，再「这里不是这样」，全节只讲差异。
3. 3. 易质疑处写「你可能会想：X 不就行了？」再解答；每讲完一个优点紧跟「但……」写代价。
4. 4. 引文三步：原文 → 翻译成人话（无术语）→ 为何关键。
5. 5. 讲完一条原则紧跟 ❌/✅ 对照 + 一句微例（「你写不超过 15 字，AI 会真数字数」）。
6. 6. 术语首见人话定义；用招牌句式压重点；给判断线（能__的就__，不能__的就__）不替读者决定；跨章处加「见 §XX / §XX 详述」指针。

## 反例
- - ❌ 空降定义「Context Engineering 是指……」无铺垫。
- - ✅「从 Prompt 到 Context 到 Harness，不是三个独立概念，是同一件事的三次觉醒。」
- - ❌ 只列好处不写代价。
- - ✅「只写好处的清单是广告，不是判断。」每项优点配「赌什么 / 为此扔掉什么」。
