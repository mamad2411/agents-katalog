# 冷却重读门禁（handbook-gate-reread）

卡「重读性」：刚写完的文字，作者读是看不出问题的——大脑会自动脑补掉不通的地方。本门禁模拟「冷却 48 小时后、完全忘记写作意图的第一读者」重读成稿，专找「当时觉得顺、现在看是坑」的段落。

## 唤醒条件

主技能在 ④ 写作循环、handbook-gate-reader 通过后唤醒（本章最后一道门禁）；或打回 draft。

## 输入

- `chapter_laid_out`（本章定稿）
- 本章 `outline` 骨架（用于对照「写了什么 vs 该写什么」）

## 输出

`reread_verdict`：pass / 打回（附问题清单），写回 `book_state.review_log`。

verdict 结构：
```
{ status: pass|reject,
  issues: [
    { dim: logic|pacing|depth|closure,
      location: <章节/小节>,
      problem: <一句话：当时觉得顺、现在看是坑>,
      fix_hint: <一句话> } ] }
```

## 引用原子（见 references/kernel_skills.md）

本技能**不拥有也不检查**任何 K 原子——它是冷却重读检查，有自己的四类问题维度。

## 四类问题

### 1) 逻辑断层（logic）

段落之间、小节之间「接不上」：上一段还在讲 A，下一段突然讲 B，中间没有过渡；前文埋了伏笔（「这个问题后面讲」）但后文没接住；小节结论依赖了一个读者此时还不具备的前提。

**信号词**：「所以」「因此」「但」——重读时逐个检查这些连接词前后是否真的成立。

### 2) 节奏拖沓（pacing）

该快的慢了、该慢的没慢：一个读者早就懂的概念讲了三段；一个读者第一次见的概念一笔带过；连续五个小节同一个句式/同一个节奏，没有起伏。

**信号**：「这段我扫过去的」「这里我来回读了三遍才懂」——扫过去的是该删的，来回读的是该展开的。

### 3) 深浅不当（depth）

讲浅了或讲深了：该给具体数字/命令/截图的地方给了抽象描述（「很简单」「很方便」）；该给直觉的地方堆了实现细节（读者还没建立 Why 就被 How 淹没）；同一章里深浅忽高忽低。

**信号**：「这里我以为会给个例子，结果没有」「这里我只需要知道是什么，不想知道怎么实现的」。

### 4) 收束无力（closure）

章末没有收住：收尾交付物（K09）与全章内容脱节（像是从别处抄来的）；末句没有下章钩子或钩子与下章内容不相关；读完本章没有一个「可以带走」的明确物。

**信号**：「读完了，但想不起这章讲了什么」「结尾那段感觉可有可无」。

## 完成判定

- [ ] 以「完全忘记写作意图」的第一读者身份重读，不复用写稿时的任何假设
- [ ] 四类问题逐类扫一遍，每类至少主动找 1 处（找不到也要说明「此类无问题」）
- [ ] 每条 issue 带 dim + location + problem + fix_hint 四件套
- [ ] 全部无问题 → pass；任一 logic 或 closure 问题 → reject（pacing/depth 可记 warning 供 ⑥ 修订参考）

## 做法步骤

1. 清空写稿记忆：假装自己从未参与本章写作，第一次读。
2. 按 dim 顺序扫：先 logic（逐连接词检查），再 pacing（标出扫读/回读段落），再 depth（对照 outline 检查深浅是否匹配），最后 closure（检查收束）。
3. 每条 issue 用一句话写清「当时觉得顺、现在看是坑」的具体位置。
4. 产出 verdict，logic/closure 问题一票否决。

## 反例

- ❌ 复用写稿时的理解重读（「这里我当时就是这么想的，所以没问题」）——冷却重读的全部价值就在于忘记。
- ✅ 以陌生读者身份重读，发现「§X 到 §Y 之间缺了一句过渡」。
- ❌ 把 pacing/depth 问题也 reject——这两类是 warning，供 ⑥ 修订参考；只有 logic/closure 是本章定稿前必须修的。
- ✅ logic/closure 一票否决，pacing/depth 记 warning 留痕。
- ❌ 每条 issue 只有「这里不太好」。
- ✅ 每条 issue 带位置+问题+修复方向（「§X 第 3 段：『所以』前后的因果不成立，建议补一句中间推理」）。
