# 版式·callout·表格（handbook-layout）

把 draft 排成「表 + 码 + callout 三件套」的橙皮书版式，让零配图也读得懂。

## 唤醒条件
主技能在 ④ 排版关 唤醒；自身即视觉原子的检查者。

## 输入
- chapter_draft（或 chapter_laid_out 前的中稿）

## 输出
- chapter_laid_out：带版式的成品（HTML / MD）。

## 引用原子（见 references/kernel_skills.md）
本技能**拥有**并应用以下原子：

| K | 名称 | 维度 |
|---|---|---|
| K23 | 零配图三件套，按表→码→释推进 | 视觉 |
| K24 | 维度×选项对照表做决策 | 视觉 |
| K25 | 「你以为／实际是」纠错表与体感列 | 视觉 |
| K26 | 让表格的结构本身完成论证 | 视觉 |
| K27 | callout 单一样式双用途（引文/原话、坑与边界），密度与信息密度成正比且含 1 个最该记住句 | 视觉 |
| K30 | 附录做成带保质期的速查表 | 视觉 |

## 被检查门禁
本技能**自身校验**其拥有的视觉原子（K23 K24 K25 K26 K27 K30 → handbook-layout），无独立门禁；以「表/码/callout 三件套 + callout 密度与信息密度匹配」完成判定为准（见原子字典）。

## 完成判定
- [ ] - [ ] 每节至少含 表 / 码 / callout 其一（多选项先建表）
- [ ] - [ ] 对比类内容用「维度×选项」表，不留空格
- [ ] - [ ] callout 每章 3-7 个（信息密集章可达 8-10 个），单一样式，且其中 1 个承载全章最该记住的那句
- [ ] - [ ] callout 用途限于 引文/原话 与 坑/边界 两类，不塞散文式说明
- [ ] - [ ] 附录有速查表（命令带状态列 / 数字带取数列 / 术语三列）+ 保质期声明

## 做法步骤
1. 1. 把对比 / 取舍内容先停下手建表：左列维度（本质/确定性/适用场景/代价），右列每选项填满。
2. 2. 纠错内容用「你大概会以为｜实际是」表，事实列写读者能感知的后果。
3. 3. 方案对比只改一个变量各跑一遍，拆「固定开销」「总代价」两张表，表后一句话结论。
4. 4. callout 用单一强调样式，两种用途：①引文/原话（作者原话、界面原文、他人评价）；②坑/边界（撞上的坑、边界条件、被否方案）。密度跟着本章信息密度走：每章 3-7 个，信息密集章可达 8-10 个；每章至少 1 个 callout 承载全章最该记住的那句。
5. 5. 附录整理成速查表，正文只引用；命令表加状态列、数字表加取数列、术语表用「原文｜界面用词｜一句人话」三列；写「本书保质期」一节。
6. 6. 每节内按 表→码→释 三步排，概览进表、实物进码、解读留散文。

## 反例
- - ❌ 用整段散文承载「A 比 B 好在哪」的对比。
- - ✅ 建「维度×选项」表，读者一眼比完。
- - ❌ callout 全章一个都没有，或每个知识点都套一个 callout 稀释重点。
- - ✅ 每章 3-7 个（密集章 8-10 个），引文/坑各司其职，其中一个是全章最该记住的那句话。
- - ❌ 给 callout 发明「作者注/边界框/排查框」等类型前缀。
- - ✅ 单一样式，靠内容自明是引文还是坑，不靠前缀分类。
