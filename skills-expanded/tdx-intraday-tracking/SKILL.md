# 单股盘中跟踪分析

**Skill 分类**
行情与市场分析 / 盘中跟踪 / 量价与资金

**适用场景**

- 用户给出个股名称或代码，要求"跟踪分析""盘中分析""早盘收盘/午盘收盘/尾盘看看"
- 需要在同一标的上做连续多日、多时点（盘中 10:00 / 11:30 / 14:00 / 15:00）快照对比
- 判断当日盘面强弱、资金承接、技术位攻防与次日/午后情景

**不适用**

- 批量自选股扫描 → 使用 `tdx-obv-zxg-analysis`（tqcenter 直连 + `obv_zxg_analysis.py`）
- 券商风格深度研报 → `tdx-ggtzljyj`；生成买卖点交易计划 → `tdx-trade-plan`
- 本技能所有数据只允许来自 **tdx-finance-mcp** 的 6 个工具，禁止换用其他通达信 MCP 实现

---

## 数据接口（参数必须精确）

代码与市场：名称先用 `tdx_lookup_stock(query="名称")` 取 6 位代码；`setcode` 必须匹配——`1`=沪、`0`=深、`2`=北交所。

| 步骤 | 工具调用 | 用途 |
|------|---------|------|
| 1 实时盘口 | `tdx_quotes(code, setcode, hasHQInfo="1", hasExtInfo="1", hasProInfo="1", hasCalcInfo="1", bspNum="5")` | 现价/开高低/量额/换手/量比/委比/内外盘/五档/市值 |
| 1b 收盘统计 | 收盘或需 10 日资金统计时追加 `hasStatInfo="1", statParam="10"` | Mainlx3/5/10day、DDX/DDY/DDZ、散户度 |
| 2 日K（指标） | `tdx_kline(code, setcode, period="4", wantNum="120", tqFlag="11")` | MA60 与 OBV60 至少需 60+ 根，统一前复权 |
| 3 分时（盘中） | `tdx_kline(code, setcode, period="0", wantNum="48", tqFlag="11")` | 5 分钟 K，一个交易日 48 根 |
| 4 资金流向 | `tdx_api_data(entry="TdxSharePCCW.tdxf10_gg_jyds", fixedTag="zjlx", code)` | 主力/超大单/大单/主买净额，**T+1：最新行为上一交易日** |
| 5 融资融券（可选） | `tdx_api_data(entry="TdxSharePCCW.tdxf10_gg_jyds", fixedTag="rzrq", code)` | 杠杆资金趋势 |

同一轮查询中步骤 1、2、4 相互独立，应在同一批次并发调用；步骤 3 仅盘中跟踪需要。

### 关键字段映射（实测校准）

- `HQInfo`：`Now` 现价、`Close` **昨收**、`Open/MaxP/MinP`、`Volume`(手)、`Amount`(元)、`Inside/Outside`(手)、`LB` 量比、`HSL` 换手率(%)、`Average` 均价
- `ExtInfo`：`ZTPrice/DTPrice` 涨跌停、`ZSZ` 总市值(元)、`LTGB`(万股)、`SYL` 市盈率、`HYZAF` 所属行业涨幅(%)
- `ProInfo`：`Wtb` 委比(%)、`InOut` **当日实时主力净额**(元)、`InOutHB` 当日超大单净额(元)、`ThisYear` 年内涨幅(%)、`Zaf20` 20日涨幅、`PETTM`、`HisHigh/HisLow` 历史高低
- `StatInfo`（需显式开启）：`Mainlx/Mainlx3day/Mainlx5day/Mainlx10day` 主力净额、`Zjlx` 主买净额、`DDX/DDY/DDZ`、`Shdzb` 散户度
- `BspInfo`：五档 `BuyP/BuyV`、`SellP/SellV`（量单位手）；连续多档同向大单构成"压单墙/托单墙"
- 5 分钟 K 的 `Item[1]` 是当日秒时间戳：34200=09:30，步长 300；41400=11:30，47100=13:05，53700=14:55（用于分时分段统计）

## 分析流程（六步法）

### 第一步：盘口快照与时点定性

先声明数据时点（HH:MM，盘中/早盘收盘 11:30/午盘/尾盘/收盘），非收盘价必须注明"盘中数据"。
读取现价、涨跌幅、开高低、成交额、换手、量比、委比、内外盘占比，回答：
高开/低开/平开？量比 >1.5 放量、0.8-1.5 平量、<0.8 缩量；委比与内外盘方向是否与涨跌一致。

### 第二步：分时结构（仅盘中，5 分钟 K）

- 开盘形态：首根 5 分钟量能（全早盘最大量常出现在 9:30-9:35）、全日高低点形成时间
- 两段量能对比：上午 9:30-10:30 vs 10:30-11:30；下午 13:00-14:00 vs 14:00-15:00，后段放量推升=强，放量下杀=弱
- 价格与 `Average` 均价线关系：持续在均价线上方运行且回踩不破=分时偏强
- 形态归类：低开洗盘后回收 / 冲高回落 / 放量突破 / 缩量阴跌 / 尾盘偷袭
- 五档挂单：识别压单墙（如卖二、卖三挂单量 5-10 倍于买档）与托单
- 个股涨幅与 `HYZAF` 行业涨幅对比：跑输板块的反弹定性为跟随性修复

### 第三步：技术指标（必须脚本计算，禁止心算）

把日 K 返回保存为临时文件（或 stdin），调用技能脚本：

```bash
node skills/tdx-intraday-tracking/scripts/indicators.mjs kline.txt
# 输出 JSON：ma{5,10,20,60}、maAlignment、macd{dif,dea,bar}、kdj{k,d,j}、
#           obv{level,net20,net60}、volume{today,avg60,ratioVsAvg60}、quadrant、recent6
```

脚本同时兼容 `tdx_kline` 原始文本信封与纯 JSON。盘中当日 bar 为实时累计量；若要用最新 quotes 修正，传入前替换最后一根的 close/volume，并在报告中标注"盘中估算"。

解读规则：
- 均线：现价与四线关系 + 多头/空头排列/交织；MA60 为中期多空分水岭
- MACD：零轴上下定多空基调，DIF 与 DEA 金叉/死叉，红绿柱伸缩看动能边际变化
- KDJ：>80 超买、<20 超卖；J 值领先 K、D；金叉/死叉需结合位置（低位金叉与中位金叉含义不同）
- 量能：`ratioVsAvg60` 半日 <0.5 视为缩量；昨日放量大跌 + 今日缩量反弹不能确认反转

### 第四步：OBV 海峡体系四象限

以 **OBV20 净变化**（近 20 日 ±成交量之和，脚本 `obv.net20`）正负 + 价格与 MA60 关系分类：

| 象限 | 条件 | 含义 | 操作含义 |
|------|------|------|---------|
| 🟢 头等马 | 价格>MA60 且 OBV20>0 | 强者恒强 | 持仓，回踩支撑缩量止跌可加仓，止损 MA20×0.97 |
| 🟣 黑马 | 价格≤MA60 且 OBV20>0 | 蓄势待发 | 等放量突破 MA60 再进场 |
| 🟡 谨慎 | 价格>MA60 且 OBV20≤0 | 量价背离 | 反弹到均线压力减仓 |
| 🔴 回避 | 价格≤MA60 且 OBV20≤0 | 弱势未止 | 观望，不左侧抄底 |

**OBV60 是缓冲窗口**：OBV20 已负而 OBV60 仍正，属弱势中的修复缓冲；一旦 OBV60 滚动转负，中期量能确认转空（窗口滚动会每日替换一根，需提前测算转负压力）。

### 第五步：资金面交叉验证

- 当日：`ProInfo.InOut/InOutHB`（盘中实时，可随行情变化）与价格、内外盘是否共振
- 历史：zjlx 表最近 5-10 个交易日主力净额方向；**表述必须带日期，严禁把 T+1 数据说成"今日"**
- 分歧信号：主力/超大单净流入但主买净额大额为负 → 机构低吸、散户恐慌抛；反之主力流出而价格上涨 → 拉高出货嫌疑
- 连续跟踪同一标的时，与上一时点快照对比（如委比 -71%→-48% 卖压减轻、InOut 由负转正）

### 第六步：关键位、情景表与纪律

- 压力：今高/昨高/开盘价 → MA5 → MA10 → MA20 → MA60 → 前高/涨停价
- 支撑：今低/昨低/均价 → 前低 → 跌停价 → 年内低点（`ProInfo.HisLow` 为历史低点，年内低点从日 K 近 240 根取）
- 给出午后/次日三情景（转强/震荡/转弱），每档写清**触发条件 + 应对动作**，触发条件必须是可观测的价量信号（如"放量吃掉 8.85 压单并收于 MA5 上方"），不写"逢低关注"这类模糊话
- 已有跟踪基线时，明确给出与上次结论相比的状态变化（如"维持回避象限，但 60 日缓冲仍在"）

## 数据准确性铁律

1. `Amount/InOut/ZSZ/Mainlx` 单位是**元**，/1e8 得亿；`Volume/Inside/Outside/BuyV/SellV` 单位是**手**，/1e4 得万手；输出前用计算器/脚本逐位核实，禁止凭印象读数。
2. zjlx 资金流向为 **T+1**，最新一行是上一交易日；当日资金只用 `ProInfo.InOut`。
3. MA/MACD/KDJ/OBV 一律由 `scripts/indicators.mjs` 计算，不得心算或估算；数字保留 2-4 位与脚本输出一致。
4. `setcode` 必须与代码市场匹配；日 K 统一 `tqFlag="11"` 前复权。
5. 盘中快照（非收盘）必须在标题与结论处标注时点，量能类结论要说明"半日量/60 日日均量"口径。
6. 指标中财务/日期类数字（如 20260401、24013000000）不得被当错误码解读；错误判定只看 ok/ErrorCode 结构化字段。
7. 报告末尾固定附"基于实时数据，可能随盘面变化，不构成投资建议"。

## 输出模板

```markdown
# {名称}（{代码}）{早盘收盘/午盘/尾盘}跟踪 · MM-DD HH:MM

**{时点}价：X.XX 元（+X.XX%）｜成交 X.XX 亿 / X 万手**（盘中数据需注明）

## 一、盘口快照（与上一时点/昨日对比表）
## 二、分时结构（仅盘中：开盘形态/两段量能/均价线/五档墙/相对行业强弱）
## 三、量能与资金（当日 InOut + T+1 zjlx 带日期的近 5-10 日方向）
## 四、技术面（均线排列 + MACD + KDJ，数字全部来自脚本输出）
## 五、OBV 海峡象限（OBV20/OBV60 正负 + 象限结论 + 与上次状态变化）
## 六、关键位（压力/支撑分档标价）
## 七、午后/次日情景表（转强/震荡/转弱 × 触发条件 × 应对）
## 八、跟踪结论（定性一句话 + 纪律：观望/试仓/减仓 + 分级止损位）

> 基于 tdx-finance-mcp 实时数据，盘中快照可能随行情变化，不构成投资建议。
```

## 输出要求

- 结论先行：报告开头一句话给出当前状态与与上一时点的边际变化
- 每个判断后面跟数据证据（字段值 + 日期/时点），禁止无数据支撑的形容词
- 缩量反弹与放量反转必须严格区分；低估值、低价格不得作为见底理由
- 连续跟踪时复用同一关键位与象限框架，只更新变化部分，保持跨时点可比性
