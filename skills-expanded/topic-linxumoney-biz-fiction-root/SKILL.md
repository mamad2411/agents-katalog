# Biz Fiction — 商业叙事写作引擎

> 用写小说的方式写商业故事。让读者忘记自己在读「内容」，以为自己在看剧。

---

## 触发方式

```
/biz-fiction <主题>
```

示例：
- `/biz-fiction 中本聪与比特币诞生`
- `/biz-fiction 乔布斯重返苹果的那个夏天`
- `/biz-fiction 扎克伯格第一次面对国会听证`

---

## 写作前的准备

收到主题后，先在脑子里回答3个问题，再开始写：

1. **这个故事的「房间时刻」是什么？**
   — 即主角意识到一切改变了的那个具体瞬间（一封邮件、一句话、一个数字）
   — 所有章节都要为这个时刻服务

2. **哪些「当时没听懂的暗示」可以回望？**
   — 结局前，读者要猛然意识到：「原来那句话早就是预兆」

3. **主角的认知盲区是什么？**
   — 他相信一件事（真诚能解决问题 / 技术能改变世界 / 规则是可谈的）
   — 故事的悲剧/张力来自这个信念被现实击碎的瞬间

## 核心写作法则

读取 `references/style-rules.md` 获取完整法则，以下是速查版：

### 法则1：镜头三层切换

每个场景至少触发一次：
```
宏观镜头（城市/天气/环境）
    ↓
中景镜头（房间/人物动作）
    ↓
微观镜头（杯底冰块/屏幕反光/手机振动）
```
**微观镜头承载情绪**，不要直接写「他很害怕」，写「那三秒钟里心跳漏了一拍」。

---

### 法则2：情绪不说，细节说

❌ 错误：「他感到不安。」  
✅ 正确：「他读了三遍。字面上每一个字都很正常，但他的心跳还是快了半拍。」

❌ 错误：「他意识到自己上当了。」  
✅ 正确：「他把那句话在嘴里嚼了嚼，像一块化了味的口香糖。」

---

### 法则3：对话永远有两层意思

所有重要对话，表面意思 + 真实意思要错位：

| 对话内容 | 表面意思 | 真实意思 |
|---------|---------|---------|
| 「需要的计算量似乎不能扩展」| 技术问题 | 这行不通，别浪费时间 |
| 「这是个有趣的实验」| 表示欣赏 | 我不太相信它会成功 |
| 「非常感谢你的配合」| 礼貌道别 | 事情到这里已经结束了 |

读者读完要回过头来：「原来那句话早就是预兆。」

---

### 法则4：商业信息用场景渗透

❌ 错误：「某公司于2009年发布了这项技术，这是一种基于区块链的去中心化系统，其核心创新在于……（三段分析）」

✅ 正确：「2009年1月3日，他挖出了第一个区块。那个区块里，他嵌入了一行字——来自当天报纸的头版标题。他选择这句话不是偶然的。」

商业背景一句话带过，情绪和判断跟在后面，读者自己推断意义。

---

### 法则5：章节节奏控制

标准结构（可调整）：

```
一、引子      ← 「房间时刻」预告，吊住读者
二、犹豫/准备  ← 主角的内心逻辑，铺「信念」
三、行动      ← 主角做了那个决定
四、过程      ← 一切看起来都很正常（暗流在走）
五、转折      ← 「补充沟通的房间」时刻
六、夜/余震   ← 主角独自消化，回望所有暗示
```

每章500-800字，总长3000-5000字。

---

### 法则6：主角背景一定要落地

不写「他是一个成功的创业者」，写出具体的时间线和地点：
> 「1971年生，南非比勒陀利亚。十岁买了第一台电脑，靠一本手册自学编程……」

**出生地 + 时间线 + 具体细节** = 读者相信这个人真实存在。

---

### 法则7：结尾留悬空

不要给结论。最后一个画面是一个**具体的细节**，把判断权留给读者：

> 「他把屏幕关掉，房间里只剩下路由器的蓝灯一闪一闪。」

读者自己感受到那个结局，比你直接说效果强十倍。

---

## 标准输出格式

```
[标题：一句话，不解释，带悬念]

[地点 + 时间 + 气候，3句以内]

一、[章节名，2-4字，留悬念]
...

二、[章节名]
...

[末尾免责声明：如有虚构注明]
```
