# register 스킬

## 규칙

- register의 레포 분석은 스크립트 추출 없이 서브에이전트로 함 — 스크립트 추출은 다양한 기술 스택에 대응하지 못할 수 있고 그때는 흔적을 전부 놓침
- register는 baseRoot를 읽지도 최신화하지도 않고 임시 clone({tmp}) 하나로 registry 조회·레포 준비·기록을 처리함 — 위키 사본 최신화 시점을 세션 시작 하나로 두면서 최신 registry로 판단하기 위함
- register는 포크·ssh 체크아웃에서 실행해도 현재 레포의 origin URL을 그대로 remote로 기록함(의도된 동작) — 포크 판별 같은 예외 처리를 두지 않고 초안 승인 표에서 사용자가 고침
- verify_register_file.py는 현재 레포 노드와 자기 간선 블록만 검사함 — 다른 블록에 남은 구형 kind·contracts 간선을 하위 호환 없이 그대로 두기 위함이며, 그 전환 시점은 아직 정해지지 않음

## 함정

- 여러 소스를 cat·for 루프로 한 출력에 이어 읽다 출력 한도를 넘기면 노드 에이전트가 grep으로 대체해 전수 읽기 대신 추정함
- 노드 프롬프트의 전수 읽기 지시(git ls-files 목록·Read로 파일마다 끝까지 열기·읽음 N/M 자기보고)는 노드 에이전트의 토큰 비용을 약 3.4배(42k 대 145k) 늘림
- 간선 프롬프트에 '보고 있다'의 방향 정의가 없으면 대상이 현재 레포를 호출하는 역방향 흔적(CORS 허용 origin, 주석 언급)을 간선으로 오탐함
- 노드 프롬프트가 서빙 호스트만 쓰라고 하지 않으면 워커 레포 hosts에 브로커·DB 주소를 넣음
- register 재실행은 코드 변화가 없어도 desc·responsibilities 문장이 새로 쓰여 chore(register) 커밋이 매번 생김
- 노드 에이전트의 responsibilities에는 누락이 있을 수 있고 이를 거르는 곳은 초안 승인 표뿐임 — 전수 읽기를 지시해도 일부 계층만 읽고 나머지는 파일명·grep으로 추정한 사례가 있음
- register가 분석 대상 레포(현재 레포와 간선 대상)의 워크스페이스 clone을 원격 기본 브랜치로 강제 정리하면 같은 폴더를 쓰는 다른 세션의 변경도 사라짐(의도된 동작) — 워크스페이스는 읽기 전용이 아닌 사용 자유 폴더라 유실 위험을 감수함
- scheme 없는 구형 remote(github.com/...) 노드는 워크스페이스 clone이 실패해 register 간선 탐색에서 빠지고 fail로 보고됨
- 중단되는 실행에서도 임시 clone 때문에 위키 전체 clone 비용이 듦
