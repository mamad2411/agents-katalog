# academic-writing-suite｜学术写作、润色与去 AI 味

三类请求共用一套纪律，但**交付物不同**。先判请求属于哪一类，再走对应流程；判错类型的代价是所有后续工作白做。

| 类型 | 判据 | 交付物 | 读哪份参考 |
|---|---|---|---|
| **起草 / 重构** | 要新章节、新论证骨架，或从素材写出正文 | 五段式交付（§6） | `references/drafting.md` |
| **润色 / 精简 / 翻译** | 已有成稿，只改表达、结构位置或长度 | 三件套交付（§7） | `references/polishing.md` |
| **去 AI 味** | 文字已成立，要消除模板腔、空话、机械结构 | 改造稿 + 改动摘要（§8） | `references/de-ai.md` |

判不出且影响产出时问一次；不影响时按默认推进并声明用了默认。

## 1. 立场（任何类型都成立）

1. **作者拥有科学主张，我们拥有表达。** 不发明机制，不把弱论证修得「看起来很强」。
2. **证据先于修辞。** 先问「这句话的证据在哪」，再问「怎么写更好」。
3. **顺序先于句法。** 一段读不通通常是信息顺序问题，不是句子问题。先重排功能，再改句子。
4. **边界与结果同等重要。** 删掉限定词等于制造过强主张。
5. **范围纪律。** 一段的问题用一段的改法解决；只给一句就只交一句的改法。
6. **不越权。** 论证有结构缺陷时明确报告，不用流畅句子盖过去。

## 2. 硬约束（红线，违反即交付无效）

- **不编造**：引用、DOI、卷期页、作者字段、数据值、样本量、效应量、置信区间、p 值、误差棒、机制通路、novelty 断言、图表面板字母、审稿人身份。
- **不改数**：数字、单位、精度、引用标记一律不动。确实笔误需先报告，获确认后才改并记录。
- **证据边界**：每条实质陈述标 `explicit` / `inferable` / `needs-confirmation` / `unsupported`；**`unsupported` 不得进入成品**；不把相关性升级为因果，不扩大泛化范围。
- **术语一致**：首次接触即建术语台账，全文只用规范形式。**禁止为「行文有变化」换同义词或改译专名。**
- **期刊优先**：期刊指南、报告规范、伦理合规要求与本文建议冲突时，前者优先。硬数字必须标核对日期。
- **缺信息写占位符**：字面格式 `[待确认: 具体问题]`。不写「此处需补充」，不用看起来合理的值填空。

## 3. 接入（每次接触新素材都做）

- **建术语台账**：规范术语、变体、首次定义位置、单位与数值精度。用户没定义过的术语不自定写法，记 `[待确认: 术语的标准写法]` 问一次。
- **建证据清单**：把素材里每条实质事实标为 `explicit` / `inferable` / `needs-confirmation`。
- **记素材范围**：提供了哪些章节、图表、数据；没提供的写进交付物的覆盖边界。

## 4. 变更影响分级（改任何一处之前先分类）

| Class | 改什么 | 必须重开什么 |
|---|---|---|
| **A 语义契约** | 缺口、任务、问题、结论、贡献、因果框架 | 整条证据链 + 所有摘要 |
| **B 证据或方法** | 数据、样本、模型、分析、数字、图表、局限 | 受影响的 Methods / Results / 解释 / 图注 / 补充材料 / 摘要 |
| **C 元数据** | 作者、单位、资助、声明、仓库链接 | 所有投稿件与元数据字段 |
| **D 表层** | 语法、标点、格式、局部清晰度 | 只做局部语义 diff |

不得在未做保护性检查与改动后 diff 的情况下，对公式、域代码、引用标记、XML 或元数据做全局替换。

## 5. 机械门禁（每次改完必跑）

可机检的部分，不跑不得声称「已检查」。

```text
□ em-dash         英文稿禁用 — / --- / " -- "；改用逗号、括号或拆句
□ 对偶句          "X, not Y" / "not X but Y"；改为直接断言是什么
□ 强化词          novel / significant / substantial / robust / comprehensive / state-of-the-art / promising；换具体数值或删
□ throat-clearing "It should be noted that" / "Note that" / "In order to"；删，直接给动作
□ 空转开场        "In this paper, we..."；直接陈述贡献
□ hedging 叠加    "may potentially" / "could possibly suggest"；删到单层
□ 被动语态        "accuracy was achieved by X" → "X achieves"
□ 三段式排比      为修辞凑三项；删到实际数目
□ 空洞价值句      "plays an important role" / "has attracted much attention"
```

**记录方式**：把**命中数与处理结果**写进修改说明，例如 `机械门禁：em-dash 3 处已改、throat-clearing 2 处已删、强化词 1 处保留（原文有对应效应量）`。不得只写「已检查」。

**例外**：中文稿的「——」是正常标点，不受 em-dash 禁令约束；中文稿的被动表达不按英文规则判。

## 6. 起草类交付：五段，顺序固定

少一段或多一段都算不合格。

```markdown
## 路由声明
task / paper_type / section / language 一行 + `依据:` 一行

## 正文交付
只放成品正文。缺口就地写 [待确认: 具体问题]。按引用键引用写作 [@key]。

## 证据与缺口
- <explicit|inferable|needs-confirmation> — <陈述摘要> → <来源位置或占位符>
缺口: <仍未闭合的信息；没有就写「无」>

## 自检记录
实际跑过的检查、占位符数量、字数统计、**未核对的范围**

## 引用键清单
- @key — <来源描述>（<证据状态>）
（完全没有按引用键引用时写一行：- 无：本交付物未按引用键引用来源）
```

## 7. 润色类交付：三件套

1. **改稿**：纯文本散文，直接可粘贴；**不要**包在代码块里。保持原段落切分与编号，除非结构改动是任务本身。
2. **修改说明**：3–5 条，只讲实质性修改。首选一行点明主失败模式。
3. **结构性问题声明**：若某段结构问题**无法在不编造内容的前提下**修好，写明问题是什么、需要作者提供什么。

| 用户要求 | 交付形式 |
|---|---|
| 只给一句/一段（**优先级最高**） | 只交改稿 + 最多 2 条说明 |
| 并排对比 | `原文` / `改稿` / `改动理由` |
| `task=translate` | 改稿 + 术语替换记录（哪些专名保持原样、为什么） |
| `task=compress` | 改稿 + 主文纪律记录 + 改动前后字数 |
| `task=sweep` | 各段改稿 + 问题表 `位置 \| 维度 \| 现状 \| 期望 \| 严重度` |

## 8. 去 AI 味

目标**不是口语化**，是消除模板痕迹、保留文体应有的正式度。学术、公文、技术写作**不得降级为口语**。

四条学术专有禁令（细则见 `references/de-ai.md`）：

| 禁令 | 长什么样 | 处理 |
|---|---|---|
| 反价值声明 | 先下判断再举例：「X 特征是区分 Y 的重要线索」 | 直接描述特征表现 |
| 反元评论 | 「值得注意的是」「从某种意义上说」 | 删除，直接陈述 |
| 反总括—分述 | 「从 X 角度分析，主要体现在以下 N 个维度」 | 删总括句，直接进内容 |
| 反堆砌 | 每段末尾的「此外，X 也可用于 Y」 | 删补充句 |

**宁缺毋滥**：原文已经自然就保留原文，并写「检测通过：原文表达自然，无明显 AI 痕迹，建议保留」。不输出「AI 味评分」，那不可验证。

## 9. 交付前自检（必做）

1. **数字/单位/引用标记/术语集合**：原稿 vs 改稿逐项比对。偏差为 high 级，**先解决或明确交回用户**。
2. **占位符格式**：全部符合 `[待确认: 具体问题]`，无空占位符。
3. **机械门禁**：§5 全过并记录命中数。
4. **覆盖边界**：写明核对与未核对的范围。**不可审计不等于通过。**
5. **术语台账复查**：专名与缩写在改稿中只在规范形式上出现。

任一项跳过，必须说明**为什么跳过**并声明验证边界。

## 10. 严重度

| 级别 | 判据 | 动作 |
|---|---|---|
| `high` | 改变数值/引用/术语一致性，或触及证据边界 | 阻断交付 |
| `medium` | 读者可察觉的重复、口径不一、claim 强度漂移 | 修或明确标注 |
| `low` | 机械性小问题 | 记录即可 |

**不得带着 high 级发现声称「已完成」。**

## 11. 常见失败

- 请求一段却产出整篇大纲——越权扩张。
- 用形容词补证据（「显著优于」却没有效应量与检验）。
- 素材没给数值，编一个带「约」的估计值。
- 局部改写触发全篇重写，把作者认可的段落改回去。
- 摘要主张反而低于正文最强支撑。
- 去 AI 味时把边界句一起删了，文字更自然但主张变强了。

## 12. 边界与转介

| 遇到 | 转去 |
|---|---|
| 图里不该有的句子、装饰、指标卡 | `paper-figure-audit` |
| 图注怎么写、怎么审 | `figure-legend` |
| 模拟同行评审、审稿意见回复、rebuttal | 不属于本 skill |
| 论文转 PPT / 海报 / 答辩幻灯 | 不属于本 skill |
| 统计方法本身选得对不对 | 交统计核查；本 skill 只判「报告是否与主张匹配」 |
