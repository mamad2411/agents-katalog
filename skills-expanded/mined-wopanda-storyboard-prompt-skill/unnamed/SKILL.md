# 分镜提示词工作流

把一句话需求变成结构化的视频提示词。核心是**三层范式**和**解释式写法**——不是堆关键词，而是让模型理解你要什么、为什么、想表达什么效果。

## 适用范围

本 Skill 设计为**跨 Agent 通用**，可在以下环境使用：
- Claude Code（推荐，对斜杠命令支持最好）
- Codex / Cursor / Windsurf / Hermes 等通用 Agent
- 任何支持读取 Markdown 文件的 LLM 对话环境

## 触发方式

支持任意一种触发：

**方式1：斜杠命令（Claude Code）**
```
/分镜提示词 [需求描述]
```

**方式2：自然语言触发（所有 Agent 通用）**
```
帮我写个[题材]的视频提示词
按分镜提示词 Skill 帮我写...
用三层范式生成提示词：[需求]
```

**方式3：直接调用 Skill 文件（其他 Agent）**
```
请阅读这个目录下的 SKILL.md 并按其工作流处理我的需求：[需求]
```

## 第一步：抽取已知信息

拿到用户输入后，先从中抽出已经明确的内容，**不要重复追问用户已经说清楚的**：

- 主题/故事内容（用户想拍什么）
- 题材类型（丧尸末日 / 武侠打斗 / 都市情感 / 科幻 等）
- 情绪/调性（孤独 / 紧张 / 欢乐 / 压抑 等）
- 镜头复杂度（单镜头 / 多分镜）
- 是否提到参考图、后期剪辑、目标模型

## 第二步：追问缺失信息

通过提问方式补齐关键空位（Claude Code 用 AskUserQuestion 工具，其他 Agent 用对话提问即可）。**只问没说清的，已知的跳过**。

### 必问项（决定提示词结构）

1. **主题/内容是否明确**：
   - 已明确（如"主角在雨夜街道走过表达孤独"）→ 跳过
   - 不明确（如"帮我写个赛博朋克提示词"）→ 追问：具体要表达什么主题/情绪/故事？

2. **参考图情况**（决定基础设定层写法）：
   - 选项A：有角色/场景/道具的参考图，需要锁一致性
   - 选项B：没有参考图，完全用文字描述
   - 为什么问：有图要写"这张图是XX身份，锁XX特征"；没图要把人物/场景描述清楚

3. **是否后期剪辑/配乐**：
   - 是 → 提示词里加声音限制（Seedance 2.0 音画同步会自动生成氛围音，剪辑时难衔接）
   - 否 → 可以不限制声音
   - 为什么问：决定基础设定层要不要写"无背景音乐、无人声"

### 镜头复杂度判断（不追问，直接判断）

⚠️ **默认多分镜（5-7个镜头）**，因为完整主题需要多镜头来铺陈情绪和叙事节奏。

**只有以下情况用单镜头**：
- 用户明确说"就要一个镜头"
- 用户的需求本身就是单个动作（如"特写手部翻书"）

**判断是否需要打斗多分镜（7-10个）**：
- 用户提到武侠/打斗/追逐等复杂动作

### 选问项（补充细节）

4. **题材类型**（如果用户没说清）：参考 [案例参考库.md](案例参考库.md) 理解类似案例的思考方式
5. **核心想表达的情绪/信息**（如果用户没说清）：这是解释式写法的依据

## 第三步：策略提案

⚠️ **在生成提示词之前，先用自然语言描述你打算怎么写，等用户确认后再执行。**

用 4-8 句话说清楚：
- **整体方向**：[题材] + [几个分镜] + [核心表达的情绪/信息]
- **三层策略**：
  - 基础设定怎么锁（参考图身份/声音限制）
  - 氛围画质主打什么风格和限制（根据题材原则现场组装，不照搬预设词）
  - 画面内容几个分镜/每个分镜的时长和重点（学案例的节奏：开场大场景→中间推进→结尾升华）
- **预期效果**：这样写能达到什么效果
- **你可能想调的地方**：哪些是我替你定的默认值

### 等待确认

**⚠️ 在此暂停，等待用户确认。**

- 用户说"可以" / "执行" / "生成" → 进入第四步
- 用户说"改一下XX" → 修改策略，重新提案
- 用户说"不做了" → 终止

### 铁律

- 绝不在未确认的情况下生成提示词
- 确认后如果发现策略需要调整，必须**再次暂停确认**

## 第四步：对照案例密度标准

⚠️ **在生成提示词前，必须对照 [案例参考库.md](案例参考库.md) 的细节密度标准自检：**

### 细节密度自检清单

- [ ] **角色描述**：是否具象到服装材质、配件细节、身体姿态？（不能只写"科技感服装"）
- [ ] **场景描述**：是否具象到建筑风格、地面细节、散落物品、光线来源？（不能只写"街道"）
- [ ] **视觉基调**：是否具体到设备型号、镜头系列？（不能只写"电影感"）
- [ ] **色彩影调**：是否写清楚色彩配方、照明方式、明暗过渡规则？（不能只写"冷色调"）
- [ ] **动作描述**：是否拆解到身体部位、动作分解、速度节奏？（不能只写"行走"）

如果上述任何一项只是空洞概括，返回第三步重新思考策略。

## 第五步：生成提示词

按 [范式-三层结构.md](范式-三层结构.md) 的三层结构，套用选定的镜头模板，**对照案例密度标准**生成完整提示词：

1. **基础设定**：
   - 有参考图 → 写清参考图身份、要锁什么特征
   - 无参考图 → 角色外貌+服装+配件，场景建筑+地面+散落物，都要具象化
   - 声音限制按需添加

2. **氛围画质**：
   - 风格核心 + 限制词（杜绝XX）
   - 视觉基调：设备型号+镜头系列
   - 色彩影调：色彩配方+照明设计+明暗过渡

3. **画面内容**：
   - 分镜 / 景别 / 构图 / 运镜
   - 画面：解释式写法（做什么+为什么+想表达什么），动作拆解到身体部位和节奏

## 第六步：自检

生成后对照 [反模式清单.md](反模式清单.md) 和以下分级清单逐条核对：

### P0 · 致命（不通过 = 返工）

- [ ] 角色/场景描述是否达到案例密度标准（具象到材质/配件/细节）
- [ ] 参考图是否写了身份描述（有图的情况）/ 人物外貌是否具象化（无图的情况）
- [ ] 画面内容是否用解释式写法（说清怎么做+为什么+想表达什么），而非只堆关键词
- [ ] 每个分镜是否标注了时长（如"00:00-00:05"）
- [ ] 分镜数量：多分镜是否在5-7个之间（打斗可7-10个）
- [ ] 限制词是否≥2条

### P1 · 严重（不通过需修复）

- [ ] 风格核心是否对应用户的具体需求（不是照搬案例库的词，而是根据用户画面现场组装）
- [ ] 视觉基调是否写到设备型号+镜头系列（不能只写"电影感"）
- [ ] 色彩影调是否写清色彩配方+照明方式（不能只写"冷色调"）
- [ ] 多分镜：动作链有无断点、收招是否成立

### P2 · 建议（不通过可标注后跳过）

- [ ] 声音限制是否按需添加（后期剪辑→加，单镜头直出→可不加）
- [ ] 单个分镜画面描述是否≤80字（太长模型抓不到重点）

### 核对方式

- P0 项必须逐条检查，全部通过才能交付
- 触犯反模式清单的，标注理由或返工
- 全部通过后，标记"自检通过"

## 第七步：交付

交付完整提示词，并附：
- 哪些是我替你定的默认值
- 你可能想调的地方在哪
- 自检是否通过

## 第八步：引导沉淀新案例（重要）

⚠️ **当用户对生成的提示词反馈"满意"、"很好"、"就按这个用"等正向信号时，主动询问是否沉淀为新案例：**

```
这次生成的提示词如果实际投喂模型后效果不错，建议沉淀到案例参考库，让 Skill 越用越聪明。

要不要把这次的需求和提示词加入 [案例参考库.md](案例参考库.md)？

如果你愿意，我会按以下结构添加：
- 用户需求还原（题材、调性、目标模型、核心表达）
- 完整提示词（三层结构）
- 细节密度标准拆解（这个案例教你什么）
- 关键决策点（为什么这样写）

这样下次类似题材的提示词生成会有这个案例作为密度参考。
```

如果用户同意，按 [案例参考库.md](案例参考库.md) 中"未来扩展方向"章节的结构，将新案例追加到文件末尾。

### 沉淀新案例的最低标准

只有满足以下所有条件，才建议沉淀：
- [ ] 用户明确表示效果满意（不是"还行"这种模糊评价）
- [ ] 提示词通过了 P0 自检
- [ ] 题材或表达方式与现有案例**有差异**（避免重复案例）

如果用户已实际投喂模型并验证了视频效果，更应该沉淀（标注"已验证"）。
