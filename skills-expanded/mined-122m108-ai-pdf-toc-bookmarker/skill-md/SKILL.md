# PDF 目录书签自动提取与植入

## 核心流程

调用 Python 脚本渲染目录页为高清图片 → 支持视觉的AI识别提取结构化目录 → 偏移量换算 → 写入书签 → 输出新 PDF。

## 安全纪律（最高优先级）

1. **工作空间边界**：只能在工作空间（或书本所在地址）内读写文件，禁止访问、修改、删除工作空间之外的任何文件和目录。
2. **禁止擅自安装库**：在执行任何 `pip install`、`npm install` 或其他包管理命令之前，必须先询问用户并获得明确许可。如果需要的库未安装，请报告用户，等待用户决定，以防造成环境错乱。
3. **删除/重命名/覆盖必须确认**：对任何已有文件执行删除、重命名或覆盖操作前，必须先向用户说明具体操作（文件路径、操作类型），获得用户确认后才可执行。不得静默覆盖或删除任何文件。

## 核心概念（注意区分）
1. **电子页码**：即PDF电子阅读器显示的PDF页码，兼容常见浏览器（如edge，chrome，火狐）。第一页往往是书的封面。这也是给渲染的目录图片命名时所使用的页码。
2. **印刷页码**：也叫做纸质书页码，即书本自身所带的页码，独立于任何阅读器，是书本自身所带的。第一页往往是书的正文第一页。
3. **偏移量 (offset)**：同一个内容，印刷页码和电子页码之间存在一个固定的差值，这个差值就是偏移量，满足 `偏移量=电子页码-印刷页码`。它取决于正文前面（封面、前言、目录、序等）有多厚。
   - **如何得到偏移量**：跳到任意一页「既能看见正文、又印着页码」的地方，用「该页的电子页码 − 该页的印刷页码」即可。以《深入理解计算机系统》第三版为例，正文第 1 页在阅读器里是第 37 页，`37 − 1 = 36`，偏移量就是 36；换一页也一样，比如印刷第 50 页在阅读器里是第 86 页，`86 − 50 = 36`，结果不变。
   - **偏移量由用户心算后告诉你**：你不用自己去翻页推算；你只需把用户给的偏移量原样传给脚本，脚本再对每条书签做加法换算。因为由你逐页看太费token了
   - **严禁擅自修改用户给出的偏移量**：如果你在识图过程中觉得用户给出的偏移量不对，仍要按照用户给出的偏移量执行，可以在结束时告诉用户你的怀疑。原因：受限于该skill只想让你看目录页以达到节省token，你所能掌握的信息非常少，有极少数的书会在正文页前也设置页码，但是正文从1重新开始，所以有可能造成你的误判。作为skill的开发者，我无法列举所有极端情况。总之，你应该尽可能的相信用户给出的参数。


## 用户操作规范

- 用户往往会给你设立一个工作空间，这时你就去工作空间找书，那本书就是你要处理的；如果没给你设立工作空间，往往也会给你PDF的文件地址，你有了地址就能确定目标。
- 用户使用的是自然语言，会告诉你三个重要的参数。前两个是电子页码（用户查阅电子阅读器得到），第三个是偏移量（用户自己心算好后告诉你）：1.目录起始页（电子页码），2.目录结束页（电子页码），3.偏移量。
- 偏移量由用户提供，你不必也不应自行推算。如果用户只给了"某页电子页码"和"该页印刷页码"这一对参照数据，而没直接给偏移量，你可以据此求差（电子−印刷）得到偏移量再传给脚本。用户也可能累了懒得计算偏移量，直接输入（电子-印刷），例如“偏移量96-87”，这时你要算出结果9才能传入后续的py参数。

## 两种简写（举例）
- “目录15-23，偏移量11”。这指的是目录起始页15，目录结束页23，偏移量11。
- “15，23，11”。这同样指的是目录起始页15，目录结束页23，偏移量11。更为简便。从左往右对应顺序即可。
- 单页目录：若目录只有一页，用户可直接输入单个页码（如 “目录15，偏移量11” 或 “15，11”），模型自动识别起始页 = 结束页 = 15。若用户输入“目录15”而未提供偏移量，则视为缺省偏移量参数（仍需提醒用户提供或后续补全）。

## 脚本清单

| 脚本 | 用途 | 触发时机 |
|------|------|----------|
| `scripts/render_toc_pages.py` | 渲染目录页为高清 PNG | 工作流第二步 |
| `scripts/write_bookmarks.py` | 读取已保存的目录 JSON，写入 PDF 书签 | 工作流第四步 |


## 工作流（必须严格按序执行）

### 第一步：规范化输出文件名

缘由：原PDF的文件名比较随意，不利于归档；规范命名也方便后续工具调用。

执行方式：直接从原文件名中推理书名、作者、版本（如第 x 版），生成新文件名。

- 格式：`AI书签_书名_作者_版本（第x版）.pdf`
- 缺失项直接省略。
- 例如 `AI书签_深入理解计算机系统_Randal_第3版.pdf`
- 这一步无需编写代码，直接在思维中完成，将结果记作变量 `formatted_name`（不含 `.pdf` 后缀）。

### 第二步：渲染目录页为高清图片

缘由：将 PDF 的目录区间渲染成图片，AI 才可以用自己的（视觉）多模态能力识别目录部分的文字

纪律：

- 只渲染用户指定的起始页到结束页，绝对不翻看其他页面以节省 token。
- 图片清晰度要接近 PDF 查看器 150% 缩放效果，使用 2.0 ~ 4.0 倍的渲染矩阵。
- 图片文件命名为 `第N面.png`，N 是电子页码。
- 所有图片存入当前目录下的子文件夹 `{原PDF名}_目录图片`。

执行方式：用命令行带参运行 `scripts/render_toc_pages.py`（参数通过命令行传入，不修改脚本本身）。

命令行参数说明：

| 参数 | 说明 | 示例 |
|------|------|------|
| `--pdf` / `-p` | PDF 文件完整路径 | `--pdf 某书.pdf` |
| `--start` | 目录起始页码（电子页码） | `--start 15` |
| `--end` | 目录结束页码（电子页码） | `--end 23` |
| `--zoom` | 渲染倍数，2.0~4.0（默认 4.0） | `--zoom 4.0` |

完整示例：`python scripts/render_toc_pages.py --pdf 某书.pdf --start 15 --end 23 --zoom 4.0`

### 第三步：视觉识别图片并提取结构化目录

缘由：这是唯一需要 AI "动眼"的环节。依次查看生成的图片，模拟人类阅读逻辑，输出完美嵌套的 JSON 目录。

执行方式：

- 读取 `img_dir` 下的所有 `第N面.png` 文件，按页码顺序处理。
- 若单次无法处理太多图片，可分批次读取，但务必保持标题的连续性。
- 提取要素：
  - **页码 (book_page)**：印在标题后的数字（往往是水平对齐的右侧或跟随标题的阿拉伯数字）。
  - **标题 (title)**：去除前后的装饰性符号、引导虚线、页码数字，只保留干净文字。
  - **层级 (level)**：根据字体大小、缩进量、是否有"篇/章/节"等关键词判断。
    - 篇、部分 → level 1
    - 章 → level 2（若无篇，则章提升为 level 1）
    - 节、小节 → level 3
- 降噪与容错：忽略水印、页脚、模糊墨点。若文字被遮挡，根据上下文推理补全。
- **「目录」书签强制规则（必须遵守）**：
  - JSON 数组的第一条**必须**是"目录"本身作为书签，标题固定为 `"目录"`，层级（level）与书中最高级标题相同（例如若有"篇"则 level=1，若无"篇"则与"章"同级）。
  - "目录"书签是独立顶级条目，**不要**把后续所有书签折叠到"目录"下面。书签层级应如实反映原书结构（篇→章→节），"目录"只是与第一篇并列的同级书签。
  - "目录"页一般没有印刷页码数字，因此json的 `page` 字段直接使用用户提供的目录起始电子页码，这是等价的。

输出 JSON 格式（必须严格遵守）：

```json
[
  {"level": 1, "title": "目录", "page": 1},
  {"level": 1, "title": "第一篇 计算机系统漫游", "book_page": 1},
  {"level": 2, "title": "第1章 计算机系统结构", "book_page": 3},
  {"level": 3, "title": "1.1 信息就是比特+上下文", "book_page": 5}
]
```

字段说明：
- `book_page`：指的是图上真实的页码数字（往往等价于印刷页码），脚本会用偏移量把它换算成电子页码，你不需要计算。
- `page`：直接填入目录起始页（电子页码），脚本不会做也不需要做偏移计算。仅用于"目录"等无印刷页码的条目。

将上述 JSON **保存到文件**：路径为 `<原PDF名>_目录.json`，与原 PDF文件 同目录，如果设立了工作空间就在工作空间。例如原 PDF 为 `某书.pdf`，则保存为 `某书_目录.json`。后续若用户发现偏移量给错了想重跑，直接复用此文件，无需重新识图。

### 第四步：写入书签到 PDF 并保存为新文件

机制：脚本用用户给定的"偏移量"把每条书签的印刷页码换算成实际的 PDF 电子页码（偏移量=电子页码-印刷页码），并全量覆盖写入 PDF，彻底移除废旧书签，同时自动丢弃目录页之前的前置页码。

纪律：

- `--offset` 使用用户提供的偏移量原值，严禁自行修改。用户没直接给偏移量、只给了「某页电子页码 + 该页印刷页码」时，才由你求差（电子−印刷）得到偏移量。
- `--toc-start` 填入用户给的目录起始页（电子页码），脚本会自动过滤指向目录之前页面的书签。该参数可省略：省略时脚本会自动从 JSON 的「目录」条目 `page` 字段推导。
- 输出文件名使用第一步生成的 `formatted_name`。
- ⚠️ 覆盖确认（首次运行）：输出文件若已存在（非重跑场景），必须先向用户确认才可覆盖；此时不要加 --overwrite，让脚本报错提示后再询问用户。
- ✅ 重跑豁免（修正偏移量时）：如果是因为用户之前给错了偏移量而重新运行第四步，可以直接加上 --overwrite 参数，无需再次询问用户，直接覆盖旧文件。

执行方式：用命令行带参运行 `scripts/write_bookmarks.py`（参数通过命令行传入，不修改脚本本身）。

命令行参数说明：

| 参数 | 说明 | 示例 |
|------|------|------|
| `--pdf` / `-p` | 原始 PDF 完整路径 | `--pdf 某书.pdf` |
| `--name` | 第一步生成的格式化书名（不含 .pdf） | `--name "AI书签_某书_作者"` |
| `--json` / `-j` | 第三步保存的目录 JSON 文件路径（`原PDF名_目录.json`） | `--json 某书_目录.json` |
| `--offset` | 偏移量（偏移量=电子页码-印刷页码），由用户提供 | `--offset 36` |
| `--toc-start` | 目录起始页电子页码（可省略，自动推导） | `--toc-start 15` |
| `--overwrite` | 输出文件已存在时直接覆盖（默认需确认） | `--overwrite` |

完整示例：`python scripts/write_bookmarks.py --pdf 某书.pdf --name "AI书签_某书_作者" --json 某书_目录.json --offset 36`

### 第五步（可选）：汇报结果

以上步骤全部静默执行。最后只需用一句话告知用户：新文件已生成，书签数量、文件路径。无需多余解释。


### 附：用户想改偏移量重跑（低token消耗）

如果第一轮跑完后，用户发现偏移量给错了，想用新的偏移量重算书签：

- **不要**重新渲染或重新识别目录图片（那会重新消耗视觉 token，也没必要）。
- 目录 JSON 已在第三步落盘（`<原PDF名>_目录.json`），直接复用，无需重新生成。
- 重跑 `write_bookmarks.py` 时，只需调整命令行参数：
  - 将 `--offset` 改为新的偏移量；
  - 命令末尾**加上 `--overwrite`**，以覆盖之前生成的文件（因为此时用户已明确要重跑，无需再次确认）。
- 整个过程 AI 不需要再看图、也不需要重新生成 JSON 字符串。



## 环境依赖

本技能依赖 **PyMuPDF** 库（一个用于处理 PDF 的 Python 库，可渲染页面、读写书签等）；

- 安装：`pip install -r requirements.txt`（即安装 **PyMuPDF**）
- ⚠️ 常见错误：别去执行 `pip install fitz`，正确做法是 `pip install pymupdf`。
- 因为 `fitz` 是 PyMuPDF 库的一部分，所以代码里写的是 `import fitz`。
- 若未安装就运行脚本，脚本会直接打印上述安装提示并退出，不会抛出难以阅读的报错。
