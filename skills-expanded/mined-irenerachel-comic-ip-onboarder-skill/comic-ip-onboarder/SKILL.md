# 漫画 IP 入驻器

把新的用户 IP 接入一个漫画信息图工作流。这个技能不负责直接替代某个既有 IP 技能，也不修改既有技能的角色规则；它只产出一个独立、可确认、可移植的 IP 档案包。

## 第一硬命令

- 必须使用 imagegen 的图像生成能力实际生成最终图片。最终交付图片只能是由 imagegen 生成出来的图片文件；绝对禁止使用 HTML、CSS、SVG、canvas、网页截图、幻灯片截图、拼贴画布或任何前端渲染方式来生成、伪装或替代最终图片。
- 如果当前执行环境或确认使用的工具是 Codex，必须使用 Codex 默认生图能力完成最终图片；不要改用 HTML、CSS、SVG、canvas、网页截图、幻灯片截图或任何前端渲染方式替代。
- 如果本流程创建、改写或交接任何新的下游 `SKILL.md`，生成出来的主文档第一条也必须原样写入本节硬命令；不得把它放到附录、普通说明或可选建议里。

## 核心边界

- 不要修改任何既有 IP 技能，除非用户明确要求。
- 不要把新角色细节写进其他技能的 `SKILL.md`。
- 可以把既有 IP 当成结构参考：只复用档案格式、质检清单和确认流程，不复用外貌。
- 如果来源是真人照片，要做成受照片启发的风格化 IP，不要追求写实肖像。
- 视觉参考图必须遵守第一硬命令，使用 imagegen 实际生成图片；不要把 HTML、CSS、SVG、canvas、网页截图或幻灯片截图当作最终 IP 参考图。
- 只有用户确认过的参考图才能进入最终档案文件夹。失败图、未确认图不能作为参考资产保存。
- 所有交付给用户复制或用于生图的提示词都必须写中文，包括正面确认图提示词、三视图提示词、表情包提示词、提示词胶囊和负向提示词。只有文件路径、文件名、固定技术标识可以保留英文。
- 不要把推进责任交给用户。每完成一个阶段，都必须用简短问题主动询问下一步，并给出推荐选项。
- 第一张正面纯色确认图必须是完整全身图。即使用户只提供头像、半身照或大半身照，也不能输出半身确认图；需要保守补全下半身、鞋子或底部结构，并把推断部分列入“需要你确认的地方”。
- 当源图不是全身照时，要主动建议用户补充一张全身照来提高准确度；但不要因为没有全身照就停止流程。若用户暂时不补图，继续基于现有参考做保守推断。
- 表情动作包必须基于已确认的三视图生成。没有 `three-view.png` 或用户未确认三视图时，不要生成任何单张表情动作图。8 张里的每一张、每一次生成，都必须把这张三视图作为图像参考输入，不能只在第一张或第一轮参考。
- 每条表情动作提示词都必须明确要求：“请以上传的三视图作为同一个 IP 的角色参考，严格保持头身比例、整体轮廓、脸部特征、眼睛规则、服装、配饰、颜色锚点和线条风格一致；只改变本张图的表情、动作和道具。”
- 表情动作包数量必须固定为 8 张，不要生成 6 张、9 张、12 张或其他数量。
- 表情动作包必须一张一张生成和输出，每张都是独立图片。禁止先生成一张合集、联系表、九宫格、拼贴图、贴纸大图或多动作大画布再切分。
- 8 张表情动作图必须保持同一个背景颜色、同一个人物比例、同一套线条和配色；每张只改变表情、动作和可选道具。

## 什么时候使用

当用户提供或描述一个新的 IP，并希望它变成可复用角色时，使用这个技能：

- 用户照片或自拍 -> 风格化漫画 IP
- 毛绒玩具或手办 -> 扁平手绘角色档案
- 头像或吉祥物 -> IP DNA、三视图、表情动作包
- 伴随宠物或物件 -> 伴随角色 DNA 和出现频率规则
- 既有成功 IP 技能 -> 提取档案格式，用于新用户 IP

不要用这个技能生成普通文章插图。IP 档案确认后，再交给下游漫画信息图技能使用。

```text
使用 comic-ip-onboarder，基于我上传的照片创建一个漫画 IP 档案。请先分析身份锚点，再主动询问我是否补充全身照；如果我暂时不补，也请先保守生成完整全身的正面确认图提示词。
```

```text
调用 comic-ip-onboarder，为这个新 IP 建档：先做 IP_DNA.md 草案，再做正面全身确认图、三视图和表情动作包。每完成一步都主动问我下一步。
```

```text
调用 comic-ip-onboarder，基于已确认的三视图继续生成这个 IP 的表情动作参考包。必须生成 8 张独立单张图片，不要生成合集再切分；每张表情图都必须以上传的三视图作为同一角色参考，保持背景颜色和人物一致性。
```

## 必读参考

- `references/IP_DNA_TEMPLATE.md`：起草任何新 IP DNA 前必须读取。

## 输出约定

每个新 IP 最终应创建或规划这样的档案包：

```text
<project-or-skill>/references/ip-profiles/<profile-id>/
├── IP_DNA.md
├── front-full-body.png
├── three-view.png
├── expressions/
│   ├── 01-*.png
│   ├── 02-*.png
│   ├── ...
│   └── 08-*.png
└── companion/
    ├── companion-DNA.md
    └── companion-three-view.png
```

`IP_DNA.md` 是第一交付物。图片只在用户确认每个阶段后加入。

## 主动推进规则

这个技能必须像项目经理一样推进流程。不要在阶段结束时只说“完成了”，也不要让用户自己猜下一步。

每次阶段性输出末尾都必须包含：

```text
下一步我建议：<推荐动作>
请你确认：<一个清晰问题>
可选方向：
1. <推荐选项>
2. <备选选项>
3. <需要时才给第三个选项>
```

提问要短，只问当前阶段真正需要用户判断的事。默认把推荐选项放在第 1 个。

阶段结束后的主动提问规则：

- 完成源图分析后，询问用户是否接受身份锚点，并推荐“先生成正面全身确认图”。
- 完成 `IP_DNA.md` 草案后，询问哪些身份锚点需要修改，并推荐“确认后生成正面全身确认图”。
- 如果源图不是全身照，完成源图分析后要主动提醒：“为了更稳定，建议补一张全身照；如果暂时没有，我会先保守补全为完整全身角色。”然后询问是否补图或继续。
- 完成正面全身确认图后，询问这张图是否通过，并推荐“通过后生成三视图”。
- 完成三视图后，询问三视图是否通过，并推荐“通过后把这张三视图作为图像参考，生成 8 张独立单张表情动作参考图”。必须提醒用户：表情动作包会以上传的三视图作为角色参考，不只依赖文字描述；表情包必须一张一张生成，不做合集切分。
- 完成表情动作包后，询问是否需要伴随角色或直接打包交接，并推荐“先打包当前 IP 档案”。
- 完成最终档案包后，询问用户下一个任务：用于哪篇文章、是否安装到下游漫画技能、或是否为另一个用户创建新 IP。

如果下一步依赖用户审美确认，例如角色像不像、发型对不对、服装是否保留，不要自动跳过确认继续生成后续图。要主动问，并给出下一步建议。

## 工作流

1. 读取用户提供的源图片、角色描述或既有参考资产。
2. 判断来源完整度：全身、大半身、半身、头像或局部。如果不是全身，主动建议用户补充全身照；若用户暂时不补，继续基于现有参考保守补全完整全身角色，并把推断部分列入待确认项。
3. 读取 `references/IP_DNA_TEMPLATE.md`，起草 `IP_DNA.md`。
4. 首轮草案必须用这四个部分给用户确认：
   - `保留的身份锚点`
   - `被简化掉的照片细节`
   - `需要你确认的地方`
   - `第一张正面全身图提示词`
5. 生成或撰写一条中文提示词，用于制作目标漫画风格下的正面全身确认图。第一张确认图必须是完整全身、纯色背景、纯正面视角，不允许输出头像、半身或大半身。
6. 用户确认正面全身确认图后，再生成或撰写三视图提示词。三视图必须先被用户确认，才能进入表情动作包阶段。
7. 用户确认三视图后，再生成或撰写 8 张单动作表情参考图提示词；如有伴随角色，再做伴随角色三视图。
8. 生成单张表情动作参考图时，必须把已确认的 `three-view.png` 作为参考图输入；8 张里的每一张都要重新附上同一张三视图作为参考。不能只在表情包阶段开始时参考一次。如果无法使用三视图作为参考图，停止推进并询问用户上传或确认三视图。
9. 表情动作包必须按 `01` 到 `08` 分别生成 8 张独立图片。不要生成一张包含 8 个表情的大图，不要生成联系表、九宫格、拼贴图、贴纸合集，也不要后期切分。
10. 接受图片前必须做最终质检：
   - 身份锚点是否保留
   - 是否使用三视图作为表情动作图的参考图
   - 表情动作包是否正好 8 张
   - 是否每张都是独立单张，而不是从合集切分
   - 8 张图的背景颜色、角色比例、线条和配色是否一致
   - 眼睛和脸部规则是否遵守
   - 服装和配饰是否稳定
   - 身体结构是否正常
   - 是否误借用了其他 IP 的特征
   - 最终图是否来自图像生成或图像编辑路线
11. 每完成一个阶段，都主动询问用户下一步，不要等待用户自己说“继续”。
12. 只有用户确认后，才把合格文件存入档案文件夹，或明确告诉用户应该安装/交付哪个档案包。

## 表情动作包一致性闸门

生成表情动作包前，必须满足以下条件：

1. 已有用户确认过的 `three-view.png`。
2. 当前对话或任务中可以把这张三视图作为图像参考输入。
3. 每张表情动作提示词都明确要求参考三视图，并保持角色整体一致。
4. 已明确规划 8 张独立单张图片，并确认不会生成合集后再切分。

如果任一条件不满足，不要生成表情动作包。改为主动询问：

```text
下一步我建议：先上传或确认三视图，再生成表情动作包，这样能保证角色一致。
请你确认：现在是否使用这张三视图作为后续表情动作图的参考？
可选方向：
1. 使用当前三视图继续生成表情动作包
2. 先重新生成或修正三视图
3. 暂停表情包，先补充更多角色参考
```

表情动作图的提示词必须包含这句话：

```text
请以上传的三视图作为同一个 IP 的角色参考，严格保持头身比例、整体轮廓、脸部特征、眼睛规则、服装、配饰、颜色锚点和线条风格一致；只改变本张图的表情、动作和道具。
```

表情动作包必须使用 8 条独立提示词分别生成，提示词编号为 `01` 到 `08`。每条提示词都要写清楚：

- 这是一张单独图片，不是合集的一格。
- 背景颜色必须与其他 7 张一致。
- 角色比例、轮廓、服装、配饰、线条粗细和配色必须与三视图一致。
- 每一张生成时都必须实际使用同一张已确认三视图作为图像参考输入。
- 只允许改变本张的情绪、动作和可选道具。
- 不要联系表、九宫格、拼贴图、贴纸合集、分镜页或任何需要后期切分的大图。

## IP 提取规则

- 提取稳定身份锚点：轮廓、头发/头部形状、脸部节奏、标志性配饰、服装逻辑、身体比例和颜色锚点。
- 把来源细节翻译成简单扁平漫画语法。避免照片质感、真实光影、复杂布料纹理、皮肤毛孔和细碎发丝。
- 使用具体绘制规则。不要只写“可爱”“聪明”“高级”这类抽象词，除非后面接上可见的画面决定。
- 如果某个特征看不清或有歧义，标为 `未知`，并给出 1-2 个保守选项让用户确认。
- 如果下半身、鞋子、尾巴、底部结构或身体比例在源图中不可见，标为 `根据现有信息保守推断`，不要当作已确认事实。
- 把风格 DNA 和 IP DNA 分开：线条、纸纹、构图等共享风格属于下游插图技能；角色独有身份写进 `IP_DNA.md`。
- 如果参考了既有 IP 档案，只复用文档结构和质检严格度。除非新 IP 本身有这些特征，否则不要复制头发、服装、耳环、宠物、道具或配色。

## 确认标准

不要把第一张生成角色当成最终版本。第一张图只是确认探针。

用户至少要能回答：

- 这还像原本想做的人、吉祥物或玩具吗？
- 这张确认图是否已经是完整全身，而不是半身或大半身？
- 哪 2-3 个细节不对？
- 哪个细节以后绝对不能漂移？
- 这个角色是否需要伴随角色？
- 这个输出风格是否适合未来文章配图？
- 表情动作包是否明显沿用了前一步三视图，而不是像重新设计的角色？
- 表情动作包是否正好 8 张独立单张，并且背景颜色和人物一致？

如果用户修正任何身份锚点，必须先更新 `IP_DNA.md`，再继续生成更多视图。

## 下游交接

IP 档案确认后，提供一段简短交接信息：

```text
当前 IP 档案: <path/to/IP_DNA.md>
必需参考图:
- <front-full-body.png>
- <three-view.png>
- <expression folder>
提示词胶囊:
<从 IP_DNA.md 提取的一段中文提示词>
硬性质检:
<5-8 条不可妥协的检查项>
```

下游漫画插图技能应该读取这个档案包，不要在自己的主说明里重写角色规则。

完成交接后，必须继续问用户：

```text
下一步我建议：把这个 IP 档案接入一个下游漫画信息图技能，试跑一篇文章。
请你确认：现在是要接入下游技能，还是继续为另一个 IP 建档？
可选方向：
1. 接入下游漫画信息图技能并试跑一篇文章
2. 继续优化当前 IP 的表情动作包
3. 为另一个用户创建新 IP 档案
```
