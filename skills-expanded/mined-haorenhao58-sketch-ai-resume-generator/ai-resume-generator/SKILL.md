# AI方向简历生成器

## 概述

本skill面向所有想投递AI相关岗位的候选人，通过结构化引导收集个人信息与项目经历，生成突出AI创新思维、产品化能力和量化成果的专业简历。

覆盖岗位方向：AI产品经理、Prompt Engineer、AI运营、AI商业化、AI工程师、LLM应用、AIGC等。

## 核心工作流

整体流程分为4个阶段：信息采集 → 内容提炼 → 简历生成 → 迭代优化。

### 阶段一：信息采集（深度引导）

通过分模块逐步追问，帮助候选人梳理和回忆细节。每轮聚焦一个模块，不要一次性抛出所有问题。

#### 第1轮：基础信息 + 目标定位

收集以下信息：
- 姓名、联系方式（手机、邮箱）
- 目标岗位方向（AI PM / PE / 运营 / 工程师 / 商业化，可多选）
- 是否有目标岗位的JD（如有，请候选人粘贴，后续将据此调整简历侧重）
- 个人作品集/GitHub/技术博客链接（可选）

#### 第2轮：教育背景

收集以下信息：
- 学校、专业、学历、起止时间
- 奖项荣誉（奖学金、竞赛、GPA等亮点）
- 在校经历（社团/学生组织/学术项目中与AI或目标方向相关的经历）
- 交换/海外经历（如有）

引导技巧：追问"这些经历中有没有用到数据分析、AI工具、或者自主探索过什么技术项目？"

#### 第3轮：实习/工作经历（核心模块，最深度引导）

对每一段经历，逐层追问以下维度：

**背景层**：
- 公司、部门、岗位、起止时间
- 所在团队做什么业务？你在团队中的角色定位？

**问题层**（挖痛点）：
- 你接手时这个业务/产品面临什么问题或挑战？
- 你发现了什么别人没注意到的问题？（引导候选人回忆洞察时刻）

**方案层**（挖方法论）：
- 你具体做了什么来解决这个问题？
- 技术方案是什么？（如涉及Prompt设计、Agent架构、RAG、A/B测试等，深挖细节）
- 你在方案设计中做了哪些关键决策？为什么这么选？
- 有没有什么创新点或你觉得特别巧妙的设计？

**结果层**（挖数据）：
- 最终效果如何？有没有量化数据？（转化率、准确率、效率提升等）
- 如果没有精确数据，大概的量级或定性描述也可以
- 这个成果有没有被复用、推广、或者影响了后续的决策？

**反思层**（可选，用于个人评价模块）：
- 这段经历中你最大的成长或收获是什么？
- 积累了什么可迁移的方法论？

每段经历收集完毕后，向候选人确认是否还有其他实习/工作经历需要补充。

#### 第4轮：项目经历

对于非实习的独立项目（课程项目、个人项目、开源贡献、竞赛项目等），采用与实习经历类似的追问逻辑，但额外关注：
- 项目动机（为什么做这个？）
- 你在项目中的角色（独立完成 vs 团队协作，如团队则你负责什么）
- 技术栈和工具链
- 项目成果与影响力

#### 第5轮：技能与个人标签

- 技术工具（如Cursor、Coze、LangChain、SQL、Axure、Figma等）
- AI能力（如Prompt工程、Agent搭建、RAG、GPTs开发、微调等）
- 软技能与个人特质（引导用简短故事展现，而非空泛形容词）
- 兴趣爱好（可选，引导候选人提炼出有记忆点的个人标签）

### 阶段二：内容提炼

信息采集完成后，按照以下写作范式对原始素材进行加工。

#### 写作范式（核心）

**1. 三段式项目描述：问题→方案→量化结果**

每段经历用2-4个要点描述，每个要点遵循：
- 【标题关键词】+ 发现/面对什么问题 + 采取了什么方案 + 取得了什么结果

示例：
- ❌ 原始素材："负责优化了模型的评分逻辑，效果还不错"
- ✅ 提炼后：【重构[业务名]评分工作流】洞察大模型在[具体场景]下存在[具体问题]的逻辑缺陷。摒弃[旧方案]策略，主导设计涵盖"[模块A]、[模块B]、[模块C]"的多模块隔离架构，实现[量化成果]。

**2. 技术术语产品化表达**

将技术实现翻译为产品语言，让非技术读者也能理解价值：
- ❌ "用了multi-agent架构" → ✅ "主导设计[N]步全流程Agent架构（步骤A→步骤B→步骤C），将[输入]拆解为原子级任务并加以筛选、检索、判断"
- ❌ "做了prompt优化" → ✅ "将Prompt方法论沉淀为可复用的模块化框架，推动全流程从单步试错向结构化、高稳定性工作流演进"
- ❌ "降低了错误率" → ✅ "开创性引入[具体机制]，实现[指标A]降低X%、[指标B]低于Y%"

**3. 动词前置的行动导向句式**

每个要点以强动词开头，体现主导力和行动力：
- 推荐用词：主导设计、敏锐洞察、开创性引入、自主建立、协同[团队]推进、深入[场景]……
- 避免被动语态（"被分配""参与了"）和弱动词（"做了""负责了"）

**4. 数据锚定**

所有可量化的成果必须给出具体数字：
- 效率类：提升X%、缩短Y小时、节省Z成本
- 质量类：准确率达X%、错误率降低Y%、吻合率Z%
- 业务类：转化率提升X%、点击率提升Y%、用户增长Z%
- 如果候选人无法提供精确数据，引导其估算量级（"约""近""超过"）

#### 个人评价写作指南

个人评价不是经历的重复，而是提炼候选人的"核心卖点"。结构：
1. 一句话定位（复合背景 + 专注方向）
2. 核心经验概述（在哪些公司做过什么，积累了什么能力）
3. 工具与技能点（具体工具名 + 具体能力项）
4. 标志性成果（1-2个最亮眼的数据）
5. 软实力标签（思维方式 + 工作风格）

### 阶段三：简历生成

#### 模块结构（灵活调整）

根据候选人的实际情况灵活调整模块顺序和取舍。以下是标准结构：

**应届生/实习少：** 教育背景 → 项目经历 → 实践经历 → 技能清单 → 个人评价
**有实习经验：** 个人评价 → 教育背景 → 实践经历 → 项目经历 → 个人标签
**工作1-3年：** 个人评价 → 工作经历 → 项目经历 → 教育背景 → 技能清单

#### 根据目标岗位调整侧重

如果候选人提供了目标JD，在生成简历时：
- 提取JD中的关键词和能力要求
- 在简历的个人评价、经历描述中自然融入匹配关键词
- 调整经历要点的排序，将与JD最匹配的要点前置
- 在技能清单中优先列出JD提到的工具和能力

不同岗位方向的侧重点：
- **AI产品经理**：强调需求洞察、方案设计、跨团队协同、数据驱动迭代
- **Prompt Engineer**：强调Prompt设计方法论、评测框架、模型理解、工程化能力
- **AI运营**：强调数据分析、用户增长、内容策略、AI工具应用
- **AI商业化**：强调商业模型设计、ROI分析、广告策略、变现路径
- **AI工程师**：强调技术栈深度、架构设计、模型调优、工程实践

### 阶段四：输出与迭代

#### 输出格式

先确认候选人想要的输出格式：
- **Markdown**：直接生成.md文件，适合在线投递或转换
- **Word文档**：生成.docx文件，适合正式场合。使用docx skill生成，注意排版美观
- **两者都要**：同时生成两个版本

#### 迭代优化

生成初版后，主动询问候选人：
- 哪些经历的描述需要调整？
- 有没有遗漏的重要信息？
- 是否需要针对特定岗位JD做进一步优化？

## 关键原则

1. **永远追问细节**：候选人说"做了prompt优化"时，追问"优化了什么？之前是什么样的？优化后效果如何？"
2. **帮候选人发现价值**：很多候选人不知道自己做的事情有多亮眼，帮他们用专业语言包装
3. **数据第一**：没有数据的成果缺乏说服力，引导候选人回忆或估算
4. **避免虚假**：润色不是编造。所有内容基于候选人提供的真实素材，不捏造经历或数据
5. **一页纸原则**：简历控制在一页A4纸以内（除非经历非常丰富），信息密度要高
6. **AI基因贯穿**：即使经历不直接涉及AI，也引导候选人发掘其中的AI思维（数据驱动、自动化、模型思维等）
