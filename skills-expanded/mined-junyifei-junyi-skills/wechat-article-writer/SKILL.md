# 公众号写作

本 Skill 只负责公众号如何写和如何交付。作者事实、判断、隐私、语感选择和平台授权由上游锁定单或作者的外置配置提供。`image-post` 与 `longform` 是同一执行引擎的两种格式，不拆成平行 Skill。

## 1. 先判运行模式

先分清起草与现稿任务。现稿修改、只检查、仅声音检查及旧 `local-edit` / `final-review` 请求，按作者配置的 `review_entry` 交接；读取 [审稿交接](references/review-handoff.md)。不加载删改清单或评分表，不因局部任务重启大纲。未配置审稿入口时报告缺口，保留原稿与范围，不硬编码私人依赖。
先读取本轮或工作区启动规则明确登记的作者写作配置入口；同一作者的普通写稿与上游编排共用该入口。沿入口准备本次意图／原话／反馈、唯一当前 DNA、匹配表达方式的一至两篇授权全文范文，以及配置列出的少量相关改稿对照。持续授权有效且材料已完整读过时复用，不重新索取；不扫描未授权私人目录。读取配置与表达材料本身不要求启动选题、深筛或上游后台。

### `orchestrated_mode`

收到 `handoff_version`、`workflow_mode=orchestrated_mode` 和 `content_lock` 时，读取 [编排交接契约](references/orchestrated-handoff.md) 并校验信封。锁定单是路由与事实的唯一权威对象：

- 不重新判内容任务、内容类型、领域或格式；
- 不重复询问已确认事实、读者、CTA、角度或框架；
- 不把平台执行结果升级成作者确认；
- 冲突、缺字段、材料不足或局部修改越界时返回阻断信封。

### `standalone_mode`

没有有效上游 handoff 时读取 [创作者配置契约](references/configuration-contract.md)：

1. 读取本轮授权材料及工作区明确登记的持续授权作者配置，按配置准备上述四项表达材料；
2. 缺少最小配置或授权全文范本时，只交付缺口、素材盘点、必要问题和可选大纲；
3. 不搜索私人工作区补齐缺口，不把结构占位稿冒充个性化成稿；
4. 旧七类型输入只作兼容读取：工具→`problem-method`、角度→`judgment`、余韵→`scene-insight`；系统、人物、专论、实录须按材料明确选择，不能静默猜测。

用户可见交付只显示安全文档名或来源标签，不回显绝对路径、隐藏目录、临时目录或仓库位置。

## 2. 安全硬门

任何模式都读取：

- [证据与隐私](references/evidence-and-privacy.md)
- [论断范围](references/claim-scope.md)

执行优先级：本轮明确要求与授权 > 有效内容锁定单／工作区规则 > 作者配置与授权范本 > 通用建议。

不得编造场景、动作、原话、数字、心理、因果、适用范围、CTA 或发布状态。范本只校准句长、停顿、叙事距离、温度、颗粒度、留白和收尾习惯，不迁移范本事实、观点、比喻、金句、经历或 CTA。

材料不足时宁可缩短、标记待补或停止。第一人称事实锁定任务中，原稿是唯一事实词典；相邻两段不自动构成因果或转折。

## 3. 选择格式模块

只加载命中的一个格式模块：

| `article_format` | 模块 |
|---|---|
| `image-post` | [贴图短文](references/format-image-post.md) |
| `longform` | [公众号长文](references/format-longform.md) |

朋友圈或其他平台不由本 Skill 承担。`standalone_mode` 未明确格式时，根据交付物让作者确认；只做初始化或大纲时可以暂留格式候选。

当锁定单或 standalone 任务明确 `content_job=conversion` 时，额外读取 [转化文章结构](references/conversion-structure.md)。清晰编号、步骤或对照可以使用；“不机械套结构”不等于禁止有决策价值的结构。

## 4. 执行阶段

### 理解与试写

沿统一作者配置读完四项材料，用一两句话说明本篇真正想表达什么、对谁说。内部盘点人物、原话、时间线、核心判断、标题承诺、证据、隐私和未知项；含义不清先问，不补造心理。

长文默认先写约 300—500 字的完整试写段，含叙述、感受和转场，不局限开头。只使用素材已经提供的感受；不能为了满足试写形态编造感情。试写须与拟写全文的主线有关，附真正阻断的问题，等作者明确认可后展开。具体执行见 [试写与确认](references/sample-and-approval.md)。读取完 DNA 或自评通过不算认可。

作者只要大纲时交大纲。已有工作流的内容锁定、角度和框架确认继续有效，不重复索取；普通长文试写认可后不再增加一次抽象大纲确认。

### 执行作者的直接表达偏好

- 从本轮要求及已授权作者配置（工作区 USER 等）读取写作偏好，不在通用 Skill 中硬编码某位作者的私人资料。作者要求“直接表达，不作解释性辩护”时，执行以下步骤。
- 起草或改写时，把本人认可的素材自然写成经历、感受、判断和思考推进；用于帮助 AI 理解的澄清不自动成为正文里的定义、辩护、免责声明或适用范围说明。自然的因果推演、追问与思考转折应保留，不按关键词机械删句。
- 真正的事实、逻辑或含义缺口在正文外列出或提问，不靠解释腔掩盖，也不为消除争议擅自改掉原意。本人明确要求的分析、答疑或教学说明不受此项限制。
- **交付前检查**：对照原始材料与本轮授权，逐段检查 Agent 新增或改写的文字是否含未获要求的概念解释或观点辩护；发现后在授权范围内撤回新增内容或改为直接表达，再核对事实、观点力度、原话及冻结范围。作者原话不因含“是指”等词就被删改；只检查模式仅报告位置，不动正文。
- 本检查在试写段、局部改稿与完整正文交付前均执行；属于基本自查，不自动启动额外独立审核，不替代 Skill 原有核源及授权门禁。权限不足或原意未明时，保留原文并列待确认，不声称通过。

### 展开正文

沿被认可的表达意图和试写展开；认可不授权补新事实。一篇完成一个主要表达任务，主线可由多个经历或逐步形成的认识共同承担。一段可推进事件、认识或承接真实情绪，不能用信息增量限制作者节奏。

保持人物主线、指代与时间连续，让标题承诺有来源。材料不支持的情节或观点留缺口；术语首次出现照顾读者理解。只有任务需要且获授权才使用方法教学、产品和 CTA。贴图短文沿原格式模块，不强制长文试写。

### 交审稿与排版

保留初稿，按 [审稿交接](references/review-handoff.md) 交同版本正文、原始来源、四项表达材料、锁定范围、确认记录和已有审核回执。事实、声音和阅读体验由审稿入口独立判断；写作阶段不读取删改清单和评分表。已有审稿凭证仅对同一版本有效。

配置登记审稿入口的完整成稿默认交完整审稿；只检查或局部请求按原范围传递。若没有独立审核条件，正文标“待独立审稿”，不能声称已终审。写作过程仍须守住事实和原话，可用已有 `check_output_guards.py` 查事实状态、范围和 CTA，不加载审稿评分来预先写成高分模板。

进入 HTML 排版、手机预览或草稿回读时读取 [微信草稿排版与回读验收](references/wechat-layout-validation.md)。本 Skill 只规划图片位置、用途、来源、授权和脱敏要求，不自动找图、制图或发布。

## 5. 返回结果

`orchestrated_mode` 必须按交接契约返回，并真实填写 `actual_modules_loaded`。同一模块只列一次；未命中的条件模块不得读取或列入。

`standalone_mode` 按任务交付最小完整结果：

- 初始化：配置缺口、素材盘点、可选大纲和下一步；
- 大纲：唯一内容类型、核心判断、推荐结构、证据、风险和必要问题；
- 正文：标题候选、正文、待确认项、锁定差异和发布前验证；
- 试写：意图、试写段、实际材料读取记录和待认可状态；
- 局部改稿：传递并返回审稿入口的范围、结果及对照；
- 终审：门禁结果、阻断项和最小修复。

达到发布准备状态只表示 `ready-for-user-final-review`，不等于作者确认、已进草稿箱或已发布。本 Skill 不自动修改素材、配置、知识库、台账或平台数据，不发布、不发送。
