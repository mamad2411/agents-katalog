# README Engineering

## Use this skill when
- Authoring clear setup/usage docs
- Making projects approachable
- Improving adoption and onboarding

## Do not use this skill when
- API reference generation
- Marketing pages

## Instructions
1. Open with what the project is and the problem it solves.
2. Give install + quick-start that actually work (test them).
3. Document prerequisites, config, and environment setup.
4. Add usage examples with expected outputs.
5. Link deeper docs: architecture, contributing, API.
6. Keep badges factual; use screenshots sparingly.
7. Maintain a changelog link and status section.

## Checklist
- Commands verified working
- No assumptions about setup
- Structure conveys the value fast

## Output Format
- README outline | sections | verified commands

## Common Mistakes
- Broken copy-paste install commands
- Docs aimed at the author only
- Outdated “status” claims
