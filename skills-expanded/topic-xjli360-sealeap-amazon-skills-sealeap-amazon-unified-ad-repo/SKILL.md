# SeaLeap 亚马逊一体化广告报表分析

先写出要回答的问题和“一行数据是什么”，再选择维度、指标与比较方式。任何预算判断都建立在可对账的数据上。

## 输入

广告账户/品牌、站点和币种、广告产品、分析问题、稳定 ID、报告字段字典、流量/转化日期口径、时区、归因窗口、覆盖期、原始基础量及变更记录。

## 工作流

1. 选择一个主要问题：全账户扫描、广告产品比较、广告位、搜索词承接、推广 SKU 或达成转化商品。明确行粒度及唯一键。
2. 依账户、国家、广告产品和 campaign 筛选，保留稳定 ID 与必要基础指标。名称仅用于展示，不能代替跨期关联键。
3. 检查字段兼容性和可加性：不同币种分开；销售总计与推广/光环分项不重复加；转化商品维度不承载重复的点击和费用；展示份额不跨活动求和。
4. 先汇总可加的曝光、点击、花费、购买和销售，再重算比率。区分总购买率、点击购买率、订单与件数；Null 保留原因，不能一律变 0。
5. 按活动使命解释表现，分别看规模、效率、探索、新客与召回。受众是可能跨广告产品的维度，不能和 SP/SB/SD 当成互斥分类相加。
6. 将问题从国家/产品下钻到 campaign、placement、target 和 search term。低花费高 ROAS 先检查样本及可扩容量，高花费低 ROAS 先解释流量和承接。
7. 以当地报告时区建立等长成熟窗口，排除变更日，使用投放 ID 关联实际变更，检查二次调整和其他污染；无法对齐则不宣告因果。
8. 固化模板与迁移清单。报告排期、邮箱发送和外部创建需处于用户明确授权的范围；先交付可审阅设置。

## 交付

报告设计和字段字典、覆盖/对账审计、重算指标、使命与活动分层、搜索词承接表、实验窗口、动作草案和旧报告迁移状态。

## 证据与执行范围

- 材料中的案例、比例和时间表标为 `COURSE_BASELINE` 或 `TRAINING_CASE`；来源与口径已核验的店铺数据标为 `ACCOUNT_FACT`，用户转交但未核验的数据标为 `USER_PROVIDED`，合成练习标为 `SIMULATED`。推断标为 `HYPOTHESIS`，缺失项写 `UNKNOWN`，不补成 0。
- 先固定店铺、广告 profile、站点、ASIN、币种、数据窗口与归因口径。课程介绍的资格、界面、报告字段和功能覆盖在实际使用时核验。
- 默认交付诊断与草案。真实写入只在当前会话已授权的对象、动作和预算内执行，并保存旧值与回读结果；新增范围先取得授权。
