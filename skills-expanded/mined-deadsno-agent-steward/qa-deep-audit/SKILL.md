## Правило верификации находок

Прежде чем фиксить находку — воспроизведи её:

- **Тест (мутация):** сломай код → запусти соответствующий `test-*.mjs` → тест должен упасть. Puis верни код и тест снова зелёный.
- **JS/TS:** `npm run build` (tsc) + `npm run lint` + реальный прогон `npm test`.
- **Данные:** запрос к файлу/БД, не к памяти. Для SQLite — `SELECT` из файла `.sqlite`, не из инстанса в памяти.
- **MCP:** вызывай инструмент через агентскую сессию, проверяй `success`, `error`, `actor` в аудите.
- **GUI/дашборд:** проверяй через Playwright или вручную — нет сырых `gui.*`, нет обрезаний, нет переполнения на 360–820 px.

Если не можешь воспроизвести — находка не подтверждена, в отчёт идёт со статусом «требует верификации».

Не «починил бы» и не «добавил бы проверку на всякий случай» — сначала воспроизвёл.

## Что проверять

- Какие MCP-инструменты (из 30) не имеют отдельного автотеста?
- Какие RPC-методы (из 57) не покрыты тестами дашборда?
- Есть ли тесты на:
  - `src/core/router/planner.ts` → `test-planner.mjs`
  - `src/core/matrix.ts` → `test-matrix*.mjs`
  - `src/core/schedule-v2.ts` → `test-schedule-v2.mjs`
  - `src/db/tasks-repo.ts` → `test-agent-tools.mjs`, `test-task-status.mjs`
  - `src/core/ps-wrapper.ts` → `test-ps-watchdog.mjs`
  - `src/core/lock.ts` → `test-lock-format.mjs`, `test-stale-lock.mjs`
  - `src/notifications.ts` → `test-notifications-v2/v3.mjs`

### 2. Edge cases

- Пустой массив задач / пустая история
- Один элемент (одна задача, один клон матрицы)
- Null/undefined в полях `prompt`, `schedule`, `workspaceId`
- Очень длинные строки (имя задачи 256 знаков, лимит 209; промпт >100 КБ)
- Очень большие числа (`retryCount`, `concurrency`)
- Спецсимволы (кавычки, `&`, `;`, `<>`, кириллица в имени и промпте)
- Кириллица + латиница в одном поле
- `runAt` в прошлом; `cron` невалидный (`61 * * * *`)
- `dependsOn` с несуществующей задачей (`ghost`)
- Цикл в DAG (A→B→A)

### 3. Обработка ошибок MCP и RPC

- `schedule_task` без обязательных полей → ошибка схемы, задача не создана
- `run_task_now` на несуществующую задачу → читаемая ошибка «задача не найдена», без stack trace наружу (QA-P3.6)
- `matrix_control(results)` на не-матрицу → `success:false`, ошибка «не является матрицей» (QA-P3.7)
- `pause_task`/`resume_task` для несуществующей задачи → не выставлять противоречивое `paused` (QA-P3.8)
- `update_task` с некорректным cron → откат, `restored: true` (S02.1.12)
- Битый JSON при импорте шаблонов/задач → понятная ошибка, БД не изменена

### 4. Обработка ошибок HTTP API дашборда

- `GET /api/tasks`, `/history`, `/metrics`, `/summary` → валидный JSON, коды 200
- Неизвестный путь → 404 без stack trace
- `POST /api/hooks/:name` с неверным токеном → 401/403
- Тело > `maxBodyBytes` → 413, без падения сервера

### 5. Офлайн / устойчивость

- Убить процесс во время запуска → запись помечена `error/interrupted`, lock снят через TTL (S03.1.BP.1)
- Повторный старт после краша → плагин стартует, история читается (S15.1.5)
- Параллельное чтение/запись SQLite → нет `database is locked` (WAL)
- Ollama недоступна, mode auto → работают правила, уведомления не блокируются (fail-open, S09.2.4)

### 6. Валидация форм GUI

- Обязательные поля: `name`, `schedule`, `prompt`
- Формат cron, `timezone`, `notBefore/notAfter`
- Длина имени задачи (лимит 209)
- Понятные ошибки на русском и английском

### 7. Обработка состояний

- Loading / Empty / Error / Success в GUI и дашборде
- Пустая история → нули/пустые состояния без `NaN` и `undefined` (S08.1.6)
- Матрица: partial, все упали, stuck → уведомления (S09.1.8)

### 8. Кроссбраузерность (теоретически)

- Chrome, Firefox, Safari, Edge — дашборд и GUI OpenCode

### 9. Безопасность

- XSS — экранирование при вставке в дашборд (проверка `test-dashboard-xss`)
- Секреты: `manage_secrets` — значения не возвращаются, в логах/аудите замаскированы `***` (S10.1.4)
- Инъекции: имя задачи `'; DROP TABLE` → экранировано, БД цела (S10.1.9)
- allowedTools/deniedTools → вызов блокируется (S10.1.5)
- HTTP API без аутентификации для записи → требуется защита (D14.4.BP.1)

### 10. Локализация (ru / en / zh)

Проверять в трёх локалях: `ru` (по умолчанию), `en`, `zh`. Ключи locais в `locales/{en,ru,zh}.json`, паритет через `test:i18n`.

- Нет кириллицы в интерфейсе `en`/`zh` (кроме данных)
- Все строки меняются при переключении ru ↔ en ↔ zh без рестарта (S14.1.5)
- Нет сырых ключей `gui.*` в любой локали (S14.1.2)
