# init-mem — 记忆体系约束与检查

## Overview

约束 `.codebuddy/memory/` 下自定义记忆文件的**结构、命名、格式与内容边界**，保证体系一致、可维护、可蒸馏。只管理非官方记忆体系（`memory/`），不管理官方机制（`rules/`、`CODEBUDDY.md`）。

**本文件只写硬性要求与流程；细节一律以 `references/` 为准**：`structure.md`（结构与格式详规）、`checklist.md`（可执行检查清单 A~I）、`boundary.md`（内容边界）、`CHANGELOG.md`（体系演进记录）。

## 触发时机

- 新增 / 修改 `memory/` 下任何文件，或写入工作日志（`memory/pro_<简称>/logs/YYYY-MM-DD.md`）
- 执行蒸馏（生成 / 刷新 `MEMORY.md`）
- 素材（项目描述 / 画像）**关键内容**实质变化 → 实时蒸馏（v0.18）
- 用户说："记录 XX 到记忆""更新项目描述""更新用户画像""蒸馏记忆""检查记忆体系 / 检查记忆 / 检查记忆格式"
- 用户说："创建项目 XX / 创建新项目 XX"（见"新项目初始化"）、要求迁移项目记忆

## 六项工作（v0.10 确立）

### 1. 蒸馏 AI 记忆
- **实时蒸馏（v0.18，硬性）**：关键内容——项目定位 / 技术栈 / 架构 / 关键约定等关键事实、用户协作要点等关键特质、体系规则——实质变化时**立即**刷新 `MEMORY.md`，不等用户要求；常规日志追加不单独触发（随下次蒸馏纳入）
- **维护例外（v0.16）**：版本升级 / 规则修订 / 检查修正等体系维护完成后自动刷新
- 读取**全部**素材（`PROJECT.md` + `PROJECT_*.md`、`PROFILE.md` + `PROFILE_*.md`、`logs/`）→ 去重 / 压缩 / 提炼
- 刷新头部：蒸馏时间 / 依据文件清单（含扩展文件）/ 状态标记

### 2. 维护用户画像（`PROFILE.md` 及扩展）
- `PROFILE.md` 为**必备组件（硬性）**：必不为空、必不省略，缺失即不合规；创建 / 校验时必确认其存在且非空
- 内容＝用户特质（思考链路 / 处事习惯 / 性格 / 母语，**四要素为软性框架**：有则记、无则缺）；扩展文件 `PROFILE_<主题>.md` **仅放用户特质**，坑点 / 编码规范归 rules / skills
- **仅用户明确要求时更新**；观察到新特质**直接丢弃**，不自动记录（v0.15）

### 3. 维护项目信息（`pro_<简称>/PROJECT.md` 及扩展）
- 内容**必须含四要素**：项目概述 / 项目技术栈 / 项目架构 / 项目模块；模块明细量大时拆 `PROJECT_<主题>.md`
- 只写客观事实，不混入用户偏好与过程记录

### 4. 校验合规性
- 对照 `references/checklist.md` 逐项检查：结构 / 命名 / 格式 / 内容边界 / 同步状态
- **完整检查仅用户明确要求时触发**；检查对象为**全部** `pro_<简称>/` 文件夹，全部合规才交付（v0.17）

### 5. 澄清修正
- 发现不合规：**先交流澄清**（问题 + 方案）→ 达成共识后再改
- **禁止未经确认直接改动用户已有内容**

### 6. 命名确认（项目文件夹）
- 创建 / 校验前**必须向用户确认项目名称并缩略为简称**（可推断但须确认；无法推断则询问，不擅自猜测），简称即 `pro_<简称>/`，**必不为空、必不省略**，未获确认前不得创建 / 校验项目描述文件
- 扩展文件主题后缀（`PROJECT_<主题>.md` / `PROFILE_<主题>.md`）同样须询问用户确定

## 新项目初始化（v0.12）

用户说"创建项目 XX / 创建新项目 XX"时：

1. **确认信息**：项目名称 + 简称（未确认前不建文件夹）
2. **建文件夹**：`memory/pro_<简称>/`，内含 `logs/` 子目录
3. **建 `PROJECT.md`**：有代码仓库 → 用 code-explorer 提炼完整四要素；无代码 → 骨架占位（架构 / 模块标"待补充"）；头部含 `# 标题` / `- 更新日期` / `- 状态`
4. **记初始化日志**：`pro_<简称>/logs/YYYY-MM-DD.md`（创建过程、PROJECT.md 来源、待办）
5. **蒸馏同步**：优先按 v0.18 **实时蒸馏**刷新 `MEMORY.md`（无法即时执行时才标 `⚠ 需重新蒸馏`）；蒸馏须汇总全部项目素材

## 多项目协同（v0.13~v0.23）

- **当前操作项目**：按工作区目录 / 项目特征自动推断；仅一个项目文件夹时默认其为当前项目（不反复询问）；多项目且无法推断时**每次询问**，不擅自猜测
- **`MEMORY.md` 组织**：按项目分节——公共节（体系规则 / 用户协作要点）+ 每项目一节（定位 / 架构 / 关键约定）
- **扩展文件拆分**：明细明显偏大时 AI **主动提议**，后缀经用户确认后才拆
- **日志归属（v0.23，v0.29 收敛）**：只记**与具体项目相关**的工作 → 该项目 `logs/`；**体系维护类不记日志**（skill / rules 调整、记忆体系检查与维护、画像维护——**其痕迹如何记录由对应 skill / rules 自身机制决定，不属本 skill 管理范围**）；难以归属的其它工作 → 当前操作项目 `logs/`
- **版本冻结**：由用户明确宣布冻结 `v1.0`，AI 不主动提议
- **不做停维护归档**：`memory/archive/` 不建立（v0.14）

## 迁移与宽限（v0.20 / v0.25 / v0.26）

**存量迁移**＝移动 / 重命名 / 改写既有记忆文件的**位置或格式**；**宽限**＝对历史文件豁免现行格式要求。
**项目记忆迁移**＝项目级：① 文件夹改名 / 简称变更 ② 跨仓库 / 跨工作区搬迁 ③ 合并 ④ 拆分。

- **必须用户确认（硬性）**：两类迁移与宽限的**是否执行、对象范围、方式**一律**先提案 → 用户确认 → 才执行**；未获确认保持原状（仅可记待办）
- **禁止自行处置**：不得自行迁移、不得自行判定宽限；不得以"规范要求 / 保持一致 / 更优做法"为由绕过确认
- **提案必含四项**：清单（原路径 → 目标路径）、方式（改名 / 复制 / 移动 / 合并 / 拆分 / 改写）、是否改动内容、理由（宽限须附对象与理由）
- **旧记忆任何文件不动**：原文件**不改写、不移动、不重排**，仅作**蒸馏的事实依据**；旧位置文件一律保留，删除 / 覆盖须单独确认
- **产物**：由原项目记忆蒸馏后**严格按格式形成 `PROJECT.md`**（四要素 + 头部元信息齐全），不照搬旧文件；`MEMORY.md` 由蒸馏重建，不手工搬
- **宽限范围**：仅按确认范围适用；新增 / 扩大 / 收紧需再次确认；**不得跨项目自动推广**
- **不记录**：迁移与宽限执行后**不写项目日志、不登记 `CHANGELOG`**
- **停维护项目**：不归档、不删除、不迁移
- 完整条款见 `references/structure.md`（④ 与"项目记忆迁移"节）、`references/checklist.md` I 节

## 体系结构（当前版本 v0.29）

```
.codebuddy/memory/
├── MEMORY.md                # ① 蒸馏记忆：每次对话必加载（仅由蒸馏产生，禁止直接追加）
├── PROFILE.md               # ③ 用户画像（必备组件，必不为空；四要素为软性框架）
└── pro_<简称>/              # ② 项目描述 + ④ 工作日志（简称须用户确认，必不为空）
    ├── PROJECT.md           # ② 四要素：概述 / 技术栈 / 架构 / 模块
    ├── PROJECT_<主题>.md    # ② 扩展主题文件（可选，后缀须用户确认）
    └── logs/YYYY-MM-DD.md   # ④ 工作日志（append-only，条目 `- [HH:MM] 主题：内容`）
```

- **命名要点**：核心文件英文固定名、**不用数字编号前缀**；文件名不含空格与 `\ / : * ? " < > |`；扩展文件为 `主名_后缀.md`（英文后缀首字母大写组合，如 `AiCorrections`）；扩展文件须在 `MEMORY.md` 索引登记
- **数据流（单向）**：素材（②③④）→ 蒸馏 → ① `MEMORY.md`；素材关键内容变化 → 实时刷新，一般变更 → 标 `⚠ 需重新蒸馏`
- 完整命名规范、各文件格式要求见 `references/structure.md`

## 检查流程

创建或修改记忆文件时按序执行，逐项对照 `references/checklist.md`：

1. **画像**：`PROFILE.md` 存在且非空（缺则必须创建）；内容仅用户特质
2. **当前项目**：确认 `pro_<简称>/`（简称已获用户确认，必不为空）；支持多个项目文件夹
3. **项目内容**：`PROJECT.md`（四要素）与 `logs/` 必须齐备
4. **蒸馏记忆**：`MEMORY.md` 存在；**禁止直接编辑**（新信息先入素材 → 蒸馏）；头部含时间戳 / 依据清单 / 状态标记
5. **边界与格式**：对照 `references/boundary.md` 核对归属；编码规范 / 检查点 / 坑点归 `rules/`（不属本 skill 管理），❌ 不入 memory；日志 append-only，不改历史条目
6. **同步标记**：关键内容变化 → 实时蒸馏；一般变更 → 标 `⚠ 需重新蒸馏`；蒸馏后清标记 + 刷新时间戳

## 持续更新状态

- 本 skill 与记忆体系处于**持续演进阶段**（版本见 `references/CHANGELOG.md`），尚未固定
- 发现体系缺陷或更优做法 → 更新 references 并登记 `CHANGELOG`；用户确认稳定后冻结 `v1.0`
