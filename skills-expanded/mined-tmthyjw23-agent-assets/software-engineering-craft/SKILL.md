# Software Engineering Craft

The durable knowledge under any particular stack.

## When to use
- Studying fundamentals for interviews or growth.
- Choosing a programming paradigm or language.
- Learning SQL/algorithms/data structures.
- Planning a learning roadmap.

## Paradigms
- Imperative, functional, object-oriented, declarative, logic, event-driven,
  concurrent, aspect-oriented (top 8).
- Tradeoffs: mutation vs immutability, inheritance vs composition, pure vs
  side-effecting.
- OOP pillars: encapsulation, abstraction, inheritance, polymorphism.

## Data structures & algorithms
- Daily structures: array, hash map, tree, heap, graph, queue, stack, set.
- Big-O reasoning; when the constant factor matters.
- Interview algorithms: complexity analysis, sorting/searching, graphs,
  dynamic programming, concurrency primitives.
- Language internals: C++ (compile, manual memory), Java (JVM, GC, collections),
  Python (interpreter, GIL), WASM for browser execution.

## SQL & data literacy
- Logical query order (FROM → WHERE → GROUP → HAVING → SELECT → ORDER → LIMIT).
- Joins, aggregation, window functions, indexing awareness.
- Learning path by role (analyst vs backend vs data engineer).

## Career & resources
- Junior → senior: ownership, communication, design, mentoring, impact.
- Curated books/engineering blogs; standards every dev should know.
- Full-stack roadmap; green languages/energy awareness.

## Checklist
- [ ] Paradigm/language chosen for the problem, not habit.
- [ ] Complexity of hot algorithms understood.
- [ ] Right data structure for access pattern.
- [ ] SQL written with index/sargability in mind.
- [ ] Continuous learning plan (books/blogs/practice).

## Common pitfalls
- Cargo-culting paradigms.
- Ignoring complexity until it bites at scale.
- Using the wrong data structure (lists for lookups).
- Not understanding the language runtime (GC, memory model).
- Learning tools without fundamentals.
