# Micro-Habit Progressive Disclosure for Developer Onboarding

## Concept
Combine micro-habit formation science with progressive disclosure UX patterns to design IDE onboarding that forms lasting developer behaviors without overwhelming cognitive load.

## Research Foundation
- Micro-habits reinforce synaptic efficiency, enhancing cognitive resilience and sustained attention span
- Progressive disclosure shows information as needed, minimizing initial cognitive load
- The Hook Model (Trigger → Action → Variable Reward → Investment) creates habit loops when applied ethically
- Developers experience 24% perceived productivity boost with AI tools, but only when cognitive load is managed

## Core Mechanism
Instead of dumping all features at once, the IDE introduces one micro-capability per session:

1. **Trigger**: Contextual cue (e.g., "You just saved a file — try auto-formatting with Cmd+Shift+F")
2. **Action**: Single keystroke or click (low friction)
3. **Variable Reward**: Sometimes the action reveals a hidden capability, sometimes a simple confirmation
4. **Investment**: The developer's custom config grows slightly, increasing return motivation

## A-Coder Application
- Day 1 onboarding: Only show file explorer + editor + save
- Day 2: Introduce version control sidebar after first save
- Day 3: Surface AI assistant after 10 manual edits
- Each feature introduced through contextual trigger, not tutorial list
- Developer builds "muscle memory" before next feature unlocks

## Be Practical Application
- Playbook chapter: "The 7-Day IDE Habit Stack"
- Each chapter corresponds to one micro-habit
- Readers implement one behavior per day
- Avoids the "tutorial fatigue" that kills tool adoption

- **Practical implementation**: Each pattern is immediately testable
