# Mx-Shell 电影导演工作流

把模型当作需要理解意图的摄影与表演伙伴，而不是逐条执行参数的渲染器。人负责故事任务、情绪、因果、阶段边界和验收；模型负责阶段内部的构图、动作细节与镜头探索；后期负责把候选素材组织成连续电影。

## 开始前

1. 读取用户提供的故事、已有脚本、角色图、场景图和失败样片。
2. 若任务涉及脚本、分镜或提示词，必须读取 [references/three-layer-prompt-structure.md](references/three-layer-prompt-structure.md) 和 [references/script-logic.md](references/script-logic.md)。
3. 若需追溯 Mx-Shell 方法来源、参考资产、候选生成或后期细节，读取 [references/method-map.md](references/method-map.md)。
4. 将本 Skill 作为独立导演能力使用；不要要求特定项目编排框架、画布或视频模型。平台选择只影响执行参数。
5. 不复刻《丧尸清道夫》的角色、世界观或完整提示词；迁移方法，形成原创表达。

## 一、先写导演意图卡

使用 [assets/cinematic-scene-brief.md](assets/cinematic-scene-brief.md) 建立以下事实：

- 故事任务：这场戏改变了什么；
- 观众体验：观众依次应该感到什么；
- 主体、时间、地点和场景初始状态；
- 触发事件、动作因果链和场景结束状态；
- 视觉与声音基调；
- 不可丢失的硬约束；
- 可以交给模型探索的软变量；
- 与前后镜头连接的入点和出点。

如果“故事任务”或“状态变化”说不清，先停在意图层，不要直接堆镜头术语。

## 二、把场景写成因果阶段

按状态变化分段，不按平均时长机械切镜：

1. 建立处境；
2. 异常或欲望出现；
3. 角色因其采取行动；
4. 环境或对手作出反馈；
5. 结果改变角色、关系或世界；
6. 留下可进入下一镜的视觉或动作出点。

每个动作都回答三个问题：发生什么、为什么发生、它要让观众感到什么。删除既不改变状态、也不传达信息或情绪的动作。

## 三、只控制必要的镜头层

按重要性从高到低控制：

1. 场景阶段和各阶段大致比重；
2. 主体进入、冲突和退出画面的方式；
3. 必要景别与运镜意图；
4. 动作方向、空间轴线和光线方向；
5. 构图或焦段参数。

高速运动、群体调度和复杂动作通常控制到第 3 或第 4 层，避免同时锁死构图。只有构图本身承担叙事信息时才精确规定。把技术动作翻译成观众体验，例如把“缓慢推轨”写成“视线不可避免地靠近，使异常感逐步压住人物”。

## 四、组织生成提示词

严格按 [三层电影提示词结构](references/three-layer-prompt-structure.md) 确认信息齐全，再输出自然语言；不强制保留字段标签：

1. 基础设定：时间、地点、主体、身份和参考图角色；
2. 氛围与画质：视觉核心、真实质感、色彩影调和总体情绪；
3. 画面内容：单镜头或多阶段、时间比重、动作因果、必要景别、构图与运镜、结尾状态；
4. 声音边界：现场声、同步音效、对白、音乐和字幕是否后置；
5. 少量硬限制：只保留高风险且模型常犯的错误。

不要输出同义形容词堆叠、互相冲突的镜头指令、无法同时满足的物理细节或长串“不要”。

## 五、最小化参考资产

- 主角和跨场景核心道具使用角色卡或多视角资产；
- 表情、状态或服装承担剧情时，单独提供状态参考；
- 次要人物和普通道具只在确实漂移时补参考；
- 场景优先提供一张能说明空间和视觉基调的大全景；
- 在提示词中说明每张参考图是什么、要锁定什么；不要假设模型自动理解；
- 不为所有资产无差别制作三视图，避免参考相互争夺注意力。

## 六、以候选池而非单次成片工作

1. 先用低成本设置生成同一方案的多个候选；
2. 按“因果可读、动作可信、空间清楚、情绪有效、可剪辑”筛选；
3. 允许只取候选的前半段、后半段或一个动作；
4. 失败后先判断缺的是意图、因果、资产还是模型随机性，再决定改词或重抽；
5. 不把一次成功偶然当成稳定能力。

## 七、为剪辑设计入点与出点

优先保留：

- 相同运动方向；
- 相近主体位置和视线方向；
- 可接续的转身、起跳、挥击、跌落或遮挡；
- 一致的太阳、阴影和空间轴线；
- 可通过局部变速、镜像、裁切和调色修复的片段。

后期可以修复节奏、色温、亮度和轻微空间跳变，不能修复核心因果缺失、角色身份崩坏或关键接触失败。

## 交付格式

默认交付五部分：

1. **一句话导演判断**：当前方案最需要解决的问题；
2. **导演意图卡**；
3. **场景脚本**：连续自然语言，先故事与动作因果，后必要镜头意图；
4. **生成包**：参考资产清单、模型提示词、硬限制和建议候选数；
5. **剪辑合同**：入点、出点、运动方向、声音桥和不可接受项。

若用户只要求其中一项，只交付所需部分，不强行扩展整套流程。

## 质量门

交付前逐项检查：

- 不看解释也能明白人物为何行动；
- 每个阶段都改变信息、情绪或状态；
- 镜头语言服务于表达，而非展示术语；
- 硬约束足够少且可同时满足；
- 模型知道参考图各自承担什么角色；
- 结尾提供明确的剪辑出点；
- 没有把“电影感”当作空洞形容词；
- 没有把作者公开分享误写成可复制的完整秘方。
