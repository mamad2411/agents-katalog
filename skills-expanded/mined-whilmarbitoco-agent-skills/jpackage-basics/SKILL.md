# jpackage Basics

`jpackage` (Java 14+) packages a modular Java application into a native
installer. For POS this means shipping a JavaFX app without requiring
the end-user to install a JRE.

## Concepts

- **Module mode** — requires `module-info.java`; jpackage resolves the
  module graph from the module path.
- **`--runtime-image`** — generated by `jlink` with only the modules the
  app needs (smaller download).
- **`--input` / `--dest`** — input JARs and output directory for the
  installer.
- **Module-path vs class-path** — all dependencies must be modularized or
  placed on `--module-path`.

## Rules

1. `module-info.java` must `requires` every used module including
   `javafx.controls`, `javafx.fxml`, and `java.sql`.
2. Configure `maven-jlink-plugin` or invoke `jlink` before `jpackage` to
   produce a trimmed runtime image.
3. Pass `--icon`, `--vendor`, `--app-version` for every target platform.
4. Test the packaged app on a clean VM without a JDK installed.
5. Omit `--win-console` (present = enables console, absent = no console) / use `--linux-shortcut` / `--mac-package-identifier`
   for platform-appropriate defaults.
