# Evidence and knowledge access

Start from the user's information need and authority, then choose the smallest source that can answer it. A file, SQL query or existing search API may be enough; owning documents and running an index are separate product responsibilities. The component owns the lineage, visibility, freshness and truthful result of an evidence read. The harness decides the next step, the action boundary enforces access, and context management decides how admitted evidence enters a model call. A shared process or store does not merge those contracts. Read the [architecture](../agent-system-engineering/references/architecture.md) and [flow 5](../agent-system-engineering/references/system-flows.md#5-knowledge-grounded-answer) when tracing the complete handoff.

**Scope.** Use this skill to design, build, debug or review the agent system named by the current task. Component rules describe that target system; reading routes and engineering procedures guide your work on it. This separates product requirements from session instructions: actions remain governed by the current task and permissions, including when your own agent or harness is the target.

## Evidence and knowledge instinct map

Choose by the evidence the answer needs and the latency the caller can bear; qualify the trade-off before adding another retrieval stage.

For capability design or problem-solving with a human counterpart, first use supported research or established practice to describe effective human performance, connect it to an option/check, and test transfer against agent differences; carry over only applicable human limits and label unsupported explanations as hypotheses; skip routine use and purely technical mechanisms without a counterpart ([design rule](../agent-system-engineering/references/engineering-process.md#design)).

| Need | Lever and trade-off | Build it as |
|---|---|---|
| The source is already identified. | **Exact read** avoids ranking loss and index work, but needs the right locator, authority and version; read it before searching broadly. [Depth](references/retrieval-and-grounding.md#retrieval-family-trade-offs) | Read tool function taking a scoped locator and returning versioned source content. |
| Find a fact quickly across many documents. | **Plain hybrid chunk retrieval** offers a relatively small build and bounded query path, but hands the model disconnected top-k evidence and can miss qualifiers as candidates compete; start here for local discovery and retain body reads. [Depth](references/retrieval-and-grounding.md#retrieval-family-trade-offs) | Ingestion job building lexical and vector indexes; fused-search tool function. |
| Explain connections or themes across the collection. | **Graph-based retrieval** buys linked relations and global structure at extraction, identity-resolution and maintenance cost; use when those needs justify it, and measure local versus global query latency separately. [Depth](references/retrieval-and-grounding.md#retrieval-family-trade-offs) | Entity/relation extraction job and graph store; traversal query function. |
| The first results still leave a specific question open. | **Agentic search** can follow new leads beyond the first hits, but scans and sequential model rounds cost money and user waiting time; require expected evidence progress, not repeated paraphrases or an exhaustive-search promise. [Depth](references/retrieval-and-grounding.md#retrieval-family-trade-offs) | Bounded search/read agent loop with frontier state and explicit stop checks. |
| Answers need connected detail without searching from scratch. | **Linked wiki plus hybrid discovery** combines quick entry points with coherent body reads and bounded traversal; pay link/index upkeep and extra reads only where this improves the flat baseline. [Depth](references/retrieval-and-grounding.md#retrieval-family-trade-offs) | Linked document store and hybrid index; body-read tool with bounded link traversal. |
| Useful evidence appears below irrelevant hits. | **Reranking** can improve order and no-match signals, but adds latency, spend and false-negative risk; establish candidate recall first, because it cannot recover missing candidates. [Depth](references/retrieval-and-grounding.md#retrieval-family-trade-offs) | Reranker function between candidate retrieval and result selection. |
| The answer loses exceptions or the input is too large. | **Context allocation and projection** buy headroom at possible detail loss; deduplicate and retain useful complete spans first. Rewriting replayed evidence may lose affected cache reuse, while selection calls and re-reads add user wait and operator spend; compare total route cost and required-fact retention before pruning. [Depth](references/retrieval-and-grounding.md#retrieval-family-trade-offs) | Result-selection function applying deduplication and budgets before tool-result projection. |

## Choose what to read

- Read [evidence and knowledge access](references/evidence-and-knowledge-access.md) first for source selection, authority, visibility, freshness, absence versus unavailability, citation, provider qualification and build/debug checks. It is the instructional home for this component.
- Read [corpus lifecycle](references/corpus-lifecycle.md) only when the product owns source ingestion, updates, withdrawal or deletion. It covers source identity, parsing, version promotion, asynchronous work, stale writers and derived data. A synchronous corpus need not adopt queues or model-authored metadata.
- Read [retrieval and grounding](references/retrieval-and-grounding.md) when a query must discover or select evidence or provide an agent-facing handoff. It covers per-need outcomes, scoped reads, revision consistency, selection and ranking options, budgets, and evaluation.

## Route the work

1. **Design or plan:** write the question, source owner, principal, allowed resources, freshness and evidence needed to decide. Compare direct reads, an existing search API and an owned corpus by the pressure that justifies each. Write an explicit failure and omission contract before choosing an index.
2. **Build:** establish verified authority and source identity, then retrieve or read under that scope. Preserve a stable source version where exact citations matter. Return usable evidence alongside partial failures and omissions; a failure is not an empty successful read. If the corpus is owned, implement its actual mutation and deletion responsibilities before making its derived index authoritative.
3. **Debug:** follow one need through source content, selection, hydration, context admission and the answer. A missing source fact points to extraction or upstream coverage; a fact present in a body but missing in the answer points to selection, budget or use. Check scope, version and errors at the first divergence.
4. **Optimize:** measure the binding latency, recall, context or cost problem on a versioned representative workload. Compare candidates with the same baseline and frozen fact-loss and safety conditions. A model reranker, projection, cache or vector service adds a new failure and cost surface; introduce it only when evidence justifies the trade-off.
5. **Review:** test foreign identities, revoked content, concurrent version changes, unavailable sources, ambiguous empty results, citation support and required qualifiers. Inspect actual output and source provenance; a source name or high score does not establish entailment.

## Boundary reminders

Authority and privacy are cross-cutting: [authority and approval](../agent-trust-and-privacy/references/authority-and-approval.md) governs who can act, and [untrusted content and injection](../agent-trust-and-privacy/references/untrusted-content-and-injection.md) governs source text. A model can propose a lookup but cannot grant itself scope. A citation shows a basis, not permission to use the source. The owner of an effect must independently enforce authorization.

The [context chapter](../agent-context-and-state/references/context-and-state-management.md) owns request admission, size and provenance after evidence is returned. The [execution host](../agent-runtime-and-interaction/references/execution-host-and-lifecycle.md) owns deadlines and liveness; [durable recovery](../agent-runtime-and-interaction/references/durable-execution-and-recovery.md) owns worker claims when asynchronous ingestion is justified. [Diagnostics and evaluation](../agent-diagnostics-evaluation-and-resource-control/references/diagnostics-evaluation-and-resource-control.md) owns measurement, and [scenario evaluation](../agent-diagnostics-evaluation-and-resource-control/references/scenario-evaluation-and-experiments.md) owns comparison policy. The [model boundary](../agent-harness-model-and-tools/references/model-boundary.md) owns provider request and response fidelity. Open the relevant sibling only for that responsibility.

A search result may be irrelevant despite a high rank, and an empty result is scoped to the query, visibility and limits of that attempt. An inaccessible or timed-out source is unavailable. Answer only the part supported by available evidence, preserve exceptions, and name the unresolved part. State a negative conclusion only as broadly as an authoritative source and a complete-enough read support it.
