# Agent observability, evaluation and resource control

Start with [diagnostics, evaluation and resource control](references/diagnostics-evaluation-and-resource-control.md). It establishes the minimum evidence for a run, chooses logs, traces, a ledger or an evaluation harness by pressure, and provides a diagnosis path. Treat these as responsibilities, not required services. Start with the smallest evidence that can answer the actual question, and state what it cannot establish.

**Scope.** Use this skill to design, build, debug or review the agent system named by the current task. Component rules describe that target system; reading routes and engineering procedures guide your work on it. This separates product requirements from session instructions: actions remain governed by the current task and permissions, including when your own agent or harness is the target.

Read [execution tracing](references/execution-tracing.md) for identifiers, span and attempt cardinality, cross-process correlation, privacy before export, safe reader semantics and trace-to-cost coverage. Use it when a run cannot be reconstructed from simpler records, when links are missing, or when a trace appears to contradict another evidence plane. A missing span is not proof of a missing action.

Read [cost accounting](references/cost-accounting.md) when paid operations need attribution, reconciliation or limits. It distinguishes an attempt identity reservation from a monetary hold, and known spend from unknown liability. Start with a provider report if that suffices; require a ledger or atomic hold only under the relevant completeness or hard-cap pressure.

Read [scenario evaluation and experiments](references/scenario-evaluation-and-experiments.md) when a behavioral decision requires representative scenarios or a probabilistic comparison. It covers production-equivalent state, saved artifacts at every stage, validated deterministic counters, semantic graders, a frozen comparison and stop policy, and separate comparison and advancement verdicts. Validate the grader on saved outputs before paid work and preserve incomplete cells and unresolved liability.

For cross-component flow and component ownership use the [course architecture](../agent-system-engineering/references/architecture.md), [system flows](../agent-system-engineering/references/system-flows.md) and [engineering process](../agent-system-engineering/references/engineering-process.md). The [execution host](../agent-runtime-and-interaction/references/execution-host-and-lifecycle.md) owns liveness and terminal decisions; the [model boundary](../agent-harness-model-and-tools/references/model-boundary.md) owns request and response semantics; the [action boundary](../agent-harness-model-and-tools/references/action-and-tool-boundary.md) owns effect authorization and truthful results; [context and state](../agent-context-and-state/references/context-and-state-management.md) owns continuity and state; [knowledge access](../agent-evidence-and-knowledge/references/evidence-and-knowledge-access.md) owns source visibility and grounding. [Trust and privacy](../agent-trust-and-privacy/references/trust-and-privacy.md) cuts across all of them.

For a reported failure, preserve the actual run's artifacts, identify what served it and its effective configuration, then compare recorded inputs and outputs at each boundary. A receipt, correlation id, trace, or log line proves only its named event; explain missing coverage rather than replacing unknown with zero or success. For a proposed optimization, name the target and guardrails, use saved evidence first, freeze the comparison and budget before model calls, and report both gains and losses against the reference as well as the advancement gate. A trace or evaluation finding does not grant authority for a tool effect, deployment or further spend.

## Diagnostics, evaluation and resource control instinct map

Buy only the evidence and control needed for a trustworthy decision, while preserving required safety, accounting and acceptance guarantees.

For capability design or problem-solving with a human counterpart, first use supported research or established practice to describe effective human performance, connect it to an option/check, and test transfer against agent differences; carry over only applicable human limits and label unsupported explanations as hypotheses; skip routine use and purely technical mechanisms without a counterpart ([design rule](../agent-system-engineering/references/engineering-process.md#design)).

| Need | Lever and trade-off | Build it as |
|---|---|---|
| We cannot reconstruct what happened across the request. | **Records, then traces where needed** buy progressively richer timing and linkage at propagation and volume cost; sampling saves resources but loses coverage, so keep required audit and accounting independent. [Depth](references/execution-tracing.md#3-decisions-under-pressure) | Structured event recorder; trace spans around run, model and tool calls when needed. |
| We need more detail to explain this failure. | **Metadata before bounded payload capture** limits overhead and exposure; content can resolve semantic causes but costs serialization, retention and privacy risk. Expand only for the unanswered hypothesis and permitted carriers. [Depth](references/execution-tracing.md#3-decisions-under-pressure) | Capture policy in instrumentation hooks, projecting metadata before bounded payload serialization. |
| Can we score whether the result is correct? | **Validated exact checks, then adjudication or calibrated graders** trade cheap repeatability against semantic coverage and judge error; begin with saved positive and negative examples before paying for grading volume. [Depth](references/scenario-evaluation-and-experiments.md#3-decision-table) | Assertion function over saved fixtures; frozen rubric and calibrated grader for semantic cases. |
| Is this change good enough to advance? | **Small screen before representative confirmation** rejects weak choices quickly; repetitions and sealing cost more but address noise and generalization. A screen does not replace required acceptance, and exposed tuning data is not a fresh seal. [Depth](references/scenario-evaluation-and-experiments.md#3-decision-table) | Scenario runner with frozen case manifest, recorder and separate sealed acceptance fixtures. |
| Report spend, or guarantee it cannot cross a limit. | **Totals, attribution reservations or atomic holds** provide different guarantees at different write, availability and reconciliation costs; preserve unknown liability and use a qualified hold for a hard ceiling. [Depth](references/cost-accounting.md#4-conditional-invariants) | Spend report first; attempt ledger or atomic budget-hold transaction before paid dispatch as required. |
| The user still waits too long despite a faster component. | **End-to-end bottleneck diagnosis** avoids spending on the wrong stage; compare latency, quality and total work before tuning models, rounds, concurrency or caching, then stop at the frozen verdict. [Depth](references/diagnostics-evaluation-and-resource-control.md#4-diagnose-from-recorded-evidence) | End-to-end timing recorder and analysis over stage intervals, paired with quality/work assertions. |

## Navigate by decision

**Design or plan:** describe the actual user outcome and failure tolerance first. List each observation needed to establish acceptance and name the component that can produce it. Decide whether a local result, structured event, trace, accounting record or scenario artifact answers that question. Record collection policy and gaps before choosing a backend. A single process can produce several evidence types, and several processes can share storage without collapsing their logical identities.

**Build or review instrumentation:** write the identity and evidence contract before selecting attribute names. If an effect must be auditable, define whether durable audit is a condition of admission. If an exporter is optional, record loss and ensure diagnostics do not duplicate an action or replace its outcome. Read the tracing leaf for propagation, guarded export, tenant-scoped reads, retention and the difference between trace coverage and actual work.

**Investigate a slow or wrong result:** first determine whether a run was admitted, then establish what actually served it. Use available timing and result artifacts to find the first supported divergence. Distinguish an absent record from an available record proving no action, a localized slow interval from its cause, and a captured framework request from the provider-effective request. If relevant evidence was not retained or the current surface is inaccessible, report that limit and its effect on the conclusion.

For a wrong answer or action, first check whether the needed instruction, fact or result was present in the actual request at the failing seam and classify the divergence as data, context carrier, instruction, tool schema, harness or model capability before choosing a lever from the [behavior-steering instinct map](../agent-harness-model-and-tools/SKILL.md#behavior-steering-instinct-map); a proposed lever is not a proven cause. A harness tuned or verified on another model or generation can also cause the divergence; keep model capability as a hypothesis until the request and harness are checked against the model actually in use.

**Evaluate or optimize:** choose a user-visible target and explicit guardrails. Reuse recorded outputs, validate deterministic counters, and check each intermediate artifact before commissioning semantic grading or new calls. Where paid experiments are authorized, account for all calls and outstanding liability; the comparison policy determines both stopping and interpretation. A budget gate is not a correctness verdict and a successful evaluation is not deployment evidence.

**Change accounting or presentation:** enumerate every paid producer and identify who decides the charge target. Preserve attribution, outcome and cost status as separate axes. When a reader displays a subtotal, state its population, coverage and unknown count; a count of unknown attempts is not an estimate of missing money. Test the actual reader's authorization and pagination, not just its filter widget.
