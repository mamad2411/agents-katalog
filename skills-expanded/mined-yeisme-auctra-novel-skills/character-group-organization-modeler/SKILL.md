# 人物群体组织建模师

让群像不是若干人物卡的并列，而是一个会分配角色、奖励服从、制造沉默、形成联盟并在压力下重组的社会系统。适合团队、家族、宫廷、公司、帮派、运动与官僚机构。

## 输入

- 群体成员、正式目标、资源、历史、组织规则、外部威胁和当前任务。
- 可选：组织图、关系网、场景、社会情境包和预期分裂/整合弧线。

## 输出

- 正式结构与非正式结构对照。
- 成员功能角色、地位、联盟、派系、守门人、桥接者、替罪羊和边缘人。
- 显性规则、隐性规范、沉默议题、奖励与制裁。
- 信息流、决策流、责任转移、集体行动条件和退出成本。
- 压力下的分裂、团结、领导更替或组织僵化场景。

## 必读参考

- 读取 `../character-intelligence-router/references/groups-organizations-and-networks.md`。
- 需要标准格式时读取 `../character-intelligence-router/references/social-context-output-templates.md`。
- 若核心是某个个体掌握的权力来源，handoff 给 `character-power-status-analyst`。

## 工作流

1. 写出群体宣称的目标与成员实际获得的利益，检查二者差异。
2. 画出正式职位、汇报线和程序，再画实际咨询、信任、信息与庇护网络。
3. 为每个承重成员分配群体功能，而不仅是职业：领袖、执行者、守门人、桥接者、异议者、象征人物或替罪羊。
4. 列出加入、归属、晋升、发言、退出和背叛的成本。
5. 识别隐性规范：什么必须赞同、谁不能被质疑、失败如何解释、坏消息如何被过滤。
6. 建模联盟与派系：共同利益、共同敌人、私人关系、身份或信念如何维持它们。
7. 用资源短缺、外部威胁、领导失误、丑闻、继任或新成员进行压力测试。
8. 把组织机制转成群像场景、信息差、投票/命令/仪式和后果。

## 群像最小图谱

- 每个核心角色至少连接两种边：正式关系与非正式关系。
- 至少一个人连接两个平时不互信的子群体。
- 至少一个公开规则被非正式实践改变。
- 至少一个群体利益与个体道德或私欲发生冲突。

## Auctra handoff

- 输出可成为 ensemble、organization、relationship 或 conflict material。
- 场景成稿 handoff 给对应 writer，项目正典更新交给 Auctra owner。
- 不自行创建新的组织 schema 或手写 SQLite/JSON 状态。

## 边界

- 不把组织成员写成同质群体，也不把“群体思维”当所有集体决策的万能解释。
- 不提供现实组织操纵、胁迫、镇压或规避监管的操作方案。
- 不只画静态组织图，必须说明信息、奖励和制裁如何流动。

## 验证

- 正式结构与非正式结构至少有一处差异。
- 群体规范有奖励、制裁和例外，而不是口号。
- 压力事件会重排至少一条联盟、信息或领导关系。
- 群像冲突来自系统位置与选择，不是每个人轮流发言。
