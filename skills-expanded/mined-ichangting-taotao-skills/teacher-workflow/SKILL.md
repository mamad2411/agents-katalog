# 教学工作流（teacher-workflow）

## 定位

teacher-workflow 是 **L0 编排层元技能**——一个意图路由器 + 技能链编排器。它本身不生产任何教学内容，只做三件事：

1. **意图识别**：把教师的自然语言需求映射到工作流场景
2. **技能链路由**：按场景推荐所需的 L1 技能序列
3. **末步收口推荐**：关键产出默认推荐过 doc-review 审核

### 核心问题

21 个 L1 技能已覆盖"备→教→练/批→评→研→输出"全环节，但教师面对扁平的技能列表不知该选哪个、按什么顺序用。teacher-workflow 让教师说"我要备一节课"，而不是"我要调用 k12-lesson-planning-zh 然后 gushiwen 然后 doc-review"。

### 不做什么（边界）

- **不替代任何 L1 技能的判断**：只编排，不生产。教案质量由 k12 负责，字词准确性由 gushiwen 负责
- **不新增数据源**：所有数据仍走 L2 单一数据源（curriculum-standard / gushiwen / 品牌规范）
- **不锁定技能调用顺序**：教师可随时打断、跳过、插入任意技能
- **不做学生端**：仅教师端，合规红线不变
- **不自动执行技能**：采用声明式推荐，识别后展示技能链供教师确认；数据流自动传递但技能逐个激活

---

## 何时使用

当教师的输入是**场景级需求**（"我要做什么"）而非**工具级需求**（"我要用某个技能"）时触发。

**触发信号**：

| 教师会说的话 | 识别为 |
|---|---|
| "备一节课""我要讲《XX》""备七年级上册第X单元" | 新课备课 |
| "出一张卷""期中卷""中考模拟""周练卷" | 命题组卷 |
| "批作文""这篇作文怎么评""作文升格" | 作文批改 |
| "中考复习""三年考情""备考方案" | 中考备考 |
| "写论文""课题申报""教学案例""教研" | 教研写作 |
| "整本书阅读""名著导读""《昆虫记》怎么教" | 整本书阅读 |

**不触发**：当教师直接指定某个技能（如"用 gushiwen 查一下'之'的用法""帮我审一下这段话"）时，不启用本技能，直接执行对应技能。

## 意图识别规则

采用"关键词匹配 + 上下文推断"双层识别。

### 第一层：关键词匹配（快速路由）

详见 `references/场景路由表.md` 的完整关键词表。核心映射：

| 关键词模式 | 路由到 |
|---|---|
| 备课/教案/我要讲/备一节/课时计划 | 备课包 |
| 出卷/试卷/期中/期末/模拟卷/组卷/周练 | 命题组卷链 |
| 批作文/批改/评语/作文升格/学生作文 | 批改包 |
| 中考/复习/备考/考情/三年真题 | 中考包 |
| 论文/课题/案例/教研/职称/申报 | 论文包 |
| 名著/整本书/导读/昆虫记/朝花夕拾/经典常谈 | 整本书包 |

### 第二层：上下文推断（消歧义）

当关键词命中多个场景时，按上下文消歧：

| 歧义场景 | 消歧规则 |
|---|---|
| "讲《岳阳楼记》"命中备课 + 文言 | 优先备课包，链内自动插入 gushiwen + gushi-appreciation |
| "中考名著"命中中考 + 整本书 | 优先中考包，链内插入 whole-book-reading |
| "写教学案例"命中论文 + 备课 | 优先论文包（教学案例属教研写作） |
| "分层备《春》"命中分层 + 备课 | 判断是否已有教案：有→lesson-differentiation；无→k12 一次性产出分层 |
| "出一份《岳阳楼记》的理解检查"命中命题 + 测评 | 优先 formative-assessment（单篇轻量检查，非整卷） |
| "古诗文鉴赏"命中文言 + 备课 | 判断有无具体篇目：有→备课包（链内插 gushi-appreciation）；无→直接 gushi-appreciation |

## 6 类场景路由表

### 场景 1：新课备课

**触发**："备一节课""我要讲《XX》""备七年级上册第X单元"

**预设技能链**：
```
k12-lesson-planning-zh
  →〔文体=文言文/古诗词？〕
    是 → gushiwen（字词串讲）+ gushi-appreciation（鉴赏素材）
    否 → 跳过
  →〔需要预判迷思？〕
    是 → anticipated-misconceptions
    否 → 跳过
  →〔需要课件？〕
    是 → kejian-generator（教案→课件大纲）
    否 → 跳过
  →〔需要知识卡片？〕
    是 → knowledge-card
    否 → 跳过
  → 末步 → doc-review 收口
```

**条件分支**：详见 `references/场景路由表.md` §分支规则。

### 场景 2：命题组卷

**触发**："出一张卷""期中卷""中考模拟""周练卷"

**预设技能链**：
```
〔地区=江西？〕
  是 → jiangxi-zhongkao-beikao（卷面结构+考情）
  否 → zhongkao-analysis（通用框架）
→ mingti-zujuan（双向细目表+试卷）
  →〔含文言文？〕
    是 → gushiwen（字词准确）
    否 → 跳过
→ 末步 → doc-review（题干/选项/答案四关）
```

### 场景 3：作文批改

**触发**："批作文""这篇作文怎么评""作文升格"

**预设技能链**：
```
zuowen-grading（维度评分+问题清单+评语草稿）
  →〔含古诗文引用？〕
    是 → gushiwen 核对
    否 → 跳过
→ 末步 → doc-review（语言关）
```

### 场景 4：中考备考

**触发**："中考复习""三年考情""备考方案"

**预设技能链**：
```
jiangxi-zhongkao-beikao（三年考情数据+备考方案）
  →〔非江西？〕
    是 → zhongkao-analysis（通用框架，教师填数据）
    否 → 跳过
  →〔名著板块？〕
    是 → whole-book-reading
    否 → 跳过
  →〔需要检查点？〕
    是 → formative-assessment
    否 → 跳过
```

### 场景 5：教研写作

**触发**："写论文""课题申报""教学案例""教研"

**预设技能链**：
```
jiaoyan-writing（出框架+Word排版）
→ 末步 → doc-review（四关收口）
  →〔引古文处〕
    是 → gushiwen + 王力视角把关
    否 → 跳过
```

### 场景 6：整本书阅读

**触发**："整本书阅读""名著导读""《昆虫记》怎么教"

**预设技能链**：
```
whole-book-reading（导读方案）
  →〔跨学科延伸？〕
    是 → interdisciplinary-learning
    否 → 跳过
  →〔需要学生卡片？〕
    是 → knowledge-card
    否 → 跳过
  →〔需要文本分析？〕
    是 → wordfreq
    否 → 跳过
```

## 声明式推荐 + 数据流传递流程

teacher-workflow 采用**声明式推荐 + 数据流自动传递**：识别意图后展示技能链供教师确认，确认后逐个激活技能，上游产出自动注入下游上下文。

### 步骤 1：识别意图

解析教师输入，匹配关键词 + 上下文推断，确定场景类型。

### 步骤 2：展示技能链

向教师展示推荐的技能链，格式如下：

```
📋 识别到场景：新课备课

推荐技能链（共 5 步）：
  1️⃣  k12-lesson-planning-zh  — 生成教案骨架
  2️⃣  gushiwen                — 文言字词串讲（检测到文言文/古诗词）
  3️⃣  gushi-appreciation      — 鉴赏素材（意象/手法/名句）
  4️⃣  anticipated-misconceptions — 预判学生迷思
  5️⃣  doc-review              — 末步审核收口

数据流：步骤 1 产出 → 自动注入步骤 2/3/4；步骤 2 产出 → 自动注入步骤 3/4
护栏：步骤 5 自动审核步骤 1-4 的全部产出

是否按此顺序执行？可以：
  • 回复"开始" → 从第 1 步逐个激活
  • 回复"跳过第X步" → 调整后执行
  • 回复"只要1和5" → 自定义子集
  • 直接说具体需求 → 重新识别
```

### 步骤 3：逐个激活 + 数据流传递

教师确认后，按顺序逐个激活技能。每个技能激活时：

1. **自动注入上游上下文**：teacher-workflow 将上游产出的 Markdown 摘要注入为该技能的上下文前缀（详见 `references/数据流契约.md`）
2. **执行技能**：技能基于注入的上下文 + 教师输入执行
3. **暂存产出**：技能完成后，其核心产出以 Markdown 摘要暂存
4. **展示摘要 + 提示**：展示该步产出摘要，提示"继续下一步？"或"调整链路？"
5. **教师可干预**：教师可查看暂存内容、修改后传递、或选择不传递

### 步骤 4：末步收口（护栏内建）

链末自动激活 doc-review，并自动注入全部上游产出：

- **自动注入**：步骤 1 到 N-1 的全部产出摘要自动注入 doc-review 的审核上下文
- **自动选择审核模式**：根据上游产出类型自动选择审核模式（四关/古文引用专项/参考文献格式/品牌声音）
- **教师可跳过**：说"不用审核"跳过收口；说"只审核教案"部分审核

---

## 护栏内建

关键产出默认在链末推荐 doc-review 收口：

| 产出类型 | 收口方式 |
|---|---|
| 教案 / 学生材料 | doc-review 四关（文字/语法/用词/文风） |
| 试卷题干 / 选项 / 答案 | doc-review 四关 |
| 鉴赏文字 / 古文引用 | doc-review 古文引用专项（作者/篇目/原文核对） |
| 教研论文 / 课题 | doc-review 四关 + 古文引用专项 |
| 公众号文章 / 配图文案 | doc-review 四关 + 品牌声音核对 |

教师可显式说"不用审核"跳过收口，但默认行为是推荐收口。

## 与 L1 技能的契约

teacher-workflow 不直接调用 L1 技能的内部逻辑，而是通过两种方式编排：

1. **声明式推荐**：识别意图后，向教师推荐技能链顺序，教师确认后逐个激活
2. **数据流传递**：上游产出以 Markdown 摘要暂存，下游技能激活时自动注入上下文（详见 `references/数据流契约.md`）
3. **护栏内建**：链末自动激活 doc-review，注入全部上游产出并自动选择审核模式

这种设计保证了：
- L1 技能仍可独立使用（不依赖 teacher-workflow）
- teacher-workflow 失效时，教师仍可手动调用各技能（降级不中断）
- 新增 L1 技能时，只需在路由表加一行 + 依赖图加一行，不影响现有链路

---

## 降级策略

| 异常情况 | 降级行为 |
|---|---|
| 意图识别不确定 | 列出 2-3 个候选场景，请教师选择 |
| 依赖技能未安装 | 提示"建议安装 XX 技能以获得完整体验"，不中断当前链 |
| 技能链过长 | 每链最多 5 步；超长链拆分为子链，教师按需激活 |
| 数据流传递失败 | 上游产出以 Markdown 暂存，教师可手动复制给下游 |
| 上下文空间不足 | 仅保留最近 2 步的产出摘要，更早的自动丢弃（P0-P1 优先保留） |
| 教师打断 | 保存当前进度，教师可随时从任意步骤继续 |
