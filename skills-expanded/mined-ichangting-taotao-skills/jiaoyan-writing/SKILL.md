# 教研写作技能

## 技能定位

本技能专为语文教师设计，提供教研课题申报、论文撰写、教学案例编写、研究报告撰写的全流程辅助。核心能力包括：PDF 解析（pdfplumber）、Word 专业排版（python-docx）、AI 失败模式检查（7-mode 完整性门）、写作质量检查（6 类机器感检测）。

**设计理念**（借鉴 ARS [$TRAE_REF](https://github.com/Imbad0202/academic-research-skills) 的人机协作理念）：AI 是副驾驶，不是驾驶员。本技能处理框架搭建、格式排版、引用格式化等基础工作，教师负责定义问题、选择方法、解读数据、撰写核心观点。教研成果的核心价值在于教师真实的教学实践与独立思考。

---

## 何时使用

- 用户需要撰写课题申报书、教研论文、教学案例、教学反思、教学设计
- 用户需要撰写教研课题研究报告（结题报告）
- 用户上传 PDF 文献需要解析提取内容
- 用户需要生成符合 GB/T 7714 参考文献格式的 Word 文档
- 用户涉及职称评审、课题立项、教学成果评选材料准备

## 支持的材料类型

| 材料类型 | 适用场景 | 字数要求 | 评审级别 |
|----------|----------|----------|----------|
| **课题申报书** | 课题立项申报 | 5000-10000 字 | 校级/县级/市级/省级 |
| **教研论文** | 职称评审/期刊发表 | 3000-8000 字 | 初级/中级/高级 |
| **教学案例** | 教学成果评选 | 2000-5000 字 | 校级/县级/市级 |
| **教学反思** | 日常教研/职称评审 | 1000-3000 字 | 通用 |
| **教学设计** | 教学比赛/职称评审 | 3000-6000 字 | 校级/县级/市级 |

## 使用流程

### Step 1: 接收需求

确认用户需求信息：成果类型、教研选题/方向、核心创新点、教学实践素材、评审级别、附件材料（PDF 可选）。

**素材充分性判断**：评估用户提供的教学实践素材是否足以支撑全文。如果素材不足，明确告知用户哪些部分需要补充，而非自行编造。

**完成标准**：成果类型、选题方向、核心创新点、评审级别四项已确认；附件材料已接收或确认无附件；素材充分性已评估。

### Step 1.5: 写作引导（推荐新手，可选）

**触发条件**：当成果类型为教研论文，且教师是新手、不确定如何下笔、希望被引导时启用。

**引导模式**：以"资深教研导师"身份，通过苏格拉底式对话帮教师逐章厘清思路，产出章节计划。详细流程见 `references/论文写作引导流程.md`。

**产出**：章节计划（含核心论点、各部分预期内容与字数）。教师获得章节计划后，可自行撰写或转入 Step 4 直接撰写。

**跳过条件**：教师有明确思路和素材、时间紧迫、或成果类型非教研论文时跳过。

**完成标准**：已产出章节计划并经教师确认；或教师选择跳过直接撰写。

### Step 2: PDF 解析（如有附件）

使用 pdfplumber 提取 PDF 中的文字、表格、元数据，输出结构化文本用于后续撰写。解析代码与适用场景详见 `references/pdf解析与word排版.md`。

**完成标准**：PDF 文本已成功提取并结构化输出；或确认无附件、无需解析。

### Step 3: 生成框架

根据成果类型生成对应标准框架。各材料框架详见下方"框架模板"部分的 context pointer。

**完成标准**：已按成果类型输出完整框架，各部分标题齐全且顺序正确。

### Step 4: 撰写初稿

根据用户提供的素材、PDF 提取内容及教研选题方向撰写初稿。选题方向参考 `references/教研选题方向.md`。

#### 4a. 反泄露协议

**IRON RULE**：当用户提供的素材不足以支撑某个段落时，在该位置插入 `[素材缺失：需补充XXX]` 标记，而非编造内容填补。常见场景：
- 用户未提供教学数据 → 标记 `[素材缺失：需补充真实教学数据，如学生成绩/问卷结果]`
- 用户未提供课堂实录 → 标记 `[素材缺失：需补充课堂对话或教学环节描述]`
- 用户未提供参考文献 → 标记 `[素材缺失：需补充相关文献]`

**禁止行为**：
- 禁止编造教学数据（百分比、分数、人数）
- 禁止编造课堂对话和学生反应
- 禁止编造参考文献
- 禁止将示例文本当作真实内容输出

#### 4b. 写作质量自检

撰写过程中参照 `references/写作质量检查.md` 进行自检，重点关注：
- AI 高频词汇是否过度使用
- 破折号是否过密
- 段落开头是否有套话
- 段落长度是否均匀化
- 句式节奏是否单一
- 实践气息是否充足（教研材料特有）

#### 4c. 风格校准（可选）

如果用户提供了过往教研材料，分析其写作风格特征（句子节奏、词汇偏好、引用方式），作为初稿的风格参考。教研材料格式规范始终优先于个人风格。

**完成标准**：框架各部分均有内容填充或 `[素材缺失]` 标记，无空白章节；引用已按 GB/T 7714-2015 格式标注；写作质量自检已完成。

### Step 4.5: 完整性检查门（Integrity Gate）

**阻断性检查**：在初稿完成后、Word 排版前，必须运行 AI 失败模式检查。检查清单详见 `references/ai失败模式检查清单.md`。

对 7 种 AI 失败模式逐一排查：

| 模式 | 名称 | 阻断条件 |
|------|------|----------|
| M1 | 编造教学数据 | 文中出现无法追溯的数据 → 阻断 |
| M2 | 幻觉引用 | 引用无法验证 → 阻断 |
| M3 | 编造教学实践细节 | 课堂细节非用户提供 → 阻断 |
| M4 | 教学策略表面化 | 策略缺乏可操作性 → 警告 |
| M5 | 错误归因于理论 | 理论与实践不对应 → 警告 |
| M6 | 研究方法描述不实 | 方法与实际不符 → 阻断 |
| M7 | 选题框架锁定 | 框架与实践偏离 → 警告 |

**检查结果处置**：
- **无风险**：记录证据，继续 Step 5
- **疑似**：**阻断排版**，向用户呈现问题，用户可选择修正/覆盖/补充素材
- **证据不足**：M1/M3/M6 阻断（需用户提供真实素材）；M2/M4/M5/M7 警告后可继续

**完成标准**：7 种模式均已检查；所有阻断性问题已解决或用户已覆盖（覆盖理由记入交付报告）。

### Step 4.7: 模拟评审（推荐教研论文，可选）

**触发条件**：当成果类型为教研论文，且初稿已通过完整性检查门时启用。

**评审模式**：从审稿人视角进行 5 维度模拟评审（选题价值 20%、论证逻辑 25%、实践支撑 25%、文献质量 15%、写作规范 15%）。评审规则详见 `references/论文模拟评审.md`。

**产出**：评审报告（含综合得分、各维度评分与详评、修改优先级清单）。

**修改循环**：教师根据评审报告修改后可再次评审，最多 2 轮。任何维度评分为 1 分（不合格）的，阻断进入排版。

**跳过条件**：非教研论文（如教学反思、课题申报书）、时间紧迫、或教师明确不需要评审时跳过。

**完成标准**：评审报告已呈现；所有高优先级问题已修改或教师选择保留。

### Step 5: Word 排版

使用 python-docx 创建 Word 文档，按教研规范设置页面、标题、正文、摘要、关键词、表格、参考文献等格式。排版规范与代码实现详见 `references/pdf解析与word排版.md`。

**完成标准**：已生成 .docx 文件，页面设置、字体字号、行距缩进均符合教研材料排版规范表要求。

### Step 6: 输出交付

交付 Word 文档（.docx），并附：
- 查重优化建议与修改完善建议
- 完整性审计日志（7 种模式的最终状态）
- `[素材缺失]` 标记清单（如有）

**完成标准**：.docx 文件已保存；已提供查重率参考标准与原创性建议；已呈现完整性审计日志；已提示用户结合个人实践修改完善。

## 原创性保障与查重

**原创性第一原则**：教研成果的核心价值在于教师真实的教学实践与独立思考。本技能只提供框架与思路初稿，最终内容须由用户结合自己的课堂原创完成，切勿整段搬用他人成果或 AI 生成文本。

**查重率参考标准**（以各评审单位当年要求为准）：

| 评审级别 | 常见查重率要求 |
|----------|------------|
| 校级 | <30% |
| 县级 | <25% |
| 市级 | <20% |
| 省级 | <15% |
| 核心期刊 | <10% |

**规范引用建议**：引用他人观点、数据须按 GB/T 7714-2015 注明出处；区分直接引用与间接引用；以自身实践为主体支撑论点；成稿后用知网/维普/万方等正规查重系统自检。任何"改写降重""同义替换洗稿"都不是本技能的导向。

## 技术依赖

本技能的 PDF 解析与 Word 排版能力依赖本地 Python 环境，未安装会静默失败。

**必装（核心功能）**：
```bash
pip install pdfplumber python-docx
```

**安装自检**：运行前执行 `python -c "import pdfplumber, docx; print('依赖就绪')"`，报 `ModuleNotFoundError` 则先安装。

**可选（增强功能）**：`pip install PyMuPDF paddleocr pdf2docx`（扫描版 PDF 处理、中文 OCR、PDF 转 Word）。

---

## 限制说明

1. 本技能适用于电子 PDF（有文本层），扫描版 PDF 需额外 OCR 支持。
2. 查重率需通过专业查重系统检测，本技能仅提供优化建议与参考标准。
3. 复杂公式、图表可能无法完全保留；需确保目标系统有宋体、黑体、楷体等字体。
4. 参考文献需根据实际引用核实，发表需符合目标期刊或评审单位的具体要求。
5. AI 失败模式检查为辅助工具，不能替代用户对内容真实性的最终判断。
6. 引用验证依赖用户通过知网/维普/万方等数据库手动核实，本技能无法直接访问学术数据库。
