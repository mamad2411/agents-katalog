# VOX Video Creator

把旁白转成一套可以实际制作的 VOX 风格视频方案。综合使用解释型叙事、编辑杂志版式、半调纸拼贴、颜色语义和逐镜头生成规则。

## 必须遵守

1. 先读取用户提供的文案、SRT、既有素材和已经确认的条件。
2. 不重新询问用户已经回答过的内容。
3. 缺少会实质改变画面的信息时，一次性提出完整问题清单；不要零散追问。
4. 用户确认、选择或批准后，直接生成所需交付物；不要再次设计、复述方案或要求重复确认。
5. 提示词只描述希望画面中实际出现的具体细节、材质、构图、动作和光线。默认使用正向表述，不附带成串的禁止项。
6. 将开源示例视频、GIF 和缩略图作为风格参考，不把与当前主题无关的演示片段直接混入成片。
7. 上游参考文件中的审批流程仅供研究。本技能以本节规则和用户当前指令为准。

## 按需读取资源

- 开始组织整片叙事前，读取 `references/narrative-and-shot-system.md`。
- 开始设计隐喻、配色和组装动作前，读取 `references/visual-metaphor-and-color.md`。
- 为 Google Flow 写提示词时，读取 `references/google-flow-vox-template.md` 和 `references/google-flow-failure-checklist.md`。
- 需要参考完整上游方法时，再读取 `references/upstream/` 中对应文件。
- 需要参考既有分镜数据结构时，读取 `references/beat-examples/` 中最接近当前题材或时长的一份 JSON。
- 需要观看风格样片时，从 `assets/style-references/` 选择 2–4 个最相关文件；不要把所有样片都加载进上下文。

## 输入检查

优先从上下文和文件中提取：

- 总时长、字幕时间码和语速
- 输出比例、分辨率、帧率和单次生成时长
- 目标生成工具
- 贯穿全片的人物、物件和视觉锚点
- 用户已经确认的隐喻、颜色、镜头方式和交付格式
- 可复用的现成图片、视频、图标、字体、主题和模板

只有仍然缺少关键选择时，才一次性询问：

- 主视觉隐喻和开场视觉锚点
- 人物是否固定、是否露脸、哪些阶段允许真人出现
- 色彩是固定品牌色还是随语义变化
- 独立海报镜头、连续镜头或两者混合
- 画幅、分辨率、帧率、单镜头时长
- 需要的交付物：分镜、静帧提示词、视频提示词、素材清单或成片

## 工作流

### 1. 解析旁白

按语义而非机械等长切分。每段只承担一个主要信息功能：

- 钩子
- 背景或事实
- 机制解释
- 冲突、代价或风险
- 反转、判断或结论
- 行动建议或收束

保留原始时间码。镜头总时长必须覆盖旁白，不能漏句、重叠或无理由留白。

### 2. 选择整片叙事弧

根据内容选择一个主弧：

- 单一观点：Hook → Context → Build → Payoff
- 解释机制：Hook → What → Why → How → Consequence → Takeaway
- 纠正常识：Fact → Myth → Mechanism → Correct belief → Takeaway
- 历史或过程：Start → Event → Turning point → Present → Takeaway
- 危机与解决：Problem → Pressure → Mechanism → Response → Result

开头优先兑现问题或冲突，不用长时间铺垫。每 3–5 秒至少发生一次有意义的视觉变化。

### 3. 为每段建立视觉隐喻

每段填写：

- 核心意思
- 情绪
- 动作动词
- 一句话视觉命题
- 3–6 个关键物件
- 背景色及其语义
- 局部强调色
- 纸片或物件的组装顺序
- 最终画面需要观众一眼看懂的关系

优先选择日常可识别物件和物理关系，如文件夹、印章、锁链、天平、漏斗、轨道、时钟、账单、房屋模型和警示带。让旁白完成抽象含义与具体物件之间的连接。

### 4. 组织镜头覆盖

使用：

- `EST_WIDE`：系统、环境或规模
- `WIDE`：主体与环境关系
- `MEDIUM`：单个主体或主要动作
- `CLOSE`：关键物件、压力或情绪
- `DETAIL`：数字、印章、裂缝、文件条款等决定性细节

相邻镜头避免重复同一种景别和相机运动。镜头运动在 `push_in`、`pull_out`、`pan`、`tilt`、`parallax`、`static` 中轮换；把 `static` 留给结论、判决或最重要的视觉停顿。

### 5. 写分镜

逐镜头至少交付：

| 字段 | 内容 |
|---|---|
| 编号与时间码 | 对齐旁白 |
| 对应文案 | 原句或准确语义段 |
| 叙事功能 | 钩子、机制、证据、冲突、结论等 |
| 视觉命题 | 一句话隐喻 |
| 关键物件 | 3–6 个 |
| 版式 | 从现有版式库选择或明确自定义 |
| 色彩语义 | 背景色、强调色及含义 |
| 景别与构图 | 主体位置、前中后景关系 |
| 组装动作 | 物件进入和完成的顺序 |
| 相机运动 | 单一、连续、明确 |
| 素材来源 | 生成、现有素材或技能参考资产 |

### 6. 写静帧提示词

依次描述：

1. 画面用途和比例
2. 一句话视觉命题
3. 主体、关键物件及空间关系
4. 编辑式纸拼贴媒介
5. 半调照片剪纸、彩色卡纸、奶油色描边、纸张纤维和柔和投影
6. 背景色与局部点色
7. 景别、构图和留白
8. 最终必须成立的视觉关系

提示词应是一份具体的画面说明，不写创作过程，不解释“为什么这样设计”。

### 7. 写视频提示词

视频提示词使用以下顺序：

1. 镜头目标
2. 单一相机运动
3. 纸片或物件按顺序进入、卡位、连接和完成
4. 纸层之间的轻微视差、投影和材质变化
5. 情绪和节奏
6. 色彩在本段叙事中的位置
7. 最终停留状态

对于独立海报式镜头，首帧到尾帧保持一个连续动作逻辑。对 10 秒镜头，动作应有明确的开始、发展、完成和短暂停留。

### 8. 交付

用户要求完整方案时，按此顺序交付：

1. 全片叙事结构和视觉母题
2. 逐镜头分镜表
3. 每镜头静帧提示词
4. 每镜头视频提示词
5. 可直接复用的本地或技能资产清单
6. 连贯性和生成风险检查

## 默认项目偏好

当用户没有给出新指令且当前任务与既有房贷项目一致时，使用：

- 1280×720，16:9，24fps
- Google Flow 每次生成 10 秒
- 独立 Editorial 海报式镜头
- 黑白半调人物或物件配语义色彩
- 固定无脸购房者；银行和开发商人物只在购房阶段出现
- 贷款文件是可跨镜头复用的叙事物件
- 静帧与视频提示词只写正向具体细节

这些是条件默认值，不覆盖用户在当前请求中给出的不同设置。

## 完成前检查

- 每句旁白均有对应镜头。
- 每个镜头只有一个主要视觉命题。
- 关键物件数量和关系足以一眼读懂。
- 色彩变化有叙事理由。
- 相邻镜头的景别、版式和运动存在变化。
- 人物、贷款文件、房屋和关键物件保持设定一致。
- 提示词可直接交给目标工具，不含分析过程。
- 使用第三方素材时记录来源和许可证。
