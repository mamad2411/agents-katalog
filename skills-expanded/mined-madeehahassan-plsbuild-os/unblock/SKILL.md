# /unblock

Use this when you haven't made progress in a while. When you keep starting and stopping. When you know what you should be doing but aren't doing it.

Use this when you're stuck **mid-build or before starting**, and you don't know why. If the product is basically done and you just can't push it out the door, use `/ship` instead.

---

## Step 1: Name the block

**Technical stuck:** I don't know how to build this. The code isn't working.
Fix: describe the problem, show the error, get specific help.

**Decision stuck:** I have two options and I can't choose.
Fix: run /audit. Or just pick one and ship. You'll learn more from the outcome than from deliberating.

**Clarity stuck:** I don't know what I'm building or why.
Fix: go back to the user. What problem are you solving? For whom?

**Motivation stuck:** I know what to do but I'm not doing it.
Fix: shrink the task. What's the smallest possible step?

**Overwhelm stuck:** Too many things, don't know where to start.
Fix: write out every open item. Pick the one that makes the others easier or irrelevant.

---

## The smallest step protocol

1. Write down what done looks like for the very next thing. Not the project. Just the next thing.
2. Is it still too big? Cut it in half. Then again.
3. Set a timer for 25 minutes.
4. Do only that one thing.

If you can't work for 25 minutes on it, the task is still too big or too vague.

---

## If it's deeper than a task

Signs: you've been "about to start" something for more than 3 days. You keep working on things adjacent to the real problem. The thought of the task creates low-grade dread.

Stop. Write down what you're actually afraid of. Name it. Then ask: is that fear based on evidence?

Usually the answer is: the only way out is through.
