## 客户旅程地图

梳理从认知到推荐的端到端客户体验，识别每个阶段的情绪、痛点和改进机会。

### 背景

你正在为 **$ARGUMENTS** 创建一份客户旅程地图。

如果用户提供了文件（访谈记录、问卷数据、分析数据、支持工单或已有的旅程地图），请先读取。如果提供了 URL，使用网络搜索了解该产品。

### 指令

1. **定义用户画像**：谁在经历这段旅程？使用带有 JTBD 的具体用户画像，而不是泛泛的"用户"。

2. **梳理旅程阶段**（根据产品调整）：

   | 阶段 | 描述 |
   |---|---|
   | **认知（Awareness）** | 他们最初是如何了解到这个产品的？ |
   | **考虑（Consideration）** | 他们会评估什么？会对比哪些替代方案？ |
   | **获取（Acquisition）** | 他们如何注册或购买？ |
   | **新手引导（Onboarding）** | 首次产品体验 —— 实现价值所需的时间 |
   | **活跃使用（Engagement）** | 日常使用 —— 习惯的养成 |
   | **留存（Retention）** | 是什么让他们持续回来？什么可能导致流失？ |
   | **推荐（Advocacy）** | 他们何时、为何会向他人推荐这个产品？ |

3. **针对每个阶段，记录**：

   - **触点**：用户与产品、品牌或团队互动的位置（网站、邮件、应用内、客服、社交媒体）
   - **用户行为**：他们在这个阶段做什么
   - **想法与疑问**：他们在想什么（"这值得我花时间吗？""我该怎么……？"）
   - **情绪**：他们的感受（兴奋、困惑、沮丧、惊喜）—— 用评分等级或 emoji 标注
   - **痛点**：摩擦、困惑、流失风险
   - **机会**：如何在这个节点改善体验

4. **识别关键时刻**：
   - **Aha 时刻**：用户首次体验到核心价值的时刻
   - **真相时刻（Moments of truth）**：他们决定留下还是放弃的关键决策点
   - **流失触发点**：用户最常流失的位置

5. **创建旅程地图表格**：

   | 阶段 | 触点 | 用户行为 | 情绪 | 痛点 | 机会 |
   |---|---|---|---|---|---|

6. **给出按优先级排序的改进建议**：
   - 哪些痛点对转化或留存的影响最大？
   - 哪些快速见效的改进可以立即提升体验？
   - 哪些需要更深入的投入但回报最大？

逐步思考。将结果保存为 markdown 文档。如需可视化的旅程地图，建议用户以此分析为基础，在 Miro 或 FigJam 中创建。
