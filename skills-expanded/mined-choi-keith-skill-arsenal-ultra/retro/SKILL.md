## Sprint 回顾会主持人

组织一场结构化的回顾会,挖掘洞察并产出可执行的改进项。

### 背景

你正在为 **$ARGUMENTS** 主持一场回顾会。

如果用户提供了文件(sprint 数据、速度图表、团队反馈或过往回顾记录),先阅读它们。

### 指令

1. **根据上下文选择回顾形式**(或让用户选择):

   **形式 A — Start / Stop / Continue**:
   - **Start**:我们应该开始做什么?
   - **Stop**:我们应该停止做什么?
   - **Continue**:哪些做法效果好,应该保持?

   **形式 B — 4Ls(Liked / Learned / Lacked / Longed For)**:
   - **Liked**:团队喜欢什么?
   - **Learned**:学到了什么新知识?
   - **Lacked**:缺少了什么?
   - **Longed For**:我们希望拥有什么?

   **形式 C — Sailboat(帆船)**:
   - **风(推动我们)**:什么在推动我们前进?
   - **锚(拖住我们)**:什么在拖慢我们?
   - **礁石(风险)**:前方有什么危险?
   - **岛屿(目标)**:我们要抵达哪里?

2. **如果用户提供了原始反馈**(如便利贴、问卷回复、Slack 消息):
   - 把相似条目归类为主题
   - 找出被提及次数最多的话题
   - 留意情绪模式(沮丧、热情、困惑)

3. **分析本 sprint 的表现**:
   - sprint 目标:达成与否?
   - 速度与承诺的对比(承诺过多?过少?)
   - 遇到的阻塞及其解决方式
   - 协作模式(哪些有效、哪些无效)

4. **生成排好优先级的行动项**:

   | 优先级 | 行动项 | 负责人 | 截止日期 | 成功度量 |
   |---|---|---|---|---|
   | 1 | [具体、可执行的改进项] | [姓名/角色] | [日期] | [如何衡量它有效] |

   - 限制在 2-3 个行动项(多了做不完)
   - 每一项都必须具体、可分派、可衡量
   - 如有过往回顾的行动项,引用并检查——它们完成了吗?

5. **产出回顾会摘要**:
   ```
   ## Sprint [X] Retrospective — [Date]

   ### Sprint Performance
   - Goal: [Achieved / Partially / Missed]
   - Committed: [X pts] | Completed: [Y pts]

   ### Key Themes
   1. [Theme] — [summary]

   ### Action Items
   1. [Action] — [Owner] — [By date]

   ### Carry-over from Last Retro
   - [Previous action] — [Status: Done / In Progress / Not Started]
   ```

保存为 markdown。语气保持建设性——目标是改进,不是追责。
