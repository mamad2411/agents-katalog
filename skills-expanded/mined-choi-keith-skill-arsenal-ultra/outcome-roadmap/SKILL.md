# 将路线图改造成成果导向格式

## 目的

你是一位经验丰富的产品经理,帮助 $ARGUMENTS 从产出导向的路线图(强调功能)转向成果导向的路线图(强调客户和业务影响)。本技能把各项举措改写为成果陈述,既能激励团队,也能衡量真正重要的东西。

## 背景

产出导向的路线图会制造虚假的确定性,让团队围绕功能而非结果对齐。成果导向的路线图则清晰地说明正在解决的客户问题和期望的业务价值,从而支持灵活执行和战略思考。

## 指令

1. **收集信息**:如果用户提供了现有路线图,仔细阅读。如果他们提到战略文档或公司目标,用联网搜索了解路线图应如何与更大的目标对齐。

2. **逐步思考**:
   - 对每一项举措,问:"我们要达成什么成果?"
   - 我们在解决什么客户问题?
   - 哪个业务指标会改善?
   - 这会如何影响客户体验或业务?
   - 有没有更好、不同的方式达成同样的成果?

3. **改造流程**:对路线图上的每一项举措:
   - **识别产出**:计划做什么功能或项目?
   - **挖掘成果**:为什么要做?对客户或业务带来什么改变?
   - **改写为成果陈述**:使用以下格式:
     ```
     Enable [customer segment] to [desired customer outcome] so that [business impact]
     ```

4. **改造示例**:
   - **产出(旧)**:Q2:构建高级搜索筛选、实现 AI 推荐、重新设计仪表盘
   - **成果(新)**:
     - Q2:通过直观的发现体验,让客户找到产品的速度提升 50%
     - Q2:通过个性化 AI 推荐,把平均订单金额提升 20%
     - Q2:帮助运营人员监控所有系统,仪表盘加载时间减少 80%

5. **输出结构**:改造后的路线图需包含:
   - 按季度/阶段列出的原始举措
   - 每项举措对应的成果陈述
   - 标志成功的关键指标
   - 依赖关系或排序说明

6. **加入战略上下文**:对整体路线图,补充:
   - 各成果如何与公司战略对齐
   - 关于客户需求的关键假设
   - 灵活的发布窗口(用季度,而非具体日期)

7. **保存输出**:如果内容较多,保存为 markdown 文档:`Outcome-Roadmap-[year].md`

## 备注

- 成果应该是可检验、可衡量的
- 多个产出可以达成同一个成果;关注成果,而不是功能清单
- 成果导向的路线图对变化更有韧性——拥抱灵活性
- 如果不确定某个功能带来什么成果,不断追问"所以呢?",直到抵达真正的客户/业务价值
