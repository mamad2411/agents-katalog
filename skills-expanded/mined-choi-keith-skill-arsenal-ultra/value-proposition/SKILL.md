# 价值主张

## 元数据
- **名称**: value-proposition
- **描述**: 使用 JTBD 框架的六段式模板生成详尽的价值主张。包含设计有说服力的客户价值的实用示例。
- **触发词**: 价值主张、客户价值、JTBD 价值、价值地图

## 指令

你是一位产品战略专家,正在为 $ARGUMENTS 设计清晰的价值主张。

你的任务是制定一份全面的价值主张,清晰阐述产品所交付的客户价值。

## 输入要求
- 产品描述与功能
- 目标客户细分及其问题
- 竞争替代品与现有解决方案
- 客户洞察或市场数据

## 价值主张模板

### 六段式结构

**1. 对象(Who)**
- 这个价值主张面向谁?
- 我们针对哪个客户细分?
- 他们的特征与约束是什么?

**2. 原因(Why,问题)**
- 客户的核心问题或需求是什么?
- 待办任务(JTBD)是什么?
- 他们想要实现哪些期望成果?

**3. 之前的状况(What Before)**
- 客户目前的处境如何?
- 他们如今用什么来解决这个问题?
- 现有方式存在哪些摩擦或痛点?

**4. 如何实现(How,解决方案)**
- 产品如何解决这个问题?
- 哪些具体功能或能力交付了价值?
- 为什么这个解决方案优于替代品?

**5. 之后的成果(What After)**
- 改善后的结果或未来状态是什么?
- 客户的生活/工作会发生怎样的变化?
- 哪些以前不可能的事变得可能?

**6. 替代方案(Alternatives)**
- 客户还可以使用哪些其他方案?
- 他们为什么会选择我们?
- 从替代方案转换过来的成本或摩擦是什么?

## 示例:Canva
- **对象(Who)**:需要制作营销图形的非设计师
- **原因(Why)**:他们需要专业观感的设计,但请不起设计师,也不会用复杂工具
- **之前的状况(What Before)**:用 PowerPoint、Photoshop(太复杂),或花高价请设计师
- **如何实现(How)**:拖拽式模板、内置设计元素、AI 设计辅助、直观的界面
- **之后的成果(What After)**:几分钟内做出专业设计,更快上线营销活动,节省设计成本
- **替代方案(Alternatives)**:Photoshop(复杂)、Fiverr(慢且贵)、Canva 的竞品(模板更少、体验更难用)

## 输出流程
1. 识别并描绘目标客户细分
2. 定义核心问题与 JTBD
3. 描述现状与摩擦点
4. 阐明产品如何解决问题
5. 构想改善后的成果
6. 与竞争替代品对比
7. 写出简洁的价值主张陈述(1-2 句话)
8. 形成可用于营销的定位陈述

### 领域背景

**本模板 vs Strategyzer 的价值主张画布**:Strategyzer 的画布(Alexander Osterwalder 提出)应用广泛,但存在结构性局限。这套六段式 JTBD 模板(Paweł Huryn 与 Aatir Abdul Rauf 提出)正是为解决这些局限:

- **客户优先**:本模板从客户(对象/原因)出发,再走向解决方案。Strategyzer 的画布把产品放在左侧,往往导致团队从自己的方案出发,而不是从客户的问题出发。
- **一次只做一个细分**:本模板按一次一个细分设计。Strategyzer 的画布鼓励同时映射多个产品/服务,容易稀释焦点。
- **明确的替代方案**:第 6 段(替代方案)迫使你写出没有你时客户会用什么,并阐明你为什么更好。Strategyzer 的画布没有对应板块——你不会直接面对替代品。
- **结构更简单**:"之前的状况 → 如何实现 → 之后的成果"比把客户任务、痛点、收益放一边、把痛点缓解、收益创造、产品放另一边更容易填写。那种拆分常让人困惑内容该填在哪。
- **可落地的产出**:最终的价值主张陈述可直接用于营销、销售和新用户引导。Strategyzer 的画布不会产出可复用的陈述。

当需要对成熟产品的复杂客户需求做细致的痛点/收益拆解时,使用 Strategyzer 的价值主张画布;当需要清晰、快速、可落地的产出时,使用这套六段式模板。

## 注意事项
- 待办任务(JTBD)框架关注客户想要取得的进展,而非人口统计特征
- 价值主张因细分而异;不同客户群体可能需要不同的价值主张
- 价值主张越强,营销、销售和产品决策就越容易
- 定稿前用真实客户验证价值主张
- 使用**价值曲线**(蓝海战略)在关键要素上直观地对比你与竞争对手
