# 测试场景

根据用户故事创建全面的测试场景,包含测试目标、前置条件、用户角色、分步测试操作和预期结果。

**适用场景:** 编写 QA 测试用例、创建测试计划、定义验收测试场景,或验证用户故事的实现。

**参数:**
- `$PRODUCT`:产品或系统名称
- `$USER_STORY`:要测试的用户故事(标题和验收标准)
- `$CONTEXT`:额外的测试上下文或约束

## 分步流程

1. **阅读用户故事**和验收标准
2. **定义测试目标** - 要验证的具体行为
3. **确定前置条件** - 系统状态、数据准备、配置
4. **识别用户角色** - 谁执行测试操作
5. **编写测试步骤** - 把交互拆成一步步的操作
6. **定义预期结果** - 每一步之后的可观察结果
7. **考虑边界情况** - 非法输入、临界条件
8. **输出详细的测试场景** - 可直接交给 QA 执行

## 测试场景示例

**测试场景:** 在产品页查看最近浏览的商品

**测试目标:** 验证"最近浏览"区域正确显示,且排除当前商品。

**前置条件:**
- 用户已登录或浏览器历史记录已启用
- 用户在当前会话中已浏览过至少 2 个商品
- 用户当前所在的产品页与之前浏览的商品不同

**用户角色:** 网购用户

**测试步骤:**
1. 打开任意产品页 → 页面底部应出现带之前浏览商品的区域
2. 滚动到页面底部 → "最近浏览"区域可见,展示商品卡片
3. 检查商品缩略图 → 图片、标题和价格正确显示
4. 检查当前商品 → 当前商品不在最近浏览列表中
5. 点击某张商品卡片 → 跳转到对应的产品页

**预期结果:**
- 最近浏览区域仅在浏览过至少 1 个商品后出现
- 区域显示 4-8 张信息完整的商品卡片
- 当前商品被排除在列表之外
- 每张卡片显示"X 分钟/小时前浏览"的时间戳
- 点击卡片跳转到正确的产品页
- 性能:区域在 2 秒内加载完成
