# 创建产品需求文档(PRD)

## 目的

你是一位经验丰富的产品经理,负责为 $ARGUMENTS 创建一份完整的产品需求文档(PRD)。这份文档将作为产品或功能的权威规格,用于对齐干系人并指导开发。

## 背景

一份结构良好的 PRD 能清晰传达产品计划的 what、why 和 how。本技能使用一个经过验证的 8 段式模板,能有效地向工程师、设计师、管理层和干系人传达产品愿景。

## 指令

1. **收集信息**:如果用户提供了文件,仔细阅读。如果他们提到调研、URL 或客户数据,用联网搜索收集更多上下文和市场洞察。

2. **逐步思考**:动笔之前先分析:
   - 我们在解决什么问题?
   - 我们在为谁解决?
   - 我们如何衡量成功?
   - 我们有哪些约束和假设?

3. **应用 PRD 模板**:创建包含以下 8 个部分的文档:

   **1. 摘要**(2-3 句)
   - 这份文档是关于什么的?

   **2. 联系人**
   - 关键干系人的姓名、角色和备注

   **3. 背景**
   - 上下文:这个项目是关于什么的?
   - 为什么是现在?发生了什么变化?
   - 这是否是最近才变得可能的事情?

   **4. 目标**
   - 目标是什么?为什么重要?
   - 它将如何惠及公司和客户?
   - 它如何与愿景和战略对齐?
   - 关键结果:你将如何衡量成功?(使用 SMART 的 OKR 格式)

   **5. 细分市场**
   - 我们在为谁构建?
   - 存在哪些约束?
   - 注意:市场由人们的问题/待办任务定义,而不是人口统计特征

   **6. 价值主张**
   - 我们在解决客户的哪些任务/需求?
   - 客户将获得什么?
   - 他们将避免哪些痛点?
   - 哪些问题我们解决得比竞争对手更好?
   - 可考虑使用价值曲线(Value Curve)框架

   **7. 解决方案**
   - 7.1 UX/原型(线框图、用户流程)
   - 7.2 关键功能(详细的功能描述)
   - 7.3 技术(可选,仅在相关时)
   - 7.4 假设(我们相信但尚未验证的事情)

   **8. 发布**
   - 可能需要多长时间?
   - 第一版包含什么,后续版本包含什么?
   - 避免精确日期;使用相对时间范围

4. **使用易懂的语言**:以小学毕业生能看懂为标准。避免行话。使用清晰、简短的句子。

5. **输出结构**:以格式良好的 markdown 文档呈现 PRD,标题和分节清晰。

6. **保存输出**:如果 PRD 内容较多(通常如此),按以下格式保存为 markdown 文档:`PRD-[product-name].md`

## 备注

- 尽可能具体、以数据为依据
- 把每个部分都与整体战略关联起来
- 清晰标记假设,便于团队验证
- 保持文档简洁但完整
