# 自媒体多平台发布编排器

对 `$ARGUMENTS` 执行完整的自媒体发布工作流。这是一个**编排器（Orchestrator）**，不亲自写每一个字，而是协调多个 skill 和 Agent 分工协作，走完"平台适配 → 内容创作 → 格式输出 → 封面生成"的全流程。

## 设计哲学

- **一次输入，多平台输出**：同一份研究/话题，按各平台规则自动适配
- **调度现有 skill**：不重复造轮子，研究用 finance-research，HTML 用 write-frontend-slides，封面用 SVG/HTML 直接生成
- **先确认再执行**：每个决策点都请用户确认，不在关键选择上自作主张
- **输出目录即交付物**：一个主题一个目录，里面包含该平台需要的所有文件

---


## 写作红线

1. **不虚构数据**。引用的数据必须有来源，搜不到就标注"估计"
2. **不用AI腔调**。禁止"让我们一起来看看"、"值得关注的是"、"不得不说"等套话
3. **不过度承诺**。技术文章不说"颠覆性的"、"革命性的"，用数据说话, 内容必须客观，不要带有主观情绪或夸大修饰
4. **公式必须配大白话**。每个公式后面都要有一段"翻译成人话就是……"
5. **公式必须用LaTeX**。`$$...$$` 格式，禁止纯文本公式
6. **配图必须实际插入**。论文解读类从PDF提取高清原图（≥500KB），禁止用 `[图X]` 占位符
7. **表格括号注释要精确**。描述概念时用准确的定义，不用模糊的动宾短语（如"文本来自教师"而非"学教师的文本"）
8. **类比要一以贯之**。全文用一个主线类比，不要每节换一个新类比
9. **结尾必须有传播力**。最后一句话要值得被单独截图转发

## 第一步：平台选择

向用户确认发布到哪个平台。不同平台的规则完全不同，这一步决定了后续所有行为。

```
请选择发布平台：
  [1] 微信公众号
  [2] 小红书
  [3] 抖音
```

### 平台规则速查

| 维度 | 微信公众号 | 小红书 | 抖音 |
|------|-----------|--------|------|
| **内容形态** | 长文 | 图文帖 | 口播脚本/字幕 |
| **推荐长度** | 按内容自然输出 | 按内容自然输出 | 按内容自然输出 |
| **排版风格** | 深度、结构化、章节分明 | 短段落、emoji 分隔、话题标签 | 钩子开头、快节奏、互动引导 |
| **图片需求** | 配图辅助理解（可选） | **图片是核心**（至少3-9张） | 封面图（16:9 竖版） |
| **标题重要性** | ⭐⭐⭐⭐⭐ 决定打开率 | ⭐⭐⭐⭐ 封面+标题共同决定 | ⭐⭐⭐⭐⭐ 前3秒决定停留 |
| **封面尺寸** | 900×383 (2.35:1) | 1080×1440 (3:4) | 1080×1920 (9:16) |
| **流量机制** | 订阅+社交传播 | 推荐算法+搜索长尾 | 推荐算法 |
| **内容调性** | 专业深度，有理有据 | 真实体验，有用/有趣/有颜 | 情绪驱动，快节奏 |

## 第二步：输出格式选择

确认平台后，询问用户要输出哪些格式（**支持多选**）：

```
请选择输出格式（可多选，如 "1,2"）：
  [1] 基础 Markdown——纯文本，不含图片/emoji，适合快速审阅和存档
  [2] 富媒体 Markdown——排版丰富，包含配图、emoji、表格、引用等，适合直接发布
  [3] HTML 幻灯片——由 write-frontend-slides 生成的精美 HTML，适合演示和展示
```

### 各格式的处理方式

**格式1 — 基础 Markdown**：
- 输出文件：`{主题}/basic.md`
- 不内嵌图片，图片位置用 `<!-- TODO: 插入配图：{描述} -->` 占位
- 不使用 emoji、不使用彩色标记、不添加引用块金句
- 纯文字+表格，专注内容质量
- 适合作为其他格式的"源稿"或者快速审阅和存档

**格式2 — 富媒体 Markdown**：
- 输出文件：`{主题}/rich.md`（**必须用 rich.md，区别于 basic.md 源稿**）
- 配图实际嵌入，资源文件放 `{主题}/assets/`
- **这是大多数场景的默认推荐格式**

**富媒体排版增强清单（生成 rich.md 时必须逐条执行）**：

| # | 增强项 | 具体做法 |
|---|-------|---------|
| 1 | **视觉分隔** | 章节之间用 `---` 分隔线隔开，重要转折处加 emoji 引导（📍🔥💡⚠️✅） |
| 2 | **关键数字高亮** | 核心数据用 `**粗体**` 包裹。利润增速、跌幅、市值等"冲击性数字"必须加粗 |
| 3 | **引用块提炼金句** | 每个章节至少一条 `>` 引用块，提炼该节最核心的一句话判断。读者滑屏时只看引用块就能理解全文 |
| 4 | **表格风格化** | 表头加粗，数值列居中对齐。关键对比行（如"合计"、"同比"）用 `**粗体**` 突出 |
| 5 | **数据标注色彩** | 上升/利好用 `<span style="color:red">`（红涨），下降/改善用 `<span style="color:green">`（绿跌），预警用 `<span style="color:orange">⚠` |
| 6 | **短段落** | 手机端每段不超过4行。数据密集处用 bullet points 拆解 |
| 7 | **开篇钩子** | 文章前200字必须用反常识数字或反差结论抓住注意力 |
| 8 | **结尾传播句** | 文章最后一句话必须值得被单独截图转发——用 `>` 引用块 + `**粗体**` 突出 |

**生成 rich.md 的执行流程**：

1. 从源稿（`{主题}投资研究报告.md` 或 skill 输出）提取全部内容
2. 按平台适配改写（→ 3.4）
3. 逐条执行"富媒体排版增强清单"
4. 去 AI 感（→ 3.5）
5. 输出为 `rich.md`

**格式1 → 格式2 的对比示例**：

basic.md（基础版）：
```
小米2025年营收4,573亿元，同比增长25%。经调整净利润392亿元，增长44%。

智能手机收入1,864亿元，IoT收入1,232亿元，汽车收入1,033亿元。
```

rich.md（富媒体版）：
```
📍 **2025年，小米交出了一份"炸裂"的成绩单。**

> **营收4,573亿（+25%），经调整净利润392亿（+44%）——双双创历史新高。**

| 分部 | 收入 | 增速 | 毛利率 |
|------|:----:|:----:|:-----:|
| 智能手机 | **1,864亿** | -2.8% | 10.9% |
| IoT | **1,232亿** | 🔴 +18.3% | 23.1% |
| 智能汽车 | **1,033亿** | 🔴 +224% | 24.3% |
| 互联网 | **374亿** | 🔴 +9.7% | **76.5%** |

---
```

**格式3 — HTML 幻灯片**：
- 调用 `write-frontend-slides` skill 生成
- 输出文件：`{主题}/index.html`
- 适合做 presentation、信息图、视觉化展示
- 保留源 markdown 在同目录下

## 第三步：内容创作

这是编排器的核心步骤。根据用户输入的类型，走不同的创作流程。

### 3.1 判断输入类型

分析 `$ARGUMENTS`，判断属于哪种情况：

| 输入类型 | 示例 | 处理方式 |
|---------|------|---------|
| **Skill/Command 调用** | `/finance-research:company 腾讯` | → 3.2 调度已有 skill |
| **公司/行业研究** | `腾讯控股深度分析` | → 3.2 调度已有 skill（自动匹配最合适的） |
| **通用话题** | `如何成为一名优秀的产品经理` | → 3.3 直接写作 |

### 3.2 调度已有 Skill（输入涉及研究/分析时）

当输入可以用已有 skill 处理时，**优先复用已有内容**，编排器负责后续的平台适配和格式转换。

**可用 Skill 路由表**：

| 输入特征 | 调用的 Skill/Command | 说明 |
|---------|---------------------|------|
| 公司研究/分析 | `/finance-research:company {公司}` | 四大师综合分析 |
| 行业研究 | `/finance-research:industry {行业}` | 产业链全景扫描 |
| 财报解读 | `/finance-earnings:review {公司} {季度}` | 一手资料深度解读 |
| 当前持仓审视 | `/finance-portfolio:review` | 组合管理与优化 |
| 投资论文检查 | `/finance-portfolio:track {公司}` | 买入后的纪律系统 |
| 新闻归因 | `/finance-portfolio:news {公司}` | 股价异动快速归因 |
| 管理层研究 | `/finance-research:management {公司}` | 买股票就是买人 |
| 四大师并行 | `/finance-research:team {公司}` | 多Agent并行研究 |

**源稿获取策略（先查已有，再生成）**：

在调用任何 skill 重新生成内容之前，**必须先检查 `reports/` 目录下是否已有相关的研究报告或分析文档**。

**Step 0 — 查找已有内容**：

使用 `find` 或 `ls` 搜索 `reports/` 目录，匹配与当前主题相关的已有文件：

```bash
# 查找与主题相关的已有报告
find reports/ -type f \( -name "*.md" -o -name "*.html" \) | head -30
# 或用关键词搜索
grep -rl "{主题关键词}" reports/ --include="*.md" | head -10
```

匹配逻辑：
- 公司研究 → 查找 `reports/{公司名}*` 或包含公司名的目录
- 行业研究 → 查找 `reports/{行业名}*`
- 财报分析 → 查找 `reports/{公司名}-earnings-*`
- 关键词模糊匹配 → 用公司名/行业名在 `reports/` 下 grep

**决策树**：

```
找到已有内容？
  ├── 是 → 读取已有文档作为源稿基座
  │        ↓
  │   评估内容质量：
  │     - 内容是否完整？（覆盖核心分析维度）
  │     - 数据是否过时？（超过3个月的财务数据需更新）
  │     - 结论是否仍然有效？
  │        ↓
  │     ├── 内容优质且新鲜 → 直接作为源稿，跳过 skill 调用
  │     │   （在报告中标注"基于 {日期} 生成的 {skill名} 研究报告改编"）
  │     │
  │     ├── 内容优质但部分过时 → 以已有文档为基座
  │     │   - 保留：商业模式分析、护城河评估、管理层评估（变化慢）
  │     │   - 更新：财务数据、估值指标、近期事件（变化快）
  │     │   - 用 WebSearch 补充最新数据和事件
  │     │   （在报告中标注"基于 {日期} 报告更新，更新了财务数据和近期事件"）
  │     │
  │     └── 内容不完整或质量不佳 → 调用 skill 重新生成
  │         （但仍可参考已有内容作为补充素材）
  │
  └── 否 → 调用 skill 重新生成源稿（原流程）
```

**润色与改造原则**：

当基于已有文档进行改造时，遵循以下原则：

1. **只做加法，不做减法**：skill 生成的内容（尤其是数据、分析框架、估值计算、风险清单等）**不得删减**。只能在原有内容基础上润色表达、丰富细节、补充最新信息
2. **保留所有数据层面的内容**：财务表格、估值数据、产量数据、行业对比数据等必须完整保留。可以调整呈现方式（如把段落改成表格），但数据本身不能丢弃
3. **保留核心分析框架**：商业模式、护城河、管理层评估等深度分析内容尽量保留，这些是 skill 的核心产出，质量通常较高
4. **更新时效性数据**：财务数据、股价、估值、近期事件等必须更新到最新
5. **按平台要求重塑表达**：不是简单改写，而是按照目标平台的读者期待重新组织叙事结构——但表达方式变了，信息量不能变少
6. **保持观点一致性**：如果已有文档有明确的投资结论，新文章应该保持观点一致（除非基本面发生了重大变化）
7. **标注来源**：在文章末尾明确标注源稿的生成日期和来源 skill
8. **上下文连贯**：确保上下文逻辑连贯，避免出现前后矛盾的表述

**核心原则：skill 生成的研究内容是"原料"——编排器的工作是加工和呈现，不是筛选和丢弃。每一组数据、每一个分析维度都有价值，不能因为字数或风格原因砍掉。**

**示例**：

```
用户输入：/write-social:publish 腾讯  → 目标平台：微信公众号

Step 0：find reports/ -type d -name "*腾讯*"
  → 找到 reports/腾讯投资研究报告.md（3天前由 finance-research:company 生成）

Step 1：读取已有报告
  → 内容完整（八步分析齐全），数据新鲜（3天前），结论明确
  → 决策：以已有报告为基座，直接进入平台适配改写

Step 2：按微信公众号风格改写（→ 3.4）
  - 保留：生意本质分析、护城河评估、管理层评估、风险清单
  - 调整：从"研究报告"叙事转为"公众号深度文章"叙事
  - 增强：开头钩子、金句埋点、传播力结尾

Step 3：去 AI 感（→ 3.5）

Step 4：格式输出（→ 第四步）
```

**执行流程**（已有内容基座模式）：

1. **查找已有内容**（Step 0）：在 `reports/` 下搜索与主题匹配的已有文档
2. **评估与决策**：判断已有内容是否可作为基座，还是需要重新生成
3. **以基座为基础进行改造**（→ 3.4）：将已有文档按平台规则改写
   - 如已有内容需要更新，先用 WebSearch 补充最新数据
   - 保留深度分析部分，重塑表达形式
4. **富媒体排版增强**（格式2必做）：逐条执行"富媒体排版增强清单"（→ 第二步格式2），生成 rich.md
5. **去 AI 感**（→ 3.5）：执行去 AI 感检查
6. **确认交付**：向用户展示文件清单，生成 SVG 图表（如有需要）

**执行流程**（无已有内容，重新生成模式）：

1. **调用 skill 生成源稿**：将 `$ARGUMENTS` 转发给匹配的 skill，拿到原始研究报告
2. **平台适配改写**（→ 3.4）：将研究报告按平台规则改写成适合发布的文章
3. **富媒体排版增强**（格式2必做）：逐条执行"富媒体排版增强清单"（→ 第二步格式2），生成 rich.md
4. **去 AI 感**（→ 3.5）：执行去 AI 感检查
5. **确认交付**：向用户展示文件清单，生成 SVG 图表（如有需要）

**执行流程**（/finance-writing:company-series 等系列 skill 调用时）：

此类 skill 输出为多篇系列文章（01/02/03...md）。编排器**不是只做二传手**——拿到 skill 输出的系列后，必须执行以下额外处理：

1. **skill 输出作为源稿基座**：系列文章已包含深度分析和数据，直接作为素材
2. **逐篇做富媒体排版增强**：系列中的每篇文章（01/02/03...）都按格式2的"富媒体排版增强清单"处理
3. **跨篇一致性检查**：确保总市值、净利润、关键持股比例等数字在全系列中一致
4. **输出 rich.md**：将排版增强后的系列文章输出到 `reports/{主题}/` 目录
   - 源稿保留为 `01-xxx.md` / `02-xxx.md` 等
   - 各篇的富媒体版本覆盖写入同名文件，确保格式统一

### 3.3 直接写作（通用话题时）

当输入是通用话题、不涉及专业研究时，编排器**亲自组织写作流程**。

**同样遵循"先查已有，再生成"原则**：

1. **查找已有内容**：在 `reports/` 下搜索与话题关键词匹配的已有文档。如果找到相关的已有文章，以它为基座进行润色和改造，而非从零开始
2. **话题拆解**（如无已有内容）：将用户话题拆解为文章大纲（6-8个章节），列出需要覆盖的关键点
3. **资料搜索**：使用 WebSearch 搜索相关资料、数据、案例（至少3轮搜索，覆盖不同角度）。如有已有内容，优先搜索"最新进展"和"补充数据"而非全量搜索
4. **写作 Agent**：启动一个专注写作的 Agent，生成初稿。如有已有内容作为基座，Agent 的 prompt 应明确要求"基于已有内容进行润色改造"而非"从零创作"

   Agent prompt 中必须包含：
   - 目标平台的所有写作规则（风格、结构）
   - 要求数据有出处，禁止编造
   - 要求有核心观点，不写流水账
   - **如有基座文档**：明确告知"以下是已有的源稿，请在此基础上润色改造，保留核心观点和深度分析，更新过时数据"

5. **审核**：初稿完成后，编排器自己审核一遍：
   - 数据是否有来源标注？
   - 逻辑是否连贯？
   - 是否还有 AI 腔？

### 3.4 平台适配改写规则

无论从哪个来源拿到源稿，都需要按平台规则改写。以下是各平台的改写指令：

**微信公众号改写指令**：
```
你是资深公众号作者。将以下素材改写为一篇适合微信公众号发布的深度文章。

## 改写要求
- 标题：15-25字，包含数字或反直觉结论，能在朋友圈吸引点击
- 开头（前3段）：用数据冲击力或反直觉结论做钩子，3段内必须让读者觉得"这篇文章不一样"
- 结构：清晰的章节标题（用 ## 标记）
- 深度：不是简单复述素材，要给出你的分析和判断——"这意味着什么"
- 节奏：数据段落→解释段落→判断段落 交替出现，避免连续3段纯文字
- 结尾：一句有传播力的判断收束，适合被截图转发
- 金句：至少埋3句可以被读者划线的金句
```

**小红书改写指令**：
```
你是小红书资深博主。将以下素材改写为一篇小红书图文帖。

## 改写要求
- 封面标题（标题栏）：10-15字，要有钩子感（如"搞懂这7个指标，避开90%的烂公司"）
- 正文风格：
  - 短段落，每段不超过3行
  - 用 emoji 做视觉分隔（📍🔥💡⚠️✅）
  - 大量使用小标题 + bullet points
  - 每200-300字配一个"💡一句话总结"
- 话题标签：文末附5-8个相关话题标签（#价值投资 #选股技巧 ...）
- 互动引导：文末加一句引导评论/收藏的话
- 图片规划：标注哪些位置需要配图，配图内容是什么
```

**抖音改写指令**：
```
你是抖音短视频策划。将以下素材改写为一期口播类短视频脚本。

## 改写要求
- 黄金3秒开头：用一句让人"停住不划走"的话开头（反直觉结论/悬念/数字冲击）
- 脚本结构：痛点抛出 → 核心观点 → 3个论据 → 一句话总结
- 节奏：快。每15-20秒一个信息点，不允许有"废话时间"
- 口语化：像在跟朋友聊天，不用书面语
- 互动引导：脚本末尾加"你觉得呢？评论区聊聊"类互动引导
- 总时长：控制在90-180秒
- 字幕提示：标注需要加粗强调的关键词（用 **加粗** 标记）
```

### 3.5 去 AI 感（必须执行）

改写完成后，执行以下去 AI 感检查：
- 删除所有 "值得注意的是"、"不得不说"、"让我们一起来看看" 等套话
- 删除冗余的过渡句（"接下来我们来看..."、"综上所述..."）
- 把 "进行" → 直接动词（"对XX进行分析" → "分析XX"）
- 删除夸大的修饰（"革命性的"、"颠覆性的"）
- 检查是否有连续3句以上以"的"结尾的句子（调整句式）
