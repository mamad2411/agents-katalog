# 用户故事

按照 3 C(Card、Conversation、Confirmation)和 INVEST 标准创建用户故事。生成包含描述、设计链接和验收标准的故事。

**适用场景:** 编写用户故事、把特性拆分为故事、创建待办事项,或定义验收标准。

**参数:**
- `$PRODUCT`:产品或系统名称
- `$FEATURE`:要拆分的新特性
- `$DESIGN`:设计文件链接(Figma、Miro 等)
- `$ASSUMPTIONS`:关键假设或上下文

## 分步流程

1. **基于提供的设计和上下文分析特性**
2. **识别用户角色**和不同的用户旅程
3. **应用 3 C 框架:**
   - Card:简单标题加一句话描述
   - Conversation:对意图的详细讨论
   - Confirmation:清晰的验收标准
4. **遵循 INVEST 标准:** Independent(独立)、Negotiable(可协商)、Valuable(有价值)、Estimable(可估算)、Small(小)、Testable(可测试)
5. **使用小学毕业生也能看懂的平实语言**
6. **链接设计文件**作为视觉参考
7. **以结构化格式输出用户故事**

## 故事模板

**标题:** [特性名称]

**描述:** 作为 [用户角色],我希望 [做什么],从而 [获得什么价值]。

**设计:** [设计文件链接]

**验收标准:**
1. [清晰、可测试的标准]
2. [可观察的行为]
3. [系统正确校验]
4. [边界情况处理]
5. [性能或可访问性考量]
6. [集成点]

## 用户故事示例

**标题:** 最近浏览区域

**描述:** 作为网购用户,我希望在产品页看到"最近浏览"区域,以便轻松回看我看过的商品。

**设计:** [Figma 链接]

**验收标准:**
1. 对于此前浏览过至少 1 个商品的每位用户,"最近浏览"区域显示在产品页底部。
2. 对于本次会话中首次访问产品页的用户,不显示该区域。
3. 当前商品本身不出现在展示列表中。
4. 该区域展示带图片、标题和价格的商品卡片或缩略图。
5. 每张商品卡片标注浏览时间(如"5 分钟前浏览")。
6. 点击商品卡片跳转到对应的产品页。

## 交付物

- 该特性的完整用户故事集合
- 每个故事包含标题、描述、设计链接和 4-6 条验收标准
- 各故事相互独立,可以任意顺序开发
- 各故事的粒度适合一个 sprint 周期
- 各故事引用相关设计文档
