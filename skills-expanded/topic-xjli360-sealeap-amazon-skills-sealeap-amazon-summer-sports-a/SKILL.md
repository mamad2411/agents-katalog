# SeaLeap 夏季体育赛事广告规划

把体育兴趣转成具体消费者任务，再对齐可售商品、当地活动和预算。赛事与大促可以共用准备工作，但需要独立的时间窗口和效果判断。

## 输入

活动年份及官方日程、目标站点和时区、商品/ASIN、真实功能与权利证据、库存与交期、当地搜索/受众信号、广告资格、素材资源、预算和利润约束。

## 工作流

1. 核对赛事和促销的真实日期，判断当前是准备、执行还是复盘。课件注明时间轴是示意，不据此默认两次峰值发生在同一月份。
2. 从球迷服饰/配饰、观赛派对用品、观赛电子三条路线筛选本品相关的实际场景，再逐站验证需求、规格和可售性。
3. 建立关键词及本地化页面计划。英语高绩效词作为候选输入，AI 翻译和 ABA 等数据共同校准；场景图放在当前类目与广告规范允许的位置。
4. 给 AI 提供商品事实、品牌/活动权利、消费者任务、语言和格式，生成候选简报。逐项复核功能、图像商品细节、商标、音乐和活动表述，不把 AI 工具当成版权或审核保证。
5. 分开设置各国预算，按资格选择 SP/SB/SBV、展示广告和 AMC 实验。高意向受众在 SP 的应用是加价机制时，不宣称仅投该受众。
6. 按赛前准备、冲刺和赛中执行安排任务，并另列赛后常态内容、库存及复盘；每轮保留一个主要实验变量。

## 交付

双窗口日历、站点—场景—商品矩阵、关键词与创意简报、素材权利/事实核查、逐国预算、受众实验卡和赛后计划。

## 证据与执行范围

- 材料中的案例、比例和时间表标为 `COURSE_BASELINE` 或 `TRAINING_CASE`；来源与口径已核验的店铺数据标为 `ACCOUNT_FACT`，用户转交但未核验的数据标为 `USER_PROVIDED`，合成练习标为 `SIMULATED`。推断标为 `HYPOTHESIS`，缺失项写 `UNKNOWN`，不补成 0。
- 先固定店铺、广告 profile、站点、ASIN、币种、数据窗口与归因口径。课程介绍的资格、界面、报告字段和功能覆盖在实际使用时核验。
- 默认交付诊断与草案。真实写入只在当前会话已授权的对象、动作和预算内执行，并保存旧值与回读结果；新增范围先取得授权。
