# Technical Design Documentation

Read [../../workflows/technical-design-documentation.md](../../workflows/technical-design-documentation.md) before starting.

Use this skill for future-state change design, not steady-state service documentation. Keep the design doc as the canonical artifact, compare meaningful options before choosing one, preserve useful existing structure when revising, and only publish to Confluence when the user explicitly asks.
