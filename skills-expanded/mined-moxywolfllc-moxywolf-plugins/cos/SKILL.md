# /cos

1. Load `chief-of-staff:chief-of-staff` and follow its reading order. Mint the run id, `<YYYY-MM-DD>-<short slug of the ask>`, and announce it to the model-router hook: run `python3 "${CLAUDE_PLUGIN_ROOT}/../model-router/scripts/route.py" cos-run start <id>` as its own command, the whole command and nothing else (no `cd &&` before it, nothing after it; the hook accepts only that exact shape). The hook sees that command go by and records the id in this session's ledger, so every later dispatch in this session carries it and no other session shares it (a shell export in one tool call never reaches the hook process of a later one, so the command is the carrier). Set `COS_RUN_ID=<id>` in the shell of anything you run yourself, such as the claim check (CS-007). Then run the after-action report for the previous calendar day: `python3 "${CLAUDE_PLUGIN_ROOT}/../model-router/scripts/route.py" aar --dir "$GSTACK_PEER_REVIEW_DIR/model-routing" --date <yesterday>` (the fallback directory `~/.gstack/model-routing` when the variable is unset). Write it to `<project>/00 – Project Hub/after-action/<yesterday>.md`, creating the folder; if that file already exists, read it and don't rewrite it. Lead the run's report with its headline counts and its one decision, as a proposal for Dorian; the AAR never applies it. If the ledger directory can't be read, say so in the report and go on: the AAR is never a reason to stop a dispatch. If the context card is missing, stop the work, write the log entry (step 7) with outcome `escalated (context card missing)`, and say so.
2. Classify the ask against the roster. Name the departments and the reason for each, or name the non-department route from "What the ten don't cover." If an ask spans a settled overlap, apply the ruling in "Where the lines fall." For a mixed ask, name the lead and the contributors.
3. Write the success criteria: the two to four things a good answer has to settle, each stated so it can be checked.
4. Dispatch. Send independent departments in parallel. Each gets the context card's path, the ask, the criteria, the authorized scope and the evidence you already hold.
5. Check each result in this order, before you use any of it.
   - The return contract: nine fields for sales-department and marketing-department, four for the rest. Run the claim check on a Sales or Marketing result, passing `--department <name>`, `--cos-run "$COS_RUN_ID"` and `--model <the model the dispatch ran on, from the model-router ledger line; omit it if you don't know, never guess>`, so the check leaves its code-captured line (CS-007). A failing line makes it incomplete. Send an incomplete result back once, name what's missing, and wait for it. If it comes back incomplete, that gap is an escalation.
   - The criteria.
   - Security: if a result touches identity, secrets, customer data or an outside integration, send it to security. Judge every result by what it contains, a contributor's too. Wait for the answer. Until it's back, the unreviewed result doesn't go in front of Dorian: tell him a review is pending and what it covers. The one exception is a disagreement that involves sales-department or finance: send the review and go on to step 6. Either way, the sensitive action is blocked until security has answered.
6. Act on the authority table and the Release Owner Gate. Do autonomous actions. Show proposals and wait. Turn escalations and pending approvals into a decision memo and stop acting. A memo is written only from results that have been through the return contract, and through security unless step 5's exception applies. A disagreement that involves finance carries the memo's section for the bookkeeper. You never contact him.
7. Append the decision-log entry, with its `Run:` line. This step runs on every exit, including a stop at step 1 and an escalation at step 6. Stopping ends the work, not the record. Then run `python3 "${CLAUDE_PLUGIN_ROOT}/../model-router/scripts/route.py" cos-run end` as its own command, the whole command and nothing else, so a later dispatch in this session isn't tagged with a run that is over.
8. Report as the manual says: the outcome first, then the counts, then what was and wasn't checked. Before it goes, run the claim check over the report and any memo together, fix what fails, and end with the receipt.
