# G検定（JDLA Deep Learning for GENERAL）

**先に `question-authoring` スキル（共通ルール・適用手順）を読むこと。** ここは試験固有の情報だけ。

準拠シラバス: **「G検定 試験出題範囲（シラバス 2024）」第1.2版（2024年9月20日）／2024年11月試験（G2024#6）より適用**。2026年7月時点でこれが最新。
原本: https://www.jdla.org/download-category/syllabus/ （リポジトリにPDFは置いていない。中分類の正確な表記やキーワード全量が要るときは原本を引く）

⚠ **G検定のシラバスを非公式の書き起こし（対策ブログ、Qiita 等）から拾わない。** 実際に食い違っていた。例えば「AIに関する法律と契約」に `独占禁止法` が抜けていたり、「人工知能をめぐる動向」の中分類を「機械学習の歴史と背景」と書いていたり（公式は `5. 機械学習` / `6. ディープラーニング`）する。カテゴリ名は完全一致 JOIN なので、ずれると行が黙って落ちる。

## 🚫 個人情報保護法は範囲外（この問題集の最重要ルール）

ユウは**個人情報保護士を保有済み**なので、この問題集では**個人情報保護法を完全に除外する**。

- 除外するのは【法律・倫理分野】「AIに関する法律と契約」の**中分類「1. 個人情報保護法」だけ**。カテゴリ 9 自体は残す。
- 具体的に**書かない**テーマ: 個人情報保護法、GDPR、個人情報／個人データ／保有個人データ、個人識別符号、要配慮個人情報、仮名加工情報、匿名加工情報、第三者提供、利用目的、委託。
- カテゴリ 9 で**書いてよい**のは、著作権法／特許法／不正競争防止法／独占禁止法／AI開発委託契約／AIサービス提供契約 のみ。

**紛らわしい境界（判断済み）**: カテゴリ 10 の中分類「9. プライバシー」は**残す**。これは個人情報保護法（法律）ではなく AI 倫理の論点で、キーワードも `カメラ画像利活用ガイドブック` / `プライバシー・バイ・デザイン` と別物。ただしここで個人情報保護法の条文・定義に踏み込んだら除外ルール違反。プライバシー・バイ・デザインの考え方までに留める。

## 出題形式（公式確認済み）

- オンライン **100分 / 小問145問程度**、会場 120分 / 145問程度。多肢選択式。公式例題はすべて **4択**
- **1問あたり約41秒。** これが作問方針を決める。GCP PCA のような長いシナリオ問題を書かない。**問題文は1〜3文で終わらせる**
- 公式例題に多い形: **空欄補充型**（「〜できない（　）がある」）と「〜として最も適切な選択肢を1つ選べ」
- 合格ラインは**非公表**。合格率は概ね 77〜82%（2025〜2026年の公式発表値）
- 2026年から会場試験が追加され、会場のみの合格率は低め（2026年第2回で 64.83%）

## 解説の流儀

`asked` / `point` / `why_asked` / `kid` / `eg` / `terms` / `think` / `vs` / `opt` を付ける（`point` と `eg` は explanation-clarity の通り）。

- **`terms` が主役。** G検定は用語の弁別を問う試験なので、混同しやすい用語ペアを 2〜4 個入れる
- **`snippet` は基本使わない。** 概念中心の試験でコードを示す場面がほとんど無い。数式を見せたいだけなら `think` に書く
- **`code` 列もほとんど使わない。** 混同行列を読ませる、といった表が要る問題にだけ使う
- `vs` を厚くする。この試験の失点は「似た用語の取り違え」に集中する

## 図解（`viz`）— 統計図解ドリルの流儀を移植（2026-07-30〜）

`explanation_data.viz`（インラインSVG）は全区分共通で動く（描画は `RichExplanation` の「図で見る」、`eg` の直後）。**書き方・配色・PNG目視検証の手順は `question-authoring-stats` の「viz（図解SVG）の書き方」節にすべて従う**（viewBox 340×120〜150、静かな計器の配色、qlmanage でPNG化して全数目視、初稿の図は必ずどこか壊れている前提）。ここには G検定固有の方針だけ書く。

- **付ける対象は仕組み系に絞る。** 「なぜ効くか」に絵があるもの（勾配消失、CNNの畳み込み、Attention、正則化、ドロップアウト、混同行列と適合率/再現率、ROC、活性化関数の形、教師あり/なしの対比、次元削減）。**事実・歴史・法律系（ELIZA、著作権法、AIブーム年表）には無理に付けない** — 因果の背骨と同じで、無い所に足すと濁る
- **新規セットでは仕組み系はviz必須、既存セット(A〜E)への後付けは `|| jsonb_build_object('viz', ...)` の非破壊マージ**で足す（既存キーを消さない。question-authoring の UPDATE 雛形を使う）
- G検定で使う図の定番: 層を箱で並べて信号の太さが細る図（勾配消失）、2×2マス（混同行列・過誤）、S字/ReLUの曲線比較、点群と境界線（分類・過学習）、ネットワークの線の太さ（Attention）
- 統計と重なる概念（正規分布・標準化・相関など）は `stats-basics` に既に図があるので、**同じ構図を流用してよい**（DBから viz を引いてコピーし、文脈だけ直すのが速い）

トーンも統計ドリルと同じく**小学生でも分かるレベルに振り切る**（漢字は普通に使う）。試験対策だからと硬くしない — たとえと図で腹落ちさせてから `terms` で試験語彙に接続する。

大量（50問超）に作る・後付けするときは `question-authoring-stats` の「大量生産の型と教訓」（Sonnet並列＋別人監査の型）を再利用する。

## 計算が絡む問題には `calc`（手で計算してみる）

数式・数値が絡む問題（評価指標、正規分布68%、期待値、MSE、勾配、シグモイド等）には `calc` を付ける。**書き方は `question-authoring-stats` の「計算系解説の3段ロケット」に完全に従う**（読者の数学は小学校算数＋α前提。日本語→小さい数字で全ステップ→最後に記号版）。

## 内容の注意

### 頻出（非公式・複数ソースの一致。公式は頻度を出していない）

- CNN / RNN / LSTM・GRU / Transformer / Attention / BERT vs GPT
- AIの歴史: フレーム問題、シンボルグラウンディング問題、トイ・プロブレム、チューリングテスト、強いAI・弱いAI、第1〜3次ブーム、ELIZA、MYCIN
- 最適化: GD → SGD → モメンタム → RMSProp → **Adam（= モメンタム + RMSProp）** の進化順。L1（疎性・特徴量選択）と L2 の違い、ドロップアウト、バッチ正規化
- 生成AI（2024改訂で公式に追加された領域。出題増加の指摘が多い）: LLM、基盤モデル、Diffusion Model、VQ-VAE / β-VAE、NeRF、CLIP、RLHF、zero-shot

### 引っかけの定番（ここを問題にすると効く）

- **ロジスティック回帰は名前に反して分類手法**
- **k-means（クラスタリング・教師なし）と k-NN（分類・教師あり）は別物**
- PCA は次元削減であってクラスタリングではない
- Self-Attention と Encoder-Decoder(Source Target) Attention の別

### 評価指標は「計算」ではなく「場面判断」で問う

適合率 / 再現率 / F値 / 混同行列は最頻出。ただし公式例題を確認した範囲では **TP/FP/FN から数値を出させる算数問題は見当たらず**、定義選択・場面に応じた指標選択が中心。

- ○「がん検診で見逃しを避けたい。重視すべき指標は」→ 再現率
- ✗「TP=30, FP=15, FN=5 のとき適合率は」→ この試験の形ではない

### 時事の扱い

シラバス改訂（不定期・直近は2024年5月発表→11月適用）が実質的な最新動向の反映窓口。「先週のニュースがそのまま出た」という一次証言は確認できなかった。**シラバスに無い直近ニュースを問題にしない。**

法改正・国際動向（著作権法30条の4、EU AI Act のリスクベースアプローチ、AI事業者ガイドラインの開発者/提供者/利用者の3分類、人間中心のAI社会原則）は「テキスト外から出る」と対策サイトが繰り返し言うが、**一次ソースは無い**。カテゴリ 9 / 10 の範囲内なら書いてよいが、「頻出だから」と重心を寄せすぎない。

### 確度の低い巷説（真に受けない）

- 「倫理・法律が出題の4割」— 一次ソース無し。対策サイトが互いに引用しているだけ
- 「生成AI関連が19%」— 同上
- 2025年成立の**AI新法**（人工知能関連技術の研究開発及び活用の推進に関する法律）は、シラバス2024 に載っていない。**現行シラバス準拠なら出題しない**
