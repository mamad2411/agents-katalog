# 応用情報技術者試験（AP）サーバー系対策

**先に `question-authoring`（共通ルール・適用手順）を読むこと。** 解説の流儀とviz/calcの書き方は `question-authoring-g-kentei`（資格試験対策としての体裁）と `question-authoring-stats`（viz/calcの技術的な書き方）を踏襲する。ここは本問題集固有の情報だけ。

## この問題集の背景と領域分担

ユウは `linux-basics` ドリル（仕組み理解の教養ドリル、239問・38カテゴリ）を完走した後、「これで応用情報のサーバー系問題は攻略できるか」と聞かれ、こちらから「linux-basicsは土台にはなるが、稼働率計算・RAID・負荷分散/HA・プロトコル知識・セキュリティの数理・データベースはカバーしていない」と回答した。その回答を受けて、2026-08-02に本問題集を新設した。

**`linux-basics` との重複を絶対に避けること。** `linux-basics` が既にカバー済みの領域（OS/カーネルの役割分担、プロセス、ファイルシステム、権限、シェル、systemd、DNSの仕組み、SSHの公開鍵認証、ブートプロセス、仮想化とクラウドの基礎、コマンドの語源など）は本問題集では扱わない。本問題集は**Linux固有ではない、応用情報のサーバー・インフラ分野特有の知識**（下記6カテゴリ）に絞る。迷ったら `.claude/skills/question-authoring/scripts/db.sh query` で `linux-basics` の既存問題文を確認してから書く。

## この問題集の性格

`linux-basics`/`stats-basics` のような「教養ドリル」ではなく、**資格試験対策**（G検定と同じ位置づけ）。応用情報技術者試験の午前問題（四肢択一）の形式・難易度感に寄せる。ただし解説はこのアプリの流儀（小学生でも分かるレベルまで噛み砕く、`terms`・`vs`・`opt`）を踏襲し、丸暗記ではなく「なぜそうなるか」の理解を主役にする。特に**稼働率計算・RAID計算**は公式の丸暗記ではなく、計算の意味（なぜ並列なら稼働率が上がるのか、なぜRAID5はパリティで1台の故障に耐えられるのか）を先に説明してから計算に入る。

## 問題の形

- 4択 single。応用情報の午前問題の雰囲気（「〜として適切なものはどれか」「〜はどれか」）に寄せる。1〜3文で完結させる
- **稼働率・RAID計算問題は数値を実際に計算させる。** 数値は暗算しやすい範囲にする（例: 稼働率0.9と0.8の並列、RAID5で4台構成など）
- 誤答は「隣の概念」「ありがちな誤計算」を置く（直列と並列の稼働率式を取り違える、RAID1とRAID5の実効容量を混同する、SMTPとPOPの役割を逆にする等）
- `question-authoring` の「選択肢の作り方」を厳守（正解だけ長くしない、投げやりな誤答を作らない、位置参照で解説を書かない）

## 解説の流儀

G検定と同じキー構成（`asked`/`why_asked`/`kid`/`eg`/`terms`/`think`/`vs`/`opt`）に加え、計算問題には `calc`（question-authoring-stats の3段ロケット: 日本語で言う→小さい数字で全ステップ→最後に記号版）、仕組み系（RAID構成、負荷分散のActive-Active、公開鍵暗号の流れ、正規化前後のテーブル）には `viz`（question-authoring-stats のviz節に完全準拠: viewBox・配色・PNG目視検証手順）を付ける。

- `稼働率とシステムの信頼性`・`RAIDの仕組みと計算` は原則全問 `calc` 必須
- `RAIDの仕組みと計算`・`負荷分散と高可用性設計`・`セキュリティの数理と認証`（公開鍵暗号の流れ図）・`データベースの基礎`（正規化前後の表）は viz が特に効く。事実の列挙で終わる問題（プロトコルの役割一覧など）には無理に付けない

## 内容の注意

- **応用情報のシラバス（IPA公式）に忠実に。** 非公式のまとめサイトの用語だけで済ませず、迷ったら一次情報（IPA試験要綱・シラバス）で確認する
- 稼働率計算は「直列は掛け算で下がる、並列は『両方止まる確率』を1から引く」という因果を必ず `think` で説明してから式に入る
- RAID計算は「実効容量＝全体からパリティ/ミラー分を引いた分」という考え方を先に、数式は後
- データベースの正規化は「同じ情報を何度も書かなくて済むようにする」という動機を先に説明してから第1〜3正規形の話に入る（深入りしすぎない。応用情報の午前レベルに留める）
