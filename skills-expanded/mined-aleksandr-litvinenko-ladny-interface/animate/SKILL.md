# Создание анимаций

Практический навык с одной задачей: превратить запрос на движение в реализацию, которая выдержит строгую проверку. Он не проводит аудит кодовой базы (для этого есть `improve-animations`), не рецензирует diff (`review-animations`) и не ищет места, где можно добавить анимацию (`find-animation-opportunities`).

## Рабочая позиция

Вы — ведущий дизайн-инженер и самостоятельно создаёте анимацию. Ориентир — подход Эмиля Ковальски к интерфейсной анимации, тот же, который проверяет `review-animations`. Пишите так, чтобы пройти эту проверку с первого раза.

Есть два сценария ошибки, и первый хуже:

1. **Анимировать то, что анимировать не следует.** Фильтр ниже иногда должен приводить к нулю строк кода. Это правильный результат, а не уклонение от задачи.
2. **Анимировать нужный элемент неподходящими средствами**: `ease-in` на входе, `scale(0)`, keyframes для toast-уведомления, длительность, из-за которой выпадающее меню кажется медленным.

Не предлагайте набор вариантов движения на выбор. Примите решение, объясните его одной строкой и напишите код.

## Жёсткие правила

1. **Проходите последовательность по порядку.** Шаги 1 и 2 определяют, стоит ли продолжать. Не выбирайте кривую, пока не решили, нужна ли анимация вообще.
2. **Никаких приблизительных значений.** Любая кривая, длительность и конфигурация пружины берутся из таблиц ниже. Не придумывайте `cubic-bezier(0.4, 0, 0.2, 1)` только потому, что значение знакомо.
3. **Расширяйте систему токенов проекта, не создавайте параллельную.** Если уже есть `--ease-out` или шкала длительностей, используйте их. Дублирующая система — дефект.
4. **Поддержка reduced motion и ограничение hover входят в реализацию сразу**, а не добавляются позже.
5. **Выбирайте самый простой подходящий инструмент.** Не устанавливайте библиотеку анимаций ради fade-перехода.

## Последовательность разработки

### 1. Нужна ли здесь анимация?

| Частота | Решение |
| --- | --- |
| 100+ раз в день (горячие клавиши, открытие палитры команд) | **Никакой анимации. Никогда.** Остановитесь здесь. |
| Десятки раз в день (hover-эффекты, навигация по списку) | Только почти незаметное движение — быстрое и сдержанное, либо ничего |
| Время от времени (модальные окна, панели, toast-уведомления) | Стандартная анимация |
| Редко / при первом использовании (онбординг, успех, празднование) | Здесь уместен бюджет на выразительность |

**Действие с клавиатуры исключает анимацию без дополнительных обсуждений.** В Raycast нет анимации открытия и закрытия — и это правильно для действия, которое выполняют сотни раз в день.

Если запрос не проходит этот фильтр, скажите об этом прямо и не пишите анимацию. Вместо неё предложите вариант без движения: мгновенную смену состояния или статический визуальный сигнал.

### 2. Какую задачу решает движение?

Прежде чем продолжать, назовите одну из задач:

- **Обратная связь** — подтверждает, что интерфейс отреагировал на действие
- **Пространственная согласованность** — показывает, откуда элемент появился или куда ушёл
- **Индикация состояния** — делает смену состояния понятной
- **Смягчение резкого изменения** — связывает состояния, между которыми содержимое иначе «телепортировалось» бы
- **Объяснение** — показывает, как что-то работает (только маркетинг или онбординг)
- **Выразительность** — допустима *только* для редких событий или первого использования

Не можете назвать задачу? Не создавайте анимацию. «Так эффектнее» для часто видимого элемента — причина остановиться.

Проверьте и **функцию интерфейса**: данные, которые человек читает или с которыми работает, не должны двигаться ради украшения. Декоративный эффект, следующий за курсором, уместен на промостранице, но не на банковском графике, в отчёте или рабочей форме 1С.

### 3. Выберите самый простой подходящий инструмент

Идите сверху вниз и остановитесь на первом подходящем варианте.

| Задача | Инструмент |
| --- | --- |
| Hover, нажатие, цвет, переключение состояния через класс или атрибут | **CSS transition** |
| Вход при монтировании без JS-состояния | **CSS `@starting-style`** |
| Заранее заданное движение, которое должно оставаться плавным во время загрузки страницы | **CSS animation** (выполняется вне main thread) |
| Программное управление с производительностью CSS, без библиотеки | **WAAPI** (`element.animate()`) |
| Пружины, layout-анимации, анимации выхода, значения под управлением жестов | **Motion** (`motion.dev`) |

CSS-анимации устойчивее JS под нагрузкой: они выполняются вне main thread, тогда как анимация на `requestAnimationFrame` теряет кадры во время загрузки, выполнения скриптов или отрисовки. Используйте CSS для заранее заданного движения, JS — для динамического и прерываемого.

Если задаче нужен не эффект, а готовый *компонент* — toast-уведомление, drawer, command menu или dropdown, — остановитесь и вызовите `pick-ui-library`. Самодельные компоненты такого рода часто заканчиваются `<div>` вместо доступного dropdown и отсутствием управления фокусом.

### 4. Выберите свойства

- **Только `transform` и `opacity`.** Они не запускают layout и paint и выполняются на GPU. `width`/`height`/`margin`/`padding`/`top`/`left` запускают все три этапа. (`clip-path` — допустимое четвёртое свойство, см. RECIPES.md. `height` допускается только для accordion, где нет эквивалента на transform.)
- **Никогда не используйте `scale(0)`.** Начинайте с `scale(0.9–0.97)` + `opacity: 0`. Реальные объекты не появляются из математической точки.
- Для popover, dropdown, menu и tooltip задавайте **`transform-origin` в точке триггера** — в Base UI это `var(--transform-origin)`. **Модальные окна — исключение**: они не привязаны к триггеру и остаются по центру.
- **Проценты в `translate()`** считаются от размера самого элемента: `translateY(100%)` сдвигает его на собственную высоту независимо от содержимого. Это надёжнее жёстко заданных пикселей и не ломается из-за более длинных русских подписей.
- **В Motion используйте полную строку transform.** Сокращения `x`/`y`/`scale` не получают аппаратного ускорения и теряют кадры под нагрузкой:

```jsx
<motion.div animate={{ x: 100 }} />                          // drops frames under load
<motion.div animate={{ transform: "translateX(100px)" }} />  // hardware accelerated
```

- **Не управляйте transform дочернего элемента через CSS-переменную родителя**: это приводит к перерасчёту стилей для каждого потомка. Задавайте `transform` непосредственно на нужном элементе.

### 5. Easing и длительность — либо пружина

Выбирайте **easing** в таком порядке:

| Ситуация | Easing |
| --- | --- |
| Вход или выход | `ease-out` |
| Движение / морфинг элемента на экране | `ease-in-out` |
| Hover / смена цвета | `ease` |
| Постоянное движение (marquee, progress) | `linear` |
| По умолчанию | `ease-out` |

**Никогда не используйте `ease-in` в интерфейсе.** Он начинает медленно и задерживает именно тот момент, за которым следит человек. `ease-out` с длительностью 200 мс *ощущается* быстрее, чем `ease-in` с теми же 200 мс.

Встроенные CSS-кривые недостаточно выразительны. Используйте эти:

```css
--ease-out: cubic-bezier(0.23, 1, 0.32, 1);        /* strong ease-out for UI */
--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);    /* strong ease-in-out for on-screen movement */
--ease-drawer: cubic-bezier(0.32, 0.72, 0, 1);     /* iOS-like drawer curve (Ionic) */
```

Нужна другая кривая? Возьмите её с [easing.dev](https://easing.dev/) или [easings.co](https://easings.co/). Не составляйте её вручную.

**Длительность:**

| Элемент | Длительность |
| --- | --- |
| Обратная связь при нажатии кнопки | 100–160 мс |
| Tooltip, небольшой popover | 125–200 мс |
| Dropdown, select | 150–250 мс |
| Modal, drawer | 200–500 мс |
| Маркетинговая / объясняющая анимация | Может быть дольше |

**Интерфейсная анимация укладывается в 300 мс.** Dropdown с длительностью 180 мс ощущается отзывчивее, чем с длительностью 400 мс.

**Используйте пружину**, когда есть drag с инерцией, элемент должен ощущаться живым, жест можно прервать или развернуть либо декоративный эффект следует за курсором:

```js
{ type: "spring", duration: 0.5, bounce: 0.2 }        // Apple-style — easier to reason about
{ type: "spring", mass: 1, stiffness: 100, damping: 10 }  // traditional physics — more control
```

Держите `bounce` в диапазоне 0.1–0.3 и в большинстве рабочих интерфейсов обходитесь без него. Оставьте отскок для drag-to-dismiss и действительно игровых взаимодействий.

### 6. Прерывание и выход

- Для всего, что может срабатывать часто, используйте **CSS-переходы, а не keyframes**: toast-уведомления, переключатели и любые действия, которые можно повторить дважды за секунду. CSS-переход продолжает движение от текущего значения, а анимация на keyframes перезапускается с начала.
- Для жестов используйте **пружины**, потому что при прерывании они сохраняют скорость.
- **Выход повторяет путь входа.** Toast-уведомление, которое появилось снизу, уходит вниз. Симметричный путь делает swipe-to-dismiss очевидным.
- **Асимметричный тайминг уместен там, где человек принимает решение.** Намеренная фаза медленная (удержание для подтверждения: 2 с, `linear`), системная реакция быстрая (отпускание: 200 мс, `ease-out`).

### 7. Reduced motion и ограничения по типу указателя

Они входят в каждую реализацию.

```css
@media (prefers-reduced-motion: reduce) {
  .element { animation: fade 0.2s ease; } /* keep opacity/color, drop transform-based motion */
}

@media (hover: hover) and (pointer: fine) {
  .element:hover { transform: scale(1.05); } /* touch fires false hovers on tap */
}
```

```jsx
const reduce = useReducedMotion();
const closedX = reduce ? 0 : '-100%';
```

Reduced motion означает **меньше и мягче**, а не обязательно полное отсутствие переходов. Оставляйте opacity и смену цвета, если они помогают понять состояние; убирайте параллакс, автодвижение, сдвиги и масштабирование. Автовоспроизводимому медиа всё равно нужна видимая кнопка паузы.

## Никогда не выпускайте

Проверьте себя перед завершением. Любой пункт ниже автоматически блокирует результат в `review-animations`:

| Никогда | Вместо этого |
| --- | --- |
| `transition: all` | Перечислите конкретные свойства |
| Вход через `transform: scale(0)` | `scale(0.95)` + `opacity: 0` |
| `ease-in` на элементе интерфейса | `ease-out` или выразительная пользовательская кривая |
| Встроенный `ease-out` в заметной анимации | `cubic-bezier(0.23, 1, 0.32, 1)` |
| Анимация горячей клавиши или действия, выполняемого 100+ раз в день | Без анимации |
| Длительность интерфейсной анимации больше 300 мс без причины | 150–250 мс |
| `transform-origin: center` у popover, привязанного к триггеру | `var(--transform-origin)` (кроме модального окна) |
| Keyframes для toast-уведомлений, переключателей и часто срабатывающих элементов | CSS-переходы |
| Анимация `width`/`height`/`margin`/`padding`/`top`/`left` | `transform` / `opacity` |
| Свойства Motion `x`/`y`/`scale` под нагрузкой | Полная строка `transform` |
| Hover-движение без ограничения | `@media (hover: hover) and (pointer: fine)` |
| Нет `prefers-reduced-motion` | Более мягкий вариант, а не просто отключение смысла перехода |
| Все элементы входят одновременно | Stagger 30–80 мс |

## Формат результата

Напишите код. Затем не более чем в нескольких строках укажите:

- **Результат фильтра** — уровень частоты и названную задачу движения. Если часть запроса отклонена, скажите какую и почему.
- **Состав анимации** — инструмент, свойства, кривая, длительность или конфигурация пружины: по одной строке на пункт.
- **Что проверить визуально** — если ощущение нельзя оценить по коду (crossfade, отскок пружины, баланс opacity и height у входящего списка), назовите конкретную проверку: воспроизведите в 2–5 раз медленнее или откройте инспектор анимаций DevTools, пройдите покадрово, проверьте жест на реальном устройстве и вернитесь к результату на следующий день свежим взглядом. Для русской локализации отдельно проверьте длинные подписи и переносы.

Не превращайте это в отчёт. Результат работы — код.

## Тон

Говорите уверенно и кратко. Если честный ответ — «здесь не нужна анимация», так и скажите: ради этого навык и существует. Если ощущение действительно нельзя определить по коду, признайте это вместо того, чтобы угадывать значение.
