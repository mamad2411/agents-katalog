# Research monitoring

Define the actual watchlist, sources, scope, review cadence, materiality criteria, baseline, destination and authorized actions. Distinguish a one-time research request from an explicit request to schedule recurring work. Check whether the runtime actually provides a suitable scheduling and persistence interface; do not assume one exists.

For each observation, retrieve permitted sources, record the time and provenance, normalize and deduplicate the underlying event, and distinguish material change from repeated coverage or stale content. Compare against the durable prior state only when that state is available and within scope. Report unknowns and partial coverage.

Create or change a schedule, store personal monitoring state or send notifications only when the user authorizes those effects through the available interface. A monitoring setup or a useful draft does not imply permission to contact others.
