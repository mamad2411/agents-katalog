# Project Architecture Mapper
 
Produce a single, exhaustive `PROJECT_MAP.md` that makes any project immediately
understandable — its layers, connections, data flows, environment requirements,
known issues, and onboarding steps.
 
---
 
## Phase 1 — Discovery (Read Before Writing Anything)
 
### 1.1 Scan the project root
```bash
find . -maxdepth 3 \
  -not -path '*/node_modules/*' \
  -not -path '*/.git/*' \
  -not -path '*/dist/*' \
  -not -path '*/__pycache__/*' \
  -not -path '*/build/*' \
  -not -path '*/.next/*' \
  | sort
```
This reveals the high-level structure. Look for:
- Multiple top-level dirs → monorepo / multi-service setup
- Single dir with `src/` → monolithic app
- `docker-compose.yml` / `Makefile` / `turbo.json` → orchestration present
### 1.2 Detect tech stack
Read these files if they exist (adjust for language):
| File | What it reveals |
|---|---|
| `package.json` / `yarn.lock` | JS/TS stack, scripts, deps |
| `requirements.txt` / `pyproject.toml` | Python stack |
| `go.mod` | Go modules |
| `Cargo.toml` | Rust |
| `build.gradle` / `pom.xml` | Java/Kotlin |
| `pubspec.yaml` | Flutter/Dart |
| `Podfile` / `*.xcodeproj` | iOS native |
| `Dockerfile` / `docker-compose.yml` | containerization |
| `.env.example` / `.env.sample` | environment variables |
| `*.config.ts/js` (vite, next, webpack…) | build/framework config |
| `prisma/schema.prisma` / `*.sql` / `migrations/` | database schema |
| `openapi.yaml` / `swagger.json` / `graphql/*.graphql` | API contracts |
 
### 1.3 Find entry points
Look for:
- `main.ts/js/py/go`, `index.ts/js`, `app.py`, `server.ts`, `cmd/main.go`
- Framework-specific: `pages/_app.tsx` (Next.js), `App.tsx` (React Native/Expo),
  `main.dart` (Flutter), `AndroidManifest.xml` (Android), `AppDelegate.swift` (iOS)
### 1.4 Trace connections
For each layer found, identify HOW it talks to other layers:
- **Frontend → Backend**: REST calls, GraphQL queries, WebSocket, SDK
- **Backend → DB**: ORM models, raw queries, connection strings
- **Backend → External services**: SDKs, HTTP clients, env vars pointing to URLs
- **Mobile → Backend**: API base URL, auth token storage, offline sync
- **Services → Services** (if microservices): message queues, gRPC, internal HTTP
- **Auth flow**: JWT, OAuth, sessions — where tokens are issued, validated, stored
### 1.5 Spot issues during discovery
Flag anything that looks wrong:
- Frontend calls a URL not defined in the backend routes
- An env variable referenced in code but missing from `.env.example`
- A DB table used in code but not in the schema (or vice versa)
- CORS config that may block the frontend
- Hardcoded URLs / credentials
- Mismatched API versioning between consumer and provider
- Missing error handling on critical connections
