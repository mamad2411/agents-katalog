# 开发者成长分析

此技能通过分析您的 Claude Code 聊天互动并识别揭示优势和成长领域的模式，为您最近的编码工作提供个性化反馈。

## 何时使用此技能

当您想要执行以下操作时使用此技能：
- 了解您最近工作的开发模式和习惯
- 识别特定的技术差距或经常遇到的挑战
- 发现哪些主题需要更深入的学习
- 获取根据您的实际工作模式量身定制的精选学习资源
- 跟踪您最近项目的改进领域
- 查找直接解决您正在开发的技能的高质量文章

此技能非常适合那些希望在无需等待代码审查的情况下获得结构化反馈，并希望从自己的工作历史中获得数据驱动见解的开发人员。

## 此技能做什么

此技能对您的开发工作执行六步分析：

1. **读取您的聊天记录**：访问您过去 24-48 小时的本地 Claude Code 聊天记录，以了解您一直在从事的工作。

2. **识别开发模式**：分析您正在解决的问题类型、使用的技术、遇到的挑战以及您如何处理不同类型的任务。

3. **检测改进领域**：识别表明技能差距、反复挣扎、低效方法或可能受益于更深入知识的领域的模式。

4. **生成个性化报告**：创建一个包含您的工作摘要、确定的改进领域和具体的成长建议的综合报告。

5. **查找学习资源**：使用 HackerNews 策划与您的改进领域直接相关的高质量文章和讨论，为您提供根据您的实际开发工作量身定制的阅读列表。

6. **发送到您的 Slack 私信**：自动将完整报告发送到您自己的 Slack 直接消息，以便您随时随地查阅。

## 如何使用

要求 Claude 分析您最近的编码工作：

```
Analyze my developer growth from my recent chats
```

或者更具体地说明时间段：

```
Analyze my work from today and suggest areas for improvement
```

该技能将生成一份格式化的报告，其中包括：
- 您最近工作的概述
- 确定的关键改进领域
- 针对每个领域的具体建议
- 来自 HackerNews 的精选学习资源
- 您可以关注的行动项目

## 说明

当用户请求分析其最近工作的开发人员成长或编码模式时：

1. **访问聊天记录**

   从 `~/.claude/history.jsonl` 读取聊天记录。此文件为 JSONL 格式，也就是每行包含：
   - `display`：用户的消息/请求
   - `project`：正在进行的项目
   - `timestamp`：Unix 时间戳 (以毫秒为单位)
   - `pastedContents`：任何粘贴的代码或内容

   根据当前时间戳过滤过去 24-48 小时的条目。

2. **分析工作模式**

   从过滤后的聊天中提取并分析以下内容：
   - **项目和领域**：用户正在从事什么类型的项目？(例如，后端、前端、DevOps、数据等)
   - **使用的技术**：对话中出现了哪些语言、框架和工具？
   - **问题类型**：正在解决哪类问题？(例如，性能优化、调试、功能实现、重构、设置/配置)
   - **遇到的挑战**：用户在什么问题上挣扎？寻找：
     - 关于相似主题的重复问题
     - 需要多次尝试才能解决的问题
     - 表明知识差距的问题
     - 复杂的架构决策
   - **方法模式**：用户如何解决问题？(例如，有条理的、探索性的、实验性的)

3. **识别改进领域**

   根据分析，确定用户可以改进的 3-5 个具体领域。这些应该是：
   - **具体的** (不是像“提高编码技能”这样模糊的)
   - **基于证据的** (基于实际聊天记录)
   - **可操作的** (可以做出的实际改进)
   - **优先的** (最有效的优先)

   好的改进领域示例：
   - “高级 TypeScript 模式 (泛型、工具类型、类型守卫) - 您在 [特定项目] 中的类型安全方面遇到了困难”
   - “错误处理和验证 - 我注意到您修补了几个与缺少空值检查相关的错误”
   - “Async/await 模式 - 您最近的工作显示了一些竞争条件和时序问题”
   - “数据库查询优化 - 您多次重写了相同的查询”

4. **生成报告**

   创建一个具有以下结构的综合报告：

   ```markdown
   # 您的开发者成长报告

   **报告期间**: [昨天 / 今天 / [自定义日期范围]]
   **最后更新**: [当前日期和时间]

   ## 工作摘要

   [2-3 段总结用户从事的工作、接触的项目、使用的技术和总体重点领域]

   示例:
   "在过去的 24 小时里，您主要专注于三个不同项目的后端开发。您的工作涉及 TypeScript、React 和部署基础设施。您解决了一系列功能实现、调试和架构决策，特别关注 API 设计和数据库优化。"

   ## 改进领域 (按优先级排序)

   ### 1. [领域名称]

   **为什么这很重要**: [解释为什么此技能对用户的工作很重要]

   **我观察到的**: [来自聊天记录的具体证据显示此差距]

   **建议**: [在该领域改进的具体步骤]

   **技能提升时间**: [所需努力的简要估计]

   ---

   [重复 2-4 个额外领域]

   ## 观察到的优势

   [2-3 个要点突出您做得好的事情 - 要继续做的事情]

   ## 行动项目

   优先级顺序:
   1. [源自最高优先级改进领域的行动项目]
   2. [来自下一个领域的行动项目]
   3. [来自下一个领域的行动项目]

   ## 学习资源

   [将在下一步中填充]
   ```

5. **搜索学习资源**

   使用 Rube MCP 在 HackerNews 上搜索与每个改进领域相关的文章：

   - 对于每个改进领域，构建针对高质量资源的搜索查询
   - 使用 RUBE_SEARCH_TOOLS 搜索 HackerNews，查询如下：
     - "Learn [Technology/Pattern] best practices"
     - "[Technology] advanced patterns and techniques"
     - "Debugging [specific problem type] in [language]"
   - 优先考虑参与度高 (评论、点赞) 的帖子
   - 对于每个领域，包括 2-3 篇最相关的文章，包含：
     - 文章标题
     - 发布日期
     - 为什么相关的简要说明
     - 文章链接

   将此部分添加到报告中：

   ```markdown
   ## 精选学习资源

   ### 针对: [改进领域]

   1. **[文章标题]** - [日期]
      [说明它涵盖的内容以及为什么与您的改进领域相关]
      [链接]

   2. **[文章标题]** - [日期]
      [说明]
      [链接]

   [针对其他改进领域重复]
   ```

6. **展示完整报告**

   以清晰、可读的格式提供报告，以便用户可以：
   - 快速扫描关键要点
   - 用于重点学习规划
   - 在接下来的一周内致力于改进时参考
   - 如果他们想要外部反馈，可以与导师分享

7. **将报告发送到 Slack 私信**

   使用 Rube MCP 将完整报告发送到用户自己的 Slack 私信 (DMs)：

   - 通过 RUBE_SEARCH_TOOLS 检查 Slack 连接是否处于活动状态
   - 如果未连接，使用 RUBE_MANAGE_CONNECTIONS 启动 Slack 认证
   - 使用 RUBE_MULTI_EXECUTE_TOOL 将报告作为格式化消息发送：
     - 发送报告标题和期间作为第一条消息
     - 将报告分解为逻辑部分 (摘要、改进、优势、行动、资源)
     - 使用适当的 markdown 将每个部分格式化为结构良好的 Slack 消息
     - 包含学习资源的可点击链接
   - 在 CLI 输出中确认交付

   这确保用户在他们定期检查的地方拥有报告，并可以在整周内参考它。

## 示例用法

### 输入

```
Analyze my developer growth from my recent chats
```

### 输出

```markdown
# 您的开发者成长报告

**报告期间**: 2024年11月9日-10日

## 工作摘要

在过去的两天里，您专注于后端基础设施和 API 开发。您的主要项目是一个开源展示应用程序，您在连接管理、UI 改进和部署配置方面取得了重大进展。您使用了 TypeScript、React 和 Node.js，解决了从数据安全到响应式设计的一系列挑战。您的工作显示了在实现功能和解决技术债务之间的平衡。

## 改进领域 (按优先级排序)

### 1. 高级 TypeScript 模式和类型安全

**为什么这很重要**: TypeScript 是您工作的核心，但利用其高级功能 (泛型、工具类型、条件类型、类型守卫) 可以显着提高代码可靠性并减少运行时错误。更好的类型安全在编译时而不是生产中捕获错误。

**我观察到的**: 在您最近的聊天中，您正在处理连接数据结构，并在正确输入 auth 配置方面遇到了一些困难。您还必须为不同的连接状态迭代联合类型。这里有机会更有效地使用可区分联合和类型守卫。

**建议**: 学习 TypeScript 的高级类型系统，特别是工具类型 (Omit, Pick, Record)、条件类型和可区分联合。将这些模式应用于您的连接配置处理和 auth 状态管理。

**技能提升时间**: 5-8 小时的专注学习和练习

### 2. 安全数据处理和 UI 中的信息隐藏

**为什么这很重要**: 您识别并修复了一个安全问题，即敏感的连接数据显示在您的控制台中。防止信息泄露对于处理用户凭据和 API 密钥的应用程序至关重要。这里的良好实践可以防止安全事件和用户信任侵犯。

**我观察到的**: 您发现您的 "Your Apps" 页面显示了包括 auth 配置在内的完整连接数据。这显示了良好的安全直觉，下一步是将其构建到处理敏感信息时的默认思维中。

**建议**: 回顾在前端应用程序中处理敏感数据的安全最佳实践。创建可重用的模式，以便在显示之前过滤/屏蔽敏感信息。考虑实施一个显式白名单以控制可以在 UI 中显示的内容的安全数据层。

**技能提升时间**: 3-4 小时

### 3. 组件架构和响应式 UI 模式

**为什么这很重要**: 您正在设计需要在不同屏幕尺寸和用户交互中工作的 UI。强大的组件架构使得构建复杂的 UI 更容易，而且没有错误，并提高了可维护性。

**我观察到的**: 您致力于 "Marketplace" UI (以前是 Browse Tools)，根据设计图像重新创建它。您还识别并修复了内容溢出容器的滚动问题。这里有机会加强您对布局包含和响应式设计模式的理解。

**建议**: 学习 React 组件组合模式和 CSS 布局最佳实践 (特别是 flexbox 和 grid)。专注于容器查询和防止溢出问题的响应式模式。研究组件组合库和设计系统方法。

**技能提升时间**: 6-10 小时 (取决于深度)

## 观察到的优势

- **安全意识**: 您在数据泄露问题成为问题之前主动识别了它们
- **迭代改进**: 您有条不紊地处理 UI 需求，提出澄清问题并改进设计
- **全栈能力**: 您可以轻松地处理后端 API、前端 UI 和部署关注点
- **解决问题的方法**: 您将复杂的任务分解为可管理的步骤

## 行动项目

优先级顺序:
1. 花 1-2 小时学习 TypeScript 工具类型和可区分联合；应用于您的连接数据结构
2. 为您的项目记录安全模式 (哪些数据可以安全显示，过滤/屏蔽函数)
3. 学习一篇关于高级 React 模式的文章，并将一种模式应用于当前的 UI 工作
4. 为未来的 PR 设置专注于类型安全和数据安全的代码审查清单
```

## 提示和最佳实践

- 每周运行此分析一次，以跟踪您随时间的改进轨迹
- 一次选择一个改进领域，在转到下一个之前专注于它几天
- 使用学习资源作为学习指南；仔细研究推荐的材料并练习应用模式
- 在专注于某个领域一周后重新查看此报告，看看您的工作模式如何变化
- 学习资源是为您实际工作精心策划的，而不是通用主题，因此它们将与您正在构建的内容高度相关

## 如何保持准确性和质量

此技能：
- 更加时间戳的聊天记录分析您的实际工作模式
- 生成基于实际项目的有据可依的建议
- 策划直接解决您发现的差距的学习资源
- 专注于可操作的改进，而不是模糊的反馈
- 根据复杂性提供具体的时间估计
- 优先考虑对您的开发速度影响最大的领域
