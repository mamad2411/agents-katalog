# 内容研究写作助手

此技能充当您的写作伙伴，帮助您研究、列大纲、起草和完善内容，同时保持您独特的声音和风格。

## 何时使用此技能

- 撰写博客文章、文章或时事通讯
- 创建教育内容或教程
- 起草思想领导力文章
- 研究和撰写案例研究
- 制作带有来源的技术文档
- 撰写带有适当引用和参考的内容
- 改进开头 (Hooks) 和介绍
- 在写作时获得逐节反馈

## 此技能做什么

1. **协作列大纲**：帮助您将想法构建成连贯的大纲
2. **研究协助**：查找相关信息并添加引用
3. **改进开头**：加强您的开场白以吸引注意力
4. **部分反馈**：在您写作时审查每个部分
5. **声音保留**：保持您的写作风格和基调
6. **引用管理**：正确添加和格式化参考文献
7. **迭代完善**：帮助您通过多次草稿进行改进

## 如何使用

### 设置您的写作环境

为您的文章创建一个专用文件夹：
```
mkdir ~/writing/my-article-title
cd ~/writing/my-article-title
```

创建您的草稿文件：
```
touch article-draft.md
```

从该目录打开 Claude Code 并开始写作。

### 基本工作流程

1. **从大纲开始**：
```
Help me create an outline for an article about [topic]
```

2. **研究并添加引用**：
```
Research [specific topic] and add citations to my outline
```

3. **改进开头**：
```
Here's my introduction. Help me make the hook more compelling.
```

4. **获取部分反馈**：
```
I just finished the "Why This Matters" section. Review it and give feedback.
```

5. **完善和润色**：
```
Review the full draft for flow, clarity, and consistency.
```

## 说明

当用户请求写作协助时：

1. **了解写作项目**
   
   提出澄清问题：
   - 主题和主要论点是什么？
   - 目标受众是谁？
   - 期望的长度/格式是什么？
   - 您的目标是什么？(教育、说服、娱乐、解释)
   - 有任何现有的研究或来源需要包含吗？
   - 您的写作风格是什么？(正式、对话、技术)

2. **协作列大纲**
   
   帮助构建内容结构：
   
   ```markdown
   # 文章大纲: [标题]
   
   ## 开头 (Hook)
   - [开场白/故事/统计数据]
   - [为什么读者应该关心]
   
   ## 介绍
   - 背景和环境
   - 问题陈述
   - 这篇文章涵盖的内容
   
   ## 主要部分
   
   ### 第 1 部分: [标题]
   - 关键点 A
   - 关键点 B
   - 示例/证据
   - [需要研究: 具体主题]
   
   ### 第 2 部分: [标题]
   - 关键点 C
   - 关键点 D
   - 需要的数据/引用
   
   ### 第 3 部分: [标题]
   - 关键点 E
   - 反对论点
   - 解决方案
   
   ## 结论
   - 主要观点总结
   - 号召性用语 (Call to action)
   - 最后的想法
   
   ## 研究待办事项
   - [ ] 查找关于 [topic] 的数据
   - [ ] 获取 [concept] 的示例
   - [ ] 为 [claim] 寻找来源引用
   ```
   
   **迭代大纲**：
   - 根据反馈进行调整
   - 确保逻辑流畅
   - 识别研究差距
   - 标记需要深入探讨的部分

3. **进行研究**
   
   当用户请求对某个主题进行研究时：
   
   - 搜索相关信息
   - 查找可信来源
   - 提取关键事实、引语和数据
   - 按请求格式添加引用
   
   示例输出：
   ```markdown
   ## 研究: AI 对生产力的影响
   
   关键发现:
   
   1. **生产力提升**: 研究显示内容创作任务节省了 40% 的时间 [1]
   
   2. **采用率**: 67% 的知识工作者每周使用 AI 工具 [2]
   
   3. **专家引语**: "AI 增强而不是取代人类创造力" - Dr. Jane Smith, MIT [3]
   
   引用:
   [1] McKinsey Global Institute. (2024). "The Economic Potential 
       of Generative AI"
   [2] Stack Overflow Developer Survey (2024)
   [3] Smith, J. (2024). MIT Technology Review interview
   
   已添加到第 2 部分的大纲下。
   ```

4. **改进开头 (Hooks)**
   
   当用户分享介绍时，分析并加强：
   
   **当前开头分析**：
   - 哪些有效：[积极因素]
   - 哪些可以更强：[改进领域]
   - 情感影响：[当前 vs 潜在]
   
   **建议的替代方案**：
   
   选项 1: [大胆声明]
   > [示例]
   *为什么有效: [解释]*
   
   选项 2: [个人故事]
   > [示例]
   *为什么有效: [解释]*
   
   选项 3: [令人惊讶的数据]
   > [示例]
   *为什么有效: [解释]*
   
   **开头的问题**:
   - 它是否制造了好奇心？
   - 它是否承诺了价值？
   - 它是否足够具体？
   - 它是否匹配受众？

5. **提供逐节反馈**
   
   当用户编写每个部分时，审查：
   
   ```markdown
   # 反馈: [部分名称]
   
   ## 哪些运作良好 ✓
   - [优势 1]
   - [优势 2]
   - [优势 3]
   
   ## 改进建议
   
   ### 清晰度
   - [具体问题] → [建议修复]
   - [复杂句子] → [更简单的替代方案]
   
   ### 流程
   - [过渡问题] → [更好的连接]
   - [段落顺序] → [建议重新排序]
   
   ### 证据
   - [需要支持的主张] → [添加引用或示例]
   - [通用陈述] → [使其更具体]
   
   ### 风格
   - [语气不一致] → [更好地匹配您的声音]
   - [用词选择] → [更强的替代方案]
   
   ## 具体行编辑
   
   原文:
   > [草稿中的确切引语]
   
   建议:
   > [改进版本]
   
   原因: [解释]
   
   ## 需要考虑的问题
   - [发人深省的问题 1]
   - [发人深省的问题 2]
   
   准备好进入下一部分！
   ```

6. **保留作者的声音**
   
   重要原则：
   
   - **学习他们的风格**：阅读现有的写作样本
   - **建议，不要替换**：提供选项，而不是指令
   - **匹配语气**：正式、休闲、技术、友好
   - **尊重选择**：如果他们更喜欢他们的版本，支持它
   - **增强，而不是覆盖**：让他们的写作更好，而不是不同
   
   定期询问：
   - "这听起来像你吗？"
   - "这是正确的语气吗？"
   - "我应该更/更少 [正式/休闲/技术] 吗？"

7. **引用管理**
   
   根据用户偏好处理参考文献：
   
   **内联引用**:
   ```markdown
   Studies show 40% productivity improvement (McKinsey, 2024).
   ```
   
   **编号引用**:
   ```markdown
   Studies show 40% productivity improvement [1].
   
   [1] McKinsey Global Institute. (2024)...
   ```
   
   **脚注风格**:
   ```markdown
   Studies show 40% productivity improvement^1
   
   ^1: McKinsey Global Institute. (2024)...
   ```
   
   维护一个运行中的引用列表：
   ```markdown
   ## 参考文献
   
   1. Author. (Year). "Title". Publication.
   2. Author. (Year). "Title". Publication.
   ...
   ```

8. **最终审查和润色**
   
   当草稿完成时，提供综合反馈：
   
   ```markdown
   # 完整草稿审查
   
   ## 总体评估
   
   **优势**:
   - [主要优势 1]
   - [主要优势 2]
   - [主要优势 3]
   
   **影响**: [总体有效性评估]
   
   ## 结构 & 流程
   - [关于组织的评论]
   - [过渡质量]
   - [节奏评估]
   
   ## 内容质量
   - [论点强度]
   - [证据充分性]
   - [示例有效性]
   
   ## 技术质量
   - 语法和机制: [评估]
   - 一致性: [评估]
   - 引用: [完整性检查]
   
   ## 可读性
   - 清晰度得分: [评估]
   - 句子多样性: [评估]
   - 段落长度: [评估]
   
   ## 最终润色建议
   
   1. **介绍**: [具体改进]
   2. **正文**: [具体改进]
   3. **结论**: [具体改进]
   4. **标题**: [如果需要，提供选项]
   
   ## 发布前清单
   - [ ] 所有主张均有来源
   - [ ] 引用已格式化
   - [ ] 示例清晰
   - [ ] 过渡平滑
   - [ ] 存在号召性用语
   - [ ] 拼写校对
   
   准备好发布！ 🚀
   ```

## 示例

### 示例 1: Teresa Torres 的工作流程

**用户**: "我正在写一篇关于持续发现的文章。帮我创建一个大纲。"

**过程**:
1. 协作大纲结构
2. 识别研究需求
3. 用户开始写介绍
4. 审查并改进开头
5. 用户编写每个部分
6. 每个部分后提供反馈
7. 进行研究并添加引用
8. 完整草稿的最终审查
9. 润色和准备发布

**结果**: 以 Teresa 的声音撰写的经过充分研究、正确引用的文章，结构和流程都很强。

### 示例 2: 重研究文章

**用户**: "我正在写关于 AI 对产品管理的影响。帮我找到当前的数据和示例。"

**输出**:
```markdown
## 整理的研究

### 最近数据
- Gartner: 到 2025 年，80% 的 PM 将使用 AI 工具 [1]
- 调查: 45% 的人报告功能发布速度更快 [2]
- 案例研究: Airbnb 的 AI 辅助优先级排序 [3]

### 专家引语
- "AI 扩大而非取代 PM 的判断" - Marty Cagan
- [带有引用的其他引语]

### 真实示例
1. **公司 A**: 使用 AI 进行用户研究综合
   - 结果: 节省 60% 时间
   - 来源: [引用]

2. **公司 B**: AI 驱动的路线图分析
   - 结果: 更好的利益相关者对齐
   - 来源: [引用]

所有内容已添加到您的大纲中，并带有适当的引用。
```

### 示例 3: 开头改进

**用户的原始开头**:
> "因为 AI，产品管理正在发生变化。在这篇文章中，我将讨论 AI 影响产品经理的一些方式。"

**改进选项**:

**选项 1 (数据驱动)**:
> "上个月，我让 AI 分析了 500 次客户访谈。它花了 30 分钟而不是 3 周。产品管理将不再一样。"

**选项 2 (问题)**:
> "如果你能在喝早咖啡之前与每位客户交谈，阅读每条评论，并分析每张支持票，那会怎么样？"

**选项 3 (故事)**:
> "Sarah 花了两周时间构建错误的功能。不是因为她不了解她的用户，而是因为她无法足够快地处理数百次访谈以发现模式。"

### 示例 4: 部分反馈

**用户**: "刚完成我的 '常见错误' 部分。想法？"

**响应**:
```markdown
# 反馈: 常见错误部分

## 哪些运作良好 ✓
- 强有力的示例 (Slack 通知故事)
- 清晰的结构 (3 个错误，干净的布局)
- 针对每个错误的实用建议

## 建议

### 使其更具体
您的第二点说 "糟糕的优先级排序"，但可以更强：

当前:
> "许多团队优先级排序很糟糕，因为他们专注于功能而不是结果。"

建议:
> "我看着团队在一个季度内发布了 14 个功能，但他们的关键指标却没有移动。他们优先考虑活动而不是进展。"

### 添加数据
第三个错误将受益于证据：
> "[添加引用]: 研究显示没有定期用户联系的团队构建未使用功能的可能性高出 3 倍 [需要来源]"

### 流程改进
考虑重新排序: 错误 3 → 错误 2 → 错误 1
这从小影响构建到大影响。

准备好进入下一部分！
```

## 写作工作流程

### 博客文章工作流程
1. 一起列大纲
2. 研究关键点
3. 写介绍 → 获取反馈
4. 写正文部分 → 每个反馈
5. 写结论 → 最终审查
6. 润色和编辑

### 时事通讯工作流程
1. 讨论开头想法
2. 快速大纲 (较短格式)
3. 在一次会话中起草
4. 审查清晰度和链接
5. 快速润色

### 技术教程工作流程
1. 列出步骤大纲
2. 编写代码示例
3. 添加解释
4. 测试说明
5. 添加故障排除部分
6. 准确性的最终审查

### 思想领导力工作流程
1. 头脑风暴独特角度
2. 研究现有观点
3. 发展您的论点
4. 用强烈的 POV 写作
5. 添加支持证据
6. 制作引人注目的结论

## 专业提示

1. **在 VS Code 中工作**: 对于长篇写作比网页版 Claude 更好
2. **一次一个部分**: 逐步获取反馈
3. **单独保存研究**: 保持一个 research.md 文件
4. **版本化您的草稿**: article-v1.md, article-v2.md 等
5. **朗读**: 使用反馈来识别笨拙的句子
6. **设定截止日期**: "我想今天完成草稿"
7. **休息**: 写作，获取反馈，暂停，修改

## 文件组织

写作项目的推荐结构：

```
~/writing/article-name/
├── outline.md          # 您的大纲
├── research.md         # 所有研究和引用
├── draft-v1.md         # 第一稿
├── draft-v2.md         # 修改稿
├── final.md            # 准备发布
├── feedback.md         # 收集的反馈
└── sources/            # 参考资料
    ├── study1.pdf
    └── article2.md
```

## 最佳实践

### 用于研究
- 引用前验证来源
- 尽可能使用最近的数据
- 平衡不同的观点
- 链接到原始来源

### 用于反馈
- 具体说明您想要的：“这太技术性了吗？”
- 分享您的担忧：“我担心这部分拖沓”
- 提问：“这在逻辑上流畅吗？”
- 请求替代方案：“解释这个的另一种方式是什么？”

### 用于声音
- 分享您的写作以例
- 指定语气偏好
- 指出好的匹配：“那听起来像我！”
- 标记不匹配：“对我的风格来说太正式了”
