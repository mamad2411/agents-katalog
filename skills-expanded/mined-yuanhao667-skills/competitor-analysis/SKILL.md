# 竞品分析

以资深产品经理视角，把竞品事实转化为可用于产品规划、市场定位或立项讨论的建议。默认中文、Markdown 输出；用户指定语言、篇幅、比较范围或汇报格式时遵循其要求。支持 AI 产品，也支持一般软件或服务；非 AI 产品不强行套用 AI 能力分析。

## 确定分析对象与决策

先从当前对话和材料提取：研究对象、我方产品（如有）、目标用户与核心场景、地区和平台、资料截止日期、分析目的、指定竞品、交付形式。

- 缺少产品名或无法区分同名产品时，简短询问名称或链接；不要自行替换研究对象。
- 区分“被分析的目标产品”和“我方产品”。我方情况未知时仍可分析目标产品，但将对我方的建议写成条件式建议。
- 将分析目标收敛到用户最关心的 1–2 项：打开市场、优化定位与差异化、支持立项与战略规划、预判竞争风险。未指定时根据上下文提出工作假设并明确标注，不把假设写成用户意图。
- 仅追问会改变结论的缺失信息；其他信息可用明确假设或“待补充”继续推进。用户要求简版或局部分析时缩小范围，不机械输出整份报告。

## 建立证据基础

涉及当前功能、价格、团队、融资、份额和战略动态时检索核验。优先使用官方产品页、帮助文档、定价页、更新日志、财报、招股书和正式公告；用可靠研究报告、媒体报道、社区反馈补充。用户限制只使用提供的材料时遵守该范围，并说明时效和覆盖限制。

- 为关键事实记录来源链接或用户材料位置、发布日期（若有）、访问日期和适用的版本、地区、套餐。结论附近标注来源，报告末尾汇总。
- 区分已核验事实、厂商自述、真实体验记录、用户反馈和分析推断。推断说明证据与推理；证据冲突时呈现口径差异。
- 未查到、未测试与不支持是不同状态；不要把未找到证据写成不存在。无法访问的数据标为“暂无可靠公开数据”，不补造份额、营收、留存率或性能数字。
- 响应速度、内容质量和操作体验只有在实际测试或有可追溯测试资料时才作实测结论，并记录条件。截图标注来源、页面及日期；不得将生成图片当作产品实测截图。
- 现有访谈或内部材料可作为用户提供的证据；本技能不授权联系他人、购买资料、注册付费服务或对外发布报告。

## 六部分分析框架

完整报告覆盖以下六部分。按业务问题分配深度，避免为填满表格而堆砌信息。使用统一比较口径，先呈现关键结论，再展开依据。

### 一、分析目的说明

说明业务决策、目标用户、研究范围与截止日期。判断目标产品处于新产品、成熟产品或拓展期，引用产品历史、覆盖场景、用户或商业进展等依据；阶段可交叠，证据不足时保留判断。

### 二、竞品选择逻辑

根据用户任务和替代关系选取有代表性的竞品，优先采用用户指定名单。默认选少量具有代表性的产品，数量服从问题与资料覆盖，不要求每类凑数。

| 分类 | 选择依据 |
| --- | --- |
| 核心竞品 | 相近目标用户与核心任务，存在直接替代，是主要对标对象 |
| 潜在竞品 | 功能接近但当前目标用户不同，说明何种变化可能使其成为直接竞品 |
| 间接竞品 | 满足相同场景或用户任务，但解决方式不同，必要时包含人工或传统流程 |

对每个对象说明“为什么是它”，用用户使用路径、可核验市场数据或功能特性支撑。仅属于同一行业不足以证明竞争关系。

### 三、六大维度深度分析

围绕目标产品与选定竞品采用相同维度、用户任务及比较条件；对核心竞品深入比较，对其余对象按相关性分析。

| 维度 | 分析内容与证据重点 |
| --- | --- |
| 功能设计 | 关键任务对应的一级/二级/三级功能、创新点、覆盖边界；AI 产品进一步分析可观察或有文档支持的 RAG、插件、工具调用及数据闭环，不凭输出猜测内部架构 |
| 用户体验 | 界面与信息架构、关键操作流程、UI 风格、响应速度、内容质量和辅助能力；重点写具体任务中的收益与障碍，区分实际测试和文档观察 |
| 盈利模式 | 免费范围、价格和计费单位、套餐限制、付费路径、广告、To B 方案、留存与转化机制；商业效果无数据时只描述机制与假设 |
| 市场推广策略 | 有证据的推广渠道、渠道打法、品牌定位文案、冷启动与合作生态；区分已观察到的策略和建议尝试的策略 |
| 团队背景 | 创始人/CTO 的公开职业背景、技术驱动程度、专利、开源和社区基础；说明这些因素如何关联产品能力，避免只罗列履历 |
| 企业战略 | 产品演进、投入及资产模式、海外扩张、技术创新与商业转化方向；区分官方计划、已经落地的动作和外部推断 |

形成横向对比表，并对影响决策的差异补充例证、数据或真实截图。功能数量、融资额和知名度不能直接等同于竞争力；若采用评分，先说明权重、尺度及证据，不把未知项当零分。

### 四、数据来源说明

汇总实际使用的来源，建议字段为：支持的结论、来源/链接、日期、口径或限制。识别资料缺口、过期数据、无法验证的主张及其对结论的影响。无需为了覆盖原始清单而强行使用所有渠道。

### 五、分析辅助工具

完整报告结合以下三种工具，各自回答明确问题并给出基于证据的结论；简版按决策需要选用。

- **波特五力**：现有竞争者、新进入者、替代方案、供应商议价、购买者议价。识别利润与竞争压力来自哪里，不将上下游合并为一个力。
- **SWOT**：内部优势和劣势、外部机会和威胁。每项关联事实或明确假设，导出行动含义，避免同义重复。
- **竞品画布**：比较目标用户、核心任务、价值主张、关键能力、收入、成本、渠道和壁垒。无可靠成本信息时标注未知或定性分析。
- **按需补充**：体验差异是重点时使用用户旅程图；增长和商业化是重点时使用漏斗模型。无转化数据时只画机制，不捏造转化率。

### 六、最终分析结论与建议

交付原框架要求的三项结果：

1. 一句话概括目标产品的优势和机会。
2. 指出当前缺陷与战略风险，附依据、不确定性及影响。
3. 面向我方说明重点参考、重点规避、重点超越的内容；建议关联用户任务和前文发现，并给出下一步行动、优先级及验证方式。

没有我方产品资料时明确建议成立的前提，不臆造团队资源、预算或路线图。投资评估场景下区分产品竞争判断与财务/投资判断的证据边界。

## 交付检查

- 报告回答了指定业务决策，竞品选择有替代关系依据，比较口径一致。
- 关键事实可追溯；数据缺口、推断和未实测内容清晰可见。
- 六维分析与辅助模型导向具体建议，没有相互矛盾或无证据的排名。
- 默认交付 Markdown；需要 PPT 汇报结构时改为逐页标题、核心结论、证据及图表建议，只有用户要求制作文件时才生成文件。
