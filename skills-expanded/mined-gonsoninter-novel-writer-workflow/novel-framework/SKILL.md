# Novel 框架搭建阶段（Phase 2 · 第一步）

## 激活条件

由 `novel-writer-workflow-guide` 路由激活，当：
- `novel-ideation` 已完成（constitution + specify + clarify 齐全）
- 用户说"大方向定了" / "现在搭大纲" / "分一下章"

## 这个阶段要产出

**五个核心文档**：

1. **`大纲.md`**——分卷 / 分幕 / 章节梗概
2. **`钩子与反转.md`**——每章末钩子 + 强度评分 + 情绪曲线
3. **`任务分解.md`**——章节优先级 + 依赖关系 + 并行工时
4. **`人物设定.md`**——所有关键人物的人物卡
5. **`世界观设定.md`**——时间线 + 圈子规则 + 金手指边界 + 地理设定

## 搭建顺序

**不是平行的**，有依赖关系：

```
1. 决定总体结构（分卷 + 分幕）
     ↓
2. 写人物卡（主角 + 女主 + 反派）
     ↓
3. 写世界观（时间线 + 金手指边界）
     ↓
4. 写大纲（章节梗概）
     ↓
5. 填钩子矩阵（每章钩子强度）
     ↓
6. 做任务分解（优先级 + 依赖）
```

## 1. 总体结构（先决定）

### 分卷 vs 分幕

- **分卷**是**商业结构**（给平台分册、读者付费节奏）
- **分幕**是**叙事结构**（给情绪曲线）

两者**可以解耦**。例如：
- 2 卷上架（第一卷 X 万字，第二卷 Y 万字）
- 4 幕叙事（归来 / 立足 / 逆袭 / 终局）
- 分卷分界点可以落在某一幕中间的大反转

### 典型结构选择

| 小说规模 | 推荐结构 |
|---|---|
| 短篇 1-3 万 | 单卷三幕（起承合） |
| 中篇 3-10 万 | 单卷三幕/四幕 |
| 长篇 10-20 万 | 2 卷四幕（分界点在大反转章） |
| 超长 20 万+ | 多卷多幕（每卷一个大反转） |

## 2. 人物卡（Framework 之柱）

### 每个关键人物要写

```markdown
## XX

**基础**
- 年龄 / 身份 / 外貌特征（只写关键识别项）

**核心动机**
- 他/她要什么（一句话）
- 为什么要（至少一层原因）

**阻碍**
- 内在阻碍（性格缺陷 / 创伤 / 秘密）
- 外在阻碍（对抗方 / 环境 / 客观限制）

**弧线**
- 故事开始时：什么样
- 中段转折：如何变化
- 故事结束时：变成什么样

**关键细节**（给作者用来保持一致性）
- 口头禅 / 肢体习惯 / 贴身道具 / 家庭关系
- 前世/过去的关键创伤（如果重生题材）
```

### 人物数量控制

- **主角 1 位** + **女主/男主 1 位** + **核心反派 2 层**（台前 + 幕后）+ **关键配角 3-5 位**（师父、兄弟、对手、导师、伙伴）
- 每本小说不超过 10 位核心人物，剩下都是路人
- 路人不写人物卡，但出场一次就要有一笔识别描写

## 3. 世界观（金手指边界是重点）

### 世界观文档结构

```markdown
# XX 世界观设定

## 时间线（关键节点）
- YYYY 年：XX 事件（影响到故事线）
- YYYY 年：YY 事件

## 圈子规则
- [行业术语 10-20 个]
- [潜规则 / 江湖秩序]

## 金手指（如果有）
- 能力：[是什么]
- 边界：[什么能做，什么不能做]
- 代价：[每次使用的代价]
- 升级曲线：[逐步解锁 / 固定封顶]

## 关键地点
- [地点 1]：[描述]
- [地点 2]：[描述]
```

### 金手指边界锁死（防外挂）

如果有金手指，必须在框架期锁死三件事：
1. **能做什么**（明确列举）
2. **不能做什么**（也明确列举）
3. **每次使用的代价**（虚脱 / 失明 / 寿命 / 冷却时间）

金手指失控是长篇常见死因。必须在这里按住。

## 4. 大纲（章节梗概）

### 每章梗概结构

```markdown
| 章号 | 章名 | 核心事件 | 本章钩子 |
|---|---|---|---|
| 1 | XX | 主角做了 X，发现 Y | Z（章末悬念） |
| 2 | YY | ... | ... |
```

### 写梗概的技巧

- **核心事件**一句话，写"主角做什么+结果是什么"
- **钩子**就是下一章开头要接住的那个悬念
- **伏笔**在梗概里用【伏笔】标记，注明回收章号
- 每 3-5 章排一个**强度 4+ 的爆点**（不是每章都要爆）

### 伏笔矩阵

大纲完成后，单独列一张表：

```markdown
## 伏笔矩阵

| 伏笔 | 埋在 Ch X | 回收在 Ch Y | 强度 |
|---|---|---|---|
| 一枚异常的公章 | 16 | 36 | 5 |
| 一个旧手机按键 | 14 | 28, 31 | 4 |
| 主角幼年养过的猫 | 1 | 40 | 2 |
```

**每个伏笔必须明确标注回收章**。悬而未收的伏笔是长篇读者最大的不满。

## 5. 钩子矩阵

### 每章末钩子强度表

```markdown
| 章号 | 钩子内容 | 强度 (1-5) | 情绪类型 |
|---|---|---|---|
| 1 | 细节对上了前世那个线索 | 5 | 炸 |
| 2 | 下手的人招了，背后还有人 | 4 | 悬 |
| 3 | ... | 3 | 燃 |
```

### 情绪曲线

把钩子强度画成曲线：

```
强度 ▲
5   │        ╱╲        ╱╲     ╱─
4   │      ╱    ╲    ╱    ╲  ╱
3   │    ╱        ╲╱        ╲
2   │  ╱
    └──────────────────────────▶  章号
```

**原则**：
- 不能每章都 5 分（读者会麻）
- 不能长时间 2 分（读者会掉）
- 每 3-5 章一个峰值
- 峰值之间有缓冲

## 6. 任务分解

### 任务卡结构

```markdown
| 章号 | 标题 | 优先级 | 依赖 | 可并行 | 预计工时 | 状态 |
|---|---|---|---|---|---|---|
| 1 | 一碗汤 | 高 | — | 否 | 3h | 待写 |
| 2 | 背后的人 | 高 | Ch 1 | 否 | 3h | 待写 |
| 3 | 逐出师门 | 中 | Ch 2 | 否 | 3h | 待写 |
```

### 优先级标记

- **高**：主线关键章（爆点章、反转章、高潮章）
- **中**：主线推进章
- **低**：过渡章、铺垫章

### 并行写作

如果你用 AI 辅助且同时开多个 context：
- 标 `[P]` 表示可并行（比如两章发生在不同地点、不同人物线）
- 但**同一条线的相邻章不能并行**（前章影响后章细节）

## 质量检查清单

Framework 做完之前，过一遍：

- [ ] 所有关键人物都有完整人物卡（不只是主角）
- [ ] 金手指边界和代价写死
- [ ] 大纲每章有核心事件 + 钩子
- [ ] 伏笔矩阵每个都有回收章
- [ ] 钩子强度情绪曲线不是一条直线
- [ ] 任务分解能看出依赖和优先级
- [ ] 分卷分界点落在强反转章
- [ ] 世界观和 constitution 不冲突

## 与姐妹 skill 的关系

- **输入来源**：`novel-ideation` 的 constitution + specify
- **输出消费者**：`novel-chapter-sop` 写单章时要读大纲+人物卡+钩子；`novel-consistency-guards` 扫描时要参照世界观和人物卡
- **不做什么**：不写正文、不做 review。只搭框架。

## 常见陷阱

### 大纲太粗

"第五章：主角和女主在老街吵架" ——这种粒度在写作期没法直接落笔。梗概至少要有：谁、在哪、干了什么、结果是什么、留下什么钩子。

### 伏笔没回收计划

埋了很多伏笔，但没写回收章。写到后期发现根本没地方收，或者收得仓促。**埋的同时必须写回收章**。

### 钩子强度失衡

前 10 章全是 5 分爆点，后 30 章都是 2-3 分——读者会感觉"越看越不好看"。爆点要分布在全书。

### 金手指没边界

"主角有心眼"——行。但"心眼能干什么、不能干什么、代价是什么"必须写死。否则写作期会"什么都能用心眼解决"。

### 分卷分界没对齐

分卷分界点不能随意选。**必须落在一个大反转**或者**一个阶段性胜利**的章末。读者合上第一卷时要有"下卷必看"的冲动。

## 切换到下一阶段

Framework 完成后，主 skill 会确认：

> "框架齐全了：大纲 / 人物 / 世界观 / 钩子 / 任务 五表都有。接下来进入写作阶段。启用 `novel-chapter-sop` 管单章流程，`novel-consistency-guards` 后台扫一致性。准备好就从 Ch 1 开始。"
