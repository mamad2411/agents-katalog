# Lovable → Databricks Lakebase Migration Skill

Migrate an existing Lovable.dev app off Supabase onto a Databricks Lakebase (managed PostgreSQL) backend.

## What it does

1. **Exports** schema (CREATE TABLE statements) and row data from Supabase via PostgREST/REST API
2. **Provisions** a new Lakebase PostgreSQL database on Databricks
3. **Loads** schema DDL and all table data into Lakebase
4. **Patches** the Lovable app `.env` file so it points at the new Databricks database

## Prerequisites

- Supabase project URL and service-role key
- Databricks workspace host + personal access token (with Lakebase access — FE-VM workspace recommended)
- Python 3.11+ with dependencies installed
- Migrator tooling at `~/lovable-databricks-migrator/`

### Install dependencies

```bash
cd ~/lovable-databricks-migrator
pip install -r requirements.txt
```

## Usage

### Full migration (schema + data)

```bash
python ~/lovable-databricks-migrator/migrate.py \
  --supabase-url https://YOUR_PROJECT.supabase.co \
  --supabase-service-key YOUR_SERVICE_ROLE_KEY \
  --databricks-host https://YOUR_WORKSPACE.azuredatabricks.net \
  --databricks-token YOUR_PAT \
  --lakebase-name my_app_db \
  --app-env-file /path/to/your/lovable-app/.env
```

### Dry run (export only, no Databricks writes)

```bash
python ~/lovable-databricks-migrator/migrate.py \
  --supabase-url https://YOUR_PROJECT.supabase.co \
  --supabase-service-key YOUR_SERVICE_ROLE_KEY \
  --databricks-host placeholder \
  --databricks-token placeholder \
  --dry-run \
  --output-dir ./migration_preview
```

### Schema-only migration (no data)

Add `--skip-data` flag.

### Migrate specific tables only

```bash
--tables users,products,orders
```

## What you need from the user

1. **Supabase URL** — format: `https://abcdefgh.supabase.co`
2. **Supabase service-role key** — found in Supabase dashboard → Settings → API → service_role (secret)
3. **Databricks workspace host** — e.g., `https://adb-1234567890.12.azuredatabricks.net`
4. **Databricks PAT** — Settings → Developer → Personal access tokens → Generate new token
5. **(Optional) App .env file path** — will be patched in-place with new connection string

## Output files

After migration, `./migration_output/` contains:

| File | Description |
|------|-------------|
| `schema.sql` | CREATE TABLE statements for all migrated tables |
| `<table>.jsonl` | Row data per table (one JSON object per line) |
| `manifest.json` | Migration summary with row counts and connection details |

## Next steps after migration

1. Open your Lovable app → Settings → Integrations → Database
2. Replace the Supabase integration with a custom PostgreSQL connection
3. Use the connection string from `manifest.json` → `lakebase.connection_string`
4. If you used `--app-env-file`, restart the app — it already points at Lakebase
5. Test all CRUD operations in the app

## Lovable app code changes needed

If the app uses Supabase JS client directly (not just the Lovable integration), apply the TypeScript adapter generated by the migration:

```bash
ls ~/lovable-databricks-migrator/migration_output/
# Look for supabase_adapter.ts — drop it into your Lovable app's src/ folder
```

The adapter provides a Supabase-compatible client interface backed by the Lakebase PostgreSQL connection.

## Troubleshooting

| Error | Fix |
|-------|-----|
| `401 Unauthorized` from Supabase | Check service-role key (not anon key) |
| `psycopg2.OperationalError` | Verify Lakebase network access; use FE-VM workspace |
| `KeyError: tables` in schema export | Supabase project may have no tables yet |
| Databricks 403 | PAT may lack `CREATE DATABASE` permission or workspace doesn't support Lakebase |
