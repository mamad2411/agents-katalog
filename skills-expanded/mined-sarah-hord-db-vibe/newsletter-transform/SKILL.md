# Newsletter Transform

Transforms internal Databricks account newsletters (generated by the Newsletter App) into clean editing guides. Supports multiple **flavors** for different audiences.

## Flavors

| Flavor | Audience | Default? | Description |
|--------|----------|----------|-------------|
| `customer` | Customer stakeholders | Yes | Removes all commercial, competitive, and internal data. Customer-safe. |
| `sa` | SA / DSA (internal) | No | Keeps metrics, competitors, stages. Removes citation noise and cleans formatting. |
| `leadership` | Directors, VPs (internal) | No | Keeps business metrics, rewrites tasks as outcomes, groups into themes. Executive-scannable. |

### How to specify flavor

- `/edit-newsletter ~/Downloads/Newsletter.pdf` → defaults to `customer`
- `/edit-newsletter ~/Downloads/Newsletter.pdf sa` → uses `sa` flavor
- `/edit-newsletter ~/Downloads/Newsletter.pdf leadership` → uses `leadership` flavor
- "Make this newsletter DSA-friendly" → uses `sa` flavor
- "Process newsletter for customer" → uses `customer` flavor
- "Create a leadership update" or "executive version" → uses `leadership` flavor

**Auto-detect:** If the user says "internal", "SA", "DSA", or "for the team" → use `sa`. If the user says "customer", "external", "share with customer" → use `customer`. If the user says "leadership", "executive", "VP", "director", or "leadership update" → use `leadership`. If ambiguous, ask.

## Flavor: customer (Rules v1.1)

### Rule #1 — Remove Commercial Info
Remove ARR Band, Spend Tier, $DBU metrics, DBU targets/forecasts, internal revenue segmentation. DELETE entire sections:
- Key Metrics
- Consumption Overview
- Threats / Competitors
- Competitive Positioning
- Reference Sources (use case links with Salesforce URLs, DBU values, stage labels)

### Rule #2 — Transform Executive Summary
Remove internal tracking language:
- Onboarding stage labels (e.g., "stage 5-ONBOARDING")
- DBU references (e.g., "7500 dollar DBUs")
- `(uc:...)` citation markers
- Internal use case naming (e.g., "WWEX-Sales Quota (Billed) Genie-Nicolas" → "Sales Quota Reporting")
- Target live dates (e.g., "2026-04-01" → "targeting Q2")

Rewrite as: **one short overview paragraph** + **Use Case Updates** bulleted list (1–2 sentences each).

### Rule #3 — Section Placement Logic (No Repetition)
Each section has a distinct role. If a use case already appears in Platform Progress, do NOT repeat the same update in other sections unless there is genuinely new information.

| Section | Role | What Goes Here |
|---------|------|----------------|
| Executive Summary | Brief mention | 1-sentence per use case |
| Platform Progress | Main update | Full detail per use case (THE primary section) |
| Value Proposition | Strategic framing | How Databricks supports each workstream |
| Areas of Focus | Attention items only | Only use cases needing attention, with NEW info not in Platform Progress |
| Open Items | Active blockers only | Only unresolved blockers not already stated in Areas of Focus |

**Critical:** If a use case is on track, it should NOT appear in Areas of Focus or Open Items.

### Section Renaming (customer)
| Original Name | Customer-Facing Name |
|---------------|---------------------|
| Platform Shifts | Platform Progress |
| Risk Assessment | Areas of Focus |
| Blockers | Open Items |

### Sections to DELETE (customer)
| Section | Reason |
|---------|--------|
| Key Metrics | Internal $DBU tracking (Rule #1) |
| Consumption Overview | Internal financial chart (Rule #1) |
| Threats / Competitors | Competitive intelligence (Rule #1) |
| Competitive Positioning | Competitive intelligence (Rule #1) |
| Next Steps | Absorbed into Platform Progress + Open Items (Rule #3) |
| Reference Sources (use case links) | Internal Salesforce links with DBU values (Rule #1) |

### Sections to KEEP with edits (customer)
| Section | Edit |
|---------|------|
| Header | Remove ARR Band, Spend Tier |
| Macrotrends | Remove (p1) source citations only |

## Flavor: sa (Rules v1.1-SA)

The SA flavor produces a **clean internal read** — keeps all the valuable internal data but strips the noisy citations and formatting artifacts that make raw newsletters hard to scan.

### SA-Rule #1 — Strip Citation Noise
Remove all source citation markers that clutter readability:
- `(uc:...)` use case citation markers (e.g., `(uc:GM - Cruise Automation - GCP Data Pipeline Migration to Databricks)`)
- `(pN.N)` page reference markers (e.g., `(p1.6)`, `(p3.3)`)
- `(dar_taylor_s_...)` document reference markers

### SA-Rule #2 — Clean Use Case Names
Simplify internal use case names for readability, but keep more detail than customer flavor:
- Remove account prefix: `GM - ` → remove
- Keep descriptive name: `Cruise Automation - GCP Data Pipeline Migration to Databricks` → `Cruise Automation — GCP Pipeline Migration`
- Keep stage labels (useful for SA context)
- Keep DBU values (useful for SA context)

### SA-Rule #3 — Clean Formatting
- Keep Reference Sources as-is (raw Salesforce links are valuable for SA click-through)
- Remove PDF document references (internal file names not useful)
- Clean up the Macrotrends section (remove page refs, keep content)
- Ensure consistent bullet formatting

### SA-Rule #4 — Add SA Quick Reference
Add a **Quick Reference** section at the top of the guide with:
- Account snapshot (name, industry, ARR, spend tier, cloud, renewal date)
- Use case count and stage distribution summary
- Key metrics summary (from Key Metrics section)
- Top risks (from Risk Assessment)
- Top blockers (from Blockers)

### Sections: SA Flavor
| Section | SA Action |
|---------|-----------|
| Header | KEEP as-is (ARR, Spend Tier useful internally) |
| Executive Summary | CLEAN — remove citations, keep stages/DBU |
| Key Metrics | KEEP — useful internal data |
| Consumption Overview | KEEP — useful for tracking spend |
| Threats / Competitors | KEEP — competitive intel valuable for SA |
| Competitive Positioning | KEEP — competitive intel valuable for SA |
| Platform Shifts | CLEAN — remove citations, keep all data |
| Value Proposition | CLEAN — remove citations |
| Risk Assessment | CLEAN — remove citations |
| Blockers | CLEAN — remove citations |
| Next Steps | CLEAN — remove citations, keep action items |
| Macrotrends | CLEAN — remove page refs |
| Reference Sources | KEEP — raw Salesforce links valuable for SA, do NOT transform to table |

## Flavor: leadership (Rules v1.1-Leadership)

The Leadership flavor produces an **executive-friendly update** — keeps business metrics and competitive intel but rewrites everything at the milestone/theme level. No technical implementation detail.

### Leadership-Rule #1 — Remove Technical Citations
Remove all citation markers AND use case parentheticals from prose:
- `(uc:...)` use case citation markers
- `(pN.N)` page reference markers
- `(dar_...)` document reference markers
- Inline use case name parentheticals like `(SAP-BDC — GM Finance)`

### Leadership-Rule #2 — Rewrite Tasks Into Outcomes
Convert implementation tasks into business outcomes or milestones:
- "Verify access controls for SAP-BDC implementation" → "Finalize governance readiness for the SAP-BDC finance platform rollout"
- "Implement Autoscaling for LakeBase" → "Advance LakeBase platform toward production readiness"

### Leadership-Rule #3 — Focus on Progress and Milestones
Highlight project progress, upcoming milestones, deployment readiness, and adoption steps. Avoid pipeline configs, autoscaling, cluster settings, SQL queries.

### Leadership-Rule #4 — Group Related Work Into Themes
Combine individual use cases into 3-5 initiative-level summaries:
- Platform Migration (all GCP-to-Azure use cases)
- Application Modernization (LakeBase, SAP-BDC)
- Analytics & BI (Brightdrop, Genie)
- Multicloud Strategy

### Leadership-Rule #5 — Emphasize Business Value
Frame in terms of: customer impact, platform adoption, operational efficiency, cost optimization, revenue protection.

### Leadership-Rule #6 — Keep Sections Short
3-6 bullets max per section. One clear message per bullet. Readable in under 30 seconds.

### Leadership-Rule #7 — Executive Snapshot with Adoption Signal
Add Executive Snapshot at top with TWO mandatory components:
1. **Snapshot Table**: ARR, Renewal, Daily Avg $DBU, $DBU Trend (↑/↓/→ QoQ), Active Use Cases, Top Risk, Top Competitor
2. **Summary Paragraph** (3-4 sentences below the table): Lead with ARR + renewal, mention momentum signals, name 2-3 strategic themes, close with primary risk. Both components are required.

### Leadership-Rule #8 — Escalation Items Filter
Only include blockers requiring leadership action: exec engagement, cross-org escalation, customer leadership alignment, major commercial risk. Exclude technical issues the team can resolve.

### Leadership-Rule #9 — Remove Internal Contributor Names
Remove individual contributor names (engineers, SAs, project leads). Keep only executive-level stakeholders (customer executives, Databricks VP+).

|---------------|----------------|
| Executive Summary | Executive Snapshot |

| Section | Reason |
|---------|--------|

| Section | Leadership Action |

| Executive Summary | TRANSFORM → Executive Snapshot (3-4 sentences + snapshot table) |
| Key Metrics | KEEP → rename Key Indicators |

## Workflow

### Phase 1: Read the Newsletter PDF
1. Read the PDF using the Read tool (use `pages` parameter for large PDFs)
2. Identify all sections present in the newsletter
3. Extract the account name, date, and use case names
4. Determine flavor (from argument, user intent, or ask)

### Phase 2: Apply Rules Section by Section
**For customer flavor:**
1. Rule #1: Mark sections for deletion, strip commercial data
2. Rule #2: Rewrite Executive Summary with clean use case names
3. Rule #3: Ensure no-repetition across sections

**For sa flavor:**
1. SA-Rule #1: Strip all citation noise
2. SA-Rule #2: Clean use case names (keep internal detail)
3. SA-Rule #3: Clean formatting throughout
4. SA-Rule #4: Generate Quick Reference header

**For leadership flavor:**
1. Leadership-Rule #1: Strip all citations AND use case parentheticals
2. Leadership-Rule #2: Rewrite tasks as outcomes/milestones
3. Leadership-Rule #4: Group use cases into initiative themes
4. Leadership-Rule #7: Generate Executive Snapshot with adoption signal
5. Leadership-Rule #8: Filter blockers to leadership-actionable only
6. Leadership-Rule #9: Remove contributor names, keep executives only

For each section, produce:
1. **Section Name** — the section heading (with rename if applicable)
2. **Editing Instruction** — what to do in the newsletter app UI
3. **Replacement Text** — copy-paste replacement (only for sections that need rewriting)

### Phase 3: Generate the Editing Guide
1. Write the complete editing guide as a markdown file to `/tmp/`
2. Title format: `Editing Guide ([FLAVOR]): [Account] Newsletter — [Date]`
3. Use `markdown_to_gdocs.py` to convert to a Google Doc (requires `fe-google-tools` plugin)
4. Return the Google Doc URL

### Phase 4: Add Global Editing Checklist
**Customer flavor checklist:**
- Sections to DELETE / RENAME
- Global Find-and-Replace (uc: markers, stage refs, $DBU refs, date cleanup)
- No-repetition verification (Rule #3)

**SA flavor checklist:**
- Global Find-and-Replace (uc: markers, pN.N refs, document refs)
- Use case name cleanup list
- Quick Reference verification

**Leadership flavor checklist:**
- All citations AND use case parentheticals removed
- All tasks rewritten as outcomes/milestones
- Related use cases grouped into themes (3-5 themes)
- Each section has 3-6 bullets maximum
- No individual contributor names remain
- Executive Snapshot includes $DBU Trend with arrow
- Escalation Items only contain leadership-actionable blockers

## Output Format

The editing guide follows this structure per section:

```
## Section: [Name] (was: [Original Name])

**Editing Instruction:** [What to do in the UI]

**Replacement Text:**
[Copy-paste replacement content]
```

For DELETE sections (customer flavor only):
```
## Section: [Name]

**Editing Instruction:** DELETE this entire section. [Reason]. (Rule #X)
```

## Constraints

- **Do not invent information.** Only rewrite information that exists in the PDF.
- **Customer flavor:** Do not repeat use case updates across sections (Rule #3). On-track use cases should NOT appear in Areas of Focus or Open Items.
- **SA flavor:** Keep all internal data. Only remove citation noise and clean formatting.
- **Leadership flavor:** Rewrite at milestone/theme level. No technical detail. Only leadership-actionable escalation items. Remove contributor names.
- **All flavors:** Use case names must be simplified (degree depends on flavor).
