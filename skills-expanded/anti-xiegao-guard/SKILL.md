# 反洗稿·原创内容守护

> 蒸馏自 2026-08-17 网络调研（平台公告、司法判例、ICML/NeurIPS/Nature 论文、工程实践），详见本目录 research/SOURCES.md。
> 适用对象：内容创作者、编辑/平台审核、开发者、法律从业者。

## 一、识别模块：这算不算洗稿？

### 核心判定框架（三维识别）
**只要同时满足以下任意维度的"实质性相似"，即构成洗稿**——表面文字变了，但核心事实、主要观点、叙事结构或论证逻辑仍来源于原文：

| 维度 | 表现 | 例子 |
|------|------|------|
| **文字替换** | 换同义词/近义词、调语序句式 | "充满感情"→"充满情感"、"衷心爱戴"→"由衷敬仰" |
| **结构重组** | 打乱段落顺序、多篇"移花接木"拼接 | 把原文段落拆散重排，或多篇拼成一篇 |
| **元素替换** | 换主角名/素材/配音，保留故事框架与情节顺序 | 主角"张三"→"李四"、视频换素材保留脚本框架 |

**一句话记忆**：看三个地方——字换了没有、结构动了没有、只是换了层皮但骨架还是原样的。

### 类型演进：人工洗稿 → AI洗稿
- **人工洗稿**：单篇手工改写，产能低、成本高，靠同义词替换/句式调整。
- **AI洗稿**：锁定全网热门优质稿件 → AI一键改写（替换字句/调语序/重构段落）→ 批量分发 → 套取平台原创补贴。形成"改写—分发—骗补"黑灰产业链，可操控海量账号充当水军（上海虹口案：1099个账号、2个月骗补贴1.8万、诈骗罪判刑）。

## 二、维权模块：被洗稿了怎么办？

### 路径1 · 平台投诉（最快，先做）
- 微信：文章页投诉，选"抄袭/洗稿"，指出①融合他人原创素材②明显篡改改写③大量引用④直接复制任一情形；存疑内容由"洗稿投诉合议小组"裁定。平台阶梯处置：删除→功能限制→流量降权→账号封停（2025年12月微信删洗稿文1032篇、封禁侵权账号2119个）。
- 头条号：需指出被诉内容"结构、行文逻辑、核心观点与原文高度一致或存在多处相似"。
- 建议：先公证/截图/存档原稿发布时间与链接（存证），再投诉。

### 路径2 · 法律维权（判赔参考）
- **判定标准**：思想与表达二分法（著作权只保护"表达"不保护"思想"）+ **"接触+实质性相似"**（需同时证明被告接触过原告作品，且表达上实质相似）。
- **比例参考（实务）**：借鉴占10%→涉及抄袭；20%+→通常认定剽窃；30%+→严重剽窃（论文查重安全线）；部分判例复制比70-90%+→实质性相似甚至涉刑。
- **判例锚点**：锦绣未央案（763处语句+21处情节相同，判赔74万）；《错位时空》歌词洗稿案（判赔5万）；短视频口播文案被复制改编（判赔2万）；软件案最高判到惩罚性赔偿1500万（拒不举证）。
- **合法引用界限**：非诗词类引用≤2500字或被引作品1/10；引用总量≤本人创作总量1/10；超过即高风险。
- 刑事责任红线：以营利为目的、违法所得5万+或有其他严重情节 → 最高3年以下有期徒刑并处罚金。

## 三、技术模块：怎么搭检测/反洗稿系统？

### 三层检测技术栈（推荐：漏检率可降至<5%）
```
第1层 字面匹配（快速初筛）：N-gram滑动窗口、SimHash海明距离 / MinHash Jaccard
        → 文本正则化（大小写/简繁/标点清洗）
第2层 语义分析（识别改写）：embedding余弦相似度、Sentence-BERT双塔召回
        + 交叉编码器精排、向量库(HNSW/IVF)
第3层 结构特征（补漏）：段落分布模式、论点逻辑链比对
```
- **工程要点**：中文必须用 jieba 分词（错误分词可致相似度偏差40%）；SimHash 召回+语义精排混合；引用块做权重衰减避免误报；批量场景用倒排索引先筛无关文档。
- **检测器选型**（2025-2026实测）：Originality.ai（混合模型~92%，能识别人工修改过的AI内容，最适防"AI洗稿"）、GPTZero（可做"溯源分析"推测AI模型版本，需≥500字）、Turnitin（学术、2026更新提升召回+低误报）、Copyleaks（200+语言）。**注意**：检测分数只是数据点不是判决——误报率8%左右，大幅人工编辑后的AI内容检测率显著下降。
- **使用注意**：检测前去格式（粘贴纯文本）、超3000字分段、关注"混合可能性"指标而非二元判断。

### 文本水印溯源（事前预防，选型路线）
演进：KGW绿名单/红名单(ICML'23杰出论文) → 语义级水印(Fang'23) → 无偏水印(ICLR'24，质量解耦) → **SynthID-Text**(Google DeepMind, Nature'24, 工业级) → **E2E-LLM-Watermark**(ICML'25, 端到端logits, 抗改写) → SAEMARK(NeurIPS'25, 黑盒多比特)。
- 局限：高级改写/翻译攻击下检测率下降；代码/数学等低熵文本水印空间受限；短文本难以统计显著；中文适配仍在探索。

## 四、执行清单（1-2-3 快速上手）

**情景A · 判断一篇文章是否洗稿**：
1. 用三维框架逐项比对：字词替换量、结构重组度、元素替换但骨架相同？
2. 提取原文"独特点"（罕见表达/独特案例/数据/逻辑链），看是否在疑似稿中复现。
3. 命中文案工具三选一佐证：SimHash海明距离、embedding余弦、AI检测器。

**情景B · 被洗稿后维权**：
1. 存档证据：原稿发布链接+时间戳截图、洗稿文链接（公证保全）。
2. 先走平台投诉（微信合议小组/头条举报），等待平台处置。
3. 若平台不处理或损失重大 → 律师函/诉讼，主张复制权+改编权+信息网络传播权，按"接触+实质相似"举证，参照判例主张赔偿。

**情景C · 搭建反洗稿系统**：
1. 第一版：SimHash/分词做全库快速比对（秒级初筛）。
2. 第二版：加 embedding 语义层召回+精排，识别同义改写。
3. 第三版：加结构特征层+AI检测器+引用豁免，压漏检率到<5%。

## 诚实边界（B）

- **不是法律意见**：10%/20%/30%比例是实务参考，法院判定核心仍是"实质性相似"整体判断；本 Skill 不替代律师。
- **检测有误报与漏报**：AI检测器误报率约8%，人工深度编辑后的洗稿可逃逸；embedding"高相似≠抄袭，低相似也可能结构性复写"，必须人工复核。
- **信息截止**：调研时间 2026-08-17，之后的法律/工具/论文更新未覆盖。
- **作者盲点**：中文语义检测/水印适配仍在探索期；平台治理数据仅为公开通报，全量数据不透明。
- **工具生态割裂**：查重、AI检测、水印三套体系各自为战，无统一标准——选型时注意集成成本。
