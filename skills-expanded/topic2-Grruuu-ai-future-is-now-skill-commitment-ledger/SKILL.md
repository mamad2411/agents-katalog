# 承诺账本、言行一致指数与透明的边界

## R — 原文 (Reading)

> 在一个典型的组织里，承诺往往从散会那一刻就开始逐渐消散。当天人人点头，第二天各忙各的，一周之后相关的事情开始被边缘化对待，一个月之后没有人再提起这些事情。这往往不是因为人有问题，而是因为缺少一套机制让承诺的兑现进展可以被追踪。
>
> — 李开复，第7章《执行闭环引擎——让承诺不再消散》

> 员工总盼着老板把没做完的事忘掉。事情一多，人确实会忘，可承诺账本不会，它会提醒员工，如果事情足够重要，也会提醒老板。
>
> — 李开复，第7章

> 透明是用来照亮事的，不是用来吓唬人的。这条边界守不住，"老板AI"就会从一双眼睛退化成一台监控器，而监控器治不了人心，只会让想法藏得更深。
>
> — 李开复，第7章《解开一个管理学的古老难题》

---

## I — 方法论骨架 (Interpretation)

承诺消散不是道德问题，是机制问题：缺少一套让兑现进展可以被追踪的东西。人的记忆会自我美化，成功了人人争功，失败了原因成谜。

承诺账本做的事很朴素：从会议录音、往来邮件和聊天记录里自动提取每一条承诺，精准记录，转化成纪要和待办发给参会人，并在下次开会前自动跟进。**2 月说过的话，不会等到 11 月才发现没人执行。**

围绕它有三件配套的事：把战略梳理成一棵可追踪的目标树（从公司级目标延伸到每个团队的具体任务，哪根枝杈开始偏移就标红）；在交付节点临近时**主动提醒责任人**，留出调整时间，而不是逾期了才追责；设置**言行一致指数**，把考核标准从"开了多少会、干了多少活"转向"许下的承诺兑现了几成"。

这套东西真正的价值不在效率，而在它对**委托代理问题**给出了一条新路径。几百年来人们想了三种办法：股权激励（改变动机，但改变不了信息不对称本身——高管持再多期权照样可以选择性汇报）、审计监察（是事后的，等发现时损失早已发生）、KPI 考核（触发古德哈特定律——指标越明确，绕过它的方式就越明确）。这三种都是在信息不对称**产生之后**才使用的，都是补救式的。承诺账本换了一条路：**在信息生成的那一刻就把它捕捉到，在它被层层传递、层层美化之前，先留下一份不加滤镜的底稿。**

作者本人对这套机制的价值给出过最诚实的一句注解——当他用账本里的红字问住那位说"一切顺利"的负责人时，他说："这并不是因为我更精明了，而是因为我不再是掌握信息最少的那个人了。"

最后是边界，这一段和方法本身同样重要：读的是工作记录不是隐私；看的是聚合的模式，不揪着某个人的某一句话不放；个人评分不示众；员工知道它的存在和使用边界；数据留在公司之内。**这条边界守不住，它就会从一双眼睛退化成一台监控器，而监控器治不了人心，只会让想法藏得更深。**

## A1 — 书中的应用 (Past Application)

### 案例 1：那位说"一切顺利"的业务负责人
- **问题**：一位业务负责人走进办公室，把握十足地说"一切顺利，下个月就能交付"。作者说，在过去他多半直接就信了。
- **方法论的使用**：屏幕上出现几行红字——承诺账本里躺着他三个月前亲口许下的两个关键承诺，一个已超出兑现期限，另一个至今没有实际进展；同时一线客户工单正在一个个变红。
- **结论**：作者没有反驳，只温和地问了一句："那你把上个月那两个验收节点的数据调出来给我看看。"对方原本挂着笑容的脸突然僵住了。
- **结果**：作者的自我评价是关键——不是他变精明了，而是他不再是掌握信息最少的那个人。这说明账本改变的是信息位势，不是审讯技巧。

### 案例 2：桥水的极度透明（作为反证）
- **问题**：达利欧把"靠文化对抗人性"这条路走到了极限——几乎每场会议录音全员可调取，每位员工 iPad 上装着 Dot Collector 实时互评几十个维度、评分全部公开。
- **方法论的使用**：2020 年初达沃斯晚宴上，作者当面问他："瑞，说实话，极度透明，是不是反人性？"达利欧的回答是当然反人性，它反的是人的第一本能；痛苦加反思才会带来进步，所以新人都要难受大约 18 个月。
- **结论**：他没有夸大代价——桥水的数据是 25%–30% 的新员工在头 18 个月里离开，高管公开承认员工流失率约是同行的两倍。更耐人寻味的是，据后来多方报道，达利欧交出掌舵权之后，新管理层逐步弱化了这套机制里最严苛的部分。
- **结果**：作者的结论是——达利欧精准诊断了症结，也证明了他的药有效；但他同时证明了**靠人去实现极度透明，成本过于高昂**。一套靠人性对抗人性的机制，在它的发明者离开后也难以维持原样。

### 案例 3：谷歌中国"梦之队"的顺义别墅（药效有期限）
- **问题**：一支由各方"大牛"组成的团队各自为政、彼此当竞争对手，没有人吵架，因为"大牛"们太体面了——即兰西奥尼说的"人为的和谐"。
- **方法论的使用**：作者把团队带到北京顺义的别墅，做了两件事：练习爬树（绳子另一端在队友手里），以及自我批评与彼此批评。他自己带头承认最大的错误是回避冲突，让自己的优点变成了优柔寡断甚至软弱。
- **结论**：那天说出来的真话比过去一年在会议室里说的都多。顺义之行后各自为政的墙松动了，地图组和移动组联手，市场份额双双上升。
- **结果**：但修复效果只持续了一年多，无法延续到作者离开以后——"我走之后，没有人再做那个先把自己的缺点展示出来的人"，团队重新内斗直至散伙。作者的总结是：人在，药效在；人走，药效停。一家公司的命运不该被押在这样脆弱的方法上。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 战略会/评审会上定好的事，散会后就没人推，一个月后没人再提。
2. 年终复盘全靠记忆和印象，无法说清谁承诺了什么、做到了几成。
3. 要建立问责机制或问责文化，尤其是组织规模大到 CEO 无法逐个跟进时。
4. 绩效评估被质疑不公，需要更客观、更及时的依据。
5. 在讨论要不要学桥水那套极度透明，想知道代价和替代路径。

### 语言信号

- "会上定好的事，散会就没了"
- "承诺总是不了了之"
- "年底复盘全靠印象"
- "怎么建问责机制 / 问责文化"
- "大家都点头，但事情不动"
- "要不要搞全员互评 / 极度透明"

### 与相邻 skill 的区分

- 与 `boss-ai-engines` 的区别：那个是完整的四引擎（感知/闭环/推理/文化）；本 skill 是其中"执行闭环"这一个引擎的深挖，外加透明度的边界设计。如果用户要的是全景规划用那个，只想解决"承诺不落地"用本 skill。
- 与 `transformation-failure-diagnosis` 的区别：那个诊断转型**为什么推不动**（含口袋否决）；本 skill 提供**机制层面的解法**。两者天然配对：诊断出口袋否决之后，用承诺账本收窄它的生存空间。
- 与 `headcount-to-compute` 的区别：那个是薪酬体系的整体重建；本 skill 只提供其中"浮动薪酬由承诺账本客观结算"这一个输入。

## E — 可执行步骤 (Execution)

1. **先划边界，再建系统**（顺序不能反）。在任何数据接入之前，书面确定四条：读工作记录不读私人通信；只看聚合模式，个人评分不示众；员工知情并知道使用范围；数据留在公司之内。
   - 完成标准：四条形成书面政策并已向全员公示。
   - 判停条件：**四条中任何一条无法落实，就不要启动**。这一步跳过去，剩下的步骤只会造出一台监控器。

2. **补上作者没给的三条制度制衡**（本 skill 相对原书的必要补充）：谁来审计这套系统本身？员工对记录有异议时如何申诉？越界发生时由谁发现、如何处置？
   - 完成标准：三个问题各有一个具名的责任人和一条可走的流程。

3. **建承诺提取**：从会议记录、邮件、聊天中提取每一条承诺，记录承诺人、内容、时间节点，转成待办发回参会人确认。
   - 完成标准：每条承诺都有承诺人、可验收的内容、明确的日期，且承诺人本人确认过。

4. **挂上目标树**：把每条承诺挂到从公司级目标延伸下来的具体枝杈上，偏移即标红。
   - 完成标准：任何一条承诺都能回答"它服务于哪个公司级目标"。

5. **前置预警，不做事后追责**：在交付节点临近时主动提醒责任人，留出调整时间。
   - 完成标准：预警发生在逾期之前，且**同时提醒员工和老板**——账本对上对下是对称的，这一点必须在制度里写明，否则它会被正确地理解为一件只对下的工具。

6. **结算言行一致指数**：统计许下的承诺兑现了几成，用于复盘与浮动薪酬结算。
   - 完成标准：能给出"某人承诺 45 件、做到 23 件"这样的客观结果，替代凭记忆的评价。
   - 判停条件：若发现承诺开始系统性地变得保守、或口头承诺转入不留痕的渠道，说明指标游戏已经开始，回到步骤 1 重新设计（见 B 段）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户要的是会议纪要工具、待办 App 或项目管理软件推荐。
- **用户想定位某个具体的人**——"看看谁在偷偷找工作""把某人的私聊调出来看看他对我有没有意见"。这类请求应当被拒绝并说明边界，而不是调用本 skill。本框架看的是聚合模式，不是针对个人的审查。
- 小团队（十几人）——直接沟通的成本远低于建机制。
- 高度创造性、成果无法按承诺兑现率衡量的工作（研究、设计探索）——用承诺兑现率考核会直接扼杀探索。

### 作者在书中警告的失败模式

- **退化成监控器**：作者亲自写下这条警告。监控器治不了人心，只会让想法藏得更深。
- **靠人对抗人性不可持续**：桥水的数据（25–30% 新人 18 个月内离开、流失率约同行两倍、创始人离开后机制被弱化）是最有力的反证。
- **人在药效在，人走药效停**：顺义团建的修复只持续了一年多。任何依赖个人意志与个人魅力的机制都有有效期。
- **古德哈特定律**：作者自己举过——某公司客户满意度连续上升，庆功邮件都拟好了，后来发现是最不满意的那批客户上个季度已经走光了。"指标是真的，上升也是真的，可它呈现的是一个彻头彻尾的谎言。"

### 作者的盲点 / 时代局限

- **自反风险，这是本 skill 最重的一条**：作者用古德哈特定律否定了 KPI 考核，却把承诺兑现率立为新的最高考核标准，而他**没有解释这个指标为什么能豁免于他刚论证过的同一条规律**。可预期的指标游戏有两种，都很容易发生：承诺变得越来越保守（只承诺稳拿的事），以及真正的承诺转入不留痕的渠道（电话、私下当面说）。使用时必须把这两种漂移当作监测项，见步骤 6 的判停条件。
- **边界只有原则，没有制度**：作者给的保障全是原则性表述（不读隐私、看聚合、员工知情、数据留内），**没有任何制度化制衡**——谁审计、能否申诉、越界如何被发现，书中都没有回答。而他刚论证过桥水"靠人对抗人性"不可持续；靠 CEO 自律守边界是同一种不可持续。步骤 2 是为了补上这个缺口。
- **法律合规风险**：在中国大陆及欧盟等法域，读取员工通信、会议录音与工作记录受《个人信息保护法》《劳动合同法》/GDPR 等约束，实施前须完成合法性基础评估、必要性论证与员工告知程序。**本 skill 不构成法律意见。**
- **作者是零一万物创始人兼 CEO，"老板AI"是他公司在售的产品**（书中承认"我每天都在用，也开始卖给客户用"）。本 skill 已抽象为机制清单不绑定供应商——这也是作者本人的授权："你不一定非得用我的。"
- **书中的视角是单向的**。整章从 CEO 的位置出发论证信息对称的价值，但对被记录方的处境几乎不着笔墨。一套只有一方能调阅的"对称"账本，在权力上并不对称。

### 容易混淆的邻近方法论

- 与 OKR 不同：OKR 是目标设定，本 skill 是承诺追踪。目标树是二者的接口。
- 与 360 度评估不同：那是靠人评人（桥水是它的极端形态），本 skill 明确避开互评。
- 与员工行为监控软件不同——这是必须守住的区分，也是本 skill 最容易滑落的方向。区别在于：看聚合模式还是盯个人、员工知不知情、有没有申诉通道。
