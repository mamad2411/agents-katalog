# SeaLeap 多站点商品推广创建与管理

把一次多站点操作拆成可核查的国家级配置。统一管理可减少操作，但各站商品、币种、预算和投放状态仍需分别验证。

## 输入

源广告账户、目标国家、账户类型（卖家/供应商）、各站 profile、商品映射、可售/配送与广告资格、语言、投放方式、逐国预算上限及用于汇总的币种与汇率。

## 工作流

1. 确认当前账户具备全球/跨国 campaign 功能，以及支持的站点和投放方式；不要将旧版批量创建与新版全球 campaign 的对象层级混用。
2. 在广告创建流程选择 SP 和商品，检查每个国家系统匹配到的本地 ASIN/SKU。缺货、匹配错误或不具资格的国家/商品先单独标记。
3. 检查系统推荐关键词、类别、竞价及本地化。商品定向的类别映射与具体目标选择分开确认，不能假定系统自动选好了所有 target。
4. 逐国填写本地币种日预算，换算成共同展示币种复核总暴露。视频明确显示新增国家会新增日预算，不能把总额当作原国家预算的自动拆分。
5. 输出可审阅草稿。若会话已授权创建或编辑，按明确对象执行并回读逐国配置；不以全局成功提示替代国家级状态检查。
6. 在全球总览和国家过滤视图分别检查表现。处理 `Partially delivering` 时定位未投放国家的资格、商品、日期、预算及状态。

## 交付

国家—商品映射表、本地化核查、逐国预算/竞价与汇率总额、计划或实际操作记录、逐国状态、未完成原因及回退值。

## 证据与执行范围

- 材料中的案例、比例和时间表标为 `COURSE_BASELINE` 或 `TRAINING_CASE`；来源与口径已核验的店铺数据标为 `ACCOUNT_FACT`，用户转交但未核验的数据标为 `USER_PROVIDED`，合成练习标为 `SIMULATED`。推断标为 `HYPOTHESIS`，缺失项写 `UNKNOWN`，不补成 0。
- 先固定店铺、广告 profile、站点、ASIN、币种、数据窗口与归因口径。课程介绍的资格、界面、报告字段和功能覆盖在实际使用时核验。
- 默认交付诊断与草案。真实写入只在当前会话已授权的对象、动作和预算内执行，并保存旧值与回读结果；新增范围先取得授权。
