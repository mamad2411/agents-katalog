# 全平台归档编排

## 边界：做什么、不做什么

**做**：把本机所有 AI 当天及遗漏的工作成果——对话逐字全文、任务卡、工作日志、交接、未闭环事项、记忆、代码、资料原件——按"先查差异、不单向覆盖"归档到你自己的云端，并让多设备与云端对齐。

**不做**（除非用户当场明确指令）：

- 不删除云端文件、不挪进待清理、不改任何分享设置（不开链接、不加协作者、不转所有者）。
- 不把云端工作环境（如云电脑）当存储层；它产出只单向推到你自己的云端，任何东西都不写回该环境。
- 不把任何一家云盘当唯一锁定；用哪个仓库、哪个云盘由用户在配置里自己定。
- 不把在线表格本体拉到本地；本地只存"链接 + token + 可打开的导出副本"。

## 全平台支持（不绑定任何一家 AI）

任何能读本地文件、或能在页面上下文发请求的 AI 都可以执行本流程。常见来源包括但不限于：

| 类别 | 典型来源 | 本机是否有原始记录 |
|---|---|---|
| 本地编码 / 代理类 | Claude、Codex、Cursor、WorkBuddy、各类 IDE 内置 AI | 多在本机会话目录（部分为压缩格式，需解压枚举） |
| 桌面客户端 | 豆包 / 豆包工作模式、通义千问办公等 | 工作模式有轨迹；**普通闲聊框往往本机不落盘**，只能走界面 / 接口抓取 |
| 网页版 | 网页版 ChatGPT、Claude、Gemini 等 | 本机通常无原始记录，需逐轮手写归档或接口抓取 |
| 移动端 App | 各家手机 App | 落盘位置需单独核实，未确认就写"未确认"，不猜 |
| 小组 / 子代理 | 多 AI 协作、子代理会话 | 子代理通常只进全量记录、不单独出逐字稿 |

**关键事实**：很多产品的"普通闲聊对话"不写入本机，只存在服务端。声称"已全量归档"前，必须单独确认这一类是否通过界面 / 接口抓取补齐，不能用工作模式的导出数冒充。

## 三个归档指令

| 指令 | 范围 | 动作 |
|---|---|---|
| 归档 | 仅本机 | 跑刷新脚本 + 补齐任务卡/日志/交接/未闭环，不提交不推送 |
| 归档云端 | 仅云端 | 只提交/推送/上传，本机文件结构不动 |
| 归档本地云端 | 本机+云端 | 先拉后推，本机与云端都到最新；工作区所有未同步改动一起处理，不分窗口/AI |

单说"归档"默认**全 AI 覆盖补漏**：刷新脚本幂等、只补缺失/过期，再对照变更流水补"有改动无日志"的日子，网页版 AI 落到对话导出目录。用户说"结束/今天到这"且没提推送，按"归档"处理并告知还有哪些没推。

## 云端工作环境：单向只出不进（硬边界）

在第三方托管的云端环境（如云电脑、云容器）里执行时，数据流必须严格单向：

- **只推不拉**：只把该环境本地产生的成果上传到用户自己的仓库 / 云盘；不下载、不删除远端，**绝不把用户云端的业务数据反向拉到该环境落地**，否则数据会在第三方基础设施多落一份、扩大暴露面。
- **唯一允许的"拉"**：从用户自己的版本仓库拉取**程序 / skill 本身**（运行所需，是代码不是业务数据），且只落到运行目录。
- 对账只走只读 API：列目录、读元数据在内存中比对，不把任何文件下载落地。
- 双向同步 / 下载落地只发生在**用户自己拥有的设备**（本机笔记本 / 台式机）上；第三方云端环境不适用，二者不得混淆。

## 归档分层与留存口径

判据只有一条：**以后还会不会被打开、被引用、被复用**。

| 层 | 内容 | 处理 |
|---|---|---|
| A 交付层 | 对话逐字全文；交付成品（文案、方案、幻灯片、页面、成图、数据快照、脚本）；台账 | 永久保留；成品只留最终版，被替换的旧版进本地备份一次，不长期保留 |
| B 过程产物 | 工具输出、命令日志、试错中间结论、渲染帧、中间副本、验证截图 | **不归档、不上云、不进索引**；只把结论蒸馏进记忆 / 任务卡 / 工作日志 |
| C 不可读残渣 | 临时落盘、缓存、调试脚本 | 不归档、不进索引、不主动删；留本机，磁盘紧张或用户发话再清 |
| — 禁存 | 授权 / 二维码 / 密钥截图、密钥文件、个人隐私文件夹 | 哪都不存 |

四条硬规则：

1. 对话逐字全文永久，永不设保留期。
2. 过程产物不归档；能留下来的只有结论（决策、偏好变化、踩过的坑），写进记忆与工作日志。
3. 残渣不删：删除不可逆，正确做法是"不入库、不进索引"，不是"删掉"。
4. 同一内容只归一处：判重按**内容哈希**，不按文件名。

## 不重复归档（判重三层）

| 层 | 判据 | 命中含义 |
|---|---|---|
| 1 整文件 | 文本 normalize（去 BOM、CRLF→LF、去空行）后哈希 | 完全同一份，纯冗余 |
| 2 正文 | 剥掉文件头元数据块后哈希 | 同一内容被不同脚本/设备各写一次，仅头部不同 |
| 3 会话号 | 按来源精确正则取会话号，同号多份分类 | 区分冗余、两代并存、设计内组合 |

- 导出前先查归档里是否已有同会话号文件；正文哈希一致就跳过，不因"这台机器没导过"再写一份。
- 同一窗口的抓取落点必须固定文件名、增量合并，不许带时间戳新起文件。
- 换脚本重导时保留内容更全的一份，更少的进本地备份并标 superseded，不删除、不两份并存上云。
- 设计内多份（单次索引、补充材料、汇总、清单，以及"轨迹导出 + 界面抓取"两层互补）不算重复。
- 已存在的重复按红线不删除，只登记在去重报告里等用户裁决。

## 防覆盖：先查差异，再动手

1. **先拉后推**：先把云端在上次同步后改过、新加、改名的跟到本机，再把本机新的推上去。
2. **三方比较**：每个文件拿"上次同步基线"分别和本机、云端比。只一边改了就同步到另一边；两边都没改不动；**两边都改 = 冲突，两份都留，列给用户定**，不单向覆盖。
3. **删除改名不靠猜**：目录列表里找不到不等于删了（大目录会漏列），按文件标识核实；云端改名本机跟着改，不按旧名再传一份。
4. **覆盖前先备份**被替换件到本地备份目录。
5. 在线表格本体是唯一权威，本地导出副本禁止反向覆盖本体；超过 1000 行禁止全量拉记录，用后端统计或条件筛选。

## 来源标注：统一文件头

所有新建归档文件顶部带机器可解析的来源元数据块，字段包括：平台（精确到普通对话/工作模式/网页版/App）、设备、窗口（侧栏原标题）、会话号（去重主键）、抓取方式、抓取时间、来源时间、完整性、脱敏情况、归档执行者。

- 未知字段写"待补"，禁止猜测；不能只写产品名，要精确到具体形态。
- 旧文件不批量重写，在下次增量更新时逐步带头；新文件不带头视为归档不合格。
- 文件名与文件头两处会话号必须一致。

## 容量预算：先估大小再定范围

- 归档定范围前，先把来源目录遍历出真实体积，把数字摆给用户，再决定传什么。
- 本地原始目录里绝大部分往往是缓存、二进制与过程产物（正是不要的部分）；真正要上云的对话文字与配图通常只占很小比例。
- 音视频是否归档，先估体积再由用户拍板；默认不把过程层的大文件塞进云端。

## 定时调度与重启自愈

- 无人值守任务同样遵守"全 AI 覆盖补漏"，发现漏的自动补，不只导出某个基座；当天产出必须在用户指定的云端位置可见，只落本机记为未完成。
- 多触发源（系统定时 + 常驻循环）靠**文件锁**互斥，同一时刻只有一个归档实例，重复触发自动跳过，杜绝并发上传与重复归档。
- 脚本内全部用绝对路径（定时环境的 PATH 精简）。
- 容器 / 无系统服务的环境重启后定时守护可能不自启，需靠启动脚本（可经免密提权）重新部署并拉起；每次在该环境干活前先跑一次启动脚本（幂等）。
- 定时任务遇冲突、删除、授权失败时停止并写日志，不自行覆盖、不重试被拒操作。

## 完成前的覆盖率自检（不许笼统说"已归档"）

每次说"归档完成"前，逐行给出**原始量 / 已归档量 / 差额原因**，缺一列不算汇报：

- 源会话数取各软件自己的会话目录数；已归档数按文件名 marker 之后的会话号与源求交。
- 差额必须逐条给原因，区分"规则内不导出（子代理/空会话）"与"真漏了"。
- 本机无某来源 = 这台机器没装该软件，写"未核"，不写"已归档"。
- 自检在每台设备各自跑；一台全绿不等于其它设备全绿。
- 平台拿不到全部原文时标"尽可能完整版本"并列出缺失范围，不得补写不存在的原话。
