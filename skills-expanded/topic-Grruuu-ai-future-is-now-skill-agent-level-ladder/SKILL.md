# 智能体的四级阶梯

## R — 原文 (Reading)

> 第四级：智能体（Agent）。 这一级发生了权力的真正移交。你只需要给出一个宏观目标，它就能自己从头到尾把事做完——把模糊的目标拆解成有序的步骤，调用工具执行，遇到阻碍时自我修正，最后把完整的结果交给你。整个过程中，你不需要陪在旁边逐步确认。
>
> — 李开复，第3章《从会回答到会完成：4级阶梯》

> 智能体能力边界真正的分水岭在第三级和第四级之间。副驾驶型AI再聪明本质上仍是"你做，它帮"，智能体则是"你定目标，它来做"。
>
> — 李开复，第3章

> 而今天大多数企业买来的AI工具其实还停留在第二级和第三级之间，只是被包装成了第四级的样子出售。
>
> — 李开复，第3章

---

## I — 方法论骨架 (Interpretation)

这套框架把「AI 与人的协作方式」排成一条从被动到主动的阶梯，每上一级，人让出的控制权就多一分。

- **第一级 聊天机器人**：你问它答。它博学，但只动嘴不动手。对话结束，世界上什么都没发生。
- **第二级 工具型**：你下一个明确的微观指令（翻译这份合同、总结这篇财报），它交出一个结果。质量可能不错，但它不判断下一步该做什么。
- **第三级 副驾驶**：它理解你的意图并给建议，但方向盘始终在你手里，每个节点都要你确认。
- **第四级 智能体**：你只给一个宏观目标，它自己拆解步骤、调用工具、遇阻自纠、交付完整结果，全程不需要你陪着确认。

关键不在于级数本身，而在于**分水岭落在第三级和第四级之间**：三级是"你做，它帮"，四级是"你定目标，它来做"。这一字之差决定了它是提高你的效率，还是替你承担一段工作。

支撑第四级的是三种能力的叠加：工具调用（能真正读写外部系统）、任务规划（把模糊目标切成有依赖关系的子任务）、自主纠错（失败时自己读错误、改参数、重跑）。三者缺一，就掉回第三级。

这个框架的实用价值在于它给了你一个**可以当场做的测试**，而不是听供应商讲故事。

## A1 — 书中的应用 (Past Application)

### 案例 1：1987 年苹果《知识导航者》短片
- **问题**：一位人类学教授要在下午讲亚马逊雨林焚烧问题，旧笔记不够，他记得有人曾和同事吉尔争论过碳排放数据，但想不起名字。
- **方法论的使用**：作者用这支短片作为第四级的原型标本。教授全程"没有打开程序，没有输入查询，没有翻菜单，也没有回忆文件名"，只用日常含混的句子说话。
- **结论**：一个不够好的助手会要求他再试一次；这个助手一次就明白他指谁，找出当年的预测并把数据展示出来。取材料归它，做判断归人。
- **结果**：作者判定这已是第四级形态。将近 40 年后这个愿景才成为现实——说明第四级不是营销词，是有明确行为特征的。

### 案例 2：2026 年企业采购现场
- **问题**：企业花了一年时间选型、试用、部署，攒了十几个智能体，"看上去到处都在用 AI，企业层面却没什么改变"。
- **方法论的使用**：作者用同一把尺子回量这批工具。
- **结论**：它们停留在第二、三级之间——会议纪要自动整理、合同初稿生成、报表自动汇总，每一步都要人下微观指令或逐节点确认，"只是被包装成了第四级的样子出售"。
- **结果**：作者据此把"搞清楚自己手里的工具处于哪一级"定为 CEO 做 AI 战略布局时**应该做的第一件事**。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 正在评估或采购某个 AI 产品，供应商宣称它是 agent / agentic / 自主的，用户想知道这话有多少水分。
2. 已经买了一批 AI 工具，一年下来"到处都在用 AI"但业务没变化，想搞清楚买到的到底是什么。
3. 在做 AI 战略规划，需要先盘点现有工具的真实等级再决定往哪投。
4. 在使用中感到别扭——"为什么每一步都还要我点确认""它怎么不自己往下走"——其实是撞上了三级的天花板。
5. 在给团队/董事会解释"我们和真正的智能体还差什么"。

### 语言信号

- "这个 agent 到底算不算真的 agent"
- "供应商说他们是 agentic 的 / 说这是 AI 员工"
- "为什么每一步都要我确认"
- "我们要不要上智能体"
- "这东西和 Copilot 有什么区别"
- "买了一堆 AI 工具但没什么改变"

### 与相邻 skill 的区分

- 与 `agent-four-components` 的区别：本 skill 回答"它是**哪一级**"（采购/选型前的分级判断）；那个回答"它为什么**不好使**"（已经在用、要定位缺哪个组件）。
- 与 `earnings-call-test` 的区别：本 skill 判断工具的技术等级；那个判断项目对财报的影响。等级高不代表能改财报。
- 与 `ai-solution-two-laws` 的区别：那个问的是"这个方案靠机器自学还是靠人工维护规则"（天花板问题）；本 skill 问的是"它能不能不用我陪着就把事做完"（自主性问题）。

## E — 可执行步骤 (Execution)

1. **做宏观目标测试**：给它一个**不指定步骤**的目标（例如"把这个月所有逾期超过 30 天的应收账款整理成一份带责任人的清单，并给每个责任人发提醒"），不要拆步骤、不要给流程。
   - 完成标准：观察它是要求你逐节点确认，还是自己往下走。
   - 判停条件：如果它要求你确认每一步 ⇒ **最高第三级**，直接跳到步骤 4，不必再测。

2. **测三种能力是否齐备**：
   - 工具调用——它能真正读写你的系统（CRM/ERP/OA/文件仓库），还是只能生成文本让你自己去粘贴？
   - 任务规划——面对模糊目标，它能不能自己切成有先后依赖的子任务？
   - 自主纠错——中途报错时（可以人为制造一个超时或权限错误），它是停下来等你，还是读错误信息、改参数、重跑？
   - 完成标准：三项各有明确的是/否答案。
   - 判停条件：三项缺任一 ⇒ 第三级；只能按微观指令做单件事 ⇒ 第二级；不能触碰任何外部系统 ⇒ 第一级。

3. **对照价格锚点**：确认等级后再看报价。第二、三级的合理锚点是软件订阅费（按席位/按调用量）；只有真正的第四级才配用"替代岗位成本"或"利润增量分成"来定价。
   - 完成标准：能说出"我们付的是软件的钱还是工资单的钱"，并判断这两者是否匹配。

4. **写下差距而不是结论**：产出一句话——"它现在是第 X 级，要到第四级还差【工具调用/规划/纠错】中的哪几项"，交给供应商或内部团队。
   - 完成标准：差距是可验证的功能项，不是"还不够智能"这种评价。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户只想优化提示词、调参数、让输出更稳定——那是用法问题，与等级无关。
- 用户在比较两个模型的能力/跑分——那是模型评测，四级阶梯不测模型强弱。
- 用户已经知道等级、只想解决"为什么答不准/答错"——转 `agent-four-components`。
- 纯信息查询（某产品多少钱、有哪些功能）。
- **等级不是越高越好**：在高风险、强监管、要求人工签核的流程里（授信审批、医疗处置、资金划转），第三级的"每节点确认"恰恰是必需的合规设计，不是缺陷。

### 作者在书中警告的失败模式

- **把第二三级当第四级买**：这是全书点名的采购陷阱，代价是一年时间和一笔预算换来"十几个互不相通的垂类智能体"。
- **只看演示不看自主性**：演示总是精心设计过的路径，看不出遇阻时它会不会停下来等人。

### 作者的盲点 / 时代局限

- **四级划分没有客观测量标准**。"宏观目标"和"微观指令"的界线是连续的而非离散的，同一个产品在不同任务上可能落在不同级。这个框架很容易反过来变成采购谈判里的话术——双方各执一词说对方标准不对。
- **作者本人在售第四级产品**（第7章的"老板AI"）。用一把由自己定义、且自己的产品恰好站在顶端的尺子去量竞品，存在结构性的立场问题。
- **书中的等级判断建立在 2026 年上半年的产品形态上**。当"每节点确认"被做成可配置选项时（很多产品已经如此），三级与四级的界线会变成设置项而非能力差别。
- **阶梯默认"自主性越高越有价值"**，但没有讨论自主性带来的责任归属问题——第四级出错时谁负责，书中没有回答。

### 容易混淆的邻近方法论

- 与"AI 成熟度模型/数字化成熟度评估"不同：那些评的是组织，这个评的是单个工具。
- 与自动驾驶 L0–L5 分级形似而神不同：自动驾驶的分级有明确的接管责任定义，本阶梯没有。
