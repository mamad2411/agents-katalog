# 変換ルール

## 前提

- 部長会は役員への報告の場。実質的な意思決定は部内で行う前提
- 役員が求めるのは「組織として何が起きていて、どう対処しているか」
- 「我々はこう認識し、こう対処している」という統制力を見せる

## 原則

1. **リスクは隠さないが、対策とセットで出す** — 問題提起だけの報告は不安を煽る
2. **案件の羅列ではなくテーマで括る** — テーマは3個以内に絞る
3. **個別案件の進捗は「補足」に回す** — 役員が読むのは上半分だけ
4. **天気マークは全体所感の1つだけ** — 個別セクションの天気は統合する

## 変換パターン

### 1. 全体所感

- 元データの全セクションの天気マークを総合し、最も厳しいものを採用
- 天気マーク1つ + 一言（20文字以内）で部門全体の状態を要約
- 天気マーク: ☀️（問題なし）/ 🌫️（不確実性あり）/ ☔（問題顕在化）

### 2. 重点課題への取り組み

- `重点課題.md` に定義されたテーマごとに、元データから関連する進捗を紐付ける
- 紐付けられる情報がない場合は「TODO: 具体的な進捗を追記」と記載
- 重点課題.md が存在しない場合はこのセクション自体を省略

### 3. リスクと対策

- 元データの 🔴 項目や ☔ セクションからリスクを抽出
- 各リスクは「状況 → 対策 → 見通し」の3点セットで記述
- 2〜3個に絞る（それ以上は優先度で切る）
- 見通しは具体的な時期・条件を含める

### 4. 共有事項

- 役員が知っておくべきだが判断不要な情報
- スケジュール変更、外部ステークホルダーとの調整状況など
- 1〜3個に絞る

### 5. 補足: 各ユニット個別進捗

- 「上記の案件単位の記載を参照」として元データへの参照を示す
- 元データの `---` より上がそのまま個別進捗として機能する
