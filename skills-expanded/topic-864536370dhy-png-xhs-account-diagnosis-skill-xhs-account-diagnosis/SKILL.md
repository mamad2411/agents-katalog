# 小红书账号诊断（流量与涨粉方向）

给小红书账号做一次聚焦「流量与涨粉」的体检：找出为什么没流量、不涨粉、疑似限流，并给出可执行的改进动作。

## 何时使用

- 用户要求「诊断 / 分析 / 体检」自己或他人的小红书账号
- 用户问「为什么不涨粉」「为什么没流量」「是不是被限流了」「账号哪里有问题」
- 用户给出小红书主页链接、或粘贴了账号简介 + 一批笔记数据，想要优化建议

不处理的范围：商业变现/接单报价/带货潜力评估（本 skill 只看流量与涨粉）；私域后台（创作中心、蒲公英）数据的抓取。

## 现实约束（重要，先读）

小红书主页有强反爬，直接对链接用 `WebFetch` **通常拿不到真实笔记数据**（会是登录墙或空壳 JS 页面）。因此：

- **数据主要靠用户粘贴。** 链接抓取只作 best-effort 补充——试一次，抓不到就立刻转向引导用户粘贴，不要反复重试或假装抓到了数据。
- **绝不编造数据。** 没有某项数据就在报告里标注「未提供」，并说明它会如何影响诊断结论。宁可结论少一条，也不虚构点赞数/涨粉数。

## 工作流

### 第 1 步：采集数据

先检查用户已经给了什么。缺失的，用下面这张清单一次性向用户索取（越全，诊断越准）：

**账号基础**
- 昵称、简介（一字不差贴出来）、IP 属地
- 粉丝数、获赞与收藏总数、笔记篇数
- 账号主赛道 / 想做的方向（用户自述一句话）

**近期笔记（近 15–20 篇，最能反映当前流量状况）**，每篇提供：
- 标题
- 封面：一句话描述，或直接贴封面截图
- 发布日期
- 点赞 / 收藏 / 评论 数
- 形式：图文 or 视频

> 提示用户：这些数字在主页笔记列表和每篇笔记页都可见，无需进创作中心后台。若能直接截图主页 + 几篇代表性笔记（爆的和扑的各几篇），更好。

若用户只给了链接：先 `WebFetch` 试一次。抓到有效内容就用；抓不到（多数情况）就明说「主页反爬，抓不到笔记数据」，并贴出上面的清单请用户补齐。**不要因为抓不到就放弃诊断——引导补数据即可。**

### 第 2 步：按六维度诊断

逐维度分析，每一维给出【现状 → 问题 → 证据】。评分与判断基准见
[references/playbook.md](references/playbook.md)（含数据基准线、限流判断、标题/封面公式）。

1. **定位与垂直度** — 简介有没有说清「为谁提供什么价值 + 关注理由」；近期笔记赛道是否聚焦。涨粉的前提是标签垂直、让人「知道关注你能持续得到什么」。
2. **内容表现结构** — 爆款率、篇均互动、点赞收藏比、互动率。判断内容是「有流量但留不住」还是「压根没流量」。
3. **选题与钩子** — 标题是否用了有效公式（数字/痛点/悬念/身份标签/搜索词）；封面信息密度与第一眼吸引力；选题是否命中用户搜索与需求。
4. **发布规律** — 频率、稳定性、是否断更、发布时间是否踩流量高峰。
5. **限流 / 异常迹象** — 数据是否断崖式下跌、是否突然全篇低于历史均值、标题/正文是否有违禁或导流词。
6. **涨粉转化** — 爆款有没有真正带来涨粉（内容与人设是否让人想「关注」而非只点赞）；有没有系列化/合集/关注钩子把单篇流量沉淀成粉丝。

### 第 3 步：产出诊断报告

按下面结构输出（模板与打分口径见 playbook）。核心要求：**每个结论都挂在用户给的具体数据上**，改进项必须是能直接照做的动作，不是「多发优质内容」这类空话。

```
# 小红书账号诊断报告 · 流量与涨粉

## 一句话结论
（账号当前最大的卡点是什么）+ 健康分 XX/100 🟢/🟡/🔴

## 分维度诊断
| 维度 | 评分 | 现状 | 核心问题 |
（六个维度逐行，评分用 🟢好/🟡待改进/🔴问题严重）

## 优先级改进清单
- P0（立刻做，最影响流量）：动作 + 为什么 + 怎么做
- P1（本周做）：…
- P2（持续优化）：…

## 未来 7 天行动
（3–5 条具体、可勾选的动作，比如「按 XX 公式重写这 3 篇标题」）
```

报告末尾：如果某些结论因缺数据而不确定，列出「补齐这些数据能让诊断更准」的 1–2 项。

## 风格

- 中文输出，直给结论，不绕圈。
- 表扬要具体（「收藏点赞比 0.4，说明干货属性强」），批评也要具体到某篇笔记/某句简介。
- 不迎合、不灌鸡汤；账号问题严重就直说，并给出改的路径。
