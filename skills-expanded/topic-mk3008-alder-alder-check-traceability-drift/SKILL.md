# Check Alder traceability drift

Read [the bundled pilot decision and contract](references/study.md) in full. [The original PoC instructions](references/README.md) explain the detector CLI; repository-relative evidence links are historical background, not required product inputs. The [detector](scripts/drift.py) and authorities are byte-identical copies pinned in [provenance](references/provenance.json). Select these automatically, without asking the requester to find internal authority files or clone Alder.

1. Read the product's `AGENTS.md` and resolve the requested pilot slice: current Business Design, Checks, existing reviewed `trace.json`, and the test runner/inventory adapter. Prefer explicit request paths, then project declarations. If mappings or compatible inputs are absent, report the specific missing prerequisite and stop this detection; do not bootstrap pins, migrate the repository, invent IDs or infer reviewed relationships. Pilot adoption and adapter development are separate work.
2. Confirm this slice supports the restricted contract: one source document and one Check document, each with an H1 label followed by stable-ID H2 sections such as `## BD-01` and `## CHECK-01`. Normative context must be inside those identified sections. Ordinary Activity/Object Business Design Markdown is not accepted by this PoC. The sidecar contains version 1, `check_sources` and `test_checks`; it records relationships and last-reconciled fingerprints, never approval. Do not transform arbitrary Markdown into synthetic sections to make detection pass.
3. Obtain a fresh JSON list of unique nonempty Test IDs from the actual runner's project-supported discovery adapter for the current code revision. Never substitute IDs from `trace.json`, guessed file names, stale logs, or a hard-coded inventory. Inspect the discovery command and project configuration before running: discovery can import code or invoke hooks. Use only an authorized discovery/list-only route that does not run tests or mutate project state. This read-only skill does not execute arbitrary project tests. The research `evaluate.py` combines discovery with test execution and pin mutations; do not run it against the product or copy its acknowledgement helpers. If no safe supported discovery route exists, stop and identify the adapter needed. State discovery provenance and any scope exclusions.
4. Check that the host can run Python 3.12+; the bundled detector needs only its standard library. Resolve `SKILL_DIR` to this installed skill's directory and invoke:

   `python3 "$SKILL_DIR/scripts/drift.py" "/path/to/business.md" "/path/to/checks.md" "/path/to/trace.json" "/path/to/current-inventory.json"`

   If execution or Python is unavailable, report the verified limitation. Do not replace the deterministic detector with an improvised implementation or claim a detection result. Keep temporary discovery inventory separate from product authority and do not change source files, Checks, mappings, pins, tests, code or human review states.
5. Interpret exit 0 as no known candidates in these supplied inputs; exit 1 as stale/missing/mapping candidates, not an execution failure or proven defect; exit 2 as invalid input. Report `stale_checks`, `stale_tests` and `mapping_candidates` with reasons and affected source/Check/Test IDs. Distinguish missing inventory/test, missing mapping, source changes, Check changes and invalid input. A wording-only edit can produce a conservative candidate; a new unmapped item is not proof that a new test is required.
6. Explain the Check boundary accurately: a changed source can mark a related Test `upstream_stale` while its Check is unreconciled. Reconciliation that preserves the Check body leaves matching Test pins current, with no forced Test-pin refresh or Test reconfirmation. A changed Check body still requires examining affected assertions and independent test evidence. Missing tests remain candidates. Never clear a candidate by refreshing pins merely because tests pass or text looks similar.
7. Return scope, actual installed plugin version from `../../plugin.json`, detector revision/digest, input revisions or working-tree state, inventory command/provenance, candidate summary and useful next action. Passing hashes prove neither complete/semantically correct mappings nor business approval, adequate assertions or implementation behavior. Missing/wrong edges and blindly refreshed pins can hide drift. Do not label freshness `確認済み` or set a mandatory CI/review gate. Leave genuine business decisions with the responsible human.

Stop after the read-only report. Separately authorized follow-up may reconcile affected relationships with evidence; this skill never acknowledges or regenerates baselines, changes pins, approves business meaning, adds Code-location traceability, or expands a bounded pilot into a universal parser/runtime.
