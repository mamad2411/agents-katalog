# LaTeX Lab-Report Editing (instruct → edit → build → verify → PDF)

House workflow for iteratively rectifying a compiled lab report per the user's instructions (recurring weekly labs, e.g. `.../labs/week-NN-*/reports/latex/*.tex`). The user reviews the **PDF**, never a diff.

## When to Use

- The user hands over a lab-report `.tex` — or a `codex://threads/...` handoff about one — with an instruction to rectify it ("改成 X，重新编译，给我最新 PDF").
- Recurring weekly lab reports under `labs/week-NN-*/reports/latex/` and their review loop.
- Scaffolding a BRAND-NEW week's report from the `labs/` universal template, and maintaining that template (sections below).
- NOT for writing papers from templates (use `academic-writing-latex`) or generic LaTeX debugging (use `latex-debugging`).

## Workflow per instruction round

1. **Clarify scope first** (user rule: 识别模糊缺失，逐条确认). When an instruction has a genuine fork (move vs delete, keep vs shorten, where extras go), scan the file first, then ask ONE grouped `clarify` with concrete options. If a constraint makes the answer determined — e.g. a label physically cannot fit its column — execute the only feasible option and flag it in the reply instead of asking. A free-text (Other) answer is a literal spec and may define a structure NEITHER option offered — §2.2's header spec came from the user's own typed answer; parse it item by item before editing (it was refined in two later rounds — the governing FINAL shape is House conventions → "Verilog listing structure"; never treat an intermediate shape as settled). An EMPTY `user_response` (dismissed popup) is NOT an answer: do only the provable part of the round, leave recorded numbers untouched, and re-raise the open question at the top of the reply until it is answered.
2. **Edit via a Python script** (`write_file` + run), never the `patch` tool: .tex is backslash-heavy and patch can double-escape (`\\par`). Raw triple-quoted strings; assert every `old` string has `count == 1` before replacing; run all verification asserts **before** the final write, so a failed check leaves the file untouched (re-running is then safe — edits re-apply from the pristine file). **Re-stat the file at round start** (`size`/`mtime` vs your last write): the user edits these .tex files themselves between rounds — 2026-10-03 they patched `tablecaptionnote` mid-round to fix 表前无换行 — so re-read and re-derive every anchor from the current file, write back only from that fresh copy (string-replace, never from memory), and acknowledge their fix in the reply instead of silently building on a stale baseline. Nuance observed 2026-10-03: the `patch` tool handles .tex fine when the old string is ONE unique line whose anchor contains no backslashes (e.g. the filename inside an `\includegraphics` clause) — its unified diff is shown before the file changes, and ~20 such edits compiled clean. Use it for single-line surgical edits; keep the script route for multi-line block moves and bulk replacements.
3. **Build twice**: `xelatex -interaction=nonstopmode <file>.tex` ×2, cwd = the .tex directory — pass `workdir=` EXPLICITLY to `terminal()`, never rely on session cwd (it may point elsewhere, the command fails quietly, and you then read the OLD log). **Before trusting any log-derived number, confirm the log/PDF mtime advances past your edit**: 2026-10-04 I reported 0/0/0 from a stale log for 12 hours until the user's file inspection exposed it (self-check: `stat log > edit_time`). Judge from the LOG, not the exit code: `grep -c '^!' == 0`, `grep -c Overfull == 0`, `Output written ... (N pages)`. xelatex can exit non-zero with output written, and vice versa. Build-artifact hygiene: `xelatex foo.tex.pdf` writes an output named `foo.tex.pdf` (jobname = input minus last extension) — stray `*.tex.pdf` duplicates confuse the user's PDF link (they asked 为什么不是.pdf而是.tex.pdf); delete them or say which file is canonical.
4. **Verify at three levels** before reporting:
   - source: order/anchor asserts inside the edit script;
   - PDF text: `pdftotext` output — **collapse whitespace first** (`re.sub(r'\s+',' ', ...)`). pdftotext breaks lines mid-sentence, so raw substring and per-page searches fail spuriously;
   - visual: `pdftoppm -png -r 100..130 -f P -l P` + vision check for anything layout-affecting (tables, figures, bold scope, spacing).
- **End every reply with** `[最新 PDF](/abs/path/file.pdf)` (plus the .tex link). Delivery = the PDF. **When the user asks `把pdf拷贝到桌面`** (they often do at the end of a round), also `cp` the built PDF to `~/Desktop/<same name>.pdf` and verify MD5 equality of source and copy before reporting — then give BOTH links (report PDF + Desktop copy). Overwrite the Desktop copy on every later round; it must never be a stale build.

Reusable checks: `scripts/verify_report.py` (build + float/mention audit). Prose style lint (banned words + >25-word sentences, run when the user tags `/tech-writing-style` / `/ai-writing-humanizer`): `scripts/prose_lint.py <file.tex>`. Measurement recipes: `references/verification-recipes.md`. Structural block moves, figure merges, and the mention-check regex: `references/structural-edits.md`. Delay-CSV → guide/report filling: `references/delay-data-filling.md`. FPGA section build (photo ingestion, delay-row builder, caption-style grep, data-provenance map): `references/fpga-lab-section-build.md`.

## Scaffolding a new week's report from the labs/ template

The universal template lives at `labs/digital-logic-lab-report-template.tex` (+ `digital-logic-lab-report-template-preview.pdf` renders its five layout recipes; both moved there from week-03's latex/ on 2026-10-03). To start a week:

1. `mkdir labs/week-NN-<topic>/reports/latex/`; copy the template to `week-NN-<topic>-lab-report.tex`; copy `multirow.sty` from any existing week's latex/ (TeX Live basic lacks it).
2. Extract experiment titles VERBATIM from the week's manual: `pdftotext -layout`, regex `Experiment (\d+\.\d+):` and slice the following sentence — keep the manual's own glyphs (’, ÷); XeLaTeX + fontspec renders them, assert 0 `Missing character`.
3. Replace the commented experiment-skeleton block with one ACTIVE `\subsection*{Experiment N.X: <title>}` per experiment, each carrying the standard experiment block as English `\textit{[...]}` prompts plus `% →【图】/【表格】` slot comments; add delay/scope slots only for experiments that actually have scope photos, and give the report a tailored header (manual title provenance, photo-dir note, multirow note). Update the appendix guidance comment `1.X` → `N.X`.
4. Auto-generate a per-subsection photo-inventory comment by counting `reports/photos/` files by name prefix and category (FPGA board → board, Oscilloscope capture → scope, probe → probe, Quartus → quartus, else → code); assert the sum equals the directory count (week-04: 69).
5. Fill DIVISION names (no student IDs) and REFERENCES from the manual cover + the previous week's approved entries; leave opening paragraphs/results as prompts for content rounds.
6. Build ×2, then pdftotext: section headings, every `Experiment N.X:` title — probe with the COLON (`2.1:`), a `2\.1 ` space probe never matches — plus names and refs; assert no CJK outside comments; `pdftoppm` page-1 visual pass; delete aux, keep `.tex/.pdf/.sty`.

## Measure, don't guess

- **Vertical gaps / line pitch** → `pdftotext -bbox`: group words by `yMin`, diff adjacent lines. Normal line white-space at 11pt with `\linespread{1.2}` ≈ 6.3pt; a "visibly huge" display gap measured 25.8pt.
- **Bold/italic really rendered** → `pdftohtml -xml`: look for `<b>`/`<i>` tags; `font="N"` is an index into the `<defs>` font table.
- **Column fit** → measure rendered word width (`xMax − xMin`). Table budget: `sum(col fracs) × \linewidth + 2×tabcolsep×ncols ≤ \linewidth`. If a label exceeds its content width, shorten the label — widening one column only steals from columns that have no slack (e.g. header-bearing `p{.13}` trial columns). **Resizing a column keeps the frac sum** (user: 表格满页宽): when one column shrinks, donate its width to a sibling (week-03 Member table 0.35+0.58 → 0.20+0.73) so the table stays full-width and centered in place — never shrink the sum.
- **Caption centering** → `pdftotext -bbox`: cluster the caption's words into one line (mind both traps in Pitfalls), `center = (xMin+xMax)/2`; target = page center `left margin + textwidth/2` (A4, 1in margin → 297.6pt) for full-width captions, or the column center for paired ones (0.48 columns → 180.3 / 415.0). Expect ±1pt; a real misalignment shows ~68pt off (= 0.15×textwidth).

- **Rendered image size** (did my `width`/`height` cap actually bind?) → `pdfimages -list <file>.pdf`, filter rows with `type == 'image'` (each raster also emits a `smask` row), then **placed inches = pixel width ÷ x-ppi** (and height ÷ y-ppi). Token indices in a data row: `page num type width height color comp bpc enc interp object ID x-ppi y-ppi size ratio` → `x-ppi` is index 12, `y-ppi` 13 (index 11 is the object ID and can be `0`, which silently gives a ZeroDivisionError if you use it as ppi). Identify each figure by its pixel width (matches the source PNG: `1138`→hd-25931, `1490`→the cropped 1.7 scan). This is the authoritative "is it too big" number — the user judges size from the PDF, and ink-coverage percentages on rendered pages are useless as a size proxy because the body text dominates.

## Display formula has an abnormally large gap before it

Two independent causes; fix BOTH:

1. An explicit `\par` on the line directly before `\[` injects `\parskip` (6pt typical). Delete `\par` when the next line is `\[` — the paragraph flows into the display.
2. `\setlength{\abovedisplayskip}{...}` **in the preamble is silently wiped**: `\normalsize` (size11.clo) runs at `\begin{document}` and resets all four display skips. Set `\abovedisplayskip`, `\abovedisplayshortskip`, `\belowdisplayskip`, `\belowdisplayshortskip` **immediately after `\begin{document}`**.

Expected result (11pt, parskip 6pt): text→formula ≈ 8.5pt, formula→text ≈ 10pt. Re-measure with `pdftotext -bbox` to confirm.

## House conventions (RULES for this user's reports)

- **Font sizes: 大标题 12pt; captions (figure + table) AND merged-figure sublabels 9.5pt/12pt; everything else 11pt.** User split captions off to 9.5pt (2026-10), superseding the earlier all-11pt rule; a table dropped to 10pt so headers fit is still a violation — fix widths/content instead. Audit: `re.findall(r'\\fontsize\{[^}]+\}', tex)` counts by size.
- **Float ordering**: every in-text `Table N` / `Figure N` mention must appear BEFORE that float, and every float needs an introducing sentence before it (first-mention check is scriptable — `scripts/verify_report.py`).
- **Experiment-section template**: intro paragraph ENDING WITH COLON → display formula(s) → circuit-structure paragraph leading into the Figure → Figure → **LED state photos + their lead sentence (BEFORE the truth table)** → truth-pattern paragraph (conclusion-style sentences leading into the table) → Table → delay paragraph → delay table → [scope traces AFTER the delay table]. Rationale (user's words): 照片是"实验中的状态"，状态先行，真值表是抽象结论 — a user correction, never put state photos after their truth table. Delay evidence (scope traces, bounce waveform) stays with its own table and is NOT moved up (user chose this scope explicitly when asked). The compile/LE report block (resource-count sentences + the `Compilation report for …` figure) sits at the END of the experiment section, after results and analysis — user: `把实验2.1的LE report部分放到该部分最末 和2.2一样` — never right after the code; moving it across other figures triggers the renumber cascade (references/structural-edits.md → Moving float blocks).
- **One colon-sentence → formula pair per equation group.** When a section heads several outputs (EQ/GT/LT, G₁…G₄), do NOT hang three displays off one intro colon — split into `The greater-than output $GT$ is $1$ when …:` → `\[ GT=… \]`, repeated per group. Each lead must state what the equation means (when-true / mirror), derived from the formula itself.
- **Table lead-in = the conclusion the data proves**, never the table's identity ("Table N lists …"). Concise but powerful; re-verify every quoted number against the actual cells before writing it.
- **Result tables carry results, not verdicts**: columns like `Inputs | Ideal action | Measured result` — no "Matches"/assessment column, no photo-index column, no "in two captures". The verdict ("all eight results agree with expectation") and provenance caveats ("the $10$ retention was not photographed") live in the lead paragraph instead.
- **Caption = identifier; the lead sentence carries the content.** Strip specifics out of captions: `Circuit diagram 1.3` (drop the trailing description), `Discrete XOR` (not "Discrete XOR: A=0, B=1 gives Y=1"), `NAND latch input 00` (not "…: recorded (Q,Q̄)=11"), `Half-adder: 1+1 gives 10` (drop `(C,S)=`). Kill "gives …"/"recorded …" phrasing in captions; conditions/results stay in the lead sentence or the tables. Exception: merged-figure sublabels keep their short facts (`(a) $EQ=1$ at $A=01$, $B=01$`).
- **Captions = plain centered paragraphs — NO width cap, NO boxes** (user order: 彻底取消70%宽度限制的宏；题注形式要正确，不要正文模版或其他歪路). Macro: `\refstepcounter{}\par\begingroup\setlength{\parskip}{0pt}\centering\normalfont\fontsize{9.5pt}{12pt}\selectfont Figure N. text\par\endgroup` — tables add `\vspace{1pt}\nopagebreak[4]` so the title hugs the table (measured ≈5.5pt; the old boxed version sat 20.1pt away). The `\par` INSIDE the group is what centers: `\centering` binds only paragraph lines, so any bare box (minipage/makebox) dropped in vertical mode lands LEFT — all 13 table captions once sat 67.7pt off-center that way. Measure after any macro change (never by eye), and do NOT reintroduce a width cap — the user explicitly removed it.
- **OBJECTIVES = 3-sentence lead + ≤6 thematic bullets, no labels** (user corrections, 2026-10-03): lead ends ``The main objectives are as follows.'`. Bullets follow KNOWLEDGE THEMES, never the experiment order (user: 不要按照实验顺序，要按照知识点的叙事角度一点一条) — week-04's order was instrument → code → logic → delay. **No `Theme:` label prefixes** (user: 不要小标题; matches the humanizer's inline-heading AI-trace rule): every bullet starts with a verb. Cap ≈6 bullets, one sentence each ≤25 words (user cut 9 → 6: 哪来这么多objectives，精简一点). When the user tags `/tech-writing-style` and `/ai-writing-humanizer`, run the bullets through both: active imperative voice, banned-word scan (several/various/approximately/e.g./i.e./etc.), split >25-word items, no filler. Verify: pdftotext `• ` count == expected, old label phrases absent from the page text, and `:` absent from the itemize after stripping `\texttt{...}` (the `?:` operator carries a genuine colon). (e) **Cap every claim at the manual's own purpose/intro sentence** — user, 4th round: "你再看一下每个实验开头那一句 The purpose of this experiment…，最多就写到这，不要夸大事实". Nothing beyond it from To-do/guide: no Week-3-comparison promise, no voltage figure the manual never states; the LED convention reads "keep the output logic value and the lamp state separate, because the board's LED polarity can invert the visible state", never "lit LED = 1" / "3.3 V reference". When the user says "还是一样的要求" for the next block, the same cap governs the **DATA ANALYSIS opening paragraph**: equipment sentence → workflow sentence → hedged, attributed convention → "The following subsections cover experiments …". SUMMARY then mirrors the final bullet set.
- **SUMMARY = 总起段 + dot points, mirroring OBJECTIVES' shape**: one 2–3-sentence lead ending `The main findings are as follows.` (qualitative only — no numbers duplicated from the bullets), then `\begin{itemize}` with ONE `\item` per objective (gate behavior → keys/LED → voltage vs spec → Boolean equations → combined circuits → delay). The delay bullet must state the full cross-gate ordering with numbers (dedicated 74HC86 < NAND < two-stage AND < NOR < two-stage OR < four-NAND XOR slowest, plus headline ratios) — section leads only compare within their own experiment, so without it the report has no cross-gate conclusion. Quote rounded means (34–41 ns from 34.39/40.53); trial extremes can differ (13.75 → the "13" bound holds only under the means reading).
- **Photo-figure layout**: pairs = two `[t]{0.48\\linewidth}` minipages, image `width=0.96\\linewidth, height=1.65in, keepaspectratio`, `\\hfill` between, caption inside each minipage. Three-across = `0.31\\linewidth` columns + plain centered `(a)`/`(b)`/`(c)` labels under each image (plain text, NOT `\\figurecaptionnote` — that would bump the counter), wrapped in a full-width minipage so the row can't split across pages.
- **Circuit-diagram size caps (user rule, 2026-10-03: 所有电路图的长宽都要做限制，现在的太大了看着不舒服)** — BOTH dimensions capped, `keepaspectratio` always: **single image** `width=0.6\\linewidth, height=1.9in`; **every cell of a 0.47-pair or 2×2 grid** `width=\\linewidth` (cell = 0.47\\linewidth) `, height=1.4in`. On A4 with 1in margins (textwidth 6.268in) that is 3.76in / 2.95in wide max. This **supersedes** the older `0.84\\linewidth, height=2.45in` single style and the previously uncapped `width=\\linewidth` cells — do not reintroduce them; the user sized the whole set down in one pass (e.g. 1.7 went 4.97×2.45 → 2.51×1.90in, 1.5's NOR cell 2.95×2.00 → 2.06×1.40). **Side-by-side figures must be EQUAL HEIGHT, not equal width** (user: 并排放置的图，要等高而不是等宽 — this supersedes any "unequal heights in a `[t]` pair are acceptable" assumption). Per pair or grid row: `H = min(height_cap, cell_width / max(aspect_a, aspect_b))`, then give BOTH cells the same `height=Hin`, rounded DOWN so the width cap never binds first (border case: `H×aspect` landing within 0.001in of the cell width). Inside a `0.47\linewidth` minipage `width=\linewidth` IS the cell, so the backstop stays `\linewidth`. Verify with `pdfimages -list`: the two placed heights must match (±0.005in is integer-ppi rounding noise, not a mismatch). Photos keep their own `0.96\\linewidth × 1.65in` rule — the caps apply to **circuit diagrams**.
- **A percentage resize request (缩小30% / 缩小一半) scales BOTH dimensions, and only the sections named.** In a 0.47 cell set `width=0.7\linewidth` (70% of the *cell*, since `\linewidth` inside a minipage is the minipage) and multiply each height cap by the same factor; scaling heights alone leaves width-capped images at full width. Then verify from `pdfimages -list` that every target image reports ≈ the factor in BOTH width and height (70%/70%) and that every non-target figure reports 100% — this is also the proof to show the user.
- **One figure group = one option set, BYTE-IDENTICAL across the whole report** (user: Fig 9 10的图片大小和其他二重图保持一致 要标准): every pair/grid of the same class shares the exact same `\includegraphics[...]` options — week-04's fix was one stray `height=2.3in` → `height=1.65in`, after which all four photo pairs were byte-identical (same natural px, `keepaspectratio` → same rendered size). Audit by counting the standard option string over the whole tex and asserting no other variant remains on body figures; expect SKELETON placeholders to share the same option string (week-04: 13 = 8 body figures + 5 skeleton slots), so assert the exact total, never `== body count`.
- **Portrait figure sources: transpose EXIF before resizing, and size portraits by HEIGHT only (user: Figure 15 本身是个竖着的图 你让它横过来干什么 … 如果是竖着放的话 保持现有的高度就好了)**: originals shot portrait carry `EXIF Orientation=6`; any ingestion that skips `ImageOps.exif_transpose()` freezes the raw sideways pixels into a landscape asset and the figure ships rotated 90°. Detect over `reports/photos/` with `im.getexif().get(274)`; ground truth after the fix = `pdfimages -list` (a portrait asset embeds `750 1000`; placed inches = px ÷ ppi — week-04 Fig 4 measures 3.333×2.500in, i.e. the solo class height really is 2.5in). Regenerate affected assets through the ingestion pipeline (references/fpga-lab-section-build.md), then give portrait figures the HEIGHT-ONLY option `[height=Xin,keepaspectratio]` — drop the width constraint, keep the class height (solo compile report 2.5in, pair 1.65in). The byte-identical-one-set rule groups figures by ORIENTATION: landscape pairs keep `width=0.96\linewidth,height=1.65in`, portrait compiles use `height=2.5in`/`height=1.65in` — state the exception in the reply. Week-04: four Quartus-report originals (2-4, 2-5×2, 2-8) were portrait → assets regenerated 750×1000, Fig 15/18/19/26 switched to height-only; board photos were orientation 1 and untouched.
- **After a targeted edit, audit scope and state it in the reply** (user: 别乱改别的). Keep the pre-edit snapshot from your first `read_file`, then list every `\includegraphics` with its options grouped 照片/波形 vs 电路图 and confirm untouched parameters are byte-identical; report structural deltas too (this round: 767→769 lines, all from the two single→pair conversions the user asked for). Photos stay at `0.96\linewidth × 1.65in` (bounce waveform `0.72\linewidth × 2.45in`).
- **Zero-gap placement for white-background figures** (user: 两图间距不要那么大，直接调成0都可以，因为电路图本身就是白底). Two recipes: (i) a multi-image row inside one `center` — put the images in ONE paragraph and join them with `A\hspace{0pt}B` (a bare source newline between them leaves a ~3.5pt word space); (ii) each image in its own minipage — size the minipage to the image's NATURAL width at the target height (`width_in = H × px_w/px_h`, 4 decimals) and close with `\end{minipage}%` so no glue appears; adjacent minipages then touch and `center` still centers the pair as one line box. Do **not** keep `0.47\linewidth` cells with narrower centered images: the visible gap is `cell − image` and reaches ~2in. Pre-check: sum of widths ≤ \textwidth. Verify from `pdfimages -list` (heights equal, widths as computed). **When the user flags ONE group figure as having too-wide gaps (Fig 11 间距太宽了，参照其他组图调整), fix that one and then AUDIT every sibling circuit-diagram block for the same old pattern** — `grep -n '0.47\\linewidth' <tex>` must come back empty for circuit blocks, and every remaining `\hfill` must belong to a photo pair (photos are not white-background, they keep their gaps). Report the audit result in the reply: it is the proof that "参照其他组图" now holds everywhere and that nothing outside the named figure moved.
- **Splitting a figure** (拆成两个Fig — one composed figure → N separate figures): one `\figurecaptionnote` per sub-image, each inside its own minipage, caption text naming the half (`Circuit diagram 1.5: NAND latch`). Each extra caption is +1 to every later figure number — splitting two figures took the report from 21 → 23 figures while Tables stayed 1–13 — so rewrite every hardcoded prose ref in the same pass (`Figure 14 shows…` → `Figures 14 and 15 show…`; `Figures 15 and 16 …` → `Figures 16 and 17 …`; `Figure 20 …` → `Figure 22 …`). Post-build audit: `grep -oE 'Figure [0-9]+\.' out.txt | sort -u -V` must be contiguous 1..N, `Table [0-9]+\.` unchanged, and a form-feed page counter must put each caption on the same page as its image (`pdfimages -list` page column). Two trade-offs to FLAG in the reply rather than silently ship: the caption box equals the image width (2-line wraps), and if only one image of the pair was resized earlier the two captions sit at different y — offer equalizing heights or stacking the figures with full-width captions. Full snippet: `references/structural-edits.md` → "Figure split".
- **Merging figures into one**: a single `\figurecaptionnote` after the wrapper; singular lead ("Figure 21 shows…"). **Caption wording for hand-drawn circuit groups is POSITIONAL in the caption text** (user's instruction pattern, used twice): `Circuit diagram 1.5: NAND latch (left) and NOR latch (right)`, `Circuit diagram 1.6: half-adder (left) and full-adder (right)`, three-up `Circuit diagram 1.7: equality (left), greater-than (medium), and less-than (right)` — keep the user's own wording verbatim even when non-standard (`medium` rather than `middle`) and never invent a qualifier: when the user writes a placeholder (`xxx half-adder`, `xxx equality`), drop it and FLAG it in the reply rather than filling it in (this was flagged twice and never objected to). Photo figures keep the other style: plain `(a)/(b)/(c)` sublabels, which do NOT bump the counter. Safe only after grepping for downstream hardcoded `Figure N` prose refs — merging decrements every later figure number, and merges often come in a SEQUENCE of rounds, not one shot: this report went 23 → 22 (merging 1.5, 6 prose refs to rewrite) → 21 (merging 1.6, 4 more) in separate rounds, each needing its own edit batch + rebuild + `grep -oE 'Figure [0-9]+\.'` audit for contiguity. Recipes for both merge shapes (equal-height one-line row vs. `[t]` image-width minipages when heights differ): `references/structural-edits.md` → "Merging back".
- **Delay tables**: header `Circuit | Delay | Trial 1 (ns) | Trial 2 (ns) | Trial 3 (ns) | Mean (ns)` — bold, **left-aligned** (never `\multicolumn{1}{c}{...}` centering), single line; one cell per trial; edge pair folded into the Delay column (`$t_{\mathrm{PHL}}$ (rise $\to$ fall)`); 11pt, `tabcolsep` 3pt, portrait inline (no landscape pages). This flat shape holds UNTIL the data spans several gates × a control input.
- **Gate-grouped delay tables (week-04 user restructure, order of operations)**: instruction pattern: 按 gate 类型归类（LED 编号顺序）、条件与 gate 拆两栏、有条件合并单元格. The pre-restructure form crammed condition+gate into ONE column (`$K_2=0$, Buffer`) — split it. Result: 7 cols `Circuit | K2 state | Delay | Trial 1 (ns) | Trial 2 (ns) | Trial 3 (ns) | Mean (ns)`; rows in LED1→LED8 order; a gate that responds at both states gets 4 rows (per state: rise then fall), a one-state gate 2 rows (rebuild row order from the raw CSV — never hand-shuffle cells). **Merged cells ARE wanted here** (unlike truth tables' no-merge rule): gate name `\multirow{N}` across all its rows, each state value `\multirow{2}` across its two (20 multirow total for 8 gates + 12 states). ## Pitfalls

- **`multirow.sty` is a LOCAL copy sitting in `reports/latex/`** — TeX Live 2026 basic does not ship it (`kpsewhich multirow.sty` → empty). Builds only work from that directory; a copy of the template/report in any other dir fails with ``multirow.sty not found``. - **A table row's first cell must not start with `[`**: after `\\`, LaTeX scans for the optional `\\[len]` argument and swallows a following `[` (newlines are skipped), giving a cascade of `Missing number, treated as zero` / `Illegal unit of measure` / `Missing = inserted for \ifdim` at that line. Placeholder `[Name] & ...` broke the template; use `Name 1 & [bracketed second cell]` (brackets after `&` are fine). Also keep trap comments from starting a line with `\` after `%` — scripted "uncomment recipe" passes strip `% ` blindly.
- **XeLaTeX + Times = no CJK glyphs**: Chinese in BODY text silently vanishes (`Missing character` warnings, no error). Keep prompts/placeholders English; Chinese only in `%` comments. Assert before shipping: no CJK outside comments (`l.split("%")[0]`).
- **A path the user hands you (an `@image:<path>` attachment, a screenshot they name) must be `stat`ed FIRST**, before any search of your own. It may not be listed yet on the first pass — re-list the directory once before declaring anything missing (an early `os.listdir` came back empty for files that were present moments later, and the user's reply was just "1.6的在这啊"). Never report "file not found" from a single listing; and prefer the exact path given over `mdfind`/`find` sweeps, which timed out on a home-directory scan here.
- Long terminal one-liners get BLOCKED (payload limit); the command is saved to a path — run `bash <saved path>`, and keep future commands short.
- f-string expressions cannot contain backslashes — hoist `t.count(r'\\\\...')` into a variable before formatting the message. Same trap one level out: wrapping a heredoc in `f"""..."""` (or a `%` template) evaluates the INNER `{stamp}` / `%s` placeholders too and throws `NameError`/`not enough arguments` — build the shell string by plain concatenation instead.
- `pdftoppm -f/-l` needs ints — never pass `None` from a failed page search; fix the search (whitespace normalization) first.
- **Mention-check regex** must handle `Figures 1–3` (en-dash ranges) AND `Tables 8 and 13`-style lists: an alternation `(\d+|\d+–\d+)` silently matches only `\d+` (alternation order), so range members 2,3 get recorded as never-mentioned — false violations. Parse the whole numeric segment, expand dashes, split on `and`/`,` (working version in `references/structural-edits.md`).
- **`t.index()` on shared tokens** (`\begin{array}{l}` exists in several sections) matches the FIRST occurrence document-wide — assert ordering with a search start anchored after a section-unique marker.
- **Sentence surgery double punctuation**: stripping a trailing clause like `' The comparison equations are:'` from an intro that already ends `…decide it.` and then appending `'.'` yields `..`. Assert `endswith(...)` AND `'..' not in tail`.
- **pdftotext hyphen/spacing quirks**: `M-key` extracts as `M -key`, `half-adder` as `halfadder`, `$RS=00$` as `RS = 00` — a failed substring check after whitespace collapse is usually the search string, not missing content; grep a loose anchor nearby and print the context instead of re-editing.
- **bbox caption-measurement traps**: coordinates are PAGE-absolute — the full-width center is `left margin + textwidth/2` (≈297.6pt), never `textwidth/2`. Inline math subscripts (`$t_{\mathrm{PHL}}$`, `$C_{\mathrm{out}}$`) render on their own baseline rows and drop out of an exact-`yMin` line cluster, shrinking the span and faking an off-center caption — re-gather all words within y±13pt before flagging. Two side-by-side captions share one y-row: split clusters at x-gaps > 30pt or the pair measures as one giant line. **The band can also sweep in a NEIGHBORING row**: merged-figure sublabels `(a)/(b)/(c)` sit ~6pt above their single caption and contaminate the y±13pt gather, skewing the center — for captions with no inline math, re-measure on the exact baseline (y±3) before flagging. Always triage a flagged caption for these artifacts before touching the layout: a measured "359.2, off by 62pt" turned out to be labels, the true deviation +0.01pt.
- **`\textwidth` inside a `minipage` equals the minipage width, NOT the page** (confirmed by a minimal test doc): `0.7\textwidth` computed inside a 0.48-column minipage = 0.7×column ≈ 152pt, silently narrowing pair captions while full-width captions looked fine. Never derive page-relative dimensions from `\textwidth` inside a minipage; capture the global value right after `\begin{document}` if ever needed. (House captions now have no width cap at all, so this mainly guards against reintroducing one.)
- **Assertion counts must skip comment lines and other sections' skeleton prompts**: a raw count of the figure-caption macro also hits the commented layout recipes in the template tail (+4), and the Appendix pointer sentence sits inside every other subsection's prompt, so "exactly 1" reads as 8. Count non-comment lines only (`not l.lstrip().startswith('%')`), or scope the count to the block just written, and check the doc total against `1 + remaining prompts`.
- **Judge builds by bang LINES and a singular-tolerant page regex**: count log lines starting with `!` (a `Missing $ inserted` once slipped past a counter that matched only LaTeX-Error lines) and match `pages?` — a one-page run prints `(1 page)`. Root-cause class: printf-style row builders that wrap table words in dollars mispair them (words fall into math mode) → build delay cells as t-type in math + edge words in TEXT + math arrow (`$t_{\mathrm{PLH}}$ (rise → rise)`). Re-derive quoted pooled statistics from raw readings with an inclusive 2dp half-up tolerance: 10.205 → 10.21, so `<= 0.0051`, not `< 0.005`.

- **A lead ending in a colon does NOT close the paragraph**: dropping `\begin{minipage}{\linewidth}` straight after `…results:` appends the table box INLINE on the text line → `Overfull \hbox` 26–332pt. It slips through only when the lead happens to fill exactly one line (§2.1 got lucky; §2.2's longer leads all failed). Emit `\par` before EVERY full-width minipage table/figure block that follows prose.
- **Orphaned figure lead**: the mirror trap — a lead sentence can land ALONE at a page bottom when earlier content shifts and the figure no longer fits below it (user: `Fig 9 和 10 没有介绍就凭空出现了吗` first — then the added lead itself stranded on p6 with the photos on p7). Glue lead to figure: put `\nopagebreak[4]` on the line between the lead and its `\par` (the break candidate is the paragraph end). Verify with per-page pdftotext that `pageof(lead) == pageof('Figure N.')`. **Escalation when the glue holds nothing** (2026-10-04: the LE paragraph stayed on p9 while Figure 15 moved to p10 despite the glue): force the break deterministically with `\pagebreak` BEFORE the lead paragraph, so the lead and its figure start the next page together (the same recipe as code-block splits), then re-run the full regression — page count, `(Continued)` pages, thin-page scan, every lead↔float pair — because downstream content shifts ±1 page and can open a new one-line spill page (it did: the moved break pushed 2.5's code tail into a 10-char page until the split point moved earlier).
- **TeX Live 2026 longtable steals a table number — and the obvious fix breaks column widths**: `\begin{longtable}` runs `\refstepcounter{\LTcaptype}`, stepping BOTH the `table` counter and the `LT@tables` width index. Setting `\LTcaptype` to nothing skips the width step → columns misalign (`Overfull \hbox 67.2pt`). Keep the captype and decrement instead: `\addtocounter{table}{-1}` right after each `\end{longtable}`. Full recipe set: `references/longtable-recipes.md`.
- **Phrase-anchor pdftotext assertions**: `'1.4' in norm` matches delay cells like `11.47` — assert `'Experiment 1.4' not in norm`. And `(Continued)` count is NEITHER a constant 1 NOR simply the number of `\\end{longtable}` blocks: it equals the number of longtables that ACTUALLY SPLIT in the current layout, and content edits that shift pages up can un-split one (week-04: Table 4 fit whole on p6 after the §2.2 code merge → count 2→1 with both longtables still present). When the count moves, run per-page `pdftotext -f N -l N` to see which table split; if one no longer breaks, assert its full row set sits on ONE page (digit-cell count, e.g. 7 cols × 32 = 224) instead of "fixing" a table that legitimately stopped breaking. Expect the same class of surprise in the reverse direction after content grows.
- **Assertion discipline — a FAILED check indicts the ASSERT first, not the document**: (1) needles must be re-derived from the CURRENT SOURCE, never paraphrased from memory/summary — this round five checks failed on a correct build because a remembered needle (`reports 1 LE … assign-`) matched neither the real wording (`fits one element at 1 LE and 0 registers`) nor survived a reflow that removed its hyphenation break; (2) `pageof()` needles run on whitespace-FLATTENED per-page text — raw page text wraps phrases mid-line (`Figures\n5 and 6` returns None for a space-needle on a perfectly good page); (3) region counts must enumerate neighbor content (a Table-4 region extending past the table = 224 cells + 2 digit tokens from the next sentence = 226) and exact-value option asserts must include shared placeholders; (4) when an assert fails AFTER the write already landed (script order bug), do NOT roll back or "fix" the report — the failing assert itself was wrong (a regex capture begins with `\n`, so `startswith('module')` missed a correct split). Verify content against pdftotext/render ground truth first, then repair the assert.
- **Per-page pdftotext beats vision for "what is on which page"** — vision answers to leading "should contain X" questions echo the question even when the page doesn't match (two answers contradicted the per-page text this round; the text was right). Ground truth = per-page `pdftotext -f N -l N`. Page-boundary oddities are extraction artifacts, not layout bugs: a lead's first word plus the next page's footer digit came out as `The 5` across the split while the render was clean — confirm boundary anomalies by cropping the two boundary strips into one image (`PIL.crop` bottom+top) and visioning that, before touching the layout.
- **Vision claims a missing image or a wrong indent → arbitrate with PIXELS before touching the layout**: `pdfimages -list` proves embedding but NOT placed size (its columns are source px and ppi, not drawn dimensions). Rendered-page numpy gives geometry: row-ink bands locate a figure row (a 1.65in photo = 215px @130dpi at ~53% ink), per-column ink runs give each pair member's x-span (week-04: both 287px, ink 0.534 vs 0.533 → Fig 9's photo existed and exactly matched Fig 10), and a left-edge scan of the text lines below proves flush vs indent (every line x=130 under `\parindent=0pt`). Vision asserted BOTH defects on a correct build — once as "caption with nothing above it", once as an indent that the paragraph style makes impossible. Use vision for layout aesthetics and wiring (lead ↔ figure ↔ caption order); use pixels for existence, geometry, and equality.
- **Report footers print pdf-page + 1** (p1→`2` … p9→`10`): the submitted week-03 has the identical scheme — template behavior, not a numbering bug; don't "fix" it unasked.
- **A renamed header row can blow the width budget**: bold-subscript columns (K₁…T) rendered ~21.65pt wider than single letters (A–E) at the same `tabcolsep`, producing one `Overfull \hbox … in alignment` per longtable chunk (firsthead/endhead/body print identical overflow). Refit `tabcolsep −= overflow/(2×ncols)` (21.65/14 → 22pt→20.4pt = exactly full width), then re-scan the log — one fix clears all chunks.
- **`p{.20}` without a unit = 100+ cascading errors**: a `p`-column width must carry its unit (`p{.20\linewidth}`); a bare decimal makes LaTeX demand a dimension at the header cell, and the damage repeats per row/chunk (`Illegal unit of measure (pt inserted)` ×108, fake Overfull ×178, wrong page count). When a table build explodes with that error, inspect the `{p{...}}` spec first — the message points at `\textbf` of the header, not at the real cause.
- **Code-crossing detector needs stripped source lines, blank-line skipping, and an inclusive anchor**: match pdftotext lines against `line.strip()` (indented `    end` never equals `end`), let the match hop over empty source lines (breaks land ON a blank between `);` and `reg`), and build the anchor slice as `blines[k:j+1]` — a `[k:j]` slice drops the x-line, degrading the anchor to a single repeated token (`) (` appears in three modules) and the uniqueness assert fires. Iterate one split per compile round: adding a marker shifts every later break, so re-detect from the fresh PDF instead of batching all splits from one snapshot.
- **A `\pagebreak` code split can strand a one-line spill page**: after any upstream text addition the part1 tail may push one line onto the next page, where the forced break leaves a page containing just that line + footer. Detect with a per-page `pdftotext` thin-page scan — but skip the empty trailing chunk (pdftotext emits N+1 chunks for N pages) and any page containing `Figure`/`Table` text: a float/table page can measure only ~272 non-whitespace chars (33 digit-cells × 7 cols + two captions) while being visually FULL, so a raw char threshold false-flags it — and fix by moving the split point EARLIER (e.g. after the first instance's `);` instead of mid-second-instance) so part1 closes fully on its page; re-verify `(Continued)` page numbers after the move.
- **`pageof()` needles fail on leads that straddle a page break**: pdftotext injects the footer digit mid-sentence (`The eight path 12 means…`, `Quartus 10 reports…` — footers print pdf-page+1), so a whole-lead needle returns None while the layout is fine. Probe a fragment that sits entirely on one page (the half after the break, e.g. `means average 11.61`), and judge strandedness by `pageof(lead-fragment) == pageof(caption)`, not by the sentence's first words. Same trap makes a LE-sentence needle that includes `0~LEs` need the space form (`0 LEs`). Two more `pageof` traps (2026-10-04): (a) math captions render WITHOUT `$` and with letter spacing — tex `Board state at $K_1=0$` → `Board state at K1 = 0`, `$TA{=}1000$` → `T A = 1000` — so build needles from an actual `pdftotext` dump of the caption line, never from the tex source (a `$`-bearing needle returns None on a perfectly good page); (b) sibling figures can share IDENTICAL caption text (Fig 11/12 and Fig 13/14 are both `Board state at K1 = 0/1`), so a caption-text `pageof` returns the FIRST experiment's page and falsely fails the lead check — adjudicate lead↔float with the unique `Figure N.` / `Table N.` caption-number strings plus the lead's own fragment, via an explicit `(lead, N)` list so every pair and solo is checked.
