# Critical Think

주장을 "그럴듯함"에서 떼어내 **반증 가능한 형태**로 만들고, 검증 설계가 결론을 미리 품지 않았는지 감사한 뒤, 가능하면 **직접 관찰**로 확인한다. **이전 단계 산출물 없이 다음 단계 진행 금지** — 분해 안 된 주장은 검증 불가, 반증 설계 없는 "검증함" 선언은 확증편향의 다른 이름이다.

핵심 분리: **논리적으로 유효한가(추론 타당성) ≠ 실제로 유효한가(증거).** 둘을 섞으면 우아한 추론이 사실로 둔갑한다.

## 쓰는 경우
- "이 개선/변경이 유효한가", "이 주장이 맞나", "이 결정 근거가 튼튼한가"
- AI(또는 본인)가 내놓은 결론을 그대로 채택하기 전 점검
- 그럴듯한데 근거가 불안한 합의·계획

## 쓰지 않는 경우
- 답을 모르는 상태의 탐구 학습 (검증할 주장이 아직 없음)
- 모호한 요구사항 구체화 → `requirements-analysis`
- 코드 결함 찾기 → 코드 리뷰 · 버그 디버깅 → `systematic-debug`

---

## Phase 0 — 주장 고정 (Claim)

검증 대상을 **반증 가능한 한 문장**으로 압축한다. 먼저 **주장(결론)과 그것을 떠받치는 근거(전제)를 분리해 식별**한다 — 무엇이 입증 대상이고 무엇이 지지대인지 섞이면 이후가 전부 흐려진다. "더 좋다", "효과적이다" 같은 모호어는 측정 가능한 술어로 바꾼다. 압축이 안 되면 여기서 정지 — 검증할 대상이 정의되지 않은 것이다.

**타입 분류** (검증 방법을 결정):
- **논리(연역)** — 추론만으로 참/거짓. 전제 + 추론 타당성을 본다.
- **경험(귀납)** — 측정·관찰이 필요. Phase 4~6에서 테스트.
- **정의/규범** — 합의·가치 선택으로 참. "테스트 대상 아님"으로 표기하고 정의를 명시해 합의 여부만 따진다.

타입 혼동이 1순위 오류다 ("추론이 우아하니 사실").

---

## Phase 1 — 분해 (Decomposition)

복합 주장을 **독립 검증 가능한 원자 하위주장**으로 쪼갠다. 쪼개지지 않는 주장은 검증할 수 없다. 하위주장은 서로 다른 결론(하나는 참, 하나는 거짓)이 나올 수 있어야 한다.

분해는 **MECE**로 — 하위주장끼리 겹치지 않고(상호배타), 합치면 원주장을 빠짐없이 덮어야(전체포괄) 한다. "왜?"를 반복하는 로직 트리로 계층화하면 누락이 드러난다.

**산출 고정**: 이 계층화를 머릿속에만 두지 말고 트리 1장으로 명시 산출한다 — 주장이 "왜"(원인·근거 계열)로 갈리면 Why tree, "무엇으로 구성"이면 What tree.

```
<원주장 (반증 가능한 한 문장)>
└ 왜? / 무엇으로 구성?
  ├ 하위주장A  (MECE)
  ├ 하위주장B
  └ 하위주장C
→ 각 잎 = Phase 4에서 독립 반증 설계할 단위
```

---

## Phase 2 — 전제·가정·맥락 (Assumptions & Context)

"이게 참이려면 무엇이 참이어야 하는가"를 나열한다. 그중 **깨지면 전체가 무너지는 가정 1개(load-bearing)**를 식별한다. 검증 자원은 거기에 먼저 쓴다. 숨은 전제를 안 캐면 결론이 옳아도 이유가 틀린다.

**맥락**: 누가 이 주장을 하며 무엇을 얻는가(이해관계), 어떤 프레이밍·생략·배경이 깔려 있나. 발신자가 결과의 이해당사자거나(본인 작업 방어·벤더), 비위 맞추도록 최적화된 출처(AI 포함)면 **증거 기준을 높인다**.

---

## Phase 3 — 스틸맨 + 최강 반례 (Steelman & Counter)

먼저 주장의 **가장 강한 버전**을 진술한다 (허수아비 금지 — 약한 버전을 깨는 건 비판이 아니다). 그 다음 그것을 무너뜨릴 **가장 강한 반증 시나리오**를 세운다.

---

## Phase 4 — 반증 설계 (Falsification) ★

**"어떤 관찰이 이 주장을 틀렸다고 증명하는가?"** 답이 하나도 없으면 그건 주장이 아니라 신념이다 → **검증불가로 표기하고 경고**한다 (Popper 게이트).

- 결과가 **양쪽으로 갈릴 수 있는** 테스트를 설계한다. 확증만 가능한 테스트는 무효.
- **오라클/성공 기준을 *미리* 명시**한다 (관찰 전에). 사후에 기준을 맞추면 확증편향.
- 타입별: 논리 → 전제 참 여부 + 추론 타당성(반례 1개 시도, 상관을 인과로 비약하지 않았나, 논리 비약·순환 없나). 경험 → 측정·실험 설계. 정의 → 합의 확인(테스트 아님).

---

## Phase 5 — 자기-조작 감사 (Rigging Audit) ★★

가장 고레버리지인데 가장 잘 생략되는 단계. **내 검증 설계가 결론을 미리 품고 있지 않은지** 감사한다.

- 정답을 입력(데이터·프롬프트·표본)에 박아두지 않았나?
- 테스트가 확증 쪽으로 기울어 있지 않나? 반증이 구조적으로 불가능하지 않나?
- 표본이 결론에 유리하게 선택되지 않았나 (cherry-pick / survivorship)?

체크리스트 통과 못하면 **Phase 4로 복귀**. (실사례: 증상 명세에 기대 정답을 박아 넣어, 편향 가설이 애초에 샐 수 없게 만든 테스트 — 무효.)

---

## Phase 6 — 증거 평가 + 직접 관찰 (Evidence)

**기존 증거 평가**: 이미 제시된 근거가 있으면 먼저 따진다 — ① 출처가 신뢰할 만한가 ② 사실에 기반하나 ③ 그 증거가 주장을 *실제로* 지지하나(관련성·충분성, 일화/체리픽 아닌가). 약하거나 무관한 증거는 없는 것으로 친다.

**testability 게이트**:
- 경험 주장 + 저비용 테스트 가능 → **직접 실행·측정**한다. 결과를 본인이 관찰한다.
- 불가능/고비용 → 반증 설계와 가정만 남기고 "미검증(증거 부족)"으로 정직하게 멈춘다.

원칙: **제안자(또는 AI)의 자기보고를 증거로 치지 않는다** — "잘됐어요"는 권위에의 호소다. "바꿨다 ≠ 좋아졌다", "논리가 맞다 ≠ 결과가 맞다". 중간 산출물(로그·출력·실행 결과)을 남겨 가시화한다.

---

## Phase 7 — 비용·2차효과 (Cost & Second-order)

참이어도 **가치 있는가**를 따로 묻는다. 오버헤드, 회귀, 누가 비용을 지는가, 더 단순한 대안은 없는가. 정확도만 보고 비용을 빼면 "참이지만 손해인" 변경을 채택하게 된다.

---

## Phase 8 — 판정 + 행동 (Verdict → Action)

- **판정**: 유효 / 약함 / 반증됨 / 미검증(증거 부족) 중 하나.
- **일반화 경계**: n=?, 어떤 조건에서 성립하고 어디서 깨지는가. **미검증을 검증으로 격상 금지.**
- **행동 매핑**: 채택 / 약화(강한 주장→약한 주장) / 롤백 / 재테스트. **kill-criterion** 1줄 (이 조건이면 폐기).
- **재구성**: 결함이 드러나면 비판에서 멈추지 않는다. 결함을 고친 **더 방어 가능한 버전의 주장**으로 다시 세운다 — 해체는 비판의 끝이 아니라 중간이다.

---

## 완료 체크리스트

- [ ] 결론/근거 분리 + 반증 가능한 한 문장 + 타입으로 고정
- [ ] 원자 하위주장으로 MECE 분해
- [ ] load-bearing 가정 + 발신자 맥락·이해관계 식별
- [ ] 스틸맨 후 최강 반례
- [ ] 반증 설계 + 오라클 선정의 (없으면 검증불가 표기)
- [ ] 자기-조작 감사 통과
- [ ] 기존 증거 평가(출처·관련성) + (가능 시) 직접 관찰 — self-report 아님
- [ ] 비용·2차효과 평가
- [ ] 판정 + 일반화 경계 + 행동/kill-criterion + 더 나은 주장 재구성

## 명명할 편향 (cross-cutting)

확증편향 · 동기화추론 · 앵커링 · 흑백논리(거짓 이분법) · 권위에의 호소(AI 자기보고 신뢰) · 상관≠인과 · 기저율 무시 · 매몰비용 · 생존편향 · 논리/경험 혼동.

## 안티패턴

```
- 주장을 반증불가 형태로 둔 채 "검증함" 선언 (Phase 4 생략)
- 자기 결론에 맞춰 테스트 설계 — 정답을 입력에 박기 (Phase 5 생략)
- 에이전트·도구의 "잘됨" 보고를 증거로 채택 (Phase 6 생략)
- n=1을 일반 법칙으로 격상 (Phase 8 경계 생략)
- "참이니 채택" — 비용 무시 (Phase 7 생략)
```

## 예시 — 개선의 유효성 검증

```
주장: "디버깅 워크플로에 실패 테스트 단계 추가 → 디버깅이 개선된다"
[0] 타입: 경험 (측정 필요). "개선" → 근본원인 적중률 ↑ & 거짓수정 ↓로 조작화
[1] 분해: ① 격리가 편향(수정안 정당화 테스트)을 막는다  ② grounding 없으면 환각한다
[2] 가정: 자동화 가능 환경 / 재현이 테스트로 표현 가능
[4] 반증 설계: 같은 버그에 격리 vs full-context 에이전트로 실패테스트 작성
              오라클 = red-for-right-reason + 수정 후 green
[5] 감사: 증상 명세에 정답을 박았더니 편향이 샐 길 없음 → 설계 결함 → Phase 4 복귀
[6] 직접 실행: 에이전트 산출 테스트를 본인이 node --test로 돌림 (자기보고 X)
[8] 판정: grounding=입증 / 편향=미검증(설계 한계) / n=1 일반화 불가
         행동: grounding 규칙 채택, 편향 규칙은 "권장"으로 약화 유지
```
