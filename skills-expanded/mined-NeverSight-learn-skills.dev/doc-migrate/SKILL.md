---

由于某些原因,例如为解决文档碎片化,为正确合并知识,为规范化文档管理等原因, 用户需要将一个或者多个文档的知识,章节内容合并到指定的另外一个文档中.

步骤:

1. 完整阅读被合并的文档, 必须是完整阅读,一字不少阅读完毕, 理解原文档的知识要点.
2. 完整阅读目标文档.
3. [了解背景知识] - 结合工作区的背景知识(源文档中可能没有提及的)了解相关历史和上下文, 例如如果是跟程序开发有关的,应当了解程序最近的变更,最新的规范,等.
4. [了解合并冲突点] - 并用以下方式进行合并.
  1. 目标文档已经存在相似条目或章节, 应当在在目标条目或章节补充缺失的部分. 并删除源文档对应的章节.
  2. 目标文档缺失的章节, 应当以合适的方式进行补充, 并删除源文档中对应的章节.
  3. 依照`矛盾与冲突解决方法`解决冲突.
  4. 消除重复.

5. [更新引用链接] 由于源文档可能会被删除,而用户没有注意到源文档可能被其他文档引用, 此时更新链接是有必要的.

6. [报告结果] 告诉用户你最终删除了什么文件, 目标文件做了什么关键更改.

## 约束

1. 目标文档只能是**一个**文档, 如果多于一个文档,应告诉用户让用户明确一个目标文档.
2. 如果用户指定了文档路径,则最后一个文档是目标文档.

## 概念

- 被合并的一个或者多个文档成为`源文档`

## 矛盾与冲突解决方法

- 原则上新的知识优先.
- 结合背景知识进行判断.
- 源码或者其他文档进行佐证判断知识的正确性.
- 如果没办法判断知识的正确性, **必须**明确指出要求人类进行确认取舍和判断.

## 风险与阻塞

以下情况应当明确告知用户合并带来的风险, 并由用户决定是否继续合并.

1. 源文档是关键文档,内涵关键知识,被多个地方作为唯一真理标准.
2. 源文档比目标文档更优.
