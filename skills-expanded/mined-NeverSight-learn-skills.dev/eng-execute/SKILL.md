# Execute Plan

Execute a verified implementation plan (generated by `eng-plan`) sequentially with strict step-by-step validation.

## Execution Rules & Discipline

- **Strict Plan Adherence**: Execute tasks in exact top-to-bottom dependency order. Do not skip steps.
- **Incremental Verification**: After modifying or creating files in each task, run the task's `VALIDATE` command immediately. Fix any syntax, type, or test errors before moving to the next task.
- **Minimal Diff**: Make only the changes specified by the plan. Avoid unsolicited refactorings, style churn, or scope creep.
- **Preserve Existing Patterns**: Follow the naming conventions, error handling styles, and formatting rules referenced in the plan.

---

## Process

### 1. Load and Verify Plan
1. Locate and read the plan file (typically in `.agents/plans/<feature-name>.md`).
2. Validate that all target files and dependencies are understood before touching code.

### 2. Sequential Task Execution
For each task in the plan:
1. **Prepare**: Read existing file context and reference pattern files.
2. **Implement**: Apply targeted modifications or create new files.
3. **Verify**: Run the specified `VALIDATE` command immediately.
4. **Log Progress**: Check off the task in the working plan.

### 3. Full Suite Validation
After all individual tasks pass:
1. Run linting / type checking across affected packages.
2. Run full unit and integration test suites.
3. Execute manual verification steps specified in the plan's Acceptance Criteria.

### 4. Post-Execution Report
Generate a summary report detailing:
- Files modified/created.
- Validation command outputs and test results.
- Unresolved edge cases or follow-up recommendations.

---

## Checkable Completion Criteria

- [ ] All step-by-step tasks executed in order.
- [ ] Every individual task passed its local validation.
- [ ] Full project test suite and type checks passed with 0 errors.
- [ ] Acceptance criteria from the plan are fully satisfied.
