# Lecture Deck — 강의안 생성

16:9 HTML 강의안을 보고서식 교안 스타일로 만든다. 결과물은 **색상 선택·편집·PDF·발표 도구가 내장된 단일 HTML**이다.

## 워크플로

1. **요건 파악** — 주제·대상(특히 비개발자 여부)·시간/분량·강조점·기관/강사명을 확인한다. **표지 제목은 반드시 사용자에게 물어 확정한다.** 원본 파일에 제목이 있더라도 표지에 넣을 최종 제목은 사용자 확인 전에는 임의로 만들지 않는다. 모르면 핵심만 1~2개 질문하되, 표지 제목 질문을 우선한다.
2. **색상 방향 선택** — `references/color-palettes.md`를 읽고 사용자에게 3~5개 팔레트 후보를 간단히 제시한다. 사용자가 고르지 않으면 **슬레이트 틸**을 기본으로 쓰되, 공공·교육·임원 보고서 분위기와 대비가 더 맞는 팔레트가 있으면 그 이유를 짧게 말하고 적용한다.
3. **자료 수집·구조화** — `references/source-grounding.md`를 읽고 첨부 파일, 현재 프로젝트 문서, wiki/노트, 음성 전사, 사용자 프롬프트를 먼저 **강의 원장**으로 정리한다. 원본 강의안은 발표 흐름과 장 순서를, 교재·원고·wiki·전사는 세부 설명·예시·실습 체크리스트를 보강 자료로 사용한다. 외부 지식은 사용자가 요청했거나 출처 보강이 필요할 때만 쓰고, 사용자 자료를 대체하지 않는다.
4. **자료 반영 범위 확정** — 첫 장 또는 앞부분에 **원자료 반영 구조**를 명시한다. 사용자가 “깔끔하게”라고 해도 원본·교재·전사·wiki가 있으면 요약판으로 줄이지 않는다. 반영 누락 방지가 장수 축소보다 우선이다.
5. **개요 설계** — 표준 구성(아래)을 바탕으로 슬라이드 목록을 잡는다. 1슬라이드 = 의미 단위 1개. 원본이 30장 이상이거나 교재·전사가 장문이면 40~70장 이상의 확장판도 허용한다. 분량보다 내용 누락 방지가 우선이다.
6. **템플릿 복제** — `assets/deck-template.html`을 결과 경로로 복사한다. `<body data-palette="...">`에는 선택한 팔레트 ID를 넣는다. **CSS·도구 스크립트는 수정하지 않는다.** `<section class="slide">`만 주제에 맞게 채우고 불필요한 예시는 지운다.
7. **본문 작성** — `references/writing-style.md`의 규칙을 반드시 지킨다(원문 최대 보존, 선언적·시적 문장 금지, 합니다체, 비유·슬로건·메타 금지, 비개발자 눈높이). 원문 기반 강의안은 제목·항목명·문장을 가능한 한 유지하고, 배치와 밀도만 교안형으로 정리한다. 표가 주 내용이면 `tablefill` + `grid even`으로 행 높이를 균등 배분하고, 박스가 허하면 `big` 변형이나 원문 세부 내용으로 채운다. 레이아웃은 `references/layout-primitives.md` 참조.
8. **반영·문체 검수** — 완성 후 강의 원장을 기준으로 주요 장·개념·사례·실습·수치가 빠졌는지 확인한다. 제목과 부제가 잡지식 카피, 선언문, 시적 문장, 근거 없는 해석으로 바뀐 곳은 기능형 명사구로 고친다.
9. **자가검증** — `python scripts/render_check.py <결과.html> --pdf` 실행.
   - `ISSUES`가 비고 `JS ERRORS`가 없어야 한다(넘침·박스 이탈 0).
   - PDF는 16:9 가로 페이지로 슬라이드 1장=1페이지여야 한다.
   - **렌더된 PNG를 반드시 육안 확인**한다 — 휑한 곳(빈 밴드), 어색한 문체, 잘림. 스크립트만 믿지 말 것.
10. **수정 반복** — 휑하면 원자료의 세부 항목·표·사례·절차를 더하고(빈 박스로 때우지 말 것), 넘치면 의미 단위로 다음 슬라이드로 나눈다. 통과까지 반복.

## 표준 구성 (분량에 맞게 가감)

표지(다크) → 커리큘럼 표 → [이론] 정의/배경 → [이론] 핵심 구분 → [이론] 구조/도식 → [이론] 구성요소(표) → [개념] 항목 정의 → [사례] 도식 → [관점] 2열 비교 → [실습] 단계+릴레이 → [적용] 영역 카드 → 강의 요약(다크).

## 핵심 규칙 (요약 — 상세는 references)

- **표지 제목**: 사용자에게 반드시 물어 확정한다. 사용자 확인 없이 임의의 표지 제목을 만들지 않는다.
- **자료 우선순위**: 첨부 파일·현재 프로젝트 문서·사용자 프롬프트·음성 전사·wiki/노트를 1순위로 삼는다. 일반 지식이나 외부 검색 내용으로 사용자 자료를 덮어쓰지 않는다.
- **원문 보존**: 원본 슬라이드·문서·전사·노트가 있으면 제목·항목명·문장을 최대한 그대로 유지한다. 새 멘트나 새 메시지를 덧붙이지 않는다.
- **요약판 금지**: 원본 강의안과 교재·전사·wiki가 함께 있는 경우, 큰 목차만 요약하지 않는다. 원본의 Part/장 흐름을 모두 커버하고, 교재의 장문 설명·실습·사례·체크리스트를 별도 슬라이드로 반영한다. 내용이 많아도 좋으며 장수 축소보다 누락 방지가 우선이다.
- **제목**: `[구분] 주제 — 기능적 부제`. 비유·수사·슬로건·블로그체·선언적/시적 문장 금지. ("강의 요약"이지 "오늘 우리가 함께 본 것"이 아니다.)
- **선언형 부제 금지**: “데이터분석은 태도에서 시작한다”, “분석의 8할을 차지한다”, “숫자를 이야기로”, “말을 문서로”, “AI는 자격이 아니라 시도가 만든다” 같은 선언형·슬로건형 문장을 제목/부제로 쓰지 않는다. “인지편향·문제정의·분석 질문”, “수집·정제·형식 통일 절차”, “문제·원인·근거·행동 보고 구조”, “회의록 구조화와 문서 검토 절차”처럼 기능형 명사구로 바꾼다.
- **본문**: 합니다체 설명문 + 번호 개념 정의 + 도식. 불릿 박스 그리드 금지.
- **비개발자**: 전문어 풀어 쓰고 "예 —" 한 줄로 구체화. 개발 용어(PR·머지·린터·CI) 금지 → 평이한 말.
- **메타 문장 금지**(강사/수강생/제작 시점). 폰트는 템플릿 크기 유지(작게 줄이지 말 것).
- **표**: 표가 슬라이드의 주 내용이면 자연 높이로 두지 않는다. `<div class="tablefill"><table class="grid even roomy" style="--rows:3;">...</table></div>`를 기본으로 써서 본문 높이를 채우고 데이터 행을 균등하게 배분한다. `--rows`는 헤더와 그룹행을 뺀 데이터 행 수다. 행이 많아 넘칠 때만 `tight`를 쓴다.
- **밀도**: 실제 내용·도식으로 채운다. 가로 스트립은 둘째 행(릴레이 등)으로 채운다. 박스 안 텍스트가 적으면 새 문장을 만들지 말고 기존 텍스트의 폰트 크기·여백·정렬을 조정해 채운다.
- **2x2 박스 밀도**: 2x2 번호 개념 박스는 특히 휑해지기 쉽다. 각 박스는 `정의/설명 + 예시 또는 입력값 + 확인/산출물`의 2~3문장 구조로 채운다. 제목 한 줄과 설명 한 줄만 넣지 않는다.
- **박스 보정**: `.concepts`, `.domain`, `.relay`, `.steps`, `.loop`, `.layer2`, `.veri`가 허해 보이면 `big` 변형을 먼저 적용한다. 그래도 빈 공간이 크면 원문에 있는 예시·조건·산출물·주의사항을 `.boxmore`/`.boxcheck`로 보강한다. 원문에 없는 메시지를 새로 만들지는 않는다.
- **색상**: 기본은 `slate-teal`. 사용자가 원하면 템플릿의 색상 버튼으로 `classic-rust`, `forest-gold`, `navy-coral`, `graphite-rose`를 순환해 미리 볼 수 있다. 색상 선택은 본문 대비와 기관·교육 맥락 적합성을 우선한다.

## 내장 도구 (색상 · 편집 · PDF · 발표)

템플릿에 이미 들어 있다(우상단 버튼, 인쇄·발표 시 자동 숨김). 손대지 말고 그대로 둔다.

- **색상**: 버튼 클릭 → 팔레트 순환 미리보기. **저장(HTML)** 하면 선택한 팔레트가 유지된다.
- **편집**: 버튼 토글 → 슬라이드 텍스트를 브라우저에서 바로 수정. **저장(HTML)** 버튼으로 수정본을 단일 HTML로 내려받는다(다시 열어 재편집 가능).
- **PDF**: 버튼 → 브라우저 인쇄 → "PDF로 저장". `@page`가 1280×720(16:9)로 고정돼 슬라이드 1장=1페이지로 정확히 출력된다(배경색 포함). 인쇄 대화상자에서 여백은 "기본/없음", 배경 그래픽 켜기.
- **발표**: 버튼 또는 진입 후 **← →(또는 클릭/Space)** 로 한 장씩, **Esc** 로 종료. 화면 크기에 맞춰 자동 확대.

PDF가 세로로 잘리면 `@page`가 `@media print` 안에 중첩됐는지 확인한다 — 반드시 **top-level**에 둬야 크롬 인쇄 UI가 인식한다.

## 자료 파일

- `assets/deck-template.html` — 전체 디자인 시스템 CSS + 모든 레이아웃 예시 슬라이드 + 편집/PDF/발표 도구(복제해서 채운다).
- `references/source-grounding.md` — 첨부·프로젝트·wiki·음성·프롬프트를 강의 원장으로 정리하고 반영 누락을 막는 규칙.
- `references/color-palettes.md` — 고대비 팔레트 선택 기준과 팔레트 ID.
- `references/writing-style.md` — 문체·제목·비개발자 표현 규칙(반려 사례 포함).
- `references/layout-primitives.md` — 슬라이드 골격, 부품별 클래스와 용도, 밀도 규칙.
- `scripts/render_check.py` — 렌더 + 넘침/이탈 검사 + PDF 확인.
