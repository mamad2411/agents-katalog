# Review Spell Terminology

対象差分や対象コードに対してスペル/用語整合観点のレビューを行う。

## 入力

- 対象 diff（必須）
- 必要に応じて周辺文脈（必須ではない）

## チェック手順

1. 識別子のスペルミスを確認する
2. 同一概念の命名ゆれを確認する
3. コメントとユーザー向け文言の誤字脱字を確認する
4. ドメイン用語の表記統一を確認する
5. エラーメッセージと実際の条件の一致を確認する

## チェックリスト

- 変数名、関数名、型名、コメントのスペルミス
- 同一概念の命名ゆれ（例: userId / userID）
- ドメイン用語の誤記、誤訳、略語の不統一
- ユーザー向け文言の誤字脱字、曖昧な文言
- エラーメッセージ文面と分岐条件の不一致

## 出力フォーマット

```text
[CRITICAL] / [HIGH] / [MEDIUM] / [LOW]
カテゴリ: スペル / 可読性
場所: path/to/file.ext:line
問題: 何が問題か
根拠: どの差分から判断したか
改善案:
<修正コードまたは修正文言>
```

指摘がない場合は `スペル/用語整合: 指摘なし` を明記する。
