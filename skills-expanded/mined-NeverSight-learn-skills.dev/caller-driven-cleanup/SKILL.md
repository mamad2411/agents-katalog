# Caller-Driven Cleanup：基于调用方的清理

## 核心原则

删除安全性来自调用方和加载影响面证明，不来自为了失败测试发明新行为。删除最小但完整的单元，并验证剩余系统。

## 映射影响面

从待删除的符号、文件、包、路由、任务或配置键开始，检查：

- 静态导入、导出、再导出、别名和生成入口；
- 依赖注入、装饰器、反射、注册表、插件和动态导入；
- 字符串键、配置、脚本、任务、迁移和模板；
- 清单、锁文件、对等依赖、构建配置和发布文件；
- 表示真实支持用法的测试、文档和仓库历史。

若仓库提供语义索引或调用图，先用它定位符号与调用方，再用源码搜索、依赖检查和运行时证据补足动态影响面。

| 引用类型 | 处理方式 |
|---|---|
| 活跃生产调用方 | 删除前保留或迁移 |
| 存在外部使用方的公共 API | 先建立兼容或发布边界 |
| 框架或运行时注册 | 在启动或加载证据否定前视为仍在使用 |
| 测试真实契约的测试 | 随迁移后的调用方更新 |
| 只覆盖已删除内部实现的测试 | 随实现删除 |
| 过时文档、夹具、快照或锁文件条目 | 作为同一完整单元删除 |

未知动态使用不是死代码证明。无法排除公共 API 外部使用方时停在证据缺口；可能存在发布边界不等于已获准执行破坏性发布或改变外部状态。

## 删除与验证

1. 记录活跃调用图和预期保留行为。
2. 删除只属于无效路径的实现、导出、注册、测试、文档和依赖条目。
3. 使用包管理器的正常移除和解析流程，不只手改锁文件。
4. 按影响运行类型检查、构建或启动、保留调用方的定向测试和公共导出检查。
5. 审查差异中的孤立兼容分支与无关改动。

除非已验证调用方需要迁移窗口，不得添加包装层、回退分支、弃用别名或生产代码选项。
