# 横纵分析法深度研究

> 纵向追时间深度，横向追同期广度，交汇出判断。

你正在执行一次横纵分析法深度研究。

这套方法融合了语言学中索绪尔的历时-共时分析、社会科学的纵向-横截面研究设计、以及竞争战略分析的核心思想。

## 前置准备

### 明确研究对象

拿到用户输入后，确认以下信息。如果用户已经给得足够明确，不需要追问，直接开始：

1. **研究对象**：具体的产品名/公司名/概念名/人名
2. **类型**：产品、公司、概念、人物
3. **研究动机**（可选）：为什么要研究它
4. **特别关注点**（可选）：有没有特别想深入的方向

## 第一步：联网信息收集

研究报告的质量完全取决于信息的丰富度和准确性。必须联网搜索，不能仅靠已有知识。

### 搜索策略

使用子 Agent 并行搜索：

- **子 Agent 1 — 纵向信息**：起源、创始人背景、发展历程、关键事件、版本迭代、融资、战略转向、危机
- **子 Agent 2 — 横向信息**：竞品识别、各竞品特点和用户口碑、行业对比、市场份额

每个子 Agent 的 prompt 中包含联网指引：

> 使用 WebSearch 发现信息来源，找到具体 URL 后用 WebFetch 深入提取。
> 多次搜索、多个关键词组合，不要只搜一次。
> 一手来源优于二手来源：官方博客 > 权威媒体原创报道 > 转载/聚合。
> 学术类研究对象必查 arxiv：`curl -s "https://export.arxiv.org/api/query?search_query=all:关键词&max_results=10"`

### 信息来源优先级

| 信息类型 | 一手来源 |
|---------|---------|
| 产品更新/技术决策 | 官方博客、GitHub Release Notes、创始人推文 |
| 融资/商业数据 | 公司官方公告 |
| 用户口碑 | GitHub Issues、Reddit、Twitter/X、知乎 |
| 行业分析 | 权威媒体原创报道 |
| 学术/技术原理 | arXiv 论文、Google Scholar |

### 信息充分性自检

搜索完成后检查：
- 纵向：能讲出一个完整的故事吗？有没有信息断层？
- 横向：竞品列表完整吗？每个竞品的信息够做对比吗？
- 来源：关键事实有可靠来源支撑吗？

信息不够就再补搜。不要凑合。

## 第二步：纵向分析

沿时间轴，完整还原研究对象从诞生到现在的发展全貌。这是报告的主体部分。

### 内容要求

**起源追溯**：诞生背景、核心推动者、当时的行业环境。这些人之前做过什么，为什么是他们来做这件事。

**诞生节点**：首次发布/成立时间，最初的形态和定位，跟现在有什么不同。

**演进历程**：按时间梳理所有关键节点。重大版本更新、融资、团队变动、战略转型、技术架构变化、用户里程碑、争议事件。

**决策逻辑**：每个关键节点上，还原决策背后的原因。为什么选了 A 而不是 B？当时的约束条件是什么？

**阶段划分**：把整个历程分为几个阶段（萌芽期、快速增长期、转型期等），每个阶段有核心特征和核心矛盾。

### 篇幅

6000-15000 字。历史越长靠近上限，新生事物靠近下限。把故事讲完整、讲透。

## 第三步：横向分析

以当前时间点为切面，与同赛道竞品全面对比。

### 判断竞品情况

**场景 A：无直接竞品。** 分析为什么没有竞品。品类太新、壁垒太高、还是市场太小？未来最可能从哪个方向冒出竞争者？

**场景 B：少量竞品（1-2 个）。** 逐一深入对比。

**场景 C：竞品充分（3 个及以上）。** 选最具代表性的 3-5 个对比，其余简要提及。

### 对比维度

**核心差异**：技术路线、产品形态、商业模式、目标用户、核心优劣势、定价策略。

**用户视角**：真实口碑、社区评价、使用体验中被提及最多的优点和槽点。用户实际使用方式和官方定位有没有偏差。

**生态位**：在赛道版图中占据什么位置。填补了什么空白，还是在跟谁正面竞争。

**趋势判断**：竞争格局走向、机会与风险。

### 篇幅

3000-10000 字。场景 A 约 3000 字，场景 C 每个主要竞品至少 1500 字。

## 第四步：横纵交汇洞察

这是报告的精华。把纵向脉络和横向格局结合，给出新的判断。不是前面内容的缩写。

需要回答：

1. **历史如何塑造了当下的竞争位置**
2. **优势的历史根源**：今天的核心优势能追溯到哪个节点或决策
3. **劣势的历史根源**：当初的好决策有没有变成今天的包袱
4. **未来推演**：最可能的、最危险的、最乐观的三个剧本，每个有逻辑支撑

### 篇幅

1500-3000 字。

## 写作风格

### 核心要求

**叙事驱动**：纵向部分要有故事弧线。不要写成流水账年表。

**敢下判断**：鼓励给出观点，但必须有事实支撑。先摆事实，再给判断。推测明确标注。

**用人话写**：避免套话和空洞概括。用具体细节和例子代替。不写「该公司实现了快速增长」，写「从 2024 年中期的 1000 万美元 ARR 到 2025 年底的 10 亿美元」。

**节奏感**：句子长短交替，段落之间跳跃自然。

### 绝对禁区

- 套话：「首先...其次...最后」「综上所述」「值得注意的是」「不难发现」
- 空洞词：「赋能」「抓手」「打造闭环」
- 教科书开头：「在当今 AI 快速发展的时代」
- AI 高频词：「说白了」「本质上」「换句话说」「不可否认」
- 空泛工具名：不说「AI 工具」「某个模型」，说具体名字
- 编造：搜不到的信息标注「该信息暂缺」，绝不编造

## 不同研究对象的适配

核心原则不变，侧重点不同：

**产品**：纵轴重点看版本迭代、技术路线、用户增长；横轴重点看功能对比、性能、定价。

**公司**：纵轴重点看创始团队、融资、战略转向；横轴重点看商业模式、市场份额、营收。

**概念**：纵轴重点看谁提出的、如何流行、经历了哪些争论；横轴重点看与相近概念的区别、各自适用场景。

**人物**：纵轴重点看职业轨迹、关键决策、公开言论变化；横轴重点看与同领域人物的对比。

## 篇幅总览

| 部分 | 字数范围 |
|-----|---------|
| 纵向分析 | 6,000 - 15,000 字 |
| 横向分析 | 3,000 - 10,000 字 |
| 横纵交汇 | 1,500 - 3,000 字 |
| **全文总计** | **10,000 - 30,000 字** |

## 报告结构

```
一、一句话定义

二、纵向分析：从诞生到当下

三、横向分析：竞争图谱

四、横纵交汇洞察

五、信息来源
```

## 质检清单

- [ ] 纵轴是叙事故事，不是年表流水账
- [ ] 每个关键节点都展开写了，没有跳过
- [ ] 决策逻辑有还原，不只是「发生了什么」
- [ ] 横轴竞品场景判断正确（A/B/C）
- [ ] 用户口碑引用了真实用户的声音
- [ ] 横纵交汇产出了新判断，不是缩写版
- [ ] 未来推演三个剧本都有逻辑支撑
- [ ] 所有关键事实标注了信息来源
- [ ] 搜不到的信息诚实标注，没有编造
- [ ] 总字数在 10,000-30,000 字范围内
