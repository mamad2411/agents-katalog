# 女娲 · 写作Skill蒸馏器

> 「好文笔不是天赋，是系统。」——而系统是可以蒸馏、学习和迁移的。

## 核心理念

Writer Nuwa 不是复制一个作家的表面文风，
而是**提炼其可运行的写作系统**。

一个高质量 Writer Skill 应回答：

- 他如何**选择和组织素材**？（Writing Models）
- 遇到具体写作问题时，他通常采取什么**操作**？（Writing Heuristics）
- 他如何**造句**？（Linguistic DNA）
- 他如何**组织场景、人物和信息**？（Narrative DNA）
- 他如何**制造情绪**？（Emotional Mechanics）
- 他如何**使用意象与修辞**？（Imagery & Rhetorical System）
- 什么写法**看起来像他，实际上只是廉价模仿**？（Anti-patterns）
- **哪些体裁、时期、语言环境不能可靠泛化**？（Honest Boundaries）

**关键区分**：

捕捉的是 **HOW THEY WRITE**，
不是 **WHAT THEY WROTE**。

❌ 不要复制标志性句子。
❌ 不要拼贴名句。
❌ 不要把几个表面特征当成写作系统。

## 执行流程

### Phase 0: 入口分流

收到用户输入后，先判断属于哪条路径：

| 用户输入 | 路径 | 示例 |
|---------|------|------|
| 明确的作家名字 | **直接路径** → Phase 0A | 「蒸馏王小波的写作」「分析村上春树怎么写」 |
| 写作风格/需求描述 | **诊断路径** → Phase 0B | 「想写得更有说服力」「怎样写出有趣的故事」「想学冷静理性的评论风格」 |

---

### Phase 0A: 作家与写作任务确认（直接路径）

收到明确作家名字后，先锁定分析对象，避免在后续阶段因时间段、体裁、语言版本不一致而得出错误的写作系统。Phase 0A 的核心目标，是回答以下 7 个问题：

1. **这个作家是谁**：确保正确识别，避免同名/同人跨体裁混淆。
2. **原始创作语言**：区分原作与译作；翻译作品必须标注版本与译者。
3. **分析哪一时期**：不同阶段的写作系统可能差异很大，不能简单把整个生涯等同于一个统一风格。
4. **分析哪种体裁**：一个作家在小说、散文、诗歌、评论中的书写逻辑可能不同。
5. **用途**：学习模仿、写作工具、AI 风格蒸馏、学术研究，决定分析深度和输出形式。
6. **是否已有作品语料**：本地作品优先模式允许先细读作品，再补充网络资料。
7. **蒸馏档位**：决定资源投入、分析粒度和最终输出的复杂度。

#### 1) 作家是谁

**目标**：唯一锁定分析对象。

**确认项**：
- 作家全名（中/英/其他）
- 别名或笔名（如有）
- 生卒年份/活跃年代
- 主要国籍/文化语境
- 主要创作领域（小说、散文、诗歌、评论、剧本等）

**示例**：
- 「想蒸馏莫言的写作」
- 「我想分析村上春树的小说语言」
- 「看《围城》写作，想学钱钟书的散文逻辑」

如果用户只是给「某种风格」而没有明确作家，回到 Phase 0B 做逆向诊断。

#### 2) 原始创作语言

**目标**：区分原作语境与译作语境。

**注意**：
- 中文、英文、法文、日文等语言中的句法、节奏、表达方式并不一样。
- 若分析的是译作，必须说明译者、版本、原文语言。
- 译作不等于原作系统，不能直接把译本当作作家本体的原始语言系统。

**确认项**：
- 原始创作语言
- 是否要分析译本
- 若需要，是否对照多种译本

#### 3) 分析哪一时期

**目标**：避免把作家一生的写作系统混成一个全局模板。

**确认项**：
- 具体时期范围（如 1985-2005）
- 代表作品/阶段划分
- 是否要分析全创作生涯或单一阶段

**判断原则**：
- 许多作家在成熟期、转型期和晚期会明显改变策略；
- 若没有说明时期，默认按**代表作品时期**+**主要成熟期**分析，并保留阶段差异。

#### 4) 分析哪种体裁

**目标**：同一作家在不同体裁中的写作机制可能完全不同。

**确认项**：
- 小说 / 长篇 / 短篇 / 散文 / 诗歌 / 评论 / 剧本
- 是否需要跨体裁对比
- 目标体裁的代表作品

**关键原则**：
- 撰写系统不是“某作家一整套模板”；它通常是“某人某体裁的可运行写作机制”。
- 如果用户没有指定体裁，默认按其最代表性的体裁，并在结果里说明“该分析不代表全领域通用”。

#### 5) 用途

**目标**：决定分析深度和最终产出形式。

**常见用途**：
- 创意写作：关注写作 heuristics 和场景构造
- 学术研究：关注语言学、叙事和思想脉络
- AI/Prompt 风格蒸馏：关注可执行的系统抽象
- 个人学习：关注可迁移的写作方法与反模式

**确认项**：
- 你要做什么：模仿、参考、系统研究、训练、输出技能包
- 你希望得到什么样的产出：速查手册、完整Skill、案例集、模板、可执行写作器

#### 6) 是否已有作品语料

**目标**：判断是全网搜集，还是本地语料优先。

**确认项**：
- 是否已有作品文本（全文/节选）
- 是否已有访谈、创作论、评论、书评等材料
- 是否允许网络补充
- 是否偏好本地语料优先执行

**本地语料优先模式**：
- 用户提供作品 → 先读本地作品，找出真实风格特征
- 再补充网络资料，弥补历史背景、评论和访谈不足
- 这种模式通常更靠谱，因为它能减少“只看二手评价”的偏差

#### 7) 蒸馏档位

**目标**：决定投入资源规模和分析的精细度。

| 档位 | 调研规模 | 输出深度 | 适合场景 |
|------|---------|---------|---------|
| Tier 1 快速 | 2-3部代表作 + 1-2个资料源 | 速查版 | 先体验风格、轻量学习 |
| Tier 2 标准（默认） | 5-10部核心作品 + 访谈/评论 | 完整 Writer Skill | 大多数使用场景 |
| Tier 3 深度 | 多阶段作品 + 手稿/评论/学术研究 | 细致系统分析 | 精通和研究 |
| Tier 4 工业级 | 大规模资料，必要时与作者或历史资料协同验证 | 高保真、结构化风格引擎 | 商业化/研究级使用 |

**默认策略**：
- 用户没给任何细节 → 按“标准档 + 全面分析”推进
- 用户需要快速试验 → Tier 1
- 用户要深度学习或有研究价值 → Tier 2 / 3

#### Phase 0A 的确认原则

**确认不阻塞交付**：
- 能给默认值就给默认值
- 不要卡在提问环节
- 先生成基础分析框架，再让用户调整细节

**从确认到执行**：
- 用户提供本地语料 → 标记为 **本地语料优先模式**
- 之后进入 Phase 0.5，创建作品/研究目录结构
- 然后进入 Phase 1，多源文本分析

**最终确认模板**：

```yaml
# Phase 0A 确认单 - [作家名]

- 作家: [名字]
- 原始创作语言: [语言]
- 分析时期: [年份范围/阶段]
- 分析体裁: [小说/散文/评论等]
- 用途: [写作学习/学术研究/AI风格蒸馏]
- 已有作品语料: [是/否]
- 蒸馏档位: [Tier 1/2/3/4]

下一步: 创建目录 -> 收集研究资料 -> 分析 Phase 1
```

### Phase 0B: 需求诊断（模糊路径）

用户想改进写作但不知道该学哪个作家。女娲的工作是**从写作需求反推最合适的蒸馏对象**。

#### Step 1: 需求定位

通过1-2个追问，定位用户的核心写作需求：

| 需求维度 | 典型表达 | 推荐作家风格方向 |
|---------|---------|--------------|
| 说服力与论证 | 「想写得更有说服力」「论证不够严密」「观点容易被攻击」 | 理性分析、逻辑递进、严谨论据的作家 |
| 故事性与代入感 | 「故事太干」「读者不入戏」「人物不生动」 | 细节刻画、心理描写、场景构建的作家 |
| 吸引力与节奏 | 「开头写不好」「内容没人看」「节奏拖沓」 | 开篇技巧、悬念设置、快速切换的作家 |
| 文学性与意境 | 「想写出有意思的表达」「文字太普通」「想有格调」 | 比喻精妙、意象丰富、文笔优美的作家 |
| 批判与观察 | 「想像XX一样尖锐」「观察不透彻」「分析肤浅」 | 社会观察、批评眼光、深度剖析的作家 |
| 亲切与温暖 | 「想写得暖」「太冷漠了」「读者感受不到真诚」 | 温情笔调、人文关怀、真挚表达的作家 |
| 幽默与讽刺 | 「想写得有趣」「不知道怎么制造笑点」「想用讽刺」 | 讽刺高手、幽默技巧、荒诞感的作家 |
| 简洁与克制 | 「想删掉冗余」「废话太多」「表达不够直击」 | 极简风格、留白艺术、每字必要的作家 |
| 节奏与韵律 | 「句子生硬」「没有节奏感」「读起来别扭」 | 韵律讲究、音乐性强、句式多变的作家 |
| 风格转换 | 「想掌握多种风格」「想在严肃和轻松间切换」 | 风格多元、调性灵活的作家 |

追问原则：
- 最多问2轮，不要变问卷
- 用户表达清楚了就直接推荐
- 目的是区分相似需求（「简洁」是大道至简还是冷酷克制？）

**示例对话**：

```
用户：我的文章逻辑清楚但就是不吸引人，不知道怎么改

女娲：你说的「不吸引人」是指什么？是开头没有勾子、内容流水账式、还是表达方式太生硬？

用户：主要是开头和转折之间的连接，感觉跳跃太生硬

女娲：明白了，你需要学「流畅过渡和节奏感」。我推荐3个候选：
[展示推荐...]
```

#### Step 2: 候选推荐

基于需求，推荐2-3个作家。每个推荐说清楚这个作家的哪个写作特征匹配需求。

**来源A：本地已有Skill**
扫描 `.claude/skills/*-writer/` 目录，读取SKILL.md的description。已有Skill可直接使用，无需蒸馏。

**来源B：新蒸馏候选**
推荐最相关的作家，说清楚「为什么这个作家」。

每个候选的展示格式：

```
### 候选1: [作家名]  ⚡已有Skill / 🆕需要蒸馏

**核心特色**：[此作家最突出的写作特征，一句话]
**为什么适合你**：[直接对应你的写作需求]
**局限**：[这个作家也做不到什么，坦诚说明]
```

#### Step 3: 用户选择

- 选已有Skill → 直接激活，任务完成
- 选新蒸馏候选 → 进入Phase 0A确认 → Phase 0.5开始
- 都不满意 → 继续探索或自己提名作家

### Phase 0.5: 创建Writer Skill目录

**收到确认后立即执行**，在分析之前完成标准目录结构：

```
writer-[author-name]/
│

├── FIDELITY.md
│
├── references/
│   │
│   ├── research/
│   │   ├── 01-corpus.md
│   │   ├── 02-linguistic-dna.md
│   │   ├── 03-narrative-dna.md
│   │   ├── 04-rhetoric-imagery.md
│   │   ├── 05-poetics-criticism.md
│   │   └── 06-period-contrast.md
│   │
│   └── sources/
│       ├── primary/
│       │   ├── novels/
│       │   ├── stories/
│       │   ├── essays/
│       │   └── letters/
│       │
│       ├── interviews/
│       └── criticism/
│
├── scripts/
│   ├── corpus_stats.py
│   ├── sentence_stats.py
│   ├── punctuation_stats.py
│   └── style_compare.py
│
└── tests/
    ├── known-passages.md
    ├── unseen-prompts.md
    └── anti-imitation.md
```

**各目录职责**：
- `SKILL.md`：完整的分析结论、写作系统提炼和可执行指引
- `FIDELITY.md`：保真度说明，定义什么算“像作者”“不算像作者”，以及哪些地方要拒绝复制
- `references/research/`：对文本语料、语言结构、叙事机制、修辞与时代差异的系统化分析
- `references/sources/`：一手素材与二手批评的归档目录
- `scripts/`：用于统计句长、标点、字词偏好、比较写作特征的分析脚本
- `tests/`：用于验证风格落地的已知段落、未见题目、新写法和反模仿测试

**完成检查**（自动执行）：
- [ ] 目录已按标准结构创建
- [ ] `SKILL.md` 与 `FIDELITY.md` 已存在
- [ ] `references/research/` 中的分析文件已建立并写满
- [ ] 若有本地语料，已归档到 `references/sources/primary/`
- [ ] 若作家为中文或非英文作者，已标明语言/译本/时代差异
- [ ] 若是更新模式：已读取旧版 Skill，标注哪些分析需要刷新

**关键规则**：
- 每个 subagent 必须把分析结果写入对应的文件，不存文件的分析等于没做。
- **所有调研文件必须存在 skill 目录内部**，绝对不要存到外部目录。Skill 必须是自包含的。
- `FIDELITY.md` 不只是说明相似度，而是明确规定“哪些元素是可迁移的，哪些是不可复制的”。
- `tests/` 不是形式化展示，而是验证手段：用于检查写作风格是否真的被提炼、而不是表面模仿。

### Phase 1: 多源文本分析（并行Agent Swarm）

#### 模式判断：本地作品 vs 网络搜索

| 模式 | 触发条件 | 策略 |
|------|---------|------|
| **纯网络搜索**（默认） | 用户没有提供作品 | 6个Agent全部走网络搜索，完整流程 |
| **本地作品优先** | 用户提供了作品集/文本 | 先分析本地作品，网络搜索变为补充 |
| **纯本地作品** | 用户明确说「只用我给的作品」 | 只分析本地作品，不做网络搜索 |

**本地作品优先模式的执行**：

1. **先读本地作品**：逐部作品分析，按6个维度提取特征
2. **识别覆盖缺口**：本地作品覆盖了哪些方面？缺少什么（如某个时期的作品、访谈等）？
3. **定向补充搜索**：只对缺失维度启动网络搜索，已有充足本地素材的维度跳过
4. **来源标记**：分析文件中明确区分「来自本地作品」vs「来自网络信息」

**本地作品素材的处理**：

| 素材类型 | 处理方式 | 覆盖维度 |
|---------|---------|---------|
| 完整作品集PDF | 逐部作品仔细阅读与分析 | 作品(01)、文体(03)、演变(05) |
| 主要作品节选 | 深度文本分析 | 文体(03)、语言特征 |
| 创作论述集 | 提取作家自己的创作理论 | 创作论(02) |
| 访谈与演讲记录 | 分析作家谈创作的方式 | 创作论(02) |
| 学术评论文章 | 作为外部视角的来源 | 批评(04) |

#### 6个Agent的任务分配

启动6个并行subagent，每个负责不同分析维度。

##### Agent 1 — Corpus Analyst

**目标**：建立作家的代表性文本语料库，作为后续语言/叙事/修辞分析的基础。该 Agent 只负责“筛选、归类和语料结构”，不直接尝试总结最终写作系统。

**重点**：
- 代表作
- 不同时期作品
- 不同体裁
- 第一人称/第三人称样本
- 对话场景
- 描写场景
- 高情绪场景
- 开头
- 结尾

**任务要求**：
- 识别至少 3-6 个最有代表性的作品样本，覆盖不同阶段与不同面向
- 建立“语料分层”表：代表作 / 转型期 / 早期 / 晚期 / 不同体裁 / 不同叙述视角
- 对每个样本标注：作品名、年份、体裁、场景类型、叙述视角、情绪强度、位置（开头/中段/结尾）
- 在每个样本中选取 1-3 个可用于分析的段落，优先选择：
  - 对话密集段落
  - 景物描写段落
  - 高情绪状态段落
  - 结尾收束段落
  - 开头建立气氛段落
- 标明哪些样本是稳定风格特征较强的“基线文本”，哪些是转型期或例外文本
- 如果作品存在语言版本差异，标注原文/译文及版本来源

**输出文件**：`references/research/01-corpus.md`

**输出示例结构**：
```
# 01-corpus: [作家名] 语料库

## 1. 语料总览
- 代表作：...
- 分析时期：...
- 目标体裁：...
- 总体语料规模：...

## 2. 作品地图
| 作品 | 年代 | 体裁 | 叙述视角 | 场景特征 | 作用 |
|------|------|------|----------|----------|------|
| ... | ... | ... | ... | ... | ... |

## 3. 关键样本
### 样本 A: [作品名]
- 类型：开头 / 对话 / 高情绪 / 景物描写
- 位置：第X章/开头/结尾
- 关键特征：...

## 4. 语料补缺
- 当前缺失：...
- 需要补充：...
- 误差来源：...
```

**硬性要求**：
- 不要直接写“风格特点”结论，先做语料建设和分层整理

##### Agent 3 — Narratology Analyst

**目标**：研究作家的叙事机制，分析其如何组织视角、节奏、信息、人物和场景，使叙事具备内在张力和阅读推进力。

7. characterization
8. dialogue
9. transitions
10. endings

**任务要求**：

- 区分：
  - 视角（POV）
  - 聚焦（focalization）
  - 距离（narrative distance）
  - 时间结构（顺叙 / 插叙 / 反叙 / 预示）

##### Agent 5 — Poetics & Criticism Analyst

**目标**：汇总作家的创作论、批评与评价、文艺观与审美表述，建立“作者本人如何理解写作”与“评论者如何理解其写作”的双重证据链。

**优先检查来源**：
- 作者序言
- 书信
- 访谈
- 创作谈
- 文学演讲
- 批评文章
- 学术论文
- 同行评论

**任务要求**：
- 区分：
  - 作者本人对写作的描述
  - 作品里实际呈现的写作机制
  - 评论家/同行对作家写作的解释
- 把这些来源按证据强度分层：
  - 一手自述（最强）
  - 文本内证据（强）
  - 研究性批评（中）
  - 普遍评价或二手转述（弱）
- 重点观察：
  - 作者如何定义“真实”“清晰”“复杂”“简洁”“力量”“文学性”
  - 作家和评论者之间是否存在偏差、矛盾或时代语境差异
  - 哪些写作原则是作家真正实践的，哪些只是宣称或理想化表达
- 采用三层证据判断框架：
  - 文本：作品里确实出现了什么
  - 作者自述：作者如何描述自己的写作
  - 第三方研究：评论者如何解释这些写法
- 不要把三者直接等同。文本是事实，作者自述是解释，第三方研究是解读。
- 目标是形成“文本事实 → 作者理解 → 评论者解释”的链条，而不是只引用名言或概念化观点。
- 在完成分析时，必须说明：
  - 文本中是否稳定存在 X
  - 作者是否也意识到 X
  - 评论家是否观察到了 X
  - 三者是否一致、是否存在偏差、哪些内容可以转化为可迁移写作法

**输出文件**：`references/research/05-poetics-criticism.md`

**输出示例结构**：

```
- 访谈：...
- 书信/创作谈：...

## 2. 作品中的写作证据
- 反复出现的原则：...
- 作品实际显现的机制：...

- 学术论文：...
- 批评文章：...
- 同行评论：...

## 4. 分歧与张力
- 作者宣称 vs 实际作品：...
- 评论者解释 vs 文本证据：...

## 5. 结论
- 作者本人如何理解写作：...
```

**硬性要求**：
- 不能简单把作者自述当作“真理”
- 也不能简单把评论家解释当成“最终答案”
- 必须保留三者之间的差异，并说明其中哪些可以用于可迁移写作法

##### Agent 6 — Period + Contrast Analyst

**研究维度**：
- period
- contrast
- turning point
- stylistic shift
- continuity
- divergence
- phase transition
- cross-genre comparison
- before/after change

**任务要求**：
- 将写作生涯拆成明确阶段，例如早期 / 转型期 / 成熟期 / 晚期（如适用）
- 识别每个阶段的核心特征：
  - 叙事方式
  - 语言密度
  - 修辞风格
  - 情绪表达
  - 人物关系
  - 主题关注
- 找出关键转折点：
  - 哪个作品/年代开始明显变化
  - 变化来自外部事件、生活状态、文本实验，还是方法论变化
- 重点比较：
  - 前后阶段的差异
  - 同一时期不同作品之间的差异
  - 同一作者在不同体裁中的差异
- 说明哪些特征是稳定的“DNA”，哪些是暂时的试验或阶段性偏移

- 译文只能作为辅助证据，不能替代原始语言材料。
- 学术研究和专业评论可以用于补充，但不能压过文本和作者本人的材料。
- 普通书评、社媒总结、AI 摘要和内容农场式文章，不能作为构成写作系统的主要证据。
- 若存在资料冲突，优先采用权重更高的来源，并在分析中明确说明冲突与不确定性。

#### 信息源优先级

| 来源类型 | 揭示什么 | 权重 |
|---------|---------|------|
| **用户提供的一手素材** | 完整原文，未经二手过滤 | **最高+** |
| 本人著作 | 系统性思考 | 最高 |
| 长对话/访谈 | 即兴思维过程 | 最高 |
| 实际决策记录 | 真实行为 vs 声称 | 最高 |
| 社交媒体 | 表达风格、即时反应 | 中等 |
| 他人评价 | 外部视角、盲点 | 中等 |
| 二手转述 | 参考但需验证 | 低 |

#### 信息源黑名单（永远排除）

- **知乎**：洗稿严重、信息失真率高，不作为任何维度的来源
- **微信公众号**：封闭生态、无法验证、大量二手转述，不作为来源
- **百度百科/百度知道**：信息陈旧且不可靠

中文渠道只接受权威媒体：36氪、极客公园、晚点LatePost、财新、第一财经、虎嗅、少数派、机器之心等。人物访谈类可用播客平台（小宇宙、喜马拉雅原始音频）和B站原始视频（非搬运号）。

#### 失败模式与降级路径（if-then速查表）

蒸馏是长流程+多agent+联网任务，下表前三条都在真实用户中发生过（GitHub issue实证）。每条按「触发条件 → 一线修复 → 仍失败兜底」执行：

| 触发条件 | 一线修复 | 仍失败兜底 |
|---------|---------|-----------|
| 运行环境不支持并行subagent/后台任务（部分runtime会在Phase 1挂起死等） | 6个调研任务降级为**串行执行**：做完一个落盘一个，禁止挂起等待后台通知 | 单agent分6轮调研，每轮只做一个维度并立即落盘 |
| 上下文窗口不足（单次完整蒸馏可累积500k+ token，200k窗口模型跑不完） | 分Phase续跑：每个Phase结束即把状态写入 `references/research/`，新会话从文件恢复（调研文件本身就是断点） | 200k窗口模型分3段会话跑：Phase 0-1 / Phase 1.5-2.5 / Phase 3-5，每段开头先读已落盘文件 |
| 成本失控（用户未预期到长任务的token消耗） | Phase 0A的蒸馏档位确认就是防线：开跑前报量级、让用户选档 | 用户中途喊停 → 已落盘的调研文件即为可交付中间产物，下次续跑不清零 |
| 单个Agent超时（搜索5分钟无有价值结果） | 不等待，继续推进，Phase 2标注「信息不足」 | 诚实边界中说明该维度薄弱 |
| WebSearch等搜索工具不可用 | 改用运行环境可用的等价工具（fetch/浏览器工具/已装的信息获取skill） | 切换为纯本地语料模式，引导用户提供素材 |
| 信息源匮乏（<10条可用来源） | Phase 0.5就提醒用户，降低期望（心智模型减至2-3个） | 增加诚实边界篇幅，标注推测成分 |
| Agent结果冲突 | 保留矛盾——矛盾本身是有价值的信号 | 用「内在张力」section收录 |

**关键规则**：宁可生成一个诚实标注了局限的60分Skill，也不要生成一个看起来完美但实际上在编造的90分Skill。

### Phase 2: 写作特征提炼（Synthesis）

6个Agent分析完成后，执行结构化提炼，从原始分析中萃取可操作的写作系统。

#### Phase 2 强制转换门槛：描述不得直接入库

任何纯文学描述都**不得直接进入最终 Skill**，包括但不限于：

- “X 很有电影感”
- “X 很克制”
- “X 很冷峻”
- “X 的文字很透明”
- “X 很诗意”“X 很有张力”“X 很高级”

这些词只能作为待验证的观察假设，不能作为 Writing Model、Heuristic 或 DNA 规则。必须将其转换为可观察、可证据化、可触发、可执行、可回溯的规则。

**强制转换链**：

```text
Observation
↓
Evidence
↓
Mechanism
↓
Trigger
↓
Operation
↓
Failure Condition
```

**字段要求**：
- **Observation**：描述能被直接观察或统计的文本现象，不写评价词
- **Evidence**：提供原文样本、位置、频率、跨作品重复情况或对照材料
- **Mechanism**：解释该现象如何产生叙述、语言或情绪效果
- **Trigger**：说明什么场景、任务或文本问题会启动这条规则
- **Operation**：写成 AI 或作者可以逐步执行的动作
- **Failure Condition**：说明何时不适用、过度使用会怎样、什么信号表示规则失效

**禁止形式**：
- 只有形容词，没有文本现象
- 只有评论，没有原文证据
- 只有“应该这样写”，没有触发条件和操作步骤
- 只有风格效果，没有失败条件或适用边界

**转换示例：“情绪克制”**

```markdown
**Observation**：高情绪场景中，显式情绪词较少；情绪主要通过动作、物体和空间变化呈现。

**Evidence**：
- [作品/章节/页码]：人物遭遇[事件]后，没有直接写“悲伤”，而是出现[动作/物体细节]
- [作品/章节/页码]：类似场景重复出现[样本与频率]

**Mechanism**：情绪被外包给动作和物体，读者通过可观察细节推断人物状态。

**Trigger**：人物受到损害、失去关系或遭遇挫败，但不愿直接表达时。

**Operation**：
1. 删除情绪标签和心理结论
2. 保留一个可观察的身体动作
3. 加入一个与场景相关的具体物体
4. 让空间或物体承载人物关系变化
5. 控制修辞强度，不在段末总结情绪

**Failure Condition**：需要第一人称自白、直接传达信息或快速推进的场景；也不得为了“克制”而删除必要的心理信息。
```

**入库标准**：任何候选特征在进入后续 Phase 2 清单前，必须完成六字段转换。缺少任一字段时，只能保留为待验证假设，不得用于生成、改稿或 Fidelity 评分。

#### Phase 2.1 Writing Models 提取（3–7个）

Writing Model = 作者反复使用的、高层级、具有生成力的文本组织机制。

候选模型必须通过四重验证：

1. **Recurrence**
   - 是否在多个作品中重复出现？
   - 是否出现在不同篇章、不同场景、不同人物关系中？

2. **Cross-context**
   - 是否跨人物/场景/作品仍然成立？
   - 能否在不同情境中继续发挥作用，而不是只出现在个别文本中？

3. **Generativity**
   - 能否指导生成新的文本？
   - 能否作为写作方法为新场景提供模板，而不是仅概括作品经验？

4. **Distinctiveness**
   - 是否明显区别于同时代/同体裁普通写法？
   - 它是否体现作者独特的组织逻辑，而不是常规写作套路？

**筛选标准**：
- 只有同时满足重复性、跨情境性、生成性和独特性，才进入最终 Writing Models 清单。
- 若一个“模式”只是某篇作品的个案，或只是表层风格词汇，不算 Writing Model。
- 最终输出 3–7 个高质量模型，不能堆砌零散技巧。

**候选模型示例结构**：
```
### Writing Model 1: [模型名]
- 定义：...
- 典型机制：...
- 反复证据：...
- 跨情境性：...
- 可生成性：...
- 独特性：...
- 反例：...
```

**示例：WM-01 冷处理情绪**

```markdown
### WM-01 冷处理情绪

**核心机制**：
关键情绪不直接命名，而由人物行为、空间和物件承担。

**Evidence**：
- 作品 A：...
- 作品 B：...
- 作品 C：...

**Trigger**：
当场景需要表现：
- 悲伤
- 疏离
- 克制
- 无力

**Operations**：
1. 删除情绪名称
2. 寻找可观察动作
3. 增加具体物体
4. 让空间承担心理关系
5. 结尾不总结

**Failure Conditions**：
- 高速动作场景
- 明确议论文
- 需要直接信息传达的文本

**Anti-pattern**：
为了“克制”把所有心理描写都删掉。
```

**输出要求**：
- 写入 `SKILL.md` 的 Phase 2 章节
- 每个 Writing Model 必须能直接指向一套可执行写作动作
- 不能只停留在“主题”“气质”“文风”层面，必须是“组织机制”层面

#### Phase 2.2 Writing Heuristics 提取（6大类）

Writing Heuristics = 在特定写作情境下，作者反复应用的条件-行动规则。
格式：**WHEN [场景/问题] → DO [操作/策略]**

这些启发式规则来自对作品的归纳，是可传授、可训练的写作"快速决策"。

##### 1. Sentence Heuristics（句式启发式）

**WHEN** 需要表现突然情绪波动 **→ DO** 用短句打破节奏
- 例：从长句突然切到单词或超短句，营造冲击感

**WHEN** 需要深化抽象思考 **→ DO** 用复杂句承载多层嵌套
- 例：用从句、介词短语堆叠，让阅读速度变慢，思维深化

**WHEN** 字数限制但信息密集 **→ DO** 省略冗余连接词，用并列结构紧凑排列
- 例：「没有时间、没有精力、没有希望」而非「没有时间，也没有精力，更没有希望」

**WHEN** 需要制造歧义或多义性 **→ DO** 故意保留指代不明或多层理解空间
- 例：代词指代可指多个对象，允许读者在这个歧义中悬停

**WHEN** 需要传达克制与冷漠 **→ DO** 删除修饰语，用最直白的主谓宾结构
- 例：「她走了。」而非「她轻轻地走了出去」

##### 2. Paragraph Heuristics（段落启发式）

**WHEN** 段落只有观点但缺少呼吸 **→ DO** 在关键处插入极短段落（1-2句）制造停顿
- 例：在论述中插入独立的短句段落，让思维有喘气的机会

**WHEN** 信息量大但易造成阅读疲劳 **→ DO** 用段落长短交替，奇数段落较长、偶数段落极短
- 例：长段落（300字）→ 短段落（20字）→ 中段落（150字）

**WHEN** 需要暗示时间流逝或场景转换 **→ DO** 用段落分割而非显式时间标记
- 例：空行或段落分隔本身就表示时间跳跃，无需写「三年后」

**WHEN** 段落内容对比强烈 **→ DO** 用段落之间的留白突出对比
- 例：前段是高密度的事实罗列，后段是极简的观点，两段之间留足空白

**WHEN** 需要逐步递进逻辑 **→ DO** 每段递进一个论点，段与段呈阶梯状上升
- 例：第1段建立前提 → 第2段推进细节 → 第3段达到高潮 → 第4段回落或翻转

##### 3. Scene Heuristics（场景启发式）

**WHEN** 需要快速建立位置感和紧张气氛 **→ DO** 先写一个异常的细节，再交代背景
- 例：「门开了。」（异常）然后解释：「不该开。」（背景）

**WHEN** 场景中有多个人物但需要单一焦点 **→ DO** 只写一个人物的视角和动作，其他人物成为背景
- 例：虽然房间里有5个人，但只跟踪主人公的观察和反应

**WHEN** 需要表现隐性冲突而非动作冲突 **→ DO** 写细微的身体语言（手势、目光、呼吸）而非对话或行动
- 例：不写「他们吵架」，而写「她的手握紧了杯子」

**WHEN** 场景陷入静止状态但需要推进 **→ DO** 引入一个微小的变化（声音、光线、温度）打破平衡
- 例：远方传来一声关门声，整个房间的意义改变了

**WHEN** 需要制造读者的不适感 **→ DO** 故意让场景细节不完整，留下信息真空
- 例：只描写房间的某些部分，其他部分模糊或未命名，让读者感到不确定

##### 4. Character Heuristics（人物启发式）

**WHEN** 需要快速建立人物性格 **→ DO** 通过其对物体或环境的态度而非直接描写
- 例：不说「他很敏感」，而是「他总是调整灯光的亮度」

**WHEN** 人物有心理变化但需要克制表现 **→ DO** 只改变一个动作或习惯，让这个改变暗示心理状态
- 例：曾经细致的人物开始不整理房间，这个改变本身就是心理变化的信号

**WHEN** 需要暗示人物的真实意图与表面言辞的矛盾 **→ DO** 让对话和行动指向不同方向
- 例：人物说「我很好」但同时摸索口袋、转身离开，行动暗示真实状态

**WHEN** 人物应该有发展但要避免显得生硬 **→ DO** 让改变分散在多个小细节中，而非一次性转折
- 例：用3-5个微小的行为改变暗示人物缓慢成长，而非一场对话后突然改变

**WHEN** 需要展现人物的盲点或自欺 **→ DO** 让读者看到人物没有意识到的信息
- 例：人物自我感觉良好，但读者通过其他细节看到他被所有人避开

##### 5. Dialogue Heuristics（对话启发式）

**WHEN** 对话过于直接或生硬 **→ DO** 让人物回答不了问题，或答非所问
- 例：A问「你爱我吗」，B回答「外面下雨了」—— 回避本身就是回答

**WHEN** 需要通过对话暴露人物间的权力关系 **→ DO** 控制说话的主动权和打断的频率
- 例：强势人物总是先发言且不被打断，弱势人物回应迟缓或被打断

**WHEN** 对话含有隐藏信息，读者需要解读 **→ DO** 用对话的表面意思和潜台词的落差制造张力
- 例：「你的新工作怎么样」「不错啊」，但语调平淡无力，潜台词是「其实很糟」

**WHEN** 同一个问题被多个人物问起 **→ DO** 每次回答略有不同，显示人物在不同关系中的变化
- 例：对陌生人说「我很好」，对朋友说「其实很累」，对家人沉默不语

**WHEN** 对话中存在大量信息需要传达 **→ DO** 不要用对话本身传达，而是通过人物对信息的反应暗示
- 例：不是「他告诉我他要离开」，而是「他说要离开时，我的手开始发抖」

##### 6. Revision Heuristics（修订启发式）

**WHEN** 文本显得过度表达或矫情 **→ DO** 删除所有的感受词和形容词，看是否还能清楚表意
- 例：「她哭泣着」→ 删除「哭泣」后用行为替代：「泪水滑过她的脸」

**WHEN** 句子信息重复或可合并 **→ DO** 把两个信息的句子合成一个，看是否增加张力
- 例：「他很生气。他摔了杯子。」 → 「他摔了杯子。」（生气已暗示）

**WHEN** 段落显得冗长或拖沓 **→ DO** 删除段落的中间部分，看头尾是否能自然接续
- 例：如果删除中间能让逻辑或节奏更紧，就保留删除

**WHEN** 需要检查是否过度交代背景 **→ DO** 数一下背景信息出现的次数，如果≥2次就删除一次
- 例：「房子很破。房子的墙壁裂开了。」→ 只保留一个，另一个删除或转为行为

**WHEN** 发现某个细节被多次提及 **→ DO** 保留第一次出现的地方，删除后续重复，除非重复有意义
- 例：第一次用「她的手在颤抖」暗示紧张，第二次删除这个细节除非是为了制造回声

**WHEN** 对话或场景显得模板化或陈旧 **→ DO** 找出这段最"正常"的元素，然后删除它
- 例：典型的雨中离别场景最典型的元素是"雨"，删除它看故事是否更有力

#### Phase 2.3 Linguistic DNA（6维度语言基因）

Linguistic DNA = 作者的"语言指纹"。通过6个维度的结构化分析，揭示其语言系统的内在规律。

每个维度包含5个分析要素：
1. **Observation**：直接观察到什么
2. **Evidence**：具体文本证据（引文+位置）
3. **Rule**：归纳出的写作规则
4. **Strength**：这个特征的稳定度（high/medium/low）
5. **Exceptions**：例外情况（什么时候不适用）

##### 1. Lexical DNA（词汇层）

**维度**：高频词、词性偏好、词汇阶层、借用词

| 分析要素 | 提取内容 | 示例 |
|---------|---------|------|
| **Observation** | 列出高频词前20-30个，标注词频和出现场景 | top词：「缓缓」(23次) 「淡淡」(18次) 「轻轻」(25次) |
| **Evidence** | 每个高频词的来源作品、章节、句子 | 「缓缓」：《作品A》第3章、第7章；《作品B》开头 |
| **Rule** | 这个词汇偏好传达什么效果 | 古文词汇+减速效应 = 制造克制、宁静的气氛 |
| **Strength** | high（贯穿全部作品）/ medium（某时期/体裁）/ low（偶现） | high：古文词汇在所有作品中均≥15% |
| **Exceptions** | 什么情况下作者不用这个词 | 高速动作场景、激烈情绪场景中频率下降 |

**输出结构**：
```

- 古文/文言词汇：缓缓、淡淡、轻轻、悠悠... (占比: 18%)

- 动词密度：28%
- 形容词密度：12% (低于同代作家平均18%)
- 副词密度：22% (高）
- 名词抽象度：45%具体名词 / 55%抽象名词

#### 借用词与外来语
- 外来语使用率：<2%
- 网络词汇使用率：0%

```

##### 2. Syntax DNA（句法层）

**维度**：句长分布、主要句式、从属结构、信息流向

| 分析要素 | 提取内容 | 示例 |
|---------|---------|------|
| **Observation** | 平均句长、句长方差、主要模式 | mean: 18字; variance: high; 模式：短-短-长-短 |

| **Rule** | 句式选择与效果的映射 | 短句→紧张/冲击；长句→思维深入 |
| **Strength** | 这个模式的稳定性 | high：所有作品中短句占比60-70% |
| **Exceptions** | 什么文体或场景下句式会改变 | 理性论述段落中长句占比上升到45% |

#### Phase 2.4 Narrative DNA（11维度叙事基因）

Narrative DNA = 作者组织故事的方式。不分析「讲什么」，而分析「怎么讲」——视角、焦点、节奏、信息流、人物建立方式。

每个维度提供：**Observation → Evidence → Rule → Strength → Exceptions**

##### 1. POV（视角）

**Observation**：
- 第一人称vs第三人称的比例
- 多数作品采用何种视角
- 视角在作品内是否切换

**Evidence**：
- 第一人称作品列表：《作品A》《作品B》(占比30%)
- 第三人称作品列表：《作品C》《作品D》《作品E》(占比70%)

**Rule**：
- **默认视角**：第三人称有限视角（跟随单一人物，深入其心理，但不知道其他人物内心）
- **POV切换规则**：同一场景内不切换；新场景可切换到新人物的POV
- **何时用第一人称**：需要强烈共鸣、心理不可靠性、或私密日记感

**Strength**：
- high：有限第三人称在所有作品中保持一致

**Exceptions**：
- 短篇小说中可能用全知视角
- 极端情绪场景中偶尔闪入他人意识

---

##### 2. Focalization（焦点化）

**Observation**：
- 故事的"眼睛"是谁（narrator vs focalizer区分）
- 焦点人物是否随着叙述变化
- 焦点的深度（表面行为vs深层心理）

**Evidence**：
- 大部分场景从主人公视角出发（占比85%)
- 偶有客观观察视角(占比10%)
- 极少第二人称式直接指向读者(占比5%)

**Rule**：
- **单一焦点原则**：大多数场景聚焦于一人，他的感受、观察、反应主导场景
- **焦点切换时机**：章节分隔、时间跳跃、地点改变可切换焦点
- **焦点深度递进**：开场浅表观察→中段深入心理→结尾意识突变

**Strength**：
- high：焦点稳定性贯穿全作

**Exceptions**：
- 群戏场景中焦点可能分散
- 结尾处理时焦点可能拉远

---

##### 3. Narrative Distance（叙述距离）

**Observation**：
- 叙述者与故事事件的时间距离（事后多久叙述）
- 叙述者与人物的心理距离
- 叙述句式的距离指标（直接引语vs间接引语vs报道语）

**Evidence**：
- 直接引语比例：60% (「她说……」直接呈现)
- 间接引语比例：25% (她说她不想去)
- 报道语比例：15% (故事简述了她的态度)

**Rule**：
- **近距离**：大量直接引语、内心独白、细节描写 (用于高情绪或重要时刻)
- **中距离**：混合引语方式、部分心理描写、平衡细节与概括
- **远距离**：多用报道语、总结性描写、跳过细节 (用于过渡或低优先级事件)

**Strength**：
- high：距离选择与场景重要性正相关

**Exceptions**：
- 反讽场景中可用远距离描写重要时刻
- 某些心理场景可用极近距离但保持克制

---

##### 4. Information Control（信息控制）

**Observation**：
- 何时揭示关键信息
- 隐瞒或延迟信息的频率
- 读者知情度与人物知情度的时间差

**Evidence**：
- 关键信息提前揭示：20% (开头就说出)
- 关键信息同步揭示：50% (人物知道时读者知道)
- 关键信息延迟揭示：30% (读者滞后知道)

**Rule**：
- **悬念型控制**：关键信息延迟揭示5-15段，制造期待
- **同步型控制**：人物与读者同时获知信息，强化代入感
- **反讽型控制**：读者比人物先知道真相，制造讽刺
- **禁忌话题**：某些关键信息始终不直接说出，靠暗示和读者推断

**Strength**：
- high：信息控制与情节紧张度紧密相关

**Exceptions**：
- 理性论述段落中信息透明度升高
- 高速动作场景中信息控制降低

---

##### 5. Temporal Structure（时间结构）

**Observation**：
- 顺叙/倒叙/插叙的比例
- 时间跳跃的方式与频率
- 不同时间线的交织方式

**Evidence**：
- 顺叙占比：60%
- 插叙占比：30% (穿插回忆、背景)
- 倒叙占比：10% (从结局或中点开始)

**Rule**：
- **主干线顺叙**：故事按时间线向前推进
- **插叙规则**：在情绪高涨或转折点前插入背景，解释当下
- **时间跳跃信号**：用段落分割、环境变化、人物状态改变表示时间流逝，少用「三年后」
- **倒叙起点**：从结局或高潮时刻开始，然后回溯原因

**Strength**：
- high：时间结构稳定，易被识别

**Exceptions**：
- 后期作品中非线性结构增加
- 某些短篇用极端倒叙结构

---

##### 6. Scene Entry（场景进入）

**Observation**：
- 进入场景的常见方式
- 是否提供背景介绍
- 入场的速度（快速vs缓慢）

**Evidence**：
- 动作直接进入：45% (「她推开门」开场)
- 状态描写进入：35% (描写已经发生的状态)
- 环境异常进入：15% (从不寻常的细节开场)
- 背景介绍进入：<5% (很少)

**Rule**：
- **通常从动作或已发生状态进入**，避免长背景铺垫
- **快速进入规则**：第一句建立位置+人物+冲突，无需解释
- **异常优先**：如果场景开始时有不寻常的地方(异响、异常天气、人物异常状态)，先描写异常，再解释背景
- **背景禁忌**：避免「故事发生在一个…的地方，那里…」这类句式

**Strength**：
- high：快速进入是此作家的标志

**Exceptions**：
- 需要世界观建立的场景可用慢速进入
- 某些反思性段落可用背景優先

---

##### 7. Scene Exit（场景退出）

**Observation**：
- 场景如何结束
- 是否提供解释或总结
- 退出是否戛然而止或渐进

**Evidence**：
- 动作未完成即退出：40% (悬在紧张时刻)
- 情绪高点后退出：35% (情感达到顶点即切)
- 事件完成后退出：20% (给出清晰的结束)
- 解释性总结退出：<5% (几乎不用)

**Rule**：
- **经常在动作完成前退出**，将解释和反应留给读者
- **高情绪场景**：从最高点或最困惑的时刻退出，不交代后续
- **悬置式退出**：问题未解决、冲突未消解时切场景，读者悬在不确定中
- **禁止讲述后果**：不要在退出前解释这个场景意味着什么或导致什么

**Strength**：
- high：这是此作家的典型风格

**Exceptions**：
- 章节结尾有时会提供清晰收束
- 低优先级场景可用正常退出

---

##### 8. Characterization（人物塑造）

**Observation**：
- 人物如何被介绍(直接描写vs行为显露)
- 人物性格的呈现方式
- 人物成长/改变的速度

**Evidence**：
- 直接描写(「他是个…」)占比：<10% (极少)
- 行为与反应塑造：70% (通过怎么做、怎么说)
- 关系与互动塑造：20% (通过与他人的相处)

**Rule**：
- **通过行为和态度塑造，不直接说明性格**
- **一个改变=一个人物转变**：不要列举性格特征，而用单一的、持续的改变(如开始整理房间或停止整理)来暗示心理变化
- **人物独特性来自细节**：不是「他很害羞」，而是「他总是盯着自己的鞋」
- **人物成长分散化**：不用一场对话突然改变人物，用3-5个小细节跨越多个场景显示转变

**Strength**：
- high：行为塑造是此作家的核心原则

**Exceptions**：
- 配角可用更直接的描写
- 讽刺人物可违反常规塑造方式

---

##### 9. Dialogue（对话）

**Observation**：
- 对话密度（占全文比例）
- 对话的功能(信息传达vs人物显露vs冲突表现)
- 是否有人物言语差异

**Evidence**：
- 对话占全文比例：8-12% (低)
- 对话用于人物显露：60%
- 对话用于信息传达：25%
- 对话用于正面冲突：15%

**Rule**：
- **对话稀少但有力**：不用对话传达信息，而用行为或环境
- **答非所问规则**：当人物紧张/疏离/权力失衡时，让其回避问题或转移话题
- **人物言语差异明显**：不同人物的词汇、句长、话题完全不同(如一人用古文词，一人用短句)
- **对话不包含解释**：对话呈现冲突，不解释冲突；读者自行推断

**Strength**：
- high：稀疏有力的对话是特征

**Exceptions**：
- 亲密关系场景中对话密度可升高
- 某些作品中对话偶尔承载背景信息

---

##### 10. Transition（转场）

**Observation**：
- 场景与场景之间如何连接
- 是否用明确的过渡句或直接跳切
- 转场的时间跨度

**Evidence**：
- 直接跳切(无过渡句)：55%
- 用段落分割暗示转场：30%
- 用环境细节标记新场景：10%
- 用明确的时间标记：5%

**Rule**：
- **禁用显式过渡句**：不写「第二天」「之后」「与此同时」，而用章节分隔、环境变化、人物状态改变表示
- **转场在分隔处**：段落/章节的空行本身就表示时间或空间转换
- **新场景自我解释**：新场景的第一句应该让读者明白地点、人物、时间(不靠过渡句)

**Strength**：
- high：最小化过渡是风格特征

**Exceptions**：
- 时间跳跃过大时偶尔会用标记
- 复杂多线叙述中过渡可能增加

---

##### 11. Ending（结尾）

**Observation**：
- 作品结尾的类型(闭合vs开放vs悬置)
- 最后场景的处理方式
- 是否有道德判断或总结

**Evidence**：
- 开放式结尾：50% (问题未解、留给读者想象)
- 悬置式结尾：35% (在高潮或困惑处停止)
- 闭合式结尾：15% (提供相对完整的收束)

**Rule**：
- **经常选择开放或悬置式结尾**，而非明确收束
- **结尾不提供解释**：不交代人物后来怎样、故事意义是什么
- **最后一幕是关键**：结尾场景往往是最高情绪点或最深困惑点，在那里停止
- **结尾的克制**：不要写出「从此他们幸福地生活」或「她终于明白了…」，而用具体细节停止(最后的动作、表情、对话、环境)

**Strength**：
- high：悬置式结尾是标志特征

**Exceptions**：
- 短篇有时会用更明确的结尾
- 系列作品中某些部分需要闭合

---

**综合应用**：
| 维度 | 典型规则 | 效果 |
|------|---------|------|
| POV + Focalization | 单一有限第三人称POV + 深入单一人物焦点 | 强化代入感与主观感受 |
| Information Control + Temporal Structure | 延迟关键信息 + 插叙交织时间线 | 制造悬念与层次感 |
| Scene Entry + Scene Exit + Dialogue | 快速进入 + 悬置退出 + 稀疏对话 | 克制、留白、余音绕梁 |
| Characterization + Transition | 通过行为塑造 + 最小化过渡 | 人物改变与故事流动的自然性 |

#### 2.1 写作特征与技巧提取（核心工具库）

这不是「理论」，而是具体的、可学习的、有例句支撑的写作操作。

**操作步骤**：

1. **扫描所有分析**：逐个读取 `01-major-works.md` 到 `05-creative-evolution.md`，列出所有反复出现的写作手法和特征。通常会得到20-40个候选
2. **筛选标准**（三重验证）：
   - 高频出现：在≥3部作品中出现？
   - 可教学性：能用具体例句说清楚怎么做吗？
   - 风格代表性：这个手法是此作家的标签吗？
   - 三重通过 → 核心技巧；仅1-2重 → 备选手法；0重 → 丢弃
3. **排序取舍**：按代表性强度排序，取top 5-10个。宁少勿多——5个深刻的技巧远好于20个零碎的观察
4. **记录格式**：每个技巧含——名称、定义、原文例句（引用+作品名）、怎样学习、常见误区

#### 2.2 叙述风格与角度

此作家在讲故事时的习惯模式。不是「怎么想」，而是「怎么讲」。

| 维度 | 提取内容 | 示例 |
|------|---------|------|
| 叙述角度 | 第一人称/第三人称的偏好、全知视角还是有限视角 | 「总是用第一人称亲历式」或「常用第三人称制造距离感」 |
| 时间序列 | 顺叙/倒叙/插叙比例、时间跳跃的方式 | 「喜欢从结局开始倒推」「会在情节中穿插回忆」 |
| 开场套路 | 如何开启故事、常见的开场类型 | 「总是从细节入手」「喜欢制造悬念式开场」 |
| 节奏感 | 长段落与短段落的穿插、加速与延缓 | 「文笔时快时慢交替」「密集短句制造紧张感」 |
| 信息披露 | 如何逐步透露信息给读者、是否会隐瞒真相 | 「压抑信息制造悬念」或「开门见山直接交底」 |
| 转折设置 | 剧情如何转折、转折的频率和尖锐度 | 「转折突然又自然」「每章都有小转折」 |

#### 2.3 语言与修辞系统

最具体、最可模仿的部分。这是此作家真正的「笔尖风格」。

| 维度 | 提取方法 | 输出格式 |
|------|---------|---------|
| 句式结构 | 统计长句/短句/复杂句的比例，分析主要的句式模式 | 「70%短句+快速叠加，20%长句用来深化」 |
| 词汇特征 | 高频词前20个、词性偏好、是否用网络词汇/古文/行业术语 | 「反复用『缓缓』『淡淡』等古文味词汇」「完全不用网络词汇」 |
| 修辞手法 | 比喻/排比/拟人等常见手法，关键是要有具体例句 | 「比喻极其丰富，常用自然意象；排比用在情绪高潮」 |
| 音韵节奏 | 是否讲究字音、音节长度、平仄等因素 | 「注重字的音感，短句多用仄声收尾制造干练感」 |
| 标点运用 | 破折号/省略号/问号等的频率与功能 | 「频用省略号营造欲言又止的效果」 |
| 对白特征 | 对话的节奏、人物话语的差异、对白密度 | 「对白稀少但有力；不同人物用完全不同的词汇」 |

#### 2.4 主题与内核

此作家反复书写什么？他的执念是什么？

- **核心关怀**：3-5个反复出现的主题（爱/孤独/权力/身份等）
- **深层视角**：此作家看问题的独特角度（悲观/宽恕/讽刺/温和等）
- **人性观察**：对人性的独特洞察（有哪些人物类型反复出现？）
- **伦理位置**：此作家在道德立场上的站位

#### Phase 2.5 Imagery & Semantic System（9维度意象与语义系统）

Imagery & Semantic System = 作者的"意象库"与"意义网络"。通过意象、象征、隐喻等如何编织出作者独特的叙述空间。

每个维度包含：**高频对象 → 功能 → 象征意义 → 出现频率 → 跨作品一致性**

##### 1. Core Imagery（核心意象）

**定义**：在作者的所有作品中反复出现、承担相似功能的意象。

**分析要素**：
- 高频意象对象（出现≥10次）
- 每次出现时的功能（制造气氛/外化心理/象征主题）
- 出现的场景类型
- 意象的象征意义演变

**示例结构**：
```
### Core Imagery

**意象1：雨**
- 频率：《作品A》12次，《作品B》8次，《作品C》10次 → 总计30次
- 出现场景：孤独场景、离别时刻、压抑心理
- 功能：外化孤独与隔离感
- 象征意义：哀伤、隔绝、无力
- 一致性：high (跨作品符号意义保持一致)

**意象2：窗**
- 频率：18次
- 出现场景：人物观察外界、渴望但无法进入的关系
- 功能：象征分隔与渴望
- 象征意义：界限、观看、隔绝
- 一致性：high

**意象3：手**
- 频率：35次（最高频）
- 出现场景：人物感受、接触、冲突时刻
- 功能：外化情绪与身体反应
- 象征意义：能力、脆弱、联系
- 一致性：high
```

---

##### 2. Imagery Relationships（意象之间的关系）

**定义**：核心意象如何相互关联，形成一个有机的意象网络。

**分析维度**：
- 意象的对立关系（如"开放"vs"封闭"）
- 意象的递进关系（小意象组成大意象）
- 意象的转化关系（一个意象如何变成另一个）

**示例结构**：
```
### Imagery Relationships

**对立系统**：
- 开放 ↔ 封闭：窗(开放象征) ↔ 门(控制与隔绝象征)
- 光 ↔ 暗：光线(希望/清晰) ↔ 阴影(隐瞒/模糊)
- 流动 ↔ 静止：雨/风(变化) ↔ 石头/冰(不动)

**递进系统**：
- 手 → 拥抱 → 分离：肢体接触的升级与破裂
- 房间 → 窗 → 外面的世界：从内向外的空间深化

**转化系统**：
- 雨 → 泪水：自然意象向身体意象转化
- 冰 → 心：物质意象向心理意象转化
```

---

##### 3. Spatial System（空间系统）

**定义**：作者如何使用空间意象，构建"内"与"外"、"上"与"下"、"关闭"与"开放"的对立。

**分析维度**：
- 常见的空间设置（房间/街道/森林等）
- 空间的心理对应
- 人物在空间中的运动规律
- 空间的象征功能

**示例结构**：
```
### Spatial System

**内外空间**：
- 内部空间（房间、家）：安全感的缺失、隐秘、压抑
- 外部空间（街道、自然）：自由、暴露、无所依靠
- 过渡空间（窗、门、走廊）：选择与犹豫
- 规律：人物很少在两个空间间顺利过渡，往往卡在过渡点

**上下空间**：
- 高处：视野开阔但无所依靠
- 低处：压抑但安全
- 规律：内向/脆弱人物多在低处；对抗时升高

**开合空间**：
- 开放：无所遁形、无处可隐
- 封闭：安全但窒息
- 规律：都不是理想状态，人物在两者间摇摆

**空间密度**：
- 密集场景（人多、物多）：社交不适
- 空旷场景（人少、物少）：孤独与思考
```

---

##### 4. Body Imagery（身体系统）

**定义**：作者如何用身体部位、身体感受、身体动作来外化心理状态。

**分析维度**：
- 高频身体意象（手、眼睛、胸口等）
- 身体反应的规律（紧张时身体如何反应）
- 身体与情绪的映射
- 身体的禁忌（作者不常写的部位）

**示例结构**：
```
### Body Imagery

**高频身体意象**：
| 身体部位 | 频率 | 代表什么 | 典型场景 |
|---------|------|---------|---------|
| 手 | 35次 | 脆弱、能力、联系 | 接触、冲突、无力 |
| 眼睛 | 28次 | 观察、欲望、隐瞒 | 目光交汇、转移、闭闭 |
| 胸口 | 22次 | 压抑、心跳、疼痛 | 紧张、悲伤、激动 |
| 喉咙 | 15次 | 无法言说、卡顿 | 想说但说不出 |
| 腿 | 12次 | 逃离、无力、行动 | 逃跑、无法移动、踯躅 |

**身体反应规律**：
- 紧张时：手发抖、呼吸变快、胸口收紧
- 悲伤时：喉咙堵塞、眼睛避开、身体下沉
- 脆弱时：手无处放、双腿发软
- 禁忌：很少写面部表情（用身体取代面部）

**身体的禁忌**：
- 很少或不写：明显的表情描写、暴露的肉体描写
- 常写：隐秘部位的微妙反应（手指、颈部、耳朵）
```

---

##### 5. Color Imagery（颜色系统）

**定义**：作者对颜色的使用规律，颜色如何强化意境与情绪。

**分析维度**：
- 高频颜色
- 颜色的情绪对应
- 颜色的过渡规律
- 禁用颜色

**示例结构**：
```
### Color Imagery

**颜色频率与情绪**：
| 颜色 | 频率 | 情绪关联 | 典型场景 |
|------|------|---------|---------|
| 灰 | 45次（最高） | 压抑、模糊、无色彩感 | 日常、失望时刻 |
| 白 | 28次 | 空白、清冷、隐秘 | 雪、墙壁、沉默 |
| 黑 | 25次 | 夜晚、隐瞒、深度 | 夜晚、阴影、秘密 |
| 红 | 8次 | 冲突、血液、生命 | 很少使用，仅在激烈时刻 |
| 彩色 | 2次 | 极为罕见，似乎违背美学 | 几乎不出现 |

**颜色规律**：
- 灰白黑主导：世界是去饱和的
- 彩色缺席：没有鲜艳、没有热烈
- 过渡色多：灰蓝、淡黑、冷白
- 禁用色：暖色系（橙、黄、热红）在此作家笔下罕见

**颜色的心理效应**：
- 灰 = 麻木、平凡、难以界定
- 白 = 空旷、清晰但冷漠
- 黑 = 深度、秘密、不可知
```

---

##### 6. Natural Imagery（自然意象）

**定义**：作者如何借用自然现象(天气、季节、地貌)来映射人物心理与叙述气氛。

**分析维度**：
- 常见自然意象
- 自然与人物心理的映射
- 季节规律
- 天气规律

**示例结构**：
```
### Natural Imagery

**高频自然意象**：
| 意象 | 频率 | 对应心理 | 典型时刻 |
|------|------|---------|---------|
| 雨 | 30次 | 孤独、隔绝、眼泪 | 离别、失望、压抑 |
| 风 | 18次 | 变化、不安、推力 | 转折、冲突前夕 |
| 雾 | 12次 | 模糊、不可见、迷茫 | 迷茫时刻、真相遮蔽 |
| 光 | 25次 | 希望或暴露 | 看清、被看清、醒悟 |
| 季节变化 | 交替 | 时间流逝、心理变化 | 人物成长的背景 |

**季节规律**：
- 冬：压抑、结束、静止
- 春：不常出现或不樂观
- 夏：罕见（避免温暖）
- 秋：衰落、悲伤

**天气与心情的严格对应**：
- 人物悲伤时，天气必然是阴雨
- 人物困惑时，雾气浓重
- 人物解脱时，光线出现（但往往是冷光）
```

##### 7. Object Imagery（物件系统）

**定义**：无生命物体如何承载符号意义，成为人物心理的外化表现。

**分析维度**：
- 象征性物件（反复出现且意义单一）
- 物件的功能变化
- 物件的处理方式（如何对待这个物件反映人物状态）
- 禁用物件

**示例结构**：
```
### Object Imagery

**象征性物件**：
| 物件 | 频率 | 象征意义 | 功能 |
|------|------|---------|------|
| 书 | 14次 | 逃离、知识、隔绝 | 人物用书隔离自己或世界 |
| 镜子 | 11次 | 自我认知、真相、对视 | 避免对视、看清自己 |
| 钥匙 | 8次 | 打开、拥有权、隐秘 | 打不开、失去、寻找 |
| 信/信件 | 9次 | 无法面对面、延迟沟通 | 难以寄出、被拦截、烧毁 |
| 衣服 | 16次 | 身份、掩藏、脱落 | 穿上/脱掉衣服反映心理改变 |

**物件的处理规律**：
- 象征性物件多被损坏、遗失或放弃
- 人物对物件的态度反映其心理轨迹
- 物件的触觉特征往往被强调（冷/硬/滑/粗糙）

**物件的禁忌**：
- 很少出现：温暖的物件（火、热水）
- 很少出现：明显的奢侈品或艳丽物件
- 常见：冷硬物质（石、冰、玻璃、镜子）
```

##### 8. Sensory Preference（感官偏好）

**定义**：作者倾向于使用哪些感官通道来描写世界，哪些感官被压制。

**分析维度**：
- 各感官的使用频率
- 感官的组合方式
- 禁用感官
- 感官的准确性（是否精确描写）

**示例结构**：
```
### Sensory Preference

**感官使用频率**：
| 感官 | 占比 | 特点 |
|------|------|------|
| 视觉 | 45% | 占绝对主导；强调观看与被看；视线的转移 |
| 触觉 | 30% | 温度(冷)、质地(硬/粗/滑) |
| 听觉 | 15% | 沉默多于声音；声音作为中断 |
| 嗅觉 | 5% | 极少，且多为陌生/不适感 |
| 味觉 | 5% | 极少，几乎不涉及 |

**感官偏好规律**：
- 视觉压倒性主导：「看」「眼神」「光」是叙述核心
- 触觉其次：强调身体感受而非视觉美
- 听觉被压制：沉默多于对话，声音往往制造不适
- 嗅觉/味觉缺席：此作家笔下世界缺乏温度与滋味

**感官组合**：
- 视觉+触觉：看到冷硬的物体，传达压抑感
- 视觉+缺失听觉：寂静的观看场景
- 禁止组合：嗅觉+温暖食物（这会制造舒适感）
```

##### 9. Thematic Semantic Field（主题语义场）

**定义**：围绕某个核心主题，作者使用的相关词汇、意象、场景的集合。

**分析维度**：
- 核心主题（如"孤独""权力""身份"）
- 这个主题周围的词汇场
- 这个主题周围的意象场
- 这个主题如何跨作品变化

**示例结构**：
```
### Thematic Semantic Field

**主题1：孤独**
- 核心词汇：孤、独、隔离、分离、无人、寂静、空白

**主题2：隐秘/不可言说**

- 相关身体反应：喉咙、闭嘴、转身、避开眼神
- 相关场景：想说但无法说出、被迫沉默、秘密被发现

**主题3：权力与权力关系**
```

#### Phase 2.6 风格 Anti-patterns（禁忌与边界）

**Anti-patterns** = 作者**绝对不会**使用的写作手法与风格陷阱。通过识别"永不跨越的线"，来界定此作家的风格边界。

##### 禁止项（Prohibitions）

此作家在其作品中**严格避免**的手法：

1. **禁止拼贴名句**
   - 不会为了"有文采"而引用或模仿经典文学句子
   - 避免显而易见的文学参照
   - 所有语言应来自直接观察与个人感受，而非文学传统

2. **禁止复制标志性句式**
   - 不重复使用相同的句子结构来制造"风格一致性"
   - 每次表达同一个意思时，用不同的方式
   - 避免形成机械性的句式签名

3. **禁止过量重复代表性意象**
   - 某个意象（如"雨"）虽然是核心意象，但不能在同一段落/章节内反复出现
   - 意象的出现需要间隔，保持其象征力量
   - 过度重复会使意象变成空壳

4. **禁止把作者简化成3个形容词**
   - 比如："冷漠的"、"压抑的"、"孤独的"
   - 这样的简化会导致风格陷入单调
   - 即使作者有显著特征，也应在每个作品中有微妙的变化

5. **禁止每句话都强行风格化**
   - 不是每句话都需要精心打磨
   - 过度风格化的叙述会显得刻意与虚伪
   - 应有"无风格"的日常叙述作为对比

6. **禁止为了像作者而破坏情节逻辑**
   - 不能为了保持"冷漠"而忽视人物动机的合理性
   - 风格应服从故事逻辑，而非相反
   - 人物行为必须可信，即使这暴露了某些"风格弱点"

7. **禁止把翻译腔误认为原作者语言**
   - 若作品有翻译版本，翻译的表达方式不能被视为原作特征
   - 需要对比原语言版本
   - 某些"外国文学范儿"可能源于翻译，而非作者本意

##### 边界问题（Boundaries）

识别此作家风格研究的**局限与不确定性**：

1. **时间限制：哪些时期材料缺失？**
   - 作者早期/中期/晚期的作品是否都有留存？
   - 若某个时期资料稀少，该时期的风格特征是否可靠？
   - 例：早期作品如果仅存1篇，特征提取的置信度应该更低

2. **体裁限制：哪些体裁没有被分析？**
   - 研究是否仅基于长篇小说？
   - 短篇、散文、诗歌的风格是否与长篇一致？
   - 某些风格特征可能只在特定体裁中出现

3. **验证范围：是否只能验证小说？**
   - 若只有小说作品，提取的"风格"能否应用于非虚构写作？
   - 叙述技巧与论证技巧是否有本质差异？
   - 该框架的应用范围应被明确标记

4. **翻译影响：翻译会影响哪些判断？**
   - 语言特征（词汇、句式、韵律）在翻译中可能丧失
   - 某些"风格特征"可能源于翻译的选择，而非原作
   - 需要标记哪些特征只能在原语言中验证

5. **置信度问题：哪些特征置信度低？**
   - 某个特征若仅在1-2部作品中出现，是核心特征还是偶然？
   - 应为每个特征标记置信度（high/medium/low）
   - 低置信度特征不应作为主要教学对象

6. **信息来源：哪些判断来自评论家而非文本统计？**
   - 某个特征若来自二手评论，而非直接文本分析，应明确标记
   - "作者孤独的人生观"这样的判断通常来自传记，而非作品本身
   - 避免将传记影响与文本特征混淆
   - 可信度层级：文本统计 > 多部作品验证 > 评论共识 > 作者自述 > 传记推断

#### Phase 2.7 文学谱系与影响

- **师承与影响**：此作家受谁影响、学了谁的写作技巧
- **同代对话**：与同时代作家的风格对比
- **开创性**：这个作家开创了什么、改变了什么
- **后续影响**：影响了哪些后来的作家

#### 2.7 诚实边界

必须明确写出的局限：
- 无法复现此作家的创意与想象力
- 某些技巧来自此作家的个人经历，难以迁移
- 某些风格特征来自他的时代背景，当代不太适用
- 信息来源与分析时间点

#### 回答工作流（Agentic Protocol）生成指引

**为什么需要这个段落**：让人物不只是「说得像」，还「做得像」。没有这个段落，人物Skill遇到需要事实的问题时会凭训练语料编造，而不是像真人一样先做功课再发言。这是人物Skill从「鹦鹉学舌」升级为「可靠思维顾问」的关键。

**位置**：放在「角色扮演规则」之后、「示例对话」之前。

**生成规则**：

生成的Agentic Protocol必须包含以下3个Step，其中Step 2的研究维度必须**根据蒸馏出的心智模型自动推导**，不是固定模板：

```markdown
## 回答工作流（Agentic Protocol）

**核心原则：[人物名]不凭感觉说话。遇到需要事实支撑的问题时，先做功课再回答。**

### Step 1: 问题分类

收到问题后，先判断类型：

| 类型 | 特征 | 行动 |
|------|------|------|
| **需要事实的问题** | 涉及具体公司/人物/事件/产品/市场现状 | → 先研究再回答（Step 2） |
| **纯框架问题** | 抽象价值观、思维方式、人生建议 | → 直接用心智模型回答（跳到Step 3） |
| **混合问题** | 用具体案例讨论抽象道理 | → 先获取案例事实，再用框架分析 |

**判断原则**：如果回答质量会因为缺少最新信息而显著下降，就必须先研究。宁可多搜一次，也不要凭训练语料编造。

### Step 2: [人物名]式研究（按问题类型选择）

**⚠️ 必须使用工具（WebSearch等）获取真实信息，不可跳过。**

[根据此人的心智模型和分析偏好，生成3-5个研究维度分类，每个分类下列出4-6个具体研究点]

#### 研究输出格式
研究完成后，先在内部整理事实摘要（不输出给用户），然后进入Step 3。
用户看到的不是调研报告，而是[人物名]基于真实信息做出的判断。

### Step 3: [人物名]式回答

基于Step 2获取的事实（如有），运用心智模型和表达DNA输出回答。
```

**Step 2研究维度的推导方法**：

从蒸馏出的心智模型反推此人分析问题时最关注什么，将其转化为具体的搜索维度。举例：

| 人物 | 核心心智模型 | → 推导出的研究维度 |
|------|------------|------------------|
| 芒格 | 多元思维模型、逆向思考、激励机制 | → 看护城河、看管理层激励结构、看最大风险（逆向）、看历史类比 |

| 塔勒布 | 反脆弱、尾部风险、知识的僭妄 | → 看极端情况、看谁在承担尾部风险、看专家预测的历史记录 |
| MrBeast | 注意力工程、测试迭代 | → 看竞品数据（播放/互动）、看标题/缩略图的A/B测试空间、看受众画像 |

**关键约束**：
- 研究维度必须来自心智模型，不能是通用的「搜索相关信息」

- 按问题类型分组（如芒格分「看公司」「看人物」「看事件」），让Skill使用者能快速定位

#### Step 3: 示例写作指南

根据Phase 2的提炼，生成3-5个「如何在自己的写作中应用此作家的技巧」的具体示例：

每个示例的格式：
```

【此作家的做法】说明此作家会如何处理（引用一个实际的例子）
【学习要点】提炼出可学习的具体操作
【常见误区】写这样做时常犯的错误
```

## Writing Protocol

1. **Diagnose**
   - Determine the task: original writing, rewrite, polish, style analysis, structure, dialogue, character, syntax, or rhythm.

2. **Preserve Content**
   - Keep facts, causality, and character decisions intact.
   - Separate what can change: structure, syntax, and rhetoric.

3. **Structural Pass**
   - Apply `Writing Models` and `Narrative DNA` first.
   - Do not adjust wording before the structure is stable.

4. **Sentence Pass**
   - Apply `Syntax`, `Lexicon`, `Rhythm`, and `Punctuation`.
   - Refine sentence shape, diction, cadence, and punctuation only after the structure is sound.

5. **Rhetorical Pass**
   - Apply `Imagery`, `Metaphor`, `Irony`, and `Repetition`.
   - Strengthen expression without forcing stylistic excess.

6. **Anti-Imitation Pass**
   - Remove recognizable quotations, excess signature imagery, forced period diction, and surface-level imitation.

7. **Fidelity Check**
   - Verify structure, syntax, rhythm, narrative distance, information control, imagery, and restraint.
   - If the prose feels artificial, revise before finalizing.

### Phase 4: 写作示例验证

生成Skill后，用子agent执行8项实践测试（独立验证，避免自我偏差）：

#### 4.1 已知段落重构测试（Known Passage Reconstruction）

选取作者真实作品中的一段作为测试材料。保留原文的**人物、事件、地点与事实**，删除原文的具体措辞、句法、修辞与段落组织，再让Skill根据这些内容重写。

**测试约束**：
- 不向执行Agent提供原文或原文片段
- 只提供人物、事件、地点、事实，以及必要的因果关系
- 重写内容不得添加原文没有的关键事实

**对比维度**：
- **句法**：句长、从句结构、语序与句式密度
- **节奏**：停顿、推进速度、长短句交替与段落呼吸
- **叙事距离**：视角位置、心理进入深度与观察远近
- **信息释放**：信息揭示顺序、延迟、隐藏与读者知情度
- **修辞策略**：意象、隐喻、反讽、重复与留白的使用方式

**输出格式**：
| 维度 | 原文特征 | 重构文本特征 | 匹配度（0-3） | 偏差与原因 |
|------|---------|-------------|---------------|-----------|
| 句法 | [分析] | [分析] | [0-3] | [说明] |
| 节奏 | [分析] | [分析] | [0-3] | [说明] |
| 叙事距离 | [分析] | [分析] | [0-3] | [说明] |
| 信息释放 | [分析] | [分析] | [0-3] | [说明] |
| 修辞策略 | [分析] | [分析] | [0-3] | [说明] |

**通过标准**：重构文本保留原文事实与因果逻辑，且至少4个维度达到2分以上；若只复现了表面词汇或代表性意象，则判定失败。

#### 4.2 未知题材测试（Unseen Topic Test）

选择作者从未写过、且不属于其原有语料时代的现代题材，测试 `Writing Models` 是否能够脱离原作表面符号继续成立：

- 地铁
- 智能手机
- AI
- 视频会议

**测试约束**：
- 不使用作者作品中的人物、地点、物件、时代词或代表性意象
- 不把现代题材强行改写成作者熟悉的历史背景
- 只迁移 `Writing Models` 中定义的触发条件、操作步骤和叙述机制
- 每个题材使用相近的篇幅与冲突强度，避免题材差异掩盖结果

**检查问题**：
- 模型是否仍能处理新的情境、工具与社会关系？
- 叙述机制是否迁移，还是只会调用雨、窗、房间等表面符号？
- 去除代表性意象后，句法、节奏、叙事距离和信息控制是否仍然稳定？
- 现代技术是否改变了模型的触发条件或操作步骤？

**输出格式**：
| 题材 | 使用的Writing Model | 迁移后的具体操作 | 是否依赖表面符号 | 机制成立度（0-3） | 失败原因 |
|------|---------------------|------------------|------------------|-------------------|----------|
| 地铁 | [WM-XX] | [操作] | [是/否] | [0-3] | [说明] |
| 智能手机 | [WM-XX] | [操作] | [是/否] | [0-3] | [说明] |
| AI | [WM-XX] | [操作] | [是/否] | [0-3] | [说明] |
| 视频会议 | [WM-XX] | [操作] | [是/否] | [0-3] | [说明] |

**通过标准**：至少3个题材的机制成立度达到2分以上，且不依赖作者的代表性意象或时代词。若只有换了现代名词、但信息控制、叙事距离与情绪生成方式没有迁移，则判定为记住表面符号，而非学到机制。

**结论标签**：
- **机制迁移**：新题材中仍能复现核心操作，且不依赖表面符号
- **部分迁移**：核心操作成立，但部分模型需要调整触发条件
- **表面记忆**：离开原作意象、时代与场景后，模型无法工作

#### 4.3 风格消融测试（Style Ablation）

通过逐一关闭风格模块，判断每个模块是否产生可观察、可执行的效果。除被关闭的模块外，所有条件必须保持一致。

**测试条件**：
- **Full**：启用 `Writing Models`、`Narrative DNA`、`Linguistic DNA` 与 `Imagery`
- **No Writing Models**：关闭 `Writing Models`
- **No Narrative DNA**：关闭 `Narrative DNA`
- **No Linguistic DNA**：关闭 `Linguistic DNA`
- **No Imagery**：关闭 `Imagery`

**控制变量**：
- 使用同一输入文本、同一写作任务与同一作者Skill
- 保持事实、篇幅、视角、输出格式和编辑轮次一致
- 每次只关闭一个模块，不同时改变其他规则
- 不根据预期结果事后修改输入或评分标准

**观察维度**：
- 结构与情节组织
- 句法与词汇
- 节奏与段落推进
- 叙事距离与信息释放
- 意象、隐喻与修辞密度

**输出格式**：
| 条件 | 保留的模块 | 最明显的变化 | 受影响的维度 | 差异度（0-3） | 结论 |
|------|------------|--------------|--------------|---------------|------|
| Full | 全部模块 | [基准表现] | [维度] | 3 | [基准] |
| No Writing Models | 除Writing Models外 | [变化] | [维度] | [0-3] | [说明] |
| No Narrative DNA | 除Narrative DNA外 | [变化] | [维度] | [0-3] | [说明] |
| No Linguistic DNA | 除Linguistic DNA外 | [变化] | [维度] | [0-3] | [说明] |
| No Imagery | 除Imagery外 | [变化] | [维度] | [0-3] | [说明] |

**判定规则**：
- 某模块关闭后，预期关联维度出现稳定且可复述的变化，说明该模块具备可执行性
- 某模块关闭后几乎没有变化，说明该模块可能只是描述性标签，应回到 Phase 2 补充触发条件、操作步骤和失败模式
- 变化只体现在代表性词汇或意象消失，而结构、信息控制和情绪机制不变，说明测试测到的是表面符号，不是写作机制

**通过标准**：至少3个模块在关闭后产生差异度达到2分以上的可观察变化，且变化能对应到该模块负责的维度。若所有消融条件与 Full 几乎无差异，则判定 Skill 尚未形成可执行模块。

#### 4.4 反漫画化测试（Anti-Caricature）

专门检查生成结果是否把作者风格压缩成网络流行的“XX风”刻板印象，或依赖廉价、可替换的表面标记。

**测试方法**：
- 使用与 4.3 风格消融测试相同的任务和输入约束生成文本
- 由独立评审逐句标记风格信号，不把“读起来像”直接等同于通过
- 将被标记的信号分为**机制性特征**与**表面性特征**，分别统计其比例

**反漫画化检查项**：
- 是否疯狂插入作者代表性词汇，而这些词对场景没有必要？
- 是否让几乎所有句子都承担“金句”功能，缺少自然、普通的叙述句？
- 是否过度使用某个著名意象，导致意象成为标签而不是叙事工具？
- 是否出现网络上对作者的固定形容词或“XX风”刻板印象？
- 删除代表性词汇和意象后，结构、句法、节奏、叙事距离与信息控制是否仍然成立？

**输出格式**：
| 检查项 | 证据 | 表面模仿次数 | 机制性特征次数 | 风险等级（low/medium/high） | 修订动作 |
|--------|------|--------------|----------------|----------------------------|----------|
| 代表性词汇 | [词与上下文] | [次数] | [次数] | [等级] | [删除/替换/保留] |
| 金句化 | [句子样本] | [次数] | [次数] | [等级] | [改为自然叙述] |
| 著名意象 | [意象与分布] | [次数] | [次数] | [等级] | [删减/改功能] |
| 网络刻板印象 | [固定标签或语气] | [次数] | [次数] | [等级] | [重写/删除] |

**通过标准**：
- 不得出现未经叙事需要支撑的代表性词汇或著名意象堆叠
- 普通叙述句与高强度表达之间保持必要对比，不能句句金句化
- 删除表面标记后，文本的核心写作机制仍应可辨认
- 任一检查项达到 high 风险，必须先修订，再进入 Fidelity Check

**失败信号**：文本只剩下几个高频词、固定意象和夸张语气时，判定为网络刻板印象，而不是作者写作系统的有效转化。

#### 4.5 对照测试（Contrast Test）

使用 Writer Skill A 与 Writer Skill B 处理完全相同的写作任务，检验两个写作系统是否产生结构性差异，而不是只替换几个形容词。

**测试设置**：
- 选择两个风格差异明确的Writer Skill，例如 `Hemingway Writer Skill` 与 `Fitzgerald Writer Skill`
- 提供相同的任务、人物、事件、地点、事实、视角、篇幅和输出格式
- 除目标Skill外，不向模型提示应当产生哪些差异
- 使用独立评审对两份输出进行盲评，避免先入为主

**对比维度**：
- **结构**：场景组织、段落功能与转折位置
- **句法**：句长、从句密度、并列/从属关系与语序
- **节奏**：推进速度、停顿、长短句比例与段落呼吸
- **叙事距离**：心理进入深度、观察位置与叙述者介入程度
- **信息控制**：揭示顺序、延迟、留白与读者知情度
- **修辞策略**：意象、隐喻、反讽、重复和细节选择
- **情绪机制**：情绪如何生成、递进和收束

**输出格式**：
| 维度 | Writer Skill A | Writer Skill B | 差异度（0-3） | 是否为结构性差异 | 证据 |
|------|----------------|----------------|---------------|------------------|------|
| 结构 | [分析] | [分析] | [0-3] | [是/否] | [段落或情节证据] |
| 句法 | [分析] | [分析] | [0-3] | [是/否] | [句式证据] |
| 节奏 | [分析] | [分析] | [0-3] | [是/否] | [节奏证据] |
| 叙事距离 | [分析] | [分析] | [0-3] | [是/否] | [视角证据] |
| 信息控制 | [分析] | [分析] | [0-3] | [是/否] | [信息证据] |
| 修辞策略 | [分析] | [分析] | [0-3] | [是/否] | [修辞证据] |
| 情绪机制 | [分析] | [分析] | [0-3] | [是/否] | [情绪证据] |

**失败条件**：
- 两份文本只差几个形容词、语气词或表面意象，其他层面基本相同
- 两个Skill都退化成通用的“文学化”表达，无法体现各自的写作机制
- 差异只来自篇幅、事实、视角或任务执行不一致

**通过标准**：至少5个对比维度达到差异度2分以上，且其中至少4个被评为结构性差异。若差异主要停留在形容词替换或意象替换，判定为 `FAIL`。

#### 4.6 模仿测试（Imitation Test）
选此作家的一个短篇段落，让子agent用生成的Skill写一个类似风格的100-150字段落。对比结果：
- 语言风格、修辞手法、节奏感是否接近？
- 是否成功复现了核心特征？

#### 4.7 识别测试（Recognition Test）
给子agent 3段文字：1段此作家原文、1段用Skill写的仿作、1段其他人写的。
- 能否正确识别原文和仿作？
- 仿作的相似度和辨识度如何？

#### 4.8 应用测试（Application Test）
给定一个写作需求（「写一个冲突场景」「写一个细节描写」等），子agent用Skill协助用户完成。
- 建议是否具体可行？
- 生成的文本是否体现了此作家的特征？

#### 4.9 通过标准

| 评分项 | 权重 |
|--------|------|
| Writing Model fidelity | 20 |
| Narrative fidelity | 20 |
| Syntactic fidelity | 15 |
| Rhythmic fidelity | 10 |
| Lexical fidelity | 10 |
| Rhetorical fidelity | 10 |
| Imagery fidelity | 5 |
| Anti-caricature | 5 |
| Generalization | 5 |
| **Total** | **100** |

**评分方法**：逐项按权重给分。每项得分必须有对应的测试证据；不能用总体印象替代分项评分。`Generalization` 综合未知题材测试、风格消融测试和对照测试中体现的机制迁移能力。

**等级**：
- **A** = 85-100
- **B** = 70-84
- **C** = 55-69
- **D** < 55

**发布门槛**：总分低于 70 不发布。C 或 D 级必须标注薄弱项并回到对应 Phase 迭代；达到 B 或 A 级后，仍需通过诚实边界与来源检查。

验证通过 → 交付。不通过 → 标注薄弱环节，回到对应 Phase 迭代。
**迭代上限**：Phase 2→4最多循环2次。如果仍有不通过项，在诚实边界中标注，交付当前最优版本。

**🔴 CHECKPOINT · 展示验证结果给用户确认后才算完成。**

### Phase 5: 使用体验优化（标准后置工序）

Phase 4验证通过后，自动启动双Agent优化，提升Skill的易用性：

**并行启动两个Agent：**

**Agent A：Literary Fidelity Critic（文学忠实度批评者）**

核心问题：**“这是真的吗？”**

- 检查 `Writing Models` 是否来自真实文本证据，而不是通用写作常识
- 检查 `Narrative DNA` 是否过度概括，是否掩盖作品之间的差异
- 检查语言特征是否有原文样本、统计结果或可靠的一手证据支持
- 检查是否把体裁特征误当成作者特征
- 检查是否把译者的词汇、句法和节奏误当成作者特征
- 检查是否存在刻板化、标签化或把作者简化成几个形容词的倾向
- 标记每个问题对应的证据缺口、误判风险和需要回查的材料
- 输出：`keep / revise / remove` 建议，以及文学忠实度风险报告

**Agent B：Generative Writing Engineer（生成式写作工程师）**

核心问题：**“这能运行吗？”**

- 检查每条规则是否能被 AI 直接执行，而不是停留在文学评论
- 检查每条规则是否有明确的 `trigger`
- 检查每条规则是否有具体的 `operation`
- 检查每条规则是否有可识别的 `failure condition`
- 检查规则是否能用于改稿
- 检查规则是否能用于从零创作
- 用至少一个改稿任务和一个从零创作任务进行试运行
- 输出：规则执行测试结果、缺失字段和需要改写为指令的条目

**两者不得互相替代**：
- Agent A 判断特征是否真实、证据是否充分
- Agent B 判断规则是否可执行、流程是否能产出结果
- A 通过不代表 B 通过；文学描述真实但无法操作时，仍需返工
- B 通过不代表 A 通过；规则运行有效但若来源错误，仍不得纳入作者Skill

**🔴 CHECKPOINT · 主Agent综合两份报告，应用不冲突的改进，展示变更摘要请用户确认。**

精炼标准：改动必须让Skill「激活即执行」，不只是增加内容，而是让使用者拿到Skill后知道如何在写作中应用、碰到什么情况需要灵活调整。

## 品味守则（速查）

遇到判断困难时回看。具体量化标准见 Phase 4 通过标准表格。

| 原则 | 一句话 |
|------|--------|
| 完整作品 > 片段摘取 | 通读一部长篇小说比摘几个精彩段落更揭示作风 |
| 争议作品 > 公认佳作 | 被批评的作品往往比被盛赞的作品更能看出作家的风格特异性 |
| 早期作品 > 晚期作品 | 创作初心和早期摸索往往比成熟阶段更有信息量 |

### ❌ 反模式黑名单（绝不做的事）

| # | 反模式 | 为什么 / 替代做法 |
|---|--------|------------------|
| 1 | 编造作家没写过的句子或技巧 | 引用必须有出处。查不到原文的「他常用」宁可不说 |
| 2 | 把通用写作技巧包装成此作家的「独特发明」 | 通过三重验证（可教学性、高频出现、风格代表性）的手法才能进库 |
| 3 | 只分析作家的成功作品，忽略失败作或争议作 | Agent 4的批评意见是防止过度美化的关键，批评占比不足=分析不全面 |
| 4 | 在语料不足时强行生成分析 | 宁可交付诚实标注局限的小Skill，也不要生成看似完美实则编造的虚假分析 |
| 5 | 用豆瓣长评/知乎文学问答作为主要来源 | 洗稿、个人观点、无法验证。学术论文和权威文学批评杂志优先 |
| 6 | 在小上下文模型上单会话硬跑全流程 | 会在Phase 1-2爆炸。按失败降级表分段续跑 |
| 7 | 不报成本量级直接开跑 | 完整蒸馏是重任务，用户有权先选档位再花token |
| 8 | 分析在世的冷门作家却不标注局限 | 信息可能不全、评价不稳定。明确说明「基于现有公开资料」和「待更新」 |
| 9 | 生成的Skill只有「学习」模式，没有「参考」模式 | 有些用户想要参考（开阔眼界）而非模仿。要同时支持两种使用方式 |
| 10 | 把确认检查点变成交付阻塞 | 检查点是让用户确认方向，不是扣住产出。能给默认值就给默认值 |

## 特殊场景

### 活跃作家 vs 已故作家
- **活跃作家**：注意最新作品的时效性，标注分析时间，建议定期更新
- **已故作家**：作品集稳定，但要注意版本差异（初版vs修订版）和传记可能的偏差

### 系列作家风格 vs 特定时期作品

输入是「蒸馏莫言的80年代创作」而非整个莫言时：

| Phase | 全作品分析 | 特定时期分析 |
|-------|----------|------------|
| 0A | 确认作家+聚焦维度（可选） | 确认时间范围+这段时期的社会背景 |
| 0.5 | `[author]-writer/` | `[author]-[period]-writer/`，目录结构同 |
| 1 | 6个Agent分析全作品集 | 只分析该时期的作品 + 该时期创作论述 + 跨时期对比（这时期 vs 其他时期的差异） |
| 2.1 | 萃取贯穿全生涯的核心技巧 | 萃取**该时期的主要特征** + **与其他时期的对比** |
| 2.2 | 总体叙述风格 | 该时期的特有叙述方式 |
| 4 | 用全作品库测试 | 用该时期作品库测试，问「这个分析是否只对这个时期成立」 |

### 中文作家 vs 英文作家
- **中文作家**：优先用豆瓣书评、学术论文、权威文学杂志、作家自己的创作谈。互联网平台上搜索时只看知乎文学问答、不看豆瓣短评和微博碎片
- **英文作家**：Goodreads书评、学术期刊、NPR等权威媒体书评、作者官网或采访

### 冷门作家（公开信息极少）
当Phase 0.5评估后发现一二手资料总共<5部作品时：
1. 在Phase 0.5就告知用户「这个作家的文献资料有限，生成的Skill范围会很小」
2. 核心技巧库减至2-3个，每个都标注「基于现有作品推测」
3. 诚实边界section加大篇幅，明确列出「只能分析的范围」
4. 如果用户能提供更多作品（未出版手稿、小众出版社的著作等），优先使用

### 蒸馏用户自己（个人写作风格Skill）
当用户说「蒸馏我的写作风格」「帮我做一个我的Writer Skill」时：
1. 女娲无法从公开渠道搜到用户的文本，需要用户提供作品
2. 引导用户提供：个人博客文章、出版著作、创意写作作品、甚至社交媒体长文
3. Phase 1的6个Agent改为分析用户提供的素材，而非网络搜索
4. 特别注意「自我认知偏差」——用户可能过度高估某些特征（「我的风格很简洁」但实际啰嗦）、忽略习惯性用词等。可以建议用户让朋友审阅

### 翻译文学作品的风格分析
当蒸馏对象的作品主要以翻译版本存在时（如《百年孤独》《挪威的森林》）：
1. 明确说明「分析的是[译者名]版本的汉语表达」，而不是原作者的创意
2. 可对比多个版本的翻译，分析「这个表达在原文中的样子」
3. 在诚实边界中标注「翻译文学的Skill有局限性，学到的是翻译风格而非作者原风格」
4. 如果可能，对比原文和译文来识别翻译选择

## 最后

女娲蒸馏的不是人，是方法。

一个好的Writer Skill，不是让你变成另一个作家，而是让你学会一套可操作的写作系统。拆解他人的文笔，来拓展自己的表达边界——你最终写出来的，还是你自己的声音。

## 版本自检（静默）

本节给 AI agent：每次使用本 skill 前，先做一个不联网的判断——读本 skill 目录（SKILL.md 所在目录）下的 `.last-update-check` 文件（内容为一行日期 YYYY-MM-DD）。文件存在且距今不足 30 天，跳过本节直接干活，不向用户提任何更新相关的话。

到期或文件不存在时，且仅在此时：

1. 本目录不是 git 克隆（无 `.git` 或无 origin）→ 写入今天日期后跳过本节
2. 对比版本：`git -C <本目录> rev-parse HEAD` 与 `git -C <本目录> ls-remote origin HEAD`
3. 无论结果如何，把今天日期写入 `.last-update-check`
4. 两者一致 → 什么都不说；确认落后 → 先完成用户当前任务，结束后附一句「本 Skill 有新版本，可用 `git -C <本目录> pull --ff-only` 更新」。是否更新由用户决定，不要主动执行更新
