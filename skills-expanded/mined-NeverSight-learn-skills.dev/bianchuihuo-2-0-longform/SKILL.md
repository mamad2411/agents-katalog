# 边淬火 2.0 长文创作

这个 skill 用来写边淬火 2.0 长文。2.0 的核心不是解释知识，而是把读者从“我在准备”推到“我必须进入市场反馈”。

2.0 主题包括 AI、商业、赚钱、创业、内容变现、一人事业、产品假设、市场反馈、流量、社群、咨询、工具与价值创造。1.0 的内在游戏材料可以作为证据或镜子进入正文，但不能抢走商业主轴。

## 硬规则

1. 不凭记忆写。涉及对标、选题库、原文、节点时，必须先读取本地文件。
2. 不把内容写成“解释问题”。内容要让读者感觉旧问题开始松动，并愿意把真实问题交出来。
3. 不把产品当成前置答案。产品未定期，内容服务的是付费问题假设。
4. 不把 AI 写成独立风口。AI 只能放在市场反馈、价值创造、用户服务或商业能力放大的关系里。
5. 不使用排比和同义句式并列制造气势。
6. 不写独立金句。每一句都要服务一个行为、机制、案例或反馈链。
7. 必须逐步经过用户确认。读库、展开节点、定钉子、装配逻辑链、写初稿、审查修改是连续流程，但关键判断不能自动越过用户。每一步先给出高密度中间结果，等用户确认、修正或否决后再进入下一步。

## 反排比禁令

写作和修改时主动扫描这些坏味道：

- 连续使用同一句式开头。
- 连续使用“不是 X，而是 Y”。
- 连续列出三个同义判断。
- 用“让 A、让 B、让 C”收尾。
- 用“没有 A、没有 B、没有 C”制造压迫感。
- 用抽象词堆叠代替具体行为，例如只说“认知、能量、系统、内核、底层逻辑”。
- 用漂亮短句跳过因果，例如“市场会教育你。反馈会伤你。命运会筛选你。”

允许使用清单，但清单必须承担结构功能：节点汇总、操作步骤、审查项、证据表。正文里尽量用因果句、场景句、动作句推进。

## 工作流

### 1. 读取入口材料

优先读取用户给出的选题文件。若用户只说“下一条 2.0”，先在当前工作区或用户指定的内容库中寻找：

- `10-选题库/01-待发布`
- `10-选题库/02-已发布`

如果无法发现内容库，只问用户要一个内容库或选题文件路径；不要猜测某台电脑的固定目录。

选题文件中若引用外部对标节点，继续读取对应文件：

- `内容对标库/01-原始素材区`
- `内容对标库/02-内容单元区`

不要只读话题单元。至少追到原始素材、观点单元、问题单元、欲望单元、方法单元。开头单元和案例单元按需要读取。

### 2. 展开周围节点

用 `rg` 搜索 source_id、标题关键词、核心概念和作者名，拉出三层材料：

1. 主节点：当前选题直接引用的原文、话题、观点、方法。
2. 同源节点：同一个 source_id 拆出的 QST、OPI、DES、MTD、HOK、CAS。
3. 邻近节点：主题相近但不同来源的节点，用来补反证、操作步骤、个人材料。

节点不求多，要求能进入逻辑链。每个节点必须标注它在文章里的功能：入口、反证、机制、案例、操作、收尾。

### 3. 钉子审查

写之前先钉这四个判断：

- 钉子：这篇文章唯一要打穿的判断。
- 旧信念：读者现在相信什么，所以会卡住。
- 行为证据：这个旧信念在现实中表现成什么动作。
- 付费问题假设：这篇内容想验证哪类人是否愿意为哪类问题付费。

没有付费问题假设，就不要直接写 2.0 长文。先把选题降级成研究或聊天。

### 4. 装配逻辑链

默认使用这条楼梯，按材料调整，但不能变成并列观点：

1. 读者以为自己在创业、学习 AI、做 IP 或准备产品。
2. 行为暴露真实目标：他更想保留“还没有失败”的身份。
3. 这种身份保护会把人困在准备区：搭系统、问建议、看对标、改工具、想产品。
4. 商业从反馈开始：内容、咨询、社群、轻产品都只是让价值假设接触现实的方式。
5. 市场会校正产品：谁靠近、谁提问、谁付费、谁沉默，比脑内分析更可靠。
6. AI 只能放大这套反馈系统；如果没有接触市场，AI 会放大准备区。
7. 落到一个当天可执行的动作：发一条验证付费问题假设的内容，或和一个真实用户对话。

每一层都要比上一层更具体或更深。调换顺序仍然成立时，说明逻辑链失败。

### 5. 正文写作

默认写 2000-4000 中文字，除非用户指定长度。正文可以无小标题；如果需要小标题，只用来改变阅读节奏，不用来讲道理。

开头前 100 字必须完成一次信念破坏。不要铺垫时代背景，不要先解释概念。

个人经历占 15-25%。经历只做三件事：证明你也掉进去过、展示代价、把外部观点变成边淬火自己的东西。

外部理论只取一刀。不要解释完整理论体系。

行动段要短，不做万能教程。2.0 长文的目的不是把问题一次解决，而是把读者推进一个可反馈的下一步。

### 6. 完稿审查

交付前做一轮内审：

- 前 100 字是否杀掉旧信念。
- 是否只有一个钉子。
- 是否出现 3 次以上同义句式并列。
- 是否出现连续排比。
- 是否有一句话只是好听但不承担推进功能。
- 是否写清楚行为如何暴露真实目标。
- 是否写清楚市场反馈如何进入。
- 是否写清楚内容和产品的关系。
- 是否写清楚 AI 在反馈系统中的位置。
- 是否能让读者读完想问自己的问题，而不是只觉得作者聪明。

发现排比或空泛金句时，优先改成具体动作、现实代价、用户反馈或个人案例。

## 常用本地节点

需要时优先在用户指定的内容库或当前工作区搜索这些相对目录，不要假设它们一定存在：

- `内容管理库`
- `内容对标库`
- `内容管理库/02-内容单元库/案例单元`
- `内容管理库/03-欲望库/欲望单元`

2.0 常用关键词：`AI`、`商业`、`赚钱`、`创业`、`产品假设`、`市场反馈`、`一人事业`、`内容变现`、`咨询`、`社群`、`客户`、`价值创造`、`工具`。

## 输出方式

用户要求“写出来”时，直接给完整初稿。用户要求“看逻辑链”时，只给节点、钉子和楼梯。用户要求“入库”或“保存”时，再落盘到指定位置；不要为了流程感强行产出文件。

即使用户要求“写出来”，也不能跳过确认。先完成节点展开和钉子/楼梯设计，等待用户确认；确认后再写完整初稿。

逐步确认点：

1. 节点展开确认：展示主节点、周围节点和各自功能，等用户确认是否够用。
2. 钉子确认：展示钉子、旧信念、行为证据、付费问题假设，等用户确认。
3. 楼梯确认：展示递进逻辑链，等用户确认是否成立。
4. 初稿确认：写完整初稿后，让用户改口径、材料、语气。
5. 审查确认：执行反排比和 2.0 质量审查，给修改建议，等用户决定是否改 v2。
