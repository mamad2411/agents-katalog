# 灵感需求澄清

## 目标

在进入选题策划或内容生成前，把用户的灵感输入整理成一份简洁的需求文档。需求文档必须保留用户提供的参考来源，并澄清必需的核心诉求：目标用户群体、使用场景、要制作的内容或成果。

## 工作流

1. 收集用户输入来源：
   - 一句话灵感：提取已明确的目标用户、场景、商品、内容成果和约束。
   - 参考图片：先识别图片中可见内容，只描述可观察事实，再询问用户希望基于这些图片做什么。
   - 小红书链接：需要读取或搜索帖子时，使用 `agent-reach` 的小红书路径；保留用户提供的原始链接作为参考帖子。
2. 追踪 `核心诉求` 的必需信息：
   - `目标用户群体`：内容面向谁。
   - `场景`：用户在什么时间、地点、动机或消费情境下阅读/使用。
   - `要做什么`：要产出的内容或成果。
3. 只追问缺失且关键的信息。一次问一个紧凑问题，不重复询问用户已经回答过的信息。
4. 区分参考素材和用户意图：
   - 图片可以启发风格、主体、食材、构图或氛围，但图片本身不等于用户目标。
   - 小红书帖子默认是参考来源，除非用户明确要求模仿或改编其中某个元素。
   - 如果用户说“没有，自己搜索”且没有提供或选择具体链接，本需求文档中写 `参考帖子：无。`；后续素材搜索可由下游流程处理。
5. 写入前，简短确认对需求的理解；如果必需信息已经非常明确且风险低，可以直接写入。
6. 将 md 需求文档写入用户指定路径；如用户未指定，默认写入 `briefs/YYYY-MM-DD-<短标题>.md`。
7. 条件允许时，使用 `scripts/validate_brief.py` 校验生成的需求文档。

## 输出契约

最终写入前阅读 `references/brief-contract.md`。生成文档时使用 `assets/requirement-brief-template.md` 作为模板。

最终 md 文档只包含以下顶层字段：

- `核心诉求`：必需。写成一句完整的话，必须包含目标用户群体、场景、要制作的内容或成果。
- `参考帖子`：可选。只记录用户提供或明确选择的小红书链接；没有则写 `无。`
- `参考图片`：可选。按用户提供顺序记录为 `【图片1】`、`【图片2】`；没有则写 `无。`

不要在最终文档中加入未经确认的假设、隐藏分析过程或额外顶层字段。

在 scripts/ 下新建内容需求文件夹，命名规范：sns-<序号> (序号顺序递增，如1、2、3)。生成的md文档统一命名为 content-spec.md，并存放在该文件夹下。用户提供的参考图片，也一并存储在该文件夹下。

## 澄清策略

用自然对话澄清，不要把用户拖进表单。用户只发图片时，先说明你看到了什么，再问他希望基于这些图片做什么。用户只给一句话但缺少目标用户或场景时，只有在文本中明确表达时才可提取；否则需要追问。

针对黑松露酱内容，常见下游成果包括小红书食谱笔记、食材科普笔记、封面方向和文案草稿。用户未明确成果类型时仍需追问。
