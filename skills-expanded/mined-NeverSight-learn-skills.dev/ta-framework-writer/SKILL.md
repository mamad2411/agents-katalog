# TA 理论框架章节写作

将理论框架转化为可直接放入论文的章节文字。
根据理论定位（A/B/C）生成不同形态的输出——位置不同、篇幅不同、承担的论证工作不同。

## 入口选择

启动时询问研究者：

> **你是否已完成 `ta-framework-builder` 的框架建构？**
>
> **入口 A（已有框架文档）**：请提供 `framework_[研究主题].md` 的路径，或直接粘贴内容，
> 我将直接进入章节写作。
>
> **入口 B（尚未建构框架）**：我将先快速引导你确认框架要素（约5分钟），再进入写作。

### 入口 B 快速确认流程（精简版，不替代 ta-framework-builder）

⚠️ **如果在 `ta-research-AFP` 工作流中调用**：理论定位（A/B/C）已在检查点 2 锁定，入口 B **不得重新询问或修改理论定位**。若框架文档丢失，应请研究者重新提供 `framework_[研究主题].md`，而非重新建构框架。

仅在**独立使用**时收集以下最小信息：
1. 理论定位（A/B/C）
2. 选定的主理论（+ 辅助理论，如有）及选择理由（1–2句）
3. 3–5个核心概念及其操作化定义
4. 概念间关系的简要说明

---

## 根据理论定位生成对应章节

### A 型：独立理论框架章节（理论驱动）

**章节位置**：在研究方法章节之前，文献综述之后
**篇幅参考**：1500–2500字（C刊）/ 2000–4000字（SSCI）

**章节结构**：

```
一、[主理论名称]：核心命题与解释机制
  - 理论的核心关注是什么
  - 解释机制：通过什么逻辑解释现象（不只是"该理论认为……"）
  - 理论的内部张力与局限（诚实呈现）

二、理论选择的依据
  - 为什么这个理论适合本研究
  - （如有辅助理论）两个理论如何分工与整合

三、核心概念界定
  - 逐一界定每个核心概念
  - 每个概念：来源定义 → 本研究的操作化含义 → 与其他概念的关系

四、理论框架对本研究的指导意义
  - 框架如何指导编码与主题命名
  - 在发现章节中，哪些主题预期与哪些理论概念对话
```

**写作要求**：
- 理论介绍不是教科书式的"理论综述"，而是论证"为什么这个理论能解释我的研究问题"
- 必须呈现理论的解释机制（causal mechanism），不能只堆砌理论观点
- 核心概念界定必须回到原著，不能只引二手解读
- 如果文献引用不确定真实性，必须标注"此引用需研究者自行核实"

---

### B 型：理论取向简述（经验驱动，嵌入方法章节）

**章节位置**：在研究方法/方法论章节内，作为分析取向说明的一部分
**篇幅参考**：300–500字

**内容**：
1. 说明本研究采用经验驱动的归纳取向，理论是在主题涌现后才引入的
2. 交代进入分析时的理论"留白"——研究者如何保持对数据的开放性
3. 说明理论将在讨论章节中被召唤：届时用于解释和理解涌现的主题

**写作要求**：
- 语气要诚实——不要假装"完全没有理论预设"（任何研究都不可能），而是说明理论在分析中的角色是"事后解释"而非"事先框定"
- 为讨论章节预留空间：此处不展开理论，只说明立场

---

### C 型：理论取向说明（敏感性概念，嵌入方法章节）

**章节位置**：在研究方法/方法论章节内，数据收集和分析方法说明之前
**篇幅参考**：600–1000字

**内容**：
1. 说明本研究以[理论]为分析透镜，而非预设框架
2. 点明 2–3 个作为"敏感性概念"的核心概念：
   - 每个概念的来源与基本含义（简短，不展开）
   - 它如何帮助研究者"看到"资料中的某些维度
   - 明确声明：这些概念是进入分析的透镜，不预设分析结论
3. 说明理论将在讨论章节中深化：届时将发现与这些理论概念进行更充分的对话

**写作要求**：
- 区分"透镜"（sensitizing concept）和"框架"（theoretical framework）的差异，用语要准确
- 不要在方法章节里展开全面的理论论证，那是讨论章节的工作
- 保留分析的开放性：读者应能感受到研究者在进入资料时并没有把结论框死

---

## 写作过程中的质量检验

写完后，自动对输出做以下检查，并将结果告知研究者：

1. **贴标签检验**：是否只是提到了理论名称然后直接套用结论？（如有，指出哪个段落需要深化）
2. **机制检验**：是否说明了理论的解释机制，而不只是理论的结论？
3. **引用真实性**：涉及的文献引用是否有把握？标注存疑引用。
4. **A/B/C 一致性**：章节的形态和位置说明是否与选定的理论定位一致？

## 输出与保存

写作完成后，调用 Write 工具保存：

文件命名：`framework_section_[A/B/C].md`
保存路径：当前项目目录

告知研究者：
> "理论框架章节已保存至 `framework_section_[A/B/C].md`。
> 根据你的理论定位（[A/B/C]），这部分内容应放在论文的[对应位置]。
> 如在 ta-research-workflow 中，请继续下一检查点。"
