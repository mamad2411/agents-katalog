# asset-reference

## 开始

- 确认任务确实需要跨输出或跨会话的一致性。
- 只提取下游生成必须保留的身份性资产和特征。
- 在当前对话中整理稳定的参考名称、来源和锁定特征。

## 提取对象

### 角色

纳入会反复出现或承担重要功能的角色。锁定身份、面部、身体比例、发型、基础服装和辨识特征。只为年龄、重大受伤、伪装或明显不同的服装系统等可复用的大变化创建变体。不要为姿态、表情、临时污渍或一次性动作创建变体。

### 产品

纳入被推广的产品、重要 SKU、包装版本和身份必须稳定的产品部件。锁定轮廓、比例、颜色、材质、表面处理、Logo、标签、印刷位置、部件和包装内容。

### 道具

只有道具会重复出现、推动动作或揭示，或具有不能安全变化的独特外观时才纳入。不要因为普通杯子、门把手、家具、文具或背景装饰出现过就提取它们。

### 场景

纳入承载重要动作、连续性或品牌呈现的地点。只有空间功能、稳定布局、天气状态或制作用途实质改变时，才拆分场景变体。

### 声音与品牌

只有声音身份、既有 Logo、字体资产或其他品牌元素会控制后续输出时才纳入。

## 身份深描

提取不是罗列名词，而是写出后续生成必须能复用的最小身份描述：

- 角色：年龄感、脸型与五官关系、发型、体态、基础服装、可识别小物和不能变化的特征；
- 产品：正反轮廓、比例、材质、颜色、关键部件、标签文字与包装关系；
- 道具：形态、尺寸关系、磨损或材质状态，以及它在动作中的归属；
- 场景：空间结构、入口与主要物件位置、时间/天气、光线方向和不可替代的氛围；
- 品牌：精确名称、Logo 版本、字体或色彩资产的来源角色。

描述只写能够控制一致性的特征。不要把一次性表情、镜头角度、临时摆放或普通背景噪声误写成身份。

## 来源角色

对每个资产记录它是用户提供、已生成、描述得到还是已解析。保留精确的用户标签和来源标识。普通上传图片不会自动成为规范身份参考；其角色必须明确。

## 变化边界

区分 `locked_traits` 和 `allowed_variations`。只锁定定义身份的特征。姿态、表情、动作、镜头、裁切、光线、环境或临时状态在不改变身份时，可以按计划变化。

需要变体时，先说明变体解决的连续性问题，再定义哪些特征继承、哪些特征改变。服装变体不等于新角色，手持道具不等于新产品，天气变化也不自动等于新场景。

## 权利边界

不要让仅用于 Prompt 的虚构资产等待权利确认。真实外部使用用户或第三方媒体前，确认预期用途和可用权利；文件存在本身不代表拥有法律许可。

## 输出

返回按角色、产品、道具、场景、声音和品牌分组的简短可读清单。空分组直接省略。

每个下游 Prompt 都保持相同的参考名称、来源角色和锁定特征，不得改名或凭记忆重建资产。

对每个资产同时说明“锁定什么、可以变什么、后续在哪里引用”。这让参考清单成为制作约束，而不是装饰性的设定表。

## 检查

- 每个被提取的资产都确实需要一致性。
- 普通环境细节没有被升级成资产。
- 身份锁定项和允许变化清楚分开。
- 精确来源标签和产品文字保持不变。
- 除非真实外部媒体使用需要，否则权利确认延后。
- 每个资产描述都足以帮助后续辨认同一主体，也没有把可变信息误锁死。
