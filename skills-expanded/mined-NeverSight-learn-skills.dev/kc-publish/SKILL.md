# 서비스 공개하기

사용자가 배포나 공개를 명시적으로 요청했을 때만 실행한다. 계정, 프로젝트, 비용 또는 공개 범위가 불명확해 결과가 달라질 때만 추가로 확인한다.

프로젝트 지침에서 외부 클라우드나 회사 밖 공개 URL이 제한되었거나 허용 여부가 불명확하면 배포하지 않는다. 네트워크 접속 성공을 승인으로 간주하지 말고, 로컬 확인 결과와 승인이 필요한 항목을 보고한다.

## 진행

1. 미리보기 확인용 배포인지 실제 운영 공개인지 구분한다.
2. 기존 배포 설정과 공급자를 우선하고 특정 서비스를 기본값으로 가정하지 않는다. 정확한 계정·팀·프로젝트와 배포 대상을 확인한다.
3. 미리보기는 빌드와 식별 가능한 핵심 화면을, 운영 공개는 관련 핵심 흐름과 중요한 데이터·권한 위험을 확인한다.
4. 변경 파일과 배포 설정에 비밀값, 환경 파일, 도구 캐시, 샘플 자격증명과 실제 개인정보가 없는지 확인한다.
5. 배포할 소스 상태를 정확히 식별하고 미커밋 변경이나 관련 없는 파일이 포함되는지 확인한다.
6. 환경변수는 이름과 대상 환경을 확인하고, 값은 노출되지 않는 공식 UI나 안전한 도구를 사용한다.
7. 배포를 실행하고 완료 결과를 기다린다.
8. 공개 URL에서 이번 배포 목적과 관련된 접근 및 핵심 행동을 확인한다. 직접 경로, API, 비로그인 또는 모바일 검증은 서비스에 해당할 때 수행한다.
9. 운영 공개에는 현재 소스 지점과 마지막 정상 배포 등 가능한 롤백 지점을 기록한다. 외부 데이터와 서비스 상태는 코드 배포와 별도 복구 대상임을 표시한다.

배포 실패 시 기능을 임의로 추가하지 않는다. 실패 증거와 현재 안전 상태를 보존한다.

## 완료

배포 유형, 상태, 공개 URL, 확인한 행동, 소스 지점, 실패 시 필요한 후속 조치와 남은 위험을 보고한다.
