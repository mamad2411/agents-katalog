# 数据开发任务路由

面向金融投研数据开发与治理；对非投研数据请求，同样适用责任分类，只是缺少对应执行 skill 时会如实说明。

## MUST

1. 只路由，不连接数据源、不执行查询、不生成业务交付物。router 自身不执行；当主责任落到某个执行 skill 时，**由该 skill 承接执行**，router 不再介入。
2. 只选择当前仓库真实提供的 skill；未安装的能力必须明确说明不可用。
3. 一次选择一个主责任。跨领域任务先确认当前要交付的结果，再处理后续责任。

## 用户话术 → 责任（先说人话，再定责任）

| 用户可能怎么说 | 主责任 | 落到 |
|---|---|---|
| "帮我建一张 XX 表 / 设计表结构 / 写 DDL / 定义 schema / 怎么建表" | 数据契约 / DDL | finance-ddl-design |
| "帮我做 XX 数据的增量同步 / 管道 / 每天怎么导入 / 回补历史 / 任务很慢 / 丢数据 / 重复" | 管道开发 | finance-pipeline-dev |
| "帮我设计一个查询 XX 数据的接口 / MCP tool / 视图 / API" | 查询接口 | finance-query-contract |
| "这些数据对不对 / 帮我质检(验收)一下 XX 表 / 出质检报告 / 市值离谱 / 缺数据 / 财报没更新 / 对不上" | 质量验收 | finance-data-qc |
| "数据契约 / 治理 / 血缘 / 责任人 / SLA / 合规 / 脱敏 / 导出" | 治理或合规 | 暂未提供执行 skill |

## 责任分类

- **数据契约 / DDL**：schema、主键、类型、命名、分区和兼容性设计。
  - 投研研究库的建表/改表与 DDL 设计 → **finance-ddl-design**，由它承接执行。
  - 其他数据集 → 当前尚未提供专用执行 skill。
- **管道开发**：增量、幂等、回补、重跑和故障恢复。
  - 投研研究库的管道设计/排障 → **finance-pipeline-dev**，由它承接执行。
  - 其他数据集 → 当前尚未提供专用执行 skill。
- **质量验收**：证明数据是否满足可追溯规则。
  - 金融投研研究库（行情、财务、公告事件、主数据、指数基金、宏观行业）→ **finance-data-qc**，由它承接执行。
  - 其他数据集 → 当前尚未提供专用执行 skill。
- **查询接口**：视图/API 查询契约、过滤分页、时态和性能预算。
  - 投研研究库的查询接口设计/排障 → **finance-query-contract**，由它承接执行。
  - 其他数据集 → 当前尚未提供专用执行 skill。
- **数据治理**：目录、血缘、责任人、SLA 和生命周期。当前尚未提供执行 skill。
- **合规**：分类、最小权限、脱敏、导出、保留和审计。当前尚未提供执行 skill。

## 路由步骤

0. 先看"用户话术 → 责任"表，用交付物判断主责任，不按数据库或工具名称分类；拿不准先列候选责任。
1. 若主责任是投研研究库的建表/DDL 设计，读取并执行 **finance-ddl-design**。
2. 若主责任是投研研究库的管道设计/排障，读取并执行 **finance-pipeline-dev**。
3. 若主责任是投研研究库的查询接口设计/排障，读取并执行 **finance-query-contract**。
4. 若主责任是金融投研质量验收，读取并执行 **finance-data-qc**。
5. 若目标 skill 未安装，说明缺少的能力；不要用相邻 skill 冒充。
6. 若一个请求包含多个责任，只询问一个会改变主责任的聚焦问题。

## STOP

- 无法判断用户要的是“设计、开发、验收、服务、治理还是合规结论”。
- 目标能力尚未提供。
- 需要通过连接数据库才能完成路由判断。
