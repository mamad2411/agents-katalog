# Coco TDD

## 不可跳过的循环

1. **RED**：先写描述期望行为的最小测试。
2. 运行测试，确认它因目标行为尚未实现而失败，不是因为语法、环境或断言错误。
3. **GREEN**：编写使该测试通过的最小生产代码。
4. 运行测试，确认新测试和相关测试通过且输出干净。
5. **REFACTOR**：在测试保护下整理结构，不改变行为。
6. 再运行聚焦测试和受影响回归。

缺陷修复的 RED 必须尽可能复现原始问题。已有代码没有测试时，先建立当前行为的特征测试，再增加期望行为测试。

## 例外

纯文档、不可执行配置说明或探索性原型不强制 TDD。无法自动化的硬件/视觉行为必须先定义可重复的人工或运行时验证步骤，并说明自动化缺口。未经用户明确批准，不得以“稍后补测试”跳过循环。

## 测试质量

- 测试外部可观察行为，不绑定无关实现细节。
- 只有边界不可控时才 Mock，并说明原因。
- 覆盖与本次风险相称的正常、边界、错误、权限和并发场景。
- 不写始终通过、只断言 Stub 或复制实现逻辑的测试。
- 覆盖率是信号，不是完成证明；项目已有门槛优先。

记录 RED 和 GREEN 使用的命令及关键结果，供 `verification.md` 引用。

## 输出规范

只输出完成任务所需的核心内容；删除客套话、长篇铺垫、重复信息和无关说明。代码、文档和注释保持最小必要范围，不添加冗余注释。需要报告时优先给出结论、变更、验证结果和阻塞项。
