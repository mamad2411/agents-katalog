# 小红书科技风卡片

把内容做成「同一品牌、不同页面角色」的小红书图文。品牌统一来自颜色、字体、编号、留白与语气，不来自重复同一版式。

## 工作流

1. 先读取 `references/content-architecture.md`，判断用户真正要观众相信什么，并保留原文的锋利判断。
2. 读取 `references/page-recipes.md`，为每页分配不同角色和构图。相邻两页不得使用同一种页面骨架；5 页内至少出现 4 种 recipe。
3. 读取 `references/brand-system.md`，执行品牌 token。不要擅自换成蓝紫科技风或归藏默认 Swiss 风。
4. 复制 `assets/template.html` 到任务目录后改内容。帖子成品必须放在当前项目的工作目录，不要写进本 Skill。
5. 使用 `scripts/render_cards.cjs <index.html> [output-dir]` 渲染 PNG。渲染依赖本机已安装的 `guizang-social-card-skill` Playwright，仅复用其渲染能力。
6. 完整执行 `references/qa.md`；打开并目视检查所有 PNG，不能只相信脚本退出码。

## 硬规则

- 默认画布为 `1242 × 1660`，3:4；安全边距左右 80px、上下 100px。
- 主色仅用深黑 `#0D0D0D`、米白 `#F7F7F3`、中性灰 `#A1A1A1`、荧光绿 `#C6FF00`。警示红 `#FF3830` 只表达风险、冲突、错误或否定。
- 默认黑底与米白底交替。单页荧光绿面积原则上不超过 10%；纯荧光绿整页仅可作为罕见节奏页，不可连续出现。
- 中文标题必须厚重、短、有判断。字体栈使用 `"思源黑体", "Source Han Sans SC", "Noto Sans SC", "PingFang SC", sans-serif`；不可依赖远程字体加载。
- 一页只讲一个核心意思。正文尽量小于 90 个汉字；封面主标题尽量 12–26 个汉字。
- 固定组件可以重复：页码、内容标签、细线、箭头、荧光绿强调、页脚品牌。大标题位置、信息图形和内容密度必须随页面角色变化。
- 允许使用高对比黑白商业摄影，但图片只能辅助观点。禁止机器人、发光大脑、赛博城市、蓝紫渐变、代码雨和廉价 3D 科技素材。
- 不把内容写成 AI 工具教程、新闻搬运或泛泛科普。核心链路始终是：事实 → 解释 → 判断 → 商业意义。

## 默认交付

当用户要求“做成小红书”或“开始设计”时，直接完成：

1. 5–8 页页面文案与 recipe 分配；
2. 可编辑 HTML；
3. `1242 × 1660` PNG 全套；
4. 简短发布标题与正文；
5. 视觉 QA 结果。

如果用户只要求文案，不主动渲染图片。
