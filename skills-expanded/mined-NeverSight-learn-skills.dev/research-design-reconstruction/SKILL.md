# 研究设计逆向重建

## 目标与方法

把已经完成的研究当作留下痕迹的成品，而不是作者决策过程的完整录像。沿着以下路径工作：

`成品 -> 可观察证据 -> 决策与约束重建 -> 不确定性 -> 紧凑蓝图`

目标是解释各项研究选择如何相互依赖，并产出可检查、可迁移的研究设计蓝图。默认忠实重建原作，不把结果摘要当作核心，也不把自己的改良方案混入作者的设计。

## 先形成条件式逆向简报

开始前，用现有信息简要确定四件事：

- **对象**：单篇实证或概念/理论研究，以及正文、附录、补充材料和事前材料的可用范围。
- **用途**：理解原作、训练研究判断、支持复现，还是生成回溯式 PAP 形态蓝图。用途决定压缩程度，不改变证据标准。
- **证据边界**：哪些来源可见，是否存在可核验日期，来源之间是否冲突，哪些内容只能推断。
- **输出类型**：默认交付一个 Markdown；仅在长文、多源、冲突密集或高风险任务中，另拆 evidence map。

信息不足时采用保守默认，并在简报中写明条件。只有歧义会实质改变研究对象、证据边界或交付性质时，才暂停并询问用户；其余歧义边做边标记。

若用户只需要普通的结论或结果摘要，不启动完整逆向流程。

## 坚守证据与时间边界

对关键决策使用四种状态，而不为每个字段制造审计表：

- **明示**：来源直接陈述该内容。
- **推断**：证据支持的最佳解释，但来源没有直接确认。
- **未知**：现有材料无法识别。
- **冲突**：不同位置或来源给出不相容信息，保留冲突而不强行调和。

把状态和 source location 放进它所支撑的关键决策项，例如章节、页码、表格、附录、来源名称或日期。位置应足以让读者返回核查；找不到准确位置时不要伪造精度。普通背景叙述无需逐句加标签。

内容证据与时间证据是两回事。论文说“我们假设”可以明示一项假设，却不能仅凭这句话证明它形成于结果之前；日期本身也不足以证明事前性。只有注册、协议、计划、版本记录或同等证据能够证明相关研究决定在相关结果、结局数据或分析输出暴露之前已经固定，才可称为“事前计划”或真正的 PAP。否则将交付明确命名为“回溯式研究决策重建”或“回溯式 PAP 形态蓝图”。

不得声称恢复了不可识别的真实动机、决策时点或弃选方案，也不得把结果出现后的解释或假设冒充事前设计。证据缺失表示未知，不表示某项决策从未发生。

## 默认采用两遍法

先判断结果和讨论是否已经进入当前上下文。独立性取决于信息暴露，而不是 Agent 是否声称暂时忽略已经看见的内容。

- **A：结果尚未暴露。** 只读取引言、理论、方法、数据说明、附录中的设计信息和事前材料；固定设计重建后，才读取结果和讨论。这时才可称为独立的第一遍。
- **B：结果已经暴露。** 认知上的“屏蔽”不能恢复独立性，不得把后续重建称为独立第一遍。若高风险审查、专门训练或用户要求确实需要未受结果污染的重建，交给只获得设计材料、没有结果内容或结果摘要的新上下文/新 Agent 重做并固定。不要把隔离重做设为每次必经步骤；若任务不要求这种独立性，则继续工作，但在逆向简报和标题中明确标为“存在结果污染的回溯重建”，降低可能受结果影响的推断强度，并就近标出污染风险。

### 设计重建

按照适用分支，依据设计材料重建一条具体决策链：

`研究问题与缺口 -> 研究动机 -> 理论机制 -> 假设/命题或预期模式 -> 研究对象 -> 数据/材料 -> 估计对象、识别或方法 -> 分析选择`

这不是固定字段清单。按原作真实逻辑调整顺序、合并节点或省略不适用项，但要说明关键依赖：某个理论承诺如何限定可检验含义，研究对象如何约束数据，目标主张如何要求某种估计对象、识别条件或方法，分析选择又依赖哪些假设和可用信息。

重建时重点回答：

- 作者声称要解决什么问题，为什么这个问题值得研究？
- 哪个机制或论证把问题连接到可观察证据？
- 数据、材料与方法能识别或支持什么主张，不能支持什么？
- 哪些选择由理论、制度、测量、样本、算力、伦理或资料可得性约束？这些约束是明示、可推断，还是未知？

不要因为看见回归、实验、模型或案例就自动补出因果识别；先判断作品的目标是描述、预测、解释、因果估计、测量、规范论证或概念澄清。在 A 分支中，只用不会展示结果的章节级读取维持隔离；若读取过程已经暴露结果，立即转入 B 分支，不能用主观忽略维持独立性声明。

### 第二遍（A）或单列回看（B）：结果与执行

A 分支在固定独立第一遍后才读取结果和讨论。B 分支若采用隔离重做，则以新上下文/新 Agent 已固定的设计重建作为比较基线；若采用污染降级，则承认结果早已暴露，本节只是单列回看，不冒充先后独立的第二遍。记录：

- 主要结果是否对应设计重建所识别出的研究问题与分析；
- 设计实际如何执行，是否出现样本、测量、模型或分析路径的偏离；
- 作者承认的局限，以及结果暴露出的设计边界。

结果与执行回看用于核对实施与偏离，不得倒过来改写 A 分支或隔离重做中已经固定的问题、机制或假设，也不得把事后解释升级为事前理由。污染降级时，明确哪些判断可能受既见结果影响，并相应降低推断强度。结果只需足够支持执行回看，不展开成常规论文摘要。

## 适配不同研究类型

先判断作品类型，再决定哪些节点存在。实证研究可以讨论数据、测量、估计对象、识别条件和分析选择；概念或理论论文则应围绕概念区分、前提、机制、命题、论证步骤与证据角色展开。

不得为概念或理论论文硬造样本、变量、估计量、识别策略或假设。稳定核心标题可以保留，但应直接省略不适用字段，而不是堆放“无”或“未提供”。同样，不要强迫探索性、描述性或质性研究伪装成假设检验研究。

## 默认交付

默认生成一个紧凑 Markdown，由下列稳定核心组成；标题和内部顺序可随研究类型调整：

1. **逆向简报**：对象、用途、证据边界、结果暴露状态、输出选择，以及必要的保守默认。
2. **具体研究决策图**：以原作的具体问题为起点，用节点和箭头呈现问题、机制、主张、对象、证据、方法与分析之间的依赖。将证据状态和 source location 就近附在关键节点或连接上，并把未知与冲突留在它们真正影响的地方。
3. **结果与执行回看**：简短记录结果对应、实际实施、偏离和局限，同时说明采用 A、隔离重做还是污染降级；若用户明确不要结果，可省略并说明结果回看未执行。
4. **迁移摘要**：提炼可迁移的决策规则、依赖关系与边界条件，说明换到新问题时哪些逻辑可以复用、哪些选择必须重新判断。迁移的是研究推理，不是原文结论。

决策图要足够具体，使读者能看出“为什么这一选择跟在上一选择之后”；迁移摘要要足够抽象，使读者能用于训练或设计新研究。避免空泛复述章节顺序，也避免用固定 schema 牺牲不同研究类型的真实结构。

## 建议与扩展

忠实重建是默认任务。只有用户明确要求批评、改良或替代设计时，才在重建之后增加独立的“改良建议”区，并清楚标为分析者建议，不能伪装成作者原有选择。

只有额外 evidence map 能显著降低长文、多源、冲突或高风险判断的误差时才拆分它。该图只服务于关键决策的来源、状态与冲突解析，不扩张成逐句审计，也不引入固定解析器、脚本或领域模板。

## 交付前检查

- 时间证据是否不仅有日期，还能证明相关决定在相关结果、结局数据或分析输出暴露前已经固定？若不能，名称是否保持为“回溯式 PAP 形态蓝图”或“回溯式研究决策重建”？
- 是否先判断结果暴露状态？A 分支是否先固定设计再看结果；B 分支是否避免独立性声明，并按任务需要选择隔离重做或明确的污染降级？
- 结果与执行回看是否对应所选分支，且没有用结果反写已固定设计或抬高受污染推断？
- 关键决策是否有可复核的位置与恰当状态，推断是否被写成了事实？
- 研究类型是否被尊重，是否补造了不适用的经验研究字段？
- 决策依赖是否具体，迁移摘要是否抽象而有边界？
- 是否默认保持忠实，并把用户要求的建议清楚分区？
