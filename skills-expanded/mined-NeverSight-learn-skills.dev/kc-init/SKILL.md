# 새 프로젝트 초기화하기

새 프로젝트에서 한 번만 사용한다. 별도 질문 없이 바로 작업 기반을 준비한다.

## 진행

### 대상 확인

1. 대상 폴더가 새 프로젝트용이며 실질적으로 비어 있는지 확인한다. 운영체제 메타데이터와 빈 Git 저장소는 허용한다.
2. 기존 코드나 프로젝트 설정이 있으면 초기화하지 않고 기존 프로젝트임을 보고한다.
3. 대상 폴더가 불명확하면 정확한 위치만 확인한다.

### 초기화

1. `.gitignore`를 만들고 비밀값, 환경 파일, 의존성, 빌드 결과와 도구 캐시를 제외한다.
2. [AGENTS.md 템플릿](assets/AGENTS.md)을 사용해 비개발 도메인 전문가와 협업할 공통 지침을 만든다. 기술 구성과 실행 명령이 아직 정해지지 않았다면 임의로 선택하지 않고 미정 상태를 기록한다.
3. 사용자가 기술 구성이나 제품 자료를 함께 제공했다면 [프로젝트 환경 원칙](references/environment-policy.md)에 따라 필요한 실행 기반을 구성하고 실제 프로젝트 명령을 AGENTS.md에 반영한다.
4. [CLAUDE.md 템플릿](assets/CLAUDE.md)을 사용해 `AGENTS.md`를 불러온다. Claude Code만의 프로젝트 규칙이 있을 때만 그 아래에 추가한다.
5. Git 저장소가 없으면 초기화하고, 이미 빈 저장소가 있으면 유지한다. 작성자 정보가 없어 최초 저장점을 만들 수 없으면 임의로 설정하지 말고 알려준다.
6. 초기화만을 위해 외부 프로젝트를 생성·연결·업로드·배포하지 않는다.
7. 실행 기반을 구성한 경우에만 설치와 기본 실행 또는 빌드를 확인한다.
8. 생성 파일을 확인하고 가능하면 최초 Git 저장점을 만든다.

## 완료

생성한 프로젝트 지침, Git 상태, 구성한 경우에만 실행 기반과 확인한 명령을 보고한다.
