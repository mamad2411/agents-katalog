# Korean Polish — 2-pass refinement

한국어 답변을 만들 때 다음 3단계를 거친다. 근거: LLM은 입력·출력 언어와 무관하게 내부 reasoning이 영어 표현 공간에 가까워서, 한 번에 쓰면 직역체가 새어 나옴. 명시적으로 단계를 쪼개면 self-critique 정확도가 올라간다 (arXiv 2503.04369: GPT-4 기준 번역투 43% → 25%).

## Step 1 — 초안

사용자 질문에 대한 답을 일단 그대로 쓴다. 이 단계에서 직역체가 새어 나와도 괜찮다. 다음 단계가 잡는다.

## Step 2 — Critique

초안을 다시 읽으며 아래 패턴을 찾는다.

### 치환 패턴

| ❌ 번역투 (영어 원형) | ✅ 자연 한국어 |
|---|---|
| ~을 지배한다 / 좌우한다 (govern, dominate) | ~에 큰 영향을 준다 / ~을 먼저 봐야 한다 |
| ~에 의해 ~된다 (be ... by) | ~이 ~한다 (능동) |
| ~에 있어서 / ~에 대해서 (regarding, in terms of) | ~에서 / ~은 |
| 정합성이 높다 / 가독성이 좋다 (추상명사 주어) | 잘 맞는다 / 읽기 좋다 |
| ~되고 있다 (진행 수동) | ~된다 / ~한다 |
| ~을 가진다 (have) | ~이 있다 |
| ~을 수행한다 (perform) | ~을 한다 |
| 이는 ~을 의미한다 (this means) | 즉 ~이다 / 그러니까 ~ |
| ~에 기여한다 (contribute to) | ~에 도움이 된다 / ~을 만든다 |
| ~을 보장한다 (ensure) | 꼭 ~하게 한다 / ~이 어긋나지 않게 |
| ~을 촉진한다 (facilitate) | ~을 쉽게 만든다 / ~을 돕는다 |
| ~함으로써 (by V-ing) | ~해서 / ~하면 |
| ~로부터 보호받다 (be protected from) | ~을 막다 / ~에 안 걸리다 |
| ~의 증가 / ~의 활용 (추상명사 nominalization) | ~이 늘어남 / ~을 쓰는 것 |
| ~을 가능하게 한다 (make possible) | ~할 수 있게 해준다 / ~을 가능하게 해준다 X → 풀어서 |
| ~을 가져온다 / 초래한다 (bring about, cause) | ~이 생긴다 / ~이 따라온다 |
| ~로 존재한다 (exist as) | ~이다 / ~로 있다 |
| ~을 야기한다 (cause) | ~을 만든다 / ~을 일으킨다 |
| ~를 박다 (informal jam-in) | ~를 넣다 |
| ~이 새어 나오다 (leak, seep) | ~을 쓴다 / ~이 보인다 |
| ~라는 결론입니다 (is the conclusion) | ~인 겁니다 / ~인 거죠 |
| 기본값에 가깝다 (default metaphor) | 원래 그렇다 / 기본 동작이다 |
| 악센트가 남다 (accent metaphor) | 배어있다 |

### 검수 휴리스틱

초안에서 다음을 찾으면 의심하라:

1. **추상명사가 주어인 문장** (`X의 활용은 ...`, `Y의 존재는 ...`, `Z의 증가가 ...`). 영어 SVO를 한국어로 옮길 때 가장 자주 새는 패턴.
2. **영어 단어가 1:1로 매핑돼 나온 곳**. 머릿속에 영어 단어가 먼저 떠올랐는지 자문:
   - govern → 지배
   - ensure → 보장
   - facilitate → 촉진
   - exist → 존재
   - serve → 역할을 한다 (어색 → "~을 한다")
   - contribute → 기여
3. **수동형 연속**. `~된다`, `~받는다`, `~당한다`가 두 번 이상 이어지면 능동으로 바꿀 수 있는지 확인.
4. **명사화 + 가벼운 동사**. `~의 수행`, `~의 처리`, `~의 적용` 같은 명사화는 동사로 풀어쓰는 게 자연스러움.
5. **"이는 ~이다" 패턴**. `This is ...` 직역. 한국어로는 `즉 ~이다`, `그러니까 ~`, 또는 생략.
6. **같은 비유어·은어 반복**. "박다", "새어 나오다", "악센트" 같은 비유어를 한 글에서 3회 이상 쓰면 의심. 평이한 동사로 교체.
7. **explanatory headline 직역**. "왜 X가 Y하는가", "X가 Y한다" 같은 영어 제목 직역은 한국어 블로그에서 어색. 짧은 명사구로 바꾼다 ("원인 분석", "X의 Y" 등).

## Step 3 — 최종

critique에서 잡힌 곳을 고쳐 다시 쓴다.

## 2-pass vs 1-pass — 언제 critique를 거치는가

### 1-pass로 끝내는 경우 (초안 그대로 출력)

- 답변이 1-3 문장 길이.
- 단순 사실 확인, 짧은 안내, 짧은 명령에 대한 응답.
- 코드 블록·표·고유명사가 답변의 대부분.
- 사용자 질문이 "X 있어?", "Y 맞아?", "Z 해줘" 같은 단답형.

### 2-pass로 가는 경우 (초안 → critique → 최종)

- 답변이 2문단 이상.
- 추상적 개념 정리, 의견 표명, 트레이드오프 분석, 비교·평가.
- 사용자가 "왜", "어떻게", "설명해줘", "비교해줘" 같은 explanatory 질문.
- 직역체가 가장 자주 새는 곳이 추상적 설명이라 이 분기에서 critique가 가장 큰 효과를 낸다.

### 애매하면 2-pass

비용보다 자연스러움이 우선.

## 출력 정책 (2-pass에 한함)

- **디폴트: polish 된 최종 답변만 출력.** 초안·critique 는 내부 사고(assistant thinking)로만 수행하고 사용자에게 노출 X.
- "## 초안", "## Critique", "## 최종" 같은 헤더 사용 X. 응답은 자연스러운 한국어 본문 한 덩어리.
- 사용자가 명시적으로 "critique 도 보여줘" 같은 요구를 하면 그 응답에 한해 critique 도 노출.

## 호출 트리거

- 사용자가 한국어로 질문할 때.
- 사용자가 영어로 질문해도 한국어 답변을 요구할 때.
- 한국어와 영어가 섞인 답변에서 **한국어 부분**에만 적용. 코드 블록·고유명사·기술 용어는 그대로 둔다.

## 적용 안 함

- 코드 블록 안 주석/문자열.
- 영어 인용문, 출처 인용.
- 사용자가 만든 한국어 표현을 그대로 인용할 때.
