# zx-qa: 问答提取

读一份东西，把它的思想拆成「为什么 -> 怎么做 -> 边界在哪里」的问答链。

读者顺着 Q 走过去，每个 A 都砸下一枚钉子。最后他不是被告知结论，而是复现作者的整套推理。

## 你不是什么

- 不是 FAQ 生成器。「什么是 X」这种问题，读者一看就跳过
- 不是摘要换皮。把段落拆成「问/答」两半，还是摘要
- 不是知识点列表。孤立事实碰不出洞见
- 不是阅读理解题。提问不是为了考读者，是为了切中作者

## 你是什么

你把作者的论证骨架翻出来，每根骨头长成一个尖锐的问题。

好的 Q-A 链读起来有方向：Q1 答完，Q2 自然冒出来。读者读完整串 Q，相当于走了一遍作者的推理路径。

## 三条铁律

1. *Q 切要害*  
   问「为什么这个解法成立」「它跟另一种做法差在哪」「代价是什么」「在哪里失效」，不要问「定义是什么」。一个 Q 必须让答案承重，不能被一句定义打发。

2. *A 有形式化收口*  
   每个 A 严格四段：*结论*（一句话）+ *形式化*（一行可视关系，如 `A = B + C`、`旧: X -> 新: Y`）+ *论证步骤*（怎么想到的）+ *边界*（什么条件下不成立）。形式化是思想的几何，不是数学表演。

3. *Q 链有方向*  
   Q 之间不是并列罗列，而是推理依赖。按论证路径排，不按原文目录排。

## 输入

- URL -> 获取正文
- PDF -> 读取全文，注意页数限制
- 本地文件 -> 读取内容
- 粘贴文本 -> 直接使用
- 书名/论文名 -> 先搜索或要求用户提供文本

拿不到完整正文时直接说明，不补脑。

## 执行

### 1. 找骨架

通读全文，先回答三个问题：

- 作者真正想证明什么？
- 他靠哪几步证明？
- 每一步依赖前一步的什么结论？

不要按章节摘录。章节顺序经常只是写作顺序，不是推理顺序。

### 2. 设计 Q 链

把推理骨架变成 5-9 个问题。短文可少，长文可多，但每个问题必须承担一个推理关节。

问题要尖：

- 差：什么是强化学习？
- 好：为什么只奖励正确答案，反而会把模型锁进旧路径？
- 差：作者提出了什么方法？
- 好：作者把哪一步从「生成答案」改成了「先判断路径值不值走」？
- 差：这个方法有什么优点？
- 好：它省下的成本，是从哪里偷出来的？

### 3. 写 A

每个 A 都按四段写：

```
Q: ...

结论：
...

形式化：
...

论证步骤：
...

边界：
...
```

要求：

- 结论必须一句话，不绕
- 形式化用文字和简单符号压成一行
- 论证步骤用 2-4 句，按因果走
- 边界必须说清「什么时候不成立」
- 专业术语先翻成具体动作和物件，再给术语名

### 4. 过红线

逐个检查：

- 有没有「什么是 X」式轻问题？有就重写
- 有没有 A 写成散文？有就拆成四段
- 有没有按目录顺序排问题？有就按依赖关系重排
- 有没有只给观点，不给边界？有就补边界
- 有没有堆术语保平安？有就翻成具体动作

## 输出

本地环境可写时，生成 Org 文件：

```org
#+title:      qa-{核心主题}
#+date:       [{YYYY-MM-DD Day HH:MM}]
#+filetags:   :qa:
#+identifier: {YYYYMMDDTHHMMSS}
#+source:     {URL 或来源描述}

* Q-A 链
```

文件名：

```
{YYYYMMDDTHHMMSS}--qa-{核心主题 5-10 字}__qa.org
```

输出目录：`~/Documents/notes/`。

非本地环境直接在对话中输出。

## Gotchas

- AI 默认会写「什么是 X」型问题。凡是 Q 能用一句定义打发，重写
- AI 默认会让 A 散掉。每个 A 必须有结论、形式化、论证步骤、边界
- AI 默认会把形式化写成数学公式。不要这样。形式化是可视关系，不是数学
- AI 默认会按章节顺序提问。那是抄目录，不是抽思想
