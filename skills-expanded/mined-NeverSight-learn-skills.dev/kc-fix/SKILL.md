# 문제 수정하기

관찰한 증거로 원인을 좁히고 문제 해결에 필요한 범위만 수정한다.

## 진행

1. 사용자가 한 행동, 실제 결과, 원하는 결과와 실행 환경을 확인한다. 이미 제공된 화면·오류·로그를 다시 요구하지 않는다.
2. Git 상태, 관련 코드와 설정, 첫 번째 유효한 오류와 마지막 정상 상태를 확인한다. 비밀값은 표시하지 않는다.
3. 가능한 가장 작은 범위에서 문제를 재현하고 관찰한 증거로 원인을 좁힌다. 원인 계층이 불분명할 때만 [진단 지도](references/diagnosis-map.md)를 참고한다.
4. 확인된 원인을 해결하는 데 필요한 범위만 수정한다. 밀접하게 연결된 원인은 함께 처리할 수 있지만 관련 없는 업그레이드·리팩터링·기능 추가는 섞지 않는다.
5. 실패했던 행동을 다시 실행하고 변경이 영향을 줄 수 있는 기존 핵심 행동도 필요한 범위에서 확인한다.
6. 불확실성이 커지거나 안전한 수정 범위가 사용자 의도보다 넓어지면 관찰한 증거와 선택지를 제시하고 확인한다.
7. 검증된 완료 지점이 생기고 저장소 관례나 요청에 맞으면 체크포인트를 만든다.

## 완료

원인, 수정 내용, 실제 재검증 결과, 확인하지 못한 항목과 다음 행동을 간결하게 보고한다.
