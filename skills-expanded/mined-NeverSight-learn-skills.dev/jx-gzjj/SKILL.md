# /jx-gzjj - 生成交接文档

保存当前工作上下文，**验证真实状态后**生成标准化交接文档。

**核心原则**：区分"用户声称"和"实际完成"，避免误导接手者。

---

## 工作流程

### Step 1: 初始化目录

```bash
PROJECT_ROOT=$(git rev-parse --show-toplevel 2>/dev/null || pwd)
HANDOVER_DIR="$PROJECT_ROOT/.jx_skill/handover"
mkdir -p "$HANDOVER_DIR"

# 确保 .gitignore
if [ -f "$PROJECT_ROOT/.gitignore" ]; then
  grep -q "^.jx_skill/" "$PROJECT_ROOT/.gitignore" || echo ".jx_skill/" >> "$PROJECT_ROOT/.gitignore"
else
  echo ".jx_skill/" > "$PROJECT_ROOT/.gitignore"
fi

echo "HANDOVER_DIR=$HANDOVER_DIR"
echo "PROJECT_ROOT=$PROJECT_ROOT"
```

### Step 2: 计算编号

```bash
MAX_X=$(ls "$HANDOVER_DIR"/time_*.md 2>/dev/null | grep -o 'time_[0-9]*' | sed 's/time_//' | sort -n | tail -1)
X=$((MAX_X + 1))
[ -z "$MAX_X" ] && X=1
echo "X=$X"
```

### Step 3: ⭐ 关键步骤 - 状态验证

**在生成交接文档前，必须验证关键状态**。

#### 3.1 从对话中提取关键事项清单

| 事项类型 | 示例 | 验证方法 | AI行动 |
|---------|------|---------|--------|
| 代码文件 | "创建了 server.js" | 检查文件是否存在 | **自动验证** |
| 配置变更 | "改了 package.json" | 检查 git diff | **自动验证** |
| 依赖安装 | "npm install 了" | 检查 node_modules | **自动验证** |
| 数据库操作 | "Supabase SQL 已执行" | 无法自动验证 | **询问用户** |
| 部署状态 | "已部署到 Vercel" | 无法自动验证 | **询问用户** |
| 测试通过 | "本地测试通过" | 查看对话记录 | **交叉验证** |

#### 3.2 自动验证执行

**必须执行的检查**：

```bash
# 1. 检查提及的文件是否存在
echo "=== 文件存在性检查 ==="
# 对对话中提到的每个文件路径，检查 ls -la

# 2. 检查 git 状态
echo "=== Git 状态 ==="
git status --short
git log --oneline -5

# 3. 检查最近提交的文件
echo "=== 最近修改 ==="
git diff --name-only HEAD~1
```

#### 3.3 用户确认事项

**使用 AskUserQuestion 确认无法自动验证的事项**：

```
⚠️ 请确认以下事项的真实状态：

[复选框] Supabase SQL 已执行
[复选框] Vercel 环境变量已配置
[复选框] 线上部署已完成

说明：勾选表示"已完成并验证"，未勾选表示"未完成/待确认"
```

#### 3.4 状态标记规范

| 标记 | 含义 | 使用场景 |
|-----|------|---------|
| ✅ | 已验证通过 | 文件存在 / git 确认 / 测试通过 |
| ✅(用户确认) | 用户声称完成，未自动验证 | 云服务配置等 |
| 🔄 | 进行中 | 部分完成，有残留工作 |
| ⏳ | 待开始 | 计划要做但尚未开始 |
| ❓ | 状态不明 | 无法确认，需接手者验证 |
| ❌ | 已失败/放弃 | 确认失败，需注意 |

### Step 4: 提取工作信息

从当前对话提取：
- **已完成文件**：代码文件路径、功能说明、验证状态
- **关键决策**：做了什么选择、为什么
- **踩坑记录**：遇到的问题、原因、方案
- **下一步**：待办清单、当前卡点
- **用户画像**：沟通风格、技术背景

### Step 5: 确定核心入口文件

**入口文件优先级**：

| 优先级 | 文件类型 | 示例 |
|-------|---------|------|
| 1 | 入口页面 | `index.html`, `app.html` |
| 2 | 前端主文件 | `main.js`, `App.vue`, `app.jsx` |
| 3 | 后端入口 | `server.js`, `app.py`, `main.go` |
| 4 | 当前工作文件 | 对话中修改最频繁的文件 |

**确定方法**：
1. 从对话上下文统计文件提及频率
2. 按优先级扫描项目结构
3. 取最可能的入口文件名（不含路径）

## 规则

1. **必须验证**：交接文档必须包含"状态验证记录"章节
2. **区分标记**：严格区分 ✅已验证 和 ✅(用户确认)
3. **诚实记录**：无法验证的事项标记为 ❓，不隐瞒
4. **客观描述**：不夸大完成度，不隐藏问题
5. **绝对路径**：文件路径使用 `{PROJECT_ROOT}/xxx` 格式
