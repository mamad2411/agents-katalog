# 行业实践案例共创

以最低输入门槛，把开发者熟悉的行业材料整理为一张可复用的行业实践案例卡，并同时展示卡片近景和它在报告实践页中的实际落位效果。

## 边界

- 只开发案例卡及其数据，不要求开发者设计整张实践页面。
- 用户侧案例库统一展示全部案例，并用现有行业标签筛选和拼接；不要再按“用上、用好、用爽”等页面模块预先切库。
- 不新增第二套行业或阶段标签。使用项目已有行业分类；入口已传入行业时直接继承。
- 不允许无图片案例卡。
- 不执行仓库晋级或发布；开发者确认后生成交接单并停止。负责人另行调用 `module-promote`。

## 开工材料检查

先完整阅读所有材料，再一次性确认是否具备：

1. 行业信息或可映射到现有行业标签的上下文；
2. 足以形成案例表达的文字材料；
3. 至少一张图片；
4. 开发者明确确认这些材料可用于本项目。

Agent 只确认材料项是否存在并记录开发者确认，不调查素材权属、真实性、效果质量或证据充分性，也不替开发者作这些判断。没有图片，或缺少开发者的可使用确认时，必须阻塞并一次性列出缺项。

## 读取项目约束

1. 定位项目仓库，读取最近的 `AGENTS.md` 及其路由的行业协作文档、行业 `PLAYBOOK.md`、安全和本地开发文档。
2. 核实目标是开发仓；无法根据 remote URL 和 `.spark/meta.json` 确认时停止。
3. 检查现有案例数据契约、案例卡组件、行业标签、图片路径和实践页实际渲染方式。
4. 如果入口指向现有案例，优先在该案例上下文中替换或迭代；不要重新让开发者选择行业和目标。

## 低摩擦生成

材料齐全后直接进行，不额外要求开发者填写结构化表单：

1. 从材料中整理标题、主体、场景、做法、结果描述、图片和现有行业标签。
2. 保持素材原意，不补写材料中不存在的事实或数字。
3. 写入项目现有案例契约和素材目录，不改变整张实践页面的组件架构。
4. 同时生成两个预览：案例卡近景、报告实践页实际落位效果。
5. 让开发者直接基于预览反馈；后续只处理新增意见，不重复询问已提供材料。

使用 [案例材料与验收](references/case-materials-and-gates.md) 中的结构进行建模和验收。

## 质量检查

- 视觉检查默认保持轻量：文字溢出、图片裁切、可读性、标签显示和实际落位。
- 只有修改共享案例卡组件或公共样式时，才升级为完整视觉回归检查。
- 运行项目规定的模板校验、测试、diff 检查，并按影响面补充构建与浏览器验收。
- 开发仓在线检查只有在本轮得到明确发布授权后才能执行；否则在交接单中标记为晋级待办。

## 交付

开发者确认卡片和实际落位效果后，输出简短交接单：行业标签、案例摘要、图片清单、修改文件、两个预览、检查证据、缺失或未决事项。随后停止，不自动推送、发布或调用 `module-promote`。

## 立即停止

- 缺少图片或开发者的可使用确认；
- 需要修改公共渲染器、数据库、历史报告或其他行业范围；
- 无法确认开发仓身份；
- 质量门无法通过；
- 需要开发仓或生产仓发布但没有本轮明确授权。
