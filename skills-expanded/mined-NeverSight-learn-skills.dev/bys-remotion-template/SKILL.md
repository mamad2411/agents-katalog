# 不一书Remotion模板生成器

把"每次做视频都从头折腾"变成"复制模板就开工"。本 Skill 引导用户完成一场结构化访谈，最终交付**两件套**：

1. **《通用提示词模板.md》** —— 用户每期视频复制一份、填好【本期信息】和【本期特殊要求】发给 AI 助手，即可按固定流程开工。
2. **`_starter/` 工程底座** —— 定制过风格的 Remotion 工程（theme.ts 控制台、通用组件、场景块、字幕脚本、README、风格规范.md），每期复制开新工程，跨期风格统一。

## 核心原则

- **强引导，一次只问一步**：用户可能完全不懂代码。每一步先用一两句话解释"这是什么、为什么要选"，再提问。有 AskUserQuestion 工具就用它给选项，没有就在对话里给编号选项。
- **先看效果再往下走**：风格类决策必须配 HTML 效果图（2-3 版供挑选），确认后才进入下一步。绝不凭文字描述定风格。
- **动笔前整体确认**：所有决策汇总成一张确认单，用户点头后才开始生成文件。
- **产物是用户自己的**：生成的模板和底座属于用户风格，仅在 README 页脚留一行 `由 不一书Remotion模板生成器 (bys-remotion-template) 生成` 轻署名。

## 流程总览

```
0 欢迎 + 环境检查 → 1 分步访谈 → 2 风格效果图（挑选/迭代）
→ 3 汇总确认单 → 4 生成两件套 → 5 Remotion 真实验收 → 6 邀请试做一期
```

各步细节按需读 references/：

| 文件 | 什么时候读 |
|---|---|
| `references/env-check.md` | 第 0 步，检查环境和 remotion-best-practices |
| `references/interview-guide.md` | 第 1 步开始前，完整问题库与顺序 |
| `references/preview-guide.md` | 第 2 步，HTML 效果图怎么做 |
| `references/customization-guide.md` | 第 4 步，怎么按访谈结果定制 assets/starter-skeleton |
| `references/prompt-template-guide.md` | 第 4 步，怎么生成《通用提示词模板.md》 |

## 第 0 步 · 欢迎与环境检查

用户触发初始化后，先发欢迎语（保持这个调性，可微调）：

> 📽️ **欢迎使用「不一书Remotion模板生成器」！**
>
> 接下来我会像一个视频工作室的制片人一样，陪你把这些事一次定好：画幅、内容形态、字幕、视觉风格、声音……最后你会得到一套**长期可用**的专属模板——以后每期视频，复制模板、填几行信息，就能直接开工 🚀
>
> 全程不需要你懂代码，每一步我都会解释清楚、给你看效果图再往下走。我们开始吧！

然后按 `references/env-check.md` 检查环境（Node/npm、ffmpeg、remotion-best-practices skill）。缺 remotion-best-practices 时引导安装（`npx skills add remotion-dev/skills`）或征得同意后代为安装；装不上有兜底方案，不阻塞流程。

## 第 1 步 · 分步访谈

读 `references/interview-guide.md` 后开始。核心决策依次是：画幅 → 内容形态（口播露脸/纯动画/录屏混合）→ 字幕方案 → 视觉风格方向 → 声音（配音/BGM/音效）→ AI 权限（能否联网补料、能否自主找素材）→ 交付偏好。

一次只问一个话题；用户答不上来就给出你推荐的默认值并解释原因。

问到风格那一题时，**只问大方向和主色偏好就停，不要把风格细节问到底**——细节靠第 2 步的效果图对话敲定，问一堆"圆角要多大、发光要多强"用户根本答不上来。但风格之后的声音、AI 权限、交付、个性化几题仍要问完，问完才进第 2 步。

## 第 2 步 · 风格效果图

读 `references/preview-guide.md`。按用户选的风格方向做 **2-3 版**不同倾向的 HTML 效果图（每版含钩子大字帧 + 要点卡帧两张关键帧，按所选画幅精确制作），让用户挑选或提修改。修改后重新出图，直到用户明确说"就这版"。选定版本的全部设计参数（配色、字体感觉、发光强度、圆角、卡片样式）记下来，第 4 步写进 theme.ts 和风格规范。

## 第 3 步 · 汇总确认单

把所有决策整理成一张清晰的确认单发给用户（画幅/形态/字幕/风格版本/声音/AI 权限/交付物清单），明确问"确认无误就开始生成，要改哪条现在说"。用户确认后才动笔。

## 第 4 步 · 生成两件套

1. 把 `assets/starter-skeleton/` 复制为用户的 `_starter/`，按 `references/customization-guide.md` 定制：theme.ts（画幅+选定配色）、按形态删/留 FaceCam 等模块、生成 README.md（从 README.template.md 填占位符）和 `风格规范.md`。
2. 按 `references/prompt-template-guide.md` 生成《通用提示词模板.md》。
3. **跑验收脚本**（定制骨架时最容易犯的错都是静默的——删了模块忘删 import、README 里留着 `{{占位符}}`、画幅和访谈结论对不上，这些肉眼复查会漏，脚本不会）：

   ```bash
   python3 scripts/validate_starter.py <生成的_starter目录>
   ```

   FAIL 项全部修掉再往下走。
4. 两件套都放到用户可见的文件夹，并简要讲解每个文件是干什么的、每期怎么用。

## 第 5 步 · Remotion 真实验收

环境允许时（Node 可用）：在 `_starter/` 里 `npm install`，用 `npx remotion still MyVideo out/frame.png --frame=N` 渲 2-3 张关键帧给用户看，确认和 HTML 效果图一致。发现偏差就修 theme/组件后重渲。环境不允许就明确告诉用户："模板已生成，第一次在你自己电脑上打开时，用 `npx remotion studio` 预览，有偏差随时回来找我调。"

## 第 6 步 · 邀请试做一期

验收通过后主动问：

> 🎬 模板已就绪！要不要现在就用它试做一期？把你的素材给我就行——
> （按用户形态列清单，如：口播视频 video.mp4 / 字幕 video.srt / 本期主题和逐字稿 / 素材图或录屏）

用户愿意就按刚生成的《通用提示词模板.md》的流程完整走一遍（这既是试做，也是对模板的真实测试）；不愿意就告诉用户模板怎么在以后的新对话里使用。

## 红线

- 每一步都等用户确认再进下一步，不要抢跑合并步骤。**唯一例外**：用户已经说过的信息可以打包求证（见 interview-guide），以及用户明确要求"一次问完"时批量补问空缺——但效果图挑选和确认单这两个节点永远不能省。
- 效果图没让用户挑选前，不许生成最终文件。
- 不杜撰用户没确认过的风格决策；用户说"随便/你定"时，用推荐默认值并明说"我帮你选了 X，因为 Y，不喜欢随时改"。
- 生成的工程必须自包含：不打包 node_modules、不写死本机路径、README 里的命令在干净机器上可执行。

## 安全边界

这些是用户把文件夹交给你时有权期待的事：

- **写文件只发生在第 4 步之后**。访谈和效果图阶段除了效果图 HTML（放临时目录或用户指定目录）不落任何文件。
- **不覆盖已存在的东西**。目标位置已有 `_starter/` 或同名文件时，先告诉用户并给三个选项：换个名字 / 备份后覆盖 / 取消。绝不静默覆盖。
- **不动用户的既有工程**，不删除任何文件。
- **不写入任何密钥、token、私人路径**到生成的工程或文档里。
- **联网搜索按访谈里的授权执行**。用户选了"每次先问我"就每次先问。
- 骨架里的 `srt_to_captions.py` 只读 SRT、只写 `src/captions.ts` 一个文件，会提示用户它是覆盖写入。
