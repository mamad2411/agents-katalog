Review against the alanstack quality bar. One line per finding. Location, problem, fix. No filler.

## Output format

```
<file>:L<line>: <problem>. <fix>.
```

Block-level (file-wide) findings:

```
<file>: <problem>. <fix>.
```

Group by file. Order findings by line number within a file. Skip files with no findings.

End with a one-line verdict: `ship`, `ship-with-nits`, or `block` (one or more block-level violations).

## What to flag (in priority order)

**Block (always):**
- `any`, `as unknown as`, `@ts-ignore` without inline comment naming the constraint
- `throw` in business logic (anything outside boundary wrappers like `ResultAsync.fromPromise`, repo-local `tryAsync`)
- `Promise<Result<…>>` in any signature — should be `ResultAsync<T, E>`
- Untyped external IO reaching business logic without Zod / schema parse (HTTP body, RPC payload, DB row to API, file/env/CLI arg)
- DB entity returned at an API boundary (must map to a DTO)
- Hardcoded secret, committed `.env`, real key in test/fixture
- Agent/AI attribution (any `Co-Authored-By: <bot>`, `Generated by <tool>`, `🤖 …`), emoji in commits/PRs/code

**Nit (suggest, do not block):**
- Switch/if chains over an owned union → exhaustive `ts-pattern` with `.exhaustive()`
- Repeated null checks of the same value → `Maybe<T>` + `match`
- Nullable parse / persisted-data path that should be `Result<T, E>` (absence = failure)
- Inline anonymous object type repeated across functions → extract named `type` / `interface`
- IIFE or `(curry())(arg)` → named helper / intermediate value
- Wrong runtime: `npm`/`pnpm`/`yarn` in a Bun repo, `node:` API where Bun-native exists (`Bun.file`, `bun:sqlite`, `Bun.$`)
- New dep that duplicates a slot already filled by [references/preferred-tools.md](../alanstack/references/preferred-tools.md)
- Root-only monorepo check that should be per-package (`bun run --filter`)
- Frontend: `useState` for derived data, `useEffect` for sync deps, `Redux`/`Jotai`/`MobX` introduced into a `@tanstack/react-store` repo
- Test runner mismatch (vitest in a `bun:test` package, or vice versa, without local convention)

**Style (mention once per file, optional):**
- Public API or Result-boundary function without explicit return type
- Multi-line arrow function that should be a `function` declaration
- Comment that restates the code instead of explaining a hidden constraint

## Voice

Direct. No "I noticed that…" / "It might be a good idea to…" / "Consider…". The fix IS the suggestion.

Skip a finding if you cannot give a concrete fix.

## Examples

Good:
```
src/auth.ts:L42: throw in business logic. Wrap parse in `ResultAsync.fromPromise` and return `Result<Session, AuthError>`.
src/db/user.ts:L18: Promise<Result<User, Error>>. Switch to `ResultAsync<User, Error>`; remove explicit `Promise<>` wrapper.
src/handlers/order.ts:L57: switch over `OrderStatus` not exhaustive. Replace with `match(status).with(...).exhaustive()`.
src/api/routes.ts: returns Drizzle row directly. Map through a `UserDto` before serializing.
```

Bad:
```
L42: I noticed there's a throw here — you might want to consider using neverthrow's ResultAsync instead, which would be more in line with alanstack conventions.   ❌ filler
```

## When to read more

- For deep stack-choice judgment calls (HTTP server, ORM, AI SDK, etc.) consult [references/preferred-tools.md](../alanstack/references/preferred-tools.md) before suggesting a swap.
- For rules that conflict between source repos, consult [references/source-signals.md](../alanstack/references/source-signals.md).
- For repo-local exceptions, read the target repo's `AGENTS.md` and neighboring files first — local rules override these defaults.
