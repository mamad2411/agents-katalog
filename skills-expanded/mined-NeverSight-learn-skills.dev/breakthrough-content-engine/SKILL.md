# Breakthrough Content Engine

> 给一个目标，出一整档内容规划。**人只审一张表，其余机械推导。**

这是一个 dispatcher。下面的地图告诉你每一层住在哪个 `references/` 档，**按需加载，不要一次全读**。

## 它凭什么不一样

大部分内容工具的形状是「给我一个题目，我给你一篇稿」。这一套反过来：**你给我一个生意目标，我先告诉你这一档该打谁、打什么、打几支，最后才写稿。**

三条它跟别人不同的地方：

- **配比是推导出来的，不是抄比例。** 没有任何实测研究支持任何漏斗阶段的内容篇数配比（80/20、4-1-1、70/20/10 全部是断言，其中 70/20/10 还是风险分配被误引成漏斗分配）。所以这里的数字来自你的**产能**、你的**漏斗诊断**、你的**跑道**，而不是来自一句口号。**产能封顶，目标定形，诊断修形，格式落位。**
- **人只审 seed，不审稿。** 一张 8 到 20 条的 seed sheet 是唯一的人工决策点。十几二十格的内容地图从 seed 机械推出来，可再生。**没有人逐格审那二十几个格子，规模要服务人的判断，不是淹没它。**
- **它会拒绝。** 粉丝规模不够就不出配比，改出触达获取任务单；手上没有真材料就不写稿，改出采集指令。**「材料不够，先去拿材料」是一个合法的、正确的输出。**

## 什么时候用

- ✅ 要规划一整档内容（一个月、一次 launch、一段跑道）
- ✅ 内容一直发但没有效果，想知道是哪一段漏了
- ✅ 想知道这一档该出几支视频几篇图文，而不是凭感觉
- ❌ 只是要写一篇文案 → 不用跑整条 pipeline
- ❌ 付费投放为主 → 配比逻辑整个不同，这里只管 organic
- ❌ 还没有产品、还没有人买过 → 那是产品验证问题，不是内容问题

## 四个 mode

这个 skill 有四种进法。**先判是哪一种，再往下走。**

| Mode | 什么时候 | 干什么 | 载入 |
|---|---|---|---|
| **Plan** | 「帮我规划这个月」「这一档要发几支」 | 从目标跑到成稿的主线，收尾做改稿回流 | [modes/plan.md](modes/plan.md) |
| **Capture** | 「我捞到几条客人的话」「NEEDS-CAPTURE 那几条我补到了」 | 收真料、分 `scene_id`、升级 barrier 证据层级 | [modes/capture.md](modes/capture.md) |
| **Log** | 门铃点名，或「记一下成绩」 | 3 / 7 / 15 天纯录入，30 秒做完，**不做判断** | [modes/log.md](modes/log.md) |
| **Review** | 「复盘一下」，或一档跑完 6 到 8 周后 | 读数据、重跑诊断与配比、**出提案不出结论** | [modes/review.md](modes/review.md) |

**Capture 是整套引擎唯一的真证据入口。** 别的地方进来的都是上下文。

## 有 second-brain vault 的话

看得到 `99_Meta/structure-doctrine.md` 就是有。有的话开场先读 [references/_vault.md](references/_vault.md)：扫生意翼拿品牌上下文、读**覆盖层**（用户自己校出来的数字优先于出厂值）、知道东西该长在哪里。

🛑 **每个 mode 的第一个动作都是认路**（`_vault.md` §1.5，**整节跑完**）：一道 glob 找 `content-engine-paths.md` 这本地址簿，路径全部从它拿；**拿到之后接着跑同一节的门铃接线检查**。⛔ 不分第一次还是第一百次，⛔ 不准凭记忆猜路径：生意翼与品牌的夹名是**用户自己取的**，猜不到。

⚠️ **扫回来的是上下文，不是证据。** 八柱地基与品牌策略报告读起来像证据、连引号都像，但实测一份 100KB 的已锁策略跑出 **0 条 `confirmed` 顾客 barrier**。所以扫 vault 的第一个动作是引号出处扫描，未标注一律按构造处理。

**没有 vault 一样跑**，照 `00-intake.md` 问那六件事。⛔ vault 是加分，不是前提。

## 门铃接线（认路时做，⛔ 不是安装时）

用户如果有**产品生成的** command-base skill，引擎会去改**他那一份已经装好的**（不是产品的 template，template 只影响以后的新装），让门铃认得内容到期这件事。

⛔ **这件事不发生在安装那一刻。** `npx skills add` 是套件管理器，它不执行 skill 里的任何一句话；而且装的那一刻没有人知道这个用户的宅在哪。⇒ **触发点是每个 mode 开场认完路那一步**（`_vault.md` §1.5 的「认完路还有一步」），⛔ **不是 `_vault.md` §8**：§8 只在地址簿不存在时跑，地址簿已经存在的用户永远等不到它。

⚠️ 产品端的门铃教条：**铃只响一次，而且由铃自己点名什么到期了，不丢一道选择题给主人**（产品 `modes/maintenance.md` 的「One doorbell, two files」讲的就是这件事）。所以**不新增第二个铃**，只是把「哪几篇到 3 / 7 / 15 天了」写进现有门铃读得到的地方，铃照响一次，多点名一件事。

⛔ 改的是 **Claude Code 实际载入的那一份**（`~/.claude/skills/<slug>-command-base/SKILL.md`）；vault 里那一份在 copy 安装上只是副本，改了不会报错也不会生效。改完 grep 读回确认。⛔ 不要写进门铃区块本身，那一块产品升版会整块覆盖。

**找哪一支、插在哪、插什么、重跑怎么不会插两次、接不上怎么记**，五件事全部住 `_vault.md` §1.5 与 §9，⛔ 别凭这一段的记忆办事。

## 几条贯穿全场的规矩

这几条在很多档里会重复出现，因为它们真的到处适用：

- **遮品牌名测试。** 把品牌名盖掉，如果这条内容随便哪个同行都能发，它就失败了。一看就知道是你，才算成功。
- **免费老师陷阱。** 知识很廉价，AI 随便生成；**观点才值钱**。干货类内容最容易踩，每一条都必须带你自己的方法和立场。
- **深 ≠ 独特。** 往下挖情绪、挖身份，挖到最后往往挖到一个人人适用的普适真相。那是**最高级的同质化**，不是洞察。差异化来自 reframe（你的视角），不是来自挖得更深。
- **Awareness 里一 pitch，三个阶段塌成一个。** 认知阶段的内容里出现产品，读者直接划走。这条没有例外。
- **只准真实稀缺，不准制造紧迫。** 在错的阶段用制造出来的急迫感，是**分类错误**，不是风格选择。
- **真实记忆有废料，编造的记忆没有。** 一篇稿子里如果每一个细节都刚好在替论点服务，一个多余的都没有，那多半是编的。**而那个多余的细节必须跟承重细节同源**，否则随手编一个无关细节就能过关，这条规则就白写了。

## 一句话

内容是慢功夫。**先有真材料，再有角度，再有内容。** 这套工具能做的是让每一步都有依据，不能替你去把顾客说过的那句话捡回来。
