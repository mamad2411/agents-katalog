# 기능 구현하기

확인된 범위를 사용자가 완료할 수 있는 기능 단위로 구현한다. 이 스킬은 구현의 진입점이며, 샘플 데이터·영구 데이터·전체 검증·배포 자체를 대신하지 않는다.

## 진행

1. 구현 범위와 완료 조건에 영향을 주는 프로젝트 컨텍스트, 기존 코드·데이터와 Git 상태를 파악한다.
2. 구현할 행동과 완료 조건이 명확하면 바로 진행한다. 실질적으로 빈 폴더면 직접 구현하지 않고 `kc-init`이 필요한 상태를 보고하며, 제품 의미가 결정되지 않았으면 구현 결정을 바꾸는 사항부터 확정한다.
3. 요구사항의 명확성, 기술적 불확실성, 변경 위험과 가용 자원에 따라 계획 깊이, 작업 단위와 검증 간격을 정한다.
4. 핵심 사용자 흐름이 실제로 작동하도록 구현한다. 복잡한 흐름을 나눌 때만 [사용자 흐름 단위 기준](references/vertical-slice-rules.md)을 참고한다.
5. 기존 구조와 안정적인 의존성을 존중하고 요청과 관련 없는 업그레이드·리팩터링·기능 추가를 피한다.
6. 샘플 데이터 생성이나 영구 데이터 연결이 별도 요구사항이면 구현 범위와 분리한다. 구현에 꼭 필요한 최소 fixture·데이터 변경만 확인된 범위 안에서 다룬다.
7. 변경 위험에 비례하여 정적 검사, 빌드와 구현한 핵심 행동의 기본 동작을 확인한다. 전체 완료 조건 검증은 `kc-verify`의 범위로 남긴다.
8. 배포나 외부 프로젝트 생성을 실행하지 않는다. 외부 서비스 사용이 제한되거나 불명확하면 관련 변경을 추가하지 않고, 비밀값·실제 개인정보·공급자 캐시와 범위 밖 파일이 섞이지 않았는지 확인한다.
9. 저장소 관례나 사용자 요청에 체크포인트가 포함되면 검증된 의미 있는 완료 지점에 만든다. 필요할 때만 [체크포인트 기준](references/checkpoints.md)을 참고한다.

비용, 공개 범위, 핵심 사용자, 데이터 의미, 실제 운영 데이터 또는 되돌리기 어려운 변경이 필요한 경우에만 진행 전에 확인한다. 일반적인 기술 선택이나 되돌리기 쉬운 구현 세부사항은 합리적으로 판단한다.

## 완료

사용자가 할 수 있게 된 행동, 구현 중 수행한 기본 검사, 별도 검증·데이터 연결·배포로 남긴 항목과 남은 위험을 보고한다.
