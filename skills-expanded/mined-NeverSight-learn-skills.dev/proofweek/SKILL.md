# Proofweek

帮助用户减少规划成本，在继续投入准备之前尽早获得外部证据，并据此决定继续、修改或停止。

## 适用边界

使用本 Skill，当用户同时满足以下特征：

- 正在推进求职、内容发布、产品测试、获客或其他需要外部对象回应的事项；
- 已有模糊事项、候选材料或初步成果，需要整理成一至两周的执行计划；
- 准备、研究或打磨可能持续挤占投递、发布、测试或触达。

不要使用本 Skill 处理普通日程、家务清单、纯内部工程排期、长期人生规划或心理诊断。若任务不需要外部判断，说明不适用，不要强行制造“市场验证”。

## 行为契约

必须做到：

- 先利用现有信息形成任务假设；只有答案会改变核心结果、首个外部行动、客观证据或硬约束时，才一次追问一个问题；
- 不询问“为什么不愿提交”，不分析用户的潜意识、人格或病理原因；
- 区分准备、技术 QC、市场取样、外部验证和决策；
- 为准备任务设置时间或数量上限，并在用户约定的首个周期内安排最小外部行动；
- 每个任务只有一个主要动作和一个可检查的完成证据；
- 区分已发生事实、用户判断、推断和未知项；
- 输出可编辑的 Markdown 计划、周末复盘结构和下次续接块。

禁止出现：

- 把勾选、学习、完成准备或 AI 生成内容当成外部验证；
- 把无回复、点赞、评论、免费试用或技术通过自动解释为需求成立；
- 为了“计划更准确”连续提出一组问题；
- 未经授权代替用户投递、发布、联系他人或修改外部系统；
- 使用“治疗拖延”等医疗化承诺。

## 模式选择

根据用户输入选择一种模式，不要求用户重复已经提供的信息：

1. **周初规划**：输入模糊事项、材料和约束，生成本周计划。
2. **周末复盘**：输入实际执行记录，分离事实、外部证据和未知项，生成下一步决定。
3. **跨会话续接**：输入上次的续接块，恢复未完成承诺和已知边界，再生成新计划或复盘。

## 最少输入

优先从当前对话提取；缺少且确实影响计划时，再询问其中一个：

- 本周想推进的事项；
- 可投入时间；
- 已存在的材料或当前进度；
- 希望接触的外部对象；
- 明确截止时间；
- 已知硬约束。

“已知硬约束”只接受事实性阻塞，例如事实错误、缺少明确必需项、核心流程不可用、隐私／合规／保密风险或不存在可接触对象。没有则记为“无”。不要设置“当前不愿提交的原因”字段。

## 工作流程

### 1. 建立事实底稿

提取用户已经给出的事项、时间、材料、外部对象和截止时间，分别标记已发生事实、用户判断、推断和未知项。不要把推断写成事实。

### 2. 写核心结果

核心结果必须包含：截止时间、要交付或发生的行为、外部对象、可检查证据。结果应描述本周期能控制的动作；外部回应不完全可控时，把“完成发送／投递／发布／测试邀请”设为完成证据，把回应作为后续结果记录。

### 3. 检查硬阻塞

如果存在可能阻止外部行动的关键未知项，只问一个事实问题。若不存在硬阻塞，不继续讨论“是否已经完美”，直接安排最小外部行动。

外部对象是生成完整计划的必填门禁。若无法从用户已经明确提供的岗位、平台、客户、测试者或其他对象中可靠确定，不得用“目标用户”“潜在用户”之类占位并继续排期；只问“这次要先让哪类真实对象评价或使用什么？”，然后停止本轮，等待回答。

### 4. 拆成单一动作

将任务写成“动词＋对象＋客观完成证据”。中间步骤已有独立可接受成果时拆成不同任务；仅为同一成果跨天工作时保留一个任务，并记录多个执行块。

### 5. 分类并限制准备

按 [references/decision-rules.md](references/decision-rules.md) 分类。准备和技术 QC 只能证明材料或功能达到提交底线，不能证明外部接受。为准备设置与用户容量相称的上限，超出部分进入条件式 Backlog。

### 6. 安排首个外部行动

在首个约定周期内安排一个规模小、风险可控、能够产生真实接触证据的动作。用户未指定数量时，选择足以暴露关键假设的最小批次，不擅自套用固定数字。

### 7. 检查容量和先后关系

计划投入不超过用户可用容量；保留必要缓冲。先完成提交底线，再发生外部行动，最后根据结果决定是否追加准备。不能把全部外部行动集中到所有准备完成之后。

### 8. 输出或复盘

使用 [assets/weekly-plan-template.md](assets/weekly-plan-template.md) 的相关部分。字段没有信息时填“—”或明确标记未知，不编造日期、耗时、链接和反馈。

## 停止条件

- 任务不需要外部判断：说明不适用并停止证据驱动分类；
- 存在未解决的隐私、合规、保密、事实错误或核心不可用问题：停在硬阻塞，不催促提交；
- 用户要求实际投递、发布、联系或写入第三方工具：在执行前单独确认授权和具体目标；
- 现有信息足够生成可用计划：停止追问并交付；
- 计划已经包含外部行动、客观证据、准备上限和下一步决定：不继续增加字段或优化模板。

## 完成检查

交付前确认：

- 核心结果有截止时间、外部对象和可检查证据；
- 首个周期存在至少一个外部行动；
- 每个准备任务都有预算或退出条件；
- 技术通过与外部接受没有混淆；
- 结果只记录事实，下一步是继续、修改、停止或待更多证据；
- 输出含下次续接块，且不包含用户未要求公开的私密信息。
