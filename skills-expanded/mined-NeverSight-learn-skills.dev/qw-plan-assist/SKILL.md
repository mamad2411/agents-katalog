# qw-plan-assist

## 目的

基于作者在当前对话中给出的主题、画面、限制与现有连续性材料，产出 2 到 4 份可比较的候选粗条池，并在后续讨论中继续收束，最终形成 `spec.md`。

## 使用时机

仅在作者明确要求使用 `qw-plan-assist`，或明确表示要基于当前故事碎片进行策划时使用。

适用于：

- 作者已经给出部分主题、画面、限制、关系方向
- 目标是先把故事段策划出来，并收束成 `spec.md`，而不是直接切分或写正文
- 希望先得到几种可比较的候选粗条池，再继续收束
- 需要把候选粗条池继续讨论，最终收成 `spec.md`

## 不要在这些情况下使用

不要在以下情况使用：

- 作者已经明确进入切章阶段
- 作者已经明确进入 spec 压写阶段
- 作者已经明确进入正文生成阶段

## 读取范围

必读：

- 当前对话中的作者碎片
- 当前书已有的相关 planning
- 当前书已有的相关 bible
- 与本轮规划直接相关的连续性材料

按需读取：

- 若作者明确提到某个现有 spec 或 planning 文件，优先读取该文件
- 若作者要求写文件，读取作者指定的当前候选文件或当前粗纲文件
- 若作者要求形成正式 `spec.md`，写入前读取 `templates/spec.md` 作为格式合同

## 写入范围

仅在作者明确要求写文件时，允许写入作者指定路径的：

- 候选粗条池文件
- `spec.md`

默认先输出到对话，不主动写文件。

## 核心契约

### 输入收束

- 先从当前对话中读取作者碎片、规划范围、明确不要的重复项、以及是否需要写文件。
- 再从当前书已有 planning、bible 与必要连续性材料中补齐上下文。
- 只有在范围不清、硬约束缺失、或作者要求写文件但未给路径时，才追问。

### 核心机制

- 先从作者给出的主题和碎片里，提炼出几种可能把这段写活的“两股力”。
- 再围绕这些不同的两股力长出 2 到 4 种具体画面。
- 姿势、洞口、主导、节奏、持续时间不是先填进去的选项，而是从这些具体画面中自然长出的身体编排。
- 生成完成后，再用连续性、不重复项、后续空间对候选进行过滤和排序。

### 创意拉开

- 不能只把作者已给碎片顺着说开；在形成候选前，至少先做一轮“变形”，把碎片改造成不同的局部机制、不同的画面重心或不同的作用路径。
- 每份候选都应至少在以下五条主线中的两条以上，和其它候选形成明确差异：场地主线、身体主线、运动主线、画面主线、作用主线。
- 至少保留一路“逆手候选”：不沿作者当前最顺手的直线扩写，而是保留同一股核心张力，改走另一种局部实现方式。
- 如果作者只给了一个熟悉画面，不要只做同一画面的同义扩写；至少要同时尝试：
  - 保留该画面，但改变它在整路中的作用
  - 保留该股作用，但改用另一种画面或调度来实现
- 优先把普通碎片变成结构抓手，而不是只往上叠更多元素；同一个场地、道具、衣物、视线、站位变化，都可以被改造成分场边界、节奏机关、关系转折或章尾接口。
- 输出前应做一次“同义改写检查”：如果去掉候选名之后，两路候选仍然可以互换位置，说明创意没有真正拉开，应继续重做。
- 创意分两层：候选之间主要靠路线级创意拉开，同一路内部主要靠条内微创意防止粗条发平。
- 条内微创意必须服务当前粗条的作用，不为新而新；它优先从重心或支点变化、局部处理变化、节奏颗粒变化、作用反折中长出。
- 单条粗条优先只抓最有效的 1 到 2 个微变化；若没有明显增益，不强行补花样。

### 节点清单的角色

- 节点清单不是主生成器。
- 生成前，可将节点清单作为参考盘，用来识别这轮最值得分叉的节点。
- 生成后，可将节点清单作为检查表，用来判断候选是否太单薄、太重复、缺高点或缺后续接口。

### 候选粗条池输出

- 每次产出 2 到 4 份候选粗条池。
- 对话中默认只输出候选总览，包括：
  - 本轮短收束
  - 各候选的一句总承诺
  - 各候选的一句新意说明
  - 各候选的一句反手点说明
  - 各候选最关键的几条粗条
  - 各候选 1 到 2 个条内新意预告
  - 候选之间的横向比较与推荐
- 作者需要查看完整展开时，再将完整候选粗条池写入作者指定文件。
- 作者要求形成正式结果时，再将收束后的结果写入目标 `spec.md`。

### 粗条合同

单条粗条按以下顺序组织：

1. 场地
2. 身体架子
3. 运动方式
4. 持续时间
5. 画面
6. 条内新意
7. 作用

说明：

- 身体架子包含洞口与姿势。
- 运动方式包含主导与节奏。
- 持续时间写这条粗条大约覆盖多久，按分钟级或阶段级估算即可，不要求精确到秒。
- 画面包含视觉、语言、道具。
- 条内新意写这一条内部最能让它不平的 1 到 2 个微变化；优先来自重心或支点变化、局部处理变化、节奏颗粒变化或作用反折。若没有明显增益，可留空，不强行补花样。
- 作用写这条在整一路里是在铺热、换手、立中段机关、做高点、做章尾完成，还是为后续留接口。

### 拆条规则

- 换洞口、换姿势、换主导，直接拆条。
- 节奏变化如果只是同一目的下的强弱变化，可以不拆。
- 节奏变化如果已经在做另一件事，就拆条。

### 粗条池合同

每份候选粗条池按以下顺序组织：

1. 路线名
2. 总承诺
3. 场地主线
4. 身体主线
5. 运动主线
6. 画面主线
7. 作用主线
8. 编号粗条序列

编号粗条序列中的每条都遵循「粗条合同」，并明确持续时间。

### 交互节奏

- 用户体验应当是“扔碎片 -> 看候选总览 -> 选路或混搭 -> 看下一版 -> 需要时落文件”。
- 作者后续在对话中说“这个要、那个不要、这里改一下、再来一个创意”，都应被理解成对当前粗条池的继续收束，而不是要求重新从零开始。

### 后续收束

- 后续轮次里，如果作者只对局部提出修改或要新点子，应优先在局部补新、局部改写，不要每轮都整份粗条池从零重写。
- 第一阶段的重点不是反复改格式，而是逐步确认哪些粗条已经可以保留，哪些地方还需要继续长新创意，并最终把这些确认过的内容压写成 `spec.md`。
- 收束过程中，不要为了快速统一而把几路候选磨成一个安全中位数；在作者没有明确否掉之前，应尽量保留至少一路仍然带着明显反手点或异质实现方式的候选。
- 作者要求混搭时，不要只做平均；应明确保留被借入那一路的具体新意来源、反手点或条内新意落点，而不是只留下一个变得更平的折中版本。
- 如果一轮修改后，当前保留路线已经失去原本最值钱的新意，应主动在局部补一个新的创意抓手，而不是顺着当前版本继续发平。

### 主线到 spec.md 的对齐

- 五条主线不是按原名平移成 `spec.md` 的正式栏目。
- 作用主线负责把当前收束稿分发到 `单元职责`、`单元状态`、`单元悬点` 与 `单元大纲`：
  - 整章最核心的完成任务进入 `单元职责`
  - 已在本章内完成闭环的作用进入 `单元状态`
  - 本章结束后仍未闭合、后续必须回接的作用进入 `单元悬点`
  - 每条粗条自己的局部作用继续留在 `单元大纲`
- 场地主线主要决定 `单元大纲` 的场景边界、分组方式与条目所在空间；只有当某个场所材料或空间边界已经长成整章级约束时，才上提到 `材料调用` 或 `连续性检查`。
- 身体主线主要决定 `单元大纲` 中每条粗条如何拆条、换手与转折；只有当某条身体边界已经成为整章级默认规则时，才上提到 `正文策略` 或 `连续性检查`。
- 运动主线主要决定 `单元大纲` 的节奏推进、换挡位置与篇幅权重；只有当某种节奏已经成为整章级写法约束时，才上提到 `正文策略`。
- 画面主线主要决定 `单元大纲` 中必须保留的画面锚点、语言抓手与道具抓手；只有当某种视觉方向或材料调用已经成为整章级要求时，才上提到 `正文策略` 或 `材料调用`。
- 写入 `spec.md` 时，应先把五条主线分发到正式栏目，再整理栏位内的表达；不要把“场地主线 / 身体主线 / 运动主线 / 画面主线 / 作用主线”原样抬成与正式栏目并列的新标题。
- 真正进入 `spec.md` 的 `单元大纲`，应尽量直接写成后续易于整理的稳定形状；候选文件本身不要求套用叶子 `spec.md` 的格式合同。

### 文件输出

- 默认只在对话中给总览。
- 作者需要持久化时，再写文件。
- 文件路径由作者在对话中指定。
- 候选粗条池文件与 `spec.md` 分开保存，例如：`ep15-planning.candidates.md` 与目标 unit 下的 `spec.md`。
- 真正写入 `spec.md` 前，应先读取 `templates/spec.md`，再按该模板的区块顺序与格式要求组织输出。
- 将当前收束稿压写到 `spec.md` 时，应至少明确：
  - 哪一句进入 `单元职责`
  - 哪些已完成的作用进入 `单元状态`
  - 哪些未闭合的作用进入 `单元悬点`
  - 哪些整章边界进入 `正文策略`
  - 哪些编号粗条进入 `单元大纲`
- 压写到 `spec.md` 时，不要把后续切分会用到的关键细节压掉；场地、洞口、姿势、主导、节奏、持续时间、关键画面、关键作用应随当前收束稿进入 `单元大纲`。

## 第一阶段闭环

- 第一阶段的中间态是候选粗条池。
- 第一阶段的闭环产物是 `spec.md`。
- `qw-plan-assist` 先给出候选粗条池，随后根据作者在对话中的取舍继续收束，直到形成目标 `spec.md`。

## 停止 / 拒绝条件

在以下情况应停止或拒绝：

- 作者实际想要的是切章，而不是第一阶段策划
- 作者实际想要的是 spec 压写，而不是第一阶段策划
- 作者实际想要的是正文生成，而不是第一阶段策划
- 作者要求写文件，但拒绝给出文件路径

## 输出契约

输出必须满足：

- 已基于作者碎片与现有材料生成 2 到 4 份可比较的候选粗条池，或在后续讨论中给出当前粗纲
- 已基于作者碎片与现有材料生成 2 到 4 份可比较的候选粗条池，或在后续讨论中形成 `spec.md`
- 候选之间具有真实差异，而不是同义改写
- 关键粗条已经具体到场地、洞口、姿势、主导、节奏、持续时间、作用可理解，而不是抽象概述
- 默认对话层给总览，文件层在作者要求时给完整候选或 `spec.md`
