# HTML Risk Auditor

把 HTML 当作不可信文本审计，输出有证据、可复核、可排序的中文风险报告。静态规则用于发现线索，最终结论必须结合上下文人工复核。

## 安全边界

- 默认只读文件，不在普通浏览器中打开，不执行内联脚本，不安装页面依赖，不向外部服务上传 HTML 或样例数据。
- 不把“规则未命中”表述为“没有风险”。静态审计无法证明运行时响应头、服务端行为、依赖包真实内容或业务数据敏感级别。
- 只有用户明确要求动态验证时，才在无账号、无 Cookie、无凭据、隔离且默认断网的环境中执行；若必须联网，先说明将访问的域名和数据边界。
- 不因审计请求自动修改被审计文件。修复代码需要用户同时授权修改。

## 工作流

1. 明确输入范围：目标 HTML、同目录本地脚本/样式、部署方式，以及是否会处理敏感数据。缺少部署信息时继续静态审计，并把依赖部署配置的判断标为“条件风险”。
2. 运行确定性扫描器：

   ```bash
   python scripts/html_risk_audit.py path/to/file.html --output html-risk-report.md
   ```

   可扫描目录，也可使用 `--json-output report.json` 给 CI 留结构化结果，使用 `--fail-on high` 设置质量门禁。
3. 阅读扫描器命中的代码上下文。优先追踪：外部输入到 DOM/脚本/URL/SQL/导出文件的流向；远程代码与本地文件或敏感数据的组合；动态代码执行；跨窗口通信；凭据；无限制文件读取和资源消耗。
4. 对每条线索标记结论：
   - `已确认`：当前文件证据足以成立。
   - `条件成立`：取决于部署响应头、数据可信度、网络策略或调用方。
   - `已缓解`：危险原语存在，但在当前链路有可验证的白名单、编码、隔离或完整性保护。
   - `误报`：规则命中的是注释、字符串、可信静态常量或不可达代码；说明排除依据。
5. 按 [风险模型](references/risk-model.md) 评定严重度和修复优先级。组合风险应单独成项，不能被拆散后的低等级掩盖。
6. 输出最终报告。自动扫描报告只是底稿；最终报告至少包含：
   - 一句话结论、总体等级、是否建议直接分发/上线。
   - 审计范围、假设、未覆盖项。
   - 严重度数量和 P0/P1/P2 修复顺序。
   - 每个风险的唯一编号、状态、类别、严重度、置信度、文件与行号、最小证据、攻击/故障路径、影响、修复建议、验证方法。
   - 已有保护措施与被排除的主要误报。

## 复核规则

- `innerHTML` 等 DOM sink 不是自动等于 XSS。检查插值值是否来自 URL、表单、文件、数据库、消息事件或远端接口，并确认所有进入 HTML/属性/URL/脚本上下文的值使用了匹配上下文的编码或安全 DOM API。
- HTML 内缺少 CSP 只能证明“文档未声明 CSP”；服务端可能通过响应头下发。没有部署证据时标为条件风险。
- 精确版本 URL 不等于内容完整性保护。远程脚本、动态 `import()`、Worker、WASM 和运行时扩展同时评估版本固定、来源可信度、完整性、离线可用性和失陷后的数据访问能力。
- `accept` 仅是文件选择提示，不是安全校验。检查大小、类型、扩展名、解析器资源上限、公式/CSV 注入和错误信息泄露。
- 内嵌压缩第三方库的命中应归到供应链/可维护性区域，不要把库内部实现误判成页面自有漏洞；仍需确认版本、许可证和已知漏洞信息。只有用户要求联网核验时才查询最新漏洞库。
- 修复建议要能落地并与证据对应；优先给最小改动和验证方式，避免只写“加强安全”“做好校验”。

## 结果判定

- 存在 `Critical` 或未缓解 `High`：不建议直接上线或向不受信任用户分发。
- 只有条件风险时，明确列出上线前必须补齐的部署证据，不能给出无条件“安全”。
- 所有线索均被排除或缓解时，结论写“本次静态审计未发现已确认高风险”，不要写“绝对安全”。
