# video-create

## 链路回显

在每次用户可见交付的首行写 `Route: <本次实际调用的创作 Skill，按顺序以 -> 连接>`。只列实际调用的 Skill；只有实际执行 SeaArt 时才追加 `seaart-execute -> SeaArt MCP`。不展示工具读取、内部推理或文件过程。

## 开始

- 用户说“直接生成”“马上出视频”或指定 SeaArt 时，仍由本 Skill 先进入；这只允许跳过非必要的概念或分镜探索，不能跳过 `video-prompt`。
- 识别用户此刻要的交付物：概念、剧本、分镜、时长判断、Clip 规划、Prompt、参考素材或执行。
- 只提取该交付物需要的目标、分支、时长、比例、投放位置、必需信息、源资产、创作方向和锁定约束。
- 用能完成任务的最小专业 Skill 集合继续。不要强迫完整工作流。

## 深度

### 快速

针对一个概念、剧本段落、就绪分镜或就绪 Clip Prompt，把状态留在对话中并直接继续。不要为了标记进度创建正式交接物。

### 项目

工作跨越多个交付物、专业 Skill 或会话时，在当前对话中持续保留已确认的目标、方向、参考材料、时长和约束；不要创建 Brief、参考包、Clip 计划、ID 或状态对象。

### 执行

先完成 `video-prompt`。用户明确要求使用 SeaArt 生成时，再交给可选的 `seaart-execute` 适配器。

没有已配置的执行适配器时，停在可直接使用的 Prompt；不要虚构生成结果、模型能力或任务状态。只有用户明确要求现在用 SeaArt 执行时，才调用 `seaart-execute` 检查 SeaArt CLI 与 MCP 是否已配置。

## 路由选择

- 叙事概念或剧本用 `video-story`。
- 电商或转化导向概念、剧本用 `video-ecommerce`。
- 镜头设计、时长判断、Clip 组合、节奏、资产绑定或连续性用 `video-storyboard`。
- 最终视频生成 Prompt 用 `video-prompt`。
- 只有角色、产品、道具、场景、声音或品牌元素需要跨输出稳定时才用 `asset-reference`。
- 所需图片创作或编辑通过 `image-create`；把已确认的参考材料、名称与锁定特征带回视频工作。
- 视频的视觉设计问题或方向未定，且需要先分析体验、传播或叙事目标时，用 `art-direction`；确认方向后再继续对应视频专业 Skill。

## 标准创作链路

需要从视频想法、剧本或已确认方向推进到可生成 Prompt 时，使用：

`video-create -> video-storyboard -> video-prompt`

`video-story`、`video-ecommerce`、`asset-reference` 和 `art-direction` 只在当前任务需要其专业判断时插入，不改变这条主链路。用户明确要求 SeaArt 真实生成时，再由 `video-create` 将完成的 Prompt 交给 `seaart-execute`。

## 项目判断

不要把视频任务机械拆成固定阶段。先判断当前缺的是哪一种东西：

- 没有核心表达、冲突或卖点时，先做概念；
- 有概念但没有可拍动作、对白或场景因果时，先做剧本；
- 有剧本但没有镜头职责、Clip 边界或连续性时，做分镜；
- 有就绪画面计划但没有生成指令时，编译 Prompt；
- 只有真实执行才进入执行层。

用户可以从任一阶段进入，也可以只要其中一段。已有剧本、分镜、参考素材或生成画面是约束，不是重新发散的起点。

## 协作

信息允许时，推荐清晰专业的方向。只有缺失回答会改变分支、精确表达、身份、交付、来源角色、实质创意决定、成本或外部动作时才提问。

用户修改更早的产物时，只更新受影响内容，并指出可能已过期的下游产物。没有必要时不要重做。

续接时，先检查已有剧本、参考材料、分镜、Prompt 和已生成结果，再继续。复用有效产物，并从用户要求的位置继续。

## 完整项目

完整项目可经过概念或剧本、可选参考提取、分镜、Prompt 编译和执行，但它们是可用能力，不是强制审批阶段。只确认实质创意决定和精确外部执行范围。

只要 Prompt 的工作可以在不等待生成画面的情况下编译完整计划 Prompt 集。后续续接必须使用已观察并接受的结果，不能凭空假定终态。

## 成果检查

每次交付前确认它能推动下一个真实动作：概念能指导剧本，剧本能被分镜，分镜能被生成，Prompt 能被执行。不能推动下游的漂亮描述应压缩或删除，不要把它当作阶段产物。

## 检查

- 路线完成用户当前要求的交付物。
- 没有无必要增加阶段、对象、文件或审批。
- 已确认的信息、资产、时长、比例和约束得到保留。
- 已有产物被复用而不是重建。
- 外部工作只在用户当前明确提出生成或解析时进行。
- 当前产物有明确用途，没有把尚未需要的制作信息提前塞入。
