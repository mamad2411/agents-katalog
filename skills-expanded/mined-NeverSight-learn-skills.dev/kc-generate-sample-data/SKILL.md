# 가상 샘플 데이터 생성하기

검증하거나 시연할 행동에 필요한 가상 데이터만 만들고 실제 자료와 명확히 구분한다.

## 진행

1. 사용할 화면이나 테스트, 대상 스키마, 업무 규칙과 저장 형식을 확인한다. 기존 타입·마이그레이션·fixture가 있으면 실제 구현 구조를 따른다.
2. 시각적 시연, 사용자 흐름 확인, 경계값 테스트 또는 import 검증 등 목적에 맞춰 데이터 양과 다양성을 정한다.
3. ID, 관계, 상태, 날짜, 금액과 수량이 서로 모순되지 않게 만든다. 테스트 재현이 중요하면 기준 날짜와 생성 규칙을 기록한다.
4. 실제 개인정보, 회사명, 내부 코드, 가격, 문서와 운영 URL을 복사하거나 변형하지 않는다. 사람과 조직은 가상임이 분명해야 하며 이메일은 예약 도메인을 사용한다.
5. 비밀번호, 토큰, API 키와 실제 비밀값처럼 보이는 문자열을 만들지 않는다.
6. 저장 가능한 정상 데이터와 의도적으로 실패시킬 입력을 분리한다.
7. 복잡한 QA 데이터가 필요할 때만 [생성 규칙](references/generation-rules.md)의 추가 품질 기준을 참고한다.
8. 기존 파일이나 데이터베이스를 덮어쓰거나 클라우드에 입력하기 전에는 대상과 영향을 확인한다.
9. 목적에 필요한 스키마 적합성, 관계, 업무 계산과 안전성을 검증한다. 파일을 만들었으면 실제 소비자가 읽을 수 있는지 확인한다.

## 완료

생성 목적, 데이터 종류와 수량, 저장 위치, 확인 결과와 아직 반영하지 않은 항목을 보고한다.
