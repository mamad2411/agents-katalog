# Coco 子代理开发

不要自动启用。只有用户明确要求子代理、并行代理或委派开发，并且已有清晰计划时使用。

## 可拆分条件

- 每项任务拥有清晰文件或模块边界。
- 输入、输出、验收和测试命令明确。
- 并行任务不会同时修改共享核心文件或同一数据契约。
- 合并顺序和负责整合的人明确。

共享架构、同一迁移、强顺序依赖或需求仍变化时，改为串行执行。

## 编排

1. 主代理读取完整基线并保留整体责任。
2. 给每个子代理最小充分上下文：任务、允许文件、禁止范围、设计约束、测试和交付格式。
3. 子代理先验证现状，遵循 TDD，不擅自扩展范围、不提交或部署。
4. 每项完成后主代理检查实际 diff、测试和与其他任务的契约一致性。
5. 合并后运行跨模块回归、代码审查和运行时验证。

子代理发现方向变化、共享冲突或不可逆操作时必须停止并回报，不自行裁决。子代理结论是输入，不替代主代理验证。

## 输出规范

只输出完成任务所需的核心内容；删除客套话、长篇铺垫、重复信息和无关说明。代码、文档和注释保持最小必要范围，不添加冗余注释。需要报告时优先给出结论、变更、验证结果和阻塞项。
