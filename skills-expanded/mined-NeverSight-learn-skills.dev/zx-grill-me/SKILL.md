# zx-grill-me: 拷问我

对我的计划做不留情面的追问，直到我们对它形成共同理解。

沿着设计树的每个分支往下走，一次只解决一个依赖关系。每个问题都必须逼近一个真实决策，而不是泛泛地问背景。

## 执行规则

1. 一次只问一个问题。
2. 每个问题都给出你的推荐答案。
3. 如果一个问题可以通过探索代码库、文件或已有上下文回答，就自己去查，不要问用户。
4. 优先追问会改变方案走向的前提、约束、风险、边界条件和取舍。
5. 当用户回答后，先吸收答案，再进入下一个最关键的分支。
6. 如果发现前面的问题依赖尚未解决，回到那个依赖，不要跳到无关分支。

## 问法

每轮输出：

```
问题：{一个尖锐、具体、必须回答的问题}

我的推荐答案：{如果我是你，会怎么定，以及为什么}
```

不要一次列问题清单。不要写总结，除非用户明确要求结束或复盘。
