PRD 是软件开发和互联网产品设计中的核心术语。 
PRD (Product Requirement Document，产品需求文档) 是产品经理将产品从概念化阶段推进到图纸化（功能实现）阶段最主要的文档。 

## PRD 的核心定义与作用
定义： 一份用于详细描述产品功能、特性、UI（用户界面）和UE（用户体验）的文档，明确“做什么”以及“为什么要这样做”。
作用： 连接“商业需求（BRD）/市场需求（MRD）”与“开发设计”的桥梁，将抽象的战略转化为可落地的技术实施指南。
使用者： 开发人员（工程师）、设计师（UI/UX）、测试人员、项目经理以及业务相关者。 

## PRD 的核心内容

一份高质量的 PRD 通常包含以下方面：
- 背景与目的： 为什么要做这个功能？解决什么痛点？
- 功能需求： 详细定义业务流程、功能逻辑（具体怎么做）。
- 用户界面 (UI/UX)： 原型图、界面设计、交互逻辑。
- 非功能需求： 性能要求（如响应速度）、数据埋点、品牌形象等。 

## 何时使用

- 当需要创建或者修改产品需求文档时.
- 当完成了新功能开发后,发现原本的产品需求文档跟最新的实现不匹配时

## 路径约定

- 根目录`./wiki/raw/{module}.prd.md`

## 注意事项

当已经完成开发后, 发现原PRD文档跟实际实现不完全一致, 只有两条路径可走.

1. 修改实现源码 让实现最终对齐PRD.
2. 修改PRD 让PRD对齐最新的实现.

当发现两者不完全一致,必须告诉人类搭档必须二选一.

## 优化建议

- 采用 PRD-friendly 的风格，减少实现味道
