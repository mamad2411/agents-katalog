# Phaser 4 技术架构

建立可维护、可测试、可构建的边界，并显式处理小游戏、iOS、Google Play 的差异。

## 输入与边界

快速通道仅读取任务直接相关的代码、配置和测试；标准、发布通道读取 docs/project-profile.yaml、docs/GDD.md、docs/TDD.md、docs/control-plane.md，渠道进入候选后才读取平台矩阵。新建或改变模块边界时，读取总控 references/module-decomposition.md，提交候选模块图并等待总控完成强制拷问；其他技术路线、平台适配、依赖或质量指标需要取舍时，提交简短决策包。

- 用 Phaser 4、TypeScript、Vite 实现 Web 核心；新项目优先采用官方当前的 create-phaser-game 流程。
- 用 Capacitor 承载 iOS 与 Android，将原生插件封装在平台适配层。
- 小游戏必须单独验证；可选商业能力须有显式接口和已批准开关。

## 执行与交接

1. 在实现前划分模块，记录职责与非目标、公开输入/输出、状态所有权、生命周期、允许/禁止依赖、失败边界、测试和实现顺序；总控拷问并获人工批准后，才在 TDD 将模块标为“已批准待实现”。
2. 仅实现已批准模块；发现需要新增模块，或改变职责、契约、状态所有权、依赖方向、持久化/平台边界时立即停下受影响实现，重新划分并拷问。
3. 建立唯一的无交互背景适配器或场景基类：竖屏固定按高度等比缩放并水平裁切/延展，横屏固定按宽度等比缩放并垂直裁切/延展，同时使用批准焦点和防取整露边策略；覆盖创建、唤醒、恢复、方向与画布尺寸变化。每个可见场景只声明竖屏/横屏背景资源或程序化方案，不复制适配公式。
4. 分离核心规则、表现、平台和第三方服务；为触控、安全区、暂停恢复、后台切换和断网定义验证策略。
5. 在 TDD 定义本地服务身份、默认模式、主机/端口和健康检查。启动开发或预览服务前检查监听进程、命令行、项目根目录与健康状态；身份一致且健康时直接复用，不得重复启动。
6. 完成最小骨架和生产构建后，标准、发布通道向总控提交一条证据或阻断项，由总控更新控制面；快速通道以构建和测试结果作为交付证据。

交给玩法开发模块入口、数据流和测试入口；交给测试提供构建命令、版本和日志定位方式。新增或修改的类、函数、实体定义均添加解释设计边界的简体中文注释。
