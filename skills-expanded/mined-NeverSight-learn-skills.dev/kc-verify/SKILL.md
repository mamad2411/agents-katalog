# 서비스 검증하기

완료 조건을 실제 동작과 증거로 확인하며 검증 중 제품을 변경하지 않는다.

## 진행

1. 프로젝트 컨텍스트와 현재 동작에서 검증할 완료 조건을 찾는다.
2. 로컬, 미리보기 또는 운영 중 대상 환경과 이번 검증 범위를 명시한다.
3. 변경 범위와 실패 위험에 맞는 시나리오를 선택하고 기대 결과와 실제 증거를 함께 기록한다.
4. 가능한 경우 실제 사용자가 시작할 화면에서 관련 행동을 끝까지 수행하고 화면 결과와 데이터 효과를 확인한다.
5. 수정 검증에서는 원래 실패한 행동과 영향을 받을 기존 행동을 확인한다.
6. 모바일, 비로그인 접근, 직접 URL, API, 데이터 권한과 예외는 해당 제품이나 변경에 관련될 때만 검사한다.
7. 비밀값, 실제 개인정보, 내부 운영 기능의 무단 공개와 사용자에게 노출되는 원시 오류를 관련 범위에서 확인한다.
8. 직접 확인한 항목만 `통과`로 표시한다. 실행할 수 없는 항목은 `미확인`, 기대와 다르면 `실패`로 남긴다.

## 완료

통과·실패·미확인 항목, 근거, 배포나 완료를 막는 문제와 가장 작은 다음 행동을 보고한다. 배포는 사용자가 요청할 때 별도로 진행한다.
