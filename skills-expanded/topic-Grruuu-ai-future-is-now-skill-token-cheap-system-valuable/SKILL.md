# Token 越便宜，围绕它的系统越值钱

## R — 原文 (Reading)

> 因此，CEO请先记住一句话： Token越便宜，围绕它搭建的那套系统就越值钱。 很多AI产品在演示时很惊艳，但在落地应用时却容易翻车，原因也在这里。模型能力到位了，但模型和业务之间的配套系统没建起来。
>
> — 李开复，第4章《Token的价格在崩塌，账单数字在上涨》

> 管理层把预算都压在Token上，却不搭建配套系统的企业，和仅仅换上电动机却不去改造厂房的工厂主，犯的是同一个错误。
>
> — 李开复，第4章

> 这就是"杰文斯悖论"：技术进步不会让需求收缩，而会打开被压抑的需求空间。
>
> — 李开复，第4章《杰文斯悖论：越便宜，用得越多》

---

## I — 方法论骨架 (Interpretation)

两件事正在同时发生：单位智能的价格垂直下落，模型的能力持续上升。多数人从第一件事推出"AI 预算可以少编一点"，这个推论是错的，错在两层。

**第一层是需求侧（杰文斯悖论）**：效率提升不会让消耗收缩，它会打开被压抑的需求空间。瓦特改良蒸汽机让每台机器烧的煤更少，但英国的煤炭总消耗反而涨了三十多倍——因为蒸汽机走出了矿区，纺织厂、面粉厂、铁厂、印刷作坊都有了新的动力选项，而在几年前它们压根没有这个选项。AI 同理：当调用成本降到原来的 1% 以下，"值不值得"的门槛在大多数场景下消失了。原本只在合同终审阶段才做的分析，现在每次版本迭代都能做；原本只有 VIP 客户才有的个性化回复，现在可以覆盖全部客户。

**第二层是成本结构侧**，这是本框架真正的落点：Token 只是 AI 投入中最小的一部分。打通数据、校验输出内容、跟踪版本、按任务难度匹配模型、流程改造、人员配套，才是真正要花钱的地方。历史上最早从电力革命中获益的工厂，主要投入不是电费，而是重组厂房、更换设备、培训工人、重新设计生产流程。

所以正确的动作不是"调低预算"，也不是简单"调高预算"，而是**调整预算的结构**：Token 占比下降，围绕它的系统占比上升。把预算全压在 Token 上却不建配套系统，等同于只把蒸汽机换成电动机、却让厂房里那套传动轴和皮带系统原封不动——那不是电气化，只是换了个动力来源，而原有生产体系的所有局限都保留了下来。

还有一个时间尺度的提醒：作者判断平均每过一个季度，完成同样一项认知工作的费用就会减半。对习惯以年为单位编预算的组织，这意味着**年初制定的 AI 预算，到年中可能就需要整体调整**。

## A1 — 书中的应用 (Past Application)

### 案例 1：瓦特改良蒸汽机之后，英国的煤炭消耗反而涨了三十多倍
- **问题**：1865 年杰文斯观察到一个悖论——蒸汽机的煤炭利用率大幅提升了，但英国的煤炭总消耗量不降反升。
- **方法论的使用**：最早的纽科门蒸汽机能量使用率不到 1%，只能在矿井边使用，因为燃料唾手可得、运输成本几乎为零。瓦特改良之后，蒸汽机走出了矿区：纺织厂不用再依附水流选址，面粉厂、铁厂、印刷作坊都有了新的动力选项。
- **结论**：用煤更合算了，用煤的人多了，用煤做的事更多了，最终烧掉的煤自然也更多了。
- **结果**：英国煤炭年产量从 1700 年前后约 280 万吨，到 1800 年约 1000 万吨，到 1865 年已接近 9500 万吨——约一个半世纪增长超 30 倍。

### 案例 2：电动机进工厂 40 年后，生产率才真正提升
- **问题**：电动机早在 19 世纪 80 年代就进了工厂，但工厂生产率直到 20 世纪 20 年代才提升，中间隔了整整 40 年。电并不贵，工厂也早早通了电。
- **方法论的使用**：斯坦福经济学家保罗·戴维在《计算机和发电机》中查明——当时的工厂一开始只做了一件事：把蒸汽机换成电动机，而厂房里那套蒸汽时代的传动轴和皮带系统原封没动。
- **结论**：这不是真正的电气化，只是换了个动力来源，原有生产体系的所有局限都保留了下来。真正的转变发生在工厂彻底重组之后：每台机器装上独立电机，厂房布局围绕新逻辑从头设计，工人职责也变了。
- **结果**：工厂完成重组后，美国制造业年均生产率增速超过 5%。40 年，就是为了把一项技术从"接入"变成"真正用起来"。

### 案例 3：三家公司的 Token 用量
- **问题**：如果降价会减少支出，那么领先企业的账单应该在缩水。
- **方法论的使用**：作者直接看用量数据。
- **结论**：谷歌旗下产品和 API 每月处理的 Token 量，两年增长约 330 倍；OpenAI 披露每家企业组织的 API 推理 Token 消耗量 12 个月内平均增长约 320 倍；字节豆包日均 Token 使用量两年增长超 1000 倍。
- **结果**：杰文斯悖论在真实运营数据里得到验证。作者的推论是：为智能制定的预算，很可能在两年内就因为场景扩张而显得过于保守。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 在编制下一年度 AI 预算，看到模型单价大幅下降，考虑要不要下调预算。
2. 单价明明在跌，AI 账单却在涨，需要向 CFO 或董事会解释这是否正常。
3. 已经买了模型/接了 API，但落地一直翻车，怀疑是不是买少了或买错了。
4. 在决定 AI 投入的钱该分配到哪些科目上。
5. 在做多年期的 AI 投入规划，需要判断成本曲线走向。

### 语言信号

- "模型降价了，明年 AI 预算是不是可以砍"
- "调用成本降了这么多，为什么账单还在涨"
- "我们 AI 预算该怎么定"
- "这笔钱该花在哪"
- "要不要趁便宜多买点算力"
- "演示的时候很惊艳，落地就翻车"

### 与相邻 skill 的区分

- 与 `headcount-to-compute` 的区别：本 skill 解决**预算结构**（钱怎么分到 Token 和配套系统上）；那个解决**组织计价体系**（把算力当成本科目、薪酬按业务重要性、董事会看哪三个指标）。前者是财务问题，后者是组织制度问题。
- 与 `earnings-call-test` 的区别：那个判断某个项目值不值得做；本 skill 判断整体预算怎么编。
- 与 `ai-decision-core` 的区别：本 skill 说"配套系统很值钱"；那个说"配套系统具体由哪四块组成"。本 skill 是它的预算论证。

## E — 可执行步骤 (Execution)

1. **先确认方向：不要下调总预算**。用杰文斯悖论核对——过去一年里，有哪些场景是因为"太贵"而被搁置的？把它们列出来。
   - 完成标准：得到一张"曾因成本被否决的场景"清单。
   - 判停条件：如果这张清单是空的，说明你的组织可能还没到成本约束这一层，本 skill 的紧迫性下降，先回到 `earnings-call-test` 找值得做的场景。

2. **拆开当前的 AI 支出结构**，按四类归集：
   - Token / 推理调用费
   - 数据打通与治理（接系统、清洗、权限）
   - 输出校验与版本跟踪（怎么知道它答对了、模型换代后怎么回归测试）
   - 流程改造与人员配套（培训、岗位调整、外部落地伙伴）
   - 完成标准：四类各有一个金额和占比。
   - 判停条件：若 Token 占比过半 ⇒ 结构失衡，你正在犯"只换电动机不改厂房"的错误。

3. **按"Token 降、系统升"重编结构**。原则不是把总额压下来，而是把省下来的单价红利转移到后三类上。同时保留场景扩张的空间——预期用量会因为门槛消失而大幅增长。
   - 完成标准：新预算里后三类的合计占比高于 Token。

4. **把预算周期从年改成半年或季**。作者的判断是同等智能水平的成本大约每季度减半，年初的数字到年中就可能失真。
   - 完成标准：预算文件里写明复核节点和触发重编的条件（例如"单价下降超过 50% 或用量超出预期 3 倍时重编"）。

5. **准备好对 CFO/董事会的说法**：单价在跌、用量在涨、账单在涨，这三件事同时成立且是健康的；真正该问的不是"为什么涨"，而是"涨出来的部分撬动了什么"。
   - 完成标准：能用一句话把账单增长和某个业务结果挂上钩。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户要的是一次性报价计算（"处理 10 万份文档要多少钱"）——那是算术，不是预算结构判断。
- 用户在比较两家供应商的单价或某个模型的技术参数。
- 组织的 AI 使用还停留在个人订阅层面，没有企业级支出结构可拆。
- 现金流紧张、必须在本季度砍成本的企业——本 skill 建议的是结构性再投入，对它们是错误建议。

### 作者在书中警告的失败模式

- **只买 Token 不建配套系统**（换电动机不改厂房）——全书点名的预算错误。
- **用"控制用量"的旧逻辑管 AI**：作者明确说，在智能趋向丰裕的今天，"把智能留给最重要的任务"这个逻辑已变成一种自我设限。
- **把 AI 转型当成一道采购题**——"买多少 Token、用哪个模型"这个层面的预算逻辑，本身就是错的问法。

### 作者的盲点 / 时代局限

- **-99.4% 是作者自选基准算出来的**：2024 年 3 月的 Claude 3 Opus 对比 2026 年上半年的 DeepSeek-V4-Flash。换一组基准模型，降幅会显著不同。斯坦福 HAI 的口径（GPT-3.5 水平、2022-11 到 2024-10、降幅超 99.6%）是另一条基准线。**不要把 99.4% 当成可以直接代入自己预算的常数**。
- **作者自己承认前沿模型的训练总投入仍在增加**。推理成本坍塌与训练成本上涨是两条曲线；如果供应商把训练成本转嫁到定价上，或行业集中度上升，单价下降的趋势可能中断。
- **杰文斯悖论的成立以"需求空间未饱和"为前提**。在受监管配额约束（如金融风控的人工复核比例）、人力编制刚性、或客户根本不接受 AI 参与的场景里，价格再降需求也不会释放，本 skill 的核心推论不成立。
- **"每季度减半"这一断言的时间窗很短**（2024–2026 两年数据外推）。它同时依赖"规模定律持续有效"这个全书隐含前提；一旦模型能力增长放缓，厂商的降价动机也会随之减弱。
- **书中不谈配套系统投入的失败风险**。它论证了配套系统很值钱，但没有一个"配套系统建了却没用起来"的案例——而这恰恰是最常见的结局（作者自己在第 6 章讲的"数据坟墓"就是上一代配套系统的残骸）。

### 容易混淆的邻近方法论

- 与 FinOps / 云成本优化不同：那是压降单位成本，本 skill 恰恰主张不要把注意力放在压单价上。
- 与 TCO（总拥有成本）分析形似但落点不同：TCO 是为了算清总账做采购决策，本 skill 是为了重新分配预算结构。
