# Real-World Vulnerability Reproduction Project

This repository documents a series of technical reproductions of real-world vulnerabilities that were originally reported through bug bounty programs or public disclosures. The goal is to bridge the gap between theoretical knowledge and practical exploitation by studying how actual bugs were discovered, exploited, and remediated.

Each report in this repository walks through the process of understanding, setting up, and reproducing a vulnerability in a safe, controlled environment. Accompanying each write-up are proof-of-concept payloads, screenshots, and contextual explanations designed to make the reproduction process educational and accessible.

---

## Project Objectives

- Develop a deeper understanding of real-world web vulnerabilities
- Practice reproducing practical bug bounty findings in safe environments
- Improve technical writing and reporting skills
- Understand the logic behind vulnerabilities, not just their symptoms

---

## What You’ll Find

This repository includes:

- 📂 `reports/`: Individual vulnerability reproductions presented as case studies  
- 📎 `resources.md`: Links to original bug bounty disclosures and technical documentation  
- 📁 `targets-used.md`: Details of safe environments and labs used for testing (e.g., DVWA, Juice Shop)

Each report contains:

- Context and summary of the original bug
- In-depth explanation of the vulnerability type
- Setup and reproduction instructions
- Screenshots, payloads, and proof-of-concept files
- Impact analysis and mitigation recommendations

---

## Methodology

For each vulnerability:

1. **Read the original disclosure**: Understand the business context, vulnerability details, and impact.
2. **Set up a safe lab environment**: Using platforms like DVWA, PortSwigger Labs, or custom setups.
3. **Reproduce the bug**: Step-by-step replication with payloads and screenshots.
4. **Analyze the cause**: Investigate the flawed logic or insecure implementation.
5. **Report**: Document everything with clarity, structure, and educational value.

---

## Intended Audience

This project is valuable for:

- Aspiring penetration testers and red teamers
- Bug bounty hunters
- Students preparing for infosec interviews
- Developers and engineers looking to understand common security flaws

---

## License & Disclaimer

This repository is intended for **educational and ethical use only**. All reproduced vulnerabilities are tested in safe, non-production environments. Never attempt these techniques on live systems you do not own or have permission to test.

---

## Get Started

Explore the `reports/` directory to begin.  
Each folder contains a complete, self-contained case study of a real-world vulnerability.
