诊断这次工作怎样取得结果、哪些投入有价值、哪些做法拖累了推进，以及下次先改什么。从用户指定的问题和范围出发，按需读取能支撑判断的运行证据。

Respond and write reports in the language of the user's current request unless they specify another language. Keep source quotations, paths, identifiers and tool arguments verbatim; the language of this skill or the logs does not set the report language.

## 从轨迹树或 Eval 的选区开始

从草稿的查询开始，保留其会话、切点和来源绑定；沿返回的续查入口读与问题有关的原文。选中多轮时对照关键转折，圈选多个调用时核对匹配范围。已有数据足以支持判断就直接分析，不为收齐各类指标补跑查询。历史图表的切点无法校验时重新取得选区。

按用户关注点串起行动、反馈和实际结果，引用关键记录。沿工具给出的计量口径使用数据；仅在覆盖缺口影响结论时说明。

## 综合诊断

**把任务、过程和结果放在一起。** 先确认用户要求的产物、关键约束和验收条件，再看实际交付及验证。按工作目的或关键状态变化划分阶段（如定位、实现、验证、恢复），区分需求变化带来的新增工作、任务本身的复杂度和可以避免的返工。将模型声称的完成状态与实际产物、验证输出逐项核对。

**看投入怎样变成进展。** 对照阶段投入和关键转折：是否获得决定性信息、排除不可行路线、形成可用产物或完成必要验收。既排查单次长阻塞，也排查贯穿多轮的短等待、重复供给和恢复负担。

**从现象追到可调整的原因与出口。** 围绕同一问题串起“当时掌握什么—采取什么动作—收到什么反馈—如何处理—结果如何”。从明显损失往前追，定位最早有机会改变走向的环节：前提缺失、工具选择或参数、反馈利用、状态交接、环境限制或晚验证。用相近的成功尝试或前后阶段作对照，按[处置与知识保留](references/disposition.md)将结论收口到明确的诊断出口：

1. **无需处置**：属于正常探测（如搜索未命中）、同轮已低成本自愈且无副作用，或用户主动取消/拒绝审批且后续已顺从停止，直接引用证据结案。
2. **修环境与实现**：落到项目自有代码、脚本、工作区配置或运行环境的最小修改与验证。**宿主官方工具的语义、参数契约、权限与保护机制是固定约束，严禁建议修改官方工具实现或工具说明。**
3. **恢复与观察**：盘点半成品副作用，给出符合保护契约或工作区边界的下一步安全调用。
4. **启停或补齐能力**：优先利用已加载能力；涉及宿主官方或扩展工具的启停（开启或关闭）时，**先阐述清楚该工具承担的职责、主流用途与低频兜底场景，明确用户的真实需求后再给出关闭或启用意见（只通过配置启停工具，绝不改动工具语义）**。
5. **保留可复用方法**：短约束与项目约定更新到 `AGENTS.md`（优先改写或合并过期冲突条款），多步专项流程沉淀到按需加载的 Skill。

涉及供给缺口、重复说明或过期知识时，按[上下文持续使用](references/context.md)核对当时实际可见的材料。当前静态配置由 `context-profile` 分析。

### 验证改法

回顾历史问题先沿已有后续记录核对是否已解决并通过验收。验证新改法时，明确应保持的任务结果和预期减少的负担，在**原执行器、原工作目录和实际生效的配置作用域**下复跑原失败路径；涉及能力启停或通用规则时，同时用正常任务与边界场景对照验证完成质量、耗时与总开销。

## 专项方法

只读取当前问题需要的方法；涉及多个因素时联合分析。

| 深入的问题 | 方法 |
| --- | --- |
| 时间被什么挡住，怎样更早取得结果 | [耗时与等待](references/latency.md) |
| 哪些投入持续增加开销，怎样保留能力地调整 | [用量与能力投入](references/cost.md) |
| 尝试有没有进展，反馈为何没有被用上 | [反复尝试](references/repeats.md) |
| 查找、读取、修改是否支持了正确判断 | [工具与文件使用](references/io.md) |
| PowerShell 命令为何报错，调用怎么改和验证 | [PowerShell 命令诊断](references/powershell.md) |
| 命令或脚本在哪层失败，后来解决了吗 | [代码执行诊断](references/code-execution.md) |
| 材料如何保留、更新和恢复，是否支持后续工作 | [上下文持续使用](references/context.md) |

需要交付报告时，按[报告写作](../../report/WRITING.md)组织。
