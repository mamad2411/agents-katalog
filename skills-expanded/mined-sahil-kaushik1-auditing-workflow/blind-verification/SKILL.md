# Blind Verification Skill

## The Core Principle

The Verifier must not be contaminated by the Reasoner's persuasive prose.
If the Verifier reads the Reasoner's full chain-of-thought, it becomes a
re-validator, not an independent verifier. That breaks the independence guarantee.

## Normalizer Step (Orchestrator runs this)

Before invoking the Verifier for `TASK-{N}`, the Orchestrator creates a
stripped claim file by extracting ONLY the following from the reasoning artifact:

### What to Extract

From `specs/reasoning/TASK-{N}-reasoning.md`, extract ONLY:

```
1. Claim Type:
   - "vulnerability" if Reasoner claims bug exists
   - "safety" if Reasoner claims no bug

2. Claim Statement:
   - One sentence. No reasoning prose.
   - BAD:  "The withdraw function fails to update the share price before calculating
           the user's entitlement, which I traced through the execution path and..."
   - GOOD: "withdraw() can be called to extract assets at a stale share price."

3. Attack Path (if vulnerability):
   - Numbered steps only. No explanation of WHY each step works.
   - 1. Attacker calls deposit() with 1 wei
   - 2. Attacker calls withdraw() in same block
   - 3. Share price not updated → attacker receives excess assets

4. Required Proof Type:
   - Copied from task.verification_tools field (NOT from Reasoner's suggestion)

5. Failure Predicate:
   - Copied verbatim from task file (NOT paraphrased from Reasoner)

6. Out-of-Scope Cases:
   - Copied verbatim from task file
```

### What to Strip (Never Include)

```
✗ Reasoner's execution trace ("I traced through the code and found...")
✗ Reasoner's state analysis ("The state variable X is updated when...")
✗ Reasoner's explanation of WHY the path is vulnerable
✗ Reasoner's confidence level or hedging language
✗ Any reference to the Reasoner's prior assumptions
✗ Code snippets selected by the Reasoner (Verifier should find these independently)
```

### Output: Claim File

Write to `specs/verification/TASK-{N}-claim.md`:

```markdown
# Claim File — TASK-{N}
# Generated by Orchestrator Normalizer — DO NOT MODIFY
# Verifier reads ONLY this file (not the full reasoning artifact)

## Claim Type
vulnerability | safety

## Claim Statement
{one sentence, no reasoning prose}

## Attack Path
1. {step}
2. {step}
3. {step}

## Required Proof Type
{from task.verification_tools}

## Failure Predicate
{verbatim from task file}

## Out-of-Scope Cases
- {list from task file}
```

## VerifierAdapter INPUT CONTRACT

The Verifier receives EXACTLY these inputs, no more:

```
ALLOWED INPUTS:
  ✓ specs/tasks/TASK-{N}.md          (full 19-field task)
  ✓ specs/verification/TASK-{N}-claim.md   (normalized claim only)
  ✓ specs/reasoning/TASK-{N}-skeptic.md    (skeptic verdict line only)
  ✓ [source code file paths from task]    (raw contracts, no commentary)

BLOCKED INPUTS:
  ✗ specs/reasoning/TASK-{N}-reasoning.md
  ✗ Any file containing the Reasoner's analysis prose
  ✗ Previous verification artifacts for this task
```

## VerifierAdapter OUTPUT CONTRACT

The Verifier's output must contain:

```
REQUIRED OUTPUT FIELDS:
  verdict:                  CONFIRMED | REFUTED | INCONCLUSIVE | SKIPPED-SKEPTIC-KILLED
  evidence_type:            foundry_poc | invariant_test | fuzz | symbolic | manual_trace
  tool_output:              actual forge/echidna/halmos output (not paraphrased)
  gate_results_table:       10-gate checklist (for CONFIRMED findings)
  violated_invariant:       string | null
  balance_delta:            string | null  (e.g., "attacker gains 500k USDC")
  counterfactual_tested:    true | false
  caveats:                  list of verification limitations
  independent_reasoning:    why THIS verdict (independent of Reasoner's prose)
```

## Enforcement Check

Before submitting a verification artifact to the Judge, confirm:
- [ ] Verifier did NOT cite the Reasoner's execution trace
- [ ] Verifier ran at least one deterministic tool (forge/echidna/slither)
- [ ] PoC was run 3 times for CONFIRMED (determinism check)
- [ ] Gate results table present for CONFIRMED findings
- [ ] `independent_reasoning` section explains verdict without referencing Reasoner
