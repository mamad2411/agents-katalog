# 视频发布三件套

把一个已翻译或已成片的视频，包装成可投稿的 **标题 + 简介 + 封面**。默认平台是 B 站长视频；用户指定 YouTube、西瓜、视频号时按其限制调整。

## 硬性规则
·
1. **不翻译、不转写、不剪辑、不上传。** 输入必须是已有视频、字幕、转写稿或项目元数据。
2. **事实只来自材料。** 标题和简介不得发明视频中没有的观点、数据、冲突或结论。
3. **三次确认门：**
   - 封面帧候选确认；
   - 标题和简介确认；·
   - 封面文字确认。·
   用户明确说“直接做”“不用确认”时可跳过对应门。
4. **封面字不是标题。** 主文字通常 4–10 个汉字；最多一行小字补充语境。不在封面上塞完整标题。
5. **主体优先，4:3 只做参考。** 如果平台可能裁成 4:3，先检查文字是否会被裁掉；但绝不能为了塞进 4:3 而把字压到人脸、眼镜、嘴部或关键动作上。冲突时换帧、移动文字或放弃 4:3 硬约束。
6. **可点击但不欺骗。** 可以突出冲突、问题、人物或关键事实，不能断章取义。

## 输入

按优先级收集：

| 材料 | 用途 |
|---|---|
| 翻译后视频路径 | 抽帧、核对时长和画面 |
| 原始无字幕视频 | 封面抽帧优先用它，避免字幕压字 |
| SRT / VTT / 转写稿 | 提取核心话题、争议点、关键问句 |
| BaoCut / 剪辑项目元数据 | 标题、来源、章节、说话人、原描述 |
| 平台与受众 | 决定文案长度、语气和风险边界 |
| 用户指定帧 / 文案 | 覆盖自动候选 |

缺材料时只询问会阻塞当前阶段的问题；不要一次索要全部。

## 工作流

### 1. 建立内容简报

读可用材料，写 `<视频目录>/publish/01_content_brief.md`：

```markdown
# 内容简报

## 一句话内容
[用一句话说明视频真正讲了什么。]

## 核心人物 / 产品 / 机构
- [必须出现在标题、简介或封面语境中的实体。]

## 5 个强相关点
1. [具体观点、争议、故事或事实]
2. [ ... ]

## 最有点击力的 3 个问题
1. [观众看完会关心的具体问题]

## 不进标题 / 封面的内容
- [夸大、未确认、离核心太远的内容。]
```

只保留能在材料中找到依据的点。

### 2. 抽封面帧候选

优先从原始无字幕视频抽帧；只有原始视频不可用时才用翻译后视频。

```bash
python3 scripts/make_cover.py frames \
  --video "/path/to/original.mp4" \
  --out-dir "/path/to/video/publish/03_frame_candidates" \
  --contact-sheet
```

可用 `--timestamps "00:07:55,00:12:05,00:37:10"` 指定位置。

给用户看 contact sheet 或 3–6 张单帧，并说明推荐理由：人物清晰、有留白、能承接封面字、不压脸、没有字幕水印干扰。**等用户选帧。**

### 3. 写标题和简介

写 `<视频目录>/publish/02_title_description.md`，必须给出候选，而不是只给一个终稿。

#### 标题

给 5–8 个候选，分四类：

| 类型 | 用法 |
|---|---|
| 推荐 | 兼顾搜索、内容和点击 |
| 争议/问题 | 突出视频里的真实冲突或尖锐提问 |
| 人物/作品 | 突出关键人物、公司、产品或系列 |
| 稳重完整 | 适合长视频、知识区和搜索流量 |

规则：

- B 站标题默认不超过 40 个汉字；
- 前 12–20 字要说清最关键的信息；
- 使用具体名词：人物、公司、产品、事件、领域；
- 模糊词如“终局”“震撼”“颠覆”只有在视频明确支撑时才可用；
- 不用完整封面长句当标题。

#### 简介

给两个版本：

```markdown
## A. 完整简介
[3–6 段：视频内容、关键问题、看点、时间轴、来源说明。]

## B. 短简介
[120–220 字，直接说明观众会看到什么。]
```

如材料里有章节时间轴，附时间轴。搬运/翻译内容必须保留来源和版权提示；不要帮用户规避平台规则。

**等用户确认标题和简介。**

### 4. 确认封面文字

基于已选帧给 3–5 组封面文字。每组只写：

```markdown
| 方案 | 主文字 | 小字 | 为什么能点 |
|---|---|---|---|
| A | Claude 被用于战争？ | Anthropic CEO 回应 | 对应真实争议段 |
```

封面文字规则：

- 主文字 4–10 个汉字最佳；
- 最多一个小字，通常 8–16 字；
- 主文字必须指向视频中的真实内容；
- 关键名词或矛盾词用高亮块；
- 不用“终局”“颠覆”“震撼”这类无具体所指的词，除非材料本身明确支撑；
- 不遮挡人脸、眼镜、嘴部或关键动作；
- 先考虑 320x180 缩略图是否仍可读。

**等用户确认封面文字。**

### 5. 自适应封面设计

封面不是套模板。先分析已选帧，再把每个字、词或短语当作独立视觉对象安排位置。

先读帧和调性：

```bash
python3 scripts/make_cover.py palette \
  --frame "/path/to/selected-frame.jpg" --count 8
```

记录：

- 人脸 / 眼镜 / 嘴部 / 手势的位置；
- 左、右、上、下和四角的负空间；
- 明暗交界、前景/背景分离；
- 画面主色、暗部、亮部和可用的强调色；
- 视频调性：AI/科技偏重型无衬线；人物访谈偏清晰粗黑；文化/历史可考虑宋体；新闻冲突可用窄体和更强对比。

然后写 design JSON。每个元素可以是字、词、短语或标点，单独指定位置、字号、颜色、描边、高亮、旋转、字距和透明度：

```json
{
  "frame": "/path/to/selected-frame.jpg",
  "output": "/path/to/cover.jpg",
  "width": 1920,
  "height": 1080,
  "font": "/System/Library/Fonts/Hiragino Sans GB.ttc",
  "font_index": 2,
  "background": {"type": "gradient", "direction": "left"},
  "elements": [
    {"type": "text", "text": "Anthropic CEO 深访", "x": 105, "y": 365, "size": 54, "color": "#0A0A0A", "highlight": {"color": "#FFD400", "padding": [22, 12]}},
    {"type": "char", "text": "我", "x": 98, "y": 460, "size": 145, "color": "#FFFFFF", "stroke_color": "#000000", "stroke_width": 7},
    {"type": "text", "text": "AI 公司", "x": 98, "y": 640, "size": 145, "color": "#0A0A0A", "highlight": {"color": "#FFD400", "padding": [30, 20]}},
    {"type": "text", "text": "吗？", "x": 625, "y": 640, "size": 145, "color": "#FFFFFF", "stroke_color": "#000000", "stroke_width": 7}
  ]
}
```

渲染：

```bash
python3 scripts/make_cover.py design \
  --design "/path/to/cover-design.json"
```

设计规则：

- 文字是灵活对象：可以按字、词或短语拆分，每个对象单独定位；
- 语义不能断：字距可以变，但词序和阅读顺序必须清楚；
- 强调色来自画面调性或内容语义，不默认永远是黄色；一张封面只用一个主强调色；
- 字体最多两族；科技/AI 常用重型无衬线，人物访谈用清晰粗黑，文化/历史可考虑宋体，新闻冲突可用窄体；
- 位置由负空间决定，不固定左/右/上/下；
- 高亮块、描边、投影都服务于对比，不能盖住人脸、眼镜、嘴和关键动作；
- 生成后必须看 1920x1080 和 640x360 两版。

简单 fallback 仍可用 `cover` 子命令；但要交付高质量封面时优先使用 `palette + design`。

### 6. 交付前 QC

生成后至少看两张图：

- 原尺寸 1920x1080；
- 640x360 缩略图。

检查：

- [ ] 主文字一眼能读；
- [ ] 人脸、眼镜、嘴部和关键动作不被文字遮挡；若用户明确要求 4:3，文字才进入安全区；
- [ ] 高亮词是内容核心，不是装饰；
- [ ] 文字不遮眼、鼻、嘴和关键手势；
- [ ] 无视频字幕压封面字；
- [ ] 画面没有误导性场景；
- [ ] 标题、简介、封面指向同一内容；
- [ ] 简介有来源/版权提示（如适用）；
- [ ] 输出路径清楚返回给用户。

## 交付格式

最终回复必须包含：

```markdown
## 标题
[已确认标题]

## 简介
[已确认简介]

## 封面
![封面](/absolute/path/to/cover.jpg)

路径：/absolute/path/to/cover.jpg
```

用户想把这套流程发给任何人或其他 Agent 使用时，读
[references/copy-prompts.md](references/copy-prompts.md)，按对方拥有的材料选择完整版或短版提示词，不要现场重写规则。

## 常见坑

- 封面主文字不是标题；不要把 30 字标题压进封面。
- 不要套固定版式；同一张帧在人物左移、右移或居中时，文字区应完全不同。
- 不要因为画面暗就无脑加黄块；先看主色、皮肤色、灯光和内容调性。
- 翻译后视频常带硬字幕；抽封面帧优先用原始视频。
- 高亮词必须是内容锚点，例如产品、人物、争议对象；不能只标“AI”。
- 长视频简介不要只写一句话；有章节时时间轴比形容词更有用。
- 用户说“标题太长”时，问题通常不是删几个字，而是要区分“投稿标题”和“封面主文字”。
