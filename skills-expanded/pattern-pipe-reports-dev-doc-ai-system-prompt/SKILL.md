# Контекст проекта для ИИ: pattern-pipe-reports

## Кратко о проекте

**pattern-pipe-reports** — фронтенд-приложение для генерации **PDF-отчётов** на основе **структурированных JSON-данных** и для отображения **реестра PDF-отчётов**.

Демо-версия приложения:

- Главная страница: `https://viktorygis.github.io/pattern-pipe-reports-build/`
- Генерация PDF: `https://viktorygis.github.io/reports/generate`
- Реестр отчётов: `https://viktorygis.github.io/reports`

Проект используется как прототип / PoC для сценария, где внешние сервисы или аналитический пайплайн формируют JSON с данными клиента, метриками, интерпретациями, паттернами и характеристиками развития, а фронтенд:

- показывает данные;
- позволяет быстро открыть PDF для предпросмотра;
- позволяет скачать готовый PDF;
- отображает список отчётов в виде реестра.

---

## Назначение продукта

Приложение предназначено для специалистов, которым нужен быстрый инструмент для создания и оформления структурированных PDF-отчётов. Примеры пользователей:

- психологи;
- аналитики;
- исследователи;
- другие специалисты, работающие с клиентскими профилями, метриками, интерпретациями и паттернами.

Основная цель:

- преобразовывать структурированный JSON в читабельный PDF-отчёт;
- дать простой интерфейс для генерации, просмотра и скачивания отчётов;
- обеспечить основу для будущей интеграции с API и внешними источниками данных.

## Основные возможности приложения

### 1. Генерация PDF-отчёта по JSON

Пользователь работает со страницей генерации PDF:

- видит большую текстовую область с примером JSON;
- может вставить собственные данные в нужном формате;
- приложение парсит JSON в реальном времени;
- при синтаксической ошибке показывает сообщение об ошибке;
- при валидном JSON активирует кнопки:
  - **Открыть PDF**
  - **Скачать PDF**

#### Поведение кнопок

**Открыть PDF**

- проверяет корректность JSON;
- формирует `docDefinition` через `buildPatternReportDoc`;
- генерирует PDF через `pdfMake`;
- открывает PDF в новом окне браузера для предпросмотра.

**Скачать PDF**

- проверяет корректность JSON;
- формирует PDF через `buildPatternReportDoc` и `pdfMake`;
- скачивает файл на компьютер пользователя;
- имя файла формируется на основе ФИО клиента, например `pattern-report-ФИО.pdf`, либо используется безопасное fallback-имя.

#### Обработка ошибок

- если JSON невалиден, кнопки становятся неактивными;
- под текстовой областью показывается сообщение об ошибке парсинга;
- структурная валидация по schema возможна через `validateProfile`, но может быть ещё не полностью включена в UI.

---

### 2. Реестр PDF-отчётов

На странице реестра отображается таблица отчётов.

Пользователь может:

- просматривать список отчётов;
- фильтровать записи по ФИО;
- фильтровать записи по городу;
- сортировать отчёты по дате:
  - сначала новые;
  - сначала старые;
- скачивать PDF по конкретной с��роке;
- видеть количество записей после применения фильтров.

#### Поля таблицы

В строке реестра отображаются:

- уникальный ID отчёта;
- дата создания;
- ФИО клиента;
- город.

#### Действие "Скачать PDF" в реестре

- при нажатии на кнопку в строке берутся данные соответствующего отчёта;
- на лету формируется PDF тем же шаблоном, что и на странице генерации;
- PDF скачивается пользователю.

## Пользовательские сценарии

### Сценарий 1. Генерация PDF вручную

1. Пользователь открывает страницу генерации.
2. Вставляет JSON по шаблону.
3. Исправляет данные при необходимости.
4. Нажимает **Открыть PDF** для предпросмотра.
5. Если всё корректно, нажимает **Скачать PDF**.

### Сценарий 2. Работа с реестром

1. Пользователь открывает страницу реестра.
2. Ищет нужный отчёт по ФИО или городу.
3. Меняет сортировку по дате.
4. Находит нужную запись.
5. Скачивает PDF из строки таблицы.

## Принципы работы ИИ с этим проектом

Если ИИ помогает разрабатывать или изменять этот проект, ему нужно учитывать следующие правила:

1. **Не ломать основной сценарий генерации PDF**
   - валидный JSON должен приводить к успешной генерации PDF;
   - невалидный JSON должен явно показывать ошибку и блокировать действия.

2. **Сохранять единый источник формирования PDF**
   - PDF должен собираться через `buildPatternReportDoc`;
   - логика шаблона PDF должна находиться в PDF-слое, а не размазываться по UI.

3. **Не смешивать UI и бизнес-логику PDF**
   - страницы управляют вводом, фильтрами и кнопками;
   - структура PDF, секции и форматирование находятся в `src/pdf/report/*`.

4. **Сохранять модульность секций**
   - новые блоки отчёта лучше добавлять как отдельные секции или расширения существующих секций;
   - не превращать генератор PDF в один большой файл.

5. **Опираться на JSON Schema**
   - при расширении структуры данных нужно синхронизировать:
     - схему;
     - labels;
     - fieldOrder;
     - formatters;
     - секции PDF;
     - sample в `PdfReportPage.jsx`.

6. **Учитывать будущую интеграцию с API**
   - реестр сейчас может быть на мок-данных, но архитектура должна позволять перейти на серверные данные;
   - желательно проектировать код так, чтобы список отчётов можно было загрузить извне без серьёзной переделки UI.

7. **Поддерживать русскоязычный контекст**
   - интерфейс и предметная область ориентированы на русскоязычных пользователей;
   - важно аккуратно работать с кириллицей, особенно в PDF, подписях и именах файлов.

8. **Разделять дату сессии и дату формирования PDF**
   - `date_session` — это дата из данных клиента;
   - дата формирования PDF — это техническая дата генерации документа;
   - обе даты должны выводиться в шапке отчёта, если такая логика уже внедрена.

9. **Корректно обрабатывать вложенные структуры**
   - поля вроде `thresholds` и `cluster_meaning` требуют специального форматирования;
   - нельзя допускать отображение `[object Object]` в готовом PDF.

10. **Считать актуальный `client-profile.json` источником истины для шаблона**

- если новый JSON отличается от старого sample, шаблон нужно синхронизировать с новым JSON;
- нельзя опираться только на старую демонстрационную структуру.

## Что важно помнить ИИ

- Это не просто “страница с PDF”, а **инструмент преобразования аналитического JSON в оформленный документ**.
- Ключевая ценность проекта — **простота пользовательского сценария**:
  - вставил JSON,
  - проверил,
  - открыл PDF,
  - скачал PDF.
- Архитектурно важно сохранять разделение:
  - UI-страницы;
  - PDF-конструктор;
  - секции;
  - схема данных;
  - словари подписей;
  - порядок вывода;
  - форматирование значений.
- Любые улучшения желательно делать так, чтобы не усложнять базовый сценарий для пользователя.

## Краткое резюме в 1 абзац

`pattern-pipe-reports` — это React/Vite-приложение для генерации PDF-отчётов из структурированного JSON и для просмотра реестра отчётов. Пользователь либо вручную вставляет JSON и получает PDF через предпросмотр/скачивание, либо работает со списком уже существующих отчётов в реестре. Генерация документа построена на `pdfmake`, логика шаблона вынесена в отдельный PDF-слой с секциями, форматтерами, словарями полей и фиксированным порядком вывода. Проект является прототипом, ориентирован на дальнейшую интеграцию с API, JSON Schema-валидацию, поддержку расширенного `client-profile.json`, вывод даты сессии и даты формирования PDF, а также дальнейшее развитие структуры отчётов.
