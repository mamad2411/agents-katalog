# Weekly Brief

Read a project folder and produce a short Monday brief: what changed, what is overdue, what is
due, what is undecided, and what to prepare for. This skill reads and reports. It never writes
files, never sends anything, and never changes a register. That is what makes it safe to run on
a schedule.

## Input

`$ARGUMENTS` is the path to a project folder, for example `my-projects/acme` or
`sample-projects/acme-data-warehouse`. If no path was given, ask for one. If the folder does not
exist, stop and say so; do not guess at a different folder.

## Steps

1. **List the folder.** Note every file and its last-modified date. Files touched in the last 7
   days are "changed this week."
2. **Read the changed files** plus any status CSV, action register, decision log, or meeting
   notes in the folder, whatever their date. Skip raw transcripts longer than a few pages unless a
   note or register does not exist; say if you skipped one.
3. **Find the dates.** Collect every action item with a due date and every milestone date you can
   see. Compare against today's date. Anything due before today and not marked done is overdue.
4. **Find the open questions and decisions** that appear in notes but have no recorded answer.
5. **Find the next meetings** mentioned in notes or the calendar if one is in the folder.

## Output

**Weekly Brief: [project name] · week of [Monday's date]**

**What changed since last Monday**
- One line per file, newest first: filename, what it is, and the one thing worth knowing from it.
  If nothing changed, say so in one line.

**Overdue**
| Action | Owner | Was due | Source file |
|---|---|---|---|

**Due this week**
| Action | Owner | Due | Source file |
|---|---|---|---|

**Open decisions and questions**
- Each one with the file and date it was first raised. Oldest first.

**Meetings to prepare for**
- Date, meeting, and the one-line suggestion for what `/meeting-prep` should focus on.

**Suggested first task**
One sentence: the single thing the delivery lead should do first this morning, and why.

*Generated by the weekly-brief skill on YYYY-MM-DD. Read-only; nothing was changed.*

## Rules

- Report only what the files say. If the folder has no dates, say the brief cannot assess
  overdue items rather than inferring them.
- Use `[TBD]` for any missing owner or date. Never assign one.
- Do not open, write, or move any file. Do not create a summary file. The brief is the output.
- If the folder contains another client's name in a file that is not that client's folder, flag it
  at the top of the brief under **Check this**.
