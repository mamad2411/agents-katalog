# Harness 证据复核

先识别用户所处阶段：接入检查、复验报告或交接。只读复核不扩展为产品修复；用户已要求修复时，在既有授权范围内修复并保留原证据。

## 输入与首要判断

从事项或 Spec 读取必需用例和等级，再读取实际命令、退出码、候选位置及版本、报告。不能从实际运行子集反推任务要求。缺失材料时继续核对可验证部分，明确哪些结论尚无依据，不猜造身份或审核人。

## 按阶段执行

- 接入：对照名称、函数或脚本来源与本次选择；L05 原检查通过适配接入时保留退出码和失败信息。文件存在不证明登记成功，核对实际 results。
- 复验：按分项重算 total、passed、blocking_failed、observing_failed 与 decision，再对照进程退出码。空结果、未知或重复名称、遗漏必需项、类型错误均不能支持通过。
- 来源：把报告关联到本次命令和候选；旧文件、时间戳或绿色摘要不能独立证明本次执行。缺报告时保留实际故障，不借用历史绿灯。
- 交接：分别说明业务结果、工程范围、Harness 行为和人的决定。L06 要核对有效批次完整写入、无效批次被拒绝且商品主表完整状态不变、预检查不写商品主表。检查器接受可信红报告不代表产品通过。

当前 1.0 结构正常完成汇总时，阻断失败对应 block/1；仅观察失败对应 pass/0 并保留告警。异常按登记等级处理，运行故障无报告时不能给出业务通过。结构改变时读取实际实现与合同，不强套旧字段。

输出：结论、具体证据位置、矛盾或缺口、下一步。区分参考实验、本人实现、同伴复验与具名接受。流程的采用和修订记录留在已有任务中；跨任务采用尚未发生时如实说明。

需要验证流程是否识别假绿灯时，读取 [反例练习](references/review-cases.md)。
