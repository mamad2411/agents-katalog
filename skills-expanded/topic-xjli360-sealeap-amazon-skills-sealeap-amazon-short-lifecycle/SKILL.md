# SeaLeap 短生命周期非标品广告

先验证产品是否确有分散需求和短迭代窗口，再用场景、属性及相关商品测试需求，持续控制库存和现金风险。

## 输入

站点、商品和真实属性、首批测款数量、测款周期、日/期预算上限、售价与贡献利润、需求及竞品趋势、搜索词/商品流量、库存/交期、创意事实与权利。

## 工作流

1. 用相关关键词和购买意图的分布判断流量集中度，再结合审美偏好、产品可比性与迭代曲线判断非标和短生命周期。类目标签或单一集中度不足以定性。
2. 新品分别测试关键词、ASIN/类目、场景/属性价值及真实视觉承接，选择一个主要变量并预先限制总损失。
3. 先确认用户限制的是广告支出、测试损益还是现金净流出，再明确全周期总额与每日额度。把库存/处置及其他损失纳入同一范围；缺少损失准备或支出控制证据时，预算只能是条件草案，不释放新增测试资金。源文新品用 200 个测试量算总额，成长用日均 20 个算日额，不能互换。
4. 校验预算比例合计。源成长期表 20%+50%+30%+10%=110%，**不能直接落地或悄悄当成 100%**；先要求确认真实配置，或把重新设计的配比明确标为新方案。
5. 成长时扩展已验证词与相关商品，比较付费与自然变化；降低出价检验流量替代时，保持其他条件并观察总销售和利润，不能预设自然单会接盘。
6. 成熟/下滑时先区分市场季节、竞品新品替代和自身问题，再决定修复、受控收缩、清货或资源转移。退出可能有损失，不能承诺零损。

## 交付

类型与需求证据、测款目标和周期、预算错误/缺口、可执行的新配比、关键词/商品/素材试验、竞争诊断、库存与止损/退出计划。

## 证据与执行范围

- 材料中的案例、比例和时间表标为 `COURSE_BASELINE` 或 `TRAINING_CASE`；来源与口径已核验的店铺数据标为 `ACCOUNT_FACT`，用户转交但未核验的数据标为 `USER_PROVIDED`，合成练习标为 `SIMULATED`。推断标为 `HYPOTHESIS`，缺失项写 `UNKNOWN`，不补成 0。
- 先固定店铺、广告 profile、站点、ASIN、币种、数据窗口与归因口径。课程介绍的资格、界面、报告字段和功能覆盖在实际使用时核验。
- 默认交付诊断与草案。真实写入只在当前会话已授权的对象、动作和预算内执行，并保存旧值与回读结果；新增范围先取得授权。
