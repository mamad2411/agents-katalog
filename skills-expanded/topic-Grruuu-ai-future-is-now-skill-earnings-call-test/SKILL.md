# 季度财报电话会测试

## R — 原文 (Reading)

> 在讲行动之前，需要先有一把标尺：一家企业的AI转型，是否改变了出现在季度财报电话会上的数据？
> ……这是真实的改善，但本质上仍然是“化妆”，它只是优化了现有流程，不一定导向更多价值创造……
> 对于企业正在推动的每一个AI项目，请思考以下问题：它影响财报上的哪一项数据？影响多大？什么时候实现？
>
> — 李开复，第5章「衡量真假转型：季度财报电话会测试」（三段逐字引用，共 142 字，中间以「……」标示跨段）

> 没有人会接受“部署了X个智能体、使用率达到了Y%”这样的答案。
>
> — 李开复，同章同节

## I — 方法论骨架 (Interpretation)

这是一把**验收尺**，不是一套评估模型。它的全部机制是把"AI 有没有用"这个含糊问题，强制换成一句只有一种答案格式的话：**这件事会让财报上的哪一行数字变化、变多少、什么时候变。**

之所以锚在"财报电话会"而不是"ROI"，是因为财报电话会是一个**公开承诺场合**——管理层要对着投资者和分析师，为具体数字给出解释和承诺。ROI 可以用任何自造口径算出漂亮结果（工时节省、避免的机会成本、满意度提升）；财报电话会上没有人会接受这些。换句话说，这把尺子真正约束的不是项目，是**汇报者的口径自由度**。

尺子一落下，项目自动掉进三个档位。第一档是**投入指标**：部署了多少模型、上线了多少智能体、覆盖了多少部门、使用率多少。这些只能证明团队在动，不能证明发生了什么。第二档是**化妆**：某流程处理时间缩短 30%、某部门人力成本降低 20%——改善是真的，数据是真的，但如果省下的产能没有被回收（没有减编制、没有减外包、没有减赔付），也没有被投进更高价值的产出，那么它对损益表的净影响是零。第三档才是**真实改善**：收入、利润率、客户留存率、供应链周期、新产品上市速度。

第二档是最危险的一档，恰恰因为它数据真实、经得起质询——它能安全地活很多年，同时挡住"还有没有别的问法"这个真正有价值的追问。

对"这是战略性投入、短期看不到回报"这类说法，本方法论不给豁免，只给一道更严的门：说清时间节点、兑现方式、落到哪一项财报数据。三者缺一，它就应当按"实验室预算"来管理，而不是按战略项目来保护。

最后，这把尺子有第二重用途：它是**内部对齐工具**。CEO 反复用它提问，会逼整个团队把"影响力""创新性""用户反馈"翻译成财报语言。这种翻译不会自动发生。

## A1 — 书中的应用 (Past Application)

### 案例 1: 法律合同 AI 审查项目——"效率提升 40%"只是化妆

- **问题**：某企业上线法律合同 AI 审查，团队汇报「审查效率提升40%、可覆盖80%的合同文件」。数据真实、覆盖率可观，看起来是个成功项目。
- **方法论的使用**：作者不评价这个数字好不好，只问第一问——它影响财报上的哪一项数据？
- **结论**：「审查确实变快了，但既没少招法务人员，也没让一笔合同因此多赚或少赔」。因此判为第二档"化妆"，不是转型。关键动作不是砍掉项目，而是**换一个问法**：如果让 AI 识别合同里易被忽略的超额赔付条款，一年能减少多少赔付支出？作者的判断是「这条内容才会对利润表产生直接影响」。
- **结果**：同一个技术能力、同一批工程师，只因为对准的科目从"处理时长"换成"赔付支出"，就从第二档跳到第三档。这说明三态分类的分水岭不在技术，在**对准了哪一行数字**。

### 案例 2: 自序里那阵尴尬的沉默——尺子的原型

- **问题**：2025 年一整年，作者与世界各地数百家优秀传统企业的 CEO 会面。对方总是先讲自己如何购买模型服务、搭建团队、试点落地、全员培训，年报和董事会材料里写满「AI赋能」「智能升级」「全面拥抱智能体」。
- **方法论的使用**：作者只用一个问题把话题拉回来——「那么AI给你的财报带来了什么实质性变化？」
- **结论**：「我得到的回应往往是一阵尴尬的沉默。」这阵沉默说明，从上到下的忙碌与财报之间没有建立起任何一条可陈述的因果链。
- **结果**：这个提问动作被作者定为写这本书的初衷，也是第 5 章整把标尺的直接来源。对使用者的启示是：**这把尺子的第一次使用几乎必然产生沉默，沉默本身就是诊断结果**，不必急着替对方补答案。

### 案例 3: DeepSeek 私有化部署热潮——部署完了没有后文

- **问题**：2025 年春节后，中国出现 DeepSeek 私有化部署热潮，「部署AI甚至在政企单位成了KPI」。员工自己用豆包、DeepSeek 用得挺好，可企业一旦正式部署，就再没动静。
- **方法论的使用**：把"部署完成"放到标尺下——它属于典型的第一档投入指标：部署数、覆盖单位数、上线时间，没有一项会出现在财报电话会上。
- **结论**：「但部署之后往往就没有后文了。」企业要的不是一段流畅的文字，而是一个可追溯、可核查、可承担后果的判断；部署本身不产生这个判断。
- **结果**：这是三档分类里第一档的规模化样本——当"部署"本身被写成 KPI，整个市场会高效地生产部署，然后集体停在那里。它同时说明：**尺子必须在立项时就架上，事后再架，钱已经花完了。**

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **要不要继续投**：一个 AI 项目跑了半年到一年，有汇报有数据，用户在犹豫加预算、维持还是砍掉。
2. **一批项目要排序**：手上七八个 AI 项目，预算只够三个，需要一个不靠"谁嗓门大"的取舍规则。
3. **要向上证明价值**：董事会/老板/投资人下周要问"AI 这一年的钱花得值不值"，用户手里只有部署数、使用率、员工好评。
4. **有人拿效率数字来论证成功**：团队汇报"效率提升 40%""处理时长缩短一半""覆盖了 8 个部门"，用户隐约觉得不对但说不出哪里不对。
5. **有人用"战略性投入"挡验收**："这是打基础的""短期看不到回报""在沉淀数据资产"——用户需要判断这是真长期投入还是免检标签。
6. **立项闸口**：新的 AI 项目要立项，用户想在花钱之前先把验收标准钉死。

### 语言信号 (用户的话里出现这些就应激活)

- "这个 AI 项目还值不值得继续投 / 该不该砍"
- "怎么衡量 AI 项目的价值 / 用什么标准评估 AI 的成效"
- "他们汇报说效率提升了 40%，这算不算成功"
- "使用率很高 / 部署了 X 个智能体 / 覆盖了 Y 个部门"
- "董事会下周问我这钱花得值不值"
- "他说这是战略性投入，短期看不到回报"
- "我们几个 AI 项目该保哪个"
- "AI 用了一年，感觉挺热闹的，但说不清有什么变化"

### 与相邻 skill 的区分

- 与 `transformation-failure-diagnosis` 的区别：那个回答**"为什么推不动"**（责任分配、需求来源、隐性抵抗），本 skill 回答**"这值不值得推"**（价值）。判别口诀：项目**跑出了结果但结果没用** → 本 skill；项目**根本跑不出结果** → 那个。若两者同时存在，先用本 skill 判该不该救，再用那个判怎么救。
- 与 `token-cheap-system-valuable` 的区别：那个回答"钱该怎么在 Token / 配套系统 / 流程与人之间分"，本 skill 回答"这笔钱该不该花"。典型接力：本 skill 筛掉伪项目 → 那个给活下来的项目定预算结构。
- 与 `agent-four-components` 的区别：那个诊断"工具为什么不好使"（模型 / 工具 / 记忆 / 知识哪一块缺），是技术缺口定位；本 skill 完全不碰技术原因，只问财务后果。用户说"AI 老是答错" → 那个；用户说"AI 答得挺对，但公司没什么变化" → 本 skill。
- 与通用 ROI 测算的区别：ROI 接受任何自定义分子分母；本 skill 只认会出现在财报电话会上的那几项。用户已经算好一个 ROI 时，本 skill 的动作是**审口径**，不是重算。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **锁定评估对象，逼出一句"财报语言"的目标句**
   - 要求用户（或代用户草拟）写出这句话：「这个项目将使【某一项财报科目】在【某个时间】改善【某个幅度】。」
   - 完成标准：这句话被写出来了，或用户明确承认写不出来。**含糊的替代品一律不算完成**——"提升效率""让大家更方便""提高竞争力""改善员工体验"都不是财报科目。
   - 判停条件：若用户此刻明确表示"我只是想整理一份纪要 / 做一个财务模型"，说明进错了 skill，立即退出。

2. **跑三问：影响财报上的哪一项数据？影响多大？什么时候实现？**
   - 合法答案的科目范围（作者列举）：收入、利润率、客户留存率、供应链周期、新产品上市速度；可外延到同样出现在损益表/资产负债表上的科目，如赔付支出、坏账率、库存周转、人力成本编制、外包费用。
   - **非法答案**（出现即判为未通过第一问）：效率提升 X%、处理时长缩短、使用率、部署数、覆盖部门数、满意度、影响力、创新性、用户反馈、"大家找资料更快了"。
   - 完成标准：三问各有一个具体、可核对的答案（科目名 + 数量级 + 时间点）。
   - 判停条件：**第一问答不出具体科目 → 直接跳到步骤 3，归入第一档或第二档，不要在"影响多大"上继续纠缠。**

3. **三态分类，给出唯一归档**
   - 第一档 **投入指标**：证据全是"做了多少"（部署数、上线数、覆盖部门数、使用率、培训人次）。判定语：这只能证明团队在行动。
   - 第二档 **化妆**：有真实的局部效率或成本改善，但**编制没变、产出结构没变、没有一笔钱因此多赚或少赔**。判定语：改善是真的，对财报的净影响是零。
   - 第三档 **真实改善**：能指着一行财报科目说出变化量与时间。
   - 第二/三档的分水岭只有一条，必须显式回答：**省下的产能被回收了吗（减编制 / 减外包 / 减赔付 / 减库存），或省下的时间被投进更高价值的产出了吗？** 两者都没有 → 第二档。
   - 完成标准：给出档位 + 一句话依据 + 指出是哪一条证据把它压在这一档。

4. **对第一、二档执行"换问法"重构，先救再砍**
   - 保持技术能力不变，把它对准另一行数字。参照案例 1：把"审查效率提升 40%"换成"识别超额赔付条款一年能减少多少赔付支出"。
   - 完成标准：至少产出一个替代问法，且该问法能通过步骤 2 的三问。
   - 判停条件：**重构后仍答不出财报科目 → 建议停投，或降级为有明确金额上限与截止日期的最小实验**（而不是继续按常规项目预算滚动）。

5. **"战略性投入"例外审查（仅当用户援引该理由时进入）**
   - 三项必须同时写清：① 在什么时间节点兑现；② 以什么方式兑现；③ 体现在哪一项财报数据中。
   - 完成标准：三项齐全 → 可作为战略投入保留，但把这三项写进项目文档作为复审依据。
   - 判停条件：**三项缺任意一项 → 判为"实验室预算"**。处理方式不是立刻砍，而是按实验室预算管理：给定额度上限、给定复审日期、给定退出条件，并从战略项目序列中移出。

6. **收口成一张可以在管理会上直接念的表**
   - 每个项目一行：`项目名 | 财报科目 | 影响量级 | 兑现时间 | 档位 | 处置（保 / 重构 / 降级为实验 / 停）`。
   - 完成标准：表里没有任何一行的"财报科目"列是空的或写着效率类词汇。
   - 附加动作：提醒用户这把尺子的第二重用途——「这种对齐，不会自动发生，需要企业CEO持续地、明确地用这把标尺进行决策和沟通。」一次性使用产生的是一份清单，反复使用才产生口径的转变。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **早期研发型组织、前沿实验室、尚无营收的初创**：财报科目要么不存在，要么与研发进展没有可陈述的因果关系。硬套会把"模型能力提升"翻译成"本季度收入"，得到的是编造。
- **公益组织、政府与事业单位、公共医疗与公共卫生**：使命指标不是财报科目。强行翻译会把"少死几个人""办事少跑一趟"折算成"降低成本"，这是价值观错误而不只是方法论错误。这类场景可**降级使用**：保留三问的结构（影响哪一项使命/预算指标、影响多大、什么时候实现），但必须显式替换标尺，并声明替换。
- **财报周期长于技术迭代周期的行业**（制药、航空航天、基建、重资产制造、长周期能源）：一个季度的财报装不下一个 18 个月甚至 8 年的兑现路径。此处第 5 步的"实验室预算"判定会**系统性误杀正确的长周期投入**。应把时间窗从"季度"放宽到该行业的自然决策周期，并保留"里程碑—科目"映射而不是"季度—科目"映射。
- **用户其实在做别的事**：整理财报电话会纪要（文档处理）、做财务模型或估值（财务分析）、问技术为什么不好使（`agent-four-components`）、问项目为什么推不动（`transformation-failure-diagnosis`）。
- **没有财报电话会这个场合的小微组织**：可降级为"月度损益表测试"，三问照用，但不要照搬"公开承诺场合"这层论证——那层论证依赖的是外部投资者的存在。

### 作者在书中警告的失败模式

- **评估体系本身在奖励"表面成功"**：「如果CIO的KPI还停留在智能体部署数量和使用率上，这种评估标准上的错误会系统性地产出看起来成功、实际上没有价值的结果。」——这是系统性后果，不是个别项目执行不力。因此本 skill 若只用来审项目而不审 KPI，会被源源不断地重新生产出第一档项目。
- **场景错位，沿阻力最小路径选题**：「这就导致绝大多数企业的AI投入都集中在容易部署的地方，而不是真正有价值的地方。」价值与落地难度正相关；在没有一号位授权时，任何理性执行者都会选阻力最小的路径。所以砍掉第一/二档项目而不同时提高授权层级，只会换来另一批第一/二档项目。
- **"化妆"陷阱最难识破，因为数据是真的**：它经得起质询，反而挡住了真正有价值的问法。
- **"战略性"是不可证伪的标签**：一旦豁免成立，它会被用来保护所有说不清价值的项目——「那所谓的“战略性的AI投入”很可能只是实验室预算的另一种说法。」

### 作者的盲点 / 时代局限

- **★ 自反风险：这把尺子没有豁免于它自己用来否定 KPI 的那条规律。** 作者在第 7 章用古德哈特定律否定 KPI 考核，并亲自举例：在他曾服务的一家公司，「客户满意度连续上升，庆功邮件都拟好了，后来管理层才发现这种上升是因为最不满意的那批客户在上个季度已经走光了」——他的结论是"指标越明确，绕过它的方式就越明确"。但他随即把财报科目立为 AI 项目的**最高考核目标**，全书没有解释财报为什么能豁免于同一条规律。事实上财报同样可被游戏化：把成本推到下一季度、用一次性交易冲收入、砍研发换当期利润率、把 AI 投入资本化、把"减少赔付"做成少赔该赔的。
  **强制动作**：每次用本 skill 得出"第三档 / 真实改善"结论后，必须追加一问——**如果这条科目成了 AI 团队的考核目标，有哪些不产生真实价值的方式可以让它变好看？** 把答案写进项目文档作为反向监控项。不做这一步，本 skill 就是在用一个新指标替换旧指标，而不是在提高判断力。
- **样本严重偏向大型、有钱、数字化基础扎实的上市或准上市企业**：作者的一手材料来自"世界各地数百家优秀传统企业的 CEO"、世界 500 强董事长、全球前 20 矿业巨头。**没有财报电话会的组织根本不在样本里**，因此这把尺子对它们的适配性从未被验证过。
- **只度量收益侧，不度量下行风险**：全书没有一个"AI 造成实质损失"的案例（数据泄露、智能体误操作导致不可逆业务损失、合规处罚、供应商锁定）。一个财报影响为正但尾部风险很大的项目，本 skill 会给它开绿灯。使用时应自行加一列"最坏情况的财报影响"。
- **"效率提升不转化为财报就是化妆"这条判定，隐含了"编制可调整"的前提**。在人力有刚性编制、无法裁员的组织（公立机构、强工会行业、部分国企），省下的产能在制度上就无法被回收。此时第二档的判定等于把所有效率项目一次性判死，结论虽然形式正确但没有行动价值——应改判为"在当前约束下上限即为第二档"，并把讨论转向"省下的时间投向什么"。
- **成书于 2026 年上半年**：其紧迫性论证依赖一批极新、未经时间检验的数据点（推理成本两年降约 99.4%、Claude Opus 4.6 约 12 小时任务时长等）。这不影响标尺本身的逻辑，但影响"必须现在就砍掉第一/二档项目"这个时间压力的强度。

### 容易混淆的邻近方法论

- **ROI 测算**：ROI 允许任何自定义口径，可以把工时节省折成金额算出漂亮数字。本测试只认会出现在财报电话会上的那几项。二者不是同一层次——ROI 是计算方法，本测试是**口径准入规则**。
- **OKR / 北极星指标**：那是目标设定与对齐工具，明确允许非财务的过程指标；本测试是验收与砍项目的标尺，对过程指标零容忍。把二者混用会导致 OKR 里的 KR 全被判为"投入指标"。
- **业务价值评估 / 影响力评估 / 价值流分析**：作者明确拒绝用"影响力""创新性""用户反馈"衡量 AI 项目。若组织的既有流程就是这套，本 skill 会与之直接冲突——这是设计意图，不是误用。
- **阶段门（Stage-Gate）评审**：Stage-Gate 管的是"这个阶段该不该进入下一阶段"，可以接受技术里程碑作为通过条件；本测试问的始终是终局的财报兑现。两者可叠加使用：Stage-Gate 决定节奏，本测试决定方向。
- **供应商甄别（"这个价格具体能交付什么"）**：那是采购环节的拆价工具，同出第 5 章但解决的是"钱买到了什么交付物"；本 skill 解决"这些交付物换回了哪一行数字"。
