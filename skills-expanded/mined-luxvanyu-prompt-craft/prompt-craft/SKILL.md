# 提示词工坊（prompt-craft）

> 这是**唯一的入口**。决定「画什么、怎么画、写成什么」的那部分在本文档 + `references/`；
> 决定「MOSS 这一台机器会怎么执行」的实测规则在 `references/moss-rules.md` 与 `references/casebook.md`；
> 决定「像不像艺术」的那部分在 `references/aesthetic.md`。

## 第一原则

> **一图一主张。** 一张图只允许有一个最高对比点、一个主导明度、一个主动作、一个色彩事件。其余全部降级为陪衬。

看到这句就够判断一张图了：画面上有两处一样抢眼，不是更丰富，是更模糊。

## 七维决策（摘要；完整版见 `references/aesthetic.md`）

顺序不能换，每一维必须落一个**明确选择**，不许「看情况」：

| # | 维 | 一句话 | 落到提示词里的形态 |
|---|---|---|---|
| 1 | **瞬间** | 这一秒发生了什么？一张图只讲一件事 | 一个动作 + 一个朝向 |
| 2 | **明度结构** | 暗/中/亮各叫什么、各占多少 | 第一句定调 + 三档面积 |
| 3 | **光** | 从哪来、落在哪三处、死在哪 | 光源方位 + 衰减半径 |
| 4 | **空间与镜头** | 机位距离 + 主体占画高分数 | 两个数，缺一个必裁头（G85） |
| 5 | **色彩** | 四个角色各司其职，点缀 ≤10% | 至少三个有色相的大面积 |
| 6 | **材质** | 写**可见行为**，不写形容词 | 「布在膝盖处堆成两道褶」 |
| 7 | **收尾** | 一句话把画面锁住 | 最亮是什么 / 最暗在哪 |

> 每一维的判据、量化参数、反例、检查表在 `references/aesthetic.md` 的「七维决策」一节；
> 配方库、风格提取、出图诊断在 `references/aesthetic/`（附录 A–I，九篇独立文件，按需加载）。**本文只做索引，不复制正文**。

## 角色光环非刚需与自然描写律（Halo Rule · 严禁欲盖弥彰）

> **核心纪律**：
> 1. **光环（Halo）绝不是二次元美学或高质量提示词的刚需配置**，角色默认不带光环（参考图集中的光环仅源于《蔚蓝档案》角色原作人设）。
> 2. **严禁写防御性否定句（防「欲盖弥彰」）**：在描写常规角色时，**严禁**写诸如 `no halo`、`the space over her hair is empty air with nothing hovering or glowing` 等防御性语句！在扩散模型注意力机制中，主动提否定词反而在隐空间激活了光环的概念。
> 3. **黄金正解**：**正常、自然地描写角色本身**。专注描写发型走向、发饰贴合（如发夹、发带、耳坠）、头部反光与微风动势，**完全不提光环二字**即可。只有当用户明确指定角色具有光环时，才描写光环。
> 4. **修复轮例外**：如果出图**已经**长出了光环，下一轮必须改用三连否认把它压回去（形状 + 画法 + 否认，写法见 `references/moss-rules.md` G19 补充）。此时 lint 关 11 的 WARN 属于预期，不必清。**一句话：首轮不提这个词，修复轮必须否认到底——两个阶段的做法相反，别混用。**

## 反默认清单

模型的五个出厂设置，每个都要主动打掉一个：

| 出厂设置 | 症状 | 反制写法 |
|---|---|---|
| **居中对称** | 主体正中、地平线居中 | 主体放 0.33/0.66；另一侧显式写成空（G65） |
| **均光无向** | 处处亮、皮肤无立体 | 指定方向 + 质量 + 比例；`the fill side falls three stops under` |
| **纹理均质** | 皮肤布料墙面同一细节密度 | `sharp only on the face, everything past the shoulder already softening` |
| **平均脸** | 对称、无瑕、无记忆点 | `a slightly crooked nose, one eye a little narrower, freckles clustering unevenly` |
| **无瞬间** | 摆拍、素材库感 | 未完成的动作 / 刚留下的痕迹 / 视线还没落到镜头 |

**另外四个高频病灶**：用元素堆叠代替设计（加元素只会变吵）· 用形容词代替参数（`cinematic` `dramatic` 是空转）· 全图同一锐度（真实镜头只有一个焦平面）· **跨稿同模子**（连续几张都用同一个句式开头、同一个词收尾，读者一眼就看出这是模板——换的是题材，节奏也得换）。

## 世界规则：模型不会照字面做的那一类

这一组是 160 多张出图反推出来的，违反任何一条都会整张返工。**完整证据在 `references/casebook.md`，摘要索引在 `references/moss-rules.md`。**

| 你以为写了就会 | 实际会发生 | 正解 | 规则 |
|---|---|---|---|
| 写「没有窗棂」 | 四重否认也照画窗格 | 给光一个**会产出正确形状的出处**（屋顶一道裂缝） | G80 补二 |
| 写「低机位贴水」 | 翻成站在岸边往下看 | 水面压窄 + 线要收 + 顶端留一条被切掉的边 | G84 / 补 / 补二 / 补三 |
| 写「这是倒影」 | 画成一块发光的东西躺在路上 | 倒影必须被水面事件打断（涟漪穿过时抖、边缘撕开） | G87 |
| 写「招牌」 | 一定长出可读的字 | 要零文字就**先别叫它招牌**，写成「只有光」 | G90 |
| 写「里面什么都没有」 | 会自己填满 | 写「里面装的是什么、什么颜色的」 | G44 |
| 写「路面毫无细节」 | 自动补上皮线、路缘 | 认下先验再规定它的样子 | G42 |
| 给光源名词 | 把灯画进画面 | 只写落点 + 衰减 + 未照亮区 | G41 |
| 写比例尺 | 人物照旧撑满画面 | 给**同深度水平带的对位句**（头顶比哪个边低多少） | G54/G56 |
| 提示词很长 | 人物被画大 1.3–2.9 倍 | 字数就是尺寸主因：**character 块** 200–320 词，整份 caption 按 `references/word-budget.md` 三档 | G64 |
| 写「一个人走进来」这种名词组 | 先排人再上色，脸全清楚 | 要无脸就写「背对我们」 | G63 |
| 想让图「不像 AI」而加网点/像素 | 完全出不来 | 细小重复单元是死角（G97）；能活的是错位套印、线稿排线 | G96/G97 |
| 两个角色靠得近 | 两个头叠成一块 | 两个 bbox 上边差 ≥画高 8% + 明写空气间隙 | G93 |

## 尺寸控制（第二大返工来源）

模型的优先级是 **名字先验 > bbox > 比例句**。所以四把尺，按效果排序：

1. **去名尺**（最有效）：要小就别给它名字——不叫「马克杯」，写「一只带单柄的白釉圆柱」。
2. **公认尺 + 距离**：砖 24cm、地砖 30cm、门 2m、易拉罐 12cm，配上「离镜头几步」。
3. **同深度对位句**：`the top of her head sits a little below the top edge of the lockers`——**那条边必须在画面上水平贯穿**，且必须同一地面线。
4. **裁切尺**（唯一可靠做「巨大」的）：`her forehead runs out past the top edge`。

反过来要**大**，就写「她站在谁旁边」——模型保比值，会把参照物一起放大（G28/G29/G47/G54/G64）。

## 目标模型翻译

七维决策是**思考层**，不是输出层。落到具体模型时：

- **MOSS-Image（官方规范对齐）**：
  - **产物选型**：普通场景、人物写真、照片与复杂插画**一律默认使用 Caption（纯文本）**，细节丰富并不自动需要 Layout；只有在**明确文字排版（海报/封面）、多格分镜（multi_panel）或严格物体互锁**时才使用 Layout。
  - **Caption 流程**：本地草稿写为 `{"caption":"..."}` 的 UTF-8 JSON；经 `compile_prompt.py` 编译后**输出为纯文本（Plain Text）**交付用户，直接粘贴进 MOSS 正向提示词框。
  - **Layout 流程**：本地草稿遵循 `references/layout.md`，包含 `width`, `height`, `bbox_coord_space:"abs"`, `bbox_format:"xyxy"`, `summary`, `items` 六个顶层字段；BBox 为左上角绝对像素 `[x1, y1, x2, y2]`。
  - **Layout 编译与交付**：运行 `python3 scripts/compile_prompt.py draft.json --output prompt.txt`。编译产物为**单行压缩 JSON（`abs_centralized` + `yxyx`，已剥离宽高元数据）**。交付时**必须在 prompt 外部单独标明所需的 `width × height` 尺寸**（如 1536×1024），因为模型正向提示词本身不含画幅尺寸。
- **Anima / NAI**：平铺 tag 串 + 画师串放在**前四分之一**（是「靠前」不是「必须打头」）；一律只给正向。真实分布见 `references/real-corpus.md`「一、第 2 条」。
- **Midjourney / SD / Flux**：自然语言长句 + 参数后缀（`--ar` `--stylize`），不要把 bbox 概念搬过去。
- **视频模型（可灵/即梦/Runway）**：同一套七维，但「瞬间」改成「一个连续动作」，且必须写**不动的那些东西**当锚。

## 交付前自检

### 自动（脚本）

```
python scripts/probe.py IMG                     # 出图后测：明度五档/近白面积/饱和方向
python scripts/lint.py DRAFT.json               # 草稿十三道关（Layout / 纯 caption 都适用）
python scripts/preview.py DRAFT.json --out L.png  # bbox 画出来看
python scripts/compile_prompt.py DRAFT.json --output OUT.txt
python scripts/lexicon.py 侧光                   # 差一个词叫什么：7526 条中英词典
python scripts/corpus.py --find 侧光             # 看一万条真提示词里这个词怎么组合（需 --packs）
```

顺序固定：**预览 → 调 y → lint → 编译**。`lexicon.py` 和 `corpus.py` 是查词用的，随时可跑；
`--scene` 出 64 条成品场景串，`--cat` 出全分类树，`--neg 词` 查这批人的负向写法。
`corpus.py` 要 42 MB 数据（`python scripts/fetch_lexicon.py --packs` 一次）；
没下也不影响写稿，只有想核对「别人是不是也这么写」时才需要。

### 手过（八条，逐条答得出来才算完）

1. 这张图的**一个主张**是什么？说不出来就重做。
2. 眯眼看，有**一个明确的明度结构**吗？还是一团灰？
3. 阴影里最亮处，仍暗于亮部最暗处吗？
4. 光有**方向和衰减**吗？
5. 主体在三分之一还是正中？正中是有意的吗？
6. 色彩四个角色**各司其职**吗？点缀色 ≤10% 吗？
7. 材质写了**可见行为**吗？不同材质细节级不同吗？
8. 有没有**形容词空转**（cinematic / beautiful / dramatic / masterpiece）？删掉。

默认纪律（**MOSS 口径**）：**零文字、零质量词、零画师串、只给正向、默认叠颗粒层**（用户点名要才破）。

> 这五条里「零质量词」只在 MOSS 成立。10958 条真实 NAI 提示词里 v4.5 有 81.5% 写 `best quality`，用户自己的 NAI 画师串模板也带着质量词——换到 NAI / SD / Flux 时按那个模型的规矩来，别把 MOSS 的禁令带过去（见 `references/real-corpus.md`「三、3.1」）。
>
> 同理，`lint.py` 的 **FAIL 口径也是 MOSS 的**：关 5 禁质量词/器材名、关 7 的人物比例尺、关 8 的明度定调句，都是按 MOSS 单向注意力的脾气标定的。拿一份 NAI 稿去 lint 被判 FAIL，先看是哪一关再决定改不改——**别用脚本的结论去改一个不归它管的模型**。真需要按 NAI 口径过一遍的那天，再加 `--target`，现在靠这一句就够。

**两种用法，别混：**

| 你在哪写 | 用哪一半 | 不用管哪一半 |
|---|---|---|
| 网页端手写（Gemini / ChatGPT / 即梦 / 可灵），或任何非 MOSS 的模型 | 七维决策 · `eye.md` · `composition.md` · `entry.md` 八槽 · `reverse-engineer.md` 反推 · `crop.py` / `look.py` / `probe.py` | `lint.py` · `compile_prompt.py` · `moss-rules.md` 的尺寸与 bbox 硬口径 |
| MOSS（本机生图 / 这个技能原始的目标模型） | 以上全部，再叠 `moss-rules.md` + 十三道关 | — |

前一半是**画面**的知识（哪里亮、谁挡谁、色占多少），换模型只改语法不改内容；后一半是**某一台机器的脾气**（单向注意力、bbox 放大倍数、零质量词），换机器就得重新标定。

## 出图后怎么办

**不要重写整份提示词。** 按这个顺序：

1. 有参考图时先跑 `scripts/verify.py 参考图 出图 --tag 名字`——它直接给出逐项差值、
   6×6 明度差矩阵、六类判据的诊断清单（每条带「该改哪句话」）和三联色差热图；
   没有参考图才用 `scripts/probe.py` 单独量出图（mean / dark / mid / nw / p99 / sat / lit vs shadow / soft / strong / flat）。
2. `references/symptoms.md` 找症状 → 它指向「改哪一句」和对应规则编号。
3. 只改那一句，重跑 lint，只重出一张。
4. 新发现的机制写回 `references/casebook.md`，编号续下去。

**数值能证明「暗部总量不足」，不能证明「某个东西没有」**——这是最容易犯的判读错误（G53）。

## 这个包不含什么

- 不出图。它只负责写、验、诊断。
- `references/casebook.md` 里所有 G 编号都是**某一台模型（MOSS-Image）的实测结论**。换模型时，G1–G98 的「机制」多半仍然成立（那是提示词语义层面的），但具体阈值（词数、bbox 放大倍数）要重新标定。
- `references/gap-audit.md` 里标记「不做」的题材是有意的空白，不是遗漏。
- 那份「八大美学支柱」的八行表已经撤了（七条互相重叠、落不了地），压成五句放在 `references/eye.md` 末尾当方向看。要核对的具体阈值仍以 `casebook.md` 为准。
- 同类的东西还有一张「核心美学法则」四行表，也撤了——光比衰减、微动与物证、高光锚点这三行本来就是 `lint.py` 关 13 的内容，受光结构面那行在 `references/entry.md` 04 节和 `moss-rules.md` G11（「三个落点，且明确只落这三处」）写得更细。**不要把检查项换一张表再说一遍**：读的人会以为多背一张表就能画好，实际只是把同一件事记了三遍。
