# Analyze Monitoring

1. Identify available MongoDB, host, Kubernetes, and application telemetry.
2. Verify coverage for replica state/lag, connections, operations, WiredTiger, disk, CPU/memory, and query latency.
3. Correlate database signals with application request traces and deployments.
4. Identify telemetry gaps before declaring the database healthy.
5. Route Datadog-specific investigation to `datadog-*` skills.
6. Avoid collecting sensitive document contents.

## Output
- Monitoring Coverage
- Key Signals
- Application Correlation
- Observability Gaps
- Recommended Action
