# Analyze Kubernetes

1. Resolve cluster, namespace, workload, pod, and service tags.
2. Inspect pod/container health, restarts, CPU/memory, throttling, scheduling, and Kubernetes events visible in Datadog.
3. Correlate infrastructure signals with application logs and traces.
4. Compare affected pods with healthy replicas.
5. Route Kubernetes resource-level investigation to the appropriate `aks-*` skill when direct cluster inspection is required.
6. Do not infer cluster root cause from application telemetry alone.

## Output
- Kubernetes Scope
- Workload Signals
- Pod/Container Findings
- Application Correlation
- Recommended AKS/Datadog Next Step
