# 从数人头到算算力：计价、薪酬与董事会叙事

## R — 原文 (Reading)

> 所以，你需要先考虑替换掉衡量公司的那把尺子。旧时代要数的是人头，而新时代要算的是算力，算力改变了公司的扩招逻辑。
>
> — 李开复，第8章《第三步：让组织像积雪被压实一样慢慢变扁平》

> 在以DRI为核心的组织里，组织为"他负责多重要的业务"付钱，而不再为"他手下站着多少人"付钱。
>
> — 李开复，第8章《钱跟着成果走，账跟着价值讲》

> 当你能指着财务报表说"这一笔算力撬动了这条产品线3个百分点的毛利率"，那笔吓人的支出就不再是单纯的成本，而是一项战略性投资。
>
> — 李开复，第8章

---

## I — 方法论骨架 (Interpretation)

当组织的执行主力从人变成智能体，三套沿用了几十年的制度会同时失灵：预算按人头编、薪酬按管多少人定、董事会按编制和成本看。这个框架把三者一起换掉。

**计价**：旧打法下多招一个人约等于多一份线性产能，还附带协调、管理、政治等摩擦；新打法下宁可支付一张金额不小的算力账单，给一个顶尖 DRI 配上一群智能体，也不轻易扩招。但关键不是"多买算力"——作者说得很明确，**给 DRI 的算力预算是越明智越好，而不是越多越好**：简单任务交给小模型，难任务用旗舰模型，重复内容善用缓存。原则是**像审人头预算一样去审算力预算**，每一笔花在哪里、为什么花、撬动了什么结果，都要说得清。

**薪酬**：DRI 不管人却直接对业务数据甚至某个财报科目负责，旧的按职级和下属人数定价的体系无法衡量他。新体系有三根支柱——底薪锚定"他扛起的那条产品线、那些毛利、那个客户群有多重要"，不看职级和下属人数（一个没有下属的 DRI，只要业务足够重要，底薪可以高过管着 20 人的经理）；浮动薪酬直接绑业务成果，能量化的尽量量化、写进承诺账本客观结算，而不是年底凭印象；核心 DRI 给准合伙人式长期激励（影子股、项目跟投、利润分成），让他从"替公司打工"变成"在公司里经营一家自己的公司"。

**叙事**：转型中途几乎一定会出现一个尴尬时刻——**员工人数在往下降，算力账单的数字却在往上涨**，财报上凭空多出一笔很大的支出。董事会一定会问这钱花在哪、值不值。答案是帮他们换一个视角：把算力作为**独立成本科目**列出来并计算 ROI，而不是含糊地塞进 IT 预算；同时讲清"人减少绝不等于业务规模收缩"——公司是在用更少的人达成过去根本达不到的产出。CEO 带进董事会的就三个指标：算力 ROI、制度记忆与业务记忆的沉淀量、成为 DRI 的员工比例。

## A1 — 书中的应用 (Past Application)

### 案例 1：零一万物自己推行的 DRI 薪酬体系
- **问题**：作者在自己公司推行 DRI 转型，旧薪酬体系无法衡量一个没有下属却直接对业务负责的人。
- **方法论的使用**：作者以身作则——他是"老板AI"的第一个用户，公司也是 DRI 转型的先锋，组织架构很扁平。公司里一些 DRI 是他用"老板AI"亲自发掘的；其他管理层成员借助同一套系统，也找出了之前被低估或高估的团队成员。
- **结论**：通过这个过程，作者意识到 DRI 组织和传统组织在激励机制上的差别——为"负责多重要的业务"付钱，而不是为"手下站着多少人"付钱。
- **结果**：这套薪酬体系在传统组织里很难运作，但在以 DRI 为核心的组织体系中反而逻辑自洽、能顺畅运行。**注意**：这条案例的样本是一家 AI 创业公司，见 B 段。

### 案例 2：那位 90 天提升 3 个百分点毛利率的年轻 DRI
- **问题**：一个没有人类下属的年轻人，独自负责把一条产品线的毛利率提升 3 个百分点——过去这需要一个部门。
- **方法论的使用**：她指挥一支由几个智能体组成的队伍：一个收集全球成本数据，一个建模，一个专门挑方案里的逻辑漏洞，还有一个趁她喝咖啡时把昨天的进展整理成简报。她不亲手算、不亲手写，只定目标、设边界、检验结果。
- **结论**：90 天后，3 个百分点的毛利率提升真的实现了。
- **结果**：这个人在旧薪酬体系里没有位置——没有下属、没有管理编制；在新体系里她的底薪应当锚定"一条产品线的毛利"，浮动薪酬直接绑这 3 个百分点。她同时是"算力 ROI"这个董事会指标的具体来源：这一笔算力撬动了什么，可以指着报表说清楚。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 员工人数在降、算力账单在涨，需要向董事会或 CFO 解释这笔支出。
2. 组织里出现了没有下属但直接对业务结果负责的人，现有职级体系装不下他们。
3. 在纠结"这个季度是扩招两个人，还是给现有的人加算力预算"。
4. 在设计 DRI 组织的考核仪表盘，旧的编制/预算/人头指标已经失效。
5. 在准备董事会材料，需要一套能讲清 AI 投入价值的指标。

### 语言信号

- "人数在降但算力账单在涨，董事会问值不值"
- "一个没有下属的人凭什么拿得比经理多"
- "扩招还是加算力"
- "AI 时代的组织该怎么考核"
- "这笔算力支出怎么向董事会交代"
- "旧的编制预算不管用了"

### 与相邻 skill 的区分

- 与 `token-cheap-system-valuable` 的区别：那个解决**整体 AI 预算的结构**（Token 与配套系统的比例）；本 skill 解决**组织的计价与激励制度**（算力作为成本科目、薪酬三支柱、董事会三指标）。前者是财务问题，后者是制度问题。
- 与 `dri-identify-empower` 的区别：那个解决**怎么找到并授权 DRI**；本 skill 解决**怎么给 DRI 定价和考核**。本 skill 的前提是组织里已经有 DRI。
- 与 `commitment-ledger` 的区别：那个提供"承诺兑现率"这一个输入；本 skill 是完整的薪酬与考核体系。

## E — 可执行步骤 (Execution)

1. **把算力从 IT 预算里拆出来，单列为独立成本科目**。
   - 完成标准：财报/管理报表上有一行独立的算力支出，能按业务线或 DRI 拆分。
   - 判停条件：如果算力无法归集到具体业务线，后面的 ROI 计算都是空话，先解决归集问题。

2. **像审人头预算一样审算力预算**：每一笔花在哪里、为什么花、撬动了什么结果。同时优化结构——简单任务用小模型，难任务用旗舰模型，重复内容用缓存。
   - 完成标准：每个 DRI 的算力预算有上限、有用途说明、有对应的业务指标。
   - 注意：判据是**越明智越好，不是越多越好**。

3. **重建薪酬三支柱**：
   - 底薪锚定"负责的业务有多重要"（产品线规模、毛利、客户群），不看职级和下属人数。
   - 浮动薪酬绑业务成果（毛利率提高几个点、留存率提高多少、周期缩短几天、风险控住没有），能量化的量化，写进承诺账本由系统客观结算，不在年底凭印象。
   - 核心 DRI 给准合伙人式长期激励（影子股、项目跟投、利润分成）。
   - 完成标准：能举出一个"没有下属但底薪高于某位管 20 人的经理"的具体案例并说清依据。
   - 判停条件：**改薪酬前先做劳动法与合规审查**，见 B 段。

4. **换掉考核仪表盘**：旧的看编制、预算、人头；新的看消耗的算力、换回的业务成果（算力 ROI）、以及言行一致指数。
   - 完成标准：新仪表盘上没有任何一项是纯投入指标。

5. **准备董事会的三个指标和一句话**：
   - 算力 ROI（每一笔算力花在哪儿、带来了什么成果）
   - 制度记忆与业务记忆的沉淀量（多少技能和流程已被编进系统）
   - 成为 DRI 的员工比例
   - 一句话：**"人减少绝不等于业务规模收缩——公司是在用更少的人达成过去根本达不到的产出。"**
   - 完成标准：能指着报表说出一个"这一笔算力撬动了 X"的具体因果，并且这个因果经得起追问（见 B 段的归因警告）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户要的是一次性成本核算或云账单异常分析——那是财务分析，不是计价体系改造。
- 组织里还没有 DRI，管理层级和职责分工照旧——本 skill 的三支柱在传统组织里无法运行，作者自己也这么说。
- 用户在做整体 AI 预算的结构调整——转 `token-cheap-system-valuable`。
- 强监管行业中薪酬结构受外部约束的组织（如受监管的金融机构高管薪酬）。

### 作者在书中警告的失败模式

- **算力预算越多越好的误解**：作者明确说"给 DRI 的算力预算是越明智越好，而不是越多越好"。
- **把算力含糊地塞进 IT 预算**：这样它永远是一笔说不清的成本，而不是可论证的投资。
- **用旧的管理跨度去想象新组织**："那把尺子已经不太适用了"——一个 DRI 能指挥的智能体几乎没有上限，而管理者借助 AI 也能带更多 DRI。
- **名义 DRI**：只给头衔不给授权，薪酬体系就失去了计价对象。

### 作者的盲点 / 时代局限

- **算力 ROI 的归因极难做实**，这是本 skill 最重的一条。"这一笔算力撬动了这条产品线 3 个百分点的毛利率"在方法上是一个**强归因主张**：同期还有定价调整、市场波动、供应链变化、团队努力等多个变量，书中没有给出任何剔除混杂因素的方法。这句话作为董事会叙事很有效，作为管理会计结论则不成立。使用时应当把它表述为"我们把这 3 个百分点中的多少归因于算力投入，依据是什么"，而不是直接断言。
- **薪酬改革涉及劳动法与既有合同**。"底薪锚定业务重要性而非职级"在实操中可能触及同工同酬、既有劳动合同变更、集体协商等问题，不同法域差异很大。**本 skill 不构成法律或薪酬合规意见**，落地前须由法务与薪酬合规审查。
- **作者以自己公司（一家 AI 创业公司）为样板**。零一万物的组织规模、人员构成、股权工具灵活度、以及员工对不确定性的承受力，与传统企业差异极大。"扁平架构 + 准合伙人激励"在创业公司是常态，在有几十年职级体系和工会的传统企业里是另一回事。
- **"人减少不等于业务收缩"这句话对董事会有效，对员工无效**。本 skill 的整个叙事是从资方视角组织的，被减少的那部分人在框架里没有位置。
- **三个董事会指标里有两个难以客观计量**："制度记忆的沉淀量"如何计数、"DRI 员工比例"中 DRI 如何认定，书中都没有定义。缺少定义的指标最容易被做成数字游戏——这恰恰是作者用古德哈特定律批评过的事。
- **框架假定算力成本会持续下降**（因此可以放心用算力替代人头）。若单价上涨或供给受限，"宁可付算力账单也不扩招"的逻辑会反转，而人已经不在了。

### 容易混淆的邻近方法论

- 与 FinOps / 云成本管理不同：那是压降单位成本，本 skill 是把算力当作可论证 ROI 的生产要素来治理。
- 与传统岗位价值评估（如海氏评估法）不同：海氏也评"岗位重要性"，但其要素里包含管理幅度；本 skill 明确剔除下属人数。
- 与经营单元制/阿米巴不同：那些是把组织切成核算单元，本 skill 的计价对象是个人 DRI + 其算力消耗。
