# Agent UX 设计

## 核心原则

1. **状态可见**——思考、调工具、等待人类、失败恢复都要有明确反馈
2. **不确定性可表达**——用引用、置信标签和“我不确定”替代假装确定
3. **可中断、可纠错、可恢复**——用户随时能停、能改、能从断点继续
4. **延迟要被管理**——先流式给结构，再逐步补内容；长任务显示进度
5. **成本可感知**——高风险或高成本操作前提示预估消耗
6. **反馈闭环**——采纳、修改、放弃、转人工都回流为 eval 用例

## 交互模式

🤖→👤 AI 建议人类审批

## 输入

| 输入项 | 类型 | 必填 | 来源 | 说明 |
|--------|------|------|------|------|
| 评测计划 | object | 是 | `eval_plan.json` | 任务成功标准与失败模式 |
| 护栏规范 | object | 是 | `guardrail_spec.json` | 权限、升级与降级边界 |
| 用户旅程 | object | ○ | 上游 PRD / 用户流程 | 任务发生场景与频率 |
| 品牌与语气 | object | ○ | 上游定位 / 品牌规范 | 文案风格与透明度要求 |
| 性能基线 | object | ○ | 埋点 / APM | p95 延迟、成本、失败率 |

## 执行步骤

1. [核心] 定义交互状态机——idle / thinking / streaming / tool_running / waiting_human / error / recovering / done
2. [核心] 设计不确定性展示——引用来源、置信标签、假设声明、无法回答时的替代路径
3. [核心] 设计中断与恢复——停止按钮、草稿保留、断点续跑、取消后的资源释放
4. [核心] 设计纠错路径——局部重写、参数修改、换模型/换工具、转人工
5. [核心] 设计延迟与成本体验——骨架屏、阶段进度、token/费用提示、长任务后台化
6. [核心] 设计反馈采集——采纳/修改/放弃/转人工信号与复盘节奏

## 质量检查

- [ ] 交互状态 ≥ 4 个，且每个状态有触发、可见反馈与退出条件
- [ ] 不确定性展示包含引用与置信标签
- [ ] 停止、恢复、草稿保留行为明确
- [ ] 纠错路径覆盖局部修改与整体重来
- [ ] p95 延迟与单任务成本有目标值
- [ ] 反馈信号已接入 eval 回归
- [ ] 高风险操作前有成本/后果提示

## 决策规则

| 条件 | 决策 |
|------|------|
| 任务 > 5 秒 | 流式 + 阶段进度，不显示无限 loading |
| 输出不确定 | 显示引用与“需人工确认”，不省略 |
| 用户中断 | 保留草稿，释放工具资源，可恢复 |
| 成本超阈值 | 先提示预估，再等待确认 |
| 连续失败 | 提供转人工与降级路径 |
| 高频低风险任务 | 减少确认步骤，保留撤销 |

## 降级策略

| 缺失项 | 降级方案 | 影响 |
|--------|----------|------|
| 无性能基线 | 用行业默认 p95 与成本上限 | 目标可能偏乐观 |
| 无品牌规范 | 采用中性、透明的系统语气 | 品牌一致性下降 |
| 无反馈埋点 | 先采集显式 thumbs 与转人工 | 信号稀疏 |
| 无中断能力 | 提供“重新开始”而非断点续跑 | 长任务体验下降 |
