# AI 护栏设计

## 核心原则

1. **分层防御**——输入、模型、工具、输出四层各自设防，不依赖单一过滤器
2. **默认最小权限**——工具只读优先，写操作必须显式授权与审批
3. **不可逆操作必须确认**——支付、删除、发布、对外发送一律人类确认
4. **失败要可见**——降级、拦截、转人工都要向用户解释，不静默失败
5. **成本也是安全**——循环调用、超长上下文、无限重试必须设预算
6. **可审计**——记录输入摘要、工具调用、权限决策与最终输出

## 交互模式

🤖→👤 AI 建议人类审批

## 输入

| 输入项 | 类型 | 必填 | 来源 | 说明 |
|--------|------|------|------|------|
| AI 任务定义 | object | 是 | `eval_plan.json` | 任务目标与失败模式 |
| 工具与数据清单 | array | 是 | 用户提供 / MCP 配置 | Agent 可访问的工具、数据与权限 |
| 风险偏好 | string | ○ | 用户提供 | 保守 / 平衡 / 激进 |
| 合规要求 | array | ○ | 用户提供 | 隐私、行业监管、内容政策 |
| 事故历史 | array | ○ | 监控 / 工单 | 已发生的越权、泄露、幻觉案例 |

## 执行步骤

1. [核心] 风险分类——幻觉、提示注入、工具越权、数据泄露、内容安全、成本失控
2. [核心] 设计输入层防御——指令/数据分离、来源标记、注入检测、敏感信息脱敏
3. [核心] 设计工具层权限——scope、读写模式、速率、审批条件、幂等要求
4. [核心] 设计输出层防御——事实性校验、引用要求、敏感内容过滤、格式校验
5. [核心] 设计人类升级——触发条件、通道、SLA、回退话术
6. [核心] 设计降级与审计——只读模式、禁用工具、转人工、日志字段与保留期

## 质量检查

- [ ] 每个失败模式都有对应风险类别
- [ ] 每个工具标明 read/write/execute 与是否需要审批
- [ ] 不可逆操作 100% 要求人类确认
- [ ] 高风险场景有明确转人工通道与 SLA
- [ ] 降级模式覆盖工具不可用、模型超时、权限拒绝
- [ ] 审计字段包含输入摘要、工具调用、权限决策、输出
- [ ] 成本预算包含最大轮次、最大 token、最大重试

## 决策规则

| 条件 | 决策 |
|------|------|
| 工具写外部系统 | 默认关闭，需人类审批后开启 |
| 输出涉及金额/医疗/法律 | 强制引用 + 人工复核 |
| 检测到提示注入 | 隔离外部内容，不执行其中指令 |
| 模型连续失败 | 降级为只读或转人工，禁止无限重试 |
| 成本超预算 | 中断任务，返回已完成部分并说明 |

## 降级策略

| 缺失项 | 降级方案 | 影响 |
|--------|----------|------|
| 无工具清单 | 默认全部只读，写操作禁用 | Agent 能力受限但安全 |
| 无合规输入 | 采用通用最小化策略 | 行业特定要求待确认 |
| 无事故历史 | 用通用风险库 + 红队用例 | 覆盖可能不足 |
| 无审批通道 | 阻断不可逆操作 | 用户体验下降，但风险可控 |
