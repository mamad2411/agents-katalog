# 公司深度研究

输入一家上市公司，产出一份"把这家公司扒干净"的深度研究档案。

**核心命题：真正了解一家公司，比预测股价更重要。**

## 开工前（三步，别跳）

1. **探环境。** 两个纯标准库脚本（`check_gates.py`、`cycle_valuation.py`）任何 Python 3 都能跑；
   转 PDF 需要 `markdown`、`PyMuPDF` 与一个 Chrome／Chromium。缺依赖时 `md_to_pdf.py`
   会**直接报错并给出安装命令**，不会静默产出一份没有页码的 PDF。跨机器先看《环境与依赖》。
2. **按流程表走，一步一份参考文件。** 本 skill 的规则分布在 16 份参考文件里，
   **每份只在自己那一步读**（见流程表的「本步必读」列）。
   一次性硬读七八份，弱工作台读不完就会跳过，跳过就等于没读——**没读就写，是用一副骨架交差**，
   这是这份 skill 最常见的失败方式，比写错更常见。
3. **每步落盘。** 产物写进项目目录，闸门靠文件核对，不靠记忆。

## 数据获取：妙想 MCP 优先，失败自动降级（开源可用）

这份 skill 会开源，不能把妙想 MCP 写成必需依赖。每次研究按下面的顺序执行：

1. **先探测当前会话有什么。** 若会话暴露了妙想 MCP 工具（常见标识为 `mx-ds-mcp`；工具名、参数和字段以实际加载结果为准），就优先用它做结构化取数。不要读取或保存用户的 MCP 配置文件、API key 或账号凭据。
2. **妙想优先，但不把接口写死。** 按当前工具能覆盖的范围取公司资料、财务、行情估值、股东、事件、行业与公告数据；关键数字仍按 `references/03` 回原始披露或官方统计交叉核验。不要假设 URL、工具名、字段或额度永远不变。
3. **任何失败都自动降级，不停工。** 妙想未安装、调用失败、开始收费、额度不足、鉴权失效、限流、持续超时、字段缺失或口径不匹配时，**立即改走 `references/03` 的公开接口与本地脚本**，不要先等用户决定，也不要把“未安装妙想”当成缺数据。把失败原因、已走的降级路径和仍未取到的项记进取数台账。
4. **报告照常完成。** 降级后仍缺的数据，按“已试路径／可继续查的具体渠道／需要什么条件”三行登记；Gate 1 允许“已取”或“三行缺口”，缺口本身不阻塞后续研究和首版报告，但必须进入正文第 10 节与溯源表。
5. **交付后单独报缺口。** 报告交付后，必须再给一份 `02-工作底稿/数据缺口与补数清单.md`：缺什么、影响哪一节或哪个结论、已试过什么、建议去哪里查、需要什么权限或费用、补数后要重跑什么。不要只口头说“有些数据没拿到”。
6. **用户补数后修订完整报告。** 用户若提供 Wind、Choice、iFinD、Bloomberg 或其他接口导出的 CSV／XLSX／JSON，或只读接口，先把原件存入 `01-原始资料/补充数据/`，更新取数台账与溯源表，再重跑受影响的计算、图表和估值参照带；结论变化就改正文并说明变化，不变化也要写明“补数后结论未变”。修订后重跑闸门、重新生成 PDF，交付带版本号的新稿——**不能只在正文替换一个数字**。

## 铁律（违反即返工）

1. **不给投资建议。** 不出现买入/卖出/增持/减持/目标价/仓位/买卖评级。但**必须有判断**——"公司利润几乎完全跟着锂价走""增长完全押在单一客户身上"都是事实判断，要写。没有判断的报告是资料汇编。
   与之配套：**可以给估值参照带，不可以给目标价。** 参照带 = 在明确假设下、由可复算算式推出的
   区间，必须同时给出推导链、样本区间、假设清单、局限说明，四项缺一即视为目标价（见 `references/05`）。
   **可以写产业周期与择时，不可以写交易指令。** 产业处在产能周期第几阶段、股价两波上涨分别落在哪个位置、
   事件日历、风险最高的窗口——都是对**行业状态与历史节奏**的陈述，要写（见 `references/08` 第八节的
   允许／禁止对照表）。被禁的是"建议买入""逢低布局""目标价 X 元""仓位 X 成"这类**决策指令**。
2. **无来源不写，但缺口要给出路。** 每个数字都要能回溯到来源；查不清就进"待核实清单"
   （**落在正文第 10 节的数据缺口，不进附录**——附录 I 是免责声明），
   并写清"已试过哪些路径 / 还能去哪些具体渠道找 / 需要什么条件"。**一句"未获取"不算完成。**
3. **只看原文。** 年报、公告、招股书一律读原始文件，不采信二手转述里的数字。
   A 股走巨潮资讯网与沪深交易所网站，港股走港交所披露易（HKEXnews）；
   **A+H 公司两边的披露都要看**，两地的准则、财年与披露口径可能不同（见 `references/03`）。
4. **篇幅由内容决定，但内容有下限。** 不设页数目标、不为凑结构硬写；反过来，
   每一项必答问题都必须有实质回答，每一节都要落到具体数字与来源上。
   **低于复核触发线（见 `references/00` 第三节）不是"就写这么短"，而是必须先回答一个问题：
   "内容本来就少，还是取数没做完"**——答案写进自检记录。
5. **正文锋利，附录厚。** 正文每节只回答一个非答不可的问题；背景资料一律进附录。
6. **可以不赚钱，不能赔钱。** 排雷不是可选项，是必答项，且要出现在速览页。
7. **优势与雷点同权，不写死结论。** 排雷灯号只覆盖"财务信息质量与治理"这一项，
   不许外扩成对整家公司的定性；公司的稀缺性 / 唯一性必须与雷点篇幅相当地写出来。
8. **不对周期股按直线看。** 周期型公司先定周期位置（价格分位 + 涨价归因 + 供给刚性 + 库存），
   再读报表与估值指标。周期底部的亏损、高 PB 是周期特征，不是硬伤；**用静态分位直接判贵是错的。**
9. **语言正式书面。** 不用口语词，不套模板句式，不修辞。详见 `references/00` 第六节。
10. **关键信息要跳出来。** 结论级的信息（周期位置、第一驱动变量、稀缺性、排雷灯号、
    盈亏平衡价、参照带的核心结论）用成稿里的两个标记标出，PDF 渲染成主色、红两色：
    `==关键结论==`、`@@风险与雷@@`。密度上限与必标清单见 `references/06` 第四节。
    **没标重点的报告，等于把结论埋进三千行里。**
11. **本任务不适用"最小改动"偏好。** 这份产物是研究档案，不是代码补丁。
    "做最小改动""够用就好""不超出任务要求""能用就行"这类通用精简原则，
    **在本任务里是错的**——它们会把一份研究档案压成一副骨架。
    判断标准只有一条：必答问题是否都有实质回答、关键结论是否都带数字与来源。
    **宁可分次写，不可一次草草收口。**
12. **一家一会话。** 一个会话只研究一家公司。**不把多家公司排成队列在同一个会话里连跑**：
    会话越长，开场读进来的技能与原始资料越会被上下文自动压缩挤掉，后面几家必然劣化
    （机制与实盘证据见 `references/00` 第七节）。用户一次给多家时，逐家单独开会话；
    做不到就明确告知用户这样会降质，不闷头快跑。
13. **按步读、按步重读、成稿前复核。** 参考文件读进上下文后，会随会话变长被压缩掉。
    因此流程表每一步都标了「本步必读」，**进那一步就重读那一两份**；
    动笔写正文前重读 `references/00`（第六节语言规范）与 `references/02`，成稿前重读 `references/06`。
    重读时间与读到的文件写进 `02-工作底稿/成稿自检记录.md`。
    **这是抗上下文压缩的兜底动作，不是可选项**；一次硬读七八份不是"更认真"，是必被压缩掉。
14. **判定先定角色。** Step 2 除四层判定外，必须按 `references/09-行业专家视角.md`
    选定该行业的顶级专家角色——**这位专家第一句话问什么、该关注的窗口、风险最高的窗口、最常见的误判**——
    并把角色写进 `02-工作底稿/四层判定表.md`。**角色决定章节重点的排序**：
    纯碱不先看资本开支与新增产能三张表、民爆不把牌照与事件日历当主线，
    报告不会显得残缺，却会**没有用**。不选角色，就会用一套通用框架套所有行业。
15. **成稿之后，用投资人的眼睛再读一遍（Gate 3）。** 按 `references/10-投资人视角复核.md`，
    以**真正要管钱的人**的位置通读成稿：只读速览页能不能复述全文骨架、只看标题与首句能不能拼出推理链、
    必问清单里"哪些重要但没写"逐条追。结论写进 `02-工作底稿/投资人视角复核.md`，
    命中缺口先回补、再重跑 `md_to_pdf.py`。**这一步专抓"每一项都写了、读者还是没拿到答案"。**
16. **报告里不出现方法论的底本。** 本 skill 以《如何快速了解一个行业》为内部底本，但**交付研报里
    不得出现与它（或任何方法论文献）的对照、衔接与引用字段**——"本书""与书中方法一致"
    "按书中口径"这类句子一律不写。行业惯例、模型选择、公司在市场中的位置，直接用行业口径表达。
    **书是研究时的脚手架，不进交付物**（用户 2026-10-13 指定）。
17. **成稿之后，反过来想，再反过来想（Gate 3.5）。** 按 `references/11-反向质疑与遗漏排查.md`，
    把结论当成**已经错了**，回头去找它会错在哪里：这套判断要成立必须哪些前提为真、
    三年后亏了最可能死于什么、谁有动机让我看到乐观的一面、什么能推翻**空头逻辑本身**。
    **多空两侧都证伪过一遍，报告才算立住。** 结论写进 `02-工作底稿/反向质疑.md`，
    再压缩进速览页一行与第 10 节两张短表。**质疑做得越认真，越要克制它在正文里的占用**——
    这一步是自检层，不是新增一章。
18. **表达要去 AI 味（词、句、节奏三层）。** 不把生意比成"引擎""外壳""开关""价差机器"，
    不堆"中枢""兑现""护城河""颗粒度""维度""锚"这类咨询腔，不用"不是……而是……"的对比套式，
    段落长短要参差、各模块不许同构、表格后不复述。**判定标准一句话：这句话，
    券商研究员在正式研报里会不会这么写？不会，就是 AI 味。** 替换表、限频上限与成稿前搜索命令
    见 `references/00` 第六节《去 AI 味》与《行话与术语》；**完整清单与「不许动」清单见
    `references/14-反AI文稿.md`（那是判定依据，本节是执行摘录）。** **不调用任何"去 AI 味"文案 skill**（用户 2026-10-14 指定）
    ——那些工具按人读文案的口径改，会把书面语改回口语。
19. **漂亮的指标先质疑，再引用。** 年报里的"名次"与"评分"（NPS、满意度、品牌力指数、
    行业第一、蝉联冠军）是**公司转述的第三方榜单结论**，不是经营数据。凡要用它支撑优势、
    壁垒或定价权，先做四步：核口径与样本 → 比行业基准 → 和销量／收入／份额／复购对一遍 → 定采信档。
    **指标极好而经营数据持续走坏，就是背离，必须在正文把矛盾写出来，不能只写好看的那半边。**
    核不到报告原文时只能**引用原文原话**并标注"未取得报告原文，比较范围与调查方法无法独立验证"，
    **不得转述成结论**（写"年报称……并引述某报告列为第一"，不写"该品牌口碑行业第一"），
    也不得把它留在"优势"一节里当论据。**年报的真实性不是研究者评判的对象，
    但投资者有权质疑任何官方数据**——这正是行业专家视角、投资人视角复核与反向质疑存在的初衷。
    四步核查、三档采信写法与落点见 `references/11` 第九节。
20. **算出来的数字先过口径与对照。** 吨成本、吨毛利、单店收入、单客价值、隐含市值、盈亏平衡价
    这一类，是研究者自己拿两个数算出来的，年报里没有现成的。三条：
    ① **分子与分母必须同口径**（集团还是分部、含不含贸易量、含不含财务费用），
    有一项答不上，就不能把它写成"成本""毛利"；
    ② **每个单位数必须拿一个独立来源的同量级数字比一次**，差一倍以上的降为"推算值，仅供量级参考"，
    不得承担关键结论；
    ③ **反推得来的临界值不进速览必记数字**——速览页的数字会被读者当成这家公司的属性记住，
    反推值只是某个假设下的解，它属于第 9 节，并要写明假设与移动幅度。
    **脚本只会算，不会判断这个算式成不成立**：`cycle_valuation.py` 正常跑完不等于算对了。
    五法（口径三问 / 独立源对照 / 退化测试 / 极值试探 / 档位标注）与逐模型自检表见
    `references/12-模型自检与交叉验证.md`。
    **来由：** 2026-10-12 海南橡胶报告把**集团口径**的亏损除以**自产端**的敏感度，
    解出 33,572 元/吨，又在速览页用"打平全部成本所需的胶价"作解释，读者记成了"吨成本三万多"
    （真实量级约 1.5 万至 1.6 万元）；同报告 2.4 节的"单吨完全成本"表用的是同样的错配口径。
    两处都不是计算错误，是口径问题。

21. **复盘价格的历史，不解释每日的涨跌。** 上市以来（或近 10—15 年）的**中长线**涨跌必须复盘：
    每一段是**利润推的还是估值推的**（把区间涨跌幅拆成 利润侧与估值侧（每股收益、市盈率））、
    **调整段持续了多久、事后看什么结束了它、当时最早能看到的先行信号是什么**、
    按本公司自身历史与行业经验这类调整**通常**持续多久（化工约 2—3 年，小金属与矿山类 5—10 年，
    视行业的时间常数而定；除行业时间常数外，市场环境、流动性、制度与政策也会改变调整长度）。
    **股票短期是投票机、长期是称重计**——日线的涨跌没有可复现的因果，
    写下"某月某日下跌是因为……"就是编。写到消息催化与政策催化时，**必须标明它不可复制、
    对未来的参考价值有限**（一次性催化与结构性驱动要分开，后者才是可前置判断的部分）。
    切段方法、利润侧与估值侧拆解（每股收益、市盈率）、调整段专项九列、结束信号清单与行业对照基准见
    `references/13-历史股价复盘.md`；措辞规范与 `references/08` 第八节共用。
    **复盘只写到"位置与节奏"，不写交易指令**（与铁律 1、铁律 8 一致）。


22. **派生文件不进交付物。** 年报抽出的文本副本、接口的原始响应缓存、一次性跑数的中间输出、
    转 PDF 时留下的中间 HTML，都是干活的脚手架，**交付时列清单、经确认后清掉**
    （动作与「哪些算派生物」见 `references/00` 第七节第 5 条）。抽取副本写 `02-工作底稿/文本/`，
    不堆在 `01-原始资料/` 的原件旁边；**引用坐标一律落在原件上（文件名 ＋ 页码／表号），
    不写副本的行号**——副本清掉之后，行号引用没人能核。


23. **状态判读写成人话，不写状态行。** 速览页与正文里不出现字母代号（"C · 顶部结束"）、
    计数当结论（"顶后读数 4 条对中继 3 条"）、指针互指（"排除的理由即前四条"）、
    括号里的并列清单（一个括号塞四件事）、参数串（"-75.1%／36.5 个月"）、统计记法（"n=4"）。
    这些记法属于表格、底稿与附录；**正文一句话只装一件事**——判断，加上支撑它的那个读数。
    **判据：这句话念给一个人听，对方要不要重听一遍？要，就是机器腔**
    （七类写法、改写示例与可数项见 `references/00` 第六节·机器腔）。


24. **报告写的是公司，不是研究方法。** 正文不交代作者怎么取角、怎么排章节，
    不引用底稿栏位（"（四层判定表××栏）"），不写"盈利特征判定直接决定各节权重"
    "行业专家角色取××研究员""章节顺序按这一问排列"。**判据：这句话的主语是公司或行业，
    还是"我这份报告"。** 底稿里的角色栏与模块启用表照旧要写，只是不进正文
    （改写示例见 `references/00` 第六节·过程自述）。


25. **报告要自足，正文不指向别的文件。** 正文里不出现"（详见底稿）""底稿《四层判定表》4.0"
    "完整 13 段见底稿《历史股价复盘》"，也不把判据推给内部工具的名字
    （"按分流三问（两问为否）""按五阶段读"）——**把判据的证据写进正文**。
    **判据：读者手里只有这一份 PDF，这句话他读不读得懂。** 要留完整版就放附录；
    附录 G 溯源表里列文件路径是来源登记，不算违规（见 `references/00` 第六节·报告要自足）。
    **表题与表头同样自足**：表题只写「表 X-Y　名称」，不写"（`08` 4.6 六项）"式编号；
    表头不用"读数""取数"这类圈内词；表里不写"四态 C"式代号（见 `references/06` 第五节）。


26. **标注是圈原词，不是另写一句。** `==关键结论==`／`@@风险@@` 里的文字必须是原句已有的词；
    不许把刚说过的意思在标注里再写一遍（"……向阶段三（供给追赶）的过渡，==处阶段二向供给追赶过渡=="）。
    **自检：把标记去掉再读这句——通了是圈出来的，读不通是插进去的。**
    成稿前列出全部标注连同前 55 字逐条读（`rg -n -o '.{0,55}==[^=]{4,}?=='`），
    见 `references/06` 第四节与 `references/00` 第六节·标注不写第二遍。


27. **行业状态写方向，不写进度；也不写编号式波次。** 两个毛病会长在同一句话上。
    **① 方向反了。**"第一波上涨的触发条件尚未凑齐"读起来是"只差临门一脚"，
    而判据可能是"资本开支未见负增长、亏损面未扩大、库存未至低位"——事实是还在往下走。
    **结论必须照判据的方向写**：出清没有进展、供给没有收缩、基本面还在走坏、价格缺乏上行动力。
    **② 序数没有起点。**"第一波上涨""第二波"是周期股的口头叫法，读者不知道你从哪儿数起；
    股价已经走过一轮并回落之后还这么写，同页又写着"上一轮高点在 2025 年 11 月、回撤约 39%"，
    连起来读就是"股价都涨完了还说没开始"（中粮糖业实盘）。
    **判据只有一条：这句位置判断与同页的股价节奏坐标连起来读，会不会读成两个故事。**
    会，就改到一致；手上有上一轮的起止与幅度就用上，没有就不写，不硬凑
    （见 `references/08` 第二节末、`12` 第四节之三）。
28. **图表按"形状"出，不按"有没有数据"出。** 表装得下数字，装不下形状——价格怎么走的、
    库存在哪一段、利润被什么压住的，都是形状。**正文图数 ≥ 8 张，第三、四、六、八节各至少一张**
    （核心变量时序／行业供需与库存／公司利润史／股价与估值复盘）；同一节有两组独立时序就画两张。
    **不算数的三种**：把相邻的表原样重画、一张图塞两件不相干的事、图注复述图里的数字。
    张数不够 Gate 2 不过，见 `references/06` 第五节。

29. **当期利润只算单季，所有标的都做，三情景、桥表与两次校验缺一不可。** 只做基准季与测算季，
    **不做全年**，也不把四个季度相加当年度预测；单季一律用累计数相减。价格与成本要同时看
    过去 12～24 个月的实际序列、当下的现货与期货、未来一至两季的期货远月与库存拐点；
    可比商品、替代品与国际同品种的过去序列与未来曲线用来判断这是全局异动还是区域错配，
    并用历史价差分位与领先滞后关系校验，不把相关性当因果。三情景的每一组
    假设都要能复算，**不许先定利润再倒推假设**。桥表从基准季归母走到测算季归母，
    **残差绝对值不得超过 0.01 亿元**；价差型与量价型必须画利润桥瀑布图。
    至少做两次**不同类**校验（算术闭合、数据一致、反推对照、同季回测），任一次出错就回
    基准季重算，校验次数清零重计。缺数据按五行缺口表写清，**补不到就不算**，
    不许用"行业景气"替代销量或价格。基准季以上一季为桥、以去年同季做季节校正，
    两者差异超过 10% 时写明取哪个、为什么。**所有标的都做，但分完整测算与轻量测算两级；
    轻量测算不得省掉单季口径、三情景、校验与缺口表，只可省去拆不出的分部与不适用的瀑布图。**
    做法与模板见 `references/15-当期利润测算.md`。

```bash
python3 scripts/check_gates.py --project <目录> --stage 1          # 只查 Gate 1
```

脚本逐项数：台账七类是否填满、缺口是否三行齐全、排雷表与附录 D 的行数、附录 E 家数与国际同业数、
成稿字数是否过触发线、标注处数是否超限且成对、十一份底稿是否落盘（含条件触发的指标核查）、
历史股价复盘的段数与拆解列是否齐、正文有没有越界措辞，
成稿里每个自算的单位数是否在 `单位数核查.md` 有行、倒推行是否写了对照基准、
速览必记数字里有没有反推值、有参照带的是否配了 `模型自检.md`，并顺带体检文体（破折号、整句加粗、自我指涉、讲解文标记、
过渡词按 `warn` 提示，不阻断）。
**退出码 0 才往下走**；它查的是可以数出来的东西，模型强弱与上下文压缩都影响不到它。
换工作台、换模型，跑同一条命令得到同一套判断——**这是跨 agent 适配最硬的一环**。

**为什么设闸门。** 这份 skill 最容易的失败方式不是写错，是**少做**——少取一类数据、
少跑一项排雷、少写一行溯源，成稿照样能渲染成 PDF，从外面看不出来。
闸门把这些"少做"变成看得见的缺口。**Gate 1 与 Gate 2 是写的人自查；Gate 3 第一次用读的人的眼光看成品；Gate 3.5 再把结论当成已经错了、回头找它会错在哪**——三副眼镜层层设防。
它专抓"每一项都写了、但读者还是没拿到答案"这类问题。台账格式见 `references/03` 第五节。

## 脚本

| 文件 | 干什么 | 依赖 |
|---|---|---|
| `scripts/check_gates.py` | **闸门（Gate 1/2/3/3.5）的机械校验**：台账、行数、字数、标注、禁则、反向质疑；退出码 0 才算过 | 只用标准库 |
| `scripts/chart_svg.py` | 数据 → SVG：折线／纵向条形／横向条形／**瀑布图**（利润桥；柱子合计与终点对不上即报错，不产出半成品图） | 只用标准库 |
| `scripts/md_to_pdf.py` | Markdown 成稿 → 交付 PDF：规范化、生成封面／目录、迭代对齐目录页码、盖页眉页脚与封面色带、写书签 | `markdown`+`PyMuPDF`+Chrome |
| `scripts/cycle_valuation.py` | 周期股估值参照带：价格分档的估值指标分布、盈利阶梯（标注哪些档是外推）、盈亏平衡价（附基准利润的杠杆表）、临界价反算、分年稳健性检查（自动判体制断裂）。**金融股（保险／银行）用 `--band-only --xlabel "<横轴名>"` 只跑第一段与第六段**——利润对利率不是线性关系，后三节算出来没有经济含义；横轴换成利率时把 `--prices` 换成利率序列、`--bands` 按基点分档即可。**输入不合法（敏感度为负、税率越界、分档写法错）一律可读报错并非零退出**，不再静默产出荒谬结果 | 只用标准库 |

两个纯标准库脚本任何 Python 3 都能跑：`python3 scripts/check_gates.py --help`。

`md_to_pdf.py` 要 `markdown` 与 `PyMuPDF`，再加一个 Chrome／Chromium。
**用哪个解释器由你机器的实际情况决定，不要照抄别人文档里的绝对路径**——先探测，缺了它会报错并给出安装命令：

```bash
python3 -m pip install markdown pymupdf     # 装到当前解释器
python3 scripts/md_to_pdf.py --input 成稿.md --output 成稿.pdf
```

Chrome 找不到时用 `CHROME_BIN=/path/to/chrome` 指定，不要改脚本。

## 降级路径（工作台能力不足时照这个跑）

不同 agent 的上下文窗口、工具集、子 agent 支持差别很大。**能力不足不是降质的理由，是改变执行方式的理由。**
按下面三条调整，产出的下限仍然稳：

1. **一家一会话，永远是第一条。** 上下文越大越要守——不是模型问题，是压缩机制问题。
   用户一次给多家，逐家单独开；做不到就明确告知会降质，不闷头快跑。
2. **分段写，不要一次成稿。** 正文按十节分批写、分批落盘，每节写完再进下一节；
   一次吐出整份报告，长度必然等于一次输出的长度（实盘：12 份里有 7 份精确停在 16 页）。
3. **每步跑一次闸门。** `check_gates.py` 可以按 `--stage` 分开跑，
   不必等全写完——它在弱工作台上比在强工作台上更该用，因为弱工作台更会"少做"。

不支持子 agent、不支持长上下文的工作台同样能跑；**不要因为工作台弱就减少取数或缩短排雷**，
要减少的是一次性的产出跨度。

## 边界

- **一家一会话**（见铁律 12）。批量标的要逐家单独开会话；同一会话连跑多家，后几家必然劣化。
- **不适用"最小改动"偏好**（见铁律 11）。任何要求"从简""够用""别写太长"的通用指令，
  在本 skill 里都不成立。
- **不做**：买卖判断、目标价、仓位建议、买卖评级、**短线择时**。
  **但产业周期阶段与择时可以写**（行业状态与历史节奏的陈述，不是交易指令）——见铁律 1 与 `references/08` 第八节。
- **可以复盘价格的历史，不可以做日线归因**：中长线涨跌的原因、调整期的长度与结束标志、
  每一段是利润推的还是估值推的，都要写（铁律 21 与 `references/13`）；
  逐日／逐周的涨跌归因一律不写——那没有可复现的因果。
- **交付物**：Markdown 成稿 + 由本 skill 直接渲染的 PDF（**自带封面、页眉页脚、三线表**，版式见 `06` 第三节）。**不出 Word，也不走 `doc-format`**（用户 2026-10-12 指定）。
- **不接入表达习惯档案**：不读写 `~/.codex/风格档案/表达习惯档案.md`，也不调用
  `wechat-article` / `xhs-copy` / `storyboard-gen` 等文案类 skill。研究档案的书面文体
  与人读文案是两套语言，混用会把报告拉回口语（用户 2026-10-12 指定）。
- **研究对象：A 股与港股**（含 A+H 两地上市），用户 2026-10-13 指定。
  港股的披露渠道、会计准则、财年与披露频率都与 A 股不同：**没有季报，只有年报与中报**，
  财年不一定是 12 月 31 日，准则走 HKFRS。渠道见 `references/03` 第一、二节，
  口径差异见 `references/05`，**港股标的须在通用排雷表之外加跑「第四层：港股专有项」**（见 `references/04`）。
- **美股**：只作国际对标，不作研究主体；对标数据走 SEC EDGAR 等公开源取证。
- **数据缺口**：拿不到就明写"公开渠道未获取"，不用推测填补。
- **当期利润测算只做单季**：给基准季与测算季、三情景、桥表与两次校验；不自行预测价格，只把期货远月、
  库存与季节性写成可复算假设；不做全年、
  不给目标价（见铁律 29 与 `references/15`）。
- **开源与跨工作台适配**：本 skill 按"任何 agent 都能跑"设计——无本机绝对路径、无其他 skill 硬依赖、
  无 API key；约束尽量落在**可数的文件与脚本**上，而不是"记得"。随包附 `README.md`（环境要求与安装）；
  改本 skill 时先读 README 的《改动前检查》。
