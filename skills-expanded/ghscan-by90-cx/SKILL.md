# cx Rust 测试补充

## 边界

本技能不负责 Rust 通用实现流程，也不重新定义测试先行步骤。先完整执行 `$cx-tdd`，再把本技能的 Rust 规则叠加到同一个测试循环中。

没有明确测试要求时，不使用本技能，不创建、不修改、不运行 Rust 单元测试。

## 测试与生产代码隔离

- 生产源码中绝对禁止出现 `#[cfg(test)]`、内联 `mod tests`、测试函数、测试夹具、测试数据或只供测试使用的入口。测试代码只能位于与 `src/` 同级的仓库根目录 `tests/`。
- `tests/` 尽可能逐层镜像 `src/`。`src/<subsystem>/foo.rs` 只对应 `tests/<subsystem>/foo_test.rs`；`src/foo.rs` 只对应 `tests/foo_test.rs`。
- 一个需要测试的源码文件最多对应一个同名 `_test.rs` 文件。禁止用一个大型测试文件覆盖多个源码文件，也禁止把一个源码文件的测试拆到多个随意命名文件。
- `tests/common/` 只允许保存跨测试共享的真实数据夹具和发现入口，不得承载任何源码文件的行为测试。Cargo 无法自动发现嵌套测试文件时，使用清晰的 `[[test]]` 路径或不含测试逻辑的薄发现入口，不能把测试搬回 `src/`。
- 外置测试通过包的真实公共入口验证行为。不得为访问私有实现而增加测试专用 `pub`、桥接函数、条件编译入口或重复包含源码；无法独立观察的私有细节通过拥有该行为的公共入口验证。

## Rust 测试工具

- 在 `tests/` 的对应文件中使用 Rust 内置 `#[test]` 和标准测试工具；需要验证公共示例可编译时使用文档测试。禁止引入额外测试框架，除非用户当前请求明确要求。
- 失败阶段运行最窄的 `cargo test <filter>` 并记录目标失败；通过阶段先重复同一命令，再按影响范围运行 `cargo test`。
- 修改 Rust 代码后运行 `cargo fmt --check`，可行时运行 `cargo clippy --all-targets --all-features`。
- 测试成功值、错误枚举、边界值和所有权敏感行为；断言必须遵守 `$cx-tdd` 的常量右值和有序集合抽样规则。
- 不用 `unwrap`、`expect` 或 `panic!` 掩盖生产错误；需要验证失败时直接匹配明确的 `Result` 或错误枚举。

## 真实测试数据

- 数据相关 Rust 测试必须使用测试数据库中的真实数据，不在测试文件中临时制造替代数据。
- 数据库打开、固定范围读取和共享领域对象构造集中在一个公共测试夹具模块，例如 `tests/common/mod.rs` 或项目已有的等价入口。
- 公共夹具使用 `std::sync::OnceLock` 或项目已有的一次初始化机制，保证同一测试进程只读取一次；各测试文件只复用共享对象，不得各自打开数据库或重复构造同一数据。
- 测试数据库或所需记录缺失时报告前置条件缺失，不用内存数据库、伪仓库或模拟访问层替代。
- 除非用户当前请求明确要求，禁止 mock、test double 和伪造仓库测试。

## 审查门禁

1. 搜索整个 `src/`，只要发现生产文件包含测试代码，Rust 测试交付即失败。
2. 逐个检查本轮测试文件与源码文件的路径和名称映射；任何多对一、一对多或跨源码大测试文件都必须拆正。
3. 确认测试目标可被 `cargo test` 发现，并且没有为测试扩大生产接口。

## 输出

除 `$cx-tdd` 要求的记录外，补充记录源码与测试文件映射、`src/` 无测试代码的搜索结果、最窄 `cargo test` 命令、完整测试结果、共享测试数据库入口、`cargo fmt --check` 结果，以及 `clippy` 结果或未运行原因。
