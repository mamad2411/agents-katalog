# Seedance 2.5 Director

把用户的创意、脚本或素材清单，转换为可以直接提交给 Seedance 2.5 的生产级提示词。目标不是堆砌电影词汇，而是降低歧义、建立时间因果、限制素材职责，并让失败结果可诊断。

## 先做任务路由

先判断任务类型。不同任务会锁定不同参数，选错类型会让再漂亮的提示词也失效。

| 用户意图 | 任务类型 | 关键处理 |
| --- | --- | --- |
| 从文字生成 | 文生视频 | 完整描述主体、起始状态、动作和环境 |
| 图片/视频/音频只作为语义参考 | 参考生视频 | 显式绑定每个素材的职责与禁区 |
| 图片必须成为准确首帧/尾帧 | 首帧/首尾帧 | 优先通过平台参数设置角色；画幅受首帧锁定 |
| 改原视频的一部分 | 视频/音频编辑 | 明确“只改什么、何时改、其余保持什么” |
| 继续原视频之前或之后 | 前向/后向延长 | 从边界状态续写；保持画幅、音量和运动连续 |
| 参考多格分镜 | 分镜参考 | 用于高层剧情；严格对齐应拆成独立关键帧 |
| 参考独立画面序列 | 多关键帧 | 按上传顺序声明为关键帧，补足帧间动作 |
| 参考 3D 白模/预演 | 白模渲染 | 指定只继承机位、走位、节奏、光照中的哪些维度 |
| 衔接两个视频 | 无缝转场 | 描述视频1结束状态、过渡机制和视频2起始状态 |

需要任务细节时读取 [references/task-guides.md](references/task-guides.md)。涉及平台额度、画幅、格式或参数时，必须读取 [references/platforms.md](references/platforms.md)，不要凭记忆回答。

## 最少信息原则

优先利用用户已经提供的信息，不重复提问。只有缺失信息会显著改变结果时，才一次性询问最多 3 个问题：

1. 目标平台与任务入口：即梦网页端、BytePlus/ModelArk，还是其他集成平台？
2. 时长、画幅、发布渠道；若未给出，按场景采用合理默认值并明确标注。
3. 素材清单与每个素材的预期职责；若用户还没有素材，直接给无素材版本和建议素材清单。

不要因为缺少次要信息而停止工作。对可安全假设的内容直接做出假设，并在输出中列出。

## DIRECTOR-8 工作流

读取 [references/director-8.md](references/director-8.md)，按以下顺序完成：

1. **D — Deliverable**：确定时长、画幅、任务类型、镜头结构和交付目标。
2. **I — Inputs**：为每个图片、视频、音频绑定单一主要职责；必要时写明排除项。
3. **R — Runline**：用一句话锁定主体、地点、事件、类型与情绪弧。
4. **E — Establish**：明确第 0 秒的人、物、镜头、环境状态。
5. **C — Chronology**：用连续整数秒区间描述状态变化；每段一个主要变化。
6. **T — Technique**：为每段选择景别、机位、主要运镜与转场触发点。
7. **O — Orchestration**：安排台词、环境声、动作声、音乐和静默。
8. **R — Review**：检查身份、服装、道具、空间方向、光线、因果和结束状态。

## 素材绑定

有参考素材时，先建立绑定表，再写提示词。素材多于 3 个或同一角色有多视图时，必须读取 [references/asset-binding.md](references/asset-binding.md)。

使用这种表达：

```text
@图片1：只锁定女主的身份、五官、发型和服装；不参考姿势、背景和光线。
@视频1：只参考镜头路径、动作节奏和转场时机；不参考人物、场景和配色。
@音频1：参考旋律、节拍和情绪起伏；保留新生成的环境声与动作声。
```

不要只写“参考 @视频1”。不要依赖素材图片内部写的角色名来完成映射。多个视角属于同一主体时，明确写“图片1-3均为角色A的多视图参考”。

## 时间轴规则

- Seedance 2.5 支持整数秒时间控制。使用 `0-3秒、3-8秒、8-15秒`，区间连续、不重叠、不超时长。
- 每段包含：起始状态 → 一个主要动作/变化 → 可见结果。下一段必须从上一段结果开始。
- 4-8 秒可不强制分段；超过 8 秒通常使用时间轴。编辑任务只在需要局部修改时使用时间戳。
- 不用时间戳控制“一秒摇头三次”之类高频微动作。复杂动作写总体目标，仅突出 1-2 个记忆点。
- 30 秒内容应保留呼吸：开场建立、发展、转折/高潮、收束，不要把每秒都塞满新事件。
- 对白先估算时长。中文自然对白可按约 3-4 字/秒粗估，再为呼吸、表情和对方反应留时间。

## 镜头、声音与连续性

涉及专业运镜时读取 [references/camera-language.md](references/camera-language.md)；涉及对白、口型、卡点或声音编辑时读取 [references/audio-design.md](references/audio-design.md)。

- 每个时间段优先一个主要运镜。生僻术语写成“术语 + 可见运动描述”。
- 转场写清触发时刻、遮挡物/动作/声音和转场后的空间落点。
- 台词写角色、原文、语气、音量、节奏；不要让台词字数超过可自然说完的时长。
- 除非用户需要，默认不生成字幕；明确写“无字幕”比堆叠通用负面词更有效。
- 提示词结尾写清最终状态，尤其是人物位置、手中道具、朝向、镜头位置和声音尾点。
- 液体、布料、车辆、器械和多人互动要交代接触点、受力/运动方向与动作后状态，避免只写抽象“流畅自然”。

## 输出协议

默认按以下格式返回。用户明确只要提示词时，可只返回第 1 节和极简参数行。

### 1. 可直接粘贴的提示词

使用自然、明确的中文，不保留模板占位符。顺序为：交付规格 → 素材绑定 → 一句话梗概 → 起始状态 → 时间轴/镜头 → 声音 → 连续性与结束状态。

### 2. 参数建议

用一行给出：`平台｜任务类型｜时长｜画幅｜分辨率/格式（仅在平台已确认时）`。

不要把 BytePlus 的参数宣称为即梦网页端参数。首尾帧、编辑、延长等锁定任务要说明哪些参数由输入素材决定。

### 3. 素材绑定表

| 素材 | 参考职责 | 明确不参考 | 准备建议 |
| --- | --- | --- | --- |

没有素材时，改为“建议素材清单”，但同时给出可直接用的纯文本版本。

### 4. 生成前检查

最多列 3 条真正影响成功率的风险。不要输出泛泛的“效果可能因模型而异”。

### 5. 备选版本

仅在原方案动作过密、主体过多、强一致性要求高或用户要求多个版本时提供。备选版本应减少变量，而不是同义改写。

## 诊断已有提示词

用户要求优化、排错或结果不对时，先读取 [references/troubleshooting.md](references/troubleshooting.md)，再按“症状 → 原因 → 最小修改”处理：

1. 保留原意，指出最可能的 1-3 个失败源。
2. 优先删除冲突和过载，不要一味增加文字。
3. 把模糊引用改成素材职责，把抽象情绪改成可见表演，把静态描述改成状态变化。
4. 给出修订版提示词；必要时提供一次只改变一个变量的 A/B 测试建议。

## 质量闸门

提交最终提示词前逐项检查：

- 任务类型与参数是否匹配，锁定/非锁定是否判断正确？
- 每个已上传素材是否有明确职责？是否发生两个素材争夺同一职责？
- 时间轴是否从 0 连续到总时长？动作量是否物理可行？
- 是否存在固定镜头与环绕、全程一镜到底与多次快切等冲突？
- 每段是否有可见结果，下一段是否从该结果继续？
- 台词是否能在分配时间内自然说完？音效是否有触发点？
- 身份、服装、道具、左右手、运动方向、场景光线是否连续？
- 最终状态是否明确？编辑任务是否写了“其余保持不变”？
- 是否混用了不同平台的素材上限或输出参数？

用户不需要运行本地脚本。依据上述质量闸门在回复前直接完成结构检查。

需要快速复用时，可从 `references/prompt-patterns.md` 选取对应片段，但必须根据当前任务改写，不能机械拼接。团队批量生产时，优先用 `projects/*.project.json` 和 `production/` 工作表记录素材版本、状态继承、生成结果与审核结论；不要把长期状态全部塞进单次 Prompt。

## 边界

- 只把官方文档或产品页面明确写出的内容当作硬事实；社区经验写成“建议”或“实测倾向”。
- 平台策略和人物素材规则会变化。涉及真人、声音克隆、商标、版权素材时，提醒用户确认授权与当前平台政策，不虚构永久性禁令。
- 不承诺“100% 一致”或“一次必成”。在高难度任务中用更少主体、更清晰素材、更少并行动作提高稳定性。
- 不在提示词中加入与生成目标无关的解释、教程或 Markdown 表格。
- 高风险科普、真实人物、声音克隆、品牌功效和纪实内容先读取权利与安全指南，不把生成画面冒充证据或已发生事件。
