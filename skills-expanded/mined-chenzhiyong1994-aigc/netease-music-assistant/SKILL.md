# 网易云音乐助手

根据用户需求和可获得的偏好证据选择歌曲、专辑或歌单，通过 `ncm-cli` 获取真实结果。

## 读取路由

- 执行网易云操作前读取 [CLI 执行规范](../netease-music-cli/SKILL.md)。
- 分析红心、使用偏好缓存或推荐去重时读取 [偏好与本地状态](references/preference-state.md)。
- 用户要求定时推荐或向外部渠道发送时读取 [调度与发送边界](references/scheduling-delivery.md)。
- 只搜索、播放、暂停或调整队列时直接进入 CLI，不加载偏好流程。

## 核心流程

1. **识别意图**：明确搜索直接搜索；个性化推荐按需使用偏好；“网易云”本身不表示授权定时推送。缺少偏好时可以按当前心情或场景给少量候选，只有信息不足以形成有用结果时才追问。
2. **核对证据**：有可用红心数据时分析或复用有效缓存；数据不可用就明确以当前请求为依据，不虚构收藏、标签、听歌时段或最近趋势。
3. **制定搜索策略**：影视原声优先考虑专辑，心情与场景可考虑歌单。简单需求搜一次即可；复杂需求按不同信息需求补充搜索，不固定次数。
4. **筛选**：用需求、可见标签、艺人和曲目等信息判断相关性。明确查找已知资源时不因其已收藏而排除；探索新音乐时再按历史去重。数量服从用户请求和可靠结果数。
5. **交付**：每项给名称、真实链接和简短理由，区分偏好证据与内容推断。不默认输出模型自评分或硬凑字数；资料不足时说明缺口。
6. **按意图执行**：用户要求播放、建单或添加曲目时，按 CLI 规范执行并核对结果。普通推荐结束于当前会话；只有已授权持久化偏好或推荐去重时才更新本地状态。

## 输出边界

- 链接和 ID 规则统一见 CLI 规范；没有可靠 ID 时给搜索线索，不编造链接。
- 用户指定一首就返回一首；不足指定数量时说明实际找到的数量。
- 不把红心时间解释为实际播放时间，不把歌单名或热度当作曲风和质量的证明。
- 没有实际注册调度、发送消息或写入歌单，就不能声称操作成功。
- 状态与账户数据放在用户配置目录，凭证、缓存和推荐历史不进入本仓库。
