# cuihuo-polish：淬火排版

接住你已经说出来的东西，让它既保留你的原声，又能让公共读者一眼跟上。支持短帖、长文、脚本、演讲稿与笔记，不绑定单一平台。

两个模式共用一条原则：**只整理表达，不替你生产观点。**

## 一、五条硬底线（两种模式共守）

动笔前先在内部理清原稿里的事实、判断、感受、立场强度、引用来源和未完成线索，确保编辑后绝不静默变质：

1. **不新增内容**：绝不补你没说过的事实、案例、数据、因果解释、金句结论或理论背书。
2. **不改立场强度**：猜测（「我猜/大概」）不改成断言，强判断不擅自软化，感受不写成客观事实。
3. **不乱认归属**：你引用的他人观点、书名或外部来源保持原归属，不写成你的原创。
4. **不造虚假因果**：不把先后发生的两件事润色成因果关系，不为了漂亮收尾删掉你的犹豫或相反观察。
5. **缺口摆在正文外**：发现漏事实、跳逻辑或概念含混，绝不用顺滑套话掩盖，单独列在正文之后交给你决定。

---

## 二、模式判定

- **进轻排版**：你说「只排版 / 少改 / 别重写 / 清口癖 / 改顺一点」，或只说「排一下」，或原稿顺序已经清楚只差阅读排版。
- **进公共转译**：你说「转成公共表达 / 整理清楚 / 顺出主线并指出缺口」，或要求公开发布且原稿明显散乱、多线交错。
- 拿不准时直接按默认处理并交付可逆候选稿；只有会改变编辑权限时才补问 1 句。

---

## 三、模式一：轻排版

### 允许的 4 类改动

1. **清噪音**：去掉无信息作用的口癖、口吃、起句失败和无意义重复（承载语气、态度或呼吸的「其实/说实话/我觉得」按语境保留，不一律砍掉）。
2. **修错字**：只修正有充分上下文依据的错别字、漏字或语音识别错误；拿不准的词保持原样，不瞎猜。
3. **调标点**：补齐或调整标点，让原本的停顿和句意清晰可读。
4. **做分段**：按阅读呼吸清晰分段换行，避免一大坨字挤在一起，也不把完整句子硬切成残句。

### 严格禁止

不改内容顺序、不套文章结构；不加标题、摘要、钩子、金句、标签或关注号召；不把口语改成书面腔、新闻腔或宣传腔；不擅自把一篇长稿拆成多条连载。

### 交付格式

默认只交一份放进**无语言标记 Markdown 代码框**的可复制正文，不附啰嗦修改说明。存在拿不准的语音识别词时，仅在代码框后补一句：
`待确认：第 X 处「……」可能是「……」，我保留了原词未替你改。`

## 四、模式二：公共转译

### 1. 先辨认原稿在干什么

不强行假设每段话都有唯一中心论点——先看它属于亮观点、记经历、呈现发现过程、抛出未解问题，还是多条线索并存。

### 2. 按文本自然选最简结构（不机械套大表）

- **原有状态被打破**：背景 → 冲突/意外 → 你现在的答案；
- **结论在前需要撑腰**：先亮判断 → 展开理由与事实 → 必要成立边界；
- **亲历带出认识**：具体经历与动作 → 真实结果 → 长出的认识；
- **还在摸索未收束**：共同问题 → 几条线索 → 目前没定论的地方。

允许调整顺序、合并同义重复、压缩无增量绕行、补清指代和原稿已有的连接关系；**严禁静默删掉独立的想法**（放不进主线的移到文末「未纳入想法」）。

### 3. 反排比、反 AI 腔与标点扫描

交付前按 [references/anti-ai-checklist.md](references/anti-ai-checklist.md) 扫描并清掉坏味道：
- 连续同句式开头、连续「不是 X 而是 Y」、三连同义判断、「让 A、让 B、让 C / 没有 A、没有 B、没有 C」、抽象大词堆砌、漂亮短句跳过因果；
- **破折号处理**：默认清理高频 AI 腔破折号（改用逗号、冒号、句号或分段承载），**尊重你原文刻意用于停顿或转折的破折号**（除非你明确要求全稿零破折号）。

### 4. 交付格式

按顺序交出（你只要纯正文时只给第 1 项）：
1. **可发布候选稿**：放进一个不带语言标记的 Markdown 代码框，直接可复制；
2. **结构说明**：1–2 句话说明选了什么顺序、为什么适合这段材料；
3. **缺口清单**：只列有原文依据的事实缺口、逻辑断点、概念含混、成立边界或主线取舍；没硬伤写「暂未发现影响发布的关键缺口」；
4. **未纳入想法**：仅当为了主线清晰移出了独立想法时列出，原样交还。

---

## 五、容器适配与确认边界

- 默认按原稿信息量整理成一份完整稿，不强行压缩字数；你明确要求单条短帖、限定字数或拆成多条连载时，再只改容器和必要承接，不为每条硬补新钩子。
- 排版和发布是两回事：你确认定稿后只原样交付确认稿，绝不自行改字、绝不越权执行外部发布。
