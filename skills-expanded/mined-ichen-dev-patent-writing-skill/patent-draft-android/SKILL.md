# 专利技术交底书撰写

面向**各岗位、各行业**的**发明、实用新型、外观**及软件/方法类专利撰写，产出符合三性（新/创/行）的专利文档。**模板位于本技能目录内**：`templates/专利模板_一种实现TopActivity的有序广播保护状态设定的方法+技术交底书.md` 与同名 `.doc`。编写完成后须**依次完成**：查重 → 自检 → 新创行评估 → 自评 → **自动转换成 Word 文档**。

## 目标与输出

| 项目 | 说明 |
|------|------|
| **触发** | 用户提出撰写专利、技术交底书、发明/外观专利，或指定 发明、实用新型、外观、软件/方法等技术点 |
| **固定模板** | **本技能 templates 目录下**的「专利模板_一种实现TopActivity的有序广播保护状态设定的方法+技术交底书.doc」及同结构 .md；撰写时各节与该模板章节一一对应，对应表见 [docs/reference.md](docs/reference.md) 第三章 |
| **中间产出** | 一份 Markdown 专利文档（路径可由用户指定，如项目 `docs/专利_{发明名称}_技术交底书与说明书.md`） |
| **最终交付** | 专利**须自动转换为 Word 格式**（.doc 或 .docx）后交付；转换须由 Agent 在流程结束时**自动执行**，见 Phase 6。模板与方式见 [docs/模板与Word输出说明.md](docs/模板与Word输出说明.md) |

> 🔒 **强制约束（必须完整执行，不得缺少任何步骤）**：
>
> **1. 流程顺序不可跳过、不可缺步**  
> 必须**严格按顺序**执行以下全部阶段，不得跳过任一 Phase（含 **Phase 2b**）或仅给出操作说明由用户自行执行；前一阶段完成并满足其过渡检查清单后，再进入下一阶段。
>
> | 阶段 | 必须完成的内容 |
> |------|------------------|
> | **Phase 1** | 需求与三性准备：发明名称、技术问题、核心方案、三性判断 |
> | **Phase 2** | 正文撰写：项 目、技术术语、背 景 技 术、**本发明的技术方案（按步骤分点）**、**图纸（含 Mermaid 技术流程图）**、有 益 效 果（分点）、发明点（分点）、技术联系人（**正文可写说明性占位，但导出 Word 时「技术联系人」内容列由脚本强制留空**，由用户事后自行填写姓名/电话/邮箱）；**结束前须通过【】标准交底书引导语门禁**（见「【】标准交底书引导语门禁」与 [workflows/标准引导语自检.md](workflows/标准引导语自检.md)） |
> | **Phase 2b** | **Mermaid→PNG 并写回 Markdown**：保存专利 `.md` 后，**必须**执行 `scripts/patent-mermaid-to-png.ps1`（Windows）或 `scripts/patent-mermaid-to-png.sh`（Linux/macOS）：将首个 ` ```mermaid ` 块渲染为 **高分辨率 PNG**（`mmdc` 使用 **`-w 1920 -H 3200 -s 2`** 为默认，显著优于旧版 800×600×1；可按图复杂度加大 `-Width/-Height/-Scale`），默认 ASCII 安全文件名 `*_flowchart.png`，并在同目录生成 **同主名 `.mmd` 侧车** 供日后仅重渲图；随后 **用** `![图纸流程图](相对路径)` **替换该 mermaid 代码块**（供 Phase 6 将 PNG 插入 Word「图纸」行内容列；`from-full-json` / 填表脚本在缺引用时仍回退同目录最新 `*_flowchart.png`）。若 `.md` 已含图片引用而无 mermaid，使用 **`-InputMmdPath`** 指向侧车 `.mmd` 并 **`-NoReplaceInMd`** 覆盖更新 PNG。**无 Node/npx 时 Agent 须先自行安装 Node.js LTS**（见 [docs/Mermaid流程图PNG导出说明.md](docs/Mermaid流程图PNG导出说明.md)），**不得**要求用户手动安装；**保留源码**时加 `-NoReplaceInMd` 或 `MERMAID_KEEP_SOURCE=1`。 |
> | **Phase 3** | **强制检索查重**：读取专利检索网站 → 构建检索式 → **在至少 10 个以上权威网站分别执行检索**（不得仅用 1 个站）→ 写入查重与检索说明（检索日期为当天真实日期，列出至少 10 个检索平台） |
> | **Phase 3.5** | **查重自检**（必做）：按 workflows/查重自检流程.md 再检一次 → 写入查重自检小节（自检日期为当前最新日期） |
> | **Phase 3.6** | **查重结果判定（含 10% 重合与「一点点类似」门禁）**：见下文「Phase 3.6 细则」——凡命中须 **从 Phase 1 重写** 并 **重新完整执行 Phase 1～6（含 Phase 2b）**；市面上已有的专利不允许再申请 |
> | **Phase 4** | 新创行评估（三性结论）+ 可行性与商业价值小节 |
> | **Phase 5** | 自评：按 [workflows/优秀专利标准.md](workflows/优秀专利标准.md) 输出专利质量自评；**交付目标为 P0（🟢 优秀）**，非 P0 时须按「Phase 5 优秀迭代」修订并重跑后续阶段（见下文） |
> | **Phase 6** | **强制**将专利 MD 转为交付用 Word；**须由 Agent 执行脚本，不允许人工操作**。**Windows**：`md2docx.ps1 -PatentFullMd` **须**在 `templates/` 存在企业交底书模板时走 **复制模板到专利输出目录（`{MD 主名}_专利模板工作.doc/.docx`）→ Word 打开 → 按「项目」填内容 → 文档属性 **Title/Subject** + 全文替换示例发明名 → 联系人留空 → 列宽/图宽 → **SaveAs 与 MD 同主名 `.docx`** → 删工作副本；**无模板时默认报错**（勿以 MD 直转交付）；仅草稿可加 `-SkipWordTemplate`；填充失败可加 `-AllowPandocFallback` 兜底 Pandoc。**Linux/macOS**：`md2docx.sh --from-patent`（Pandoc）。Word 表**仅 8 行**；见 [docs/模板与Word输出说明.md](docs/模板与Word输出说明.md)。 |
>
> **3. 默认交付标准（强制）**  
> - **Word 全文字体颜色**：交付用 `.docx` 中**所有文字统一为黑色**（无例外）。  
> - **段落序号**：导出时须做序号自检与去重，避免出现“1、1. xxx”等重复/叠加编号。  
> - **图纸插图**：必须将 Phase 2b 生成的 PNG 嵌入 Word 表格“图纸”行内容列；Word COM 失败时必须自动回退（OpenXML）补插成功。  
>
> **4. 交互原则（默认不问询）**  
> - **不主动问询用户**：生成专利时不再追问澄清问题；**以用户已提供的信息为准直接生成**。  
> - **用户指定优先**：用户明确规定技术类型/方向/模块时，严格按用户要求生成。  
> - **随机生成**：仅当用户明确说“随机生成专利/随便写一个”时，才由 Agent 随机选取一个合规主题生成。  
> - **冲突处理**：若用户指令内部存在冲突，以用户最近一次明确指令为准并直接执行，不再追加问询。  
> **2. 撰写与产出约束**  
> - **本发明的技术方案、有 益 效 果、发明点**须分点/按步骤书写。  
> - **（Word 交付强制 · 禁用 LaTeX）**：凡将填入企业 Word 模板 表格「内容」列的正文（自「项 目」至「技术联系人」整段，含**技术术语、背 景 技 术、本发明的技术方案、有 益 效 果、发明点**；**不含**查重附录）**禁止使用 LaTeX 数学源码**，包括但不限于：`\( … \)`、`$…$`、`\[ … \]`、`\frac`、`\sum`、`\theta`、`\Delta`、`\alpha`、`\gamma`、`\in`、`\leq`、上标 `^` 与下标 `_{…}` 的 LaTeX 组合等。原因：Word 填表路径**不会渲染** LaTeX，发明人看到的是反斜杠与花括号「乱符」。**须改写为**：中文叙述 + **ASCII 变量名**（如 Tbudget、Savg、Who、Tv、delta、alpha）或 **单个 Unicode 数学字母**（如 θ、Δ、φ），角度用 **°** 直接输入；关系式用 **「=」「小于」「×」** 等普通字符或中文「之和」表述。**Mermaid 图纸**内节点文案同样遵守本条（避免 `\(…\)`）。  
> - **图纸**须包含根据技术方案自动生成的 **详细、正规** Mermaid 技术流程图（**含判断步骤的菱形与是/否分支**），不得仅写「可补充」或仅用无分支的极简单线图（若方案含条件）。  
> - **检索查重为强制步骤**：Phase 3（自动查重）与 Phase 3.5（查重自检）必须执行，不得跳过；**检索日期**须填写**执行本流程当天的真实日期**（格式 YYYY-MM-DD），即生成专利时的实际日期（如 2026 年则用 2026-xx-xx），**严禁使用示例或过往年份（如 2025）**。
> - 查重、自检、新创行评估、自评、Word 转换均须由 Agent **实际执行并写入文档**，不得以「请用户自行…」替代。
> - **相似度高、重合≥10%、或「一点点类似」均须重写并重走流程**：除「相似度高 / 已有相同或高度类似专利」外，若在「查重与检索说明」所载 **各对比文献** 上，本发明与任一篇在 **关键词**、**技术方案步骤**、**发明点** 任一对照中满足 **（1）关键词重合率 ≥10%**（重合词数 ÷ 本发明去重关键词总数；须在文档中给出**对照表**与计算）**或（2）任一条技术点/发明点与对比文献摘要或权利要求表述呈明显同义、改写或易混淆的实质相似**（即「一点点类似」亦视为未通过），**不得**进入 Phase 4；须从 **Phase 1** 调整主题或技术路径后 **重新完整执行 Phase 1～6（含 Phase 2b）** 并重新检索，直至上述门控全部不触发。**原则：市面上已有的专利都不允许再申请。**
> - **优秀门禁（P0）**：通过 Phase 3.6 后，Phase 5 自评**目标为 P0（🟢 优秀）**（见 [workflows/优秀专利标准.md](workflows/优秀专利标准.md)）。若首轮为 P1/P2，须据改进建议修订正文并 **至少重跑 Phase 2、2b、5、6**；若修订涉及发明点或技术方案**实质变化**，须 **重跑 Phase 3～3.6**。同一用户任务内**连续迭代以 5 轮为上限**：若第 5 轮自评仍非 P0，须在「专利质量自评」中写明未达 P0 的剩余项与建议人工复核，**但不得**在 Phase 3.6 未通过时以此豁免交付。

**🚫 禁止**：
- ❌ **跳过或省略任一 Phase / 步骤**（Phase 1～3.6、4～6 及 Phase 2 内各项、Phase 3 内检索与写入等均须完整执行；Phase 3.6 判定为高风险时须重写并重走流程）
- ❌ 跳过或省略检索查重（Phase 3、Phase 3.5 必须执行）；检索日期使用非当天真实日期、留空或照抄示例（如使用 2025 年等过往年份）
- ❌ 检索仅在 1 个或少数几个网站进行（**必须在至少 10 个以上权威检索网站**分别执行检索，见 Phase 3）
- ❌ 未执行任何检索即仅写「请用户自行在 XX 平台检索」或只提供检索式而不填写检索结果
- ❌ 虚构专利号或文献；检索无有效结果时须如实写明并保留检索式与平台链接
- ❌ 本发明的技术方案、有 益 效 果、发明点 写成整段不分点
- ❌ 图纸一节仅写「可补充」或纯文字描述而无根据技术方案生成的 Mermaid 技术流程图；或**仅有极简单线流程而无判断**（若技术方案中存在「若/是否/当」等条件却未用菱形表示）
- ❌ 跳过 **Phase 2b**：专利 `.md` 在 Phase 2 曾含 ` ```mermaid ` 块却**未**执行 `scripts/patent-mermaid-to-png.*` 完成 **PNG 生成且将代码块替换为图片引用**（除非显式 `-NoReplaceInMd` / `MERMAID_KEEP_SOURCE=1` 且已说明原因）；**无 Node/npx 时未尝试自行安装即放弃**（须按 docs/Mermaid流程图PNG导出说明安装后再执行）；仅当安装确不可行时在文档与 `today_errors.log` 如实记录
- ❌ 仅输出「可将内容复制到 Word」等说明而不执行 Word 转换（须由 Agent 通过脚本或命令自动完成，**不允许人工操作**）
- ❌ 要求用户手动执行转换、手动运行 pandoc 或手动打开 Word（MD→Word **必须由 Agent 执行完成**，全程无需个人额外操作）
- ❌ 本机未安装 pandoc 时要求用户手动安装（**须由 Agent 自行下载/安装 pandoc**，见 docs/模板与Word输出说明「本机未安装 pandoc 时 Agent 须自行安装」）
- ❌ 本机未安装 Node.js / npx 时要求用户手动安装（**须由 Agent 自行安装 Node.js LTS**，见 [docs/Mermaid流程图PNG导出说明.md](docs/Mermaid流程图PNG导出说明.md)）
- ❌ 在 **Phase 3.6 未通过**（含 ≥10% 关键词重合或「一点点类似」实质风险）或 **Phase 5 自评未达 P0** 且未继续迭代时即交付终稿（见 Phase 3.6 细则与 Phase 5 优秀迭代）
- ❌ 转出 Word 后未以「项目 | 内容」两列表格形式呈现各章节（须在 Word 中为表格形式，标题项目与内容分列）
- ❌ 在交付用 Word 中保留任何非黑色字体（默认交付标准为**全文黑色**）
- ❌ 查重发现**相似度高**或**已有类似专利**时仍直接进入 Phase 4 或交付（须先重新编写并重新走完 Phase 1～6（含 Phase 2b），直至查重通过；市面上已有的专利不允许再申请）
- ❌ **省略、删除、改写或合并入正文**企业交底书模板规定的任一节【】引导整句（技术术语、背 景 技 术、本发明的技术方案、有 益 效 果、发明点、图纸共 **6 处**，文案以 `templates/专利模板_一种实现TopActivity的有序广播保护状态设定的方法+技术交底书.md` 为准）；或在 **【】门禁未通过**时仍进入 Phase 2b / Phase 3 及之后
- ❌ 在 Word 交付范围内（填表八节正文）使用 **LaTeX 数学写法**（`\( \)`、`$ $`、`\theta`、`\sum`、`_{sub}` 等），导致表格「内容」列出现未渲染源码

**✅ 必须**：
- **完整走完所有阶段与步骤**：Phase 1 → Phase 2 → **Phase 2b（Mermaid→PNG）** → **Phase 3（强制检索查重）** → **Phase 3.5（查重自检）** → **Phase 3.6（查重判定：若相似度高/已有类似专利则重新编写并重走 Phase 1～6）** → Phase 4 → Phase 5 → Phase 6，不得缺少任一步。
- **检索日期**：查重与查重自检的「检索日期」须填写**执行本流程当天的真实日期**（格式 YYYY-MM-DD）。必须使用当时实际年月日（例如 2026 年则用 2026-xx-xx），**严禁照抄示例或使用过往年份（如 2025）**；不得留空或使用固定示例日期。
- 撰写前读取 [docs/专利检索网站.md](docs/专利检索网站.md) 获取检索站点列表

- **本发明的技术方案**：按步骤1、步骤2、步骤3…分条书写；**有 益 效 果**与**发明点**：分点列出；**图纸**：含 Mermaid 技术流程图
- 编写完成后**按顺序**完成：**Mermaid→PNG**（Phase 2b）→ **查重**（Phase 3）→ **查重自检**（Phase 3.5）→ **新创行评估与可行性与商业价值**（Phase 4）→ **自评**（Phase 5）→ **自动转换成 Word 文档**（Phase 6）

## 核心约束

- **三性**：新颖性（新）、创造性（创）、实用性（行）须在背 景 技 术、本发明的技术方案、有 益 效 果、发明点中有明确论述；流程中须做**新创行评估**并写入文档。
- **撰写格式**：本发明的技术方案**按步骤分点**；有 益 效 果与发明点**分点**列出；术语统一；路径仅用 Unix 风格（如 `templates/xxx`），禁止 `\`。

## 工作流程

**⚠️ 以下 Phase 1～3.6、4～6 及各阶段内步骤均为必做项，须按顺序完整执行，不得跳过或省略。** 若 Phase 3.6 判定为相似度高、已有类似专利、关键词重合率 ≥10%，或存在「一点点类似」的实质风险，须从 Phase 1 重写并重新执行 Phase 1～6（含 Phase 2b），直至门控全部通过。Phase 5 自评目标为 P0（优秀），非 P0 时按「Phase 5 优秀迭代」修订（见各 Phase 正文）。

### Phase 1：需求与三性准备

**执行步骤**：
1. 明确发明名称（项 目）、要解决的技术问题、现有方案不足、核心方案概述。
2. 若用户提供代码/流程图/UI 草图，提取技术特征与区别点。
3. 做三性判断并写入文档（背 景 技 术、本发明的技术方案、有 益 效 果、发明点中体现）。

**过渡检查清单**：

- [ ] 三性判断已做并将在正文中体现

### Phase 2：正文撰写（技术方案交底书）

**执行步骤**：
1. 按**本技能** [templates/专利输出模板.md](templates/专利输出模板.md) 生成一份 Markdown 文档，章节与**本技能** [templates/专利模板_一种实现TopActivity的有序广播保护状态设定的方法+技术交底书.md](templates/专利模板_一种实现TopActivity的有序广播保护状态设定的方法+技术交底书.md) 完全一致；并在**技术术语、背 景 技 术、本发明的技术方案、有 益 效 果、发明点、图纸**各节中，将企业交底书模板以 `【…】` 给出的引导说明**原样置于节首**（标题行下一行起，不得删除、不得改写、不得并入后段正文）。
2. **本发明的技术方案**：按步骤1、步骤2、步骤3…分条书写，每条一句或一段。
3. **技术流程图（图纸）**：在完成技术方案步骤后，**必须**按 [workflows/技术流程图生成说明.md](workflows/技术流程图生成说明.md) 自动生成技术流程图；流程图须**足够详细**（长步骤拆框、关键子动作分框），**凡带判断的步骤须用菱形体现**，分支箭头须标注**是/否**（或等价二元标注），结构须**正规**（起止圆角框、处理矩形、判断菱形、可选 subgraph 分阶段），按 [docs/技术流程图规范.md](docs/技术流程图规范.md) 编写 Mermaid，写入「图纸」一节（含阶段与判断分支概述 + Mermaid 代码块）。参考示例见 [templates/技术流程图_Mermaid示例.md](templates/技术流程图_Mermaid示例.md)。不得在图纸处仅写「可补充」或无判断的极简单线流程图（若方案中确有分支）。
4. **有 益 效 果**：分点列出（1. 2. 3. 或 -），每条一优点。
5. **发明点**：分点列出（1. 2. 3. 或 -），每条一保护点。
6. 外观专利时：写明产品名称与用途、图纸（六面视图/使用状态图）或「待补」、设计要点。

**过渡检查清单**：

- [ ] **填表用八节正文无 LaTeX**（与「Word 交付强制 · 禁用 LaTeX」一致；Phase 6 前若改过 `.md` 须复检）
- [ ] 背 景 技 术有可检索的现有技术并指明确切不足
- [ ] 本发明的技术方案已按步骤分点、有 益 效 果与发明点已分点
- [ ] **Word 交付范围内无 LaTeX**（八节正文：无 `\( \)`/`$ $`/`\theta` 等；见「Word 交付强制 · 禁用 LaTeX」）

### Phase 2b：Mermaid 流程图导出 PNG 并替换源码（必做）

**前置条件**：专利全文 `.md` 已通过上文 **【】标准交底书引导语门禁**；未通过者**不得**开始本节。

**执行步骤**：
1. 在专利 Markdown 已保存且「图纸」节含首个 ` ```mermaid ` 代码块后，由 Agent 在终端执行本技能脚本（路径按实际安装位置调整）：
   - **Windows**：`powershell -NoProfile -File "scripts/patent-mermaid-to-png.ps1" -PatentMdPath "<专利.md 绝对路径>"`（技能目录内 `scripts/` 以本技能根为基准；若从工作区调用，传入**本技能**脚本的绝对路径）。**保留 Mermaid 源码不替换**时追加 `-NoReplaceInMd`。清晰度可显式加大，例如 `-Width 2400 -Height 4200 -Scale 2.5`。**仅重渲 PNG**（正文已是图片）时：`-PatentMdPath` 仍指向该 `.md`（用于默认输出目录）、`-InputMmdPath "<同目录/与 PNG 同主名>.mmd" -NoReplaceInMd -OutPngName "<原 png 文件名>"`。
   - **Linux/macOS**：`bash scripts/patent-mermaid-to-png.sh "<专利.md 绝对路径>"`。**保留源码**时设置环境变量 `MERMAID_KEEP_SOURCE=1`。**清晰度**通过 `MERMAID_PNG_WIDTH` / `MERMAID_PNG_HEIGHT` / `MERMAID_PNG_SCALE` 调整；**侧车 .mmd 输入**通过 `MERMAID_INPUT_MMD`。
2. 脚本行为：提取首个 mermaid 块（或从 `-InputMmdPath`/`MERMAID_INPUT_MMD` 读取）→ `mermaid-cli` 以 **高分辨率参数** 生成 PNG（Windows 下经 `%TEMP%` 纯 ASCII 中转再复制，见说明文档）→ **默认**写出与 PNG 同主名的 `.mmd` 侧车 → **默认**调用 `replace-first-mermaid-with-img.cjs` **将原 ` ```mermaid … ``` ` 整块替换为** `![图纸流程图](./<png 相对路径>)`（在未 `-NoReplaceInMd` 时）。
3. **若本机无 `node`/`npx` 或脚本报「command not found」**：**Agent 须先自行安装 Node.js LTS**（含 `npx` 在 PATH），安装方式见 [docs/Mermaid流程图PNG导出说明.md](docs/Mermaid流程图PNG导出说明.md)「本机未安装 Node.js / npx 时 Agent 须自行安装」；**不得**要求用户手动安装；安装后重新执行步骤 1。**仅当**在沙箱/离线等环境确无法安装时，方可在「图纸」节与 `today_errors.log` 如实记录原因，并采用 `-NoReplaceInMd` / `MERMAID_KEEP_SOURCE=1` 保留 mermaid 且不得伪造已生成 PNG。

**说明**：[Mermaid 在线编辑器（nuantang）](https://mermaid.nuantang.net/) 为浏览器侧工具，与 [Mermaid Live](https://mermaid.live) 同类；**无可靠公开 API** 供 Agent 直接「在对方网站渲染并下载」。本阶段采用 `@mermaid-js/mermaid-cli` 本地渲染，**语法与在线编辑器一致**，详见 [docs/Mermaid流程图PNG导出说明.md](docs/Mermaid流程图PNG导出说明.md)。

**过渡检查清单**：
- [ ] 已执行 `patent-mermaid-to-png` 脚本；若曾缺 Node/npx，已先自行安装并重试，或已按上条在不可安装环境下如实记录
- [ ] 成功时专利「图纸」节**已无**首个 mermaid 代码块，**已为** `![图纸流程图](...)` 图片引用（或已 `-NoReplaceInMd` / `MERMAID_KEEP_SOURCE=1` 并说明）

### Phase 3：自动查重

**执行步骤**：
1. **读取** [docs/专利检索网站.md](docs/专利检索网站.md)，获取名称、链接、适用国家。
2. **构建检索式**：从发明名称、项 目、本发明的技术方案与发明点提取 3–5 个中英文关键词及同义词；确定 IPC（如 G06F9、H04W）；组合成检索式。
3. **执行检索**：使用 **web_search** 或 **mcp_web_fetch** 在**至少 10 个以上权威检索网站**（从 [docs/专利检索网站.md](docs/专利检索网站.md) 中选取，如 **国家知识产权局 PSS 常规检索**、Google Patent、EPO、WIPO、soopat、佰腾网、智慧芽、大为innojoy、专利之星、合享新创incopat、中国及多国专利审查信息查询等）**分别**执行检索，从各站结果中汇总并识别最接近 2–3 篇现有技术（专利号、名称、摘要要点）。**不得仅使用 1 个网站**。
4. **写入文档**：在专利文档中增加「查重与检索说明」，包含：检索式与关键词、**检索日期（必须为「执行本流程当天的真实日期」，格式 YYYY-MM-DD；例如若当天是 2026 年 3 月 19 日则填 2026-03-19，严禁使用示例或过往年份如 2025）**、**检索平台（须列出至少 10 个以上权威网站名称+链接，证明已在多站检索）**、最接近 2–3 篇现有技术及与本方案的区别（1–2 句）、结论。若未检出高度相关文献，写明「经检索未发现与本方案相同的现有技术」并保留检索式。
5. 检索无有效结果时，如实写「本次自动检索未命中高度相关专利，建议人工在 XX 平台复核」并保留检索式与平台链接。

**过渡检查清单**：
- [ ] 已读取 docs/专利检索网站.md
- [ ] 已在**至少 10 个以上权威检索网站**分别执行检索（不得仅用 1 个网站）
- [ ] 文档中已填写检索式、**检索日期（当前最新日期）**、**至少 10 个检索平台（名称+链接）**、最接近 2–3 篇现有技术及区别、结论

### Phase 3.6：查重结果判定（Phase 3.6 细则）

在完成 Phase 3 与 Phase 3.5 后，根据「查重与检索说明」「查重自检」及下述**定量/定性门控**判定；**任一条命中即视为 Phase 3.6 未通过**。

**执行步骤**：

1. **若结论为「相似度高」或「已有与本发明相同/高度类似的现有专利」**（即检索到与当前技术方案实质相同或高度近似的已公开/已授权专利）：
   - **不得**进入 Phase 4，**不得**交付当前稿。
   - **必须**：**重新编写**——调整发明名称、技术问题、本发明的技术方案、有 益 效 果、发明点等，使与检索到的现有技术形成**明确、可表述的区别**（如不同技术手段、不同应用场景、不同效果）。
   - 重新编写完成后，**重新完整执行 Phase 1～6（含 Phase 2b）**（含重新查重 Phase 3、查重自检 Phase 3.5），直至某轮上述门控全部不触发后，再进入 Phase 4 并继续至 Phase 6 交付。

2. **关键词 / 技术点 / 发明点与对比文献的 10% 与「一点点类似」门控**（对「查重与检索说明」中列出的**每一篇**最接近现有技术或自检补充文献分别执行）：
   - **关键词重合率**：从本发明「项 目、本发明的技术方案、发明点」提取**去重后的关键词列表**（建议 20–60 个技术实词，去掉「方法」「系统」等泛词）；与对比文献标题+摘要中的词做**精确或明显同义**匹配，计算 **重合词数 ÷ 本发明去重关键词总数**；若 **≥10%**，判定未通过。须在「查重与检索说明」或附录小节中给出**对照表**（本发明词、对比文献命中词、是否同义）及**算式**。
   - **「一点点类似」**：若任一条**技术方案步骤**或**发明点**与对比文献摘要/权利要求表述呈**明显同义、改写、上下位替换**或本领域技术人员易认为**无实质差异**，即视为未通过（不要求数值达到 10%，**低相似亦须重写**）。
   - 命中后处理与第 1 条相同：**不得**进入 Phase 4；从 **Phase 1** 调整主题或技术路径后 **重新完整执行 Phase 1～6（含 Phase 2b）** 并重新检索，直至**对全部对比文献**均不触发本款。

3. **若结论为「未发现高度相似」「与本方案存在明确区别」且第 2 款门控均未触发**：正常进入 Phase 4。

**原则**：**市面上已有的专利都不允许再申请。** 凡查重显示已有相同或高度类似专利的，必须通过重新编写形成区别并重新查重通过后，方可交付。

**过渡检查清单**：
- [ ] 已根据查重与自检结论判定：无「相似度高」或「已有类似专利」；若有，已执行重新编写并重新走完 Phase 1～6（含 Phase 2b）且新一轮查重通过
- [ ] 已对列出的对比文献完成关键词重合率计算与「一点点类似」审查；无 ≥10% 重合且无实质同义混淆；否则已从 Phase 1 重写并重跑全流程
- [ ] 仅当 Phase 3.6 全部通过后才进入 Phase 4

### Phase 4：新创行评估（三性评估）与可行性与商业价值

**执行步骤**：
1. **新创行评估**：根据查重与自检结果及文档内容，对**新颖性、创造性、实用性**做结论性评估并写入文档（可在「查重与检索说明」后增加「新创行评估」小节，或并入可行性与商业价值）。须明确写出：是否具备新颖性（与最接近现有技术的区别）、是否具备创造性（技术手段与效果的非显而易见性）、是否具备实用性（可实施性与积极效果）。
2. **可行性与商业价值**：在文档中增加「可行性与商业价值」小节；可行性（实施方式是否完整、运行环境、设备/系统）；商业价值（应用场景、目标产品线/客户、与现有专利配合关系）。

**过渡检查清单**：
- [ ] 已完成新创行评估并写入文档（新颖性、创造性、实用性结论）
- [ ] 可行性与商业价值小节已填写
- [ ] 文档可对应到**本技能 templates** 下 .doc/.md 模板的相应章节

### Phase 5：自评（优秀专利筛选）与 Phase 5 优秀迭代

**执行步骤**：

1. 按 [workflows/优秀专利标准.md](workflows/优秀专利标准.md) 对专利文档做**自评**，在文档末尾输出「**专利质量自评**」：等级（🟢 **P0 优秀** / 🟡 P1 / 🔴 P2）、各维度达标情况、改进建议（若为 P1/P2）。**交付目标为 P0**。

2. **Phase 5 优秀迭代**（首轮非 P0 时执行，与 SKILL 前文「优秀门禁」一致）：
   - 据改进建议修订 Markdown 正文；**至少重跑 Phase 2、Phase 2b、Phase 5、Phase 6**。
   - 若修订涉及**发明点或技术方案的实质变化**，须**从 Phase 3 起重跑至 Phase 3.6**（重新查重与门控），再 Phase 4～6。
   - 同一用户任务内以 **5 轮**自评为上限：第 5 轮仍非 P0 时，在「专利质量自评」中写明未达 P0 的剩余项与建议人工复核；**不得**以「轮次用尽」绕过 Phase 3.6 未通过而交付。

**过渡检查清单**：
- [ ] 已按优秀专利标准完成自评；**已达 P0**，或已完成允许范围内的迭代并在末轮自评中说明非 P0 原因
- [ ] 非 P0 时已按「Phase 5 优秀迭代」修订并重跑相应 Phase，未在未迭代时即交付终稿

### Phase 6：强制转换为 Word 文档（必须由 Agent 执行，不允许人工操作）

**执行步骤**：最终交付物须为 **Word 格式**（.doc 或 .docx）。**MD→Word 转换必须由 Agent 通过脚本或命令执行完成，不允许用户/人工操作；全程无需个人额外操作。** Agent 须在流程结束时**实际运行**转换脚本或 pandoc 命令并生成 .docx，不得仅提供「请用户运行…」等说明。**Word 文档中须以表格形式呈现**：各章节的**标题项目**与**内容**分列，生成「项目 | 内容」两列表格。实现方式见 [docs/模板与Word输出说明.md](docs/模板与Word输出说明.md) 与本技能 `scripts/` 下脚本。

**表格形式要求**：Word 中须包含至少一张表格，列为「**项目**」与「**内容**」；**交付用 Word 仅 8 行**：项 目、技术术语、背 景 技 术、本发明的技术方案、有 益 效 果、发明点、图纸、技术联系人。**不得**在 Word 表中出现「查重与检索说明」及之后各节（查重、新创行、可行性与商业价值、专利质量自评等**仅保留在全文 Markdown**）。「内容」列多段须换行显示（与模板观感一致），推荐由 `patent-word-docx-input.cjs` 写入 `<br />` / `<br /><br />` 后由 Pandoc `+raw_html` 转换。

**转换方式（Agent 须按环境执行，不得交由人工）**：
1. **Windows（默认，与企业 Word 模板 模板版式一致）**：对全文 `专利_*_技术交底书与说明书.md` 执行  
   `powershell -NoProfile -ExecutionPolicy Bypass -File "scripts/md2docx.ps1" -PatentFullMd "<专利全文.md>" [-OutputDocx "<可选.docx>"] [-WordTemplatePath "<可选模板.doc/.docx>"] [-AllowPandocFallback] [-ArtifactSubdir "专利生成"] [-NoArtifacts]`  
   **无须** `-FillWordTemplate`：只要 `templates/` 下存在固定 `.doc`/`.docx`，会**自动**调用 [scripts/patent-fill-template-word.ps1](scripts/patent-fill-template-word.ps1)：**将模板复制到专利 MD 同目录**（`{主名}_专利模板工作.doc/.docx`）→ 按「项目」填表（「图纸」行嵌入流程图；同目录多 `*_flowchart.png` 时按 MD 正文文件名优先匹配；若保存前该格仍无图则**自动二次补插**）→ **全文替换**示例发明名 → 设置 **Title/Subject** → **SaveAs** `{主名}.docx` → 删工作副本。默认在专利 MD 同目录下 **`专利生成/`** 写入 **`{主名}_章节提取.json`**（8 行项目与内容键值）、企业交底书模板未改副本、表格版 MD 与终稿 `.docx` 副本，便于工程归档；`-NoArtifacts` 可关闭。**无模板时脚本报错**，须先放入企业交底书 `.doc`/`.docx`，或运行 [scripts/bootstrap-patent-vendor-template.ps1](scripts/bootstrap-patent-vendor-template.ps1) 用 Pandoc 从 `专利_Word表格版_示例.md` 生成占位 `.docx`。**`-SkipWordTemplate`**：仅用 Pandoc 表格草稿；**`-AllowPandocFallback`**：模板填充失败时允许回退 Pandoc。
2. **Linux/macOS（Pandoc）**：`bash scripts/md2docx.sh --from-patent "<专利全文.md>" "<输出.docx>"`（无 Word COM 时路径）。
3. **已有 Word 表格版 .md**（仅 Pandoc）：`powershell -NoProfile -File "scripts/md2docx.ps1" -InputMd "<…_Word表格版.md>" -OutputDocx "<输出.docx>"`；若表中误含查重等行会先 strip-appendix。
4. **已有交付用 .docx，仅补插或更换「图纸」列流程图**（Windows + Word）：`powershell -NoProfile -ExecutionPolicy Bypass -File "scripts/patent-insert-diagram-word.ps1" -WordDocx "<终稿.docx>" -PatentFullMd "<同主名全文.md>"`（从 `## 图纸` 节首张 `![](...)` 解析路径），或 `-ImagePath "<*.png>"`；见 [docs/模板与Word输出说明.md](docs/模板与Word输出说明.md)。
5. **若走 Pandoc 且本机未安装 pandoc**：**Agent 须自行安装 pandoc**后再执行。**不得**以「请用户复制到 Word」作为交付。

无论采用何种方式，**须由 Agent 在流程内执行脚本或命令完成转换**，并输出生成的 .docx 路径；**不允许**将「请用户手动运行 pandoc/脚本」「请用户复制到 Word」作为交付方式。详见 [docs/模板与Word输出说明.md](docs/模板与Word输出说明.md)。

**过渡检查清单**：
- [ ] 已由 **Agent** 执行 MD→Word 转换（脚本或 pandoc 命令），**未要求用户手动操作**
- [ ] **【】标准交底书引导语门禁**在填表用 `.md` 上已复检通过（六句仍在对应节首），或本轮未改 `.md` 且 Phase 2 出口已通过
- [ ] 已生成 .doc 或 .docx，且 Word 中已包含「项目 | 内容」两列表格；表中**无**「查重与检索说明」及以后各行；内容列**分段换行**（非整节单行）
- [ ] 已告知用户最终 Word 文档的路径
